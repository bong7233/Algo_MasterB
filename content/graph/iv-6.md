# IV-6 위상 정렬

::: lead
"무엇을 먼저 해야 하는가"를 그래프가 대신 답하게 하는 법, 그리고 그 답이 없다는 것이 무엇을 뜻하는가.

## 1. 문제

`make app` 한 줄을 치면 빌드 도구가 해야 하는 일은 이것이다. `app`은 `main.o`와 `util.o`를 링크해서 만든다. `main.o`는 `main.c`와 `util.h`를 컴파일해서 만든다. `util.o`는 `util.c`와 `util.h`로 만든다. **어느 것부터 실행할 것인가.**

```text nolines
   util.h ─┬──────────────▶ main.o ─┐
           │                ▲       │
           │       main.c ──┘       ├──▶ app
           │                        │
           └──────────────▶ util.o ─┘
                            ▲
                   util.c ──┘
```

순서를 손으로 적어 두는 방법이 있다. 실제로 그렇게 하는 빌드 스크립트가 많다. 세 가지 이유로 무너진다.

**첫째, 순서가 유일하지 않다.** `main.o`를 먼저 만들어도 되고 `util.o`를 먼저 만들어도 된다. 어느 쪽을 적어도 틀리지 않지만, 그렇다면 무엇이 "옳은 순서"인지 규칙으로 말할 수 없다는 뜻이다. 규칙이 없으면 파일이 늘 때 어디에 끼워 넣을지도 판단할 수 없다.

**둘째, 규모가 커지면 사람이 못 한다.** 리눅스 커널 빌드의 의존 그래프는 정점이 수만 개다. 하나를 잘못 놓으면 아직 만들어지지 않은 `.o`를 링크하고, 그 실패는 빌드 로그 3만 줄 중간에서 난다.

**셋째, 순서가 아예 존재하지 않을 수 있다.** 누군가 헤더를 잘못 건드려 `a.h`가 `b.h`를 포함하고 `b.h`가 `a.h`를 포함하게 만들면, 어느 것을 먼저 처리해도 상대가 필요하다. **이때 빌드 도구는 아무 순서나 고르면 안 되고 "순환 의존이다"라고 말해야 한다.**

같은 문제가 빌드 밖에도 널려 있다. 스프레드시트는 수식이 참조하는 셀을 먼저 계산해야 하고, 패키지 매니저는 의존 라이브러리를 먼저 설치해야 하며, 작업 스케줄러는 선행 작업이 끝난 뒤에만 다음 작업을 던져야 한다. 셋 다 "순환이면 거부한다"까지 똑같다.

## 2. 아이디어

간선 `u → v`를 "u를 v보다 먼저"로 읽으면 이 문제는 그래프 문제가 된다. 모든 간선의 방향을 어기지 않는 정점의 일렬 나열을 **위상 순서**라고 하고, 그것을 구하는 것이 위상 정렬이다.

### 2.1 진입차수 0에서 시작한다

지금 당장 시작할 수 있는 일은 무엇인가. **들어오는 간선이 하나도 없는 정점**이다. 선행이 없으니 기다릴 것이 없다. 들어오는 간선의 개수를 그 정점의 **진입차수**라고 한다.

하나를 골라 처리하고 나면 그 정점은 그래프에서 지워진다. 지워지면 거기서 나가던 간선들도 지워지고, 그 간선이 가리키던 정점들의 진입차수가 하나씩 줄어든다. **어떤 정점의 진입차수가 0이 되는 순간이 곧 그 작업의 선행이 전부 끝난 순간이다.** 그때 큐에 넣는다.

이것이 Kahn의 알고리즘이다. 실제로 간선을 지울 필요는 없고 진입차수 배열의 숫자만 줄이면 된다.

### 2.2 순서가 존재하는 조건

위상 순서는 언제 존재하는가. **사이클이 없을 때, 그리고 그때만이다.** 사이클이 없는 방향 그래프를 **DAG**라고 부른다. 양쪽 방향을 다 봐야 한다.

**사이클이 있으면 순서가 없다.** 사이클 `v₁ → v₂ → … → vₖ → v₁`이 있다고 하자. 위상 순서가 존재한다면 이 중에 가장 먼저 나오는 정점이 하나 있을 것이고, 그것을 `vᵢ`라 하자. 그런데 `vᵢ`에는 사이클 안의 다른 정점에서 들어오는 간선이 있고, 그 정점은 `vᵢ`보다 앞에 있어야 한다. `vᵢ`가 가장 앞이라는 가정과 모순이다.

**DAG면 순서가 있다.** 진입차수 0인 정점이 반드시 하나는 있다는 것부터 보인다. 없다고 하자. 그러면 모든 정점에 들어오는 간선이 있으므로, 아무 정점에서나 간선을 거꾸로 계속 따라갈 수 있다. 정점은 유한한데 걸음은 무한하니 언젠가 같은 정점을 두 번 밟고, 그 사이 구간이 사이클이다. DAG라는 가정과 모순이다. 그러므로 진입차수 0인 정점이 있고, 그것을 떼어 내면 남은 것도 DAG이므로 같은 논증을 반복할 수 있다.

==그래서 위상 정렬은 정렬 알고리즘이면서 동시에 사이클 검출기다.== Kahn을 끝까지 돌렸는데 꺼낸 정점 수가 전체보다 적다면, 남은 정점들은 전부 진입차수가 1 이상이고 — 방금 보인 논증에 의해 — 그 안에 사이클이 있다. **빌드 도구가 순환 의존을 잡아내는 코드가 순서를 만드는 코드와 같은 코드다.**

### 2.3 두 번째 구성: DFS 후위 역순

다른 길도 있다. 정점 하나에서 DFS를 돌리면 그 정점에서 도달 가능한 것을 전부 훑고 돌아온다. **어떤 정점의 DFS가 끝났다는 것은 그 정점 뒤에 와야 할 것들이 전부 끝났다는 뜻이다.** 그러니 끝난 순서(후위)를 기록하고 뒤집으면 위상 순서가 나온다.

이쪽은 사이클 검출이 공짜가 아니다. 정점에 세 가지 상태를 둬야 한다.

```text nolines
   WHITE   아직 안 봤다
   GRAY    지금 재귀 스택 위에 있다
   BLACK   자손을 전부 끝내고 빠져나왔다
```

이미 본 정점을 다시 만났을 때, **그것이 GRAY면 사이클이고 BLACK이면 아니다.** GRAY는 지금 내려온 경로 위에 있다는 뜻이라 거기로 가는 간선은 되돌아가는 간선이다. BLACK은 이미 끝난 다른 가지라 다시 갈 이유가 없을 뿐 순환은 아니다. 이 둘을 구분하지 않고 `visited` 하나로 처리하면 마름모 모양 그래프를 사이클로 오진한다.

| | Kahn | DFS 후위 역순 |
|---|---|---|
| 자료구조 | 진입차수 배열 + 큐 | 재귀 스택 + 3색 배열 |
| 사이클 검출 | 꺼낸 개수 < 정점 수 | GRAY 정점으로 향하는 간선 |
| 사이클을 **찾아 주는가** | 아니다. 남은 정점 집합만 안다 | 그렇다. 스택 위 경로가 곧 사이클이다 |
| 부가 산출물 | 동시에 시작 가능한 작업 묶음 | 강한 연결 요소 분해로 이어진다 |
| 깊이 위험 | 없다 | 재귀 깊이가 정점 수까지 간다 |

## 3. 손으로 따라가기

정점 6개, 이름은 `1 util.h`, `2 main.c`, `3 util.c`, `4 main.o`, `5 util.o`, `6 app`.

- [ ] 마지막에 순서의 길이는 얼마인가. 정점 수와 같은가
- [ ] 간선 `6→1`을 하나 더 넣고 처음부터 다시 하면 초기 큐에는 무엇이 들어가는가

|---|---|---|---|---|---|---|
| — | — | 2 | 2 | 2 | 1 2 3 | (비었다) |
| 0 | 1 | 1 | 1 | 2 | 2 3 | 1 |
| 1 | 2 | 0 | 1 | 2 | 3 4 | 1 2 |
| 2 | 3 | 0 | 0 | 2 | 4 5 | 1 2 3 |
| 3 | 4 | 0 | 0 | 1 | 5 | 1 2 3 4 |

순서는 `util.h main.c util.c main.o util.o app` 이고 길이는 6, 정점 수와 같다. **사이클이 없다.**

첫 번째 질문. 4는 **큐의 뒤**로 들어간다. 그래서 스텝 2에서 꺼내지는 것은 4가 아니라 이미 큐에 있던 3이다. 여기서 오해가 잘 생긴다 — 큐에 있다는 것은 "다음에 처리된다"가 아니라 **"이제 언제 처리해도 된다"** 는 뜻이다. 큐 안의 정점들은 서로 아무 순서로 배치해도 위상 순서가 깨지지 않는다. 스텝 2 시점의 큐 `3 4`가 그 예다.

두 번째 질문의 요점은 길이 비교다. 이 비교 하나가 사이클 검출의 전부다.

세 번째. 간선 `6→1`을 넣으면 `indeg[1]`이 1이 되어 **초기 큐에는 2와 3만 들어간다.** 2를 꺼내면 `indeg[4]`가 1, 3을 꺼내면 `indeg[5]`가 1이 되고 거기서 큐가 빈다. 순서의 길이는 2, 정점 수는 6이다. 못 꺼낸 `1 4 5 6`이 정확히 사이클 `1→4→6→1`과 거기에 딸린 `5`다. **남은 정점 집합이 사이클을 포함하지만 사이클 자체는 아니라는 것**에 주의하라. 5는 사이클 위에 있지 않은데도 사이클의 하류라 영원히 진입차수가 0이 되지 않는다.

## 4. 구현

두 구성을 나란히 둔다. 같은 그래프에 넣고 마지막에 간선 하나를 더해 사이클을 만든다.

::: dual
```python title="위상 정렬 — Kahn과 DFS 후위 역순"
from collections import deque

NAMES = ["", "util.h", "main.c", "util.c", "main.o", "util.o", "app"]


def kahn(n, edges):
    adj = [[] for _ in range(n + 1)]
    indeg = [0] * (n + 1)
    for u, v in edges:
        adj[u].append(v)
        indeg[v] += 1
    q = deque(v for v in range(1, n + 1) if indeg[v] == 0)
    order = []
    while q:
        v = q.popleft()
        order.append(v)
        for nx in adj[v]:
            indeg[nx] -= 1          # v 를 지웠으니 v 에서 나가는 간선도 지운다
            if indeg[nx] == 0:      # 선행이 전부 사라진 순간에만 큐로
                q.append(nx)
    if len(order) < n:
        return None                 # 못 꺼낸 정점은 전부 사이클의 하류다
    return order


WHITE, GRAY, BLACK = 0, 1, 2


def dfs_topo(n, edges):
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
    color = [WHITE] * (n + 1)
    post = []
    ok = True

    def go(v):
        nonlocal ok
        color[v] = GRAY             # 지금 재귀 스택 위에 있다
        for nx in adj[v]:
            if color[nx] == GRAY:   # 스택 위로 되돌아갔다 = 사이클
                ok = False
            elif color[nx] == WHITE:
                go(nx)
        color[v] = BLACK            # 자손을 전부 끝냈다
        post.append(v)              # 끝난 순서대로 쌓인다 = 후위

    for v in range(1, n + 1):
        if color[v] == WHITE:
            go(v)
    return post[::-1] if ok else None    # 후위의 역순이 위상 순서다


def show(tag, order):
    if order is None:
        print(f"{tag}: 사이클 — 위상 순서가 없다")
    else:
        print(f"{tag}: " + " ".join(NAMES[v] for v in order))


n = 6
edges = [(1, 4), (2, 4), (1, 5), (3, 5), (4, 6), (5, 6)]
show("Kahn", kahn(n, edges))
show("DFS ", dfs_topo(n, edges))

cyclic = edges + [(6, 1)]           # app 이 util.h 를 만든다고 하면
show("Kahn", kahn(n, cyclic))
show("DFS ", dfs_topo(n, cyclic))
```
```cpp title="위상 정렬 — Kahn과 DFS 후위 역순"
#include <functional>
#include <iostream>
#include <queue>
#include <string>
#include <vector>
using namespace std;

const vector<string> NAMES = {"", "util.h", "main.c", "util.c", "main.o", "util.o", "app"};

vector<int> kahn(int n, const vector<pair<int, int>>& edges) {
    vector<vector<int>> adj(n + 1);
    vector<int> indeg(n + 1, 0);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        indeg[v] += 1;
    }
    queue<int> q;
    for (int v = 1; v <= n; v++)
        if (indeg[v] == 0) q.push(v);
    vector<int> order;
    while (!q.empty()) {
        int v = q.front();
        q.pop();
        order.push_back(v);
        for (int nx : adj[v]) {
            indeg[nx] -= 1;         // v 를 지웠으니 v 에서 나가는 간선도 지운다
            if (indeg[nx] == 0)     // 선행이 전부 사라진 순간에만 큐로
                q.push(nx);
        }
    }
    if ((int)order.size() < n)
        return {};                  // 못 꺼낸 정점은 전부 사이클의 하류다
    return order;
}

const int WHITE = 0, GRAY = 1, BLACK = 2;

vector<int> dfs_topo(int n, const vector<pair<int, int>>& edges) {
    vector<vector<int>> adj(n + 1);
    for (auto [u, v] : edges) adj[u].push_back(v);
    vector<int> color(n + 1, WHITE), post;
    bool ok = true;

    function<void(int)> go = [&](int v) {
        color[v] = GRAY;            // 지금 재귀 스택 위에 있다
        for (int nx : adj[v]) {
            if (color[nx] == GRAY)  // 스택 위로 되돌아갔다 = 사이클
                ok = false;
            else if (color[nx] == WHITE)
                go(nx);
        }
        color[v] = BLACK;           // 자손을 전부 끝냈다
        post.push_back(v);          // 끝난 순서대로 쌓인다 = 후위
    };

    for (int v = 1; v <= n; v++)
        if (color[v] == WHITE) go(v);
    if (!ok) return {};
    return vector<int>(post.rbegin(), post.rend());   // 후위의 역순이 위상 순서다
}

void show(const string& tag, const vector<int>& order) {
    if (order.empty()) {
        cout << tag << ": 사이클 — 위상 순서가 없다\n";
        return;
    }
    cout << tag << ": ";
    for (size_t i = 0; i < order.size(); i++)
        cout << NAMES[order[i]] << (i + 1 < order.size() ? " " : "\n");
}

int main() {
    int n = 6;
    vector<pair<int, int>> edges = {{1, 4}, {2, 4}, {1, 5}, {3, 5}, {4, 6}, {5, 6}};
    show("Kahn", kahn(n, edges));
    show("DFS ", dfs_topo(n, edges));

    auto cyclic = edges;
    cyclic.push_back({6, 1});       // app 이 util.h 를 만든다고 하면
    show("Kahn", kahn(n, cyclic));
    show("DFS ", dfs_topo(n, cyclic));
    return 0;
}
```

두 언어의 출력은 같다.

```console
Kahn: util.h main.c util.c main.o util.o app
DFS : util.c main.c util.h util.o main.o app
Kahn: 사이클 — 위상 순서가 없다
DFS : 사이클 — 위상 순서가 없다
```

**두 순서가 다르다는 것이 이 출력의 핵심이다.** 둘 다 옳다. `util.c`를 맨 앞에 두든 `util.h`를 맨 앞에 두든 어떤 간선의 방향도 어기지 않는다. 위상 순서는 유일하지 않고, **유일해지는 조건은 매 스텝 진입차수 0인 정점이 정확히 하나뿐일 때**다.

**복잡도:** 둘 다 시간 $O(V + E)$ — Kahn은 정점마다 큐 삽입 1회·꺼내기 1회이고 간선마다 진입차수 감소 1회이므로 $V + E$에 비례한다. DFS도 정점마다 진입 1회이고 각 정점에서 나가는 간선을 한 번씩 훑으므로 같다. 공간 $O(V + E)$ — 인접 리스트가 $E$, 진입차수 배열과 큐(또는 색 배열과 재귀 스택)가 $V$다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 중첩 함수 재귀 | `def go(v)` 안에서 바깥 변수를 쓰려면 `nonlocal` | 람다는 `[&]` 캡처. 자기 자신을 부르려면 `std::function`이 필요하다(`auto`로는 타입이 안 정해진다) |
| 뒤집기 | `post[::-1]` — 새 리스트를 만든다 | `vector<int>(post.rbegin(), post.rend())` — 역방향 반복자 구간으로 새 벡터를 만든다 |
| "답 없음" 표현 | `None` | 빈 `vector`. 정점이 0개인 그래프와 구분이 안 되므로 실무에서는 `optional<vector<int>>`가 낫다 |
| 재귀 깊이 | 기본 1,000. 정점이 $10^5$이면 `dfs_topo`가 그대로 죽는다 | 스택 한계까지. 8 MB면 $10^5$ 근처가 경계다([IV-8](#/iv-8)) |

::: pitfall
- **진입차수를 매번 다시 세려고 한다.** "진입차수 0인 정점을 찾아 제거"를 글자 그대로 구현하면 매 스텝 전체를 훑어 $O(V^2)$가 된다. 배열을 한 번 만들고 감소만 시켜야 $O(V+E)$다.
- **큐에 넣는 시점을 `indeg[nx] == 0`이 아니라 `indeg[nx] <= 0`으로 쓴다.** 같아 보이지만 `indeg`가 음수로 내려갈 수 있는 구현(중복 간선)에서는 같은 정점을 여러 번 넣는다. 정확히 0이 되는 그 순간만 잡아라.
- **`visited` 하나로 DFS 사이클을 판정한다.** `1→2, 1→3, 2→4, 3→4` 같은 마름모에서 4를 두 번 만나는데 사이클은 없다. GRAY와 BLACK을 구분하지 않으면 오진한다.
- **사이클 검사를 빼먹는다.** 사이클이 있는 그래프에 Kahn을 돌리면 예외 없이 **짧은 순서를 조용히 돌려준다.** 길이 비교를 안 하면 절반짜리 빌드 순서가 정답인 척 나간다.
- **간선 방향을 반대로 넣는다.** "A를 먼저 풀어야 B를 푼다"는 `A → B`다. 지문이 "B는 A가 필요하다"로 쓰여 있으면 화살표가 뒤집혀 보인다. 방향을 정하고 나서 진입차수를 세라.
:::

::: deep
Kahn의 큐를 최소 힙으로 바꾸면 **사전순으로 가장 앞선 위상 순서**가 나온다. 매 스텝 "지금 가능한 것들" 중 번호가 가장 작은 것을 고르는 것이 그리디로 옳기 때문이다 — 지금 가능한 정점 중 가장 작은 것을 나중으로 미뤄서 얻을 이득이 없다.

같은 자리에 다른 우선순위를 꽂으면 다른 스케줄러가 된다. 소요 시간이 긴 작업을 먼저 꺼내면 전체 완료 시각을 줄이는 휴리스틱이 되고, 마감이 임박한 것을 먼저 꺼내면 EDF에 가까워진다. **위상 정렬은 "가능한 것들의 집합"을 유지해 주고, 그중 무엇을 고를지는 별개의 정책이다.** 우선순위 큐의 내부는 [II-8 힙과 우선순위 큐](#/ii-8)에, 실시간 스케줄링 정책은 [XI-5 실시간 스케줄링 개념](#/xi-5)에 있다.
:::

## 5. 어디에 쓰이는가

**`make`와 `ninja`가 하는 일이 이것이다.** 규칙 파일에서 의존 그래프를 만들고 위상 정렬로 실행 순서를 정한다. 순환이 있으면 `Circular dependency dropped` 같은 진단을 내고 멈추는데, 그 진단의 출처가 §2.2의 길이 비교다.

**`make -j8`이 Kahn의 큐를 그대로 쓴다.** 큐 안의 정점들은 서로 간에 어떤 간선도 없어서 **동시에 실행해도 안전하다.** 그래서 병렬 빌드는 "큐에서 최대 8개를 꺼내 동시에 던지고, 하나가 끝날 때마다 진입차수를 줄여 새로 0이 된 것을 큐에 넣는" 루프가 된다. 한 스텝에 꺼낼 수 있는 정점 수가 그 시점의 병렬도이고, 그래프를 진입차수 0인 층으로 나눈 층 수가 **코어가 무한히 많아도 줄일 수 없는 최소 라운드 수**다. 이 값이 곧 DAG에서 가장 긴 경로의 길이다.

**빌드 시간 추정과 크리티컬 패스도 같은 그래프 위에서 나온다.** 각 작업에 소요 시간을 붙이고 위상 순서대로 `finish[v] = max(선행들의 finish) + cost[v]`를 채우면 전체 완료 시각이 나온다. 순서가 이미 정해져 있으므로 각 정점을 딱 한 번 계산하면 되고, 이것이 DAG 위의 DP다 — 최단경로와 DP가 같은 것이라는 이야기는 [V-4 DP와 최단경로는 같은 것이다](#/v-4)에서 정면으로 다룬다.

**작업 오더 스케줄링에서는 사이클이 곧 장애다.** 작업 A가 끝나야 B가 시작되고 B가 끝나야 A가 시작되는 관계가 만들어지면 두 작업 모두 영원히 시작되지 않는다. 자원 할당 그래프에서 이 모양을 찾는 것이 교착 검출이고, 검출 알고리즘의 뼈대가 여기서 본 사이클 판정이다([V-10 교착 검출과 회피](#/v-10)). 상태 기계로 표현된 작업 오더에서 전이 그래프에 사이클이 있는지 보는 검사도 마찬가지다([XI-6 상태 기계](#/xi-6)).

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "A를 하려면 B를 먼저 해야 한다", "선수과목", "먼저 푸는 것이 좋은 문제", "앞에 서야 한다", "순서를 정하시오", "불가능하면 -1을 출력"
- 제약조건: 간선에 **방향**이 있고 그 방향이 시간·순서를 뜻한다. 정점 $V \le 10^5$, 간선 $E \le 5 \times 10^5$ 정도면 $O(V+E)$가 여유롭다. 가중치가 있어도 위상 순서 자체는 가중치를 쓰지 않는다
- 혼동 주의: 방향이 없으면 위상 정렬이 아니라 그냥 연결 요소 문제다([IV-5](#/iv-5)). "가장 빨리 끝나는 시각"을 물으면 위상 정렬 **뒤에** DAG 위 DP가 붙는다. 정점마다 값이 있고 최소 비용 경로를 물으면 [V-1 다익스트라](#/v-1)이지만, 그래프가 DAG면 힙 없이 위상 순서만으로 $O(V+E)$에 끝난다
- 반례 함정: 사이클이 있는 입력을 안 내면 길이 비교를 빼먹은 코드가 통과해 버린다. 그리고 **진입차수 0인 정점이 처음부터 여러 개**인 입력 — 답이 여러 개라 채점이 스페셜 저지이거나, 사전순 같은 추가 조건이 붙어 있다. 조건을 놓치면 "맞는 답"을 내고 틀린다
:::

## 연습

::: quiz
전부 위상 정렬의 원형이다. **간선 방향을 어느 쪽으로 잡을지부터 종이에 적어라.**

**1. 백준 2252 줄 세우기 (골드 3)** — https://www.acmicpc.net/problem/2252
- 신호: "A가 B 앞에 서야 한다"는 관계만 주어지고 키 같은 절대값은 없다. 관계가 곧 간선이다.
- 상태: 진입차수 배열 하나. 답이 여러 개일 수 있고 아무거나 출력하면 된다.
- 자료구조: 인접 리스트 + 큐. 이 문제가 위상 정렬의 가장 벌거벗은 형태라서 먼저 푼다.

**2. 백준 14567 선수과목 (골드 5)** — https://www.acmicpc.net/problem/14567
- 신호: "각 과목을 이수하려면 최소 몇 학기가 걸리는가". 순서가 아니라 **층 번호**를 묻는다.
- 상태: 진입차수 배열 + `semester[v]`. 진입차수가 0이 되어 큐에 들어갈 때 `semester[nx] = max(semester[nx], semester[v] + 1)`로 채운다. 이것이 DAG 위 DP의 가장 작은 형태다.
- 자료구조: 인접 리스트 + 큐. 위상 순서를 따르므로 각 정점을 한 번만 갱신하면 끝난다는 것이 요점이다.

**3. 백준 1005 ACM Craft (골드 3)** — https://www.acmicpc.net/problem/1005
- 신호: "건물 W를 짓는 데 걸리는 최소 시간" + "선행 건물이 전부 완성되어야 시작할 수 있다". 2번의 층 번호가 소요 시간으로 바뀐 것이다.
- 상태: `finish[v] = max(선행들의 finish) + cost[v]`. `max`인 이유는 선행들이 **동시에** 지어져도 가장 늦은 것을 기다려야 하기 때문이다.
- 자료구조: 인접 리스트 + 큐 + 비용 배열. 테스트 케이스가 여러 개이니 초기화가 답을 가른다.
:::

## 요약

- 간선 `u → v`를 "u를 v보다 먼저"로 읽으면 순서 문제가 그래프 문제가 된다. 그 나열이 위상 순서다.
- **진입차수 0 = 지금 시작할 수 있는 일.** 정점을 지우면 하류의 진입차수가 줄고, 0이 되는 순간이 그 작업의 선행이 다 끝난 순간이다.
- 위상 순서는 **DAG일 때, 그리고 그때만** 존재한다. 그래서 위상 정렬은 사이클 검출기이기도 하다.
- Kahn은 **꺼낸 개수 < 정점 수**로 사이클을 안다. DFS 후위 역순은 GRAY/BLACK 구분이 있어야 알고, 대신 사이클 자체를 스택 위에서 꺼내 준다.
- 둘 다 $O(V+E)$. 위상 순서는 **유일하지 않고**, 유일해지는 것은 매 스텝 후보가 하나뿐일 때다.
- 큐 안의 정점들은 서로 독립이라 **동시에 실행해도 된다.** `make -j`의 병렬도가 그 큐의 크기다.
- 순서를 정한 뒤 `finish[v] = max(선행) + cost[v]`를 붙이면 DAG 위 DP가 되고, 빌드 시간과 크리티컬 패스가 여기서 나온다.
