# IV-8 트리에서의 DFS

::: lead
사이클이 없다는 사실 하나로 탐색 코드에서 무엇이 사라지고, 자식에서 부모로 값을 올리는 순서가 왜 후위인가.
:::

## 1. 문제

`du -s` 는 디렉터리 하나가 차지하는 총 용량을 알려 준다. 파일시스템이 아는 것은 **파일 하나하나의 크기**뿐이다. 디렉터리 자체는 몇 킬로바이트짜리 목록이라 그 안에 무엇이 얼마나 들었는지는 적혀 있지 않다.

같은 모양의 질문이 어디에나 있다. 조직도에서 각 부서의 총 인원, 부품 조립도에서 완제품 하나에 들어가는 나사의 총 개수, 화면 레이아웃에서 컨테이너 하나가 차지해야 하는 높이. **개별 값은 잎에만 있고, 물어보는 값은 중간 노드에 있다.**

그러면 위에서 아래로 훑으면서 채우면 되지 않느냐는 생각이 든다. 안 된다. 루트의 값은 자식들의 값이 전부 확정된 뒤에만 계산할 수 있고, 그 자식의 값도 손자가 끝나야 나온다. **의존이 잎 쪽에서 뿌리 쪽으로 흐른다.** 이 순서를 지키면서 각 노드를 정확히 한 번만 계산하려면 어떻게 훑어야 하는가.

반대 방향으로 흐르는 값도 있다. 각 노드의 **깊이**는 부모의 깊이 + 1이라 뿌리에서 잎 쪽으로 흐른다. 두 방향의 정보를 각각 한 번씩, 총 두 번 훑어야 하는가.

## 2. 아이디어

::: widget tree-traversal {"edges":[[1,2],[1,3],[2,4],[2,5],[3,6],[5,7]],"root":1,"orders":["preorder","postorder"],"showStack":true}
:::

위젯은 정점 7개짜리 트리에 DFS를 걸고, 재귀 호출 스택과 전위·후위 순서를 동시에 보인다. 스텝을 밀면 스택이 깊어졌다 얕아지는 동안 **전위 표시는 스택이 깊어지는 순간에, 후위 표시는 얕아지는 순간에** 찍히는 것이 보인다. 같은 한 번의 탐색이 두 개의 순서를 만들어 낸다. 순회의 종류는 [II-10 트리 순회](#/ii-10)에서 정리했다.

여기서 두 가지를 가져간다.

**첫째, 한 번의 DFS가 양방향 정보를 다 나른다.** 깊이는 내려가는 길에 `depth[child] = depth[v] + 1`로 채우고, 크기는 올라오는 길에 `size[v] += size[child]`로 누적한다. 두 번 훑을 필요가 없다.

**둘째, 후위란 "자식이 전부 끝난 뒤"의 다른 이름이다.** §1이 요구한 계산 순서가 정확히 후위다. `size[v]`에 자식의 값을 더하는 코드가 재귀 호출 **뒤에** 놓이면 그것만으로 의존 순서가 지켜진다. 순서를 따로 계산할 필요가 없다는 뜻이다.

### 2.1 `visited`가 사라진다

일반 그래프 DFS는 방문 배열이 필수다. 없으면 사이클을 만나 무한히 돈다. 트리에서는 다르다.

트리는 **사이클이 없는 연결 그래프**다. 정점 $V$개에 간선이 정확히 $V - 1$개이고, 두 정점 사이의 경로가 유일하다. 이 사실을 탐색의 언어로 옮기면 이렇게 된다.

> 이미 방문한 정점으로 가는 간선이 있다면 그것은 사이클을 닫는 간선이다([IV-7 §2.3](#/iv-7)). 트리에는 사이클이 없다. 그러므로 **되돌아갈 수 있는 곳은 방금 타고 내려온 부모 하나뿐이다.**

그래서 방문 배열 전체가 **인자 하나**로 줄어든다.

```text nolines
   general graph      if visited[nx]: continue
   tree               if nx == parent: continue
```

이것을 배열 하나 아꼈다고 읽으면 요점을 놓친다. 진짜 이득은 **상태가 전역에서 호출 인자로 내려왔다**는 것이다. 배열은 탐색이 끝난 뒤 다음 탐색을 위해 지워야 하지만 인자는 지울 것이 없다. 루트를 바꿔 가며 DFS를 $n$번 돌리는 코드에서 초기화 비용이 통째로 사라진다.

::: warn
같은 간선이 두 번 들어오는 입력에서는 이 규칙이 무너진다. `1-2`가 두 줄 들어오면 그것은 트리가 아니라 길이 2짜리 사이클인데, `nx == parent` 검사가 둘 다 걸러 버려 탐색이 조용히 성공한다. **입력이 트리임이 지문에 보장될 때만 부모 규칙을 쓴다.**
:::

### 2.2 루트를 바꾸면 무엇이 바뀌는가

`size[v]`는 트리 자체의 성질이 아니다. **루트를 어디에 두느냐에 달린 값**이다. 간선 하나를 잘라 보면 관계가 보인다.

간선 `(u, v)`를 자르면 트리는 두 조각으로 갈라진다. 조각의 크기는 어느 쪽을 루트로 삼든 같다. 달라지는 것은 이름뿐이다. 루트가 `u` 쪽에 있으면 `v` 쪽 조각을 `size[v]`라고 부르고, 루트가 `v` 쪽에 있으면 `u` 쪽 조각 — 즉 `n - size[v]` — 를 `size[u]`라고 부른다.

```text nolines
   root at u side        u ---- v        size[v] = 3
                                         n - size[v] = 4

   root at v side        u ---- v        size[u] = 4
```

**한 번의 DFS로 모든 간선에 대해 양쪽 조각의 크기를 알게 된다.** 루트를 옮겨 가며 $n$번 다시 도는 대신, 한 번 재고 나머지는 뺄셈으로 얻는다. 이 발상을 값이 크기가 아니라 임의의 누적량일 때까지 밀어붙인 것이 리루팅 기법이고, [VIII-8 트리 DP](#/viii-8)에서 다룬다. 두 정점의 관계를 깊이와 조상으로 다루는 쪽은 [IX-5 LCA와 희소 배열](#/ix-5)로 간다.

## 3. 손으로 따라가기

::: trace
정점 7개, 간선 `1-2  1-3  2-4  2-5  3-6  5-7`. 루트는 1이다.

인접 리스트는 간선 순서대로 쌓인다. `adj[1] = [2, 3]`, `adj[2] = [1, 4, 5]`, `adj[3] = [1, 6]`, `adj[5] = [2, 7]`. 자식은 이 순서대로 방문한다.

각 정점은 자기 자신을 세고 시작하므로 `size[v]`의 출발값은 1이다. **표는 정점이 "끝나는" 순서, 즉 후위 순서로 채운다.**

| 후위 순서 | v | depth[v] | 자식들의 size 합 | 확정된 size[v] |
|---|---|---|---|---|
| 1 | 4 | 2 | 0 | 1 |
| 2 | 7 | 3 | 0 | 1 |
| 3 | 5 | 2 | 1 (7) | 2 |
| 4 |  |  |  |  |
| 5 |  |  |  |  |
| 6 |  |  |  |  |
| 7 |  |  |  |  |

세 가지를 확인하라.

- [ ] 4번 자리에 오는 정점은 무엇인가. 왜 6이 아닌가
- [ ] 마지막 줄의 `size`는 얼마여야 하는가
- [ ] `size[v] += size[nx]`를 재귀 호출 **앞**으로 옮기면 표의 어느 줄부터 틀어지는가
:::

::: answer
| 후위 순서 | v | depth[v] | 자식들의 size 합 | 확정된 size[v] |
|---|---|---|---|---|
| 1 | 4 | 2 | 0 | 1 |
| 2 | 7 | 3 | 0 | 1 |
| 3 | 5 | 2 | 1 (7) | 2 |
| 4 | 2 | 1 | 1 (4) + 2 (5) = 3 | 4 |
| 5 | 6 | 2 | 0 | 1 |
| 6 | 3 | 1 | 1 (6) | 2 |
| 7 | 1 | 0 | 4 (2) + 2 (3) = 6 | 7 |

첫 번째 질문. 4번 자리는 **2**다. 6이 아닌 이유는 DFS가 1의 첫 자식 2로 내려가 그 아래(4, 5, 7)를 **전부 끝낸 뒤에야** 1로 돌아와 두 번째 자식 3으로 가기 때문이다. 6은 3의 자식이므로 3의 차례가 와야 방문된다. ==후위 순서는 "깊이 순"이 아니라 "서브트리 단위로 뭉쳐서" 나온다.== 표를 보면 `4, 7, 5, 2`가 한 덩어리이고 `6, 3`이 다음 덩어리다.

두 번째. 마지막 줄은 루트이므로 `size[1] = 7`, 정점 수와 같다. **이것이 이 알고리즘의 검산이다.** 루트의 크기가 $n$이 아니면 어딘가에서 한 번 더 세었거나 빠뜨린 것이다.

세 번째. `size[v] += size[nx]`를 재귀 호출 앞으로 옮기면 **3번 줄부터** 틀어진다. 5가 7을 더할 때 `size[7]`은 아직 초기값 1이라 우연히 맞는다. 그러나 4번 줄에서 2가 5를 더할 때 `size[5]`는 아직 1이므로 `size[2] = 1 + 1 + 1 = 3`이 되어 정답 4와 어긋난다. **잎에서 한 칸 떨어진 곳까지는 우연히 맞고, 두 칸부터 틀린다.** 작은 예제로만 확인하면 놓치는 종류의 버그다.
:::

## 4. 구현

깊이는 내려가면서, 크기는 올라오면서. 두 줄의 위치가 곧 전위와 후위다.

::: dual
```python title="서브트리 크기와 깊이 — 재귀"
def subtree(n, edges, root):
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    size = [1] * (n + 1)            # 자기 자신을 이미 센 상태에서 시작한다
    depth = [0] * (n + 1)

    def go(v, parent):
        for nx in adj[v]:
            if nx == parent:        # 방문 배열 대신 부모 한 칸만 막는다
                continue
            depth[nx] = depth[v] + 1    # 내려가면서 채운다 = 전위
            go(nx, v)
            size[v] += size[nx]     # 자식이 끝난 뒤 올린다 = 후위
    go(root, 0)
    return size, depth


n = 7
edges = [(1, 2), (1, 3), (2, 4), (2, 5), (3, 6), (5, 7)]
size, depth = subtree(n, edges, 1)
print("v     :", " ".join(f"{v:2d}" for v in range(1, n + 1)))
print("size  :", " ".join(f"{size[v]:2d}" for v in range(1, n + 1)))
print("depth :", " ".join(f"{depth[v]:2d}" for v in range(1, n + 1)))
```
```cpp title="서브트리 크기와 깊이 — 재귀"
#include <cstdio>
#include <functional>
#include <vector>
using namespace std;

void subtree(int n, const vector<pair<int, int>>& edges, int root,
             vector<int>& size, vector<int>& depth) {
    vector<vector<int>> adj(n + 1);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }
    size.assign(n + 1, 1);          // 자기 자신을 이미 센 상태에서 시작한다
    depth.assign(n + 1, 0);

    function<void(int, int)> go = [&](int v, int parent) {
        for (int nx : adj[v]) {
            if (nx == parent)       // 방문 배열 대신 부모 한 칸만 막는다
                continue;
            depth[nx] = depth[v] + 1;   // 내려가면서 채운다 = 전위
            go(nx, v);
            size[v] += size[nx];    // 자식이 끝난 뒤 올린다 = 후위
        }
    };
    go(root, 0);
}

int main() {
    int n = 7;
    vector<pair<int, int>> edges = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {3, 6}, {5, 7}};
    vector<int> size, depth;
    subtree(n, edges, 1, size, depth);
    printf("v     :");
    for (int v = 1; v <= n; v++) printf(" %2d", v);
    printf("\nsize  :");
    for (int v = 1; v <= n; v++) printf(" %2d", size[v]);
    printf("\ndepth :");
    for (int v = 1; v <= n; v++) printf(" %2d", depth[v]);
    printf("\n");
    return 0;
}
```
:::

두 언어의 출력은 같다.

```console
v     :  1  2  3  4  5  6  7
size  :  7  4  2  1  2  1  1
depth :  0  1  1  2  2  2  3
```

**복잡도:** 시간 $O(V)$ — 정점마다 함수 진입이 정확히 한 번이고, 각 정점에서 인접 리스트를 한 번 훑는다. 인접 리스트의 총 길이는 무방향 간선 $V-1$개의 두 배이므로 $2(V-1)$, 즉 $O(V)$다. 간선 항을 따로 쓰지 않는 이유가 이것이다 — **트리에서는 $E = V - 1$이라 $O(V+E)$와 $O(V)$가 같은 말이다.** 공간 $O(V)$ — 인접 리스트와 두 배열, 그리고 재귀 스택이 최악에 깊이 $V$까지 쌓인다.

**마지막 항이 문제를 일으킨다.** 트리가 한 줄로 늘어선 모양이면 재귀 깊이가 곧 정점 수다.

::: perf
정점 $10^5$개가 `1 - 2 - 3 - … - n` 한 줄로 이어진 트리에 위의 재귀 `subtree`를 그대로 돌린 결과다.

| | 결과 |
|---|---|
| Python 3.13, 기본 한도 | `RecursionError`. 실측한 실제 진입 가능 깊이는 **997**이다 |
| Python 3.13, `setrecursionlimit(300000)` | 통과. 깊이 500,000까지 통과를 확인했다 |
| C++17 `-O2`, 스택 8 MB | 정점 **104,500**은 통과, **104,800**은 `SIGSEGV`. 프레임당 약 80바이트 |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. `ulimit -s` = 8192. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/tree_dfs_recursion_depth.py` 와 `.cpp` 다.)

세 줄이 각각 다른 이야기를 한다.

Python의 기본 한도 1,000은 $10^5$짜리 트리 앞에서 **무조건** 걸린다. 한도를 올리면 CPython 3.12 이상에서는 순수 Python 함수의 재귀가 C 스택을 쓰지 않아 실제로 통과한다 — 이 사실과 그럼에도 한도를 크게 올리는 것이 안전한 조치가 아닌 이유는 [0-10 언어별 상수와 TLE 대응](#/0-10)에 있다.

**C++ 쪽이 더 위험하다.** 한도를 올릴 방법이 없고, 넘기면 예외가 아니라 `SIGSEGV`다. 잡을 수도 없고 어디서 죽었는지도 안 알려 준다. 그리고 경계가 하필 $10^5$ 바로 위다 — **문제의 제약이 `N ≤ 100,000`이면 딱 살아남고 `N ≤ 200,000`이면 죽는다.** 채점기의 스택 한계가 로컬과 다르면 로컬에서만 통과하는 코드가 나온다.
:::

같은 알고리즘을 명시적 스택으로 옮기면 깊이 문제가 사라진다. 요령은 후위를 직접 흉내 내지 않는 것이다. **전위 순서를 기록해 두고 그 역순으로 누적하면 된다** — 전위에서 부모는 항상 모든 자손보다 앞에 나오므로, 뒤집으면 자손이 항상 부모보다 앞에 온다.

::: dual
```python title="서브트리 크기와 깊이 — 명시적 스택"
def subtree_iter(n, edges, root):
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    size = [1] * (n + 1)
    depth = [0] * (n + 1)
    parent = [0] * (n + 1)
    order = []
    stack = [root]
    while stack:
        v = stack.pop()
        order.append(v)             # 꺼낸 순서가 곧 전위 순서다
        for nx in adj[v]:
            if nx == parent[v]:
                continue
            parent[nx] = v
            depth[nx] = depth[v] + 1
            stack.append(nx)
    for v in reversed(order):       # 전위의 역순에서는 자식이 부모보다 먼저 나온다
        if v != root:
            size[parent[v]] += size[v]
    return size, depth


n = 100000                          # 한 줄로 늘어선 트리 — 깊이가 곧 정점 수다
edges = [(v, v + 1) for v in range(1, n)]
size, depth = subtree_iter(n, edges, 1)
print("정점", n, "짜리 경로 트리")
print("size[1] =", size[1], "/ depth[n] =", depth[n])
```
```cpp title="서브트리 크기와 깊이 — 명시적 스택"
#include <cstdio>
#include <vector>
using namespace std;

void subtree_iter(int n, const vector<pair<int, int>>& edges, int root,
                  vector<int>& size, vector<int>& depth) {
    vector<vector<int>> adj(n + 1);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }
    size.assign(n + 1, 1);
    depth.assign(n + 1, 0);
    vector<int> parent(n + 1, 0), order, stack;
    stack.push_back(root);
    while (!stack.empty()) {
        int v = stack.back();
        stack.pop_back();
        order.push_back(v);         // 꺼낸 순서가 곧 전위 순서다
        for (int nx : adj[v]) {
            if (nx == parent[v]) continue;
            parent[nx] = v;
            depth[nx] = depth[v] + 1;
            stack.push_back(nx);
        }
    }
    for (int i = (int)order.size() - 1; i >= 0; i--) {  // 전위의 역순에서는 자식이 부모보다 먼저 나온다
        int v = order[i];
        if (v != root) size[parent[v]] += size[v];
    }
}

int main() {
    int n = 100000;                 // 한 줄로 늘어선 트리 — 깊이가 곧 정점 수다
    vector<pair<int, int>> edges;
    for (int v = 1; v < n; v++) edges.push_back({v, v + 1});
    vector<int> size, depth;
    subtree_iter(n, edges, 1, size, depth);
    printf("정점 %d 짜리 경로 트리\n", n);
    printf("size[1] = %d / depth[n] = %d\n", size[1], depth[n]);
    return 0;
}
```
:::

```console
정점 100000 짜리 경로 트리
size[1] = 100000 / depth[n] = 99999
```

**복잡도:** 시간 $O(V)$ — 정점이 스택에 한 번씩만 들어가고, 마지막 누적 루프도 정점 수만큼 돈다. 공간 $O(V)$ — 여기서는 힙에 잡힌 배열이라 **OS 스택 한계와 무관하다.** 이것이 이 판본을 쓰는 유일한 이유다. 상수는 재귀보다 약간 크다. `parent`와 `order` 배열이 추가로 필요하고, 재귀판은 그 정보를 호출 스택이 공짜로 들고 있었기 때문이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 재귀 깊이 한계 | 기본 1,000. `sys.setrecursionlimit`으로 올릴 수 있다 | 올릴 수 없다. OS 스택 한계에 부딪히면 `SIGSEGV` |
| 한계 초과의 모습 | `RecursionError` 예외. 잡을 수 있다 | 정의되지 않은 동작. 잡을 수 없다 |
| 중첩 함수 재귀 | `def go(v, parent)` 그대로 | 람다가 자기를 부르려면 `std::function`이 필요하다. `auto`로는 타입이 안 정해진다 |
| 역순 순회 | `for v in reversed(order)` — 사본을 만들지 않는다 | 인덱스를 내리거나 `rbegin()/rend()` |
| 배열 이름 `size` | 지역 변수라 문제없다 | `std::size`와 겹치지만 지역 변수가 가린다. 전역이면 충돌한다 |

::: pitfall
- **누적을 재귀 호출 앞에 쓴다.** `size[v] += size[nx]`가 `go(nx, v)`보다 위에 있으면 자식이 아직 안 끝난 값을 더한다. 손추적의 세 번째 질문이 이것이고, **잎에서 두 칸 떨어진 곳부터** 틀린다.
- **간선을 단방향으로만 넣는다.** 입력이 `부모 자식` 순서로 주어진다는 보장이 없으면 양방향으로 넣어야 한다. 단방향으로 넣고 루트가 1이 아니면 탐색이 즉시 끝난다.
- **부모 규칙을 쓰면서 `size`를 0으로 초기화한다.** 자기 자신을 세는 `1`이 어디에도 없으면 모든 값이 0이 된다. 초기값 1이거나 재귀 첫 줄에 `size[v] = 1`이거나 둘 중 하나다.
- **깊이를 후위에서 채우려 한다.** 깊이는 부모에게서 내려오는 값이라 재귀 호출 **전에** 채워야 한다. 크기와 방향이 반대다.
- **트리가 아닌 입력에 부모 규칙을 쓴다.** 중복 간선이나 자기 간선이 섞이면 조용히 틀린다. §2.1의 경고가 그것이다.
- **깊이 $10^5$을 넘는데 재귀로 짠다.** Python은 기본 한도에서 즉시 죽고 C++은 채점기 스택에 따라 죽는다. 경로 모양 트리는 예제가 아니라 **저격용 입력으로 실제로 들어온다.**
:::

## 5. 어디에 쓰이는가

**`du`가 이 알고리즘이다.** 디렉터리 트리를 후위로 훑으면서 자식의 총 용량을 부모에 누적한다. `du -a`가 잎부터 출력하고 디렉터리 줄이 그 아래 파일들보다 **뒤에** 찍히는 것이 후위 순회의 증거다. 파일시스템이 트리라는 사실이 부모 규칙을 성립시키는데, 심볼릭 링크는 이 가정을 깬다 — 링크를 따라가는 옵션을 켜면 그래프가 되고 `du`는 방문한 아이노드를 기록하는 진짜 `visited` 집합을 다시 들어야 한다. **자료구조가 트리에서 그래프로 바뀌는 순간 코드도 되돌아간다.**

**UI 레이아웃 엔진이 두 방향 순회를 그대로 쓴다.** 브라우저가 화면을 그릴 때 각 요소의 크기는 자식들의 크기가 정해져야 계산되고(후위), 각 요소의 화면 좌표는 부모의 좌표에 자기 오프셋을 더해 정해진다(전위). 그래서 레이아웃은 트리를 두 번 훑는다 — 올라오면서 크기, 내려가면서 위치. 3D 씬 그래프의 월드 변환 행렬 누적도 정확히 같은 구조이고, 로봇의 좌표 프레임 트리에서 링크의 월드 자세를 구하는 계산도 여기에 해당한다.

**조직·부품 집계에서 이 코드가 재무 로직이 된다.** 부서 트리에서 부서별 총 인원과 총 예산, 부품 조립도(BOM)에서 완제품 하나에 필요한 원자재 수량이 전부 후위 누적이다. BOM은 같은 부품이 여러 상위 부품에 쓰여 트리가 아니라 DAG인 경우가 많은데, 그때는 이 절의 코드가 아니라 [IV-6 위상 정렬](#/iv-6) 뒤에 붙는 DAG 위 DP가 맞다. **트리인지 DAG인지가 알고리즘을 가르므로 자료를 먼저 확인한다.**

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "서브트리에 속한 정점의 수", "각 노드의 부모를 구하시오", "트리의 지름", "루트로부터의 거리", "N개의 정점과 N-1개의 간선", "사이클이 없는 연결 그래프"
- 제약조건: 간선이 정확히 $V - 1$개이고 그래프가 연결되어 있다. $V \le 10^5 \sim 10^6$이면 $O(V)$가 여유롭다. **깊이가 $V$까지 갈 수 있다는 것이 이 유형의 고유 제약이다**
- 혼동 주의: 간선이 $V-1$개가 아니면 트리가 아니라 일반 그래프이므로 `visited`가 필요하다([IV-2 DFS](#/iv-2)). 방향이 있고 여러 부모가 가능하면 트리가 아니라 DAG이고 [IV-6 위상 정렬](#/iv-6)이다. 자식의 값으로 부모의 **최적값**을 정하면 여기가 아니라 [VIII-8 트리 DP](#/viii-8)다
- 반례 함정: **한 줄로 늘어선 경로 모양 트리.** 정답률을 떨어뜨리려고 실제로 들어오는 입력이고, 재귀로 짜면 여기서만 죽는다. 그리고 **루트가 1이 아닌 입력** — 간선을 단방향으로만 넣은 코드가 여기서 빈 답을 낸다
:::

## 연습

::: quiz
**루트가 어디인지, 간선을 양방향으로 넣었는지, 깊이가 얼마까지 가는지 셋을 먼저 확인하라.**

**1. 백준 11725 트리의 부모 찾기 (실버 2)** — https://www.acmicpc.net/problem/11725
- 신호: "루트 없는 트리가 주어질 때 루트를 1이라고 정했을 때 각 노드의 부모를 구하라". 간선이 부모-자식 순서로 주어지지 않는다는 것이 지문에 박혀 있다.
- 상태: `parent[v]` 배열 하나. 크기도 깊이도 필요 없고, 탐색이 지나간 방향 자체가 답이다.
- 자료구조: 인접 리스트를 **양방향으로** 만들고 1에서 탐색한다. $N \le 100{,}000$이고 경로 모양 입력이 가능하므로 재귀로 짜면 Python은 한도를 올려야 하고 C++도 아슬아슬하다.

**2. 백준 15681 트리와 쿼리 (골드 5)** — https://www.acmicpc.net/problem/15681
- 신호: "정점 U를 루트로 하는 서브트리에 속한 정점의 수" + 쿼리가 여러 개. 이 절에서 만든 `size` 배열이 그대로 답이다.
- 상태: `size[v]`. 쿼리마다 다시 탐색하면 $O(QV)$이지만, 한 번 재 놓으면 쿼리당 $O(1)$이다.
- 자료구조: 인접 리스트 + `size` 배열. **전처리와 질의를 분리하는 사고**의 가장 작은 예이고, 세그먼트 트리로 가기 전에 이 감각을 먼저 잡는 편이 좋다.

**3. 백준 1967 트리의 지름 (골드 4)** — https://www.acmicpc.net/problem/1967
- 신호: "트리에 존재하는 모든 경로 중 가장 긴 것". 모든 쌍을 다 보면 $O(V^2)$이라 다른 관찰이 필요하다.
- 상태: 아무 정점에서 가장 먼 정점을 찾고, 거기서 다시 가장 먼 정점까지의 거리. DFS 두 번이면 끝난다.
- 자료구조: 가중치 있는 인접 리스트 + 거리 배열. **왜 두 번으로 충분한지**를 설명할 수 있어야 이 문제를 푼 것이다. 서브트리 크기 대신 "자식 쪽 최대 깊이 두 개의 합"을 후위로 올리는 풀이도 있고, 그쪽이 [VIII-8 트리 DP](#/viii-8)로 이어진다.
:::

## 요약

- 트리는 사이클이 없는 연결 그래프다. $E = V - 1$이고 두 정점 사이 경로가 유일하다.
- 그래서 되돌아갈 곳이 부모 하나뿐이고, **`visited` 배열이 인자 `parent` 하나로 줄어든다.** 초기화할 상태가 사라지는 것이 진짜 이득이다.
- 한 번의 DFS가 두 방향을 다 나른다. **깊이는 내려가면서(전위), 크기는 올라오면서(후위).**
- 후위란 "자식이 전부 끝난 뒤"의 다른 이름이다. 누적을 재귀 호출 **뒤에** 두는 것만으로 의존 순서가 지켜진다. 앞에 두면 잎에서 두 칸 떨어진 곳부터 틀린다.
- 트리에서는 $O(V+E)$와 $O(V)$가 같은 말이다.
- **경로 모양 트리에서 재귀 깊이가 정점 수와 같아진다.** Python 기본 한도는 1,000이고, C++은 스택 8 MB에서 정점 10만 4천 근처가 경계다. 넘으면 `SIGSEGV`다.
- 반복 판본은 **전위 순서를 기록하고 역순으로 누적**한다. 전위에서 부모는 항상 자손보다 앞이므로 뒤집으면 후위의 성질이 나온다.
- 간선 하나를 자르면 조각 크기는 `size[v]`와 `n - size[v]`다. 한 번의 DFS로 모든 간선의 양쪽을 알게 되고, 이것이 리루팅의 출발점이다([VIII-8](#/viii-8)).
