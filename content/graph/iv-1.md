# IV-1 그래프 표현

::: lead
격자와 의존성 목록과 상태공간은 어떻게 같은 것이 되는가.
:::

## 1. 문제

세 문제가 나란히 있다.

**첫째.** `1`은 길이고 `0`은 벽인 $N \times M$ 격자가 주어진다. 왼쪽 위에서 오른쪽 아래까지 최소 몇 칸을 지나는가.

**둘째.** 컴퓨터 $N$대와 "$a$와 $b$는 연결되어 있다"는 목록 $M$줄이 주어진다. 1번이 감염되면 몇 대가 감염되는가.

**셋째.** 부피가 각각 $A, B, C$인 물통 셋이 있다. 한 통이 비거나 다른 통이 찰 때까지만 부을 수 있다. 첫 통이 비었을 때 셋째 통에 남을 수 있는 물의 양을 전부 구하라.

셋은 서로 다른 문제로 보인다. 입력 형식이 다르고, 첫 번째는 2차원 배열이고 두 번째는 간선 목록이고 세 번째는 배열이라 부를 것조차 없다. 실제로 격자 문제를 무리 없이 푸는 사람이 두 번째에서 멈추고, 두 번째를 푸는 사람이 세 번째에서 멈춘다.

멈추는 이유는 알고리즘을 몰라서가 아니다. **셋 다 같은 알고리즘 한 개로 끝난다.** 멈추는 지점은 그 앞이다. 세 입력이 전부 "점들과 점 사이의 이동"이라는 사실이 안 보이는 것이고, 이것이 [I-1 왜 판별이 병목인가](#/i-1)가 매핑 결손이라고 부른 그 지점이다.

이 챕터는 알고리즘을 하나도 다루지 않는다. 대신 그 앞의 번역을 다룬다. ==입력을 그래프로 옮길 수 없으면 그래프 알고리즘을 아는 것은 쓸모가 없다.== 반대로 옮기고 나면 Part IV와 Part V 전체가 한꺼번에 열린다.

## 2. 아이디어

그래프의 정의는 두 줄이다. **정점의 집합 $V$와, 정점 쌍의 집합 $E$.** 끝이다. 나머지는 전부 표현의 문제다.

위의 세 입력을 이 두 줄에 맞춰 본다.

| 문제 | 정점 하나가 뜻하는 것 | 간선 하나가 뜻하는 것 |
|---|---|---|
| 격자 미로 | 칸 $(r, c)$ 하나 | 상하좌우로 한 칸 이동 |
| 컴퓨터 연결 | 컴퓨터 한 대 | 케이블 한 줄 |
| 물통 | 세 통의 물 양 $(a, b, c)$ 조합 하나 | 한 번의 부어붓기 |

세 번째 줄이 이 표의 핵심이다. **정점은 물리적으로 존재하는 것이 아니어도 된다.** "물 양의 조합"처럼 계산으로만 존재하는 것도 정점이 된다. 이렇게 만든 그래프를 **상태공간 그래프**라 부르고, 게임의 한 국면, 퍼즐의 한 배치, 기계의 한 모드가 전부 여기 해당한다.

정점을 정하고 나면 남는 질문은 하나다. **"어떤 정점의 이웃을 어떻게 알아내는가."** 방법이 셋 있다.

### 2.1 인접 행렬

$V \times V$ 크기의 표를 만들고 `mat[u][v]`에 간선의 유무를 적는다.

```text nolines
    0 --- 1                0 1 2 3 4 5         adj[0] = 1 2
    |     |            0 [ 0 1 1 0 0 0 ]       adj[1] = 0 3
    2 --- 3 --- 4      1 [ 1 0 0 1 0 0 ]       adj[2] = 0 3
                |      2 [ 1 0 0 1 0 0 ]       adj[3] = 1 2 4
                5      3 [ 0 1 1 0 1 0 ]       adj[4] = 3 5
                       4 [ 0 0 0 1 0 1 ]       adj[5] = 4
                       5 [ 0 0 0 0 1 0 ]
```

무방향 그래프라 표가 대각선 기준으로 대칭이다. 간선을 넣을 때 `mat[u][v]`와 `mat[v][u]` 양쪽에 찍어야 한다는 뜻이고, 한쪽만 찍는 것이 이 표현의 대표 실수다.

행렬이 잘하는 일은 하나다. **"$u$와 $v$가 붙어 있는가"에 $O(1)$로 답한다.** 못하는 일도 하나다. **$u$의 이웃을 전부 훑으려면 실제 이웃이 둘이어도 $V$칸을 다 읽어야 한다.**

### 2.2 인접 리스트

정점마다 이웃 번호만 모아 둔다. 위 그림 오른쪽의 `adj`가 그것이다.

이쪽은 반대다. 이웃 순회가 $O(\deg(u))$로 실제 이웃 수에 비례하고, 대신 "붙어 있는가" 질의에는 목록을 훑어야 해서 $O(\deg(u))$가 든다.

메모리도 갈린다. 행렬은 간선이 하나도 없어도 $V^2$칸을 잡는다. 리스트는 $V + 2E$개의 자리만 쓴다. 정점 $10^5$개에 간선 $2 \times 10^5$개인 흔한 제약에서 행렬은 $10^{10}$칸이라 **메모리에서 먼저 죽는다.**

::: perf
정점 2,000개, 간선 10,000개(평균 차수 10)인 무방향 그래프를 두 표현으로 들고 세 가지를 쟀다.

| | 인접 행렬 | 인접 리스트 | 배수 |
|---|---|---|---|
| 메모리 (Python) | 4.1 MB | 0.8 MB | 4.9배 |
| 메모리 (C++) | 4.05 MB | 0.16 MB | 25.7배 |
| 전체 이웃 순회 (Python) | 178.9 ms | 1.17 ms | **153배** |
| 전체 이웃 순회 (C++) | 1.83 ms | 0.023 ms | **79배** |
| 간선 질의 10만 회 (Python) | 17.4 ms | 25.0 ms | 리스트가 1.4배 손해 |
| 간선 질의 10만 회 (C++) | 0.51 ms | 2.34 ms | 리스트가 4.6배 손해 |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/graph_repr_cost.py` 와 `.cpp` 다.)

읽을 것은 배수의 방향이다. 순회에서는 리스트가 두 자릿수로 이기고, 질의에서는 행렬이 한 자릿수로 이긴다. **그리고 탐색 알고리즘이 하는 일은 거의 전부 순회다.** BFS도 DFS도 다익스트라도 "지금 정점의 이웃을 전부 본다"를 반복할 뿐 "이 둘이 붙어 있나"를 묻지 않는다. 기본값이 인접 리스트인 이유가 이것이다.

질의 쪽 배수가 작은 것도 근거가 있다. 평균 차수가 10이라 선형 탐색이 열 칸이면 끝난다. 차수가 커지면 이 격차는 벌어진다.
:::

행렬을 쓸 자리도 분명히 있다. **간선이 조밀하거나($E \approx V^2$), $V$가 수백 이하로 작거나, 입력이 애초에 행렬로 주어지거나, "붙어 있는가"를 반복해서 묻는 경우다.** 플로이드-워셜([V-3](#/v-3))은 세 조건을 동시에 만족해 행렬 말고 선택지가 없다.

### 2.3 암묵 그래프

세 번째 방법은 **아무것도 저장하지 않는 것**이다.

::: widget grid-search {"algos":["bfs"],"rows":14,"cols":14,"walls":"rooms","start":[1,1],"goal":[12,12],"weights":"uniform"}
:::

위젯은 벽이 있는 격자에서 BFS가 시작 칸부터 동심원처럼 번져 목표 칸에 닿는 장면을 한 스텝씩 보여 준다. 색이 진한 칸이 먼저 확장된 칸이고, 스텝을 밀면 원이 벽을 만나 문 쪽으로 새어 나가는 모습이 나온다.

여기서 볼 것은 탐색 순서가 아니다. **이 위젯은 간선 목록을 한 번도 만들지 않는다.** 정점 196개짜리 인접 리스트도 없다. 있는 것은 벽 배열 하나와 델타 배열 `DR = [-1, 1, 0, 0]`, `DC = [0, 0, -1, 1]` 두 줄뿐이고, 이웃은 필요할 때마다 `(r + DR[k], c + DC[k])`로 **계산해서** 만든다.

이런 그래프를 **암묵 그래프**라 한다. 정점 집합과 간선 집합이 메모리 어딘가에 놓여 있는 것이 아니라 **함수로 정의된다.**

```text nolines
    explicit    edge list  ->  adj[]  ->  for v in adj[u]        <- 미리 만든다
    implicit    rule       ->  f(u)   ->  for v in neighbors(u)  <- 그때 만든다
```

암묵 그래프가 반쪽짜리 요령이 아니라는 근거는 두 가지다.

**첫째, 만들 수 없는 경우가 흔하다.** 물통 문제의 정점은 $(a, b, c)$ 조합 전부이고, 세 통의 부피가 200이면 조합은 800만 개가 넘는다. [I-5](#/i-5)에서 다룬 숨바꼭질(백준 1697)의 정점은 좌표 0부터 100,000까지이고, 여기에 시간 축을 얹는 [V-8 시공간 A\*와 예약 테이블](#/v-8)의 정점은 (위치, 시각) 쌍 전부다. 이런 그래프는 미리 다 만들면 메모리가 먼저 터진다. **탐색이 실제로 닿는 부분만 만들어지는 것이 암묵 표현의 본질적인 이득이다.**

**둘째, 만들 필요가 없다.** $1000 \times 1000$ 격자를 인접 리스트로 옮기면 정점 100만 개에 간선 400만 개짜리 자료구조가 생기고, 그것을 만드는 데만 격자를 한 번 다 훑어야 한다. 델타 배열 두 줄이 그 전부를 대신한다.

::: tip
격자 문제에서 델타 배열은 관용구다. 대각선까지 여덟 방향이면 `DR = [-1,-1,-1,0,0,1,1,1]`, `DC = [-1,0,1,-1,1,-1,0,1]`이다. **네 방향과 여덟 방향을 지문에서 확인하지 않고 짜는 것이 격자 문제의 가장 흔한 오답 원인이다.** 좌표 변환과 회전은 [III-5 구현·시뮬레이션형](#/iii-5)에 있다.
:::

### 2.4 무엇을 정점으로 둘 것인가

암묵 그래프를 인정하고 나면 판별의 질문이 하나로 압축된다. **"이 문제에서 한 순간의 상태를 완전히 적으려면 무엇이 필요한가."** 그 답이 정점이다.

| 지문의 조건 | 정점에 들어가야 할 것 |
|---|---|
| 격자를 돌아다닌다 | `(r, c)` |
| 벽을 최대 $K$번 부술 수 있다 | `(r, c, 부순 횟수)` |
| 열쇠를 모아야 문이 열린다 | `(r, c, 가진 열쇠 비트마스크)` |
| 이동 수단이 둘이고 갈아탈 수 있다 | `(위치, 현재 수단)` |

**빠뜨리면 같은 칸을 다른 상태에서 다시 못 밟는다.** 벽을 한 번도 안 부수고 도착한 칸과 두 번 부수고 도착한 칸은 앞으로의 가능성이 다르므로 다른 정점이다. 이것을 `(r, c)` 하나로 뭉개면 먼저 도착한 쪽이 나중을 막아 오답이 난다. 상태가 모자라서 나는 실패의 일반형은 [VIII-11 DP 상태 정의 실패 사례집](#/viii-11)에 있고, 원인은 같다.

## 3. 손으로 따라가기

::: trace
아래 격자에서 **각 칸의 이웃 목록**을 델타 배열로 뽑아 채워라. `#`은 벽이고 벽 칸으로는 갈 수 없다. 이웃을 보는 순서는 위·아래·왼쪽·오른쪽 순으로 고정한다.

```text nolines
        c=0  c=1  c=2  c=3
   r=0   .    .    .    #
   r=1   .    #    .    .
   r=2   .    .    .    .
```

| 칸 | 위 | 아래 | 왼쪽 | 오른쪽 | 이웃 목록 | 차수 |
|---|---|---|---|---|---|---|
| (0,0) | 범위 밖 | (1,0) | 범위 밖 | (0,1) | (1,0) (0,1) | 2 |
| (1,0) | (0,0) | (2,0) | 범위 밖 | 벽 | (0,0) (2,0) | 2 |
| (1,2) |  |  |  |  |  |  |
| (2,3) |  |  |  |  |  |  |
| (0,3) |  |  |  |  |  |  |

세 가지를 확인하라.

- [ ] 벽 칸 `(0,3)`도 이웃을 가지는가. 벽 칸을 정점으로 볼 것인가 아닌가
- [ ] 차수를 전부 더하면 얼마인가. 그 값과 간선 수는 어떤 관계인가
- [ ] 이 격자를 인접 리스트로 만들면 몇 칸이 필요한가
:::

::: answer
| 칸 | 위 | 아래 | 왼쪽 | 오른쪽 | 이웃 목록 | 차수 |
|---|---|---|---|---|---|---|
| (0,0) | 범위 밖 | (1,0) | 범위 밖 | (0,1) | (1,0) (0,1) | 2 |
| (1,0) | (0,0) | (2,0) | 범위 밖 | 벽 | (0,0) (2,0) | 2 |
| (1,2) | (0,2) | (2,2) | 벽 | (1,3) | (0,2) (2,2) (1,3) | 3 |
| (2,3) | (1,3) | 범위 밖 | (2,2) | 범위 밖 | (1,3) (2,2) | 2 |
| (0,3) | 범위 밖 | (1,3) | (0,2) | 범위 밖 | (1,3) (0,2) | 2 |

**첫 번째 질문이 이 표의 목적이다.** `(0,3)`은 벽인데도 이웃 계산은 멀쩡히 돌아간다. 이웃 함수는 "갈 수 있는 칸인가"만 보고 "지금 서 있는 칸이 벽인가"는 안 보기 때문이다. 실전에서는 벽 칸을 아예 정점으로 두지 않는다 — 탐색이 벽에서 출발할 일이 없으므로 시작 칸만 벽이 아니면 문제가 안 생기고, 그래서 이 누락은 조용히 지나간다. 다만 [IV-4](#/iv-4)의 다중 시작점 BFS처럼 **여러 칸을 한꺼번에 큐에 넣는 순간** 벽 칸이 섞여 들어가 오답이 된다.

두 번째. 벽이 아닌 칸 열 개의 차수를 전부 더하면 26이다. 무방향 그래프에서 **차수의 합은 항상 간선 수의 두 배**다. 간선 하나가 양 끝 정점의 차수를 각각 1씩 올리기 때문이고, 따라서 이 격자의 간선은 13개다. 손으로 세어도 가로 이음 7개, 세로 이음 6개로 13개다.

세 번째. 인접 리스트는 정점 12개(벽 포함)에 이웃 자리 26개, 합쳐 38칸이다. 인접 행렬이면 $12 \times 12 = 144$칸이다. **$3 \times 4$짜리 장난감 격자에서 이미 네 배 가까이 차이가 난다.** 격자가 $1000 \times 1000$이면 행렬은 $10^{12}$칸이고, 이 숫자가 격자 문제에서 인접 행렬을 아무도 쓰지 않는 이유다.
:::

## 4. 구현

세 표현을 한 번에 만들어 본다. 앞의 그림과 같은 정점 6개짜리 그래프, 그리고 손추적에 쓴 격자다.

::: dual
```python title="세 가지 그래프 표현"
V = 6
edges = [(0, 1), (0, 2), (1, 3), (2, 3), (3, 4), (4, 5)]

# (1) 인접 행렬 — V×V 표. 무방향이므로 양쪽에 찍는다
mat = [[0] * V for _ in range(V)]
for u, v in edges:
    mat[u][v] = 1
    mat[v][u] = 1

# (2) 인접 리스트 — 정점마다 이웃 번호만 모은다
adj = [[] for _ in range(V)]
for u, v in edges:
    adj[u].append(v)
    adj[v].append(u)

print("mat[3] =", " ".join(map(str, mat[3])))
print("adj[3] =", " ".join(map(str, adj[3])))
print("deg(3) =", sum(mat[3]), len(adj[3]))

# (3) 암묵 그래프 — 간선을 만들지 않고 이웃을 그때그때 계산한다
grid = ["...#", ".#..", "...."]
R, C = len(grid), len(grid[0])
DR = (-1, 1, 0, 0)          # 위 아래 왼쪽 오른쪽. 순서를 고정해 두면 손추적과 대조된다
DC = (0, 0, -1, 1)


def neighbors(r, c):
    for k in range(4):
        nr, nc = r + DR[k], c + DC[k]
        if 0 <= nr < R and 0 <= nc < C and grid[nr][nc] != "#":
            yield nr, nc


for r, c in ((1, 2), (2, 3), (0, 3)):
    got = " ".join(f"({a},{b})" for a, b in neighbors(r, c))
    print(f"neighbors({r},{c}) = {got}")
```
```cpp title="세 가지 그래프 표현"
#include <iostream>
#include <string>
#include <vector>
using namespace std;

const int V = 6;
const int DR[4] = {-1, 1, 0, 0};   // 위 아래 왼쪽 오른쪽. 순서를 고정해 두면 손추적과 대조된다
const int DC[4] = {0, 0, -1, 1};

vector<string> grid = {"...#", ".#..", "...."};
const int R = 3, C = 4;

// (3) 암묵 그래프 — 간선을 만들지 않고 이웃을 그때그때 계산한다
vector<pair<int, int>> neighbors(int r, int c) {
    vector<pair<int, int>> out;
    for (int k = 0; k < 4; k++) {
        int nr = r + DR[k], nc = c + DC[k];
        if (0 <= nr && nr < R && 0 <= nc && nc < C && grid[nr][nc] != '#')
            out.push_back({nr, nc});
    }
    return out;
}

int main() {
    vector<pair<int, int>> edges = {{0, 1}, {0, 2}, {1, 3}, {2, 3}, {3, 4}, {4, 5}};

    // (1) 인접 행렬 — V×V 표. 무방향이므로 양쪽에 찍는다
    vector<vector<int>> mat(V, vector<int>(V, 0));
    for (auto [u, v] : edges) {
        mat[u][v] = 1;
        mat[v][u] = 1;
    }

    // (2) 인접 리스트 — 정점마다 이웃 번호만 모은다
    vector<vector<int>> adj(V);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    cout << "mat[3] =";
    int deg_mat = 0;
    for (int v = 0; v < V; v++) { cout << " " << mat[3][v]; deg_mat += mat[3][v]; }
    cout << "\nadj[3] =";
    for (int v : adj[3]) cout << " " << v;
    cout << "\ndeg(3) = " << deg_mat << " " << adj[3].size() << "\n";

    for (auto [r, c] : vector<pair<int, int>>{{1, 2}, {2, 3}, {0, 3}}) {
        cout << "neighbors(" << r << "," << c << ") =";
        for (auto [a, b] : neighbors(r, c)) cout << " (" << a << "," << b << ")";
        cout << "\n";
    }
    return 0;
}
```
:::

두 언어의 출력은 한 글자도 다르지 않다.

```console
mat[3] = 0 1 1 0 1 0
adj[3] = 1 2 4
deg(3) = 3 3
neighbors(1,2) = (0,2) (2,2) (1,3)
neighbors(2,3) = (1,3) (2,2)
neighbors(0,3) = (1,3) (0,2)
```

**복잡도:** 표로 정리한다. $\deg(u)$는 정점 $u$의 이웃 수이고, 격자에서는 4로 묶여 있다.

| 연산 | 인접 행렬 | 인접 리스트 | 암묵 그래프 |
|---|---|---|---|
| 만드는 시간 | $O(V^2 + E)$ | $O(V + E)$ | $O(1)$ |
| 공간 | $O(V^2)$ | $O(V + E)$ | $O(1)$ |
| $u$의 이웃 순회 | $O(V)$ | $O(\deg(u))$ | $O(\deg(u))$ |
| $(u,v)$ 간선 질의 | $O(1)$ | $O(\deg(u))$ | $O(1)$ |
| 전체 탐색 1회 | $O(V^2)$ | $O(V + E)$ | $O(V + E)$ |

근거는 마지막 줄에 다 있다. 탐색은 모든 정점을 한 번씩 꺼내고 꺼낼 때마다 그 이웃을 전부 본다. 이웃 순회 비용이 리스트에서는 $\deg(u)$이고 이것을 모든 정점에 대해 더하면 차수의 합, 즉 $2E$다. 행렬에서는 정점마다 $V$칸을 읽으므로 $V \cdot V$가 되고, **간선이 하나도 없어도 $V^2$을 낸다.** 공간도 같은 이유로 갈린다.

암묵 그래프의 "만드는 시간 $O(1)$"은 정말로 아무것도 안 만든다는 뜻이다. 대신 격자 배열 자체는 입력으로 이미 들고 있으므로 실제 메모리는 $O(V)$다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 2차원 배열 초기화 | `[[0] * V for _ in range(V)]`. **`[[0] * V] * V`는 같은 행을 V번 참조해 한 칸을 고치면 전 행이 바뀐다**([0-2](#/0-2)) | `vector<vector<int>>(V, vector<int>(V, 0))` — 각 행이 독립된 vector다 |
| 이웃 생성 | `yield`로 지연 생성. 이웃을 다 만들지 않고 하나씩 흘린다 | 값 반환이라 `vector` 하나를 매번 만든다. 성능이 중요하면 이웃을 콜백으로 받거나 루프를 인라인한다 |
| 인접 리스트 타입 | `list[list[int]]` — 원소마다 포인터 8바이트에 int 객체가 따로 붙는다 | `vector<vector<int>>` — 안쪽이 연속 메모리라 캐시에 유리하다([0-6](#/0-6)) |
| 간선 구조 분해 | `for u, v in edges` | `for (auto [u, v] : edges)` — C++17 구조적 바인딩 |

::: pitfall
- **무방향 그래프인데 한쪽만 넣는다.** `adj[u].append(v)`만 쓰고 `adj[v].append(u)`를 빠뜨리면 그래프가 조용히 방향 그래프가 된다. 예제는 통과하고 큰 입력에서만 답이 틀린다. **지문에 "양방향"이라는 단어가 있는지 먼저 확인하고, 있으면 두 줄을 붙여서 쓴다.**
- **정점 번호가 1부터인데 배열을 `V`칸만 잡는다.** 백준 문제의 정점은 대개 1번부터다. `V + 1`칸을 잡고 0번을 버리는 편이 인덱스를 옮기는 것보다 안전하다.
- **격자에 인접 행렬을 쓴다.** $1000 \times 1000$ 격자의 정점은 100만 개이고 행렬은 $10^{12}$칸이다. 격자는 예외 없이 암묵 그래프다.
- **차수의 합과 간선 수를 혼동한다.** 무방향에서 차수의 합은 $2E$다. 인접 리스트의 총 원소 수를 간선 수로 착각하면 복잡도 계산이 두 배 어긋난다.
- **중복 간선과 자기 루프를 안 걸러 낸다.** 지문이 금지하지 않으면 같은 쌍이 두 번 들어오거나 `(u, u)`가 들어온다. 인접 리스트는 그대로 받아들이고, 그 상태로 [IV-2](#/iv-2)의 무방향 사이클 검출을 돌리면 오탐이 난다.
:::

## 5. 어디에 쓰이는가

**패키지 매니저와 빌드 시스템의 뼈대가 인접 리스트다.** `package.json`의 `dependencies`, `Makefile`의 규칙, 컴파일 단위의 `#include` 관계는 전부 "정점 = 모듈, 간선 = 의존"인 방향 그래프다. 여기서 순환을 찾는 것이 [IV-2](#/iv-2)이고 빌드 순서를 정하는 것이 [IV-6 위상 정렬](#/iv-6)이다. 의존 그래프는 극단적으로 희소하다 — 모듈이 수만 개여도 한 모듈이 직접 의존하는 것은 열 개 안팎이라, 행렬을 쓰면 그 자리에서 메모리가 날아간다.

**대규모 그래프의 실제 저장 형식은 인접 리스트를 한 번 더 접은 CSR이다.** 인접 리스트를 "리스트의 리스트"로 들면 정점마다 별도 할당이 생겨 이웃을 훑을 때마다 다른 메모리 영역으로 점프한다. 도로망이나 소셜 그래프처럼 정점이 수억 개인 경우 이 포인터 추적이 지배적인 비용이 된다. 이웃을 전부 한 배열에 이어 붙이고 시작 위치만 따로 들고 다니는 표현이 CSR이고, [XI-10 그래프의 메모리 표현](#/xi-10)에서 다룬다. **표현을 바꾸는 것만으로 같은 알고리즘이 몇 배 빨라지는 지점이다.**

**상태공간 그래프는 제어 소프트웨어의 검증 도구다.** 기계의 모드, 통신 세션의 단계, 주문의 처리 상태를 정점으로 두고 전이를 간선으로 두면, "도달 불가능한 상태가 있는가", "여기서 초기 상태로 돌아올 수 있는가"가 전부 그래프 탐색 질문이 된다. 상태 기계를 코드로 짜는 방법은 [XI-6 상태 기계](#/xi-6)와 [XII-8 State](#/xii-8)에 있고, 그 상태 기계를 **그래프로 보고 검사하는 것**이 이 챕터의 관점이다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "연결되어 있다", "인접한", "~에서 ~로 갈 수 있다", "상하좌우로 이동", "A는 B 다음에", "최소 몇 번 만에", "몇 개의 덩어리"
- 제약조건: 정점 $V \le 10^5$, 간선 $E \le 2 \times 10^5$면 인접 리스트로 $O(V+E)$가 표준이다. $V \le 400$이고 모든 쌍을 묻거나 입력이 행렬로 주어지면 인접 행렬. 격자 $N, M \le 1000$이면 정점 $10^6$이라 암묵 그래프 말고 선택지가 없다
- 혼동 주의: 정점이 명시적으로 주어지지 않는데 상태 조합이 정점인 문제를 완전탐색으로 오해하기 쉽다. 상태가 유한하고 전이가 상수 개면 그래프 탐색이다([IV-3](#/iv-3)). 상태에 순서가 있어 계산 순서를 말할 수 있으면 DP다([VIII-1](#/viii-1))
- 반례 함정: 상태에 넣어야 할 요소를 빠뜨리는 것. 벽을 $K$번 부술 수 있으면 정점은 `(r, c, 부순 횟수)`이지 `(r, c)`가 아니다. `(r, c)`로 뭉개면 먼저 도착한 경로가 나중 경로를 막아 오답이 난다
:::

## 연습

::: quiz
전부 **표현을 정하는 것이 절반인** 문제다. 코드를 짜기 전에 "정점 하나가 무엇인가"를 한 문장으로 적어라.

**1. 백준 1260 DFS와 BFS (실버 2)** — https://www.acmicpc.net/problem/1260
- 신호: 간선 목록이 주어지고 "정점 번호가 작은 것을 먼저 방문"한다. $N \le 1000$, $M \le 10{,}000$.
- 상태: 정점 번호 하나. 그래프가 입력에 그대로 있어 번역이 필요 없다.
- 자료구조: 인접 리스트 + 각 목록 정렬. 번호 순 방문 조건이 곧 **인접 리스트를 정렬하라**는 지시다. $N \le 1000$이라 행렬도 통과하지만, 행렬을 쓰면 정렬이 필요 없는 대신 순회가 $O(V)$가 된다. 두 선택의 차이를 직접 재 보라.

**2. 백준 11403 경로 찾기 (실버 1)** — https://www.acmicpc.net/problem/11403
- 신호: 입력이 **인접 행렬 그 자체**로 주어지고 출력도 인접 행렬이다. $N \le 100$.
- 상태: `(i, j)` 쌍마다 "길이가 양수인 경로가 있는가".
- 자료구조: 인접 행렬. $N \le 100$이므로 $N^2 = 10^4$칸이고 모든 쌍을 묻는다 — §2.1이 말한 행렬의 세 조건이 전부 겹친다. 정점마다 탐색을 한 번씩 돌려도 되고 [V-3 플로이드-워셜](#/v-3)로 세 겹 루프를 돌려도 된다. 두 방법의 복잡도가 같은 이유를 설명할 수 있어야 한다.

**3. 백준 1325 효율적인 해킹 (실버 1)** — https://www.acmicpc.net/problem/1325
- 신호: "A가 B를 신뢰하면 B를 해킹하면 A도 해킹할 수 있다"는 **방향** 관계. $N \le 10{,}000$, $M \le 100{,}000$.
- 상태: 컴퓨터 번호 하나. 간선의 방향을 어느 쪽으로 저장할지가 문제의 전부다.
- 자료구조: 인접 리스트. $N^2 = 10^8$이라 행렬은 메모리에서 탈락한다. 여기서 확인할 것은 **간선을 신뢰 방향으로 넣을지 반대로 넣을지**다. 방향을 잘못 잡으면 코드는 멀쩡히 돌고 답만 틀린다.

**4. 백준 16928 뱀과 사다리 게임 (골드 5)** — https://www.acmicpc.net/problem/16928
- 신호: 칸 100개짜리 판, 주사위를 굴린 횟수의 최솟값. 간선 목록이 어디에도 없다.
- 상태: 지금 서 있는 칸 번호 하나(1부터 100). 사다리와 뱀은 **정점이 아니라 이동 규칙**이다 — 칸 $x$에서 주사위 $k$를 굴리면 $x+k$로 가고, 거기에 사다리나 뱀이 있으면 즉시 끌려간다. 이 "즉시 끌려감"을 간선의 끝점에 접어 넣는 것이 이 문제의 번역이다.
- 자료구조: 암묵 그래프 + 크기 101짜리 거리 배열. 정점 하나의 이웃이 정확히 6개(주사위 눈)라는 사실이 이웃 함수를 두 줄로 만든다.

## 요약

- 그래프는 정점 집합과 간선 집합 두 줄이 전부다. 격자·의존 목록·상태 조합이 전부 여기에 들어간다.
- **인접 행렬**은 $O(V^2)$ 공간에 $O(1)$ 간선 질의, **인접 리스트**는 $O(V+E)$ 공간에 $O(\deg)$ 이웃 순회다. 탐색이 하는 일은 거의 전부 순회라 기본값은 리스트다.
- 실측에서 전체 이웃 순회는 리스트가 Python 153배, C++ 79배 빨랐고, 간선 질의는 반대로 행렬이 이겼다. **배수의 방향이 선택 기준이다.**
- **암묵 그래프**는 간선을 만들지 않고 이웃을 함수로 계산한다. 격자의 델타 배열이 그 예이고, 상태공간처럼 미리 다 만들 수 없는 그래프에서는 유일한 선택지다.
- 정점을 정하는 질문은 하나다. **"한 순간의 상태를 완전히 적으려면 무엇이 필요한가."** 요소를 빠뜨리면 먼저 도착한 경로가 나중 경로를 막는다.
- 무방향 그래프에서 차수의 합은 항상 $2E$다. 간선을 한쪽에만 넣는 실수는 예제를 통과하고 큰 입력에서만 드러난다.
- 실무에서는 대규모 그래프를 CSR로 접어 포인터 추적을 없앤다([XI-10](#/xi-10)). 표현을 바꾸는 것만으로 같은 알고리즘이 빨라진다.
