# IV-7 이분 그래프·사이클 판정

::: lead
"이 둘은 같이 둘 수 없다"는 제약 목록을 두 덩어리로 가를 수 있는가, 없다면 그 이유를 어떻게 짚어 주는가.
:::

## 1. 문제

야간 배치 작업 다섯 개를 워커 두 대에 나눠 돌리려 한다. 대부분은 아무 데서나 돌아도 되는데, 운영팀이 넘긴 목록에 이런 줄들이 있다.

> 작업 1과 작업 2는 같은 워커에서 돌면 안 된다. 같은 테이블을 잠근다.
> 작업 2와 작업 3도 안 된다. 작업 3과 작업 4, 작업 4와 작업 5, 작업 5와 작업 1도 안 된다.

**두 대로 되는가.** 손으로 해 보면 이렇다. 1을 A에 두면 2는 B, 3은 A, 4는 B, 5는 A다. 그런데 5와 1이 충돌하는데 둘 다 A에 있다. 처음에 1을 B에 뒀어도 전부 뒤집힐 뿐 같은 자리에서 막힌다.

여기서 필요한 답은 "안 됩니다" 한 줄이 아니다. 운영팀이 물을 다음 질문이 정해져 있다. **어떤 제약을 풀면 되느냐.** 답할 수 없으면 그 검사는 쓸모가 없다. 그러니 판정기는 실패할 때 **실패의 증거**를 함께 내놓아야 한다.

제약 두 개짜리 목록이 실패하는 일은 없다. 다섯 개가 되니 실패했다. 몇 개부터, 그리고 **어떤 모양일 때** 실패하는가.

## 2. 아이디어

작업을 정점으로, "같이 둘 수 없다"를 간선으로 두면 목록이 그래프가 된다. 워커 배정은 정점을 두 색으로 칠하는 일이고, 제약은 **간선의 양 끝이 다른 색이어야 한다**는 조건이다.

이렇게 두 색으로 칠할 수 있는 그래프를 **이분 그래프**라고 한다.

### 2.1 색은 선택이 아니라 강제다

시작점 하나의 색만 정하면 나머지는 전부 결정된다. 이웃은 반드시 반대 색이고, 그 이웃의 이웃은 다시 원래 색이다. **고를 여지가 없으므로 탐색 한 번이면 끝난다.** BFS로 한 겹씩 번지면서 새로 만나는 정점에 `color[v] ^ 1`을 찍고, 이미 색이 있는 정점을 만나면 검사만 한다.

- 색이 다르다 → 제약 만족. 넘어간다.
- 색이 같다 → **모순.** 이 그래프는 이분이 아니다.

연결 요소가 여러 개면 각각 독립이다. 요소마다 아무 색으로 시작해도 되고, 한 요소의 선택이 다른 요소를 제약하지 않는다.

### 2.2 홀수 사이클이 유일한 장애물이다

실패하는 그래프의 정체는 무엇인가. 위의 다섯 작업은 5-사이클이었다. 4개짜리 사이클과 비교해 보면 답이 보인다.

```text nolines
   1 --- 2          1 --- 2
   |     |          |      \
   4 --- 3          5       3
                     \     /
                       - 4 -
```

왼쪽 4-사이클은 `A B A B`로 칠하고 끝난다. 오른쪽 5-사이클은 `A B A B A`까지 가서 마지막 A가 첫 A와 맞닿는다. 사이클을 한 바퀴 도는 동안 색은 매 간선마다 뒤집히고, 출발한 색으로 돌아오려면 **뒤집기가 짝수 번**이어야 한다.

**정리: 그래프가 이분이라는 것과 홀수 길이 사이클이 없다는 것은 같은 말이다.** 양쪽을 다 보인다.

**이분이면 홀수 사이클이 없다.** 사이클 위를 걸으면 간선 하나마다 색이 바뀐다. 출발점으로 돌아왔을 때 색이 원래대로여야 하니 간선 수가 짝수다. 그러므로 홀수 사이클은 존재할 수 없다.

**홀수 사이클이 없으면 이분이다.** 각 연결 요소에서 아무 정점을 시작점으로 잡고 BFS 거리 `dist`를 잰 뒤, 거리의 홀짝으로 색을 준다. 이 색칠이 조건을 어기는 경우가 있다고 하자. 즉 간선 `(u, v)`인데 `dist[u]`와 `dist[v]`의 홀짝이 같다. 그러면 시작점에서 `u`까지의 경로(길이 `dist[u]`), 간선 `(u, v)`, `v`에서 시작점까지의 경로(길이 `dist[v]`)를 이어 붙인 **닫힌 보행**의 길이가 `dist[u] + dist[v] + 1`이고 이것은 홀수다.

여기에 보조 사실 하나가 필요하다. ==홀수 길이의 닫힌 보행이 있으면 홀수 길이의 사이클이 반드시 있다.== 길이에 대한 귀납으로 보인다. 그 보행이 이미 단순 사이클이면 끝이다. 아니라면 어떤 정점을 두 번 지나므로 그 지점에서 잘라 더 짧은 닫힌 보행 둘로 나뉘고, 두 길이의 합이 홀수이니 둘 중 하나는 홀수다. 그것을 택해 반복하면 언젠가 단순한 홀수 사이클에 닿는다.

그러므로 색칠이 실패했다면 홀수 사이클이 있다. 대우를 취하면 홀수 사이클이 없을 때 색칠이 성공한다.

**이 증명이 §1의 요구를 그대로 채운다.** 실패한 자리에서 발견한 간선 `(u, v)`와 두 거리로부터 길이 `dist[u] + dist[v] + 1`인 홀수 닫힌 보행이 나오고, 그것이 실패의 원인이다. "제약이 너무 많습니다"가 아니라 **"1-2-3-4-5-1 이 다섯 개가 홀수 고리를 이룹니다. 이 중 하나를 풀면 됩니다"** 라고 답할 수 있다.

### 2.3 사이클이 있는지만 물을 때

홀짝을 따지지 않고 사이클의 유무만 묻는 경우도 흔하다. 방향이 있는지에 따라 방법이 갈린다.

**무방향 그래프.** 탐색 중에 이미 방문한 정점을 만났는데 그것이 **타고 내려온 부모가 아니면** 사이클이다. 부모를 되밟는 것은 방금 지나온 간선을 거꾸로 보는 것일 뿐이라 사이클이 아니다. 이 한 줄이 무방향 사이클 판정의 전부다. 뒤집어 말하면, 연결 그래프에서 사이클이 없다는 것은 간선이 정확히 $V - 1$개라는 것이고 그것이 트리의 정의다([IV-8 트리에서의 DFS](#/iv-8)).

**방향 그래프.** 부모 규칙이 통하지 않는다. `1→2, 1→3, 2→4, 3→4`는 4를 두 번 만나지만 사이클이 없다. 지금 재귀 스택 위에 있는 정점(GRAY)으로 가는 간선만이 사이클이고, 이미 끝난 정점(BLACK)으로 가는 간선은 아니다. 3색 판정은 [IV-6 위상 정렬](#/iv-6)에서 이미 다뤘고, Kahn의 길이 비교도 같은 답을 준다.

## 3. 손으로 따라가기

::: trace
정점 5개, 간선은 `1-2  2-3  3-4  4-5  5-1` — §1의 다섯 작업이다.

인접 리스트는 간선을 넣은 순서대로 쌓인다. `adj[1] = [2, 5]`, `adj[2] = [1, 3]`, `adj[3] = [2, 4]`, `adj[4] = [3, 5]`, `adj[5] = [4, 1]`.

1에서 BFS를 시작하며 `color[1] = 0`, `dist[1] = 0`. 새로 만나는 정점은 `color[v] ^ 1`로 칠하고 큐 뒤에 넣는다. 이미 색이 있으면 검사만 한다.

| 스텝 | 꺼낸 v | color[1..5] | dist[1..5] | 큐 | 사건 |
|---|---|---|---|---|---|
| — | — | 0 · · · · | 0 · · · · | 1 | 시작점을 0으로 |
| 0 | 1 | 0 1 · · 1 | 0 1 · · 1 | 2 5 | 2와 5를 1로 칠했다 |
| 1 | 2 | 0 1 0 · 1 | 0 1 2 · 1 | 5 3 | 1은 색이 달라 통과, 3을 0으로 |
| 2 |  |  |  |  |  |
| 3 |  |  |  |  |  |

세 가지를 확인하라.

- [ ] 모순이 처음 드러나는 스텝은 언제이고 어느 간선에서인가
- [ ] 그때 `dist[u] + dist[v] + 1`은 얼마인가. 사이클 길이와 맞는가
- [ ] 간선 `5-1`을 지우면 표는 어디까지 가고 무엇으로 끝나는가
:::

::: answer
| 스텝 | 꺼낸 v | color[1..5] | dist[1..5] | 큐 | 사건 |
|---|---|---|---|---|---|
| — | — | 0 · · · · | 0 · · · · | 1 | 시작점을 0으로 |
| 0 | 1 | 0 1 · · 1 | 0 1 · · 1 | 2 5 | 2와 5를 1로 칠했다 |
| 1 | 2 | 0 1 0 · 1 | 0 1 2 · 1 | 5 3 | 1은 색이 달라 통과, 3을 0으로 |
| 2 | 5 | 0 1 0 0 1 | 0 1 2 2 1 | 3 4 | 4를 0으로, 1은 색이 달라 통과 |
| 3 | 3 | 0 1 0 0 1 | 0 1 2 2 1 | 4 | **간선 (3,4)에서 둘 다 0 — 모순** |

모순은 스텝 3의 간선 `3-4`에서 드러난다. 3은 1을 거쳐 2로 내려온 색이고 4는 5를 거쳐 내려온 색인데, **양쪽에서 내려온 길이가 둘 다 2**라 같은 색이 됐다.

`dist[3] + dist[4] + 1 = 2 + 2 + 1 = 5`. 사이클 `1-2-3-4-5-1`의 길이 5와 맞는다. 여기서 나온 것이 닫힌 보행의 길이이지 항상 최소 홀수 사이클의 길이는 아니라는 점은 짚어 둘 만하다 — 이 예에서는 우연히 일치한다.

간선 `5-1`을 지우면 그래프는 한 줄로 늘어선 경로가 된다. BFS는 `1 → 2, 5 → 3, 4` 순으로 색을 칠하고 모순 없이 끝난다. 색은 `0 1 0 1 0`이 아니라 `color = [0, 1, 0, 0, 1]` 그대로다 — 4는 5 쪽에서 칠해졌기 때문이다. 두 배정 모두 옳다. **이분 그래프의 색칠은 연결 요소마다 두 가지가 있고 둘 중 아무거나 답이다.**
:::

## 4. 구현

색칠과 거리를 같이 들고 다닌다. 거리는 색을 정하는 데 필요하지는 않지만(색만으로 판정된다) 실패했을 때 **홀수 보행의 길이를 보고하는 데** 쓴다.

::: dual
```python title="이분 판정 — 2-색칠과 홀수 보행 보고"
from collections import deque


def two_color(n, edges):
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    color = [-1] * (n + 1)          # -1 = 아직 색이 없다
    dist = [0] * (n + 1)            # 그 연결 요소의 시작점에서의 BFS 층
    for s in range(1, n + 1):
        if color[s] != -1:
            continue                # 이미 다른 요소를 칠하면서 처리됐다
        color[s] = 0
        q = deque([s])
        while q:
            v = q.popleft()
            for nx in adj[v]:
                if color[nx] == -1:
                    color[nx] = color[v] ^ 1    # 이웃은 반드시 반대 색
                    dist[nx] = dist[v] + 1
                    q.append(nx)
                elif color[nx] == color[v]:     # 같은 색끼리 간선 = 홀수 닫힌 보행
                    return None, (v, nx, dist[v] + dist[nx] + 1)
    return color, None


def report(tag, n, edges):
    color, bad = two_color(n, edges)
    if color is None:
        v, nx, length = bad
        print(f"{tag}: 이분 그래프 아님 — 간선 ({v},{nx}) 에서 홀수 길이 {length} 의 닫힌 보행")
    else:
        left = [v for v in range(1, n + 1) if color[v] == 0]
        right = [v for v in range(1, n + 1) if color[v] == 1]
        print(f"{tag}: 이분 그래프 — A={left} B={right}")


report("4-사이클", 4, [(1, 2), (2, 3), (3, 4), (4, 1)])
report("5-사이클", 5, [(1, 2), (2, 3), (3, 4), (4, 5), (5, 1)])
```
```cpp title="이분 판정 — 2-색칠과 홀수 보행 보고"
#include <iostream>
#include <queue>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

// 이분이면 color 를 채워 true, 아니면 bad 에 (v, nx, 닫힌 보행 길이) 를 담아 false
bool two_color(int n, const vector<pair<int, int>>& edges, vector<int>& color,
               tuple<int, int, int>& bad) {
    vector<vector<int>> adj(n + 1);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }
    color.assign(n + 1, -1);        // -1 = 아직 색이 없다
    vector<int> dist(n + 1, 0);     // 그 연결 요소의 시작점에서의 BFS 층
    for (int s = 1; s <= n; s++) {
        if (color[s] != -1) continue;   // 이미 다른 요소를 칠하면서 처리됐다
        color[s] = 0;
        queue<int> q;
        q.push(s);
        while (!q.empty()) {
            int v = q.front();
            q.pop();
            for (int nx : adj[v]) {
                if (color[nx] == -1) {
                    color[nx] = color[v] ^ 1;   // 이웃은 반드시 반대 색
                    dist[nx] = dist[v] + 1;
                    q.push(nx);
                } else if (color[nx] == color[v]) {   // 같은 색끼리 간선 = 홀수 닫힌 보행
                    bad = {v, nx, dist[v] + dist[nx] + 1};
                    return false;
                }
            }
        }
    }
    return true;
}

void report(const string& tag, int n, const vector<pair<int, int>>& edges) {
    vector<int> color;
    tuple<int, int, int> bad;
    if (!two_color(n, edges, color, bad)) {
        auto [v, nx, length] = bad;
        cout << tag << ": 이분 그래프 아님 — 간선 (" << v << "," << nx
             << ") 에서 홀수 길이 " << length << " 의 닫힌 보행\n";
        return;
    }
    string left, right;
    for (int v = 1; v <= n; v++) {
        string& side = color[v] == 0 ? left : right;
        if (!side.empty()) side += ", ";
        side += to_string(v);
    }
    cout << tag << ": 이분 그래프 — A=[" << left << "] B=[" << right << "]\n";
}

int main() {
    report("4-사이클", 4, {{1, 2}, {2, 3}, {3, 4}, {4, 1}});
    report("5-사이클", 5, {{1, 2}, {2, 3}, {3, 4}, {4, 5}, {5, 1}});
    return 0;
}
```

```console
4-사이클: 이분 그래프 — A=[1, 3] B=[2, 4]
5-사이클: 이분 그래프 아님 — 간선 (3,4) 에서 홀수 길이 5 의 닫힌 보행
```

**복잡도:** 시간 $O(V + E)$ — 정점마다 큐 삽입·꺼내기 각 1회이고, 각 간선은 양 끝에서 한 번씩 총 2회 검사된다. 공간 $O(V + E)$ — 인접 리스트가 $E$, 색·거리·큐가 $V$다. 그래프 탐색 한 번의 비용에 색 배열 하나가 더 붙었을 뿐이다.

**여기서 값싸다는 사실이 중요하다.** 정점을 $k$색으로 칠할 수 있는지 묻는 일반 문제는 $k \ge 3$부터 NP-완전이라 알려진 다항 시간 알고리즘이 없다. **2색만이 선형 시간에 풀린다.** 색이 하나 늘면 "이웃과 다르게"에 선택의 여지가 생기고, 그 순간 탐색 한 번으로 결정되던 문제가 탐색 공간 전체를 뒤지는 문제가 된다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 여러 값 반환 | 튜플로 그냥 돌려준다 | 참조 인자로 채우거나 `tuple`을 쓴다. 여기서는 `tuple<int,int,int>` |
| 튜플 분해 | `v, nx, length = bad` | `auto [v, nx, length] = bad` — C++17 구조적 바인딩 |
| 배타적 논리합 | `color[v] ^ 1` | 같다. 둘 다 정수 비트 연산 |
| "없음" 표현 | `None` | `bool` 반환 + 출력 인자. `optional<T>`가 더 정확하지만 코드가 길어진다 |

이제 홀짝을 묻지 않고 사이클의 유무만 판정하는 쪽이다. §2.3의 부모 규칙 하나로 끝난다.

::: dual
```python title="무방향 그래프 사이클 판정 — 부모만 제외한다"
def find_cycle_edge(n, edges):
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)
    parent = [0] * (n + 1)
    seen = [False] * (n + 1)
    for s in range(1, n + 1):
        if seen[s]:
            continue
        seen[s] = True
        stack = [s]
        while stack:
            v = stack.pop()
            for nx in adj[v]:
                if nx == parent[v]:     # 타고 내려온 간선을 되밟는 것은 사이클이 아니다
                    continue
                if seen[nx]:            # 트리 간선이 아닌 간선 = 사이클을 닫는 간선
                    return (v, nx)
                seen[nx] = True
                parent[nx] = v
                stack.append(nx)
    return None


def report(tag, n, edges):
    bad = find_cycle_edge(n, edges)
    if bad is None:
        print(f"{tag}: 사이클 없음 — 간선 {len(edges)}개, 정점 {n}개")
    else:
        print(f"{tag}: 사이클 있음 — 간선 {bad} 가 닫는다")


report("트리   ", 5, [(1, 2), (1, 3), (3, 4), (3, 5)])
report("트리+1 ", 5, [(1, 2), (1, 3), (3, 4), (3, 5), (2, 4)])
```
```cpp title="무방향 그래프 사이클 판정 — 부모만 제외한다"
#include <iostream>
#include <string>
#include <vector>
using namespace std;

// 사이클을 닫는 간선을 찾으면 true 와 함께 bad 에 담는다
bool find_cycle_edge(int n, const vector<pair<int, int>>& edges, pair<int, int>& bad) {
    vector<vector<int>> adj(n + 1);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }
    vector<int> parent(n + 1, 0);
    vector<bool> seen(n + 1, false);
    for (int s = 1; s <= n; s++) {
        if (seen[s]) continue;
        seen[s] = true;
        vector<int> stack = {s};
        while (!stack.empty()) {
            int v = stack.back();
            stack.pop_back();
            for (int nx : adj[v]) {
                if (nx == parent[v])    // 타고 내려온 간선을 되밟는 것은 사이클이 아니다
                    continue;
                if (seen[nx]) {         // 트리 간선이 아닌 간선 = 사이클을 닫는 간선
                    bad = {v, nx};
                    return true;
                }
                seen[nx] = true;
                parent[nx] = v;
                stack.push_back(nx);
            }
        }
    }
    return false;
}

void report(const string& tag, int n, const vector<pair<int, int>>& edges) {
    pair<int, int> bad;
    if (!find_cycle_edge(n, edges, bad))
        cout << tag << ": 사이클 없음 — 간선 " << edges.size() << "개, 정점 " << n << "개\n";
    else
        cout << tag << ": 사이클 있음 — 간선 (" << bad.first << ", " << bad.second
             << ") 가 닫는다\n";
}

int main() {
    report("트리   ", 5, {{1, 2}, {1, 3}, {3, 4}, {3, 5}});
    report("트리+1 ", 5, {{1, 2}, {1, 3}, {3, 4}, {3, 5}, {2, 4}});
    return 0;
}
```
:::

```console
트리   : 사이클 없음 — 간선 4개, 정점 5개
트리+1 : 사이클 있음 — 간선 (4, 2) 가 닫는다
```

**복잡도:** 시간 $O(V + E)$ — 정점은 스택에 한 번씩만 들어가고 각 간선은 양 끝에서 한 번씩 검사된다. 공간 $O(V + E)$ — 인접 리스트와 부모·방문 배열, 그리고 스택이다. 사이클이 있으면 **첫 번째 비트리 간선에서 즉시 반환**하므로 실제 수행은 훨씬 짧게 끝나는 경우가 많다.

::: pitfall
- **부모 대신 "직전에 꺼낸 정점"을 제외한다.** 스택에서 꺼낸 순서와 부모 관계는 다르다. 반드시 `parent[v]`를 배열로 들고 다녀라.
- **중복 간선을 부모 규칙이 삼킨다.** `1-2`가 두 번 들어온 입력은 길이 2짜리 사이클이지만, `nx == parent[v]`가 둘 다 걸러 버려 사이클 없음이 나온다. 중복 간선이 가능한 문제라면 부모 **정점**이 아니라 부모 **간선 번호**로 제외해야 한다.
- **방향 그래프에 부모 규칙을 쓴다.** 마름모에서 오진한다. 방향이 있으면 3색이다([IV-6](#/iv-6)).
- **연결 요소가 하나라고 가정한다.** 이분 판정과 사이클 판정 모두 바깥 루프로 모든 시작점을 훑어야 한다. 입력이 연결 그래프라는 보장은 지문에 명시될 때만 있다.
- **`color`를 `bool`로 잡는다.** "안 칠함"과 "0번 색"을 구분할 자리가 없어진다. `-1`을 쓰거나 별도 `visited`를 둬라.
:::

## 5. 어디에 쓰이는가

**§1의 워커 배정이 실무 그대로다.** "이 두 작업은 같은 노드에서 돌면 안 된다"는 반친화(anti-affinity) 제약을 두 노드에 배치하는 문제가 정확히 2-색칠이고, 실패했을 때 "이 홀수 고리가 원인"이라고 짚어 주는 것이 §2.2의 결과다. 노드가 셋 이상이면 문제는 $k$-색칠이 되어 성질이 완전히 달라진다 — 두 대일 때만 값이 싸다.

**이분 그래프는 매칭의 전제 조건이다.** 작업을 기계에 배정하고, 지원자를 자리에 배정하고, 로봇을 목적지에 배정하는 문제는 "왼쪽 집합과 오른쪽 집합이 있고 가능한 짝만 간선"인 구조에서 최대 매칭을 구하는 문제가 된다. 그 알고리즘은 [IX-8 네트워크 플로우 입문](#/ix-8)에 있고, 거기서 다루는 헝가리안 매칭은 **입력이 이분 그래프임을 전제한다.** 데이터가 정말 이분인지 확인하는 것이 이 절의 코드다. 비용까지 최소화하는 할당 문제는 [V-11 할당 문제](#/v-11)로 이어진다.

**무방향 사이클 판정은 신장 트리 검증이다.** 간선을 하나씩 추가하면서 "이 간선이 사이클을 만드는가"를 물어 만들면 버리는 것이 크루스칼 알고리즘의 뼈대이고([IX-4 최소 신장 트리](#/ix-4)), 그 판정은 매번 DFS를 도는 대신 유니온 파인드로 $O(\alpha)$에 한다([IX-1 유니온 파인드](#/ix-1)). **간선이 정적으로 다 주어지면 이 절의 DFS가 맞고, 하나씩 추가되며 매번 물으면 유니온 파인드가 맞다.** 갈림점은 질의가 한 번인가 여러 번인가다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "두 그룹으로 나눌 수 있는가", "서로 인접한 것끼리는 다른 편", "같은 편이 될 수 없다", "이분 그래프인지 판별", "사이클이 존재하는가", "처음으로 사이클이 만들어지는 시점"
- 제약조건: 간선이 "함께 둘 수 없다" 또는 "서로 다르다"를 뜻하고, 나눌 그룹이 **정확히 둘**이다. 정점 $V \le 10^5$, 간선 $E \le 2 \times 10^5$ 정도면 $O(V+E)$로 여유롭다. 그룹이 셋 이상이면 이 유형이 아니다
- 혼동 주의: 방향이 있는 사이클이면 [IV-6 위상 정렬](#/iv-6)의 3색 또는 Kahn이다. 간선이 하나씩 추가되며 매번 사이클을 물으면 [IX-1 유니온 파인드](#/ix-1)다. 이분임을 확인한 다음 짝을 최대로 맺으라고 하면 [IX-8 네트워크 플로우 입문](#/ix-8)이다
- 반례 함정: **연결 요소가 여러 개인 입력.** 시작점 하나에서만 BFS를 돌리면 나머지 요소를 통째로 놓치고 "이분 맞음"을 낸다. 그리고 **간선이 하나도 없는 그래프**는 이분이다 — 자명한 참을 거짓으로 처리하는 구현이 흔하다. 자기 자신으로 가는 간선이 하나라도 있으면 길이 1인 홀수 사이클이라 즉시 이분이 아니다
:::

::: interview
"이분 그래프인지 어떻게 판정합니까"는 그래프 질문의 단골이고, 이어지는 질문이 정해져 있다.

**"왜 BFS 한 번이면 됩니까. 되돌아가서 다시 칠할 일은 없습니까."**
시작점의 색을 정하는 순간 나머지가 전부 강제된다는 것이 답의 뼈대다. 선택지가 없으므로 백트래킹이 필요 없고, 그래서 $O(V+E)$다. 색이 셋이면 선택지가 생기고 문제가 NP-완전이 된다는 대비까지 붙이면 왜 2색만 특별한지가 설명된다.

**"이분이 아닌 그래프의 특징을 한마디로 말하면."**
홀수 길이 사이클이 있다는 것이다. 여기에 "사이클을 돌면 색이 간선마다 뒤집히므로 제자리로 오려면 짝수여야 한다"는 한 줄 근거를 붙인다.

**"이분이 아니라고 판정했을 때 사용자에게 무엇을 보여 주겠습니까."**
실무 감각을 보는 질문이다. 실패한 간선과 BFS 부모 포인터를 거슬러 올라가면 홀수 사이클을 정점 목록으로 복원할 수 있고, 그것이 "이 제약들 중 하나를 풀면 된다"는 실행 가능한 답이 된다고 답한다.
:::

::: quiz
**색이 강제된다는 사실과 부모만 제외한다는 사실, 두 가지만 확실히 하고 들어가라.**

**1. 백준 1707 이분 그래프 (골드 4)** — https://www.acmicpc.net/problem/1707
- 신호: 지문이 이분 그래프의 정의를 그대로 주고 판별하라고 한다. 유형의 원형이다.
- 상태: `color` 배열 하나. `-1`은 안 칠함, `0`과 `1`이 두 편이다.
- 자료구조: 인접 리스트 + 큐. 테스트 케이스가 여러 개라 매번 초기화해야 하고, **연결 요소가 여러 개일 수 있어** 바깥 루프가 필수다. 이 두 가지가 이 문제의 실제 난도다.

**2. 백준 9466 텀 프로젝트 (골드 3)** — https://www.acmicpc.net/problem/9466
- 신호: "각자 한 명씩만 고른다" — 정점마다 나가는 간선이 정확히 하나인 방향 그래프다. 팀은 사이클이고, 팀에 못 드는 학생은 사이클로 흘러 들어가기만 하는 꼬리다.
- 상태: 3색. 지금 따라가는 경로 위에서 같은 정점을 다시 만나면 거기서부터가 사이클이고, 이미 끝난 정점에 닿으면 이 경로 전체가 꼬리다.
- 자료구조: `choice[v]` 배열 하나면 인접 리스트가 필요 없다. 나가는 간선이 하나뿐이라 탐색이 한 줄로 진행되고, 그래서 재귀 깊이가 정점 수까지 간다 — 반복으로 짜는 편이 안전하다.

**3. 백준 20040 사이클 게임 (골드 4)** — https://www.acmicpc.net/problem/20040
- 신호: 간선이 **한 번에 하나씩** 추가되고 그때마다 "지금 사이클이 생겼는가"를 묻는다. 정적 판정이 아니라 동적 질의다.
- 상태: 각 정점이 속한 집합의 대표. 새 간선의 두 끝이 이미 같은 집합이면 그 간선이 사이클을 닫는다.
- 자료구조: 매 질의마다 DFS를 돌리면 $O(m(V+E))$라 터진다. 유니온 파인드로 질의당 거의 상수에 답한다([IX-1](#/ix-1)). **같은 판정을 자료구조 하나가 대신하는 사례**로 풀어 보라.
:::

## 요약

- "같이 둘 수 없다"를 간선으로 두면 두 그룹 배정이 **2-색칠**이 된다. 이분 그래프 판정이 곧 배정 가능성 판정이다.
- 시작점의 색을 정하면 나머지는 **전부 강제된다.** 선택지가 없으므로 탐색 한 번, $O(V+E)$다.
- **이분 ⟺ 홀수 길이 사이클이 없음.** 사이클을 돌면 간선마다 색이 뒤집히므로 제자리로 오려면 짝수여야 한다. 역방향은 BFS 거리의 홀짝으로 칠하고, 어긋나는 간선이 홀수 닫힌 보행을 만들며, 홀수 닫힌 보행은 홀수 사이클을 품는다.
- 실패했을 때 간선 `(u,v)`와 `dist[u] + dist[v] + 1`이 **실패의 증거**다. "안 됩니다"가 아니라 "이 고리를 푸세요"로 답할 수 있다.
- 3색부터는 NP-완전이다. **선형 시간에 풀리는 것은 2색뿐이다.**
- 무방향 사이클 판정은 "이미 본 정점인데 부모가 아니면 사이클" 한 줄이다. 방향 그래프에는 통하지 않고 3색이 필요하다([IV-6](#/iv-6)).
- 간선이 하나씩 추가되며 매번 물으면 DFS가 아니라 유니온 파인드다([IX-1](#/ix-1)).
