# XV-8 일관성 해싱

::: lead
캐시 노드를 하나 늘렸을 뿐인데 캐시가 전부 비었다면, 문제는 노드가 아니라 나머지 연산이다.
:::

## 1. 문제

[II-6 해시](#/ii-6)에서 키 하나를 저장할 위치를 `해시값 % 용량`으로 정했다. 테이블 하나 안에서는 이 방식이 옳다 — 용량이 커지면 리해싱 한 번으로 전부 다시 넣으면 그만이고, 그 비용은 분할상환으로 흡수된다.

이제 테이블이 아니라 **서버**가 여러 대다. 캐시 서버 4대에 세션 데이터를 나눠 담고, 서버를 고르는 규칙이 `hash(session_id) % 4`다. 서버가 늘 때마다(트래픽이 늘어 5대로 증설할 때) `% 4`가 `% 5`로 바뀐다.

**나머지 연산은 분모가 바뀌면 답이 통째로 바뀐다.** 리해싱은 한 테이블 안에서 옮기는 비용이지만, 여기서는 "다시 계산된 나머지가 다른 서버를 가리킨다"는 것이 곧 **그 세션이 원래 없던 서버에 요청이 간다**는 뜻이다. 그 서버의 캐시에는 그 세션이 없으니 미스가 나고, 데이터베이스로 요청이 그대로 넘어간다. 서버 한 대를 늘렸는데 데이터베이스가 그 순간 폭주로 넘어가는 사고가 여기서 난다.

::: dual
```python title="단순 모듈로 — 재배치 비율 (조각)"
def naive_owner(key, n):
    """단순 모듈로 — 노드 수 n 이 바뀌면 나머지가 바뀌어 소유자가 통째로 흔들린다."""
    return h(key) % n
```
```cpp title="단순 모듈로 — 재배치 비율 (조각)"
// 단순 모듈로 — 노드 수 n 이 바뀌면 나머지가 바뀌어 소유자가 통째로 흔들린다.
int naive_owner(const string& key, int n) { return (int)(h(key) % n); }
```
:::

**복잡도:** $O(1)$ — 나눗셈 하나. 문제는 속도가 아니라 **안정성**이다. §4에서 이 코드를 그대로 돌려 재배치 비율을 잰다.

노드가 $n$대에서 $n+1$대로 늘 때, 단순 모듈로는 **키의 거의 전부**가 옮겨간다. 옮기지 않아도 되는 키(우연히 두 나머지가 같은 것)만 남는데 그 비율은 $1/(n+1)$ 근처다. 늘어야 할 서버가 하나뿐인데 대가가 전체 재구성인 것이 이 방식의 결함이다. **필요한 것은 노드 하나가 늘 때 딱 그 노드의 몫만큼만 옮기고 나머지는 그대로 두는 방법이다.**

## 2. 아이디어

### 2.1 나머지 연산 대신 원

해시값이 향하는 곳을 배열의 칸이 아니라 **원 위의 한 점**으로 바꾼다. 해시 함수의 출력 범위(예: 32비트 정수)를 원 하나로 접는다고 생각하면 된다. 노드도 자기 이름을 해시해서 원 위의 한 점에 놓는다. 키도 마찬가지로 원 위의 한 점에 놓인다.

**규칙은 하나다. 키는 자신의 위치에서 시계 방향으로 처음 만나는 노드가 담당한다.**

```text nolines
                    0
                    |
        D(555) *----+----* B(269)
                \         /
   C(650) *      (원)      * A(412)
                \         /
                 +---*---+
                    |
                 k1=489, k2=632 ...
```

노드가 하나 늘면(원 위에 점 하나가 새로 찍히면) **그 점과 시계 방향 이전 노드 사이의 호(arc)에 있던 키만** 새 노드에게 넘어간다. 그 호 바깥의 키는 자기보다 시계 방향으로 가까운 노드가 여전히 그대로이므로 안 움직인다. §1의 "전체가 흔들린다"는 문제가 여기서 "**호 하나만** 흔들린다"로 줄어든다.

이 성질을 §2.2에서 손으로 확인한다.

### 2.2 노드가 적으면 원이 고르지 않다

노드를 원 위에 딱 하나씩만 놓으면 문제가 남는다. 노드 넷을 무작위 해시로 찍으면 네 호의 길이가 우연에 좌우된다. 어떤 노드는 원의 60%를 담당하고 어떤 노드는 5%만 담당할 수 있다 — **부하가 노드 수가 아니라 운에 좌우된다.**

해법은 노드 하나를 **여러 점**으로 원에 찍는 것이다. `A#0`, `A#1`, ..., `A#99`처럼 가상의 이름을 해시해 A를 원 위에 100개 점으로 흩뿌린다. 노드 하나가 담당하는 호가 100조각으로 쪼개져 흩어지므로, **큰 수의 법칙**이 작동해 노드 간 총합이 고르게 수렴한다. 실측은 §4에 있다.

### 2.3 원을 안 쓰는 대안 — 랑데부 해싱

원과 정렬된 점 목록을 유지하는 대신, **키마다 모든 노드에 대해 점수를 매겨 최댓값을 고르는** 방법도 있다. `score(key, node) = hash(key + node)`를 모든 노드에 대해 계산하고 가장 큰 점수를 낸 노드가 담당한다(**랑데부 해싱**, Highest Random Weight). 노드 하나가 추가되면 그 노드의 점수만 새로 계산하면 되고, 다른 노드의 점수는 그대로다 — 그 키가 새 노드로 넘어가는지는 새 노드의 점수가 기존 최댓값을 이기는지로만 결정된다. 자료구조가 필요 없다는 것이 장점이고, 조회마다 노드 수만큼 해시를 계산해야 한다는 것이 대가다($O(n)$, 해시 링은 $O(\log n)$).

## 3. 손으로 따라가기

::: trace
노드 A, B, C를 해시 링(0~999로 접은 원)에 하나씩(가상 노드 없이) 놓는다. `hash(A)=412`, `hash(B)=269`, `hash(C)=650`. 키 여섯 개를 넣은 뒤 노드 D(`hash(D)=555`)를 추가한다.

규칙: 키는 자기 해시값에서 **시계 방향으로 처음 만나는 노드**가 담당한다(원의 끝을 넘으면 0으로 돌아가 가장 작은 노드부터 다시 본다).

| 키 | hash(키) | D 추가 전 담당 | D 추가 후 담당 | 이동? |
|---|---|---|---|---|
| k1 | 489 | C (650) | | |
| k2 | 632 | C (650) | | |
| k3 | 251 | B (269) | B (269) | 아니오 |
| k4 | 346 | A (412) | | |
| k5 | 965 | B (269, 원을 넘어 감) | | |
| k6 | 108 | B (269) | | |

세 가지를 채워라.

- [ ] D(555)가 새로 끼어드는 자리는 어느 두 노드 사이인가. 그 구간에 있던 키만 옮겨간다는 규칙을 적용하면 몇 개가 옮기는가
- [ ] k5=965는 어떤 노드보다도 해시값이 크다. 그런데 왜 B가 담당하는가
- [ ] 이동한 키의 이전 담당자와 D의 관계는 무엇인가 — "D 바로 다음 시계방향 노드"가 항상 이동분을 내주는 쪽이라는 규칙이 여기서도 성립하는가
:::

::: answer
| 키 | hash(키) | D 추가 전 담당 | D 추가 후 담당 | 이동? |
|---|---|---|---|---|
| k1 | 489 | C (650) | D (555) | **예** |
| k2 | 632 | C (650) | C (650) | 아니오 |
| k3 | 251 | B (269) | B (269) | 아니오 |
| k4 | 346 | A (412) | A (412) | 아니오 |
| k5 | 965 | B (269, 원을 넘어 감) | B (269, 원을 넘어 감) | 아니오 |
| k6 | 108 | B (269) | B (269) | 아니오 |

D(555)는 A(412)와 C(650) 사이에 끼어든다. 그 구간(412 초과 555 이하)에 있던 키는 k1(489) 하나뿐이고, **정확히 그 하나만 이동했다.**

k5=965는 A·B·C·D 전부보다 크지만, 원은 끝에서 다시 처음으로 이어진다. 965보다 큰 노드가 없으므로 **가장 작은 노드**(B=269)로 돌아간다. 원의 이 "감아 돌기"가 나머지 연산의 `% n`을 대신한다.

이동한 키 k1의 이전 담당자는 **C**였고, C는 D 바로 다음(시계 방향으로) 노드다. **새 노드는 언제나 자기 바로 다음 노드의 몫 일부를 가져오고, 다른 노드는 전혀 건드리지 않는다.** 이 성질이 단순 모듈로와의 차이 전부다.
:::

## 4. 구현

`Ring`은 정렬된 (해시, 노드) 목록 하나다. 삽입은 이진 탐색으로 자리를 찾아 끼워 넣고, 조회도 이진 탐색으로 "시계 방향으로 처음 만나는 점"을 찾는다.

::: dual
```python title="일관성 해싱 링 — 가상 노드와 재배치 비율"
import bisect

MASK = 0xFFFFFFFF


def fnv1a(data):
    h = 0x811C9DC5
    for b in data:
        h ^= b
        h = (h * 0x01000193) & MASK
    return h


def h(s):
    return fnv1a(s.encode())


def naive_owner(key, n):
    """단순 모듈로 — 노드 수 n 이 바뀌면 나머지가 바뀌어 소유자가 통째로 흔들린다."""
    return h(key) % n


class Ring:
    """해시 링 + 가상 노드. 각 물리 노드를 vnodes 개의 점으로 링에 흩뿌린다."""

    def __init__(self, nodes, vnodes):
        self.vnodes = vnodes
        self.points = []
        for node in nodes:
            self.add_node(node)

    def add_node(self, node):
        for i in range(self.vnodes):
            p = h("%s#%d" % (node, i))
            bisect.insort(self.points, (p, node))

    def owner(self, key):
        """키의 해시에서 시계 방향으로 처음 만나는 점의 노드."""
        p = h(key)
        idx = bisect.bisect_left(self.points, (p, ""))
        if idx == len(self.points):
            idx = 0
        return self.points[idx][1]


KEYS = ["session%d" % i for i in range(2000)]

naive4 = [naive_owner(k, 4) for k in KEYS]
naive5 = [naive_owner(k, 5) for k in KEYS]
moved_naive = sum(1 for a, b in zip(naive4, naive5) if a != b)

ring = Ring(["A", "B", "C", "D"], vnodes=100)
own4 = [ring.owner(k) for k in KEYS]
ring.add_node("E")
own5 = [ring.owner(k) for k in KEYS]
moved_ring = sum(1 for a, b in zip(own4, own5) if a != b)

print("키 %d개, 노드 4 -> 5" % len(KEYS))
print("  단순 모듈로   재배치 %d개 (%.1f%%)" % (moved_naive, 100 * moved_naive / len(KEYS)))
print("  일관성 해싱   재배치 %d개 (%.1f%%)  이론상 1/5 = %.1f%%" % (moved_ring, 100 * moved_ring / len(KEYS), 100 / 5))
```
```cpp title="일관성 해싱 링 — 가상 노드와 재배치 비율"
#include <algorithm>
#include <cstdint>
#include <cstdio>
#include <string>
#include <vector>
using namespace std;

const uint32_t MASK = 0xFFFFFFFFu;

uint32_t fnv1a(const string& data) {
    uint32_t h = 0x811C9DC5u;
    for (unsigned char b : data) {
        h ^= b;
        h = (h * 0x01000193u) & MASK;
    }
    return h;
}

uint32_t h(const string& s) { return fnv1a(s); }

// 단순 모듈로 — 노드 수 n 이 바뀌면 나머지가 바뀌어 소유자가 통째로 흔들린다.
int naive_owner(const string& key, int n) { return (int)(h(key) % n); }

// 해시 링 + 가상 노드. 각 물리 노드를 vnodes 개의 점으로 링에 흩뿌린다.
struct Ring {
    int vnodes;
    vector<pair<uint32_t, string>> points;

    Ring(const vector<string>& nodes, int vnodes_) : vnodes(vnodes_) {
        for (auto& node : nodes) add_node(node);
    }

    void add_node(const string& node) {
        for (int i = 0; i < vnodes; i++) {
            uint32_t p = h(node + "#" + to_string(i));
            auto it = lower_bound(points.begin(), points.end(), make_pair(p, node));
            points.insert(it, {p, node});
        }
    }

    // 키의 해시에서 시계 방향으로 처음 만나는 점의 노드.
    string owner(const string& key) {
        uint32_t p = h(key);
        auto it = lower_bound(points.begin(), points.end(), make_pair(p, string("")));
        if (it == points.end()) it = points.begin();
        return it->second;
    }
};

int main() {
    vector<string> KEYS;
    for (int i = 0; i < 2000; i++) KEYS.push_back("session" + to_string(i));

    vector<int> naive4, naive5;
    for (auto& k : KEYS) naive4.push_back(naive_owner(k, 4));
    for (auto& k : KEYS) naive5.push_back(naive_owner(k, 5));
    int moved_naive = 0;
    for (size_t i = 0; i < KEYS.size(); i++) if (naive4[i] != naive5[i]) moved_naive++;

    Ring ring({"A", "B", "C", "D"}, 100);
    vector<string> own4;
    for (auto& k : KEYS) own4.push_back(ring.owner(k));
    ring.add_node("E");
    vector<string> own5;
    for (auto& k : KEYS) own5.push_back(ring.owner(k));
    int moved_ring = 0;
    for (size_t i = 0; i < KEYS.size(); i++) if (own4[i] != own5[i]) moved_ring++;

    printf("키 %d개, 노드 4 -> 5\n", (int)KEYS.size());
    printf("  단순 모듈로   재배치 %d개 (%.1f%%)\n", moved_naive, 100.0 * moved_naive / KEYS.size());
    printf("  일관성 해싱   재배치 %d개 (%.1f%%)  이론상 1/5 = %.1f%%\n",
           moved_ring, 100.0 * moved_ring / KEYS.size(), 100.0 / 5);
    return 0;
}
```
:::

두 언어의 출력은 같다.

```console
키 2000개, 노드 4 -> 5
  단순 모듈로   재배치 1610개 (80.5%)
  일관성 해싱   재배치 399개 (19.9%)  이론상 1/5 = 20.0%
```

**복잡도:** `add_node`는 시간 $O(v \log(nv))$ — 가상 점 $v$개를 각각 정렬된 목록에 이진 탐색+삽입하며, 목록 길이가 $nv$다(삽입 자체는 배열이라 $O(nv)$이지만 지면의 구현은 단순함을 우선했다 — 실전에서는 균형 트리나 정렬된 배열의 일괄 재구성을 쓴다). `owner` 조회는 $O(\log(nv))$ — 이진 탐색 한 번. 단순 모듈로는 조회 $O(1)$이지만 노드 수가 바뀌는 순간 재배치가 $O(N)$이다($N$은 키 총량) — **일관성 해싱은 조회에서 로그를 얹는 대가로 재배치를 $O(N/n)$으로 줄인다.**

실측이 이론과 맞는다. 노드 4대에서 5대로 늘 때 단순 모듈로는 키의 **80.5%**가 재배치됐고, 일관성 해싱은 **19.9%**로 이론값 $1/5 = 20\%$에 거의 정확히 맞는다. **단순 모듈로가 옮기는 양의 4분의 1이다.**

| 언어 차이 | Python | C++ |
|---|---|---|
| 정렬된 목록 삽입 | `bisect.insort` — 이진 탐색 위치 찾기와 삽입이 한 호출 | `lower_bound` + `insert`를 따로 부른다. `vector::insert`는 뒤 원소를 전부 미는 $O(n)$이라 삽입이 잦으면 `std::set`이나 `std::map`이 낫다 |
| 튜플 비교 | `(hash, node)` 튜플은 첫 원소가 같으면 두 번째로 비교 | `pair<uint32_t, string>`도 동일하게 사전식 비교. `lower_bound`에 빈 문자열 `""`을 넣어 "이 해시값 이상 중 가장 작은 것"을 흉내낸다 |
| 해시 폭 | 임의 정밀도, `& MASK`는 의도 표시용 | `uint32_t` 곱셈이 자동으로 32비트에서 랩어라운드한다 |

::: pitfall
- **가상 노드 수를 너무 적게 잡는다.** §4.1의 실측처럼 물리 노드가 몇 대뿐이면 가상 점 하나로는 부하가 크게 치우친다. 실무에서는 노드당 수백 개를 쓴다.
- **노드 제거를 노드 추가의 역연산으로 안 짠다.** 추가는 점을 끼워 넣지만 제거는 그 노드의 가상 점을 **전부** 지워야 한다. 하나라도 남으면 이미 사라진 노드로 조회가 몰린다.
- **원의 감아 돌기를 빠뜨린다.** 가장 큰 해시값의 키는 원을 넘어 가장 작은 노드로 가야 한다(§3의 k5). 이진 탐색 결과가 끝을 넘으면 0번으로 되돌리는 코드가 없으면 그 구간의 키가 담당자를 못 찾는다.
- **랑데부 해싱과 헷갈려 링 없이 최댓값만 비교하면서 "일관성 해싱"이라 부른다.** 둘은 같은 문제(노드 변화 시 재배치 최소화)를 다른 자료구조로 푼다. §2.3의 차이를 구분해서 말할 수 있어야 한다.
:::

::: note
가상 노드 수를 늘릴수록 부하가 고르게 수렴하는 것은 별도로 실측했다(`tools/bench/xv8_vnode_stddev.py`, MD5 해시 — 본문 FNV-1a는 짧은 문자열에서 편향이 있어 이 추세를 보이는 데 적합하지 않다). 물리 노드 4대, 키 20,000개.

| 노드당 가상 점 | 노드별 키 개수 | 표준편차 | 평균 대비 |
|---|---|---|---|
| 1 | 633, 301, 8014, 11052 | 4,660 | 93% |
| 10 | 2438, 7958, 4390, 5214 | 1,983 | 40% |
| 50 | 5246, 4527, 5668, 4559 | 481 | 10% |
| 1,000 | 5235, 4936, 4744, 5085 | 182 | 4% |

가상 점 1개에서는 노드 하나가 11,052개(전체의 55%)를 떠안는다. 1,000개로 늘리면 네 노드가 4,744~5,235로 거의 같아진다. **가상 노드는 부하를 줄이는 장치가 아니라 운을 큰 수의 법칙으로 바꾸는 장치다.**
:::

## 5. 어디에 쓰이는가

**샤딩이 이 챕터의 원래 문제 그대로다.** 분산 캐시(Memcached 클라이언트 라이브러리의 일관성 해싱), 분산 데이터베이스의 파티셔닝(Cassandra·DynamoDB류)이 키를 노드에 배정하는 규칙으로 해시 링을 쓴다. [II-6](#/ii-6)에서 "테이블 하나 안에서 리해싱"으로 풀던 문제가, 테이블이 여러 대로 쪼개지는 순간 "노드가 늘 때 재배치를 최소화"라는 새 문제로 바뀐다 — **이 챕터는 II-6이 한 대를 넘어설 때 무엇이 달라지는가**에 대한 답이다.

**로드 밸런서가 세션 어피니티를 지킬 때도 같은 구조다.** 같은 사용자의 요청을 매번 같은 백엔드 서버로 보내야 하는데, 서버가 늘거나 죽을 때 대부분의 사용자가 같은 서버를 계속 쓸 수 있어야 한다. 서버 목록을 링에 놓고 사용자 ID를 키로 쓰면 §4의 재배치 비율이 그대로 적용된다.

**CDN이 오리진 서버를 고르는 데도 쓴다.** 캐시 안 된 콘텐츠를 요청받은 엣지 서버가 "이 URL은 어느 오리진이 담당인가"를 일관성 해싱으로 정하면, 오리진 서버가 늘어도 대부분의 URL이 같은 오리진을 계속 바라봐 캐시 적중률이 유지된다.

## 연습

::: quiz
**1. 세션 스토어를 4대에서 8대로 늘린다**
- 상황: 웹 서비스가 로그인 세션을 캐시 서버 4대에 `hash(session_id) % 4`로 분산해 두었다. 트래픽이 늘어 8대로 증설한다.
- 무엇이 병목이거나 깨지는가: 나머지 연산의 분모가 바뀌는 순간 세션의 대부분이 다른 서버를 가리킨다. 8대 전부가 동시에 캐시 미스를 겪고, 그 요청이 전부 인증 데이터베이스로 쏟아진다 — 증설이 오히려 장애를 만든다.
- 어떤 구조이고 무엇을 대가로 치르는가: 해시 링으로 바꾸면 새로 추가된 4대가 원래 4대의 몫에서 자기 구간만 나눠 가진다. 대가는 조회가 $O(1)$에서 $O(\log n)$으로 늘고, 클라이언트마다 같은 노드 목록을 정확히 공유해야 한다는 것이다 — 목록이 노드마다 다르면 같은 키가 서버마다 다른 담당자를 가리킨다.

**2. 파티션 4개짜리 메시지 큐를 파티션 16개로 다시 만든다**
- 상황: 메시지 큐가 파티션 4개로 시작했는데, 한 파티션에 부하가 몰려 파티션 수를 늘리려 한다. 파티션은 컨슈머 그룹의 병렬성 단위이기도 하다.
- 무엇이 병목이거나 깨지는가: 파티션은 "노드"가 아니라 **분할 단위**이지만 배정 규칙은 같은 나머지 연산이다. 파티션을 늘리면 거의 모든 메시지 키의 배정 파티션이 바뀌고, 순서 보장이 걸린 키(같은 파티션에서만 순서가 보장된다)의 순서 보장이 그 경계에서 깨진다.
- 어떤 구조이고 무엇을 대가로 치르는가: 일관성 해싱으로 파티션을 링에 놓으면 재배치되는 키가 최소화된다. 그런데 파티션 수 자체를 늘리는 것은 순서 보장을 요구하는 시스템에서는 애초에 신중해야 할 결정이다 — 일관성 해싱은 재배치량을 줄일 뿐, 순서가 재배정 순간에 흔들리는 근본 문제 자체를 없애지는 못한다.

**3. 정적 자산을 캐싱하는 CDN 엣지 서버 배치**
- 상황: CDN이 리전마다 엣지 서버를 두고, 캐시 안 된 요청은 정해진 규칙으로 오리진 서버 여러 대 중 하나로 보낸다. 오리진 서버가 장애로 하나 빠지는 일이 잦다.
- 무엇이 병목이거나 깨지는가: 나머지 연산으로 오리진을 고르면 서버 하나가 빠질 때마다 남은 서버 전체의 담당 URL이 재계산된다. 방금까지 캐시 적중률이 높던 오리진들도 전부 새 URL 집합을 받아 콜드 스타트를 겪는다.
- 어떤 구조이고 무엇을 대가로 치르는가: 해시 링에 오리진들을 가상 노드와 함께 놓으면 서버 하나가 빠져도 그 서버의 몫만 나머지 서버에 흩어져 넘어간다. 대가는 노드 목록의 정합성이다 — 엣지 서버마다 오리진 목록 갱신 시점이 다르면 같은 URL이 순간적으로 서로 다른 오리진을 가리킬 수 있다.
:::

## 요약

- 나머지 연산(`hash(key) % n`)은 $n$이 바뀌면 답이 통째로 바뀐다. 노드가 늘 때마다 재배치가 전체 규모다.
- 해시 링은 노드와 키를 모두 원 위의 점으로 놓고, 키는 시계 방향으로 처음 만나는 노드가 담당한다. 노드 하나가 늘면 **그 노드 바로 앞뒤 구간의 키만** 옮겨간다.
- 노드가 적으면 원이 고르지 않다. **가상 노드**로 각 물리 노드를 원 위 여러 점으로 흩뿌리면 큰 수의 법칙이 작동해 부하가 고르게 수렴한다.
- 실측: 노드 4→5대에서 단순 모듈로는 키의 **80.5%**가 재배치됐고 일관성 해싱은 **19.9%**(이론값 20%)였다. 가상 노드를 1개에서 1,000개로 늘리면 노드별 부하의 표준편차가 평균 대비 93%에서 4%로 줄었다.
- **랑데부 해싱**은 링 없이 키마다 모든 노드의 점수를 계산해 최댓값을 고른다. 조회가 $O(n)$인 대신 자료구조가 필요 없다.
- 이 챕터는 [II-6 해시](#/ii-6)의 분산판이다 — 테이블 하나에서 통하던 리해싱이 노드 여러 대로 쪼개지는 순간 통하지 않게 되고, 그 자리를 해시 링이 메운다.
