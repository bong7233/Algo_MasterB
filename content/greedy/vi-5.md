# VI-5 좌표 압축

::: lead
값이 10억까지 가는데 개수는 10만 개뿐일 때, 크기를 버리고 순서만 남기는 세 줄.
:::

## 1. 문제

접속 로그에 사용자 번호가 10만 개 찍혀 있다. 번호는 1부터 10억 사이의 아무 값이고, 물어야 하는 것은 "번호 X보다 작은 번호를 쓰는 사용자가 몇 명인가"다. 그것도 10만 번.

이 질문의 표준 도구는 **값을 인덱스로 쓰는 배열**이다. 번호 X를 만나면 `count[X] += 1`을 하고, 질의가 오면 `count[0..X-1]`의 합을 읽는다. [VI-4 누적 합과 차분 배열](#/vi-4)이 그 합을 상수 시간으로 만들어 준다. 문제는 배열의 크기다.

```text nolines
   count = [0] * 1_000_000_001        <- 10억 칸
```

Python의 정수 리스트는 칸마다 포인터 8바이트라 8GB, C++의 `int` 배열이어도 4GB다. **메모리 제한이 512MB인 채점기에서는 선언 자체가 불가능하고, 서버라도 이 배열은 캐시를 통째로 밀어 버린다.** 그런데 실제로 쓰이는 칸은 10만 개뿐이다. 나머지 99.99%는 0을 담고 있다.

여기서 한 가지를 알아채야 한다. **이 알고리즘은 번호의 크기를 쓰지 않는다.** 번호끼리 더하지도, 빼지도, 나누지도 않는다. 오직 "누가 더 작은가"만 묻는다. 크기가 아니라 순서만 쓰는데 크기만큼의 메모리를 내고 있는 것이다.

같은 상황이 격자 밖 좌표에서도 나온다. 세그먼트 트리로 구간을 관리하고 싶은데 좌표가 $\pm 10^9$이면 트리의 잎이 20억 개다. 트리를 세울 수가 없다. 그런데 실제로 등장하는 좌표는 구간 끝점 몇십만 개뿐이다.

## 2. 아이디어

### 2.1 무엇을 보존하고 무엇을 버리는가

좌표 압축은 값들을 **순서를 지키면서** 0, 1, 2, … 로 다시 매기는 일이다.

```text nolines
   원본   -100        5        5       42     1000000000
   순위      0        1        1        2              3
```

보존되는 것은 비교 결과뿐이다. `a < b`였으면 압축 후에도 `rank(a) < rank(b)`이고, 같았으면 같다. **버려지는 것은 값의 차이·합·비율 전부다.** `1000000000 - 42`는 압축 후 `3 - 2 = 1`이 되어 아무 뜻이 없다.

그래서 판정 기준이 하나로 정리된다. ==알고리즘이 값에서 비교만 쓰면 압축해도 되고, 산술을 쓰면 안 된다.== 등수 매기기·중복 세기·트리의 인덱스는 비교만 쓴다. 구간 길이·거리·합은 산술을 쓴다. 뒤쪽이 필요하면 압축 배열 `xs`를 함께 들고 다니며 필요할 때 원래 값을 되찾는다.

### 2.2 절차는 세 줄이다

1. **정렬한다.** 순서를 만든다.
2. **중복을 제거한다.** 같은 값은 같은 순위를 받아야 한다.
3. **각 값의 순위를 이분 탐색으로 찾는다.**

세 번째 줄이 이분 탐색인 이유는 `xs`가 이미 정렬되어 있기 때문이다. 값 `v`의 순위는 "`xs`에서 `v`가 들어갈 가장 왼쪽 자리"이고, 그것이 곧 `lower_bound`다.

📖 `bisect.bisect_left(xs, v)` — 정렬된 `xs`에서 `v` 이상인 첫 원소의 인덱스. $O(\log n)$.
   `xs`에 `v`가 있으면 그 위치를, 없으면 삽입될 자리를 준다. 중복이 있으면 **첫 번째** 위치다.
   쓰는 곳: 좌표 압축(이 절), LIS의 $O(n \log n)$ 판([VIII-6](#/viii-6)).
   C++ 대응: `std::lower_bound(xs.begin(), xs.end(), v)` — 반복자를 돌려주므로 `begin()`을 빼야 인덱스가 된다. 경계 의미는 [VII-2 lower_bound / upper_bound / bisect](#/vii-2)에 있다.

압축이 세 줄이라는 사실 자체가 말할 값어치가 있다. **이것은 자료구조가 아니라 전처리다.** 어려운 것은 압축이 아니라 "지금 압축해도 되는가"와 "무엇을 압축 대상으로 넣을 것인가"의 판단이고, 아래 두 절이 그 판단을 다룬다.

::: note
중복 제거를 할지 말지가 문제마다 갈린다. "자신보다 작은 **서로 다른** 값의 개수"를 물으면 중복을 제거한 순위가 답이다. "정렬했을 때 몇 번째인가"를 물으면 같은 값이 서로 다른 자리를 받아야 하므로 제거하지 않는다. 지문의 명사 하나가 결정한다.
:::

### 2.3 구간을 압축할 때 — 빈틈이 사라진다

값이 아니라 **구간의 끝점**을 압축하는 순간 함정이 생긴다. 정수 칸 위의 닫힌 구간 두 쌍을 보자.

| 입력 | 실제 덩어리 수 | 끝점만 모아 압축하면 |
|---|---|---|
| `[1,2] [3,4]` | 1 (칸 1,2,3,4가 이어진다) | 좌표 {1,2,3,4} → 순위 {0,1,2,3} |
| `[1,2] [4,5]` | 2 (칸 3이 비어 있다) | 좌표 {1,2,4,5} → 순위 {0,1,2,3} |

**두 입력이 압축 후 완전히 같아졌다.** 첫 줄의 답은 1이고 둘째 줄의 답은 2인데, 압축된 좌표만 보고는 둘을 구별할 방법이 없다. 어떤 알고리즘을 얹어도 한쪽은 틀린다.

원인은 명확하다. 압축은 **등장한 좌표만** 남긴다. `[1,2]`와 `[4,5]` 사이의 칸 3은 아무 구간의 끝점도 아니라 목록에서 빠지고, 빠지는 순간 "2와 4 사이에 빈틈이 있다"는 정보가 사라진다. 압축 좌표에서는 2와 4가 이웃한 두 순위가 되어 맞닿은 것처럼 보인다.

해법은 **구간을 반열림으로 바꾸고 `r+1`을 좌표 목록에 함께 넣는 것**이다. 닫힌 구간 `[l, r]`은 반열림 `[l, r+1)`과 같다.

```text nolines
   [1,2] [3,4]  ->  [1,3) [3,5)  ->  xs = 1 3 5      <- 3 이 공유되어 맞닿는다
   [1,2] [4,5]  ->  [1,3) [4,6)  ->  xs = 1 3 4 6    <- 3 과 4 사이에 빈 슬롯이 생긴다
```

`xs`가 만드는 것은 점이 아니라 **슬롯**이다. 슬롯 `i`는 원좌표 구간 `[xs[i], xs[i+1])`을 통째로 대표하고, 그 슬롯 안에서는 모든 칸이 똑같이 덮이거나 똑같이 비어 있다. 끝점을 전부 넣었으므로 그 성질이 보장된다.

여기서 두 번째 규칙이 따라온다. ==슬롯의 길이는 압축 좌표가 아니라 원좌표로 잰다.== 슬롯 하나가 원좌표 1칸일 수도 있고 100만 칸일 수도 있다. 길이는 `xs[i+1] - xs[i]`다. 순위 차 `1`을 길이로 쓰는 순간 답이 무너진다.

### 2.4 압축하면 안 되는 자리

- **값끼리 더하거나 빼는 곳.** 구간 합, 거리, 넓이가 전부 여기 해당한다. 순위 차이는 값의 차이가 아니다.
- **값 자체를 출력해야 하는 곳.** 이때는 `xs[rank]`로 되돌린다. `xs`를 버리면 복원이 불가능하다.
- **값의 절대적 의미가 판정에 쓰이는 곳.** "좌표가 0 이상인가", "값이 K의 배수인가"는 압축이 파괴한다.

## 3. 손으로 따라가기

::: trace
정수 칸 위에 닫힌 구간 세 개가 있다.

`A = [1, 2]`, `B = [4, 5]`, `C = [2, 3]`

반열림으로 바꾸면 `A = [1,3)`, `B = [4,6)`, `C = [2,4)`다. 끝점 집합은 `{1, 3, 4, 6, 2, 4}`이고, 정렬·중복 제거하면 `xs = [1, 2, 3, 4, 6]`이다. 슬롯 `i`는 `[xs[i], xs[i+1])`을 뜻한다.

| 슬롯 i | 원좌표 구간 | 길이 | 덮는 구간 | 덮임? | 누적 칸 수 |
|---|---|---|---|---|---|
| 0 | [1, 2) | 1 | A | 예 | 1 |
| 1 | [2, 3) | 1 | A, C | 예 | 2 |
| 2 | | | | | |
| 3 | | | | | |

세 가지를 확인하라.

- [ ] 슬롯 3의 **길이가 1이 아니다.** 얼마이고 왜 그런가
- [ ] 칠해진 칸의 총합은 얼마인가. 구간을 직접 칠한 결과와 같은가
- [ ] 덩어리는 몇 개인가. `xs`에 `r+1`을 넣지 않았다면 이 답이 어떻게 달라지겠는가
:::

::: answer
| 슬롯 i | 원좌표 구간 | 길이 | 덮는 구간 | 덮임? | 누적 칸 수 |
|---|---|---|---|---|---|
| 0 | [1, 2) | 1 | A | 예 | 1 |
| 1 | [2, 3) | 1 | A, C | 예 | 2 |
| 2 | [3, 4) | 1 | C | 예 | 3 |
| 3 | [4, 6) | 2 | B | 예 | 5 |

슬롯 3의 길이는 **2**다. `xs`에 5가 없기 때문이다 — 5는 어느 구간의 시작도 아니고 어느 구간의 `r+1`도 아니다(B의 `r+1`은 6이다). 그래서 원좌표 4와 5가 한 슬롯에 묶였고, 그 안에서는 둘 다 B에 덮이므로 묶어도 답이 안 변한다. **압축 좌표에서는 슬롯 하나지만 원좌표에서는 두 칸이다.**

칠해진 칸은 `1 + 1 + 1 + 2 = 5`. 직접 칠하면 `{1,2,3} ∪ {4,5} ∪ {2,3} = {1,2,3,4,5}`로 다섯 칸이다. 같다.

덩어리는 **1개**다. 네 슬롯이 전부 덮였고 서로 이어져 있어 원좌표 1부터 5까지가 한 덩어리다.

마지막 질문이 이 챕터의 요점이다. `r+1`을 넣지 않았다면 `xs = [1, 2, 3, 4, 5]`가 되고 슬롯은 `[1,2) [2,3) [3,4) [4,5)`가 된다. B의 오른쪽 끝인 칸 5를 담을 슬롯이 아예 없어져 칠해진 칸이 4로 계산된다. ==구간의 오른쪽 끝은 좌표 목록에 `r`이 아니라 `r+1`로 들어가야 한다.== 닫힌 구간을 반열림으로 바꾸는 절차가 그 규칙을 자동으로 만들어 준다.
:::

## 4. 구현

압축 자체는 세 줄이다.

::: dual
```python title="좌표 압축 — 정렬, 중복 제거, 순위"
import bisect


def compress(values):
    xs = sorted(set(values))                              # 정렬 + 중복 제거
    ranks = [bisect.bisect_left(xs, v) for v in values]   # 값 -> 순위
    return xs, ranks


vals = [1000000000, 5, 5, -100, 42]
xs, ranks = compress(vals)
print("vals  =", vals)
print("xs    =", xs)
print("ranks =", ranks)
print("복원  =", [xs[r] for r in ranks])                  # xs 가 역변환표다
```
```cpp title="좌표 압축 — 정렬, 중복 제거, 순위"
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

pair<vector<long long>, vector<int>> compress(const vector<long long>& values) {
    vector<long long> xs = values;
    sort(xs.begin(), xs.end());                           // 정렬
    xs.erase(unique(xs.begin(), xs.end()), xs.end());     // 중복 제거 (unique 는 지우지 않는다)
    vector<int> ranks;
    for (long long v : values)                            // 값 -> 순위
        ranks.push_back(lower_bound(xs.begin(), xs.end(), v) - xs.begin());
    return {xs, ranks};
}

template <class T>
void show(const string& label, const vector<T>& v) {
    cout << label << " [";
    for (size_t i = 0; i < v.size(); i++) cout << (i ? ", " : "") << v[i];
    cout << "]\n";
}

int main() {
    vector<long long> vals = {1000000000, 5, 5, -100, 42};
    auto [xs, ranks] = compress(vals);
    vector<long long> restored;
    for (int r : ranks) restored.push_back(xs[r]);        // xs 가 역변환표다
    show("vals  =", vals);
    show("xs    =", xs);
    show("ranks =", ranks);
    show("복원  =", restored);
    return 0;
}
```
:::

```console
vals  = [1000000000, 5, 5, -100, 42]
xs    = [-100, 5, 42, 1000000000]
ranks = [3, 1, 1, 0, 2]
복원  = [1000000000, 5, 5, -100, 42]
```

**복잡도:** 시간 $O(n \log n)$ — 정렬이 지배한다. 중복 제거는 정렬된 배열을 한 번 훑는 $O(n)$이고, 순위 조회는 값마다 이분 탐색이라 $O(n \log n)$이다. 공간 $O(n)$ — 서로 다른 값의 수만큼의 배열 하나. **상수는 정렬 쪽에 몰려 있다.** 값이 이미 정렬되어 들어오는 문제라면 정렬을 건너뛰어 $O(n)$이 된다.

이제 §2.3의 함정을 코드로 확인한다. 같은 두 입력에 세 가지 계산을 나란히 돌린다.

::: dual
```python title="구간을 압축할 때 — 끝점만 vs 끝점 + 1"
import bisect


def blocks_naive(segs, hi):                  # 대조용 — 칸을 직접 칠한다
    painted = [False] * (hi + 1)
    for l, r in segs:
        for x in range(l, r + 1):
            painted[x] = True
    return count_blocks(painted)


def count_blocks(cover):                     # 0 에서 1 로 바뀌는 횟수가 덩어리 수다
    blocks, prev = 0, 0
    for c in cover:
        if c and not prev:
            blocks += 1
        prev = c
    return blocks


def blocks_wrong(segs):                      # ❌ 끝점만 압축한다 — 빈틈이 사라진다
    xs = sorted({v for l, r in segs for v in (l, r)})
    cover = [0] * len(xs)
    for l, r in segs:
        for i in range(bisect.bisect_left(xs, l), bisect.bisect_left(xs, r) + 1):
            cover[i] = 1
    return count_blocks(cover)


def blocks_right(segs):                      # ✅ r+1 까지 넣고 반열림 슬롯으로 다룬다
    xs = sorted({v for l, r in segs for v in (l, r + 1)})
    cover = [0] * (len(xs) - 1)
    for l, r in segs:
        for i in range(bisect.bisect_left(xs, l), bisect.bisect_left(xs, r + 1)):
            cover[i] = 1
    return count_blocks(cover)


def label(segs):
    return " ".join("[%d,%d]" % (l, r) for l, r in segs)


for segs in ([(1, 2), (3, 4)], [(1, 2), (4, 5)]):
    print("%s  ->  브루트포스 %d / 끝점만 %d / 끝점+1 %d"
          % (label(segs), blocks_naive(segs, 8), blocks_wrong(segs), blocks_right(segs)))
```
```cpp title="구간을 압축할 때 — 끝점만 vs 끝점 + 1"
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

using Segs = vector<pair<int, int>>;

int count_blocks(const vector<int>& cover) {  // 0 에서 1 로 바뀌는 횟수가 덩어리 수다
    int blocks = 0, prev = 0;
    for (int c : cover) {
        if (c && !prev) blocks++;
        prev = c;
    }
    return blocks;
}

int blocks_naive(const Segs& segs, int hi) {  // 대조용 — 칸을 직접 칠한다
    vector<int> painted(hi + 1, 0);
    for (auto [l, r] : segs)
        for (int x = l; x <= r; x++) painted[x] = 1;
    return count_blocks(painted);
}

vector<int> sorted_unique(vector<int> xs) {
    sort(xs.begin(), xs.end());
    xs.erase(unique(xs.begin(), xs.end()), xs.end());
    return xs;
}

int idx(const vector<int>& xs, int v) {
    return lower_bound(xs.begin(), xs.end(), v) - xs.begin();
}

int blocks_wrong(const Segs& segs) {          // ❌ 끝점만 압축한다 — 빈틈이 사라진다
    vector<int> raw;
    for (auto [l, r] : segs) { raw.push_back(l); raw.push_back(r); }
    vector<int> xs = sorted_unique(raw);
    vector<int> cover(xs.size(), 0);
    for (auto [l, r] : segs)
        for (int i = idx(xs, l); i <= idx(xs, r); i++) cover[i] = 1;
    return count_blocks(cover);
}

int blocks_right(const Segs& segs) {          // ✅ r+1 까지 넣고 반열림 슬롯으로 다룬다
    vector<int> raw;
    for (auto [l, r] : segs) { raw.push_back(l); raw.push_back(r + 1); }
    vector<int> xs = sorted_unique(raw);
    vector<int> cover(xs.size() - 1, 0);
    for (auto [l, r] : segs)
        for (int i = idx(xs, l); i < idx(xs, r + 1); i++) cover[i] = 1;
    return count_blocks(cover);
}

string label(const Segs& segs) {
    string s;
    for (size_t i = 0; i < segs.size(); i++) {
        if (i) s += " ";
        s += "[" + to_string(segs[i].first) + "," + to_string(segs[i].second) + "]";
    }
    return s;
}

int main() {
    for (Segs segs : {Segs{{1, 2}, {3, 4}}, Segs{{1, 2}, {4, 5}}})
        cout << label(segs) << "  ->  브루트포스 " << blocks_naive(segs, 8)
             << " / 끝점만 " << blocks_wrong(segs)
             << " / 끝점+1 " << blocks_right(segs) << "\n";
    return 0;
}
```
:::

```console
[1,2] [3,4]  ->  브루트포스 1 / 끝점만 1 / 끝점+1 1
[1,2] [4,5]  ->  브루트포스 2 / 끝점만 1 / 끝점+1 2
```

**복잡도:** 세 함수 모두 좌표 압축이 $O(n \log n)$이고 덮기가 슬롯 수에 비례한다. 여기서는 구간마다 슬롯을 직접 훑으므로 최악 $O(n^2)$이지만, 압축의 함정을 보이는 것이 목적이라 그대로 두었다. **덮기까지 $O(n \log n)$으로 만드는 것이 [VI-6 스위핑](#/vi-6)이다** — 슬롯을 훑는 대신 시작·끝 이벤트만 정렬한다. 대조용 `blocks_naive`는 좌표 범위에 비례하는 $O(\text{hi})$라 좌표가 $10^9$이면 쓸 수 없다. 그것이 애초에 압축을 하는 이유다.

첫 줄은 **끝점만 압축해도 맞는다.** 그래서 위험하다. 두 입력의 차이는 칸 하나뿐인데 한쪽에서만 틀리고, 그 한쪽이 예제에 없으면 제출 전까지 드러나지 않는다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 중복 제거 | `set()`으로 한 번에. 순서가 사라지므로 `sorted`가 필수 | `sort` 후 `unique` + `erase`. **`unique`는 지우지 않고 뒤로 밀 뿐이다**([0-7](#/0-7)) |
| 순위 조회 | `bisect_left`가 인덱스를 돌려준다 | `lower_bound`가 반복자를 돌려주므로 `- xs.begin()`이 필요하다 |
| 해시로 대체 | `{v: i for i, v in enumerate(xs)}`가 흔히 더 빠르다 | `unordered_map`은 해시 비용과 캐시 미스 때문에 이분 탐색보다 느린 경우가 많다 |
| 값의 범위 | 임의 정밀도라 좌표가 커도 그대로 | 좌표가 $10^9$이고 `r+1`을 더하면 `int` 경계에 닿는다. `long long`을 고려하라 |

::: pitfall
- **`r+1`을 좌표 목록에 안 넣는다.** 이 절의 반례가 정확히 그것이다. 닫힌 구간을 다룰 때 반드시 반열림으로 바꾼 뒤 압축하라.
- **압축 좌표로 길이를 잰다.** 슬롯의 길이는 `xs[i+1] - xs[i]`다. 순위 차 1이 원좌표 100만 칸일 수 있다.
- **중복 제거를 빠뜨린다.** 같은 값이 다른 순위를 받으면 "서로 다른 값의 개수"가 어긋난다. C++에서는 `unique`만 부르고 `erase`를 잊는 것이 같은 결과를 낸다.
- **`xs`를 버린다.** 값을 출력해야 하는 순간 되돌릴 방법이 없다. 압축과 역변환표는 한 쌍이다.
- **압축한 값으로 산술을 한다.** 순위끼리 더한 값에는 아무 의미가 없다.
:::

## 5. 어디에 쓰이는가

**컬럼 스토어의 사전 인코딩(dictionary encoding)이 좌표 압축과 같은 절차다.** Parquet·ORC 같은 컬럼 포맷은 문자열 컬럼을 저장할 때 서로 다른 값을 모아 정렬한 사전을 만들고, 각 행에는 그 사전의 **인덱스**만 적는다. 국가 이름 열이 1억 행이어도 서로 다른 값이 200개면 행마다 1바이트면 된다. 정렬된 사전을 쓰면 이득이 하나 더 붙는다 — `country > 'K'` 같은 범위 조건을 원본 문자열을 꺼내지 않고 **사전 인덱스 비교로 처리**할 수 있다. 순서를 보존한다는 성질이 그대로 질의 성능이 된다. 같은 발상이 pandas의 `Categorical`, 문자열 인터닝, 그래프의 정점 번호 재매핑에 들어 있다.

**큰 좌표 위의 구간 자료구조는 압축 없이는 서지 않는다.** 좌표가 $\pm 10^9$인 세그먼트 트리는 잎이 20억 개라 불가능하지만, 등장하는 끝점이 20만 개면 잎이 20만 개인 트리로 같은 문제를 푼다. [IX-2 세그먼트 트리와 lazy propagation](#/ix-2)과 [IX-3 펜윅 트리(BIT)](#/ix-3)를 실전 좌표에 얹을 때 거의 항상 이 전처리가 먼저 온다. 반도체 설계 규칙 검사나 지도 렌더링에서 직사각형 합집합 넓이를 구하는 코드가 그 조합이다 — 좌표를 압축하고, [VI-6 스위핑](#/vi-6)으로 훑고, 슬롯 길이는 원좌표로 잰다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "몇 번째로 큰", "자신보다 작은 수의 개수", "좌표의 절댓값은 10억 이하", "서로 다른 값의 개수", "등수를 매겨라"
- 제약조건: 값의 범위가 $10^9$ 이상인데 값의 **개수**는 $10^5\!\sim\!10^6$이다. 알고리즘이 값을 배열 인덱스로 쓰려 하고, 값끼리 더하거나 빼지 않는다
- 혼동 주의: 값 자체로 계산해야 하면 압축하면 안 된다. 등장 순서만 필요하면 정렬만으로 끝나 압축이 불필요하다. 구간 질의가 섞이면 압축은 전처리일 뿐이고 본체는 [IX-2](#/ix-2)나 [VI-6](#/vi-6)다
- 반례 함정: **구간의 끝점을 압축할 때 `r+1`을 빼먹는다.** `[1,2] [3,4]`와 `[1,2] [4,5]`가 같은 압축 좌표가 되어 한쪽만 틀린다. 압축 좌표로 길이를 재는 것도 같은 뿌리의 오류다
:::

**2. 백준 1689 겹치는 선분 (골드 2)** — https://www.acmicpc.net/problem/1689
- 신호: 선분이 100만 개인데 좌표는 절댓값 10억 이하다. 좌표를 배열 인덱스로 쓰는 순간 메모리가 끝난다.
- 상태: 등장한 끝점만 남긴 목록과, 그 위에서 열려 있는 선분의 개수.
- 자료구조: 압축된 끝점 배열. 지문의 "끝 점에서 겹치는 것은 겹치는 것으로 세지 않는다"가 반열림 구간을 뜻한다는 것을 읽어내야 한다. 본체 풀이는 [VI-6 스위핑](#/vi-6)이고, 이 절의 몫은 **좌표를 인덱스로 바꾸는 전처리**다.

**3. 손 과제 — 반례 만들기.** 닫힌 구간 세 개로, 끝점만 압축한 계산과 `r+1`을 넣은 계산이 **덩어리 수는 같은데 칠해진 칸 수는 다른** 입력을 만들어라. 두 계산을 손으로 끝까지 돌려 숫자를 적어라.

**4. 손 과제 — 판정 연습.** 다음 넷 중 좌표 압축이 가능한 것과 불가능한 것을 가르고 이유를 한 줄로 적어라. ① 각 수보다 작은 수가 몇 개인지 ② 가장 가까운 두 수의 차 ③ 수들을 정렬했을 때 K번째 값 ④ 모든 수의 합이 짝수인지

::: answer
**3.** `[1,2] [4,5] [7,8]`이 한 예다. 세 구간이 서로 떨어져 있어 덩어리는 어느 계산에서나 3이다. 하지만 끝점만 압축하면 슬롯이 여섯 개(좌표 1,2,4,5,7,8)이고 전부 덮인 것으로 세어 칸 수를 6으로 계산할 수도, 슬롯 사이 간격을 원좌표로 재면서 빈 슬롯을 놓쳐 8로 계산할 수도 있다. 정답은 6칸이다. **덩어리 수가 맞았다고 압축이 옳았다는 뜻이 아니다** — 어느 답을 묻느냐에 따라 같은 실수가 드러나기도 하고 숨기도 한다.

**4.** ① 가능. 비교만 쓴다. ② **불가능.** 차를 구하려면 원래 값이 필요하다. 순위 차는 값의 차가 아니다. ③ 가능. K번째 값의 **위치**는 순위로 찾고, 출력할 때 `xs[rank]`로 되돌리면 된다. 역변환표를 들고 있어야 한다는 조건이 붙는다. ④ **불가능.** 합과 홀짝은 값의 절대적 성질이라 압축이 파괴한다.

## 요약

- 좌표 압축은 값들을 순서를 지키며 0, 1, 2, …로 다시 매기는 전처리다. **보존되는 것은 비교뿐이고 차이·합·비율은 버려진다.**
- 판정 기준은 하나다. 알고리즘이 값에서 **비교만 쓰면 압축 가능**, 산술을 쓰면 불가능.
- 절차는 세 줄이다. 정렬 → 중복 제거 → `bisect_left` / `lower_bound`로 순위. 시간 $O(n \log n)$, 공간 $O(n)$.
- 중복 제거 여부는 지문이 정한다. "서로 다른 값의 개수"면 제거하고 "정렬했을 때 몇 번째"면 제거하지 않는다.
- **구간의 끝점을 압축할 때는 `r+1`을 함께 넣는다.** 안 넣으면 `[1,2] [3,4]`와 `[1,2] [4,5]`가 같은 압축 좌표가 되어 빈틈이 사라진다.
- **슬롯의 길이는 원좌표로 잰다.** `xs[i+1] - xs[i]`이지 1이 아니다.
- `xs`는 역변환표다. 값을 출력해야 하면 반드시 함께 들고 다닌다.
