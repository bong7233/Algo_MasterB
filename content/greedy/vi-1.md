# VI-1 그리디가 성립하는 조건

::: lead
지금의 최선이 끝까지 최선이라는 것을 어떻게 증명하는가.
:::

## 1. 문제

회의실이 하나 있고 예약 요청이 여섯 개 들어왔다. 각 요청은 `(시작, 끝)`이다.

```text nolines
  (1,4)  (3,5)  (0,6)  (5,7)  (6,8)  (8,11)
```

겹치는 것은 동시에 승인할 수 없다. **최대 몇 개를 승인할 수 있는가.**

코드는 세 줄이면 나온다. 끝나는 시각이 이른 것부터 정렬하고, 앞에서부터 훑으면서 직전에 승인한 것과 겹치지 않으면 승인한다. 답은 3이다.

문제는 코드가 아니다. **왜 그게 맞는가.**

"끝이 이른 것부터"라는 규칙에는 근거가 안 보인다. 시작이 이른 것부터 고르는 규칙도, 짧은 것부터 고르는 규칙도 똑같이 그럴듯하다. 셋 다 코드 길이가 같고, 셋 다 이 입력에서 3을 낸다. 그런데 셋 중 둘은 틀렸다(어떤 입력에서 틀리는지는 [VI-2](#/vi-2)에서 숫자로 확인한다).

여기서 그리디의 실체가 드러난다. ==그리디는 알고리즘이 아니라 **주장**이다.== "매 순간 이 기준으로 고르면 전체가 최적이다"라는 주장이고, 주장은 참이거나 거짓이다. 코드를 짜는 데는 30초가 걸리고 그 주장이 참인지 판정하는 데는 그보다 오래 걸린다. 순서를 뒤집으면 — 짜고 나서 제출로 판정하면 — 틀렸을 때 되돌릴 것이 코드가 아니라 접근 전체다.

[I-5 오분류 사례집](#/i-5)은 이 실패의 한쪽 면을 다뤘다. 동전 `{1, 4, 5}`로 8원을 만들 때 그리디가 4개, 정답이 2개인 사례다. 거기서의 결론은 **"반례를 만들어 보라"** 였다. 이 챕터는 반대편을 다룬다. **반례를 만들려고 진지하게 시도했는데 실패했다면, 그다음에 무엇을 하는가.** 실패는 증명이 아니다. 아직 못 찾은 것과 없는 것은 다르다.

그 간극을 메우는 도구가 **교환 논법**이다.

## 2. 아이디어

### 2.1 그리디가 요구하는 두 가지

그리디가 최적해를 내려면 문제가 두 가지 성질을 가져야 한다.

**최적 부분구조.** 전체 문제의 최적해가 부분 문제의 최적해를 포함한다. 회의 세 개를 고르는 최적해에서 첫 회의를 떼어 내면, 남은 것은 "첫 회의가 끝난 뒤에 시작하는 회의들"이라는 더 작은 같은 문제의 최적해다. 이 성질이 없으면 문제를 쪼갤 수 없고, 쪼갤 수 없으면 그리디도 DP도 성립하지 않는다.

**탐욕적 선택 속성.** ==첫 선택을 그리디 기준으로 해도 손해 보지 않는 최적해가 반드시 존재한다.== 이것이 그리디만의 요구다. "그리디 선택이 모든 최적해에 들어 있다"가 아니다. 그런 최적해가 **하나라도** 있으면 된다. 이 완화가 증명을 가능하게 한다.

두 성질의 관계가 그리디와 DP를 가른다.

| | 최적 부분구조 | 탐욕적 선택 속성 | 첫 선택을 몇 가지 시도하는가 | 비용 |
|---|---|---|---|---|
| 완전탐색 | 불필요 | 불필요 | 전부 | 지수 |
| DP | 필요 | **불필요** | 전부, 단 겹치는 계산은 재사용 | 상태 수 × 전이 수 |
| 그리디 | 필요 | **필요** | **하나** | 대개 정렬 $O(n \log n)$ |

DP는 첫 선택을 모두 시도하고 그중 최선을 남긴다. 그래서 탐욕적 선택 속성이 필요 없다. 그리디는 첫 선택을 하나만 시도하고 나머지는 쳐다보지도 않는다. **그 하나가 옳다는 보증이 탐욕적 선택 속성이고, 그 보증이 없으면 나머지를 버린 순간 답이 사라진다.** DP의 절차는 [VIII-1](#/viii-1)에서 다룬다.

### 2.2 교환 논법 — 세 단계

탐욕적 선택 속성을 증명하는 표준 도구다. 이름 그대로 **최적해를 그리디해로 한 조각씩 바꿔치기**한다.

**① 갈림 지점을 잡는다.** 그리디해 $G$와 임의의 최적해 $O$를 나란히 놓는다. 둘이 완전히 같으면 증명할 것이 없다. 다르다면 처음 갈리는 자리 $k$가 있다. $k$ 앞은 완전히 같고, $k$번째부터 다르다.

**② 그 자리를 바꾼다.** $O$의 $k$번째 선택을 $G$의 $k$번째 선택으로 교체한다. 그리고 두 가지를 보인다.

- **여전히 유효한가.** 교체한 결과가 문제의 제약을 어기지 않는가.
- **여전히 최적인가.** 값(개수·비용·가치)이 나빠지지 않는가.

**③ 반복한다.** 교체 후의 해 $O'$는 $G$와 최소 $k$번째까지 일치한다. 일치 구간이 매번 최소 1씩 늘고 해의 길이는 유한하므로, 유한 번 반복하면 $O$가 $G$가 된다. 그동안 값은 한 번도 나빠지지 않았다. $O$가 최적이었으므로 **$G$도 최적이다.**

==증명의 전부는 ②다.== ①과 ③은 형식이고, ②만이 문제마다 다르다. ②를 보일 수 없다면 둘 중 하나다. 그리디가 틀렸거나, 정렬 키를 잘못 골랐거나.

### 2.3 구간 스케줄링에 적용한다

$G$를 "끝 이른 순" 그리디의 결과라 하자. $G$의 원소를 고른 순서대로 $g_1, g_2, \dots$ 로, 최적해 $O$의 원소를 시각 순으로 $o_1, o_2, \dots$ 로 쓴다.

**②를 보이는 데 필요한 사실은 하나다: $g_k$의 끝 시각은 $o_k$의 끝 시각보다 늦지 않다.**

근거는 그리디의 규칙 그 자체다. $k$ 이전이 같다면 $g_k$와 $o_k$는 **같은 후보 집합**에서 골라진다 — 둘 다 "$g_{k-1}$이 끝난 뒤에 시작하는 회의" 중 하나다. 그 집합에서 그리디는 **끝이 가장 이른 것**을 고른다. 그러니 $o_k$가 무엇이든 $g_k$보다 일찍 끝날 수는 없다.

이제 교체가 안전한 이유가 나온다.

```text nolines
  k = 1 :  O  = (3,5) (6,8) (8,11)
           G  = (1,4) (5,7) (8,11)
                 ^^^^^ first divergence

  swap  :  end(G[1]) = 4  <=  5 = end(O[1])
           O' = (1,4) (6,8) (8,11)      still valid, same size
```

$g_k$는 $o_k$보다 일찍 끝나므로 $O$의 $k+1$번째 이후와 겹칠 수 없다. 앞쪽과도 겹치지 않는다 — 그리디가 $g_k$를 고를 때 이미 $g_{k-1}$ 이후라는 조건을 확인했고, $k$ 앞은 $O$와 $G$가 같다. 개수는 하나를 빼고 하나를 넣었으니 그대로다. **유효하고, 나빠지지 않았다.** ②가 끝났다.

::: note
$g_k$가 $o_k$보다 **일찍 끝난다**는 성질에 "stays ahead"(항상 앞서 있다)라는 이름이 붙어 있다. 교환 논법과 짝을 이루는 표현일 뿐 다른 증명이 아니다. 매 단계 그리디가 앞서 있으니 교환이 언제나 안전하다는 말이다.
:::

### 2.4 실전 절차 — 반례 먼저, 증명은 그다음

교환 논법은 그리디가 **맞을 때** 쓰는 도구다. 틀린 그리디에 교환 논법을 시도하면 ②에서 막히지만, 막혔다는 사실을 알아채는 데 시간이 걸린다. 그래서 순서를 정한다.

```text nolines
  1. counterexample hunt   ~2 min   원소 3~4개로 그리디를 죽여 본다
  2. if killed  -> DP or search      죽었으면 끝. 그리디는 후보에서 빠진다
  3. if alive   -> exchange argument 살았으면 (2) 를 종이에 써 본다
  4. if (2) fails -> wrong sort key  키를 바꿔 1번으로 돌아간다
```

1번이 싸다. 원소 세 개짜리 입력을 대여섯 개 만들어 손으로 돌리는 데 2분이면 된다. **틀린 그리디는 대개 아주 작은 입력에서 죽는다** — 이 챕터의 배낭 반례는 원소 세 개고, [I-5](#/i-5)의 동전 반례도 세 종류다. 2분을 안 쓰고 25분짜리 구현으로 직행하는 것이 가장 비싼 선택이다.

3번에 도달했을 때 쓸 문장은 늘 같다. **"$O$의 첫 선택을 내 그리디 선택으로 바꿔도 여전히 유효하고 손해가 없다."** 이 한 문장을 구체적으로 채울 수 있으면 그리디는 안전하다.

## 3. 손으로 따라가기

교환을 한 번만 하고 끝내면 증명이 아니다. **일치 구간이 실제로 매번 늘어나는지**를 봐야 한다.

::: trace
입력: `(1,4) (3,5) (0,6) (5,7) (6,8) (8,11)`

끝 이른 순 그리디의 결과는 $G$ = `(1,4) (5,7) (8,11)`이다. 여기 크기가 같은 다른 최적해 $O$ = `(3,5) (6,8) (8,11)`가 있다. $O$를 $G$로 바꿔 간다.

관찰할 것은 세 열이다. **일치 구간의 길이**(늘어나야 한다), **교체가 안전한 근거**(그리디 쪽 끝이 더 이르다), **크기**(변하면 안 된다).

| 단계 | 지금의 $O$ | 일치 구간 | $k$ | $o_k$ | $g_k$ | `end(g_k) <= end(o_k)` | 교체 후 크기 |
|---|---|---|---|---|---|---|---|
| 0 | (3,5) (6,8) (8,11) | 0개 | 1 | (3,5) | (1,4) | 4 ≤ 5 ✓ | 3 |
| 1 | (1,4) (6,8) (8,11) | 1개 | 2 | (6,8) | (5,7) | 7 ≤ 8 ✓ | 3 |
| 2 | | | | | | | |
| 3 | | | | | | | |
:::

::: answer
| 단계 | 지금의 $O$ | 일치 구간 | $k$ | $o_k$ | $g_k$ | `end(g_k) <= end(o_k)` | 교체 후 크기 |
|---|---|---|---|---|---|---|---|
| 0 | (3,5) (6,8) (8,11) | 0개 | 1 | (3,5) | (1,4) | 4 ≤ 5 ✓ | 3 |
| 1 | (1,4) (6,8) (8,11) | 1개 | 2 | (6,8) | (5,7) | 7 ≤ 8 ✓ | 3 |
| 2 | (1,4) (5,7) (8,11) | 2개 | 3 | (8,11) | (8,11) | 11 ≤ 11 ✓ | 3 |
| 3 | (1,4) (5,7) (8,11) | **3개 = $O$ = $G$** | — | — | — | 교체 끝 | 3 |

단계 1에서 확인할 것이 하나 더 있다. $(6,8)$을 $(5,7)$로 바꿀 때 **앞의 $(1,4)$와 겹치지 않는가.** 겹치지 않는다 — 그리디가 $(5,7)$을 고른 이유가 바로 "$4$ 이후에 시작한다"였다. 교체의 안전성은 뒤쪽만 보면 되는 것이 아니라 앞쪽 조건까지 그리디의 선택 규칙이 이미 보장하고 있다.

세 번의 교체 동안 크기는 3에서 한 번도 움직이지 않았다. $O$가 최적이었으므로 $G$도 최적이다. **이 표가 증명 전체다.**
:::

## 4. 구현

### 4.1 교환 논법이 통하는 쪽

증명이 끝났어도 코드에는 버그가 있을 수 있다. 그리디를 **완전탐색과 대조**하는 것은 습관으로 굳혀야 한다. 부분집합을 전부 세는 코드는 정답의 정의를 그대로 옮긴 것이라 틀릴 여지가 거의 없고, $n \le 15$면 즉시 끝난다([0-12](#/0-12)).

::: dual
```python title="구간 스케줄링 — 그리디를 완전탐색과 대조한다"
seed = 12345


def next_rand(m):                                  # 두 언어가 같은 수열을 내도록 직접 짠 LCG
    global seed
    seed = (seed * 1103515245 + 12345) % 2147483648
    return seed % m


def greedy_select(jobs):
    jobs = sorted(jobs, key=lambda job: job[1])    # 끝나는 시각 오름차순 — 교환 논법이 지목한 키
    picked = []
    last_end = 0
    for s, e in jobs:
        if s >= last_end:                          # 앞의 선택과 겹치지 않으면 무조건 담는다
            picked.append((s, e))
            last_end = e
    return picked


def brute_best(jobs):
    n = len(jobs)
    best = 0
    for mask in range(1 << n):                     # 부분집합 전수 — 정답의 정의 그대로
        chosen = [jobs[i] for i in range(n) if (mask >> i) & 1]
        chosen.sort(key=lambda job: job[1])
        ok = True
        for i in range(1, len(chosen)):
            if chosen[i][0] < chosen[i - 1][1]:
                ok = False
                break
        if ok and len(chosen) > best:
            best = len(chosen)
    return best


jobs = [(1, 4), (3, 5), (0, 6), (5, 7), (6, 8), (8, 11)]
picked = greedy_select(jobs)
line = ""
for s, e in picked:
    line += "(" + str(s) + "," + str(e) + ") "
print("greedy = " + str(len(picked)) + " : " + line)
print("brute  = " + str(brute_best(jobs)))

same, diff = 0, 0
for t in range(500):                               # 무작위 입력으로 그리디를 반증해 본다
    n = 1 + next_rand(8)
    trial = []
    for i in range(n):
        s = next_rand(12)
        trial.append((s, s + 1 + next_rand(5)))
    if len(greedy_select(trial)) == brute_best(trial):
        same += 1
    else:
        diff += 1
print("random 500 : same = " + str(same) + ", diff = " + str(diff))
```
```cpp title="구간 스케줄링 — 그리디를 완전탐색과 대조한다"
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

using Job = pair<int, int>;
unsigned long long seed = 12345;

int next_rand(int m) {                             // 두 언어가 같은 수열을 내도록 직접 짠 LCG
    seed = (seed * 1103515245ULL + 12345ULL) % 2147483648ULL;
    return (int)(seed % (unsigned long long)m);
}

vector<Job> greedy_select(vector<Job> jobs) {
    sort(jobs.begin(), jobs.end(),                 // 끝나는 시각 오름차순 — 교환 논법이 지목한 키
         [](Job a, Job b) { return a.second < b.second; });
    vector<Job> picked;
    int last_end = 0;
    for (auto [s, e] : jobs)
        if (s >= last_end) {                       // 앞의 선택과 겹치지 않으면 무조건 담는다
            picked.push_back({s, e});
            last_end = e;
        }
    return picked;
}

int brute_best(const vector<Job>& jobs) {
    int n = (int)jobs.size();
    int best = 0;
    for (int mask = 0; mask < (1 << n); mask++) {  // 부분집합 전수 — 정답의 정의 그대로
        vector<Job> chosen;
        for (int i = 0; i < n; i++)
            if ((mask >> i) & 1) chosen.push_back(jobs[i]);
        sort(chosen.begin(), chosen.end(), [](Job a, Job b) { return a.second < b.second; });
        bool ok = true;
        for (size_t i = 1; i < chosen.size(); i++)
            if (chosen[i].first < chosen[i - 1].second) {
                ok = false;
                break;
            }
        if (ok && (int)chosen.size() > best) best = (int)chosen.size();
    }
    return best;
}

int main() {
    vector<Job> jobs = {{1, 4}, {3, 5}, {0, 6}, {5, 7}, {6, 8}, {8, 11}};
    vector<Job> picked = greedy_select(jobs);
    string line = "";
    for (auto [s, e] : picked) line += "(" + to_string(s) + "," + to_string(e) + ") ";
    cout << "greedy = " << picked.size() << " : " << line << "\n";
    cout << "brute  = " << brute_best(jobs) << "\n";

    int same = 0, diff = 0;
    for (int t = 0; t < 500; t++) {                // 무작위 입력으로 그리디를 반증해 본다
        int n = 1 + next_rand(8);
        vector<Job> trial;
        for (int i = 0; i < n; i++) {
            int s = next_rand(12);
            trial.push_back({s, s + 1 + next_rand(5)});
        }
        if ((int)greedy_select(trial).size() == brute_best(trial)) same++;
        else diff++;
    }
    cout << "random 500 : same = " << same << ", diff = " << diff << "\n";
    return 0;
}
```

```console
random 500 : same = 500, diff = 0
```

**복잡도:** 그리디는 시간 $O(n \log n)$ — 정렬이 지배하고 이후에는 각 회의를 한 번씩만 보므로 $O(n)$이 더해진다. 공간 $O(n)$ — 정렬된 사본과 선택 목록. 완전탐색은 시간 $O(2^n \cdot n \log n)$ — 부분집합이 $2^n$개이고 각각을 정렬해 검사하므로 곱해진다. 대조용이지 제출용이 아니다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 정렬 키 | `key=lambda job: job[1]` — 키 함수 하나 | `[](Job a, Job b){ return a.second < b.second; }` — **비교자**. strict weak ordering을 어기면 크래시한다([0-8](#/0-8)) |
| 정수 크기 | 임의 정밀도. LCG의 곱셈이 넘칠 일이 없다 | `int`로 짜면 `seed * 1103515245`가 **오버플로한다**. `unsigned long long`이 필수다 |
| 정렬 안정성 | `sorted`는 안정(Timsort) | `std::sort`는 불안정. 끝 시각이 같은 회의의 순서는 보장되지 않는다 — 이 문제에서는 개수만 세므로 무해하다 |

무작위 500회에서 불일치가 0이다. **이것은 증명이 아니라 증명의 확인이다.** 교환 논법이 이미 최적성을 보장했고, 이 대조가 검사하는 것은 코드가 그 알고리즘을 제대로 옮겼는지다. 순서를 헷갈리면 안 된다 — 대조가 500번 통과했다고 증명이 되지는 않는다.

### 4.2 교환 논법이 막히는 쪽

같은 절차를 0/1 배낭에 적용해 본다. 무게 한도 `cap`이 있고, 물건마다 무게와 가치가 있고, 쪼갤 수 없다. 그럴듯한 그리디는 **밀도(가치 ÷ 무게)가 높은 것부터** 담는 것이다.

교환 논법 ②를 시도해 보면 즉시 막힌다. 최적해의 첫 물건을 밀도 1등 물건으로 바꾸면 **무게가 달라진다.** 무게가 늘면 뒤의 물건이 안 들어가고, 무게가 줄면 남은 공간이 생기는데 그 공간을 채울 물건이 있는지 없는지 알 수 없다. 구간 스케줄링에서는 "하나를 빼고 하나를 넣으면 개수가 같다"가 자동이었는데, 여기서는 그것이 성립하지 않는다. **교체가 값을 보존하지 않는다.**

막혔으면 반례가 있다. 찾는 것은 기계에 시킨다.

::: dual
```python title="0/1 배낭 — 밀도 그리디의 반례를 기계로 찾는다"
from functools import cmp_to_key

seed = 777


def next_rand(m):
    global seed
    seed = (seed * 1103515245 + 12345) % 2147483648
    return seed % m


def by_density(a, b):                              # v/w 내림차순. 나눗셈 없이 교차곱으로 비교한다
    if a[1] * b[0] != b[1] * a[0]:
        return -1 if a[1] * b[0] > b[1] * a[0] else 1
    if a[0] != b[0]:
        return -1 if a[0] < b[0] else 1
    return 0


def greedy_knapsack(items, cap):
    items = sorted(items, key=cmp_to_key(by_density))
    total, room = 0, cap
    for w, v in items:
        if w <= room:                              # 밀도가 높은 것부터, 들어가면 담는다
            room -= w
            total += v
    return total


def brute_knapsack(items, cap):
    n = len(items)
    best = 0
    for mask in range(1 << n):
        w_sum, v_sum = 0, 0
        for i in range(n):
            if (mask >> i) & 1:
                w_sum += items[i][0]
                v_sum += items[i][1]
        if w_sum <= cap and v_sum > best:
            best = v_sum
    return best


hand = [(6, 10), (5, 7), (5, 7)]
print("hand   : greedy = " + str(greedy_knapsack(hand, 10)) +
      ", brute = " + str(brute_knapsack(hand, 10)))

for t in range(1, 1001):                           # 반례를 찾을 때까지 무작위로 두들긴다
    items = [(1 + next_rand(9), 1 + next_rand(15)) for i in range(4)]
    cap = 5 + next_rand(12)
    g, b = greedy_knapsack(items, cap), brute_knapsack(items, cap)
    if g != b:
        line = ""
        for w, v in items:
            line += "(" + str(w) + "," + str(v) + ") "
        print("random : trial " + str(t) + ", cap = " + str(cap) + ", items = " + line)
        print("         greedy = " + str(g) + ", brute = " + str(b))
        break
```
```cpp title="0/1 배낭 — 밀도 그리디의 반례를 기계로 찾는다"
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

using Item = pair<int, int>;
unsigned long long seed = 777;

int next_rand(int m) {
    seed = (seed * 1103515245ULL + 12345ULL) % 2147483648ULL;
    return (int)(seed % (unsigned long long)m);
}

bool by_density(Item a, Item b) {                  // v/w 내림차순. 나눗셈 없이 교차곱으로 비교한다
    if (a.second * b.first != b.second * a.first)
        return a.second * b.first > b.second * a.first;
    return a.first < b.first;
}

int greedy_knapsack(vector<Item> items, int cap) {
    sort(items.begin(), items.end(), by_density);
    int total = 0, room = cap;
    for (auto [w, v] : items)
        if (w <= room) {                           // 밀도가 높은 것부터, 들어가면 담는다
            room -= w;
            total += v;
        }
    return total;
}

int brute_knapsack(const vector<Item>& items, int cap) {
    int n = (int)items.size();
    int best = 0;
    for (int mask = 0; mask < (1 << n); mask++) {
        int w_sum = 0, v_sum = 0;
        for (int i = 0; i < n; i++)
            if ((mask >> i) & 1) {
                w_sum += items[i].first;
                v_sum += items[i].second;
            }
        if (w_sum <= cap && v_sum > best) best = v_sum;
    }
    return best;
}

int main() {
    vector<Item> hand = {{6, 10}, {5, 7}, {5, 7}};
    cout << "hand   : greedy = " << greedy_knapsack(hand, 10)
         << ", brute = " << brute_knapsack(hand, 10) << "\n";

    for (int t = 1; t <= 1000; t++) {              // 반례를 찾을 때까지 무작위로 두들긴다
        vector<Item> items;
        for (int i = 0; i < 4; i++) items.push_back({1 + next_rand(9), 1 + next_rand(15)});
        int cap = 5 + next_rand(12);
        int g = greedy_knapsack(items, cap), b = brute_knapsack(items, cap);
        if (g != b) {
            string line = "";
            for (auto [w, v] : items) line += "(" + to_string(w) + "," + to_string(v) + ") ";
            cout << "random : trial " << t << ", cap = " << cap << ", items = " << line << "\n";
            cout << "         greedy = " << g << ", brute = " << b << "\n";
            break;
        }
    }
    return 0;
}
```

```console
hand   : greedy = 10, brute = 14
random : trial 19, cap = 9, items = (6,10) (7,11) (6,4) (1,13) 
         greedy = 23, brute = 24
```

**복잡도:** 밀도 그리디는 시간 $O(n \log n)$ — 정렬이 지배한다. 완전탐색은 시간 $O(2^n \cdot n)$ — 부분집합 $2^n$개마다 원소 $n$개의 무게·가치를 더한다. 반례 탐색 전체는 시도 횟수 $T$를 곱해 $O(T \cdot 2^n n)$이고, 여기서는 19번째 시도에서 멈췄다.

📖 `functools.cmp_to_key(cmp)` — **두 값을 받아 음수/0/양수를 돌려주는 비교 함수**를 `sorted`의 `key=`로 쓸 수 있게 감싼다. Python의 정렬은 키 하나만 받으므로, "밀도 내림차순, 같으면 무게 오름차순" 같은 다단 규칙을 나눗셈 없이 표현할 때 쓴다. 오버헤드가 있어 `key=`로 표현 가능하면 그쪽이 빠르다([0-4](#/0-4)).
　 C++ 대응: `std::sort`의 세 번째 인자가 처음부터 비교자다. 감쌀 필요가 없다.

손으로 만든 사례부터 본다. 한도 10에 물건이 `(무게 6, 가치 10)`, `(5, 7)`, `(5, 7)`이다. 밀도는 각각 $10/6 \approx 1.67$, $1.4$, $1.4$이므로 그리디는 첫 물건을 담고 총 **10**을 얻는다. 남은 공간 4에는 아무것도 안 들어간다. 정답은 뒤의 둘을 담아 **14**다. 밀도 1등이 남긴 공간이 죽은 공간이 됐다.

기계가 19번째 시도에서 찾은 반례도 같은 구조다. 한도 9, 물건 `(6,10) (7,11) (6,4) (1,13)`. 밀도 1등은 $(1,13)$이라 그리디도 이건 담는다. 남은 공간 8에서 밀도 2등 $(6,10)$을 담아 **23**에서 멈춘다. 하지만 $(1,13)$과 $(7,11)$을 담으면 무게 8에 가치 **24**다. 그리디가 무게 6짜리를 담는 순간 남은 공간 2가 영영 죽는다.

==쪼갤 수 없다는 제약이 교환을 막는다.== 물건을 쪼갤 수 있다면(분수 배낭) 밀도 그리디는 최적이고 교환 논법도 통과한다 — 최적해에 밀도 1등이 덜 들어 있으면 다른 물건을 그만큼 덜어 내고 1등을 채우면 되며, 밀도가 더 높으니 값은 오른다. 쪼갤 수 없으면 "그만큼"을 만들 수 없다. **한 문장 차이가 그리디와 DP를 가른다.** 0/1 배낭의 DP는 [VIII-5](#/viii-5)에 있다.

::: pitfall
- **작은 예제 통과를 증명으로 쓴다.** 밀도 그리디는 무작위 입력 18번을 연속으로 맞혔다. 19번째에 틀렸다. 대조 루프를 500번 돌리는 이유가 이것이다.
- **정렬 키를 정하지 않고 그리디라고 부른다.** "좋아 보이는 것부터"는 알고리즘이 아니다. 키가 정해져야 교환 논법을 시도할 수 있고, 키가 바뀌면 증명을 처음부터 다시 해야 한다.
- **밀도 비교를 부동소수로 한다.** `v / w`로 정렬하면 값이 큰 입력에서 같은 밀도가 다르게 판정된다([X-7](#/x-7)). 교차곱 `a.v * b.w`로 비교하면 정수 연산으로 끝난다. 단 C++에서는 이 곱이 `int` 범위를 넘길 수 있으니 값의 상한을 확인하라.
- **모든 최적해가 그리디 선택을 포함한다고 말한다.** 필요한 것은 "포함하는 최적해가 하나 존재한다"뿐이다. 강하게 주장하면 참이 아닌 명제를 증명하려다 막힌다.
:::

## 5. 어디에 쓰이는가

**허프만 코딩**이 교환 논법으로 최적성이 증명되는 대표 사례이고, 그 코드는 지금 이 순간에도 돌고 있다. `gzip`·`zlib`·PNG가 쓰는 DEFLATE와 JPEG의 엔트로피 부호화 단계가 허프만 트리를 만든다. 절차는 "빈도가 가장 낮은 두 심볼을 합친다"의 반복이고, 최적성의 근거가 교환 논법이다 — **어떤 최적 접두 부호 트리에서든 빈도가 가장 낮은 두 심볼을 가장 깊은 형제 자리로 바꿔 넣어도 전체 길이가 늘지 않는다.** 깊은 자리에 있던 심볼은 빈도가 더 높으므로 위로 올라가면서 오히려 이득이거나 본전이다. ②가 성립한다.

**크루스칼의 최소 신장 트리**도 같은 뼈대다. 간선을 가중치 오름차순으로 보면서 사이클을 만들지 않으면 채택한다. 최적성의 근거는 "가장 가벼운 간선을 포함하는 최소 신장 트리가 존재한다"이고, 증명은 교환이다 — 그 간선이 빠진 신장 트리에 그것을 넣으면 사이클이 생기고, 사이클 안의 더 무거운 간선을 빼면 여전히 신장 트리이며 가중치 합은 줄거나 같다([IX-4](#/ix-4)).

**다익스트라**도 그리디다([V-1](#/v-1)). "아직 확정 안 된 정점 중 거리가 가장 짧은 것을 확정한다"가 탐욕적 선택이고, 이것이 옳은 이유는 간선 가중치가 음수가 아니기 때문이다. 음수 간선이 하나만 있어도 "지금 가장 가까운 것이 최종으로도 가장 가까운 것"이 깨지고 그 순간 벨만-포드로 가야 한다([V-2](#/v-2)). ==그리디의 성립 조건이 지문의 제약 한 줄에 달려 있다는 이 책의 반복되는 명제가, 최단경로에서는 "가중치가 음수인가"라는 형태로 나타난다.==

::: interview
**"이 문제를 그리디로 풀었다고 했는데, 최적이라는 것을 어떻게 압니까?"**

답변 뼈대는 세 문장이다. **① 정렬 키를 명시한다** — "끝나는 시각 오름차순입니다." **② 탐욕적 선택 속성을 진술한다** — "첫 회의를 가장 일찍 끝나는 것으로 잡아도 손해 보지 않는 최적해가 존재합니다." **③ 교환을 구체적으로 보인다** — "최적해의 첫 회의를 그것으로 바꿔도 제 것이 더 일찍 끝나므로 뒤의 회의들과 겹치지 않고, 개수는 그대로입니다. 첫 갈림 지점을 뒤로 밀어 가면 최적해가 제 답이 됩니다."

"직관적으로 그럴 것 같아서"는 답이 아니다. 반대로 그리디가 안 되는 경우를 짚을 수 있으면 이해의 증거가 된다 — "물건을 쪼갤 수 없으면 교환이 무게를 보존하지 않아서 이 논법이 막힙니다. 그래서 0/1 배낭은 DP입니다."
:::

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "최대 몇 개", "최소 비용으로", "가장 많이" + **선택이 순차적**이고 한 번 고르면 되돌리지 않아도 될 것 같은 구조. "정렬하면 될 것 같다"는 느낌 자체가 그리디 후보의 신호다
- 제약조건: $N \le 10^5\!\sim\!10^6$이라 정렬 $O(n \log n)$만 허용되고 DP의 상태 수(대개 $N \times$ 값 범위)가 메모리에 안 들어갈 때. 반대로 $N$이 작고 값 범위가 좁으면 DP가 안전하다([0-9](#/0-9))
- 혼동 주의: 선택이 뒤의 선택 가능성을 **수치로** 제약하면(무게·예산·잔여 용량) 그리디가 깨지고 [VIII-5 배낭 문제](#/viii-5)다. 한 번 고른 것을 무르고 싶어지면 힙을 얹는다([II-8](#/ii-8)). "그리디로 보이는 DP"의 사례집은 [I-5](#/i-5)
- 반례 함정: 그리디는 작은 입력을 연달아 맞힌 뒤 특정 구조에서만 틀린다. 원소 3~4개, 값이 서로 가까운 입력, **한도를 아슬아슬하게 남기는 입력**을 먼저 던져라. 밀도 그리디는 `(6,10) (5,7) (5,7)`, 한도 10에서 죽는다
:::

**2. 백준 1744 수 묶기 (골드 4)** — https://www.acmicpc.net/problem/1744
- 지문: 수열의 원소들을 둘씩 묶어 곱해서 더할 수 있다. 묶지 않아도 된다. 합의 최댓값.
- 3단 사고: "최대화" + 짝짓기라는 신호. 상태는 정렬한 뒤 양쪽 끝에서 좁혀 오는 두 포인터([VI-3](#/vi-3)). 자료구조는 정렬된 배열. **양수와 음수를 따로 묶어야 하는 이유, 그리고 0과 1이 왜 예외인지**를 교환으로 설명하라 — 1은 곱하는 것보다 더하는 것이 낫고, 0은 음수를 죽이는 데 쓴다.

**3. 백준 1715 카드 정렬하기 (골드 4)** — https://www.acmicpc.net/problem/1715
- 지문: 정렬된 카드 묶음 여러 개를 둘씩 합친다. 크기 A와 B를 합치는 비용은 A+B. 전체 비용의 최솟값.
- 3단 사고: "합치는 비용의 최소" + 합친 결과가 다시 후보가 된다는 신호. 상태는 "지금 남아 있는 묶음들의 크기 집합"이다. **자료구조가 정렬이 아니라 최소 힙인 이유**를 말하라 — 합칠 때마다 새 원소가 생기므로 후보 집합이 스텝마다 바뀐다([II-8](#/ii-8)). 이것이 허프만 코딩과 같은 알고리즘이고, 최적성의 증명도 같은 교환이다.

**4. 백준 11047 동전 0 (실버 4)** — https://www.acmicpc.net/problem/11047
- 지문: `A_i`가 `A_{i-1}`의 배수인 동전 n종으로 k원을 만든다. 동전 개수의 최솟값.
- 3단 사고: "최소 개수"라는 신호는 그리디와 DP를 **동시에** 가리킨다([I-5](#/i-5)). 갈림점은 제약조건의 **배수 조건** 한 줄이다. 상태는 남은 금액 하나, 자료구조는 정렬된 배열. **교환 논법 ②를 배수 조건 위에서 써라** — 최적해가 큰 동전을 그리디보다 적게 썼다면 작은 동전들의 합이 그 큰 동전의 값 이상이 되고, 배수 조건 덕분에 그 작은 동전 뭉치를 큰 동전 하나로 정확히 바꿔치기할 수 있다. 개수는 반드시 줄어든다. **배수 조건이 없으면 이 교체가 불가능하고** 문제는 DP가 된다.
:::

## 요약

- 그리디는 알고리즘이 아니라 **주장**이다. "이 기준으로 매번 고르면 전체가 최적"이라는 주장이고, 참·거짓을 판정해야 한다.
- 성립 조건은 둘이다. **최적 부분구조**(DP와 공유)와 **탐욕적 선택 속성**(그리디만의 요구). DP는 첫 선택을 전부 시도하므로 후자가 필요 없다.
- **교환 논법**의 세 단계: ① 최적해와 그리디해가 처음 갈리는 자리를 잡고 ② 그 자리를 그리디 선택으로 바꿔도 유효하고 나빠지지 않음을 보이고 ③ 일치 구간이 늘어남을 근거로 반복한다. **②만이 문제마다 다르다.**
- 구간 스케줄링에서 ②의 근거는 한 줄이다. **그리디의 $k$번째 선택은 최적해의 $k$번째보다 일찍 끝난다.** 같은 후보 집합에서 끝이 가장 이른 것을 골랐기 때문이다.
- 실전 순서는 **반례 사냥이 먼저, 교환 논법이 나중**이다. 원소 3~4개로 2분간 죽여 보고, 안 죽으면 ②를 종이에 쓴다. ②가 막히면 정렬 키가 틀렸거나 그리디 자체가 틀린 것이다.
- 0/1 배낭에서 ②가 막히는 이유는 **교체가 무게를 보존하지 않기** 때문이다. 쪼갤 수 있으면 그리디가 최적이고, 쪼갤 수 없으면 DP다. `(6,10) (5,7) (5,7)`에 한도 10이면 10과 14로 갈린다.
- 증명이 끝났어도 **완전탐색과 대조하라.** 증명은 알고리즘을 보증하고 대조는 구현을 보증한다. 둘은 다른 것을 검사한다.
