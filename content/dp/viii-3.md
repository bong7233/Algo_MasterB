# VIII-3 1차원 DP

::: lead
상태가 정수 하나로 끝나는 문제들. 그리고 그 정수 하나를 "i까지의"로 잡느냐 "i로 끝나는"으로 잡느냐가 왜 정답과 오답을 가르는가.
:::

## 1. 문제

계단이 $n$개다. 한 번에 한 칸 또는 두 칸씩 오른다. 꼭대기까지 올라가는 서로 다른 방법이 몇 가지인가.

$n = 5$면 손으로 센다. 여덟 가지다. $n = 35$는 어떨까. 방법을 하나씩 만들어 세는 재귀를 그대로 돌리면 이렇게 된다.

```text nolines
   n = 10 :          177 회 호출
   n = 20 :       21,891 회
   n = 30 :    2,692,537 회      Python 0.30 s / C++ 0.003 s
   n = 35 :   29,860,703 회      Python 3.53 s / C++ 0.029 s
```

$n$이 5 늘 때마다 열한 배다. $n = 50$은 어떤 언어로도 끝나지 않는다.

그런데 이 재귀가 실제로 던진 **서로 다른 질문**은 몇 개인가. 재귀가 받는 인자는 0부터 35까지 정수 하나이고, 그러니 질문은 **36가지뿐이다.** 2,986만 번의 호출이 36개의 질문을 반복해서 물은 결과다.

[VIII-1](#/viii-1)이 이 상황에 이름을 붙였다. 중복 부분문제다. 이 절은 거기서 세운 네 단계 절차를 **상태가 정수 하나인 문제들**에 반복 적용한다. 계단, 타일링, 그리고 최대 부분합 셋을 본다.

앞의 둘은 점화식이 눈에 보인다. 셋째는 다르다. **상태를 가장 자연스러운 쪽으로 잡으면 점화식이 아예 서지 않는다.** 그 지점이 이 절의 본론이다.

## 2. 아이디어

### 2.1 계단 오르기 — 네 칸을 채운다

**① 상태 정의.** $dp[i]$ = $i$번째 칸에 도달하는 방법의 수.

지금까지 어떻게 올라왔는지는 앞으로와 무관하다. 3번 칸에 서 있다면 그다음에 할 수 있는 일은 어떤 경로로 왔든 똑같다. 기억할 것은 "지금 몇 번 칸인가" 하나이고, 그것이 정수 하나다.

**② 점화식.** 마지막 결정 하나를 떼어 낸다. $i$번 칸에 도착한 **마지막 걸음**은 한 칸이었거나 두 칸이었다. 앞의 경우 직전에 $i-1$에 있었고, 뒤의 경우 $i-2$에 있었다. 두 경우는 겹치지 않으므로 더한다.

$$dp[i] = dp[i-1] + dp[i-2]$$

**③ 초기값.** $dp[0] = 1$, $dp[1] = 1$. 출발점에 도달하는 방법은 "아무것도 안 하는 것" 하나다. 개수를 세는 DP라 0번 칸이 0이 아니라 1이다([VIII-1](#/viii-1) §2.4의 두 번째 함정이 바로 이 자리다).

**④ 계산 순서.** $i$를 2부터 올린다. $dp[i]$가 읽는 칸이 전부 자기보다 작은 인덱스이므로 왼쪽에서 오른쪽으로 한 번 훑으면 조건이 저절로 지켜진다.

### 2.2 타일링 — 다른 문제, 같은 표

$2 \times n$ 직사각형을 $1 \times 2$ 타일로 빈틈없이 덮는 방법의 수. 겉보기에는 계단과 아무 상관이 없다.

**① 상태.** $dp[n]$ = $2 \times n$을 덮는 방법의 수.

**② 점화식.** 마지막 결정은 **가장 오른쪽 열을 무엇으로 덮는가**다. 세로 타일 하나로 덮으면 남는 것이 $2 \times (n-1)$이다. 세로가 아니라면 오른쪽 끝 칸은 가로 타일에 물려 있고, 그러면 그 아래 칸도 가로 타일이어야만 빈틈이 안 생긴다. 즉 오른쪽 두 열이 가로 두 장으로 채워지고 남는 것은 $2 \times (n-2)$다.

$$dp[n] = dp[n-1] + dp[n-2]$$

계단과 글자 하나 다르지 않다.

여기서 반드시 확인할 것이 있다. **두 경우가 배타적인가.** 구분 기준은 "오른쪽 끝 열이 세로 타일 하나인가 아닌가"이고 이것은 참·거짓이므로 겹치지 않는다. 그리고 오른쪽 두 열을 가로로 채우는 방법은 정확히 한 가지다 — 위 칸에 한 장, 아래 칸에 한 장. ==개수를 세는 DP에서 경우를 배타적으로 가르는 기준을 못 찾으면 답은 반드시 부풀어 오른다.== 최솟값 DP는 같은 것을 두 번 세도 최솟값이 안 변하지만, 개수 DP는 그 자리에서 틀린다.

::: note
계단과 타일링이 같은 표라는 사실은 우연이 아니다. 둘 다 **길이 $n$짜리를 길이 1 조각과 길이 2 조각으로 자르는 방법의 수**이고, 계단은 그 조각을 걸음으로, 타일링은 세로 타일 한 열과 가로 타일 두 열로 읽었을 뿐이다. 문제의 표면이 아니라 그 밑의 분해 구조가 같으면 점화식이 같다. 이 알아보기가 [I-4](#/i-4)가 훈련하는 능력과 정확히 같은 것이다.
:::

### 2.3 배열을 버릴 수 있을 때, 그리고 그 대가

$dp[i]$가 읽는 칸은 $dp[i-1]$과 $dp[i-2]$ 둘뿐이다. 표 전체를 들고 있을 이유가 없다. 변수 두 개를 굴리면 공간이 $O(1)$이 된다.

::: perf
계단 점화식, $n = 2{,}000{,}000$, 값은 10007로 나눈 나머지.

| | 시간 | 메모리 |
|---|---|---|
| Python 배열판 | 343 ms | 74.7 MB |
| Python 롤링판 | 156 ms | 0.2 KB |
| C++ 배열판 | 12.4 ms | 7.6 MB (`int` 200만 개) |
| C++ 롤링판 | 6.9 ms | 변수 두 개 |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/viii3_1d_dp.py` 와 `.cpp` 다.)

같은 200만 칸인데 Python이 74.7 MB, C++이 7.6 MB다. C++ 쪽은 `int` 4바이트 × 200만이 전부이고, Python 쪽은 정수 하나가 객체라 객체 본체 28바이트에 리스트가 든 포인터 8바이트가 더 붙는다 — 곱하면 72 MB이고 리스트 여유분이 나머지다. **같은 알고리즘도 같은 메모리를 쓰지 않는다.**
:::

**대신 잃는 것이 있다.** 배열을 버리면 $dp[k]$를 나중에 다시 물어볼 수 없고, "어떤 선택이었는가"를 되짚는 역추적도 불가능하다. 계단·타일링은 답이 마지막 칸 하나라 문제가 없다. 하지만 여러 $n$을 한꺼번에 물어보는 문제나 실제 경로를 출력해야 하는 문제에서는 표를 남겨야 한다. ==공간 압축은 공짜가 아니라 표를 버리는 대가로 산 것이다.== [VIII-4](#/viii-4)와 [VIII-5](#/viii-5)에서 같은 교환이 다시 나온다.

### 2.4 최대 부분합 — 상태를 잘못 잡으면 점화식이 서지 않는다

수열이 주어진다. **연속한** 몇 개를 골라 합을 최대로 만든다. 최소 한 개는 골라야 한다.

$$a = [3,\ -2,\ 4,\ -7,\ 5,\ 2,\ -1,\ 3]$$

앞의 둘과 같은 방식으로 상태를 잡아 보자. 자연스럽게 이 문장이 나온다.

> $dp[i]$ = $a[0..i]$ 구간에서의 최대 부분합

편하기까지 하다. 답이 곧 $dp[n-1]$이다. 점화식도 그럴듯하게 나온다. $a[i]$를 안 쓰거나, 앞 구간에 이어 붙이거나, $a[i]$에서 새로 시작하거나 셋이다.

$$dp[i] = \max\big(dp[i-1],\ dp[i-1] + a[i],\ a[i]\big)$$

이 식을 위 수열에 돌리면 **17**이 나온다. 정답은 **9**다.

무엇이 깨졌는지는 가운데 항에 있다. $dp[i-1] + a[i]$는 "앞 구간에 $a[i]$를 이어 붙인다"는 뜻인데, **$dp[i-1]$이 어디서 끝난 구간의 합인지 그 값 하나로는 알 수 없다.** $i=1$까지의 최대 부분합 3은 구간 $[0,0]$에서 나온 값이고, 거기에 $a[2] = 4$를 이어 붙이면 사이에 $a[1] = -2$가 끼어 있어 **연속이 아니다.** 존재하지 않는 구간의 합 7이 표에 들어앉고, 그 뒤 계산은 전부 그 거짓말 위에 쌓인다.

우연한 반례가 아니다. 길이 1~10, 값 -9~9인 무작위 수열 3,000개를 완전탐색과 대조하면 이 상태는 **1,463개(48.8%)에서 틀린 답을 낸다**(`tools/bench/viii3_1d_dp.py`). 절반은 맞으므로 예제 몇 개로는 절대 걸리지 않는다.

원인은 계산 실수가 아니다. **상태가 정보를 덜 담고 있다.** 이어 붙이는 연산이 합법이려면 앞 구간의 끝점이 $i-1$로 고정되어 있어야 하는데, "$i$까지의 최대"는 그것을 보장하지 않는다. [VIII-1](#/viii-1)의 기준으로 다시 읽으면 이렇다 — **미래의 선택(이어 붙일 것인가)을 정하는 데 필요한 정보가 상태에 없다.**

고치는 방법은 상태를 넓히는 것이 아니라 **좁히는** 것이다.

**① 상태 정의.** $dp[i]$ = **$a[i]$로 끝나는** 최대 부분합. $a[i]$를 반드시 포함한다.

이제 $dp[i-1]$은 $i-1$에서 끝난 구간의 합임이 정의로 보장된다. 이어 붙이는 것이 언제나 합법이다.

**② 점화식.** 마지막 결정은 둘뿐이다. $a[i]$ 앞에 $dp[i-1]$의 구간을 붙일 것인가, $a[i]$ 혼자로 새로 시작할 것인가.

$$dp[i] = \max\big(dp[i-1] + a[i],\ a[i]\big)$$

$dp[i-1]$이 음수면 붙이는 순간 손해이므로 새로 시작한다. 이것이 카데인 알고리즘이다.

**③ 초기값.** $dp[0] = a[0]$. 첫 원소로 끝나는 구간은 자기 자신뿐이다. 0이 아니다 — 0으로 두면 원소가 전부 음수인 수열에서 "아무것도 안 고른" 빈 구간이 답으로 나온다.

**④ 계산 순서.** $i$ 오름차순.

**대신 답이 마지막 칸에 없다.** $dp[n-1]$은 "$a[n-1]$로 끝나는" 최대일 뿐이다. 진짜 답은 $\max_i dp[i]$다. 위 수열에서 그것은 $i=7$의 9이고, 구간은 $a[4..7] = [5, 2, -1, 3]$이다.

==상태를 좁히면 점화식이 서고, 대신 답을 마지막 칸에서 읽지 못한다.== 이 교환은 1차원 DP에서 계속 반복된다. [VIII-6](#/viii-6)의 LIS도 상태가 "$i$로 끝나는 증가 부분수열의 최대 길이"이고, 거기서도 답은 마지막 칸이 아니라 표 전체의 최댓값이다. **"~로 끝나는"이 1차원 DP의 기본 상태 형태이고, "~까지의"는 그것으로 점화식이 설 때만 쓴다.**

## 3. 손으로 따라가기

::: trace
$a = [3, -2, 4, -7, 5, 2, -1, 3]$. 카데인을 손으로 돌린다.

각 줄에서 후보 두 개를 다 적고 큰 쪽을 고른다. `start[i]`는 그 최적 구간이 **어디서 시작했는가**이고, 새로 시작한 줄에서만 값이 바뀐다. 맨 오른쪽 열은 지금까지 본 $dp$의 최댓값이다.

| i | a[i] | dp[i-1]+a[i] | a[i] | dp[i] | start[i] | 지금까지 최대 |
|---|---|---|---|---|---|---|
| 0 | 3 | - | - | 3 | 0 | 3 |
| 1 | -2 | 3 + (-2) = 1 | -2 | 1 | 0 | 3 |
| 2 | 4 | 1 + 4 = 5 | 4 | 5 | 0 | 5 |
| 3 | -7 | | | | | |
| 4 | 5 | | | | | |
| 5 | 2 | | | | | |
| 6 | -1 | | | | | |
| 7 | 3 | | | | | |

네 가지를 확인하라.

- [ ] `start[i]`가 처음 바뀌는 줄은 어디인가. 그 줄에서 왜 이어 붙이지 않았는가
- [ ] $dp$의 최댓값은 몇 번 칸에 있는가. 그것이 마지막 칸인가
- [ ] $dp[3] = -2$는 음수다. 이 칸을 "쓸모없다"고 0으로 덮으면 답이 달라지는가
- [ ] 같은 수열에 §2.4의 잘못된 상태 $dp[i] = \max(dp[i-1],\ dp[i-1]+a[i],\ a[i])$를 돌리면 $i=2$에서 값이 얼마가 되는가. 그 값을 내는 구간을 실제로 적어 보라
:::

::: answer
| i | a[i] | dp[i-1]+a[i] | a[i] | dp[i] | start[i] | 지금까지 최대 |
|---|---|---|---|---|---|---|
| 0 | 3 | - | - | 3 | 0 | 3 |
| 1 | -2 | 3 + (-2) = 1 | -2 | 1 | 0 | 3 |
| 2 | 4 | 1 + 4 = 5 | 4 | 5 | 0 | 5 |
| 3 | -7 | 5 + (-7) = -2 | -7 | -2 | 0 | 5 |
| 4 | 5 | -2 + 5 = 3 | 5 | **5** | **4** | 5 |
| 5 | 2 | 5 + 2 = 7 | 2 | 7 | 4 | 7 |
| 6 | -1 | 7 + (-1) = 6 | -1 | 6 | 4 | 7 |
| 7 | 3 | 6 + 3 = 9 | 3 | 9 | 4 | **9** |

첫 번째. `start`는 $i=4$에서 0에서 4로 바뀐다. 그 줄에서 $dp[3] = -2$가 음수라 이어 붙이면 5가 3으로 줄어든다. **앞이 음수면 버리는 것이 언제나 이득이다** — 이 한 줄이 카데인의 전부다.

두 번째. 최댓값 9는 $i=7$, 즉 마지막 칸에 있다. 하지만 그것은 이 수열에서 우연이다. $a$ 뒤에 $-100$을 하나 붙이면 $dp[8] = -91$이 되고 답은 여전히 9이지만 마지막 칸은 아니게 된다. ==$dp[n-1]$을 답으로 출력하는 것이 이 유형의 가장 흔한 오답이다.==

세 번째. **달라진다.** $dp[3]$을 0으로 덮으면 $dp[4] = \max(0+5, 5) = 5$로 값은 같지만, 만약 $a[4]$가 $-1$이었다면 $dp[4] = \max(0-1, -1) = -1$이 아니라 $0$이 되어 **원소를 하나도 안 고른 빈 구간**이 답 후보로 들어온다. 전부 음수인 수열에서 답이 0으로 나오는 버그가 정확히 이 경로다.

네 번째. 잘못된 상태로는 $dp[0] = 3$, $dp[1] = \max(3,\ 1,\ -2) = 3$, $dp[2] = \max(3,\ 3+4,\ 4) = 7$이다. 7을 내는 구간을 적으려면 $[0,0]$의 3에 $a[2]$의 4를 붙여야 하는데 그 사이에 $-2$가 있다. **그런 연속 구간은 존재하지 않는다.** 끝까지 돌리면 17이 나오고 정답 9와 크게 벌어진다.
:::

## 4. 구현

### 4.1 계단과 타일링

::: dual
```python title="계단·타일링 — 완전탐색, 배열판, 롤링판"
MOD = 10007


def naive(n, calls):
    """메모 없는 재귀. calls 가 곧 중복 부분문제의 양이다."""
    calls[0] += 1
    if n <= 1:
        return 1
    return naive(n - 1, calls) + naive(n - 2, calls)


def table(n):
    """dp[i] = i 번 칸에 도달하는 방법의 수. 표를 통째로 남긴다."""
    dp = [0] * (max(n, 1) + 1)
    dp[0] = 1                                   # 초기값: 아무것도 안 하는 방법 하나
    dp[1] = 1
    for i in range(2, n + 1):                   # 계산 순서: 자기보다 작은 칸만 읽는다
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD
    return dp


def rolling(n):
    """읽는 칸이 둘뿐이므로 변수 두 개면 된다. 대신 표가 사라진다."""
    prev2, prev1 = 1, 1                         # dp[0], dp[1]
    for _ in range(2, n + 1):
        prev2, prev1 = prev1, (prev1 + prev2) % MOD
    return prev1


N = 12
dp = table(N)

print("[1] 표 — 계단과 타일링이 같은 표를 쓴다")
print("    i     " + "".join(" %4d" % i for i in range(N + 1)))
print("    dp[i] " + "".join(" %4d" % dp[i] for i in range(N + 1)))

print("[2] 완전탐색 호출 수 — 서로 다른 질문은 n+1 가지뿐이다")

    calls = [0]
    v = naive(n, calls)
```

```cpp title="계단·타일링 — 완전탐색, 배열판, 롤링판"
#include <algorithm>
#include <cstdio>
#include <vector>
using namespace std;

const int MOD = 10007;

// 메모 없는 재귀. calls 가 곧 중복 부분문제의 양이다.
long long naive(int n, long long& calls) {
    calls += 1;
    if (n <= 1) return 1;
    return naive(n - 1, calls) + naive(n - 2, calls);
}

// dp[i] = i 번 칸에 도달하는 방법의 수. 표를 통째로 남긴다.
vector<int> table(int n) {
    vector<int> dp(max(n, 1) + 1, 0);
    dp[0] = 1;                                  // 초기값: 아무것도 안 하는 방법 하나
    dp[1] = 1;
    for (int i = 2; i <= n; i++)                // 계산 순서: 자기보다 작은 칸만 읽는다
        dp[i] = (dp[i - 1] + dp[i - 2]) % MOD;
    return dp;
}

// 읽는 칸이 둘뿐이므로 변수 두 개면 된다. 대신 표가 사라진다.
int rolling(int n) {
    int prev2 = 1, prev1 = 1;                   // dp[0], dp[1]
    for (int i = 2; i <= n; i++) {
        int next = (prev1 + prev2) % MOD;       // 임시 변수가 필요하다
        prev2 = prev1;
        prev1 = next;
    }
    return prev1;
}

int main() {
    const int N = 12;
    vector<int> dp = table(N);

    printf("[1] 표 — 계단과 타일링이 같은 표를 쓴다\n");
    printf("    i     ");
    for (int i = 0; i <= N; i++) printf(" %4d", i);
    printf("\n    dp[i] ");
    for (int i = 0; i <= N; i++) printf(" %4d", dp[i]);
    printf("\n");

    printf("[2] 완전탐색 호출 수 — 서로 다른 질문은 n+1 가지뿐이다\n");
    for (int n : {10, 20, 25}) {
        long long calls = 0;
        long long v = naive(n, calls);
        printf("    n=%2d  답 %7lld  호출 %9lld회  서로 다른 질문 %d개\n", n, v, calls, n + 1);
    }

    printf("[3] 세 판이 같은 답을 내는가\n");
    bool ok = true;
    for (int n = 1; n <= 20; n++) {
        long long calls = 0;
        if (naive(n, calls) % MOD != table(n)[n] || table(n)[n] != rolling(n)) ok = false;
    }
    printf("    n=1..20 완전탐색 == 배열판 == 롤링판 : %s\n", ok ? "True" : "False");
    return 0;
}
```

**복잡도:** 시간 $O(n)$ — 칸이 $n+1$개이고 칸마다 덧셈과 나머지 연산을 한 번씩 한다. 공간은 배열판이 $O(n)$(칸 수만큼), 롤링판이 $O(1)$(변수 두 개). 완전탐색은 $O(\phi^n)$ — 호출 수가 답 자체와 같은 속도로 자라기 때문이고, §1의 표가 그 지수를 실측한 것이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 롤링 갱신 | `prev2, prev1 = prev1, prev1 + prev2` — 우변이 **전부 먼저** 평가되므로 임시 변수가 필요 없다 | 대입이 순차적이라 `prev2 = prev1`을 먼저 하면 옛 `prev2`가 사라진다. `next` 변수가 필수다 |
| 큰 정수 | `naive`가 $n$이 커도 정확한 값을 낸다(임의 정밀도) | `long long`이라 $n \le 90$까지 안전하고 그 위는 오버플로다 |
| 재귀 깊이 | 기본 한도 1000. $n$이 1000을 넘으면 `naive`가 `RecursionError`로 먼저 죽는다 | 스택 한도까지 간다 |
| 배열 초기화 | `[0] * (max(n,1)+1)` | `vector<int> dp(max(n,1)+1, 0)` |

### 4.2 최대 부분합

::: dual
```python title="최대 부분합 — 잘못된 상태, 카데인, 완전탐색 대조"
a = [3, -2, 4, -7, 5, 2, -1, 3]


def wrong_state(a):
    """dp[i] = 'i 까지의 최대 부분합'. 존재하지 않는 구간을 만든다."""
    dp = a[0]
    for i in range(1, len(a)):
        dp = max(dp, dp + a[i], a[i])
    return dp


def kadane(a):
    """dp[i] = 'a[i] 로 끝나는' 최대 부분합. start[i] 는 그 구간의 시작."""
    n = len(a)
    dp = [0] * n
    start = [0] * n
    dp[0] = a[0]                                # 초기값: 첫 원소로 끝나는 구간은 자기 자신
    for i in range(1, n):
        if dp[i - 1] + a[i] >= a[i]:            # 앞 구간에 이어 붙인다
            dp[i] = dp[i - 1] + a[i]
            start[i] = start[i - 1]
        else:                                   # a[i] 혼자로 새로 시작한다
            dp[i] = a[i]
            start[i] = i
    best = 0                                    # 답은 마지막 칸이 아니라 표 전체의 최댓값
    for i in range(n):
        if dp[i] > dp[best]:
            best = i
    return dp, start, best


def brute(a):
    """모든 연속 구간을 실제로 더해 본다. 검산용."""
    best = a[0]
    for i in range(len(a)):
        s = 0
        for j in range(i, len(a)):
            s += a[j]
            if s > best:
                best = s
    return best


dp, start, best = kadane(a)
print("    a        " + "".join(" %3d" % x for x in a))
print("    dp[i]    " + "".join(" %3d" % x for x in dp))
print("    start[i] " + "".join(" %3d" % x for x in start))
print("카데인   = %d  구간 a[%d..%d] = %s"
      % (dp[best], start[best], best, str(a[start[best]:best + 1])))
print("완전탐색 = %d" % brute(a))
print("마지막 칸 dp[n-1] = %d  ← 이것을 답으로 내면 틀린다" % dp[-1])
print("잘못된 상태('i 까지') = %d  ← 존재하지 않는 구간의 합" % wrong_state(a))
```
```cpp title="최대 부분합 — 잘못된 상태, 카데인, 완전탐색 대조"
#include <algorithm>
#include <cstdio>
#include <string>
#include <vector>
using namespace std;

vector<int> a = {3, -2, 4, -7, 5, 2, -1, 3};

// dp[i] = 'i 까지의 최대 부분합'. 존재하지 않는 구간을 만든다.
long long wrong_state(const vector<int>& a) {
    long long dp = a[0];
    for (size_t i = 1; i < a.size(); i++)
        dp = max(dp, max(dp + a[i], (long long)a[i]));
    return dp;
}

// dp[i] = 'a[i] 로 끝나는' 최대 부분합. start[i] 는 그 구간의 시작.
int kadane(const vector<int>& a, vector<long long>& dp, vector<int>& start) {
    int n = a.size();
    dp.assign(n, 0);
    start.assign(n, 0);
    dp[0] = a[0];                               // 초기값: 첫 원소로 끝나는 구간은 자기 자신
    for (int i = 1; i < n; i++) {
        if (dp[i - 1] + a[i] >= a[i]) {         // 앞 구간에 이어 붙인다
            dp[i] = dp[i - 1] + a[i];
            start[i] = start[i - 1];
        } else {                                // a[i] 혼자로 새로 시작한다
            dp[i] = a[i];
            start[i] = i;
        }
    }
    int best = 0;                               // 답은 마지막 칸이 아니라 표 전체의 최댓값
    for (int i = 0; i < n; i++)
        if (dp[i] > dp[best]) best = i;
    return best;
}

// 모든 연속 구간을 실제로 더해 본다. 검산용.
long long brute(const vector<int>& a) {
    long long best = a[0];
    for (size_t i = 0; i < a.size(); i++) {
        long long s = 0;
        for (size_t j = i; j < a.size(); j++) {
            s += a[j];
            if (s > best) best = s;
        }
    }
    return best;
}

int main() {
    vector<long long> dp;
    vector<int> start;
    int best = kadane(a, dp, start);

    printf("    a        ");
    for (int x : a) printf(" %3d", x);
    printf("\n    dp[i]    ");
    for (long long x : dp) printf(" %3lld", x);
    printf("\n    start[i] ");
    for (int x : start) printf(" %3d", x);
    printf("\n");

    string seg = "[";
    for (int i = start[best]; i <= best; i++) {
        if (i > start[best]) seg += ", ";
        seg += to_string(a[i]);
    }
    seg += "]";
    printf("카데인   = %lld  구간 a[%d..%d] = %s\n", dp[best], start[best], best, seg.c_str());
    printf("완전탐색 = %lld\n", brute(a));
    printf("마지막 칸 dp[n-1] = %lld  ← 이것을 답으로 내면 틀린다\n", dp[a.size() - 1]);
    printf("잘못된 상태('i 까지') = %lld  ← 존재하지 않는 구간의 합\n", wrong_state(a));
    return 0;
}
```

이 수열에서는 마지막 칸이 우연히 답과 같다. **바로 그래서 위험하다** — 이런 입력만 보고 넘어가면 버그가 살아남는다.

**복잡도:** 시간 $O(n)$ — 원소마다 비교 한 번과 덧셈 한 번, 그리고 최댓값을 찾는 한 바퀴가 더해져 상수배다. 공간 $O(n)$ — `dp`와 `start` 배열. **구간을 출력할 필요가 없으면 공간은 $O(1)$로 떨어진다.** 현재 합과 지금까지의 최댓값 두 변수면 되기 때문이고, 그 순간 §2.3과 같은 대가로 시작 위치를 잃는다. 완전탐색은 $O(n^2)$ — 시작점 $n$가지 × 끝점 최대 $n$가지이고, 안쪽 합을 누적으로 굴려도 그 곱은 줄지 않는다.

::: pitfall
- **답으로 $dp[n-1]$을 출력한다.** "$i$로 끝나는"이라는 상태 정의를 그대로 읽으면 마지막 칸은 마지막 원소를 포함한 구간의 최대일 뿐이다. **표 전체의 최댓값**을 취해야 한다.
- **초기값이나 중간 값을 0으로 덮는다.** `best = 0`, `cur = max(0, cur + a[i])`로 짜면 원소가 전부 음수인 수열에서 답이 0으로 나온다. 빈 구간을 허용하는 문제라면 맞지만, "최소 한 개는 골라야 한다"면 틀린다. **지문을 다시 읽어라.**
- **개수 DP의 초기값을 0으로 둔다.** 계단·타일링은 $dp[0] = 1$이다. 0으로 두면 표 전체가 0이 된다.
- **`dp[1]`을 채우기 전에 $n = 0$을 넣는다.** 배열 크기가 1이면 `dp[1]`에서 인덱스 오류다. 위 코드가 `max(n, 1) + 1`로 잡은 이유다.
- **나머지 연산을 마지막에 한 번만 한다.** 방법의 수는 $n$에 지수로 자란다. C++에서 `long long`이라도 $n$이 100만이면 넘친다. 문제가 나머지를 요구하면 **덧셈마다** 취해야 한다.
- **음수 나눗셈.** 값이 음수일 수 있는 상태에 나머지를 씌우면 Python의 `%`는 항상 음이 아닌 값을, C++의 `%`는 부호를 남긴다([0-5](#/0-5)).
:::

## 5. 어디에 쓰이는가

**생물정보학의 서열 검색이 최대 부분합을 그대로 쓴다.** 두 DNA·단백질 서열을 비교할 때, 일치하면 양수 점수를 불일치하면 음수 점수를 주고 **점수 합이 최대인 연속 구간**을 찾는다. 그 구간이 "의미 있게 닮은 조각"이고, 서열 검색기가 보고하는 국소 정렬 조각의 정체다. 상태 정의가 이 절과 글자 그대로 같다 — "$i$로 끝나는 최대 점수 구간". 앞의 누적 점수가 음수가 되는 순간 버리고 새로 시작하는 것도 같다. 점수가 음수로 내려간 구간을 끌고 가면 뒤에 붙는 진짜 유사 구간의 점수만 깎기 때문이다.

**시계열 모니터링의 이상 구간 검출도 같은 모양이다.** 각 시점의 관측값에서 기준선을 뺀 편차 수열을 만들면, "편차 합이 가장 큰 연속 구간"이 곧 이상이 지속된 구간이다. 스트리밍으로 들어오는 데이터에 대해 $O(1)$ 공간으로 갱신되기 때문에 버퍼를 쌓지 않고 한 번 지나가며 처리할 수 있다. §2.3의 롤링이 여기서 성능 최적화가 아니라 **가능·불가능의 문제**가 된다.

**세그먼트 트리의 구간 최대 부분합 노드**도 이 점화식의 확장이다([IX-2](#/ix-2)). 노드마다 "구간 전체 합 / 왼쪽 끝에서 시작하는 최대 / 오른쪽 끝에서 끝나는 최대 / 구간 안의 최대"를 들고 있으면 두 자식을 합칠 수 있는데, 그중 세 번째가 정확히 이 절의 $dp[i]$를 구간 단위로 일반화한 것이다.

- 신호어: "한 칸 또는 두 칸씩", "~하는 방법의 수", "채우는 경우의 수", "연속한 몇 개를 골라", "연속된 며칠 동안의 합이 최대", "이어지는 구간"

- 혼동 주의: 고르는 것이 연속 구간이 아니라 **순서만 지킨 부분수열**이면 → [VIII-6 LIS](#/viii-6). 축이 하나 더 필요하면(격자의 두 좌표, 두 문자열) → [VIII-4](#/viii-4), 용량이 붙으면 → [VIII-5 배낭](#/viii-5). 구간 합을 **묻기만** 하고 최적화가 없으면 DP가 아니라 [VI-4 누적 합](#/vi-4)이다. 창을 늘였다 줄이며 조건을 유지하는 문제면 [VI-3 투 포인터](#/vi-3)
- 반례 함정: 상태를 "$i$**까지의** 최대"로 잡으면 존재하지 않는 구간의 합이 나온다(무작위 입력의 48.8%에서 틀린다). 그리고 "$i$**로 끝나는**"으로 제대로 잡은 뒤 답을 $dp[n-1]$로 출력하는 것, 원소가 전부 음수인 수열에서 0을 답으로 내는 것
:::

::: interview
**"최대 부분합을 $O(n)$에 푸는 방법을 설명해 보라."**

코드가 아니라 **상태 정의부터** 말하는 것이 답의 핵심이다. "$dp[i]$를 '$a[i]$로 끝나는 최대 부분합'으로 잡습니다. 그러면 $dp[i]$는 앞 구간에 이어 붙이거나 혼자 새로 시작하거나 둘 중 하나라 $\max(dp[i-1]+a[i],\ a[i])$가 됩니다. 답은 $dp[n-1]$이 아니라 $dp$ 전체의 최댓값입니다."

이어서 거의 반드시 **"왜 '$i$까지의 최대'로 잡으면 안 되는가"**가 붙는다. 준비된 답은 이렇다 — "그 상태로는 $dp[i-1]$이 어디서 끝난 구간인지 알 수 없어서, 이어 붙이는 순간 중간이 끊긴 구간의 합이 나옵니다. `[3, -2, 4]`에서 3과 4를 이어 붙여 7이 나오는 식입니다."
:::

## 연습

::: quiz
**상태 문장을 먼저 쓴다. "$i$로 끝나는"인지 "$i$까지의"인지를 그 자리에서 정하고, 왜 그쪽인지 한 줄로 말할 수 있어야 한다.**

**1. 백준 1912 연속합 (실버 2)** — https://www.acmicpc.net/problem/1912
- 신호: "연속된 몇 개의 수를 선택해서 구할 수 있는 합 중 가장 큰 합". "수는 한 개 이상 선택해야 한다"는 문장이 §4.2의 두 번째 함정을 정면으로 겨눈다.
- 상태: $dp[i]$ = $a[i]$로 끝나는 최대 부분합. "$i$까지의"로 잡으면 §2.4의 17이 나온다.
- 자료구조: 배열 하나, 또는 변수 두 개. 답을 마지막 칸이 아니라 최댓값으로 읽는 것을 잊지 마라. $n \le 100{,}000$이라 $O(n^2)$은 통과하지 못한다.

**2. 백준 11726 2×n 타일링 (실버 3)** — https://www.acmicpc.net/problem/11726
- 신호: "채우는 방법의 수". 최솟값이 아니라 개수이므로 $\max$가 $+$로 바뀐다.
- 상태: $dp[n]$ = $2 \times n$을 덮는 방법의 수. §2.2의 배타성 논증을 스스로 다시 세워 보라 — 왜 가로 타일을 "두 장씩" 세면 중복이 아닌가.
- 자료구조: 배열 하나. 답을 10007로 나눈 나머지로 요구하므로 **덧셈마다** 나머지를 취한다.

**3. 백준 2579 계단 오르기 (실버 3)** — https://www.acmicpc.net/problem/2579
- 신호: "연속된 세 개의 계단을 모두 밟아서는 안 된다". §2.1의 계단인데 조건이 하나 붙었고, **그 조건 때문에 상태가 부족해진다.**
- 상태: $dp[i]$만으로는 안 된다. $i$번 계단을 밟을 때 "직전 계단도 밟았는가"를 알아야 하므로 상태에 축이 하나 더 필요하다. $dp[i][0]$과 $dp[i][1]$로 가르거나, 점화식에서 두 칸 뒤까지 직접 참조하는 두 가지 표현이 있다.
- 자료구조: 배열 하나 또는 $n \times 2$ 배열. **상태가 부족할 때 무엇이 깨지는지**를 먼저 관찰하라 — 그것이 [VIII-11](#/viii-11)의 주제다.

**4. 백준 13398 연속합 2 (골드 4)** — https://www.acmicpc.net/problem/13398
- 신호: "수를 하나 제거할 수 있다". 1912에 선택지가 하나 붙었을 뿐인데 상태가 부족해진다.
- 상태: $dp[i][0]$ = $a[i]$로 끝나면서 아직 아무것도 안 지운 최대합, $dp[i][1]$ = 하나 지운 최대합. **"이미 썼는가"를 상태에 넣는 것**이 이 유형의 표준 대응이다.
- 자료구조: 배열 두 줄. $dp[i][1]$이 어디서 오는지가 전부다 — 지금 지우거나($dp[i-1][0]$), 전에 지웠거나($dp[i-1][1] + a[i]$).
:::

## 요약

- 1차원 DP는 상태가 **정수 하나**로 끝나는 문제다. 계단·타일링·최대 부분합이 그 원형이다.
- 계단과 타일링은 같은 점화식 $dp[i] = dp[i-1] + dp[i-2]$를 쓴다. 표면이 달라도 **분해 구조가 같으면 점화식이 같다.**
- 개수를 세는 DP는 초기값이 $dp[0] = 1$이고, 경우를 **배타적으로** 갈라야 한다. 겹치면 그 자리에서 틀린다.
- 읽는 칸이 몇 개 안 되면 배열을 버리고 변수 몇 개로 접을 수 있다. **대신 역추적과 나중 질의가 죽는다.**
- 최대 부분합에서 상태를 "$i$까지의 최대"로 잡으면 **점화식이 서지 않는다.** 이어 붙일 앞 구간의 끝점을 알 수 없어 존재하지 않는 구간의 합이 나온다. 무작위 입력의 48.8%에서 틀린다.
- 상태를 "$i$**로 끝나는**"으로 좁히면 점화식이 서고, 대신 답을 마지막 칸에서 읽지 못한다. $\max_i dp[i]$가 답이다.
- 원소가 전부 음수일 수 있으면 0으로 초기화하지 마라. 빈 구간을 허용하는지 지문에서 확인한다.
