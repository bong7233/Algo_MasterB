# VIII-7 구간 DP

::: lead
구간을 두 조각으로 자르는 위치가 상태가 되면, 표를 채우는 순서가 행 우선이 아니라 구간 길이 순이어야 한다. 그 이유가 이 절의 전부다.
:::

## 1. 문제

행렬 네 개를 순서대로 곱해야 한다.

```text nolines
   A1 (10 x 100)   A2 (100 x 5)   A3 (5 x 50)   A4 (50 x 20)
```

$N \times M$ 행렬과 $M \times K$ 행렬을 곱하면 결과는 $N \times K$이고, 그때 필요한 스칼라 곱셈은 $N \times M \times K$번이다. 행렬 곱셈은 **결합법칙을 만족한다.** 어느 쌍부터 곱하든 최종 결과 행렬은 완전히 같다.

비용은 같지 않다.

```text nolines
   ((A1 A2) A3) A4  =  5000 + 2500 + 10000  =  17500
   ((A1 A2) (A3 A4))=  5000 + 5000 +  1000  =  11000
```

같은 답을 내는 데 한쪽이 1.6배를 쓴다. 그리고 앞의 것은 아무렇게나 고른 순서가 아니다. **"지금 당장 가장 싼 인접 쌍부터 합친다"**는 규칙이 정확히 그 순서를 만든다. 처음에는 5,000짜리 `A1A2`가 제일 싸고, 그다음에는 2,500짜리가 제일 싸다. 매 단계 최선을 골랐는데 전체는 최선이 아니다. 무작위 차원으로 400번 대조하면 **227번(56.8%)에서 이 그리디가 최적을 놓친다**(측정 스크립트 `tools/bench/viii7_interval_dp.py`).

그러면 괄호를 치는 모든 방법을 다 세면 된다. 행렬 $n$개의 괄호 배치 수는 카탈란 수 $C_{n-1}$이고, 재귀 호출 수는 $3^{n-1}$로 자란다.

```text nolines
   n =  4      괄호 배치       5 가지     호출        27
   n =  8      괄호 배치     429 가지     호출     2,187
   n = 10      괄호 배치   4,862 가지     호출    19,683
   n = 13      괄호 배치 208,012 가지     호출   531,441
```

$n$이 500까지 오는 문제 앞에서 이 방향은 없다. 그런데 [VIII-1](#/viii-1)이 말한 그 격차가 여기에도 있다 — 호출 53만 번이 실제로 푸는 서로 다른 부분문제는 몇 개인가.

## 2. 아이디어

### 2.1 상태가 부분집합이 아니라 구간인 이유

[VIII-5](#/viii-5)의 배낭에서 상태의 한 축은 "앞에서 몇 개까지 봤는가"였고, 고른 것들은 흩어져 있어도 됐다. 여기서는 안 된다.

행렬 곱셈에는 **교환법칙이 없다.** `A1 A3`는 아예 만들 수 없는 곱이다. 그래서 계산 도중에 존재할 수 있는 중간 결과는 예외 없이 **연속한 묶음** $A_i \cdots A_j$ 하나다. `{A1, A3}` 같은 부분집합은 이 문제의 부분문제가 아니다.

부분문제가 구간이면 상태도 구간이다.

> $dp[i][j]$ = 행렬 $A_i$부터 $A_j$까지를 하나로 곱치는 데 드는 **최소 스칼라 곱셈 횟수**

상태 수는 $i \le j$인 쌍의 개수라 $O(n^2)$이다. 완전탐색의 $3^{n-1}$이 여기로 접힌다.

### 2.2 마지막 결정은 "맨 마지막에 하는 곱셈"이다

[VIII-1](#/viii-1) §2.3의 방법을 그대로 쓴다. 최적해가 이미 있다고 가정하고 **마지막 결정 하나를 떼어 낸다.**

구간 $[i, j]$를 하나로 만드는 어떤 방법이든, 맨 마지막에 하는 곱셈은 딱 한 번이다. 그 곱셈의 두 피연산자는 각각 연속 묶음이고 둘이 붙어 $[i, j]$를 덮어야 한다. 그러므로 어떤 $k$가 있어서 왼쪽은 $[i, k]$, 오른쪽은 $[k+1, j]$다.

```text nolines
   i          k  k+1            j
   [ A i ... A k ][ A k+1 ... A j ]
     ----------      ------------
      dp[i][k]        dp[k+1][j]        <- 안쪽을 어떻게 곱했든 여기까지의 최소 비용
     d[i-1] x d[k]   d[k] x d[j]        <- 두 중간 결과의 크기
              \        /
        d[i-1] x d[k] x d[j]            <- 마지막 곱셈 한 번의 비용
```

여기가 급소다. **두 중간 결과의 크기는 $k$ 하나로 정해진다.** 안쪽을 어떤 순서로 곱했든 $[i, k]$의 결과는 언제나 $d_{i-1} \times d_k$ 행렬이다. 그래서 마지막 곱셈의 비용이 안쪽 선택과 무관해지고, 안쪽은 각자 최소로 만들면 그만이다. 이것이 최적 부분구조가 성립하는 자리다.

$$dp[i][j] = \min_{i \le k < j} \big( dp[i][k] + dp[k+1][j] + d_{i-1} \cdot d_k \cdot d_j \big)$$

$k$는 **자르는 위치**이지 고르는 원소가 아니다. `k`를 원소로 읽으면 점화식이 무너진다.

초기값은 $dp[i][i] = 0$이다. 행렬 하나짜리 구간은 곱할 것이 없다.

### 2.3 계산 순서 — 이 절의 본론

::: widget dp-table {"kind":"interval","dims":[10,100,5,50,20]}
:::

위젯은 §1의 네 행렬로 표를 채운다. 볼 것은 값이 아니라 **어느 칸에서 화살표가 나오는가**다.

$dp[i][j]$가 읽는 칸은 둘이다. $dp[i][k]$는 **같은 행의 왼쪽**이고, $dp[k+1][j]$는 **같은 열의 아래**다. [VIII-4](#/viii-4)의 격자 DP가 위와 왼쪽만 읽던 것과 다르다. 아래를 읽는 순간, 왼쪽 위에서 오른쪽 아래로 훑는 관성이 깨진다.

행 우선으로 채워 보면 어디서 깨지는지가 정확히 보인다. $i=1$ 행을 왼쪽부터 채우면 두 번째로 $dp[1][3]$을 만난다. 그 칸의 후보 $k=1$은 $dp[1][1] + dp[2][3] + \cdots$인데, **$dp[2][3]$은 2행이라 아직 손도 대지 않았다.** 배열이 0으로 초기화되어 있으면 이 자리에서 예외가 나지 않는다. 0을 읽고 계산이 그대로 진행되어 답이 조용히 작아진다.

읽는 두 칸의 공통점은 하나뿐이다. **구간 길이 $j - i + 1$이 자기보다 짧다.** $[i, k]$도 $[k+1, j]$도 $[i, j]$의 진부분구간이기 때문이다. 그러니 길이를 축으로 삼으면 순서가 저절로 지켜진다.

```text nolines
   L = 1    [1,1] [2,2] [3,3] [4,4]        <- 기저. 전부 0
   L = 2    [1,2] [2,3] [3,4]              <- L=1 만 읽는다
   L = 3    [1,3] [2,4]                    <- L=1, 2 만 읽는다
   L = 4    [1,4]                          <- L=1, 2, 3 만 읽는다
```

표 위에서는 대각선 띠가 오른쪽 위로 한 칸씩 올라가는 모양이다. **구간 DP의 정체는 점화식이 아니라 이 순서다.** 점화식은 세 줄이면 쓰지만, 순서를 틀리면 코드가 돌면서 틀린 답을 낸다.

## 3. 손으로 따라가기

::: trace
$d = [10, 100, 5, 50, 20]$. 즉 $A_1$은 $10 \times 100$, $A_2$는 $100 \times 5$, $A_3$은 $5 \times 50$, $A_4$는 $50 \times 20$이다.

길이 $L$ 순으로 채운다. 각 칸에서 후보 $k$를 전부 적고 최솟값을 고른다.

| L | 구간 | 후보 (dp 왼쪽 + dp 오른쪽 + 마지막 곱셈) | dp | 자른 위치 k |
|---|---|---|---|---|
| 1 | [1,1] [2,2] [3,3] [4,4] | 기저 | 0 | - |
| 2 | [1,2] | k=1: 0 + 0 + 10·100·5 = 5000 | 5000 | 1 |
| 2 | [2,3] | k=2: 0 + 0 + 100·5·50 = 25000 | 25000 | 2 |
| 2 | [3,4] | k=3: 0 + 0 + 5·50·20 = 5000 | 5000 | 3 |
| 3 | [1,3] | | | |
| 3 | [2,4] | | | |
| 4 | [1,4] | | | |

채운 뒤 세 가지를 확인하라.

- [ ] $dp[1][4]$를 채울 때 읽는 칸을 전부 적어라. 그 시점에 여섯 칸이 모두 채워져 있는가
- [ ] **행 우선으로 채웠다면** $dp[1][3]$의 $k=1$ 후보가 읽는 칸은 무엇이고, 그 칸은 그때 채워져 있는가
- [ ] `자른 위치 k` 열을 $[1,4]$부터 재귀로 따라가면 괄호가 어떻게 쳐지는가
:::

::: answer
| L | 구간 | 후보 | dp | 자른 위치 k |
|---|---|---|---|---|
| 1 | [1,1] [2,2] [3,3] [4,4] | 기저 | 0 | - |
| 2 | [1,2] | k=1: 0 + 0 + 10·100·5 = 5000 | 5000 | 1 |
| 2 | [2,3] | k=2: 0 + 0 + 100·5·50 = 25000 | 25000 | 2 |
| 2 | [3,4] | k=3: 0 + 0 + 5·50·20 = 5000 | 5000 | 3 |
| 3 | [1,3] | k=1: 0 + 25000 + 50000 = 75000 / k=2: 5000 + 0 + 2500 = 7500 | 7500 | 2 |
| 3 | [2,4] | k=2: 0 + 5000 + 10000 = 15000 / k=3: 25000 + 0 + 100000 = 125000 | 15000 | 2 |
| 4 | [1,4] | k=1: 0 + 15000 + 20000 = 35000 / k=2: 5000 + 5000 + 1000 = 11000 / k=3: 7500 + 0 + 10000 = 17500 | 11000 | 2 |

첫 번째. $dp[1][4]$는 $k$ 세 개마다 두 칸씩, $dp[1][1]\,dp[2][4]$ / $dp[1][2]\,dp[3][4]$ / $dp[1][3]\,dp[4][4]$를 읽는다. 여섯 칸의 구간 길이는 각각 1, 3, 2, 2, 3, 1이고 **전부 4보다 짧다.** 길이 3까지 다 채운 뒤에 길이 4를 시작했으므로 여섯 칸이 모두 확정되어 있다.

두 번째. $k=1$ 후보는 $dp[1][1] + dp[2][3] + 10 \cdot 100 \cdot 50$이다. 행 우선이면 $dp[2][3]$은 2행이라 아직 비어 있다. 0으로 읽으면 이 후보가 $50{,}000$이 되어 진짜 값 $75{,}000$보다 작아진다. **틀린 값이 더 작으므로 $\min$이 그것을 고른다.** 오답이 오답을 부르는 방향이 최솟값 문제에서는 항상 이쪽이다. 최종 답은 11,000이 아니라 **6,000**이 나온다(§4의 `[5]` 줄이 그 값이다). 무작위 차원 300번 중 **290번**에서 행 우선이 틀린 답을 낸다.

세 번째. $[1,4]$의 $k$가 2이므로 $(A_1 A_2)(A_3 A_4)$로 갈린다. $[1,2]$의 $k$는 1, $[3,4]$의 $k$는 3이라 각각 더 쪼갤 것이 없다. 괄호는 $((A_1 A_2)(A_3 A_4))$이고 §1에서 본 11,000짜리 순서다. **자른 위치를 적어 두지 않으면 비용은 알아도 순서는 모른다.**
:::

## 4. 구현

### 4.1 행렬 곱셈 순서

::: dual
```python title="행렬 곱셈 순서 — 길이 순으로 채우고 괄호를 복원한다"
d = [10, 100, 5, 50, 20]                    # A_i 는 d[i-1] x d[i] 행렬
INF = 10 ** 18

n = len(d) - 1
dp = [[0] * (n + 1) for _ in range(n + 2)]  # dp[i][j] = 구간 [i,j]를 하나로 곱치는 최소 곱셈 수
sp = [[0] * (n + 1) for _ in range(n + 2)]  # sp[i][j] = 그때 마지막으로 자른 위치 k
for L in range(2, n + 1):                   # 계산 순서: 짧은 구간부터. 길이 L은 L-1 이하만 읽는다
    for i in range(1, n - L + 2):
        j = i + L - 1
        dp[i][j] = INF
        for k in range(i, j):               # k = 마지막 곱셈이 가르는 위치
            t = dp[i][k] + dp[k + 1][j] + d[i - 1] * d[k] * d[j]
            if t < dp[i][j]:
                dp[i][j] = t
                sp[i][j] = k


def paren(i, j):
    """sp 를 따라가며 괄호를 복원한다."""
    if i == j:
        return "A%d" % i
    k = sp[i][j]
    return "(" + paren(i, k) + paren(k + 1, j) + ")"


def brute(i, j, calls):
    """모든 괄호 배치를 다 만들어 본다."""
    calls[0] += 1
    if i == j:
        return 0
    best = INF
    for k in range(i, j):
        t = brute(i, k, calls) + brute(k + 1, j, calls) + d[i - 1] * d[k] * d[j]
        if t < best:
            best = t
    return best


def row_major():
    """행 우선으로 채운다 — 아직 안 채운 칸을 0으로 읽는다."""
    bad = [[0] * (n + 1) for _ in range(n + 2)]
    for i in range(1, n + 1):
        for j in range(i + 1, n + 1):
            bad[i][j] = INF
            for k in range(i, j):
                t = bad[i][k] + bad[k + 1][j] + d[i - 1] * d[k] * d[j]
                if t < bad[i][j]:
                    bad[i][j] = t
    return bad[1][n]


print("[1] 행렬 " + "  ".join("A%d:%dx%d" % (i, d[i - 1], d[i]) for i in range(1, n + 1)))
print("[2] 길이 순으로 채운 dp")
print("    i\\j" + "".join("%7d" % j for j in range(1, n + 1)))
for i in range(1, n + 1):
    row = "".join("%7s" % ("-" if j < i else dp[i][j]) for j in range(1, n + 1))
    print("    %3d" % i + row)
calls = [0]
print("[3] 최적 괄호 = %s  곱셈 %d회" % (paren(1, n), dp[1][n]))
print("[4] 완전탐색 = %d  호출 %d회" % (brute(1, n, calls), calls[0]))
print("[5] 행 우선 = %d  ← 아직 안 채운 칸을 0으로 읽은 값" % row_major())
```
```cpp title="행렬 곱셈 순서 — 길이 순으로 채우고 괄호를 복원한다"
#include <cstdio>
#include <string>
#include <vector>
using namespace std;

vector<long long> d = {10, 100, 5, 50, 20};     // A_i 는 d[i-1] x d[i] 행렬
const long long INF = 1000000000000000000LL;

int n = (int)d.size() - 1;
vector<vector<long long>> dp, sp;

string paren(int i, int j) {                    // sp 를 따라가며 괄호를 복원한다
    if (i == j) return "A" + to_string(i);
    int k = (int)sp[i][j];
    return "(" + paren(i, k) + paren(k + 1, j) + ")";
}

long long brute(int i, int j, long long& calls) {   // 모든 괄호 배치를 다 만들어 본다
    calls += 1;
    if (i == j) return 0;
    long long best = INF;
    for (int k = i; k < j; k++) {
        long long t = brute(i, k, calls) + brute(k + 1, j, calls) + d[i - 1] * d[k] * d[j];
        if (t < best) best = t;
    }
    return best;
}

long long row_major() {                         // 행 우선 — 아직 안 채운 칸을 0으로 읽는다
    vector<vector<long long>> bad(n + 2, vector<long long>(n + 1, 0));
    for (int i = 1; i <= n; i++)
        for (int j = i + 1; j <= n; j++) {
            bad[i][j] = INF;
            for (int k = i; k < j; k++) {
                long long t = bad[i][k] + bad[k + 1][j] + d[i - 1] * d[k] * d[j];
                if (t < bad[i][j]) bad[i][j] = t;
            }
        }
    return bad[1][n];
}

int main() {
    dp.assign(n + 2, vector<long long>(n + 1, 0));  // dp[i][j] = 구간 [i,j]를 하나로 곱치는 최소 곱셈 수
    sp.assign(n + 2, vector<long long>(n + 1, 0));  // sp[i][j] = 그때 마지막으로 자른 위치 k
    for (int L = 2; L <= n; L++)                    // 계산 순서: 짧은 구간부터. 길이 L은 L-1 이하만 읽는다
        for (int i = 1; i + L - 1 <= n; i++) {
            int j = i + L - 1;
            dp[i][j] = INF;
            for (int k = i; k < j; k++) {           // k = 마지막 곱셈이 가르는 위치
                long long t = dp[i][k] + dp[k + 1][j] + d[i - 1] * d[k] * d[j];
                if (t < dp[i][j]) { dp[i][j] = t; sp[i][j] = k; }
            }
        }

    printf("[1] 행렬 ");
    for (int i = 1; i <= n; i++) printf("%sA%d:%lldx%lld", i > 1 ? "  " : "", i, d[i - 1], d[i]);
    printf("\n[2] 길이 순으로 채운 dp\n    i\\j");
    for (int j = 1; j <= n; j++) printf("%7d", j);
    for (int i = 1; i <= n; i++) {
        printf("\n    %3d", i);
        for (int j = 1; j <= n; j++) {
            if (j < i) printf("%7s", "-");
            else printf("%7lld", dp[i][j]);
        }
    }
    long long calls = 0;
    printf("\n[3] 최적 괄호 = %s  곱셈 %lld회\n", paren(1, n).c_str(), dp[1][n]);
    long long b = brute(1, n, calls);
    printf("[4] 완전탐색 = %lld  호출 %lld회\n", b, calls);
    printf("[5] 행 우선 = %lld  ← 아직 안 채운 칸을 0으로 읽은 값\n", row_major());
    return 0;
}
```

```console
[3] 최적 괄호 = ((A1A2)(A3A4))  곱셈 11000회
[4] 완전탐색 = 11000  호출 27회
[5] 행 우선 = 6000  ← 아직 안 채운 칸을 0으로 읽은 값
```

`[4]`가 `[3]`과 같다는 것이 점화식과 초기값이 옳다는 증거이고, `[5]`가 더 작다는 것이 **계산 순서만 틀려도 답이 무너진다**는 증거다.

**복잡도:** 시간 $O(n^3)$ — 구간 $(i, j)$ 쌍이 $\binom{n}{2}$개이고 구간 하나마다 분할점 $k$를 $j - i$개 본다. 총 시도 횟수는 $\sum_{i<j}(j-i) = \binom{n+1}{3} = n(n^2-1)/6$이다. 공간 $O(n^2)$ — `dp`와 `sp` 두 개의 $n \times n$ 표. 복원은 구간을 재귀로 쪼개므로 $O(n)$이다.

::: perf
같은 구간 DP를 $n$을 키우며 잰 시간이다. 세 번째 열이 위 복잡도의 $n(n^2-1)/6$이다.

| 100 | 166,650 | 0.034 s | 0.0002 s |
| 300 | 4,499,950 | 1.16 s | 0.0065 s |
| 500 | 20,833,250 | 6.9 s | 0.037 s |
| 1,000 | 166,666,500 | — | 0.38 s |

$n$이 세 배가 되면 분할점 시도가 27배가 되고 실측 시간도 30배 안팎으로 뛴다. 세제곱이 눈에 그대로 보인다. 같은 $n=300$에서 두 언어의 차이가 **약 180배**이고, 이것이 판단을 바꾼다 — 제약이 $n \le 500$이면 C++은 여유롭고 파이썬은 시간 제한 안에 못 들어간다([0-10](#/0-10)).

### 4.2 팰린드롬 분할 — 구간 표를 만들고 그 위에서 1차원 DP

문자열을 팰린드롬 조각으로 쪼갤 때 조각 수를 최소로 하는 문제다. 여기서도 같은 순서 규칙이 나온다. `pal[i][j]`는 **안쪽 구간** `pal[i+1][j-1]`을 읽으므로 길이 순으로 채워야 한다.

::: dual
```python title="팰린드롬 분할 — 구간 표 + 최소 조각 수"
s = "ABBACDC"
INF = 10 ** 9

n = len(s)
pal = [[False] * (n + 2) for _ in range(n + 2)]     # pal[i][j] = s[i..j]가 팰린드롬인가 (1-based)
for L in range(1, n + 1):                           # 여기도 길이 순이다: 길이 L은 길이 L-2를 읽는다
    for i in range(1, n - L + 2):
        j = i + L - 1
        if L == 1:
            pal[i][j] = True
        elif L == 2:
            pal[i][j] = s[i - 1] == s[j - 1]
        else:
            pal[i][j] = s[i - 1] == s[j - 1] and pal[i + 1][j - 1]

cut = [INF] * (n + 1)                               # cut[j] = 앞 j글자를 나누는 최소 조각 수
back = [0] * (n + 1)
cut[0] = 0
for j in range(1, n + 1):
    for i in range(1, j + 1):
        if pal[i][j] and cut[i - 1] + 1 < cut[j]:
            cut[j] = cut[i - 1] + 1
            back[j] = i

piece, j = [], n
while j > 0:
    piece.append(s[back[j] - 1:j])
    j = back[j] - 1
piece.reverse()

print("[1] s = %s" % s)
print("[2] 팰린드롬 표 (# = 맞다, . = 아니다)")
print("    i\\j" + "".join("%3d" % j for j in range(1, n + 1)))
for i in range(1, n + 1):
    print("    %3d" % i + "".join("%3s" % ("#" if pal[i][j] else ".") if j >= i else "%3s" % " "
                                 for j in range(1, n + 1)))
print("[3] cut[j]")
print("    j  " + "".join("%3d" % j for j in range(n + 1)))
print("    cut" + "".join("%3d" % cut[j] for j in range(n + 1)))
print("[4] 답 = %d 조각: %s" % (cut[n], " | ".join(piece)))
```
```cpp title="팰린드롬 분할 — 구간 표 + 최소 조각 수"
#include <algorithm>
#include <cstdio>
#include <string>
#include <vector>
using namespace std;

int main() {
    string s = "ABBACDC";
    const int INF = 1000000000;

    int n = (int)s.size();
    vector<vector<bool>> pal(n + 2, vector<bool>(n + 2, false));   // pal[i][j] = s[i..j]가 팰린드롬인가 (1-based)
    for (int L = 1; L <= n; L++)                                   // 여기도 길이 순이다: 길이 L은 길이 L-2를 읽는다
        for (int i = 1; i + L - 1 <= n; i++) {
            int j = i + L - 1;
            if (L == 1) pal[i][j] = true;
            else if (L == 2) pal[i][j] = s[i - 1] == s[j - 1];
            else pal[i][j] = s[i - 1] == s[j - 1] && pal[i + 1][j - 1];
        }

    vector<int> cut(n + 1, INF);                                   // cut[j] = 앞 j글자를 나누는 최소 조각 수
    vector<int> back(n + 1, 0);
    cut[0] = 0;
    for (int j = 1; j <= n; j++)
        for (int i = 1; i <= j; i++)
            if (pal[i][j] && cut[i - 1] + 1 < cut[j]) {
                cut[j] = cut[i - 1] + 1;
                back[j] = i;
            }

    vector<string> piece;
    for (int j = n; j > 0; j = back[j] - 1)
        piece.push_back(s.substr(back[j] - 1, j - back[j] + 1));
    reverse(piece.begin(), piece.end());

    printf("[1] s = %s\n", s.c_str());
    printf("[2] 팰린드롬 표 (# = 맞다, . = 아니다)\n    i\\j");
    for (int j = 1; j <= n; j++) printf("%3d", j);
    for (int i = 1; i <= n; i++) {
        printf("\n    %3d", i);
        for (int j = 1; j <= n; j++) printf("%3s", j < i ? " " : (pal[i][j] ? "#" : "."));
    }
    printf("\n[3] cut[j]\n    j  ");
    for (int j = 0; j <= n; j++) printf("%3d", j);
    printf("\n    cut");
    for (int j = 0; j <= n; j++) printf("%3d", cut[j]);
    printf("\n[4] 답 = %d 조각: ", cut[n]);
    for (size_t z = 0; z < piece.size(); z++) printf("%s%s", z ? " | " : "", piece[z].c_str());
    printf("\n");
    return 0;
}
```

**복잡도:** 시간 $O(n^2)$ — `pal` 표는 칸이 $O(n^2)$개이고 칸마다 글자 비교 한 번과 안쪽 칸 조회 한 번이라 상수 작업이다. `cut`도 $j$마다 $i$를 훑어 $O(n^2)$다. **여기서 $k$를 훑는 세 번째 루프가 없는 이유는 `pal`이 조각의 유효성만 판정하기 때문**이고, 그래서 같은 구간 DP인데도 $n^3$이 아니라 $n^2$이다. 공간 $O(n^2)$ — 표 전체. 길이 2,500이면 625만 칸이고, `bool`이면 6 MB이지만 `int`로 잡으면 25 MB다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 큰 값 | `INF = 10 ** 18`. 정수가 임의 정밀도라 더해도 안전 | `long long`. 차원이 500이면 항 하나가 $1.25 \times 10^8$이고 구간마다 누적되어 `int` 범위를 넘는다 |
| 2차원 표 만들기 | `[[0] * (n + 1) for _ in range(n + 2)]`. `[[0] * m] * n`은 같은 행을 공유한다([0-2](#/0-2)) | `vector<vector<long long>>(n+2, vector<long long>(n+1, 0))` |
| 불리언 표 | `[[False] * m for _ in range(n)]` — 그냥 리스트다 | `vector<vector<bool>>`는 비트로 압축된 특수화라 `bool&` 참조를 못 얻는다. 읽고 쓰기만 하는 이 코드에서는 문제없지만 참조를 넘기려는 순간 컴파일이 막힌다([0-6](#/0-6)) |
| 부분 문자열 | `s[a:b]` — 끝 **위치** | `s.substr(pos, len)` — 두 번째 인자가 **길이**다. 의미가 다르므로 그대로 옮기면 틀린다 |
| 문자열 연결로 괄호 만들기 | `"(" + ... + ")"` | `to_string(i)`로 숫자를 문자열로 바꿔야 한다 |

::: pitfall
- **행 우선으로 채운다.** 이 절의 주제이자 실제로 가장 많이 나오는 결함이다. 예외가 아니라 오답으로 끝난다 — §1의 입력에서 11,000 대신 6,000이 나오고, 무작위 300회 중 290회에서 틀린다.
- **`dp[i][j]`를 `INF`로 초기화하지 않는다.** 0으로 두면 첫 후보와 비교할 때 이미 0이 최소라 아무 후보도 채택되지 않는다. 답이 전부 0이 된다.
- **차원 인덱스를 헷갈린다.** 마지막 곱셈 비용은 `d[i-1] * d[k] * d[j]`다. `d[i]`로 쓰면 예제에서도 틀리지만, 정사각 행렬만 있는 예제로 시험하면 통과한다.
- **`k`의 범위를 `range(i, j+1)`로 쓴다.** $k = j$면 오른쪽 구간이 $[j+1, j]$가 되어 빈 구간을 읽는다. $k$는 $j$ 직전까지다.
- **C++에서 `int`로 누적한다.** 차원이 500이면 항 하나가 $1.25 \times 10^8$이고 구간이 수백 개 겹치면 즉시 넘친다. `long long`으로 간다.
- **팰린드롬 표를 `i` 오름차순으로 채운다.** `pal[i][j]`는 `pal[i+1][j-1]`, 즉 **아래쪽 행**을 읽는다. 행 우선이면 아직 없다. 같은 함정이 형태만 바꿔 두 번 나온다.
- **원형 구간에 그대로 쓴다.** 지문에 "원형으로 이어져 있다"가 있으면 배열을 두 배로 이어 붙이고 길이 $n$짜리 구간만 답 후보로 본다.
:::

## 5. 어디에 쓰이는가

**행렬 곱셈 라이브러리가 실제로 이 DP를 돌린다.** NumPy의 `multi_dot`은 행렬 여러 개를 받으면 곱하기 전에 먼저 이 절의 표를 채워 괄호 순서를 정한 뒤 그 순서로 곱한다. 순서를 잘못 고르면 계산량이 몇 배가 되고, 그 손해가 표를 채우는 $O(n^3)$보다 훨씬 크기 때문이다. 텐서 여러 개를 줄이는 `einsum`의 경로 선택도 같은 문제인데, 그쪽은 축이 사슬이 아니라 일반 그래프라 상태가 구간이 아니라 부분집합이 되고 [VIII-9](#/viii-9)의 비트마스크 DP로 넘어간다.

**관계형 데이터베이스의 조인 순서 결정이 같은 계보다.** 조인도 결합법칙만 있고 교환 순서에 따라 중간 결과의 **행 수**가 달라진다. 옵티마이저는 "이 순서로 조인하면 중간 결과가 몇 행인가"를 비용으로 두고 부분문제를 표에 쌓는다. 조인 그래프가 한 줄로 이어진 사슬이면 부분문제가 정확히 구간이라 이 절의 식과 같은 모양이 되고, 그렇지 않으면 부분집합 DP로 커진다. **"결합법칙은 있는데 비용은 순서에 의존한다"**가 이 유형의 정체이고, 행렬과 조인은 그 조건을 만족하는 서로 다른 두 연산일 뿐이다.

**병합 순서 문제에서는 인접 제약의 유무가 알고리즘을 가른다.** 파일 두 개를 합칠 때 비용이 두 크기의 합이라고 하자. 아무 두 개나 합쳐도 되면 가장 작은 둘부터 합치는 그리디가 최적이고 우선순위 큐로 $O(n \log n)$에 끝난다([II-8](#/ii-8)). **연속한 것끼리만 합쳐야 한다는 조건이 붙는 순간** 그리디가 깨지고 구간 DP가 된다. 지문에서 "연속"이라는 단어 하나를 놓치면 알고리즘 선택이 통째로 바뀐다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "연속한 것끼리만 합칠 수 있다", "괄호를 어디에 치는가", "구간을 두 부분으로 나눈다", "하나로 만드는 최소 비용", "구간 [i, j]를 ~하는 최적", "원형으로 이어져 있다"
- 제약조건: $n \le 500$ 안팎. 상태가 $O(n^2)$, 전이가 $O(n)$이라 $O(n^3)$이고 $500^3/6 \approx 2 \times 10^7$이 한계선이다([0-9](#/0-9)). 파이썬은 같은 식에서 $n \le 300$이 현실적인 상한이다
- 혼동 주의: 인접 제약이 없고 아무거나 합쳐도 되면 그리디 + 우선순위 큐([II-8](#/ii-8)). 순서를 지키되 고르기만 하면 되면 [VIII-6](#/viii-6)의 부분수열. 흩어진 것을 골라도 되면 [VIII-5](#/viii-5)의 배낭. 구간이 아니라 정점 집합에 의존이 걸리면 [VIII-8](#/viii-8)의 트리 DP다
- 반례 함정: **행 우선으로 채우기.** 배열이 0으로 초기화되어 있으면 예외 없이 답만 작아진다. 그리고 **정사각 행렬로만 만든 예제** — 차원 인덱스를 `d[i]`로 잘못 써도 통과한다
:::

::: interview
**"구간 DP는 왜 이중 루프의 바깥을 구간 길이로 잡습니까."**
"$dp[i][j]$가 읽는 칸이 같은 행의 왼쪽과 같은 열의 아래이기 때문입니다. 아래를 읽으므로 행 우선으로 훑으면 아직 안 채운 칸을 읽습니다. 읽는 두 칸의 공통점은 구간 길이가 자기보다 짧다는 것 하나뿐이라, 길이를 바깥 루프로 두면 의존 순서가 저절로 지켜집니다. 그리고 이 실수는 예외를 내지 않고 답만 작아져서 작은 예제로는 잘 안 걸립니다." 여기에 **"메모이제이션으로 짜면 순서 자체가 필요 없다"**([VIII-2](#/viii-2))를 덧붙이면 두 방식의 차이까지 정리된다.
:::

## 연습

::: quiz
**"연속"이라는 단어가 지문에 있는지, 그리고 표를 어느 순서로 채워야 하는지 둘을 먼저 확인하라.**

**1. 백준 11049 행렬 곱셈 순서 (골드 3)** — https://www.acmicpc.net/problem/11049
- 신호: 이 절의 원형 그대로다. "곱셈 연산의 수가 최소가 되는" + $N \le 500$이 $O(N^3)$을 가리킨다.
- 상태: $dp[i][j]$ = 구간 $[i, j]$를 하나로 곱치는 최소 곱셈 수. 상태가 구간인 이유는 교환법칙이 없어 중간 결과가 언제나 연속 묶음이기 때문이다.
- 자료구조: $N \times N$ 표 + 길이 바깥 루프. 답이 $2^{31}$을 넘을 수 있으므로 C++은 `long long`이다.

**2. 백준 11066 파일 합치기 (골드 3)** — https://www.acmicpc.net/problem/11066
- 신호: "연속되도록" 합쳐야 한다는 조건이 지문에 박혀 있다. 이 단어가 없으면 우선순위 큐 그리디 문제이고, 있으므로 구간 DP다.
- 상태: $dp[i][j]$ = 파일 $i$부터 $j$까지를 하나로 합치는 최소 비용. 마지막 합침이 $k$에서 갈린다.
- 자료구조: 표 + **누적 합**. 마지막 합침의 비용이 구간 전체 크기의 합이라 매번 더하면 $O(N^4)$이 된다. 누적 합으로 $O(1)$에 꺼내는 것이 이 문제의 두 번째 장치다([VI-4](#/vi-4)).

**3. 백준 10942 팰린드롬? (골드 4)** — https://www.acmicpc.net/problem/10942
- 신호: 구간 $[S, E]$가 팰린드롬인지 묻는 질의가 100만 개다. 질의마다 확인하면 $O(MN)$이라 안 된다.
- 상태: `pal[i][j]` = 구간이 팰린드롬인가. §4.2의 표 그 자체이고, 답은 질의당 $O(1)$ 조회다.
- 자료구조: $N \times N$ 불리언 표. $N \le 2{,}000$이라 400만 칸이고, **길이 순으로 채워야 한다**는 것이 이 문제의 유일한 함정이다.

**4. 백준 1509 팰린드롬 분할 (골드 1)** — https://www.acmicpc.net/problem/1509
- 신호: "분할의 개수의 최솟값". 10942의 표를 만든 뒤 그 위에서 한 단계를 더 얹는다.
- 상태: 구간 표 `pal[i][j]` + 1차원 `cut[j]` = 앞 $j$글자의 최소 조각 수. **두 DP를 겹쳐 쓰는 형태**가 이 문제의 배울 점이다.
- 자료구조: 2차원 표 + 1차원 배열. 길이 2,500이므로 표는 625만 칸이고 메모리 형태를 신경 써야 한다.

## 요약

- 구간 DP의 상태는 **연속한 부분** $[i, j]$다. 흩어진 부분집합이 부분문제가 될 수 없는 문제에서 나온다 — 행렬 곱셈에 교환법칙이 없는 것이 그 조건이다.
- 점화식은 **마지막에 하는 한 번의 연산**을 떼어 내 만든다. 그 연산이 자르는 위치 $k$를 전부 시도한다.
- 점화식이 성립하는 근거는 **마지막 연산의 비용이 $k$만으로 정해진다**는 것이다. 안쪽을 어떻게 계산했든 중간 결과의 크기는 같다.
- $dp[i][j]$는 같은 행의 왼쪽과 **같은 열의 아래**를 읽는다. 그래서 행 우선으로 채우면 아직 없는 칸을 읽는다.
- 읽는 칸의 공통점은 구간 길이가 짧다는 것뿐이다. 그러므로 **바깥 루프는 구간 길이**다. 이것이 이 유형의 정체다.
- 순서를 틀려도 예외는 안 난다. 0을 읽고 답이 조용히 작아진다. 무작위 300회 중 290회에서 틀린 답이 나온다.
- 복잡도는 $O(n^3)$이고 근거는 구간 $O(n^2)$개 × 분할점 $O(n)$개, 정확히는 $n(n^2-1)/6$번이다. $n \le 500$이 한계선이고 파이썬은 그 절반쯤이다.
- 자른 위치를 따로 적어 두지 않으면 최소 비용은 알아도 **어떤 순서였는지는 모른다.**
