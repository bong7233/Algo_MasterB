# VIII-6 LIS와 LCS

::: lead
순서를 지키면서 고르는 문제 둘, 그리고 그중 하나에서 DP의 안쪽 루프가 통째로 이분 탐색으로 바뀌는 자리.
:::

## 1. 문제

코드 리뷰 화면이 두 버전의 파일을 나란히 놓고 바뀐 줄만 색으로 칠해 준다. 그 밑에서 도구가 실제로 계산하는 것은 "무엇이 바뀌었나"가 아니라 그 반대다. **양쪽에 같은 순서로 남아 있는 줄을 최대한 많이 찾는다.** 그렇게 짝지어진 줄이 공통 부분이고, 짝을 못 찾은 줄이 추가·삭제로 표시된다.

줄을 짝지을 때 순서를 어겨서는 안 된다. 옛 파일의 10번 줄을 새 파일의 3번 줄에 짝지어 놓고, 옛 파일의 5번 줄을 새 파일의 20번 줄에 짝지으면 두 짝이 교차한다. 교차하는 짝은 화면에 그릴 수 없다. **연속일 필요는 없지만 순서는 지켜야 한다** — 이것이 부분수열(subsequence)이고, 부분집합만 고르면 됐던 [VIII-5](#/viii-5)와 갈라지는 지점이다.

같은 제약이 전혀 달라 보이는 문제에도 있다. 컨베이어에서 상자가 번호 순서 없이 도착한다. 집게로 몇 개를 빼내 버려서 남은 상자들이 번호 오름차순이 되게 하려면 최소 몇 개를 빼야 하는가. 뒤집으면 **순서를 지키면서 증가하도록 남길 수 있는 최대 개수**를 묻는 문제다.

두 문제 모두 완전탐색은 $2^n$이다. 그리고 둘 다 그리디가 무너진다. 수열 `2 5 3 7`에서 앞에서부터 욕심껏 이으면 `2 5 7`로 길이 3이지만, `2 3 7`도 길이 3이고 끝값이 더 작아 **뒤에 6이 오면 `2 3 6`만 살아남는다.** 어떤 값을 남겨 두느냐가 나중을 바꾼다.

## 2. 아이디어

### 2.1 LIS — 상태에 "어디서 끝나는가"를 넣는다

[VIII-1](#/viii-1)의 네 단계를 적용한다.

**① 상태 정의.** `dp[i] = a[i]에서 끝나는 증가 부분수열의 최대 길이`.

"앞 i개까지의 답"이 아니라 **"i에서 끝나는 답"**이라는 것이 핵심이다. 앞 i개까지의 최대 길이만 들고 있으면 그 부분수열의 끝값을 모르므로 `a[i]`를 이어붙일 수 있는지 판단할 수 없다. 상태가 부족한 전형적인 사례이고 [VIII-11](#/viii-11)이 그 실패를 모아 다룬다.

**② 점화식.** $dp[i] = 1 + \max \{ dp[j] : j < i,\ a[j] < a[i] \}$ (해당하는 $j$가 없으면 1).

**③ 초기값.** 모든 `dp[i] = 1`. 자기 자신 하나짜리는 언제나 증가 수열이다.

**④ 계산 순서.** `i`를 왼쪽에서 오른쪽으로. `dp[i]`는 자기보다 왼쪽만 읽는다.

전체 답은 `dp[n-1]`이 아니라 **`max(dp)`**다. 가장 긴 것이 맨 끝에서 끝난다는 보장이 없다.

::: widget dp-table {"kind":"lis","seq":[2,5,3,7,11,8,10,13,6]}
:::

위젯의 윗줄이 입력 수열, 아랫줄이 `dp`다. `i`를 하나 정하고 왼쪽의 `j`를 전부 훑는 장면이 그대로 보인다. `a[j] >= a[i]`면 화살표가 아예 안 뜨고(이어붙일 수 없다), 이어붙일 수 있어도 이미 가진 값보다 길어지지 않으면 점선으로 뜬다. **안쪽 루프가 매번 왼쪽 전부를 훑는 것**이 $O(n^2)$의 정체다.

### 2.2 그 안쪽 루프를 이분 탐색으로 바꾼다

§1의 관찰을 다시 보라. 길이가 같은 두 부분수열이 있으면 **끝값이 작은 쪽이 언제나 낫다.** 뒤에 오는 어떤 값을 이어붙일 수 있는지가 끝값으로만 정해지고, 끝값이 작을수록 이어붙일 수 있는 값이 많기 때문이다. 이것은 [VI-1](#/vi-1)의 교환 논법과 같은 모양의 논증이다.

그래서 각 길이마다 하나만 기억하면 된다.

> `tails[k]` = 길이가 `k+1`인 증가 부분수열의 **가능한 가장 작은 끝값**

새 원소 `x`를 만나면 할 일은 둘 중 하나다. `x`가 지금까지의 모든 끝값보다 크면 길이가 하나 늘어난다(맨 뒤에 붙인다). 그렇지 않으면 **`x` 이상인 첫 자리를 `x`로 덮어쓴다.** 길이는 그대로인데 그 길이의 끝값이 더 작아진 것이다.

`tails`는 항상 오름차순이므로 "`x` 이상인 첫 자리"는 이분 탐색으로 찾는다. 그것이 정확히 `lower_bound` / `bisect_left`이고, [VII-2](#/vii-2)가 다룬 함수다. **DP의 안쪽 루프 $O(n)$이 $O(\log n)$으로 줄어드는 것이 이 결합의 전부다.**

::: danger
==`tails`는 LIS가 아니다.== 길이만 맞고 내용은 다르다.

`tails`의 각 칸은 서로 다른 시점에 갱신되므로, 마지막에 남은 배열이 원래 수열에서 **순서대로 나타나지 않을 수 있다.** §3의 손추적이 정확히 그 장면을 만든다. `tails`를 그대로 출력하면 길이는 맞고 내용은 틀린 답이 나오고, 길이만 묻는 채점에서는 통과하기 때문에 오해가 오래 살아남는다.

실제 수열이 필요하면 §4.2처럼 **각 원소가 어느 자리에 들어갔는지와 그때 앞 자리에 있던 원소가 누구인지**를 따로 기록해야 한다.
:::

### 2.3 LCS — 축이 둘이면 상태도 둘이다

수열이 둘이므로 "어디까지 봤는가"도 둘이다.

**① 상태.** `dp[i][j] = s의 앞 i글자와 t의 앞 j글자의 최장 공통 부분수열 길이`.
**② 점화식.** `s[i] == t[j]`면 `dp[i-1][j-1] + 1`. 다르면 `max(dp[i-1][j], dp[i][j-1])`.
**③ 초기값.** 한쪽이 빈 문자열이면 0이므로 0행과 0열이 전부 0.
**④ 계산 순서.** 위에서 아래로, 왼쪽에서 오른쪽으로. 읽는 칸이 전부 위·왼쪽·대각선이다.

::: widget dp-table {"kind":"lcs","a":"ACAYKP","b":"CAPCAK"}
:::

글자가 같을 때 **대각선 하나만** 읽는 것이 이 점화식의 급소다. 위나 왼쪽을 함께 보면 같은 글자를 두 번 쓰게 된다. `dp[i-1][j-1]`은 두 글자를 모두 소비하기 전의 상태이므로, 거기에 1을 더하는 것이 "이 짝을 채택한다"의 정확한 표현이다.

다를 때 `max(위, 왼쪽)`은 "둘 중 한쪽 글자를 버린다"이다. 어느 쪽을 버려야 하는지는 모르니 둘 다 해 보고 나은 쪽을 취한다.

## 3. 손으로 따라가기

::: trace
수열 `a = [2, 5, 3, 7, 11, 8, 10, 13, 6]`에 §2.2의 `tails` 방법을 돌린다.

각 원소 `x`마다 `tails`에서 **`x` 이상인 첫 자리** `k`를 찾는다. `k`가 배열 끝이면 뒤에 붙이고, 아니면 `tails[k]`를 `x`로 덮어쓴다.

| i | a[i] | 자리 k | 갱신 후 tails |
|---|---|---|---|
| 0 | 2 | 0 (끝) | [2] |
| 1 | 5 | 1 (끝) | [2, 5] |
| 2 | 3 | 1 (덮어씀) | [2, 3] |
| 3 | 7 | | |
| 4 | 11 | | |
| 5 | 8 | | |
| 6 | 10 | | |
| 7 | 13 | | |
| 8 | 6 | | |

끝까지 채운 뒤 세 가지를 확인하라.

- [ ] 마지막 `tails`를 원래 수열 `a` 위에서 왼쪽부터 짚어 갈 수 있는가. 즉 그것은 `a`의 부분수열인가
- [ ] `i = 2`에서 5가 3으로 덮였다. 그때 무엇을 잃고 무엇을 얻었는가
- [ ] 길이 6짜리 실제 증가 부분수열을 하나 손으로 찾아보라. `tails`와 같은가
:::

::: answer
| i | a[i] | 자리 k | 갱신 후 tails |
|---|---|---|---|
| 0 | 2 | 0 (끝) | [2] |
| 1 | 5 | 1 (끝) | [2, 5] |
| 2 | 3 | 1 (덮어씀) | [2, 3] |
| 3 | 7 | 2 (끝) | [2, 3, 7] |
| 4 | 11 | 3 (끝) | [2, 3, 7, 11] |
| 5 | 8 | 3 (덮어씀) | [2, 3, 7, 8] |
| 6 | 10 | 4 (끝) | [2, 3, 7, 8, 10] |
| 7 | 13 | 5 (끝) | [2, 3, 7, 8, 10, 13] |
| 8 | 6 | 2 (덮어씀) | [2, 3, 6, 8, 10, 13] |

첫 번째 질문. **부분수열이 아니다.** 마지막 `tails`는 `[2, 3, 6, 8, 10, 13]`인데, 6은 원래 수열의 **맨 끝**에 있고 8, 10, 13은 그보다 앞에 있다. `a` 위에서 왼쪽부터 짚어 가면 6 다음에 8을 찾을 수 없다. **길이 6은 맞고 내용은 틀렸다.**

두 번째. 5를 3으로 덮을 때 잃은 것은 "길이 2짜리가 5로 끝난다"는 사실이고, 얻은 것은 "길이 2를 3으로도 끝낼 수 있다"는 사실이다. 잃은 쪽은 버려도 된다 — 5로 이어붙일 수 있는 값은 3으로도 전부 이어붙일 수 있기 때문이다. **덮어쓰기가 정보를 버리는 것이 아니라 쓸모없어진 정보를 지우는 것**이라는 점이 이 알고리즘의 정당성이다.

세 번째. `2 3 7 8 10 13` 또는 `2 5 7 8 10 13`. 둘 다 길이 6이고 둘 다 정답이다. 마지막 `tails`와는 다르다. §4.2의 코드가 복원하는 것이 앞의 것이고, §4.1의 $O(n^2)$ 판이 복원하는 것이 뒤의 것이다. **LIS는 유일하지 않다.**
:::

## 4. 구현

### 4.1 LIS $O(n^2)$ — 역추적까지

::: dual
```python title="LIS O(n^2) — dp와 역추적"
a = [2, 5, 3, 7, 11, 8, 10, 13, 6]

n = len(a)
dp = [1] * n                                # dp[i] = i에서 끝나는 증가 부분수열의 최대 길이
prev = [-1] * n                             # 역추적용 — dp[i]를 만들어 준 앞 원소의 인덱스
for i in range(n):
    for j in range(i):
        if a[j] < a[i] and dp[j] + 1 > dp[i]:
            dp[i] = dp[j] + 1
            prev[i] = j

best = max(range(n), key=lambda i: dp[i])   # 가장 긴 것이 어디서 끝나는가
seq, cur = [], best
while cur != -1:
    seq.append(a[cur])
    cur = prev[cur]
seq.reverse()

print("a  :", " ".join("%2d" % x for x in a))
print("dp :", " ".join("%2d" % x for x in dp))
print("LIS 길이 =", dp[best], "/ 수열 =", seq)
```
```cpp title="LIS O(n^2) — dp와 역추적"
#include <cstdio>
#include <vector>
using namespace std;

int main() {
    vector<int> a = {2, 5, 3, 7, 11, 8, 10, 13, 6};

    int n = a.size();
    vector<int> dp(n, 1);                       // dp[i] = i에서 끝나는 증가 부분수열의 최대 길이
    vector<int> prev(n, -1);                    // 역추적용 — dp[i]를 만들어 준 앞 원소의 인덱스
    for (int i = 0; i < n; i++)
        for (int j = 0; j < i; j++)
            if (a[j] < a[i] && dp[j] + 1 > dp[i]) {
                dp[i] = dp[j] + 1;
                prev[i] = j;
            }

    int best = 0;                               // 가장 긴 것이 어디서 끝나는가
    for (int i = 0; i < n; i++)
        if (dp[i] > dp[best]) best = i;
    vector<int> seq;
    for (int cur = best; cur != -1; cur = prev[cur]) seq.push_back(a[cur]);

    printf("a  :");
    for (int x : a) printf(" %2d", x);
    printf("\ndp :");
    for (int x : dp) printf(" %2d", x);
    printf("\nLIS 길이 = %d / 수열 = [", dp[best]);
    for (int k = (int)seq.size() - 1; k >= 0; k--) printf("%d%s", seq[k], k ? ", " : "");
    printf("]\n");
    return 0;
}
```
:::

```console
a  :  2  5  3  7 11  8 10 13  6
dp :  1  2  2  3  4  4  5  6  3
LIS 길이 = 6 / 수열 = [2, 5, 7, 8, 10, 13]
```

**복잡도:** 시간 $O(n^2)$ — 각 `i`마다 왼쪽의 `j`를 전부 훑으므로 비교 횟수가 $0 + 1 + \dots + (n-1) = n(n-1)/2$다. 공간 $O(n)$ — `dp`와 `prev` 두 배열. **역추적이 공짜인 것이 이 판의 장점이다.** `prev` 배열 하나면 실제 수열이 나온다.

### 4.2 LIS $O(n \log n)$ — 그리고 실제 수열 복원

::: dual
```python title="LIS O(n log n) — tails와 실제 수열 복원"
from bisect import bisect_left

a = [2, 5, 3, 7, 11, 8, 10, 13, 6]

n = len(a)
tails = []                                  # tails[k] = 길이 k+1인 증가 부분수열의 "가능한 가장 작은 끝값"
tails_idx = []                              # 그 끝값이 원래 수열의 몇 번 자리였는가
prev = [-1] * n                             # 역추적용
for i, x in enumerate(a):
    k = bisect_left(tails, x)               # x가 들어갈 자리 = x로 끝나는 부분수열의 길이 - 1
    if k == len(tails):
        tails.append(x)
        tails_idx.append(i)
    else:
        tails[k] = x                        # 같은 길이인데 끝값이 더 작아졌다 — 덮어쓴다
        tails_idx[k] = i
    prev[i] = tails_idx[k - 1] if k > 0 else -1
    print("x=%2d → 자리 %d, tails = %s" % (x, k, tails))

seq, cur = [], tails_idx[-1]
while cur != -1:
    seq.append(a[cur])
    cur = prev[cur]
seq.reverse()

print("tails =", tails, "← 길이는 맞지만 이것은 부분수열이 아니다")
print("LIS 길이 =", len(tails), "/ 실제 수열 =", seq)
```
```cpp title="LIS O(n log n) — tails와 실제 수열 복원"
#include <algorithm>
#include <cstdio>
#include <vector>
using namespace std;

void show(const char* head, const vector<int>& v, const char* tail) {
    printf("%s[", head);
    for (size_t i = 0; i < v.size(); i++) printf("%d%s", v[i], i + 1 < v.size() ? ", " : "");
    printf("]%s", tail);
}

int main() {
    vector<int> a = {2, 5, 3, 7, 11, 8, 10, 13, 6};

    int n = a.size();
    vector<int> tails;                          // tails[k] = 길이 k+1인 증가 부분수열의 "가능한 가장 작은 끝값"
    vector<int> tails_idx;                      // 그 끝값이 원래 수열의 몇 번 자리였는가
    vector<int> prev(n, -1);                    // 역추적용
    for (int i = 0; i < n; i++) {
        int x = a[i];
        int k = lower_bound(tails.begin(), tails.end(), x) - tails.begin();
        if (k == (int)tails.size()) {
            tails.push_back(x);
            tails_idx.push_back(i);
        } else {
            tails[k] = x;                       // 같은 길이인데 끝값이 더 작아졌다 — 덮어쓴다
            tails_idx[k] = i;
        }
        prev[i] = k > 0 ? tails_idx[k - 1] : -1;
        printf("x=%2d → 자리 %d, tails = ", x, k);
        show("", tails, "\n");
    }

    vector<int> seq;
    for (int cur = tails_idx.back(); cur != -1; cur = prev[cur]) seq.push_back(a[cur]);
    reverse(seq.begin(), seq.end());

    show("tails = ", tails, " ← 길이는 맞지만 이것은 부분수열이 아니다\n");
    printf("LIS 길이 = %d / 실제 수열 = ", (int)tails.size());
    show("", seq, "\n");
    return 0;
}
```
:::

```console
x= 2 → 자리 0, tails = [2]
x= 5 → 자리 1, tails = [2, 5]
x= 3 → 자리 1, tails = [2, 3]
x= 7 → 자리 2, tails = [2, 3, 7]
x=11 → 자리 3, tails = [2, 3, 7, 11]
x= 8 → 자리 3, tails = [2, 3, 7, 8]
x=10 → 자리 4, tails = [2, 3, 7, 8, 10]
x=13 → 자리 5, tails = [2, 3, 7, 8, 10, 13]
x= 6 → 자리 2, tails = [2, 3, 6, 8, 10, 13]
tails = [2, 3, 6, 8, 10, 13] ← 길이는 맞지만 이것은 부분수열이 아니다
LIS 길이 = 6 / 실제 수열 = [2, 3, 7, 8, 10, 13]
```

복원의 요령은 **덮어쓰기가 일어난 시점을 붙잡는 것**이다. `x`가 자리 `k`에 들어간 순간, 그 앞자리 `k-1`에 있던 원소는 `x`보다 작고 `x`보다 왼쪽에 있다. 그러므로 그 원소를 `x`의 부모로 기록해 두면 나중에 배열이 아무리 덮여도 그때의 연결은 남는다. **`tails`는 시간에 따라 변하지만 `prev`는 한 번 쓰면 변하지 않는다.**

**복잡도:** 시간 $O(n \log n)$ — 원소마다 이분 탐색 한 번, 각 $O(\log n)$. 공간 $O(n)$ — `tails`, `tails_idx`, `prev`. **`tails`의 길이가 곧 답**이라는 것이 이 판의 특이한 점이고, 그래서 길이만 필요하면 배열 하나로 끝난다.

::: perf
원소가 균등 무작위인 수열에서 두 판의 시간이다.

| n | 판 | Python | C++ |
|---|---|---|---|
| 5,000 | $O(n^2)$ | 0.71 s | 0.045 s |
| 5,000 | $O(n \log n)$ | 0.8 ms | 0.2 ms |
| 1,000,000 | $O(n \log n)$ | 0.22 s | 0.06 s |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/lis_two_versions.py` 와 `.cpp` 다.)

$n = 5{,}000$에서 이미 Python 기준 **900배** 차이다. 그리고 $n = 10^6$에서 $O(n^2)$은 $10^{12}$회라 C++로도 끝나지 않는다 — 이 표에 그 줄이 없는 이유다. **제약이 $n \le 1{,}000$이면 $O(n^2)$을 쓰고 역추적을 공짜로 얻고, $n \ge 10^5$이면 선택지가 없다.**
:::

### 4.3 LCS — 표와 문자열 복원

::: dual
```python title="LCS — 표와 문자열 복원"
s = "ACAYKP"
t = "CAPCAK"

n, m = len(s), len(t)
dp = [[0] * (m + 1) for _ in range(n + 1)]  # dp[i][j] = s의 앞 i글자와 t의 앞 j글자의 LCS 길이
for i in range(1, n + 1):
    for j in range(1, m + 1):
        if s[i - 1] == t[j - 1]:
            dp[i][j] = dp[i - 1][j - 1] + 1             # 같은 글자를 둘 다 쓴다
        else:
            dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])  # 한쪽 글자를 버린다

out, i, j = [], n, m                        # 역추적: 대각선으로 움직인 자리가 답에 들어간 글자다
while i > 0 and j > 0:
    if s[i - 1] == t[j - 1]:
        out.append(s[i - 1])
        i -= 1
        j -= 1
    elif dp[i - 1][j] >= dp[i][j - 1]:
        i -= 1
    else:
        j -= 1
out.reverse()

print("      " + "  ".join(t))
for i in range(n + 1):
    head = " " if i == 0 else s[i - 1]
    print(head + " " + " ".join("%2d" % dp[i][j] for j in range(m + 1)))
print("LCS 길이 =", dp[n][m], "/ 문자열 =", "".join(out))
```
```cpp title="LCS — 표와 문자열 복원"
#include <algorithm>
#include <cstdio>
#include <string>
#include <vector>
using namespace std;

int main() {
    string s = "ACAYKP";
    string t = "CAPCAK";

    int n = s.size(), m = t.size();
    vector<vector<int>> dp(n + 1, vector<int>(m + 1, 0));   // dp[i][j] = s의 앞 i글자와 t의 앞 j글자의 LCS 길이
    for (int i = 1; i <= n; i++)
        for (int j = 1; j <= m; j++) {
            if (s[i - 1] == t[j - 1])
                dp[i][j] = dp[i - 1][j - 1] + 1;            // 같은 글자를 둘 다 쓴다
            else
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]); // 한쪽 글자를 버린다
        }

    string out;                                 // 역추적: 대각선으로 움직인 자리가 답에 들어간 글자다
    int i = n, j = m;
    while (i > 0 && j > 0) {
        if (s[i - 1] == t[j - 1]) {
            out += s[i - 1];
            i--;
            j--;
        } else if (dp[i - 1][j] >= dp[i][j - 1]) {
            i--;
        } else {
            j--;
        }
    }
    reverse(out.begin(), out.end());

    printf("     ");
    for (int j = 0; j < m; j++) printf("%s%2c", j ? " " : "", t[j]);
    for (int r = 0; r <= n; r++) {
        printf("\n%c ", r == 0 ? ' ' : s[r - 1]);
        for (int c = 0; c <= m; c++) printf("%s%2d", c ? " " : "", dp[r][c]);
    }
    printf("\nLCS 길이 = %d / 문자열 = %s\n", dp[n][m], out.c_str());
    return 0;
}
```

**복잡도:** 시간 $O(nm)$ — 칸이 $(n+1)(m+1)$개이고 칸마다 상수 작업이다. 공간 $O(nm)$ — 표 전체. 길이만 필요하면 두 줄만 굴려 $O(m)$으로 줄일 수 있지만 **그러면 복원이 죽는다.** 문자열 길이가 각 5,000이면 표가 2,500만 칸이라 `int`로 100 MB다. 메모리 제한이 128 MB인 채점에서 실제로 걸린다 — 이때는 `short`를 쓰거나 분할 정복 복원(Hirschberg)으로 간다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 이분 탐색 | `bisect_left(tails, x)` — 값을 반환 | `lower_bound(...) - tails.begin()` — 반복자라 시작 반복자를 빼야 인덱스가 된다 |
| 최댓값 위치 | `max(range(n), key=...)` — 동점이면 첫 번째 | 직접 루프. `>`로 비교하면 동점에서 첫 번째가 남는다 |
| 배열 뒤집기 | `seq.reverse()` — 제자리 | `reverse(seq.begin(), seq.end())` 또는 인덱스를 거꾸로 출력 |
| 문자열 이어붙이기 | `"".join(out)` — 리스트에 모았다가 한 번에. `+=`는 매번 새 문자열을 만든다([0-3](#/0-3)) | `out += c` — `string`이 가변이라 그대로 붙여도 된다 |
| 리스트 출력 | `print(tails)` → `[2, 3, 7]` | 직접 찍어야 한다. 이 챕터의 C++ 코드에 `show()`가 있는 이유다 |

::: pitfall
- **`tails`를 답으로 출력한다.** 길이만 맞고 내용은 틀리다. §2.2와 §3이 그 장면이다.
- **`bisect_left`와 `bisect_right`를 바꿔 쓴다.** 순증가(같은 값 불가)면 `bisect_left`/`lower_bound`, 비내림차순(같은 값 허용)이면 `bisect_right`/`upper_bound`다. 지문의 "증가"가 어느 쪽인지 먼저 읽어라. 예제로는 거의 안 갈린다.
- **`max(dp)` 대신 `dp[n-1]`을 쓴다.** LIS가 마지막 원소에서 끝난다는 보장이 없다.
- **LCS를 부분문자열(연속)과 혼동한다.** 연속이면 점화식이 다르다 — 다를 때 0으로 끊어야 하고, 답은 표 전체의 최댓값이다. 지문에 "연속"이 있는지 없는지가 전부다.
- **LCS 역추적에서 문자열을 뒤집지 않는다.** 뒤에서부터 복원하므로 결과가 거꾸로 나온다. 예제가 회문이면 이 버그가 통과한다.
- **$n \le 1{,}000$인데 $O(n \log n)$으로 짜고 역추적을 포기한다.** 작은 입력에서는 $O(n^2)$ 판이 더 쉽고 `prev` 하나로 복원이 끝난다. 빠른 판이 항상 옳은 것은 아니다.
:::

::: note
**LIS와 LCS는 서로 변환된다.** 수열 `a`가 순열이면 `a`의 LIS는 `LCS(a, sorted(a))`와 같다. 정렬된 수열과의 공통 부분수열은 곧 증가 부분수열이기 때문이다.

쓸모 있는 방향은 반대쪽이다. 두 수열의 **원소가 전부 서로 다르면**, 한쪽 수열에서의 위치로 다른 쪽을 번역한 뒤 LIS를 구하면 그것이 LCS다. $O(nm)$이 $O(n \log n)$이 된다. 다만 원소가 중복되면 짝지을 수 있는 쌍이 최악에 $n \times m$개라 이 변환이 오히려 느려진다. **원소가 서로 다른가**가 판단 기준이다.
:::

## 5. 어디에 쓰이는가

**`diff`가 LCS다.** 두 파일의 줄을 원소로 보고 최장 공통 부분수열을 구하면, 짝지어진 줄이 공통 부분이고 나머지가 `-`와 `+`로 출력된다. 실제 `git diff`는 표를 다 채우는 대신 편집 그래프 위에서 최단 경로를 찾는 Myers 알고리즘을 쓰지만 **구하는 답은 같은 것**이고, 줄 단위 비교를 먼저 하는 이유도 같다 — 글자 단위로 하면 표가 $10^{12}$칸이 된다.

**그리고 여기서 LIS가 LCS 안으로 들어온다.** Hunt–Szymanski 알고리즘은 소스 파일처럼 **같은 줄이 거의 반복되지 않는** 입력을 노려, 일치하는 줄 쌍만 모은 뒤 그 위에서 LIS를 구한다. §4 마지막 노트의 변환이 실제 도구에 들어간 사례이고, 조건("원소가 거의 서로 다르다")이 왜 중요한지도 여기서 보인다.

**생물정보학의 서열 정렬이 같은 표다.** DNA·단백질 서열 두 개를 놓고 공통 부분을 찾는 계산은 LCS에 치환 점수와 간격 벌점을 붙인 것이다. 서열이 길어 표가 메모리를 넘기 때문에 앞서 말한 Hirschberg 방식의 선형 공간 복원이 실제로 쓰인다.

**패키지·데이터 동기화의 "무엇이 바뀌었나"도 이 계보다.** 다만 rsync처럼 블록 해시로 차이를 찾는 쪽은 LCS가 아니라 해시 기반이다. **줄·원소 단위로 순서를 지켜 짝지어야 할 때만 LCS**이고, 그렇지 않으면 더 싼 도구가 있다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "가장 긴 증가하는 부분 수열", "순서를 유지하면서", "연속일 필요는 없다", "두 문자열에 공통으로 나타나는", "최소 몇 개를 제거하면", "서로 교차하지 않는 최대 개수"
- 제약조건: LIS는 $n \le 1{,}000$이면 $O(n^2)$, $n \le 10^6$이면 $O(n \log n)$. LCS는 두 길이의 곱이 기준이라 $nm \le 10^8$이고, **길이 5,000 × 5,000이면 시간보다 메모리(약 100 MB)가 먼저 걸린다**
- 혼동 주의: "연속"이면 부분수열이 아니라 부분문자열이라 점화식이 다르다. 순서를 안 지켜도 되면 부분수열이 아니라 부분집합이고 [VIII-5](#/viii-5)다. 실제 수열까지 출력해야 하면 $O(n \log n)$ 판에 `prev`가 반드시 필요하다. 두 수열이 아니라 한 수열을 구간으로 쪼개는 문제면 [VIII-7](#/viii-7)이다
- 반례 함정: **`tails` 배열을 LIS 자체로 출력하는 것.** 길이만 채점하면 통과하고 수열까지 채점하면 틀린다. 그리고 **같은 값이 반복되는 입력** — `bisect_left`와 `bisect_right`가 갈리는 유일한 자리이고, 예제에는 대개 중복이 없다
:::

## 연습

::: quiz
**연속인지, 길이만 묻는지 수열까지 묻는지, 원소가 서로 다른지 셋을 먼저 확인하라.**

**1. 백준 12015 가장 긴 증가하는 부분 수열 2 (골드 2)** — https://www.acmicpc.net/problem/12015
- 신호: 11053과 지문이 같은데 $N \le 1{,}000{,}000$이다. **제약조건만 바뀐 문제**이고, 그것이 $O(n^2)$을 버리라는 지시다([0-9](#/0-9)).
- 상태: `tails[k]` = 길이 `k+1`인 증가 부분수열의 가장 작은 끝값. 답은 `tails`의 길이다.
- 자료구조: 배열 하나 + `lower_bound`. 길이만 물으므로 `prev`도 `tails_idx`도 필요 없다 — 이 문제가 유일하게 `tails`만으로 끝나는 경우다.

**2. 백준 9252 LCS 2 (골드 4)** — https://www.acmicpc.net/problem/9252
- 신호: "LCS의 길이"에 더해 **"LCS를 출력한다"**가 붙었다. 표를 버리고 두 줄만 굴리는 최적화를 쓰면 복원이 불가능해진다.
- 상태: `dp[i][j]` = 앞 i글자와 앞 j글자의 LCS 길이. 문자열 길이가 최대 1,000이라 표는 100만 칸으로 여유롭다.
- 자료구조: 2차원 표 전체 + 역추적. 대각선으로 움직인 자리만 답에 넣고, 마지막에 뒤집는다.

**3. 백준 5582 공통 부분 문자열 (골드 5)** — https://www.acmicpc.net/problem/5582
- 신호: "부분 **문자열**" — 연속이다. LCS와 한 글자 차이의 지문이고 점화식이 갈린다.
- 상태: `dp[i][j]` = `s[i]`와 `t[j]`에서 **끝나는** 공통 접미사의 길이. 글자가 다르면 0으로 끊는다.
- 자료구조: 2차원 표. 답이 `dp[n][m]`이 아니라 **표 전체의 최댓값**이라는 것이 LCS와의 두 번째 차이다. 이 문제와 9252를 나란히 풀면 "연속"이라는 단어의 무게가 남는다.
:::

## 요약

- 부분수열은 순서를 지키되 연속일 필요가 없다. 부분집합만 고르면 됐던 배낭과 갈라지는 지점이다.
- LIS의 상태는 "앞 i개까지"가 아니라 **"i에서 끝나는"**이다. 끝값을 모르면 이어붙일 수 있는지 판단할 수 없다.
- 길이가 같으면 **끝값이 작은 쪽이 언제나 낫다.** 이 관찰이 각 길이마다 하나만 기억하게 만들고, 그 배열이 정렬 상태를 유지하므로 안쪽 루프가 이분 탐색으로 바뀐다.
- **`tails`는 LIS가 아니다.** 길이만 맞다. 실제 수열은 `prev` 기록으로 복원한다.
- $O(n^2)$ 판은 느린 대신 역추적이 공짜다. $n \le 1{,}000$이면 그쪽이 낫다.
- LCS는 축이 둘이라 상태도 둘이다. 같으면 **대각선 하나만** 읽는 것이 "두 글자를 함께 소비한다"의 표현이다.
- LCS 표를 두 줄로 줄이면 복원이 죽는다. 길이 5,000짜리 두 문자열은 시간보다 메모리가 먼저 걸린다.
- 원소가 서로 다르면 LCS는 LIS로 번역되어 $O(n \log n)$이 된다. `diff`의 Hunt–Szymanski가 그 사례다.

**다음 절**: [VIII-7 구간 DP](#/viii-7) — 수열을 자르는 위치가 상태가 되면, 표를 채우는 순서가 행 우선이 아니라 **구간 길이 순**이어야 하는 이유가 나온다.
