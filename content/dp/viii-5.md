# VIII-5 배낭 문제

::: lead
예산 안에서 무엇을 고를 것인가. 그리고 "각각 한 번씩"과 "몇 번이든"을 가르는 것이 왜 루프 방향 하나인가.
:::

## 1. 문제

배포 창이 9분 열린다. 그 안에 돌려야 할 마이그레이션 작업이 셋이고, 각각 걸리는 시간과 회수되는 디스크 용량이 다르다.

| 작업 | 걸리는 시간 | 회수되는 용량 |
|---|---|---|
| A | 3분 | 8 GB |
| B | 4분 | 9 GB |
| C | 5분 | 11 GB |

창을 넘기면 작업이 강제로 잘린다. 9분 안에 끝나는 조합 중 회수량이 최대인 것을 골라야 한다.

효율이 좋은 것부터 넣는 것이 자연스러워 보인다. 분당 회수량은 A가 2.67, B가 2.25, C가 2.2다. A를 넣고(3분), 남은 6분에 B를 넣고(4분), 남은 2분에는 아무것도 안 들어간다. **17 GB.**

그런데 B와 C만 넣으면 정확히 9분이고 **20 GB**다. 효율이 가장 나쁜 두 개를 고른 쪽이 이겼다.

그리디가 무너지는 이유는 [VI-1](#/vi-1)이 다룬 것과 같다. 남는 시간은 되팔 수 없다. 2분이 남았다는 것은 2분어치를 벌어 둔 것이 아니라 **2분을 버린 것**이고, 효율 순 선택은 그 버려지는 자투리를 계산에 넣지 않는다.

그러면 전부 해 보면 된다. 작업이 3개면 조합이 8가지다. 그러나 작업이 100개면 $2^{100}$가지이고, 이것은 어떤 기계로도 끝나지 않는다. **부분집합을 전부 만들지 않으면서 최적 조합을 찾는 방법**이 필요하다.

## 2. 아이디어

[VIII-1](#/viii-1)의 네 단계를 그대로 적용한다.

**① 상태 정의.** `dp[i][c] = 앞 i개의 물건만 고려하고 용량이 c일 때의 최대 가치`.

여기서 결정적인 것은 **`i`라는 축**이다. "용량 c에서의 최대 가치"만으로 상태를 잡으면 같은 물건을 두 번 넣는 답이 섞여 들어온다. 어떤 물건까지 검토를 끝냈는지를 상태에 적어 두어야 "각각 한 번씩"이 지켜진다. ==상태에 무엇을 넣느냐가 곧 규칙을 어디에 새기느냐다.==

**② 점화식.** `i`번 물건 앞에서 할 수 있는 일은 둘뿐이다. 넣거나, 넣지 않거나.

$$dp[i][c] = \max(dp[i-1][c],\; dp[i-1][c-w_i] + v_i)$$

넣지 않으면 앞 $i-1$개로 용량 $c$를 채운 값 그대로다. 넣으면 무게 $w_i$만큼 자리를 미리 비워 둔 상태, 즉 $dp[i-1][c-w_i]$에 가치 $v_i$를 더한 값이다. **두 항 모두 $i-1$행을 읽는다.** 이것이 "각 물건을 한 번만 쓴다"의 정확한 표현이다.

**③ 초기값.** `dp[0][c] = 0`. 물건이 하나도 없으면 용량이 얼마든 가치는 0이다.

**④ 계산 순서.** $i$를 1부터 올린다. 각 행은 바로 윗 행만 읽으므로 위에서 아래로 한 번 훑으면 끝난다.

::: widget dp-table {"kind":"knapsack","cap":9,"items":[{"w":3,"v":8},{"w":4,"v":9},{"w":5,"v":11}]}
:::

위젯은 방금 세운 점화식을 그대로 그린다. 칸 하나를 채울 때마다 화살표 두 개가 뜬다. 하나는 **바로 윗줄의 같은 열**(넣지 않는 쪽), 다른 하나는 **바로 윗줄에서 $w$칸 왼쪽**(넣는 쪽)이다. 실선이 채택된 항, 점선이 비교만 하고 버린 항이다.

`c < w`인 열에서는 화살표가 하나뿐이다. 용량이 물건 무게보다 작으면 넣는 선택지 자체가 없어서 윗줄을 그대로 베낀다. 마지막에 위젯이 역추적하는 장면도 보라 — **어떤 칸의 값이 윗칸과 같으면 그 물건은 안 넣은 것이고, 크면 넣은 것이다.** 표에 답만이 아니라 "어떻게"까지 들어 있다.

### 2.1 한 줄로 접기, 그리고 방향

표 전체를 들고 있을 필요는 없다. 각 행이 읽는 것은 **바로 윗 행뿐**이므로 배열 한 줄이면 된다.

문제는 한 줄을 덮어쓰면 그 "윗 행"이 사라진다는 것이다. `dp[c]`를 갱신하는 순간, 아직 갱신되지 않은 칸은 윗 행의 값이고 이미 갱신된 칸은 이번 물건을 쓴 값이다. 그러므로 **읽는 칸 `dp[c-w]`가 아직 갱신되지 않았어야** 점화식이 지켜진다. `c-w`는 `c`보다 왼쪽이므로 답은 하나다.

```text nolines
   c 내림차순   dp[c-w] not yet touched   ->  each item used once   (0/1)
   c 오름차순   dp[c-w] already updated   ->  item reused freely    (unbounded)
```

여기서 이 챕터의 요점이 나온다. **오름차순은 버그가 아니라 다른 알고리즘이다.** 이번 물건을 이미 쓴 값 위에 또 쓰므로 같은 물건을 몇 번이든 쓰게 되고, 그것이 정확히 **무한 배낭**(complete knapsack)이다. 두 알고리즘의 코드는 루프 방향 한 글자만 다르다.

::: warn
그래서 이 유형의 오답은 예외도 경고도 없이 나온다. 0/1로 짜야 할 것을 오름차순으로 돌리면 "각 물건을 여러 번 쓴" 더 큰 값이 나오고, 무한 배낭을 내림차순으로 돌리면 "한 번씩만 쓴" 더 작은 값이 나온다. **어느 쪽도 프로그램이 죽지 않는다.**
:::

## 3. 손으로 따라가기

::: trace
용량 `W = 9`, 물건은 A(무게 3, 가치 8) 하나만 놓고 **1차원 배열**을 갱신한다. 시작은 `dp = [0]*10`이다.

갱신은 `dp[c] = max(dp[c], dp[c-3] + 8)`이다. 관찰할 것은 **읽는 칸 `dp[c-3]`이 이번 물건을 이미 반영한 값인가**이다.

**(가) 내림차순** `c = 9, 8, 7, …, 3`

| c | dp[c-3] 읽은 값 | dp[c] 결과 |
|---|---|---|
| 9 | dp[6] = 0 | 8 |
| 8 | dp[5] = 0 | 8 |
| 7 | | |
| 6 | | |
| 5 | | |
| 4 | | |
| 3 | | |

**(나) 오름차순** `c = 3, 4, 5, …, 9`

| c | dp[c-3] 읽은 값 | dp[c] 결과 |
|---|---|---|
| 3 | dp[0] = 0 | 8 |
| 4 | dp[1] = 0 | 8 |
| 5 | | |
| 6 | | |
| 7 | | |
| 8 | | |
| 9 | | |

세 가지를 확인하라.

- [ ] 두 표는 어느 `c`에서 처음으로 갈라지는가
- [ ] (나)의 `dp[9]`는 얼마이고, 그 값은 물건 A를 몇 개 쓴 것인가
- [ ] 물건이 A 하나뿐인데도 두 답이 다르다. 물건이 여러 개일 때 이 차이는 커지는가 작아지는가
:::

::: answer
**(가) 내림차순**

| c | dp[c-3] 읽은 값 | dp[c] 결과 |
|---|---|---|
| 9 | dp[6] = 0 | 8 |
| 8 | dp[5] = 0 | 8 |
| 7 | dp[4] = 0 | 8 |
| 6 | dp[3] = 0 | 8 |
| 5 | dp[2] = 0 | 8 |
| 4 | dp[1] = 0 | 8 |
| 3 | dp[0] = 0 | 8 |

결과: `[0, 0, 0, 8, 8, 8, 8, 8, 8, 8]`

**(나) 오름차순**

| c | dp[c-3] 읽은 값 | dp[c] 결과 |
|---|---|---|
| 3 | dp[0] = 0 | 8 |
| 4 | dp[1] = 0 | 8 |
| 5 | dp[2] = 0 | 8 |
| 6 | dp[3] = **8** | **16** |
| 7 | dp[4] = 8 | 16 |
| 8 | dp[5] = 8 | 16 |
| 9 | dp[6] = **16** | **24** |

결과: `[0, 0, 0, 8, 8, 8, 16, 16, 16, 24]`

첫 번째 질문. **`c = 6`에서 처음 갈라진다.** 오름차순에서는 `dp[3]`이 이미 8로 갱신되어 있고, 그 8 위에 다시 8을 얹어 16이 된다. 내림차순에서 `dp[3]`을 읽는 시점에는 아직 0이다.

두 번째. `dp[9] = 24 = 8 × 3`. **무게 3짜리 물건을 세 번 썼다.** 물건은 하나뿐인데 세 개를 쓴 답이 나왔다.

세 번째. 차이는 **커진다.** 물건 하나로도 `⌊W/w⌋`번까지 중복되고, 물건이 여러 개면 각각이 독립적으로 중복된다. 그래서 이 오류는 작은 예제에서 우연히 맞고 큰 입력에서 크게 틀리는 것이 아니라, **작은 예제에서도 이미 틀린다.** 위 표가 그 증거다.
:::

## 4. 구현

### 4.1 2차원 표 그대로

::: dual
```python title="0/1 배낭 — 2차원 표와 역추적"
W = 9
items = [(3, 8), (4, 9), (5, 11)]           # (무게, 가치)

n = len(items)
dp = [[0] * (W + 1) for _ in range(n + 1)]  # dp[i][c] = 앞 i개만 쓰고 용량 c일 때 최대 가치
for i in range(1, n + 1):
    w, v = items[i - 1]
    for c in range(W + 1):
        dp[i][c] = dp[i - 1][c]                       # i번을 넣지 않는다
        if c >= w and dp[i - 1][c - w] + v > dp[i][c]:
            dp[i][c] = dp[i - 1][c - w] + v           # i번을 넣는다

print("c    :", " ".join("%2d" % c for c in range(W + 1)))
for i in range(n + 1):
    print("i=%d  :" % i, " ".join("%2d" % dp[i][c] for c in range(W + 1)))

chosen, c = [], W                           # 윗줄과 값이 같으면 그 물건은 안 넣은 것이다
for i in range(n, 0, -1):
    if dp[i][c] != dp[i - 1][c]:
        chosen.append(i)
        c -= items[i - 1][0]
chosen.reverse()
print("최대 가치 =", dp[n][W], "/ 고른 물건 =", chosen)
```
```cpp title="0/1 배낭 — 2차원 표와 역추적"
#include <cstdio>
#include <vector>
using namespace std;

int main() {
    int W = 9;
    vector<pair<int, int>> items = {{3, 8}, {4, 9}, {5, 11}};   // (무게, 가치)

    int n = items.size();
    vector<vector<int>> dp(n + 1, vector<int>(W + 1, 0));       // dp[i][c] = 앞 i개만 쓰고 용량 c일 때 최대 가치
    for (int i = 1; i <= n; i++) {
        int w = items[i - 1].first, v = items[i - 1].second;
        for (int c = 0; c <= W; c++) {
            dp[i][c] = dp[i - 1][c];                            // i번을 넣지 않는다
            if (c >= w && dp[i - 1][c - w] + v > dp[i][c])
                dp[i][c] = dp[i - 1][c - w] + v;                // i번을 넣는다
        }
    }

    printf("c    :");
    for (int c = 0; c <= W; c++) printf(" %2d", c);
    for (int i = 0; i <= n; i++) {
        printf("\ni=%d  :", i);
        for (int c = 0; c <= W; c++) printf(" %2d", dp[i][c]);
    }
    printf("\n");

    vector<int> chosen;                                          // 윗줄과 값이 같으면 그 물건은 안 넣은 것이다
    int c = W;
    for (int i = n; i >= 1; i--) {
        if (dp[i][c] != dp[i - 1][c]) {
            chosen.push_back(i);
            c -= items[i - 1].first;
        }
    }
    printf("최대 가치 = %d / 고른 물건 = [", dp[n][W]);
    for (int k = (int)chosen.size() - 1; k >= 0; k--)
        printf("%d%s", chosen[k], k ? ", " : "");
    printf("]\n");
    return 0;
}
```

**복잡도:** 시간 $O(nW)$ — 칸이 $(n+1)(W+1)$개이고 칸마다 상수 번의 비교와 덧셈만 한다. 공간 $O(nW)$ — 표를 통째로 들고 있다. 역추적을 하려면 이 표가 필요하고, 답의 값만 필요하면 다음 절처럼 한 줄로 줄인다.

### 4.2 한 줄로 접기 — 방향이 알고리즘을 정한다

::: dual
```python title="1차원 배낭 — 루프 방향과 완전탐색 검산"
W = 9
items = [(3, 8), (4, 9), (5, 11)]


def knapsack(items, W, reuse):
    dp = [0] * (W + 1)                      # dp[c] = 용량 c에서 지금까지의 최대 가치
    for w, v in items:
        # 방향이 전부다. 내림차순이면 dp[c-w]는 이번 물건을 아직 안 쓴 값이고,
        # 오름차순이면 이번 물건을 이미 쓴 값이다.
        span = range(w, W + 1) if reuse else range(W, w - 1, -1)
        for c in span:
            if dp[c - w] + v > dp[c]:
                dp[c] = dp[c - w] + v
    return dp


def brute(items, W, reuse):                 # 검산용 완전탐색 — 물건마다 쓸지 말지 다 해 본다
    def go(idx, cap):
        if idx == len(items):
            return 0
        best = go(idx + 1, cap)             # 이 물건을 쓰지 않는다
        w, v = items[idx]
        if cap >= w:
            cand = go(idx if reuse else idx + 1, cap - w) + v
            if cand > best:
                best = cand
        return best
    return go(0, W)


down = knapsack(items, W, False)            # 내림차순 — 각 물건을 최대 한 번
up = knapsack(items, W, True)               # 오름차순 — 각 물건을 몇 번이든
print("c              :", " ".join("%2d" % c for c in range(W + 1)))
print("내림차순(0/1)  :", " ".join("%2d" % x for x in down), "→", down[W])
print("오름차순(무한) :", " ".join("%2d" % x for x in up), "→", up[W])
print("완전탐색 0/1 =", brute(items, W, False), "/ 완전탐색 무한 =", brute(items, W, True))
```
```cpp title="1차원 배낭 — 루프 방향과 완전탐색 검산"
#include <cstdio>
#include <functional>
#include <vector>
using namespace std;

int W = 9;
vector<pair<int, int>> items = {{3, 8}, {4, 9}, {5, 11}};

vector<int> knapsack(const vector<pair<int, int>>& items, int W, bool reuse) {
    vector<int> dp(W + 1, 0);               // dp[c] = 용량 c에서 지금까지의 최대 가치
    for (auto [w, v] : items) {
        // 방향이 전부다. 내림차순이면 dp[c-w]는 이번 물건을 아직 안 쓴 값이고,
        // 오름차순이면 이번 물건을 이미 쓴 값이다.
        if (reuse) {
            for (int c = w; c <= W; c++)
                if (dp[c - w] + v > dp[c]) dp[c] = dp[c - w] + v;
        } else {
            for (int c = W; c >= w; c--)
                if (dp[c - w] + v > dp[c]) dp[c] = dp[c - w] + v;
        }
    }
    return dp;
}

int brute(const vector<pair<int, int>>& items, int W, bool reuse) {   // 검산용 완전탐색
    function<int(int, int)> go = [&](int idx, int cap) -> int {
        if (idx == (int)items.size()) return 0;
        int best = go(idx + 1, cap);        // 이 물건을 쓰지 않는다
        auto [w, v] = items[idx];
        if (cap >= w) {
            int cand = go(reuse ? idx : idx + 1, cap - w) + v;
            if (cand > best) best = cand;
        }
        return best;
    };
    return go(0, W);
}

int main() {
    vector<int> down = knapsack(items, W, false);   // 내림차순 — 각 물건을 최대 한 번
    vector<int> up = knapsack(items, W, true);      // 오름차순 — 각 물건을 몇 번이든
    printf("c              :");
    for (int c = 0; c <= W; c++) printf(" %2d", c);
    printf("\n내림차순(0/1)  :");
    for (int c = 0; c <= W; c++) printf(" %2d", down[c]);
    printf(" → %d", down[W]);
    printf("\n오름차순(무한) :");
    for (int c = 0; c <= W; c++) printf(" %2d", up[c]);
    printf(" → %d\n", up[W]);
    printf("완전탐색 0/1 = %d / 완전탐색 무한 = %d\n",
           brute(items, W, false), brute(items, W, true));
    return 0;
}
```

```console
완전탐색 0/1 = 20 / 완전탐색 무한 = 24
```

**복잡도:** 시간 $O(nW)$ — 물건마다 용량 축을 한 번 훑으므로 $n \times W$회의 갱신이다. 2차원 판과 같다. 공간 $O(W)$ — 배열 한 줄. **줄어든 것은 공간뿐이고, 대신 역추적이 불가능해진다.** 덮어쓰는 순간 "어느 물건에서 이 값이 왔는지"가 사라지기 때문이다. 고른 물건을 출력해야 하면 2차원 표를 유지하거나 선택 여부를 따로 기록해야 한다.

완전탐색이 두 값을 그대로 재현한다. `reuse` 인자가 `idx`를 진행시키느냐 마느냐만 바꾸는 것과, DP에서 루프 방향만 바꾸는 것이 정확히 같은 일이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 역방향 루프 | `range(W, w - 1, -1)` — 끝값이 배타적이라 `w - 1` | `for (int c = W; c >= w; c--)` — 조건이 포함적이라 `>= w` |
| 루프 방향 분기 | `range` 객체를 변수에 담아 한 루프로 쓴다 | `range` 객체가 없어 `if`로 루프를 둘로 쓴다. 여기가 두 코드의 유일한 구조 차이다 |
| 2차원 배열 | `[[0] * (W+1) for _ in range(n+1)]`. `[[0]*(W+1)]*(n+1)`은 같은 줄을 공유한다([0-2](#/0-2)) | `vector<vector<int>>(n+1, vector<int>(W+1, 0))` |
| 튜플 분해 | `for w, v in items` | `for (auto [w, v] : items)` — C++17 구조적 바인딩 |
| 재귀 람다 | 중첩 `def go` 그대로 | `std::function`이 필요하다. `auto`로는 자기 타입이 안 정해진다 |

### 4.3 $O(nW)$는 다항식이 아니다

::: perf
무게가 균등 무작위인 물건 100개, 용량 $10^5$. 즉 표가 $10^7$칸이다.

| | 시간 |
|---|---|
| Python 3.13, 1차원 내림차순 | **1.69 s** |
| C++17 `-O2`, 같은 코드 | **0.010 s** |

부분합(§4.4)에서 $n = 100$, 합 상한 $10^5$:

| | 시간 |
|---|---|
| Python 불린 배열 | 0.73 s |
| Python 정수 비트 연산 | **0.4 ms** (약 1,800배) |
| C++ `vector<char>` | 0.007 s |
| C++ `std::bitset` | **0.3 ms** |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 5회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/knapsack_scale.py` 와 `.cpp` 다.)

**비트 연산 쪽 배수는 유효숫자 두 자리로만 적었다.** 분모가 밀리초 이하라 실행마다 크게 흔들린다 — 5회에서 Python 비트 연산은 0.3\~0.7 ms, C++ `bitset`은 0.3\~0.5 ms였고, 그 결과 Python 배수는 970배에서 2,250배 사이를 오갔다. ==흔들리는 것은 배수의 끝자리이고 흔들리지 않는 것은 "안쪽 루프가 통째로 사라졌다"는 사실이다.== 초 단위로 재는 쪽은 조용하다 — Python 1차원 배낭은 1.59\~1.80 s, 불린 부분합은 0.72\~0.82 s였다.

C++이 170배 가까이 빠른 것은 언어 상수만이 아니라 `-O2`가 안쪽 루프를 벡터화하기 때문이다. 그래도 자릿수의 교훈은 남는다 — **$10^7$칸은 Python에서 1초대, C++에서 0.01초대다.**
:::

$O(nW)$를 보고 "다항식이니 안전하다"고 읽으면 안 된다. 입력의 **크기**는 물건 $n$개와 용량을 적은 숫자 하나다. 숫자 $W$를 적는 데 드는 자릿수는 $\log W$이므로, $W$에 비례하는 시간은 **입력 길이에 대해 지수적**이다. 이런 복잡도를 유사 다항식(pseudo-polynomial)이라고 부른다.

실전에서 이것이 무엇을 뜻하는지는 간단하다. $n = 100$이어도 $W = 10^9$면 표가 $10^{11}$칸이고, 배열 한 줄만 잡아도 4 GB다. **$n$이 작다는 사실은 배낭에서 아무 위안이 되지 않는다.** 이때는 무게가 아니라 가치를 축으로 잡거나(가치의 총합이 작을 때), 물건을 반으로 갈라 중간에서 만나는 방법으로 간다.

### 4.4 부분합 — 값이 참/거짓인 배낭

"합이 정확히 $S$가 되는 부분집합이 있는가"는 가치를 버리고 도달 가능성만 남긴 배낭이다. `max`가 `or`로 바뀔 뿐 구조는 같고, **내림차순이어야 하는 이유도 그대로다.**

::: dual
```python title="부분합 — 불린 DP와 비트 연산"
nums = [3, 4, 5, 8]
S = 20                                      # 관심 있는 합의 상한
target = 12

can = [False] * (S + 1)                     # can[s] = 부분집합의 합으로 s를 만들 수 있는가
can[0] = True                               # 아무것도 안 고르면 합은 0이다
for x in nums:
    for s in range(S, x - 1, -1):           # 0/1과 같은 이유로 내림차순이다
        if can[s - x]:
            can[s] = True

bits = 1                                    # 비트 i = 합 i를 만들 수 있는가. 0번 비트만 켠 상태에서 시작
for x in nums:
    bits |= bits << x                       # 이 한 줄이 위의 안쪽 루프 전체를 대신한다

dp_sums = [s for s in range(S + 1) if can[s]]
bit_sums = [s for s in range(S + 1) if bits >> s & 1]
print("불린 DP :", " ".join("%2d" % s for s in dp_sums))
print("비트 연산:", " ".join("%2d" % s for s in bit_sums))
print("두 결과가 같은가:", dp_sums == bit_sums)
print("합 %d 을 만들 수 있는가: %s" % (target, can[target]))
```
```cpp title="부분합 — 불린 DP와 비트 연산"
#include <bitset>
#include <cstdio>
#include <vector>
using namespace std;

const int S = 20;                           // 관심 있는 합의 상한
int target = 12;

int main() {
    vector<int> nums = {3, 4, 5, 8};

    vector<char> can(S + 1, 0);             // can[s] = 부분집합의 합으로 s를 만들 수 있는가
    can[0] = 1;                             // 아무것도 안 고르면 합은 0이다
    for (int x : nums)
        for (int s = S; s >= x; s--)        // 0/1과 같은 이유로 내림차순이다
            if (can[s - x]) can[s] = 1;

    bitset<S + 1> bits;                     // 비트 i = 합 i를 만들 수 있는가
    bits[0] = 1;                            // 0번 비트만 켠 상태에서 시작
    for (int x : nums)
        bits |= bits << x;                  // 이 한 줄이 위의 안쪽 루프 전체를 대신한다

    vector<int> dp_sums, bit_sums;
    for (int s = 0; s <= S; s++) if (can[s]) dp_sums.push_back(s);
    for (int s = 0; s <= S; s++) if (bits[s]) bit_sums.push_back(s);
    printf("불린 DP :");
    for (int s : dp_sums) printf(" %2d", s);
    printf("\n비트 연산:");
    for (int s : bit_sums) printf(" %2d", s);
    printf("\n두 결과가 같은가: %s\n", dp_sums == bit_sums ? "True" : "False");
    printf("합 %d 을 만들 수 있는가: %s\n", target, can[target] ? "True" : "False");
    return 0;
}
```
:::

```console
불린 DP :  0  3  4  5  7  8  9 11 12 13 15 16 17 20
비트 연산:  0  3  4  5  7  8  9 11 12 13 15 16 17 20
두 결과가 같은가: True
합 12 을 만들 수 있는가: True
```

**복잡도:** 불린 판은 시간 $O(nS)$ — 수마다 합 축을 한 번 훑는다. 비트 판은 $O(nS/64)$ — 한 번의 시프트가 워드 64칸을 동시에 옮기므로 갱신 횟수가 워드 폭만큼 나뉜다. 점근 표기의 차수는 같고 **상수만 64분의 1**인데, 그 상수가 §4.3의 실측에서 약 1,800배로 나타났다. Python 쪽 배율이 64보다 훨씬 큰 것은 바이트코드 루프 한 바퀴가 워드 하나를 옮기는 것보다 비싸기 때문이다.

::: note
비트 판은 "만들 수 있는가"만 답한다. **어떤 원소로 만들었는지는 알려 주지 않는다.** 구성까지 필요하면 불린 표를 남기고 역추적하거나, 각 수를 처리한 뒤의 비트 상태를 따로 저장해야 한다.
:::

::: pitfall
- **0/1을 오름차순으로 돈다.** 같은 물건이 여러 번 들어간 값이 조용히 나온다. §3의 손추적이 그 장면이다.
- **무한 배낭을 내림차순으로 돈다.** 반대 방향의 같은 실수다. 각 물건을 한 번씩만 쓴 답이 나온다.
- **"정확히 채워야 한다"를 `dp = [0]*(W+1)`로 시작한다.** 용량을 남겨도 되는 문제면 0이 맞지만, 정확히 $W$를 채워야 하는 문제라면 `dp[0] = 0`, 나머지는 $-\infty$로 시작해야 한다. 0으로 두면 "못 채운 상태"와 "채웠는데 가치가 0"이 구분되지 않는다.
- **무게가 0인 물건.** 0/1에서는 문제없지만 무한 배낭에서는 무한히 넣을 수 있어 무한 루프나 오버플로가 된다. 입력에 `w = 0`이 가능한지 확인하라.
- **`W`가 크다.** $W \le 10^5$ 정도까지가 실용 범위다. $10^9$이 보이면 이 유형이 아니라 다른 축을 찾아야 한다(§4.3).
- **가치의 합이 `int`를 넘는다.** 물건 $10^5$개에 가치 $10^5$이면 합이 $10^{10}$이다. C++에서 `long long`으로 가야 한다. Python은 상관없다.
:::

## 5. 어디에 쓰이는가

**동영상 인코더의 비트 배분이 배낭이다.** 프레임 하나에 쓸 수 있는 비트가 정해져 있고, 블록마다 양자화 수준을 어떻게 고르느냐에 따라 비트 소모와 화질 손실이 달라진다. "총 비트 예산 안에서 왜곡 합을 최소화한다"는 문장은 배낭의 정의 그 자체다. 실제 인코더는 표가 너무 커서 라그랑주 완화로 근사하지만, **그 근사가 무엇을 근사하는지가 이 챕터의 표**다.

**부분합은 회계 대사와 지갑의 잔돈 선택에 그대로 있다.** 입금 한 건이 어떤 청구서들의 합인지 찾는 작업, 그리고 암호화폐 지갑이 보낼 금액을 맞추려고 보유한 잔액 조각(UTXO)의 부분집합을 고르는 작업이 같은 문제다. 후자는 조각이 많아 순수 DP 대신 분기한정 탐색을 쓰지만, **"거스름돈이 남지 않는 조합이 있는가"를 먼저 묻는 구조**가 부분합이다.

**클라우드 인스턴스 하나에 어떤 작업을 올릴지 고르는 것도 배낭이다.** 단, 여기서 흔한 착각이 하나 있다. 서버가 여러 대이고 모든 작업을 어딘가에는 올려야 한다면 그것은 배낭이 아니라 **빈 패킹**(bin packing)이고, 다항 시간 최적해가 알려져 있지 않아 근사 알고리즘을 쓴다. **용량이 하나면 배낭, 상자가 여러 개면 빈 패킹이다.** 이 구분을 못 하면 없는 알고리즘을 찾게 된다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "무게 제한", "최대 K원까지", "제한 시간 안에", "가치의 합을 최대로", "합이 정확히 S가 되는", "각 물건은 한 번만 / 몇 개든 쓸 수 있다"
- 제약조건: 물건 수 $n \le 100 \sim 10^4$, 용량 $W \le 10^5$ 수준. $nW \le 10^8$이면 통과한다. **$W$가 $10^9$이면 이 유형이 아니다** — 가치 축으로 뒤집거나 절반으로 나누는 다른 풀이를 찾아야 한다
- 혼동 주의: 개수 제한이 없으면 무한 배낭(오름차순), 있으면 0/1(내림차순). 가치 없이 도달 가능성만 물으면 부분합. **비율 순으로 담아도 최적이면 그건 배낭이 아니라 분할 가능 배낭이고 그리디다**([VI-1](#/vi-1)). 상자가 여러 개면 빈 패킹이라 DP로 안 풀린다. 물건이 아니라 순서를 고르는 것이면 [VIII-6](#/viii-6)이나 [VIII-7](#/viii-7)이다
- 반례 함정: **효율(가치/무게) 순 그리디.** §1의 예제가 그것이고, 예제 입력에서는 자주 맞는다. 그리고 **"정확히 채워야 한다"는 조건** — 초기값을 0으로 두면 못 채운 상태가 성공으로 위장한다
:::

::: interview
"0/1 배낭과 무한 배낭의 구현 차이를 말해 보라"는 자주 나온다. 답의 뼈대는 세 문장이다. ① 2차원 점화식은 둘 다 `max(안 넣기, 넣기)`이고, 0/1은 `dp[i-1][c-w]`를, 무한은 `dp[i][c-w]`를 읽는다. ② 1차원으로 접으면 그 차이가 **용량 루프 방향**으로 나타난다 — 내림차순이면 아직 안 갱신된 값(= 윗줄)을, 오름차순이면 이미 갱신된 값(= 같은 줄)을 읽는다. ③ 그래서 두 코드는 한 글자 차이이고, 잘못 쓰면 예외 없이 다른 문제의 정답이 나온다.

이어서 "$O(nW)$인데 왜 어렵다고 하는가"가 붙는다. **유사 다항식**이라는 단어와 그 이유($W$의 입력 길이는 $\log W$)를 말할 수 있으면 된다.
:::

## 연습

::: quiz
**개수 제한이 있는지, 정확히 채워야 하는지, 축이 무게인지 가치인지 셋을 먼저 확인하라.**

**1. 백준 2293 동전 1 (골드 5)** — https://www.acmicpc.net/problem/2293
- 신호: "각각의 동전은 몇 개라도 사용할 수 있다" + "경우의 수". 개수 무제한이므로 무한 배낭이고, 답이 최댓값이 아니라 개수이므로 `max`가 `+`로 바뀐다.
- 상태: `dp[s]` = 합이 `s`가 되는 경우의 수. 초기값 `dp[0] = 1`.
- 자료구조: 1차원 배열, **동전 루프가 바깥이고 금액 루프가 안쪽이며 오름차순**이다. 두 루프를 뒤집으면 순서가 다른 것을 다른 경우로 세어 답이 커진다. 이 문제의 전부가 그 순서다.

**2. 백준 1699 제곱수의 합 (실버 3)** — https://www.acmicpc.net/problem/1699
- 신호: "제곱수들의 합으로 표현할 때 항의 최소 개수". 제곱수는 몇 번이든 쓸 수 있으니 무한 배낭이고, 가치가 아니라 개수를 최소화한다.
- 상태: `dp[v]` = `v`를 만드는 최소 항 수. 초기값 `dp[0] = 0`.
- 자료구조: 배열 하나. 물건 목록을 미리 만들 필요도 없다 — `j*j <= v`인 `j`를 그 자리에서 훑으면 된다.

**3. 백준 7579 앱 (골드 3)** — https://www.acmicpc.net/problem/7579
- 신호: "메모리를 M바이트 이상 확보" + "비용의 합을 최소화". 0/1 배낭인데 **확보해야 할 메모리가 $10^7$까지**라 무게를 축으로 잡으면 표가 터진다.
- 상태: `dp[c]` = 비용을 정확히 `c`만큼 쓸 때 확보 가능한 최대 메모리. **축을 무게에서 가치로 뒤집는 것**이 이 문제의 유일한 아이디어이고, 비용의 총합은 100 × 100 = 10,000을 넘지 않는다.
- 자료구조: 1차원 배열 + 내림차순. 답은 `dp[c] >= M`을 만족하는 가장 작은 `c`다.
:::

## 요약

- 배낭은 "예산 안에서 부분집합 고르기"다. 효율 순 그리디는 **남는 자투리를 계산에 넣지 못해** 틀린다.
- 상태 `dp[i][c]`의 `i`축은 성능이 아니라 **규칙을 새기는 자리**다. 그 축이 있어야 "각 물건 한 번"이 지켜진다.
- 점화식은 `max(dp[i-1][c], dp[i-1][c-w]+v)`. 두 항 모두 윗줄을 읽는다는 것이 0/1의 정의다.
- 한 줄로 접으면 차이가 **루프 방향**으로 나타난다. 내림차순이면 0/1, 오름차순이면 무한 배낭이다. **오름차순은 버그가 아니라 다른 알고리즘이다.**
- 부분합은 값이 참/거짓인 배낭이다. `or`로 바꾸면 그대로이고, 비트 시프트 한 줄이 안쪽 루프를 대신해 상수가 64분의 1이 된다.
- $O(nW)$는 **유사 다항식**이다. $W$를 적는 데 드는 자릿수는 $\log W$이므로 $W = 10^9$이면 $n$이 100이어도 끝나지 않는다.
- 1차원으로 접으면 역추적이 죽는다. 고른 물건을 출력해야 하면 2차원 표를 남겨라.
- 상자가 하나면 배낭, 여러 개면 빈 패킹이다. 후자는 이 DP로 풀리지 않는다.
