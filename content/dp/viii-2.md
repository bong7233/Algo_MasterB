# VIII-2 메모이제이션 vs 타뷸레이션

::: lead
같은 점화식을 답에서 내려오며 풀 것인가, 가장 작은 것부터 쌓아 올릴 것인가. 이 선택은 취향이 아니라 어느 쪽이 **아예 안 되는지**의 문제다.
:::

## 1. 문제

[VIII-1](#/viii-1)에서 세운 절차의 마지막 칸은 계산 순서였고, 거스름돈에서는 그것이 공짜였다. $dp[x]$가 자기보다 작은 인덱스만 읽으니 1부터 올리면 끝났다. 상태가 조금만 복잡해지면 그 공짜가 사라진다.

부분집합의 합 문제를 보자. 무게 12개가 있고 각각 5만에서 90만 사이다. 용량 300만을 넘지 않게 골라 합을 최대로 만든다. [VIII-5](#/viii-5)의 배낭 표를 그대로 쓰면 상태는 `(몇 번째 물건까지 봤는가, 남은 용량)`이고, 표는 $13 \times 3{,}000{,}001 = $ **3,900만 칸**이다.

그런데 무게 12개로 만들 수 있는 "남은 용량"은 아무리 많아야 $2^{12} = 4{,}096$가지다. **표의 99.99%는 아무도 묻지 않는 질문이다.** 실제로 재 보면 이렇다.

| | 시간 | 다룬 칸 |
|---|---|---|
| 표를 전부 채운다 | 2,068 ms | 39,000,013 |
| 답에서 내려오며 필요한 것만 계산한다 | **1.4 ms** | **3,403** |

1,500배다. 두 방법의 점화식은 **글자 하나 다르지 않다.**

반대 방향의 사고도 있다. `1로 만들기`(수를 2로 나누거나 3으로 나누거나 1을 빼서 1로 만드는 최소 횟수)를 $n = 10^6$에 대해 답에서 내려오며 풀면, 재귀가 $10^6$번 겹쳐 쌓인다. Python은 `RecursionError`로 멈추고, C++은 **SIGSEGV로 그냥 죽는다.** 표를 아래에서 쌓으면 212 ms에 끝난다.

같은 점화식, 두 방향. **어느 쪽이 이기는지는 문제가 정하고, 그 판정 기준은 이 절에서 끝난다.**

## 2. 아이디어

### 2.1 두 방향의 정의

| | 하향식 — 메모이제이션 | 상향식 — 타뷸레이션 |
|---|---|---|
| 어디서 시작하는가 | **답**의 상태 | 가장 **작은** 상태 |
| 어떻게 진행하는가 | 필요한 하위 상태를 재귀로 요구한다 | 루프로 순서대로 채운다 |
| 언제 적는가 | 재귀가 돌아온 뒤 | 그 자리에서 |
| 계산 순서를 누가 정하는가 | **재귀 호출 스택** | **사람** |

마지막 줄이 이 절의 전부다. 나머지 차이는 전부 거기서 파생된다.

### 2.2 재귀 호출 스택이 위상 정렬을 대신한다

[VIII-1](#/viii-1) §2.5가 계산 순서의 정체를 이미 말했다. 상태 사이의 의존 관계를 그래프로 그리면 그것은 사이클 없는 방향 그래프이고, 유효한 계산 순서란 곧 그 그래프의 **위상 순서**다([IV-6](#/iv-6)).

상향식은 그 위상 순서를 사람이 미리 찾아 루프의 형태로 적어 넣는다. 인덱스가 곧 의존 순서면 공짜지만, 아니면 직접 만들어야 한다.

하향식은 만들지 않는다. **의존 그래프를 DFS로 훑고, 되돌아오는 순간에 값을 적는다.** 그것이 후위 순회이고, 후위 순회의 역순이 위상 순서라는 것이 [IV-6](#/iv-6)의 결론이었다. ==메모에 값이 적히는 순서는 그 자체로 하나의 위상 순서다.== §3에서 손으로 확인한다.

[V-4](#/v-4)가 이미 이 대비를 최단경로에서 보여 줬다. 벨만 방정식이라는 하나의 점화식을, 벨만-포드는 "몇 개의 간선을 썼는가"라는 축을 추가해서, 다익스트라는 실행 중에 확정 순서를 만들어 내면서 푼다. **최단경로가 DP의 한 사례였고, 하향식과 상향식의 대비는 그 사례에서 본 것의 일반형이다.**

### 2.3 하향식이 이기는 조건 — 희소한 상태 공간

상향식은 **표의 모든 칸을 채운다.** 그것이 정의다. 그래서 이런 상황에서 무너진다.

- 상태가 `(인덱스, 남은 자원)` 꼴이고 자원의 범위가 크다. §1의 3,900만 칸이 그 모양이다.
- 도달 가능한 상태가 전체의 일부다. 무게 12개로 도달 가능한 잔여 용량은 4,096가지 이하인데 표는 300만 칸을 잡는다.
- 상태의 인덱스가 정수가 아니다. 좌표쌍, 문자열, 비트마스크와 정수의 곱 — 배열로 잡을 수 없으면 표를 만들 수 없다.

하향식은 **묻지 않은 질문에는 답하지 않는다.** 답의 상태에서 출발해 실제로 필요한 것만 아래로 요구하므로, 계산되는 상태는 정확히 "답에서 도달 가능한 상태"뿐이다.

### 2.4 상향식이 이기는 조건 — 깊이와 상수와 압축

반대로 상태가 조밀하면(표의 거의 모든 칸이 필요하면) 상향식이 네 가지를 가져간다.

- **재귀 깊이가 없다.** 하향식의 깊이는 의존 사슬의 길이이고, 그것이 $10^5$을 넘으면 Python은 예외로, C++은 신호로 죽는다.
- **호출 오버헤드가 없다.** 함수 호출 한 번에는 프레임 준비·인자 전달·메모 조회가 붙는다. 루프의 한 바퀴에는 없다. 실측에서 같은 문제가 Python 5.2배, C++ 7.4배 차이였다.
- **캐시 지역성이 있다.** 표를 인덱스 순으로 훑으면 연속 메모리를 순차 접근한다. 해시 메모는 접근이 흩어진다([II-1](#/ii-1)).
- **한 줄로 접을 수 있다.** $dp[i]$가 $dp[i-1]$만 읽으면 배열 한 줄로 공간을 줄일 수 있다([VIII-5](#/viii-5) §4.2). **하향식으로는 불가능하다** — 호출이 언제 돌아올지 모르므로 지울 수 있는 칸이 없다.

### 2.5 같은 표, 다른 채우는 순서

::: widget dp-table {"kind":"knapsack","cap":8,"items":[{"w":5,"v":5},{"w":3,"v":3},{"w":2,"v":2}]}
:::

위젯은 무게 `{5, 3, 2}`와 용량 8의 표를 채운다. 가치를 무게와 같게 두었으므로 각 칸은 "앞 $i$개 중 골라 용량 $left$를 넘지 않는 최대 합"이고, 점화식은 다음과 같다.

$$dp[i][left] = \max\big(dp[i-1][left],\; w_i + dp[i-1][left-w_i]\big)$$

**여기서 볼 것은 값이 아니라 스텝 번호다.** 위젯이 채우는 순서는 $i$를 1부터 올리며 각 행에서 $left$를 0부터 올리는 것 — 27칸을 하나도 빠뜨리지 않고 순서대로 채운다. 화살표는 예외 없이 **바로 윗 행**의 이미 채워진 칸을 가리킨다.

하향식은 같은 표에서 **7칸만 건드리고, 그 7칸을 다른 순서로 확정한다.** 그 순서가 무엇이고 왜 그래도 되는지가 다음 절의 손추적이다.

## 3. 손으로 따라가기

::: trace
무게 `ws = [5, 3, 2]`, 용량 8. 하향식의 상태는 `(i, left)` = "앞 $i$개만 놓고 남은 용량이 $left$일 때의 최대 합"이고, `go(3, 8)`에서 시작한다.

`go(i, left)`는 두 갈래를 본다. **먼저** `go(i-1, left)`(안 넣는다), **그다음** 무게가 들어가면 `go(i-1, left - w)`(넣는다). `i == 0`은 기저라 메모에 적지 않는다.

메모에 값이 **적히는 순서**를 적어라. 적히는 시점은 재귀가 돌아온 뒤다.

| 순서 | 확정되는 칸 (i, left) | 읽은 칸 | 값 |
|---|---|---|---|
| 1 | (1, 8) | (0,8)=0, (0,3)=0 | 5 |
| 2 | (1, 5) | (0,5)=0, (0,0)=0 | 5 |
| 3 | (2, 8) | (1,8)=5, (1,5)=5 | 8 |
| 4 | | | |
| 5 | | | |
| 6 | | | |
| 7 | | | |

세 가지를 확인하라.

- [ ] 상향식은 $i = 1, 2, 3$의 모든 $left$를 채워 27칸을 다룬다. 하향식이 **끝까지 한 번도 건드리지 않는 칸은 몇 개**인가
- [ ] 확정 순서를 위에서 아래로 읽으면, **각 칸은 자기가 읽는 칸보다 항상 뒤에 나오는가.** 그렇다면 이 순서는 무엇인가
- [ ] `(1, 3)`의 값은 0이다. 이것은 "아무것도 못 넣었다"인가 "합이 0인 조합을 골랐다"인가. 두 뜻이 갈리는 문제라면 무엇을 바꿔야 하는가
:::

::: answer
| 순서 | 확정되는 칸 (i, left) | 읽은 칸 | 값 |
|---|---|---|---|
| 1 | (1, 8) | (0,8)=0, (0,3)=0 | 5 |
| 2 | (1, 5) | (0,5)=0, (0,0)=0 | 5 |
| 3 | (2, 8) | (1,8)=5, (1,5)=5 | 8 |
| 4 | (1, 6) | (0,6)=0, (0,1)=0 | 5 |
| 5 | (1, 3) | (0,3)=0 | 0 |
| 6 | (2, 6) | (1,6)=5, (1,3)=0 | 5 |
| 7 | (3, 8) | (2,8)=8, (2,6)=5 | 8 |

첫 번째. 하향식이 확정한 칸은 **7개**, 상향식이 채우는 칸은 **27개**다. 건드리지 않는 칸이 **20개**, 즉 74%다. 무게가 셋뿐인 장난감 입력에서도 이 비율이 나온다. §1의 실제 입력에서는 99.99%였다.

두 번째. **그렇다.** 순서 3의 `(2,8)`은 자기가 읽는 `(1,8)`과 `(1,5)`가 확정된 뒤에 나오고, 순서 6의 `(2,6)`은 `(1,6)`·`(1,3)` 뒤에, 순서 7의 `(3,8)`은 `(2,8)`·`(2,6)` 뒤에 나온다. 예외가 없다.

==그러므로 이 순서는 의존 그래프의 위상 순서다.== 상향식이 쓰는 사전식 순서 `(1,0) (1,1) … (1,8) (2,0) …`도 또 다른 위상 순서다. **둘은 서로 다른 순서지만 같은 조건을 만족한다** — "읽는 칸이 이미 확정되어 있을 것". 하향식은 그 순서를 사람이 찾은 것이 아니라 재귀 호출이 만들어 낸 것이고, 그것이 §2.2의 요점이다.

세 번째. 무게 5가 남은 용량 3에 들어가지 않으니 `(1,3)`은 "안 넣는다" 한 갈래만 보고 0을 받았다. 이 문제에서는 두 뜻이 같다 — 아무것도 안 골라도 합 0은 유효한 답이기 때문이다.

**"정확히 용량을 채워야 한다"로 바뀌면 갈린다.** 그때 0은 "성공했고 합이 0"이라는 뜻이 되어, 못 채운 상태가 성공으로 위장한다. 초기값을 $-\infty$로 두고 기저만 0으로 두어야 한다([VIII-1](#/viii-1) §2.4, [VIII-5](#/viii-5)). ==방향을 바꾸는 것으로는 상태 정의와 초기값의 오류를 절대 고칠 수 없다.==
:::

## 4. 구현

### 4.1 같은 점화식을 두 방향으로

::: dual
```python title="두 방향과 확정 순서 — 브루트포스로 검산"
WS = [5, 3, 2]
CAP = 8


def top_down(ws, cap):
    """하향식 — 답에서 시작해 필요한 상태만 재귀로 요구한다."""
    memo = {}
    order = []                                  # 메모에 값이 적히는 순서

    def go(i, left):
        if i == 0:
            return 0                            # 기저: 물건이 없으면 합은 0
        key = (i, left)
        if key in memo:
            return memo[key]
        best = go(i - 1, left)                  # i번째를 안 넣는다
        w = ws[i - 1]
        if w <= left:
            cand = w + go(i - 1, left - w)      # i번째를 넣는다
            if cand > best:
                best = cand
        memo[key] = best
        order.append(key)                       # 재귀가 돌아온 뒤에 적힌다
        return best

    return go(len(ws), cap), order


def bottom_up(ws, cap):
    """상향식 — 가장 작은 상태부터 순서대로 표를 전부 채운다."""
    n = len(ws)
    dp = [[0] * (cap + 1) for _ in range(n + 1)]
    order = []
    for i in range(1, n + 1):                   # 계산 순서를 사람이 루프로 적는다
        w = ws[i - 1]
        for left in range(cap + 1):
            dp[i][left] = dp[i - 1][left]
            if w <= left and w + dp[i - 1][left - w] > dp[i][left]:
                dp[i][left] = w + dp[i - 1][left - w]
            order.append((i, left))
    return dp[n][cap], order


def brute(ws, cap):
    """완전탐색 — 부분집합을 전부 만든다. 검산용."""
    best = 0
    for mask in range(1 << len(ws)):
        s = sum(ws[i] for i in range(len(ws)) if mask >> i & 1)
        if s <= cap and s > best:
            best = s
    return best


ans_td, order_td = top_down(WS, CAP)
ans_bu, order_bu = bottom_up(WS, CAP)
print("[1] 답 — 하향식 %d / 상향식 %d / 브루트포스 %d"
      % (ans_td, ans_bu, brute(WS, CAP)))
print("[2] 하향식이 확정한 칸 %d개, 적힌 순서" % len(order_td))
print("    " + " ".join("(%d,%d)" % (i, c) for i, c in order_td))
print("[3] 상향식이 채운 칸 %d개, 앞 9개" % len(order_bu))
print("    " + " ".join("(%d,%d)" % (i, c) for i, c in order_bu[:9]))
```
```cpp title="두 방향과 확정 순서 — 브루트포스로 검산"
#include <cstdio>
#include <functional>
#include <map>
#include <vector>
using namespace std;

vector<int> WS = {5, 3, 2};
const int CAP = 8;

using Cells = vector<pair<int, int>>;

// 하향식 — 답에서 시작해 필요한 상태만 재귀로 요구한다.
int top_down(const vector<int>& ws, int cap, Cells& order) {
    map<pair<int, int>, int> memo;              // 메모에 값이 적히는 순서를 order 가 받는다

    function<int(int, int)> go = [&](int i, int left) -> int {
        if (i == 0) return 0;                   // 기저: 물건이 없으면 합은 0
        pair<int, int> key = {i, left};
        auto hit = memo.find(key);
        if (hit != memo.end()) return hit->second;
        int best = go(i - 1, left);             // i번째를 안 넣는다
        int w = ws[i - 1];
        if (w <= left) {
            int cand = w + go(i - 1, left - w); // i번째를 넣는다
            if (cand > best) best = cand;
        }
        memo[key] = best;
        order.push_back(key);                   // 재귀가 돌아온 뒤에 적힌다
        return best;
    };

    return go((int)ws.size(), cap);
}

// 상향식 — 가장 작은 상태부터 순서대로 표를 전부 채운다.
int bottom_up(const vector<int>& ws, int cap, Cells& order) {
    int n = ws.size();
    vector<vector<int>> dp(n + 1, vector<int>(cap + 1, 0));
    for (int i = 1; i <= n; i++) {              // 계산 순서를 사람이 루프로 적는다
        int w = ws[i - 1];
        for (int left = 0; left <= cap; left++) {
            dp[i][left] = dp[i - 1][left];
            if (w <= left && w + dp[i - 1][left - w] > dp[i][left])
                dp[i][left] = w + dp[i - 1][left - w];
            order.push_back({i, left});
        }
    }
    return dp[n][cap];
}

// 완전탐색 — 부분집합을 전부 만든다. 검산용.
int brute(const vector<int>& ws, int cap) {
    int best = 0;
    for (int mask = 0; mask < (1 << (int)ws.size()); mask++) {
        int s = 0;
        for (size_t i = 0; i < ws.size(); i++)
            if (mask >> i & 1) s += ws[i];
        if (s <= cap && s > best) best = s;
    }
    return best;
}

int main() {
    Cells order_td, order_bu;
    int ans_td = top_down(WS, CAP, order_td);
    int ans_bu = bottom_up(WS, CAP, order_bu);
    printf("[1] 답 — 하향식 %d / 상향식 %d / 브루트포스 %d\n",
           ans_td, ans_bu, brute(WS, CAP));
    printf("[2] 하향식이 확정한 칸 %d개, 적힌 순서\n", (int)order_td.size());
    printf("    ");
    for (size_t k = 0; k < order_td.size(); k++)
        printf("%s(%d,%d)", k ? " " : "", order_td[k].first, order_td[k].second);
    printf("\n[3] 상향식이 채운 칸 %d개, 앞 9개\n", (int)order_bu.size());
    printf("    ");
    for (size_t k = 0; k < 9 && k < order_bu.size(); k++)
        printf("%s(%d,%d)", k ? " " : "", order_bu[k].first, order_bu[k].second);
    printf("\n");
    return 0;
}
```

**복잡도:** 상향식은 시간 $O(n \cdot cap)$ — 칸이 $(n+1)(cap+1)$개이고 칸마다 비교와 덧셈 상수 번이다. 공간도 $O(n \cdot cap)$이고, 각 행이 윗 행만 읽으므로 한 줄로 접으면 $O(cap)$이다.

하향식은 시간 $O(R \cdot 2)$ — $R$은 **도달 가능한 상태 수**이고, 상태 하나마다 전이 두 갈래를 한 번씩만 본다(두 번째부터는 메모 적중이라 $O(1)$). 공간 $O(R)$ + 재귀 깊이 $O(n)$. **$R$의 상한은 $n \cdot cap$이지만 실제 값은 입력이 정한다** — 여기서는 27 중 7이었고, §1에서는 3,900만 중 3,403이었다.

### 4.2 상태가 희소하면 표가 성립하지 않는다

§1의 입력을 실제로 돌린다. 브루트포스는 무게가 12개뿐이라 $2^{12}$가지를 전부 만들어 대조할 수 있다.

::: dual
```python title="희소 상태 — 하향식이 실제로 묻는 질문은 몇 개인가"
import sys

WS = [812371, 455129, 690001, 137777, 908213, 51233,
      377777, 641009, 219999, 705001, 88811, 493337]
CAP = 3000000


def top_down(ws, cap):
    """반환: (최대 합, 실제로 계산한 상태 수)."""
    memo = {}

    def go(i, left):
        if i == 0:
            return 0
        key = (i, left)
        hit = memo.get(key)
        if hit is not None:
            return hit
        best = go(i - 1, left)
        w = ws[i - 1]
        if w <= left:
            cand = w + go(i - 1, left - w)
            if cand > best:
                best = cand
        memo[key] = best
        return best

    return go(len(ws), cap), len(memo)


def brute(ws, cap):
    """부분집합 4096가지를 전부 만든다."""
    best = 0
    for mask in range(1 << len(ws)):
        s = 0
        for i in range(len(ws)):
            if mask >> i & 1:
                s += ws[i]
        if s <= cap and s > best:
            best = s
    return best


ans, states = top_down(WS, CAP)
cells = (len(WS) + 1) * (CAP + 1)
print("답 %d (브루트포스 %d)" % (ans, brute(WS, CAP)))
print("하향식이 계산한 상태 %d개" % states)
print("상향식 표의 칸      %d개" % cells)
print("닿는 상태는 표의 %.5f%%" % (states / cells * 100))
sys.stdout.flush()
```
```cpp title="희소 상태 — 하향식이 실제로 묻는 질문은 몇 개인가"
#include <cstdio>
#include <functional>
#include <map>
#include <vector>
using namespace std;

vector<int> WS = {812371, 455129, 690001, 137777, 908213, 51233,
                  377777, 641009, 219999, 705001, 88811, 493337};
const int CAP = 3000000;

// 반환: (최대 합, 실제로 계산한 상태 수).
pair<int, long long> top_down(const vector<int>& ws, int cap) {
    map<pair<int, int>, int> memo;

    function<int(int, int)> go = [&](int i, int left) -> int {
        if (i == 0) return 0;
        pair<int, int> key = {i, left};
        auto hit = memo.find(key);
        if (hit != memo.end()) return hit->second;
        int best = go(i - 1, left);
        int w = ws[i - 1];
        if (w <= left) {
            int cand = w + go(i - 1, left - w);
            if (cand > best) best = cand;
        }
        memo[key] = best;
        return best;
    };

    int ans = go((int)ws.size(), cap);
    return {ans, (long long)memo.size()};
}

// 부분집합 4096가지를 전부 만든다.
int brute(const vector<int>& ws, int cap) {
    int best = 0;
    for (int mask = 0; mask < (1 << (int)ws.size()); mask++) {
        int s = 0;
        for (size_t i = 0; i < ws.size(); i++)
            if (mask >> i & 1) s += ws[i];
        if (s <= cap && s > best) best = s;
    }
    return best;
}

int main() {
    auto [ans, states] = top_down(WS, CAP);
    long long cells = (long long)(WS.size() + 1) * (CAP + 1);
    printf("답 %d (브루트포스 %d)\n", ans, brute(WS, CAP));
    printf("하향식이 계산한 상태 %lld개\n", states);
    printf("상향식 표의 칸      %lld개\n", cells);
    printf("닿는 상태는 표의 %.5f%%\n", (double)states / (double)cells * 100.0);
    return 0;
}
```

**복잡도:** 하향식 $O(R \log R)$ — 상태 $R$개를 계산하고 메모 조회가 정렬 컨테이너면 $O(\log R)$이다(해시면 평균 $O(1)$). 상향식은 $O(n \cdot cap) = 3.9 \times 10^7$로 고정이고, **$R = 3{,}403$이 그 값과 무관하게 결정된다는 것이 이 절의 논점이다.** 브루트포스는 $O(2^{12} \cdot 12)$라 여기서만 쓸 수 있다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 메모 저장소 | `dict[(i, left)]` — 튜플이 그대로 키가 된다 | `map<pair<int,int>, int>`. **`pair`에는 기본 `std::hash`가 없어 `unordered_map`에 바로 못 넣는다** — 해시를 직접 주거나 키를 정수로 인코딩한다 |
| 재귀 깊이 초과 | `RecursionError` **예외**. `try`로 잡힌다 | **SIGSEGV.** 잡을 수 없고 스택 트레이스도 안 남는다 |
| 메모 데코레이터 | `@functools.lru_cache(maxsize=None)` 한 줄 | 대응물이 없다. 메모 자료구조를 직접 든다 |
| 재귀 람다 | 중첩 `def go` 그대로 | `std::function`이 필요하다. `auto`로는 자기 타입이 안 정해진다 |
| 2차원 표 | `[[0]*(cap+1) for _ in range(n+1)]` | `vector<vector<int>>`는 행마다 별도 할당이라 캐시 지역성이 나쁘다. 1차원 `vector`에 `i*(cap+1)+c`로 접는 편이 빠르다([II-1](#/ii-1)) |

::: pitfall
- **깊은 재귀에 `lru_cache`를 씌운다.** `setrecursionlimit`을 아무리 올려도 3,332에서 죽는다(실측). 깊이가 문제인 곳에서는 `dict` 메모를 손으로 쓴다.
- **`sys.setrecursionlimit`을 올리면 안전하다고 믿는다.** 한도만 올리고 실제 스택이 부족하면 파이썬 인터프리터 자체가 세그멘테이션 폴트로 죽는다. 깊이가 $10^5$을 넘으면 방향을 바꾸는 것이 정답이다.
- **하향식으로 짜 놓고 한 줄 압축을 시도한다.** 불가능하다. 호출이 언제 돌아올지 모르므로 지워도 되는 칸이 없다.
- **메모 키에 상태의 일부만 넣는다.** 서로 다른 처지가 같은 칸에 겹쳐 답이 조용히 틀린다. **이것은 방향 문제가 아니라 상태 정의 실패다**([VIII-11](#/viii-11)).
- **기저를 메모에 적지 않아 매번 다시 탄다.** 기저가 상수 시간이면 상관없지만, 기저 안에서 반복문을 돌리면 그것이 병목이 된다.
- **파이썬에서 `dict` 메모의 상수를 잊는다.** 튜플 키 하나마다 해시와 객체 할당이 붙는다. 상태가 조밀하면 리스트 인덱싱이 훨씬 싸다.
:::

## 5. 어디에 쓰이는가

**빌드 시스템의 증분 빌드가 하향식 메모 그 자체다.** `make`나 Bazel은 요청받은 타깃에서 출발해 의존성을 재귀로 요구하고, 이미 만들어진 결과는 캐시에서 꺼낸다. 상태는 "이 타깃의 입력 해시", 값은 "그때의 출력물"이고, 캐시 적중이 곧 메모 적중이다. 왜 상향식이 아닌가 — 저장소 전체의 타깃 수에 비해 한 번의 빌드가 실제로 닿는 타깃은 극히 일부이기 때문이다. **§2.3의 희소 상태와 정확히 같은 근거다.** "전부 다시 빌드"가 상향식이고, 그것이 왜 느린지도 같은 문장으로 설명된다.

**스프레드시트 재계산 엔진은 두 방향을 다 쓴다.** 셀 의존 그래프를 위상 정렬해 전부 다시 계산하는 것이 상향식(push)이고, 화면에 보이는 셀에서 출발해 dirty로 표시된 의존 셀만 재귀로 요구하는 것이 하향식(pull)이다. 시트가 커질수록 pull이 이긴다. 그리고 이 엔진들이 **순환 참조를 에러로 띄우는 이유**가 이 절의 §2.2와 같은 사실이다 — 계산 순서는 DAG의 위상 순서여야 하고, 사이클이 있으면 어느 방향으로도 순서가 없다.

**PEG 파서의 packrat 기법도 하향식 메모다.** `(문법 규칙, 입력 위치)` 쌍을 메모해 백트래킹을 선형 시간으로 만든다. 상태 공간은 규칙 수 × 입력 길이지만 실제로 시도되는 조합은 그 일부라, 표를 전부 채우는 방식은 성립하지 않는다. 대신 대가를 치른다 — 메모가 입력 길이에 비례해 커져서, 긴 입력에서 메모리가 병목이 되는 것이 packrat의 알려진 약점이다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "함수 w(a,b,c)를 다음과 같이 정의한다" 처럼 **지문이 재귀식을 그대로 준다**, "더 큰 칸으로만 이동한다" 처럼 **계산 순서를 좌표로 만들 수 없다**, 상태가 "(인덱스, 남은 예산)" 꼴인데 예산 범위가 크다, 그리고 반대편 신호로 "$N \le 10^6$"
- 제약조건: 닿는 상태 수 × 전이 수가 $10^7$ 이하([0-9](#/0-9)). **판정 기준은 표 칸 수 대비 닿는 상태 수의 비**다. 의존 사슬의 길이가 $10^4$을 넘으면 Python 하향식이, $10^5$을 넘으면 C++ 하향식도 위험하다
- 혼동 주의: 인덱스가 곧 의존 순서면 상향식이 짧고 빠르다([VIII-3](#/viii-3)). 배열 한 줄로 접어야 메모리가 맞으면 상향식만 가능하다([VIII-5](#/viii-5)). 상태 그래프에 사이클이 있으면 DP가 아니라 최단경로 계열이다([V-1](#/v-1), [V-2](#/v-2))
- 반례 함정: **`lru_cache`를 씌우면 `setrecursionlimit`을 올려도 깊이 3,332에서 죽는다**(실측). 그리고 메모 키에 상태의 일부만 넣으면 서로 다른 처지가 겹쳐 답이 조용히 틀린다 — 방향을 바꿔도 고쳐지지 않는다([VIII-11](#/viii-11))
:::

::: interview
**"메모이제이션과 타뷸레이션의 차이는 무엇입니까."**
"점화식은 같고 계산 순서를 누가 정하느냐가 다릅니다. 타뷸레이션은 사람이 루프로 순서를 적고, 메모이제이션은 재귀 호출 스택이 그 순서를 만듭니다. 메모에 값이 적히는 순서 자체가 의존 그래프의 위상 순서입니다."

**"그러면 어느 쪽을 씁니까."**
"상태가 희소하면 메모이제이션입니다. 타뷸레이션은 표를 전부 채우는데, 상태가 `(인덱스, 남은 용량)` 꼴이고 용량이 300만이면 표가 3,900만 칸인데 실제로 닿는 상태는 3,000개 남짓인 경우가 있습니다. 반대로 상태가 조밀하면 타뷸레이션입니다 — 재귀 깊이 제한이 없고, 호출 오버헤드가 없고, 배열 한 줄로 접어 메모리를 줄일 수 있습니다. **한 줄 압축은 하향식으로는 불가능합니다.**"

여기까지 말하면 후속 질문은 대개 "재귀 깊이가 문제가 되는 지점"이다. Python 기본 한도 1000, C++은 스택 크기가 곧 한도이고 넘으면 예외가 아니라 SIGSEGV라는 것을 짚으면 된다.
:::

## 연습

::: quiz
세 문제 모두 **방향을 먼저 정하고** 코드를 열어라. 판정 기준은 하나다 — 표를 전부 채워야 하는가, 답에서 닿는 것만 계산하면 되는가.

**1. 백준 9184 신나는 함수 실행 (실버 2)** — https://www.acmicpc.net/problem/9184
- 신호: **지문이 재귀 함수의 정의를 그대로 준다.** 점화식을 세울 필요조차 없다. 남은 일은 "같은 인자로 몇 번이나 다시 부르는가"뿐이다.
- 상태: `(a, b, c)` 세 정수. 20을 넘으면 `w(20,20,20)`으로 접히므로 유효한 범위는 $-1 \le a,b,c \le 20$의 정수 격자다.
- 자료구조: 21×21×21 배열 또는 dict. **하향식이 자연스러운 대표 사례다** — 지문의 재귀를 그대로 옮기고 메모만 붙이면 끝난다. 상향식으로 짜려면 세 축의 계산 순서를 직접 찾아야 하는데, 그 순서를 찾는 일이 이 문제의 본질이 아니다.

**2. 백준 1937 욕심쟁이 판다 (골드 3)** — https://www.acmicpc.net/problem/1937
- 신호: "더 많은 대나무가 있는 칸으로만 이동한다" + "최대 몇 칸". **이동 조건이 값의 대소이지 좌표가 아니다.**
- 상태: `dp[r][c]` = 그 칸에서 출발했을 때 갈 수 있는 최대 칸 수. 어디서 왔는지는 미래에 영향을 주지 않는다.
- 자료구조: 2차원 배열 메모 + DFS. **상향식으로 가려면 칸을 대나무 양 내림차순으로 정렬해야 한다** — 그것이 이 의존 그래프의 위상 순서다([IV-6](#/iv-6)). 하향식은 그 정렬을 재귀 스택에 맡긴다. 두 방향을 다 짜서 답이 같은지 대조하면 §2.2가 손에 남는다. $n \le 500$이라 깊이는 최대 250,000이므로 재귀 깊이를 반드시 확인하라.

**3. 백준 12852 1로 만들기 2 (실버 1)** — https://www.acmicpc.net/problem/12852
- 신호: [VIII-1](#/viii-1)의 1463과 같은 점화식인데 **연산 과정까지 출력**하라고 한다. 값 외에 선택을 복원해야 한다.
- 상태: `dp[x]` = $x$를 1로 만드는 최소 연산 수, 그리고 `from[x]` = 그때 다음으로 간 수.
- 자료구조: 배열 두 개. $N \le 10^6$이라 **하향식은 재귀 깊이가 $10^6$이 되어 그대로는 죽는다.** 상향식으로 가거나, 하향식을 고집한다면 방향 선택의 대가가 무엇인지 §4의 [C] 표로 확인하라.

**4. 손 과제 — 방향 판정.** 다음 셋을 하향식과 상향식으로 갈라라. 근거는 "표 칸 수 대비 닿는 상태 수"와 "의존 사슬의 길이" 둘뿐이다. ① 동전 `{1,3,4}`로 금액 $10^6$을 만드는 최소 동전 수 ② 무게가 $10^9$까지 가는 물건 20개의 부분합 ③ 21×21×21 격자 위의 재귀식
:::

## 요약

- 하향식(메모이제이션)과 상향식(타뷸레이션)은 **같은 점화식의 두 방향**이다. 답이 달라지지 않는다. 달라지는 것은 어떤 칸을 계산하느냐와 계산이 가능하냐다.
- 차이의 뿌리는 하나다. **계산 순서를 재귀 호출 스택이 만드는가, 사람이 루프로 적는가.**
- 메모에 값이 적히는 순서는 그 자체로 **의존 그래프의 위상 순서**다([IV-6](#/iv-6)). 상향식의 인덱스 순서는 또 다른 위상 순서일 뿐이다.
- **상태가 희소하면 하향식이 이긴다.** 무게 12개·용량 300만에서 표는 3,900만 칸인데 닿는 상태는 3,403개(0.009%)이고, 시간이 2,068 ms 대 1.4 ms다.
- **상태가 조밀하면 상향식이 이긴다.** 재귀 깊이 제한이 없고, 호출 오버헤드가 없고, 캐시 지역성이 있고, **배열 한 줄로 접을 수 있다** — 마지막 것은 하향식으로는 불가능하다.
- 깊이 한도는 실물로 존재한다. Python 기본 1000, `lru_cache`를 씌우면 한도를 올려도 **3,332**, C++은 스택 크기가 한도이고 넘으면 예외가 아니라 **SIGSEGV**다.
- 방향을 바꾸는 것으로 **상태 정의와 초기값의 오류는 고쳐지지 않는다.** 두 방향이 같은 오답을 낸다.
