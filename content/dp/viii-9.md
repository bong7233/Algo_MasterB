# VIII-9 비트마스크 DP

::: lead
"어디를 이미 들렀는가"가 상태에 들어가야 하는 문제에서, 그 집합을 정수 하나로 접으면 표가 선다. 그리고 그 표는 지점이 20개를 넘는 순간 무너진다.
:::

## 1. 문제

자동 창고에서 주문 하나를 처리한다. 담아야 할 품목이 선반 12곳에 흩어져 있고, 로봇은 적재대에서 출발해 12곳을 전부 들른 뒤 적재대로 돌아온다. 통로가 일방통행이라 A에서 B로 가는 시간과 B에서 A로 가는 시간이 다르다. **어떤 순서로 돌아야 총 이동 시간이 최소인가.**

가까운 곳부터 집는 규칙이 먼저 떠오른다. 그리고 그 규칙은 마지막 한 곳이 반대편 끝에 남는 순간 무너진다. 매 걸음의 최선이 전체의 최선이라는 보장이 없다([VI-1](#/vi-1)).

그러면 순서를 전부 만들어 본다. 출발점이 고정이므로 나머지 $n-1$곳의 순열, 즉 $(n-1)!$가지다.

```text nolines
   n = 12    (n-1)! =        39,916,800
   n = 14    (n-1)! =     6,227,020,800
   n = 16    (n-1)! = 1,307,674,368,000
```

실제로 재 보면 이렇다. 순열 완전탐색은 C++로 $n=12$에서 0.44초, $n=13$에서 5.65초, **$n=14$에서 78.4초**다. Python은 $n=12$에서 이미 26.7초다(측정 스크립트 `tools/bench/tsp_bitmask.py`, `.cpp`).

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

$n$이 1 늘 때마다 $n-1$배다. 12를 겨우 넘긴 자리에서 벽이 선다.

## 2. 아이디어

### 2.1 순열의 공통 접두사를 하나로 묶는다

$0 \to 1 \to 2$로 시작하는 순열과 $0 \to 2 \to 1$로 시작하는 순열을 비교한다. 두 접두사는 다르다. 그런데 **그 뒤에 남은 일은 똑같다** — 아직 안 간 곳이 같고, 서 있는 위치도 2와 1로 다를 뿐 나머지 선택지는 같은 규칙을 따른다.

여기서 [VIII-1](#/viii-1)의 질문을 그대로 던진다. **지금까지 무엇을 했든, 앞으로의 최적 선택을 정하는 데 필요한 정보는 무엇인가.**

둘이다.

- **아직 안 간 곳이 어디인가.** 뒤집으면 이미 간 곳의 집합이다.
- **지금 어디에 서 있는가.** 다음 이동 비용이 여기서 정해진다.

그 외에는 아무것도 필요 없다. 어떤 순서로 왔는지, 지금까지 얼마를 썼는지는 앞으로의 선택을 바꾸지 않는다. $(n-1)!$개의 순열이 $2^n \times n$개의 상태로 접힌다.

### 2.2 방문 집합만으로는 안 된다

"이미 간 곳의 집합"만 상태로 두고 싶어진다. 목표가 "전부 방문"이니 집합이 곧 진행도처럼 보인다. 그러나 점화식을 쓰려고 하면 그 자리에서 막힌다.

$$dp[\text{mask} \cup \{j\}] = dp[\text{mask}] + cost[\;?\;][j]$$

**첫 번째 첨자를 쓸 수 없다.** 다음 이동의 비용은 "어디서 $j$로 가는가"에 달렸는데 집합에는 그 정보가 없다. 상태가 전이 비용을 결정하지 못하면 점화식이 성립하지 않는다.

우회로가 하나 떠오른다. `dp[mask]`의 최솟값을 낸 마지막 도시를 부가 정보로 함께 들고 다니는 것이다. 그것은 DP가 아니라 **각 마스크에서 가장 싼 접두사 하나만 남기는 그리디**이고, 실제로 지는 입력이 있다. 4개 도시로 손에 잡히는 반례가 나온다 — [VIII-11](#/viii-11)에서 숫자를 끝까지 계산한다.

==상태는 "지금까지의 진행도"가 아니라 "미래를 결정하는 최소한의 정보"다.== 그래서 현재 위치가 상태에 들어간다.

### 2.3 집합을 정수 하나로 — III-3을 이어받는다

[III-3](#/iii-3)에서 집합 하나를 정수 하나로 접었다. 그 표현이 여기서 값을 한다. **상태가 정수여야 배열의 첨자가 되기 때문이다.** `frozenset`을 키로 쓰는 딕셔너리로는 100만 개 상태를 감당하지 못한다 — 원소 13개짜리 `set` 하나가 728바이트다.

이 챕터가 쓰는 관용구는 넷뿐이다.

| 하는 일 | Python | C++ |
|---|---|---|
| $v$를 방문 집합에 넣기 | `mask \| (1 << v)` | `mask \| (1 << v)` |
| $v$를 이미 갔는가 | `mask >> v & 1` | `mask >> v & 1` |
| 전부 갔는가 | `mask == (1 << n) - 1` | `mask == (1 << n) - 1` |
| 몇 곳을 갔는가 | `mask.bit_count()` | `__builtin_popcount(mask)` |

마지막 줄만 갈라진다. Python의 `int.bit_count()`는 3.10부터이고 그 이전에는 `bin(mask).count("1")`이었다. C++17에는 표준 함수가 없어 컴파일러 내장 `__builtin_popcount`를 쓴다(`std::popcount`는 C++20이다).

📖 `mask.bit_count()` — 켜진 비트 수. 정수 하나에 대해 $O(1)$(내부적으로는 워드 수에 비례).
   쓰는 곳: 상태를 방문 개수 순으로 훑을 때, 전이 개수를 셀 때.
   C++ 대응: `__builtin_popcount(mask)` — `int`용이고 `long long`은 `__builtin_popcountll`이다. **표준이 아니라 컴파일러 확장**이라는 점이 다르다.

### 2.4 상태와 점화식

**① 상태 정의.** $dp[\text{mask}][i]$ = **0에서 출발해 mask에 담긴 도시를 정확히 다 방문했고, 지금 $i$에 서 있을 때의 최소 비용.** 한국어 한 문장으로 써진다.

**② 점화식.** 마지막 결정 하나를 떼어 낸다 — 다음에 어디로 갈 것인가.

$$dp[\text{mask} \,|\, (1 \ll j)][j] \;=\; \min_{i \,\in\, \text{mask}} \big( dp[\text{mask}][i] + cost[i][j] \big), \quad j \notin \text{mask}$$

**③ 초기값.** $dp[1][0] = 0$. 0번만 방문했고 0번에 서 있으며 비용은 0이다. 나머지는 전부 `INF`다 — 도달 불가와 비용 0을 섞으면 안 된다([VIII-1](#/viii-1)).

**④ 계산 순서.** **mask 오름차순.** 근거가 명확하다. 전이는 항상 꺼진 비트 하나를 켜므로 `mask | (1 << j)`는 반드시 `mask`보다 **크다.** 읽는 칸의 첨자가 자기보다 작다는 사실이 이 순서를 정당화한다.

상태를 방문 개수(popcount)로 층을 나누면 의존 관계가 한눈에 보인다.

```text nolines
   popcount 1      popcount 2          popcount 3        popcount 4
   0001            0011 0101 1001      0111 1011 1101    1111
     |               |    |    |         |    |    |       |
     +--- set one ---+----+----+-- set --+----+----+-- set +
          more bit                one more bit
```

화살표는 예외 없이 왼쪽에서 오른쪽으로만 간다. 층 안에서는 전이가 없다. **의존 그래프에 사이클이 없다**는 것이 곧 이 DP가 성립하는 근거다.

## 3. 손으로 따라가기

::: trace
도시 4개. `cost[i][j]`는 $i$에서 $j$로 가는 비용이고 **대칭이 아니다.**

```text nolines
        to 0   to 1   to 2   to 3
   0        0     10     15     20
   1        5      0      9     10
   2        6     13      0     12
   3        8      8      9      0
```

0에서 출발해 전부 들르고 0으로 돌아온다. 표는 $dp[\text{mask}][i]$이고 mask는 이진수 네 자리(오른쪽이 0번)다. 0번을 담지 않은 마스크는 쓰이지 않으므로 뺀다. `.`은 도달 불가다.

| mask | i=0 | i=1 | i=2 | i=3 |
|---|---|---|---|---|
| 0001 | 0 | . | . | . |
| 0011 | . | 10 | . | . |
| 0101 | . | . | 15 | . |
| 0111 | | | | |
| 1001 | | | | |
| 1011 | | | | |
| 1101 | | | | |
| 1111 | | | | |

세 가지를 확인하라.

- [ ] `0111`의 `i=1` 칸과 `i=2` 칸에 **서로 다른 값**이 들어간다. 그 둘은 어떤 경로인가
- [ ] 마지막 답은 $dp[1111][i] + cost[i][0]$의 최솟값이다. 어느 $i$에서 최소가 나오는가
- [ ] `1111` 행을 채울 때 읽는 칸이 전부 그 시점에 확정되어 있는가. 왜 그런가
:::

::: answer
| mask | i=0 | i=1 | i=2 | i=3 |
|---|---|---|---|---|
| 0001 | 0 | . | . | . |
| 0011 | . | 10 | . | . |
| 0101 | . | . | 15 | . |
| 0111 | . | 28 | 19 | . |
| 1001 | . | . | . | 20 |
| 1011 | . | 28 | . | 20 |
| 1101 | . | . | 29 | 27 |
| 1111 | . | 35 | 29 | 31 |

첫 번째. `0111`은 `{0, 1, 2}`를 방문한 상태다. 두 칸이 각각 다른 경로다.

- `i=2` 칸 19 — 경로 $0 \to 1 \to 2$. $10 + 9 = 19$.
- `i=1` 칸 28 — 경로 $0 \to 2 \to 1$. $15 + 13 = 28$.

**같은 집합인데 값이 둘이다.** §2.2가 말한 것이 이 두 칸이다. 여기서 값이 작은 19만 남기고 "지금 2에 있다"로 뭉개면 $0 \to 2 \to 1$로 시작하는 모든 경로가 사라진다.

두 번째. $dp[1111][1] + cost[1][0] = 35 + 5 = 40$, $dp[1111][2] + cost[2][0] = 29 + 6 = \mathbf{35}$, $dp[1111][3] + cost[3][0] = 31 + 8 = 39$. **답은 35**이고 마지막 도시는 2다. 거꾸로 따라가면 $0 \to 1 \to 3 \to 2 \to 0$이다.

세 번째. `1111`이 읽는 것은 `0111`, `1011`, `1101`이고 셋 다 값이 더 작다. 전이가 비트를 켜기만 하므로 mask는 단조 증가하고, 따라서 오름차순 한 번의 훑기로 "읽는 칸은 이미 채워져 있다"가 보장된다. ==계산 순서를 고민할 필요가 없는 것이 비트마스크 표현이 주는 두 번째 이득이다.==
:::

## 4. 구현

```python title="외판원 순회 — 완전탐색과 비트마스크 DP, 그리고 경로 복원"
from itertools import permutations

INF = float("inf")
COST = [
    [0, 10, 15, 20],
    [5, 0, 9, 10],
    [6, 13, 0, 12],
    [8, 8, 9, 0],
]


def brute(cost):
    """(n-1) 개의 순열을 전부 만들어 본다."""
    n = len(cost)
    best, order = INF, ()
    for p in permutations(range(1, n)):
        prev, s = 0, 0
        for x in p:
            s += cost[prev][x]
            prev = x
        s += cost[prev][0]
        if s < best:
            best, order = s, (0,) + p
    return best, order


def restore(par, mask, last):
    """par 를 거꾸로 따라가 실제 순회 순서를 복원한다."""
    out = []
    while last != -1:
        out.append(last)
        prev = par[mask][last]
        mask ^= 1 << last
        last = prev
    out.reverse()
    return tuple(out)


def tsp(cost):
    """dp[mask][i] = 0 에서 출발해 mask 를 방문하고 지금 i 에 서 있는 최소 비용."""
    n = len(cost)
    full = (1 << n) - 1
    dp = [[INF] * n for _ in range(1 << n)]
    par = [[-1] * n for _ in range(1 << n)]
    dp[1][0] = 0                                # 초기값: 0 만 방문했고 0 에 서 있다
    for mask in range(1 << n):                  # 계산 순서: mask 오름차순
        for i in range(n):
            if dp[mask][i] == INF:
                continue
            for j in range(n):
                if mask >> j & 1:               # 이미 방문한 도시는 건너뛴다
                    continue
                nm = mask | (1 << j)            # j 를 방문 집합에 넣는다
                v = dp[mask][i] + cost[i][j]
                if v < dp[nm][j]:
                    dp[nm][j] = v
                    par[nm][j] = i
    best, last = INF, -1
    for i in range(1, n):
        v = dp[full][i] + cost[i][0]            # 마지막에 0 으로 돌아온다
        if v < best:
            best, last = v, i
    return best, restore(par, full, last), dp


n = len(COST)
b, border = brute(COST)
d, dorder, dp = tsp(COST)
print("[1] 완전탐색   비용 %d  순서 %s" % (b, list(border)))
print("[2] 비트마스크 비용 %d  순서 %s" % (d, list(dorder)))
print("[3] dp[mask][i] — 도달 불가는 . 로 적는다")
print("    mask   i=0  i=1  i=2  i=3")
for mask in range(1 << n):
    if mask & 1 == 0:
        continue                                # 0 을 안 담은 마스크는 쓰이지 않는다
    row = "".join("%5s" % ("." if dp[mask][i] == INF else dp[mask][i]) for i in range(n))
    print("    %s %s" % (format(mask, "04b"), row))
print("[4] 상태 수와 순열 수")
for k in (4, 8, 12, 16, 20):
    perms = 1
    for t in range(1, k):
        perms *= t
    print("    n=%2d  상태 2^n*n = %10d   순열 (n-1)! = %20d" % (k, (1 << k) * k, perms))
```
```cpp title="외판원 순회 — 완전탐색과 비트마스크 DP, 그리고 경로 복원"
#include <algorithm>
#include <bitset>
#include <cstdio>
#include <numeric>
#include <string>
#include <vector>
using namespace std;

const int INF = 1000000000;
vector<vector<int>> COST = {
    {0, 10, 15, 20},
    {5, 0, 9, 10},
    {6, 13, 0, 12},
    {8, 8, 9, 0},
};

// (n-1) 개의 순열을 전부 만들어 본다.
pair<int, vector<int>> brute(const vector<vector<int>>& cost) {
    int n = (int)cost.size();
    vector<int> p(n - 1);
    iota(p.begin(), p.end(), 1);
    int best = INF;
    vector<int> order;
    do {
        int prev = 0, s = 0;
        for (int x : p) { s += cost[prev][x]; prev = x; }
        s += cost[prev][0];
        if (s < best) {
            best = s;
            order = {0};
            order.insert(order.end(), p.begin(), p.end());
        }
    } while (next_permutation(p.begin(), p.end()));
    return {best, order};
}

// par 를 거꾸로 따라가 실제 순회 순서를 복원한다.
vector<int> restore(const vector<vector<int>>& par, int mask, int last) {
    vector<int> out;
    while (last != -1) {
        out.push_back(last);
        int prev = par[mask][last];
        mask ^= 1 << last;
        last = prev;
    }
    reverse(out.begin(), out.end());
    return out;
}

// dp[mask][i] = 0 에서 출발해 mask 를 방문하고 지금 i 에 서 있는 최소 비용.
pair<int, vector<int>> tsp(const vector<vector<int>>& cost, vector<vector<int>>& dp) {
    int n = (int)cost.size(), full = (1 << n) - 1;
    dp.assign(1 << n, vector<int>(n, INF));
    vector<vector<int>> par(1 << n, vector<int>(n, -1));
    dp[1][0] = 0;                                 // 초기값: 0 만 방문했고 0 에 서 있다
    for (int mask = 0; mask < (1 << n); mask++) { // 계산 순서: mask 오름차순
        for (int i = 0; i < n; i++) {
            if (dp[mask][i] == INF) continue;
            for (int j = 0; j < n; j++) {
                if (mask >> j & 1) continue;      // 이미 방문한 도시는 건너뛴다
                int nm = mask | (1 << j);         // j 를 방문 집합에 넣는다
                int v = dp[mask][i] + cost[i][j];
                if (v < dp[nm][j]) {
                    dp[nm][j] = v;
                    par[nm][j] = i;
                }
            }
        }
    }
    int best = INF, last = -1;
    for (int i = 1; i < n; i++) {
        int v = dp[full][i] + cost[i][0];         // 마지막에 0 으로 돌아온다
        if (v < best) { best = v; last = i; }
    }
    return {best, restore(par, full, last)};
}

string fmt(const vector<int>& v) {
    string s = "[";
    for (size_t i = 0; i < v.size(); i++) { if (i) s += ", "; s += to_string(v[i]); }
    return s + "]";
}

int main() {
    int n = (int)COST.size();
    vector<vector<int>> dp;
    auto [b, border] = brute(COST);
    auto [d, dorder] = tsp(COST, dp);
    printf("[1] 완전탐색   비용 %d  순서 %s\n", b, fmt(border).c_str());
    printf("[2] 비트마스크 비용 %d  순서 %s\n", d, fmt(dorder).c_str());
    printf("[3] dp[mask][i] — 도달 불가는 . 로 적는다\n");
    printf("    mask   i=0  i=1  i=2  i=3\n");
    for (int mask = 0; mask < (1 << n); mask++) {
        if ((mask & 1) == 0) continue;            // 0 을 안 담은 마스크는 쓰이지 않는다
        string row;
        for (int i = 0; i < n; i++) {
            char buf[16];
            if (dp[mask][i] == INF) snprintf(buf, sizeof buf, "%5s", ".");
            else snprintf(buf, sizeof buf, "%5d", dp[mask][i]);
            row += buf;
        }
        printf("    %s %s\n", bitset<4>(mask).to_string().c_str(), row.c_str());
    }
    printf("[4] 상태 수와 순열 수\n");
    for (int k : {4, 8, 12, 16, 20}) {
        long long perms = 1;
        for (int t = 1; t < k; t++) perms *= t;
        printf("    n=%2d  상태 2^n*n = %10d   순열 (n-1)! = %20lld\n",
               k, (1 << k) * k, perms);
    }
    return 0;
}
```
:::

두 언어의 출력은 같다.

[2] 비트마스크 비용 35  순서 [0, 1, 3, 2]
[3] dp[mask][i] — 도달 불가는 . 로 적는다
    mask   i=0  i=1  i=2  i=3
    0001     0    .    .    .
    0011     .   10    .    .
    0101     .    .   15    .

    n= 4  상태 2^n*n =         64   순열 (n-1)! =                    6

    n=20  상태 2^n*n =   20971520   순열 (n-1)! =   121645100408832000

**복잡도:** 시간 $O(2^n \cdot n^2)$ — 항을 하나씩 쪼갠다. 마스크가 $2^n$개, 마스크마다 "지금 서 있는 도시" $i$가 $n$가지, 각각에서 "다음에 갈 도시" $j$가 $n$가지다. 세 루프가 곱해져 $2^n \cdot n \cdot n$이다. 공간 $O(2^n \cdot n)$ — `dp`와 `par` 각각 상태 하나당 값 하나다.

$(n-1)!$과 $2^n n^2$의 차이가 실제로 어떻게 벌어지는지가 §1과 위 `[4]` 표에 있다. $n=20$에서 순열은 $1.2 \times 10^{17}$개, 상태는 $2.1 \times 10^7$개다. **10자릿수 차이다.**

::: perf
$n$을 늘려 가며 DP 자체가 언제 무너지는지 잰다. 측정 스크립트는 `tools/bench/tsp_bitmask.cpp` 다.

| n | 상태 수 | 표 크기(`int` 기준) | 최대 RSS | 시간 |
|---|---|---|---|---|
| 16 | 1,048,576 | 4.0 MB | 10.1 MB | 0.030초 |
| 18 | 4,718,592 | 18.0 MB | 29.6 MB | 0.142초 |
| **20** | **20,971,520** | **80.0 MB** | **123.6 MB** | **0.706초** |
| 22 | 92,274,688 | 352.0 MB | 483.6 MB | 4.666초 |
| 24 | 402,653,184 | 1,536.0 MB | 2,179.4 MB | 94.060초 |

> (Linux x86-64 / g++ 13 `-O2` 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

**$n = 20$이 실질 한계인 이유가 시간이 아니라 메모리다.** 메모리 제한이 256 MB인 환경에서 $n=20$은 124 MB로 들어가고 $n=22$는 484 MB로 그 자리에서 죽는다. 시간 쪽은 $n=22$도 4.7초라 아직 여지가 있어 보이지만 메모리가 먼저 끝난다.

$n=24$의 94초는 $n=22$의 4.7초에서 예상되는 20초보다 훨씬 크다. 표가 2 GB를 넘으면서 캐시가 전혀 듣지 않고, `vector<vector<int>>`가 행마다 따로 할당되어 접근이 흩어지기 때문이다. ==$O(2^n n^2)$의 상수는 $n$이 커질수록 나빠진다.== 복잡도 식만 보고 외삽하면 틀린다.

Python 쪽은 표 자체가 더 무겁다. 같은 스크립트의 `tracemalloc` 측정으로 $n=16$에 12.0 MB, $n=18$에 52.2 MB다. C++의 4.0 MB / 18.0 MB의 3배 언저리이고, 파이썬 정수 객체가 상태마다 하나씩 붙기 때문이다.
:::

| 언어 차이 | Python | C++ |
|---|---|---|
| popcount | `mask.bit_count()` (3.10+). 그 이전은 `bin(mask).count("1")` | `__builtin_popcount` — 표준이 아니라 컴파일러 내장. `std::popcount`는 C++20 |
| 시프트 폭 | 임의 정밀도라 `1 << 40`도 그냥 된다 | `1 << 31`은 부호 있는 오버플로로 **정의되지 않은 동작**이다. $n > 31$이면 `1LL << i`([III-3](#/iii-3)) |
| `INF` | `float("inf")`. 정수와 섞어 비교해도 되지만 비교가 느려진다 | `1e9`를 `int`로. `INT_MAX`를 쓰면 `dp + cost`에서 즉시 오버플로다 |
| 팩토리얼 | `(n-1)!`이 몇 자리든 정확하다 | 19!까지만 `long long`에 들어간다. 21!은 조용히 다른 수가 된다 |
| 표 메모리 | 상태마다 정수 객체가 붙어 C++의 3배 언저리 | `vector<vector<int>>`는 행마다 따로 할당된다. 1차원 `vector<int>(1<<n, n)`로 펴면 캐시가 산다 |

::: pitfall
- **초기값을 $dp[0][0] = 0$으로 둔다.** 마스크 0은 "아무 데도 안 갔다"이고 그 상태에서는 0번에 서 있을 수도 없다. 출발점을 이미 방문한 것으로 보아 $dp[1][0] = 0$이다.
- **`INF` 칸에서 전이를 시작한다.** `dp[mask][i]`가 `INF`인데 `+ cost`를 하면 C++에서는 오버플로이고, Python에서는 `inf`가 퍼져 나가 표가 전부 `inf`로 오염된다. **`continue` 한 줄이 이 둘을 동시에 막는다.**
- **마지막에 출발점으로 돌아오는 비용을 잊는다.** $dp[\text{full}][i]$는 아직 $i$에 서 있는 상태다. 순회를 닫으려면 $cost[i][0]$을 더해야 하고, 이 한 항이 빠지면 답이 조용히 작아진다.
- **돌아갈 길이 없는 도시를 0으로 둔다.** 일방통행 때문에 $cost[i][j]$가 존재하지 않을 수 있다. 그 자리를 0으로 두면 공짜 이동이 생긴다. `INF`로 둔다.
- **`n`이 커지면 재귀 메모이제이션으로 도망친다.** 상태 수가 같으므로 시간은 그대로이고 파이썬에서는 호출 오버헤드와 재귀 한도가 추가된다. 이 점화식은 계산 순서가 공짜로 주어지므로 반복문 판이 낫다([VIII-2](#/viii-2)).
- **$2^n$이 커서 못 도는 문제에 이 도구를 든다.** $n=25$면 상태가 8억 개다. 비트마스크 DP는 $n \le 20$의 도구이고, 그 밖은 다른 방법의 영역이다.
:::

## 5. 어디에 쓰이는가

**창고의 주문 피킹 경로가 이 문제 그대로다.** 주문 하나에 담을 품목이 통로 여러 곳에 흩어져 있고, 작업자나 로봇이 적재대에서 출발해 전부 들르고 돌아온다. 주문당 품목 수는 대개 10~20개라 $2^n n^2$가 정확히 들어맞는 구간이고, 근사해가 아니라 **최적해를 실시간에 뽑을 수 있는 드문 규모**다. 통로가 일방통행이면 비용 행렬이 비대칭이 되는데, 이 챕터의 점화식은 대칭성을 전혀 쓰지 않으므로 그대로 성립한다.

**기판 드릴링과 부품 실장기의 헤드 경로도 같은 문제다.** 구멍 위치가 정해져 있고 헤드가 전부 찍고 원위치로 돌아온다. 여기서는 구멍이 수천 개라 $n \le 20$을 넘으므로 전체를 한 번에 풀지 않는다. 대신 **구역으로 쪼개 구역 안을 이 DP로 최적화**하고 구역 사이는 다른 방법으로 잇는다. 지수 알고리즘을 쓰는 표준적인 방식이 이 "쪼개서 작게 만들기"다.

**작업 할당도 같은 표로 푼다.** 사람 $n$명에게 일 $n$개를 하나씩 배정하되 비용 합을 최소로 만드는 문제에서, 상태는 "이미 배정된 일의 집합"이고 그 집합의 크기가 곧 지금 배정할 사람의 번호다. 여기서는 **현재 위치를 따로 둘 필요가 없다** — popcount가 그 역할을 하기 때문이다. 상태가 $2^n$개로 줄고 시간은 $O(2^n \cdot n)$이다. $n$이 20을 넘으면 헝가리안 알고리즘의 $O(n^3)$으로 갈아탄다([V-11](#/v-11)). ==같은 문제에 대해 지수와 다항식이 공존하고, 어느 쪽이 빠른지가 $n$에서 갈린다.==

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "모든 지점을 한 번씩 방문", "이미 방문한 곳은 다시 가지 않는다", "N명에게 N개의 일을 하나씩", "각 원소를 어떤 그룹에 넣을지" — 그리고 **N이 유난히 작게 못 박혀 있다**
- 제약조건: $N \le 20$. 상태 $2^n \cdot n$이 2천만이고 표가 80 MB다([0-9](#/0-9)). $N \le 16$이면 여유 있고, $N \ge 22$면 메모리가 먼저 죽는다. 전이가 부분집합 순회까지 가면 $3^n$이라 $N \le 16$이 한계다([III-3](#/iii-3))
- 혼동 주의: 집합을 만들기만 하고 다시 쓰지 않으면 [III-3](#/iii-3)의 단순 마스크 순회나 [III-4](#/iii-4)의 백트래킹으로 충분하다. 지점 사이 이동 비용이 그래프 최단거리로 주어지면 **먼저 [V-3 플로이드-워셜](#/v-3)로 전 쌍 거리를 만든 뒤** 그 행렬로 이 DP를 돌린다. $N$이 수백이면 비트마스크가 아니라 근사·휴리스틱의 영역이다
- 반례 함정: 현재 위치를 상태에서 빼고 "가장 싼 마스크"만 남기는 코드. 예제에서는 맞고 비대칭 비용에서 어긋난다([VIII-11](#/viii-11)). 그리고 마지막에 출발점으로 돌아오는 비용을 빼먹는 코드 — 답이 언제나 조금 작게 나온다
:::

::: interview
**"외판원 순회의 시간 복잡도가 $O(2^n n^2)$인 이유를 설명해 보세요."**
항을 쪼개서 답한다. "상태가 (방문 집합, 현재 위치)이므로 $2^n \times n$개이고, 상태 하나에서 다음에 갈 도시가 $n$가지라 전이가 $n$번입니다. 곱하면 $2^n n^2$입니다." 이어지는 질문은 대개 "그럼 $n$은 어디까지 됩니까"이고, **여기서 시간이 아니라 메모리로 답해야 한다.** "$n=20$이면 표가 2천만 칸, `int`로 80 MB입니다. 22면 350 MB라 메모리 제한에 먼저 걸립니다."

**"방문 집합만 상태로 두면 왜 안 됩니까."**
"다음 이동 비용 `cost[i][j]`의 `i`를 쓸 수 없습니다. 같은 집합에 도달한 경로들이 서로 다른 도시에 서 있고, 그중 지금까지 싼 쪽이 앞으로도 싸다는 보장이 없습니다. 4개 도시로 반례가 만들어집니다." **상태 정의의 기준이 '진행도'가 아니라 '미래를 결정하는 정보'라는 문장**까지 붙이면 답이 완성된다.
:::

## 연습

::: quiz
네 문제 모두 $N$이 작게 못 박혀 있다. **제약을 먼저 읽고 $2^N$을 계산하라.**

**1. 백준 2098 외판원 순회 (골드 1)** — https://www.acmicpc.net/problem/2098
- 신호: "모든 도시를 거쳐 다시 출발 도시로 돌아오는 순회 경로", $N \le 16$. 이 챕터의 원형이다.
- 상태: $dp[\text{mask}][i]$ = mask를 방문하고 $i$에 서 있는 최소 비용. **갈 수 없는 길이 0으로 주어진다**는 조건을 어떻게 처리할지 먼저 정하라.
- 자료구조: `int` 배열 $2^{16} \times 16$. 출발점을 0으로 고정해도 되는 근거(순회는 회전 대칭이다)를 말할 수 있어야 한다.

**2. 백준 1311 할 일 정하기 1 (골드 1)** — https://www.acmicpc.net/problem/1311
- 신호: "각 사람은 일을 하나 담당", "각 일을 담당하는 사람은 한 명", $N \le 20$. 할당 문제다.
- 상태: $dp[\text{mask}]$ = mask에 담긴 일이 배정된 상태의 최소 비용. **현재 위치가 필요 없다** — §5의 이유를 스스로 재구성하라.
- 자료구조: 크기 $2^{20}$ 배열 하나. 지금 배정할 사람 번호는 popcount로 얻는다.

**3. 백준 1102 발전소 (골드 1)** — https://www.acmicpc.net/problem/1102
- 신호: "고장난 발전소를 재시작", "적어도 P개는 돌아가야 한다", $N \le 16$. 켜짐/꺼짐이 곧 마스크다.
- 상태: $dp[\text{mask}]$ = 켜진 발전소 집합이 mask일 때 여기까지 든 최소 비용. 전이는 "켜진 것 하나로 꺼진 것 하나를 켠다"라 $n^2$이다.
- 자료구조: 배열 하나. **초기 상태가 전부 꺼져 있으면 답이 -1**이라는 예외를 표에서 어떻게 드러낼지 생각하라.

**4. 백준 1562 계단 수 (골드 1)** — https://www.acmicpc.net/problem/1562
- 신호: "0부터 9까지의 수가 모두 등장해야 한다", $N \le 100$. 방문 집합이 도시가 아니라 **숫자 10개**다.
- 상태: $dp[\text{길이}][\text{마지막 숫자}][\text{등장한 숫자 집합}]$. 축이 셋이고 그중 하나가 마스크다.
- 자료구조: $100 \times 10 \times 1024$ 배열. 마스크가 상태의 **일부**일 뿐인 형태이고, 이 형태가 실전에서 더 흔하다.
:::

## 요약

- 방문 집합이 상태에 들어가야 하는 문제에서 집합을 정수로 접으면([III-3](#/iii-3)) 그 집합이 **배열 첨자**가 된다. 이것이 비트마스크 DP의 전부다.
- 외판원 순회의 상태는 $(\text{방문 집합}, \text{현재 위치})$ **둘 다**다. 집합만으로는 다음 전이 비용 $cost[?][j]$의 첨자를 쓸 수 없다.
- 계산 순서는 mask 오름차순이다. 전이가 비트를 켜기만 하므로 읽는 칸의 첨자가 언제나 자기보다 작다.
- 복잡도 $O(2^n n^2)$의 항은 마스크 $2^n$ × 현재 위치 $n$ × 다음 도시 $n$이다. $(n-1)!$과는 $n=20$에서 10자릿수 차이다.
- **한계는 시간이 아니라 메모리다.** 실측으로 $n=20$이 124 MB / 0.71초, $n=22$가 484 MB / 4.67초다. 메모리 제한 256 MB에서 $n=20$이 벽이다.
- 할당 문제처럼 "지금 처리할 대상"이 popcount로 정해지면 현재 위치 축이 필요 없고 상태가 $2^n$개로 줄어든다.
- 실무에서는 지점이 20개를 넘으면 구역으로 쪼개 구역 안만 최적으로 풀거나, 다항식 알고리즘([V-11](#/v-11))으로 갈아탄다.
