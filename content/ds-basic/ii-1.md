# II-1 배열과 동적 배열

::: lead
배열의 모든 성질은 "메모리가 연속이다" 하나에서 따라 나온다. $O(1)$ 인덱싱도, $O(n)$ 중간 삽입도, 같은 복잡도끼리 열 배가 갈리는 것도 전부 그 한 문장의 결과다.
:::

## 1. 문제

장비 하나가 10밀리초마다 값을 하나 올려 보낸다. 하루면 864만 개다. 이 값들을 담아 두고 "37만 번째 값"을 물으면 즉시 답해야 한다. 담긴 순서가 곧 번호다.

담을 곳을 먼저 정해야 한다. 그런데 몇 개가 들어올지 모른다. 선택지는 셋이고 셋 다 문제가 있다.

**크게 잡는다.** 1억 개짜리 자리를 미리 확보한다. `int`면 400MB다. 실제로 들어온 것이 864만 개면 92%가 놀고, 메모리 제한 256MB인 채점 환경에서는 시작도 못 한다.

**작게 잡고 넘치면 죽는다.** 가장 흔한 실제 장애다. 배열 끝을 넘어 쓰는 순간 C++은 아무 말 없이 옆 변수를 덮어쓴다. 증상은 한참 뒤 엉뚱한 곳에서 나온다.

**하나 들어올 때마다 딱 하나만 더 잡는다.** 안전해 보인다. 그런데 자리를 늘린다는 것은 **새 자리를 잡고 있던 것을 전부 옮긴다**는 뜻이다. 864만 번째 값을 넣으려고 864만 개를 옮긴다. 총 복사량은 $1 + 2 + \dots + n \approx n^2/2$, 864만이면 37조 회다.

세 번째가 이 챕터의 출발점이다. **"조금씩 늘린다"가 왜 재앙인가, 그리고 얼마나 늘려야 공짜에 가까워지는가.** 답은 배수로 늘리는 것이고, 그 근거는 감이 아니라 계산으로 나온다.

::: note
Python `list`와 C++ `vector`의 문법·API·실제 증가율은 [0-3 Python 내장 자료구조의 실제 비용](#/0-3)과 [0-6 C++ 컨테이너 세트](#/0-6)에서 이미 다뤘다. 이 절은 그 위층이다. **왜 그런 정책이어야 하는가**와 **언제 배열이 옳은 선택인가**를 다룬다.
:::

## 2. 아이디어

### 2.1 곱셈 하나, 덧셈 하나

배열이 하는 일은 하나다. 인덱스를 주소로 바꾼다.

$$\text{addr}(i) = \text{base} + i \times \text{elemsize}$$

```text nolines
  base           +4             +8             +12
  ┌────────┬────────┬────────┬────────┐
  │   10   │   20   │   30   │   40   │        <- int 4바이트씩 빈틈 없이
  └────────┴────────┴────────┴────────┘
      0        1        2        3             <- index
```

`a[0]`을 읽든 `a[999999]`를 읽든 계산은 곱셈 하나와 덧셈 하나다. ==$O(1)$ 인덱싱은 자료구조의 재주가 아니라 산술식 하나다.== 이 식이 성립하려면 조건이 둘이다. **모든 원소의 크기가 같아야 하고, 사이에 빈틈이 없어야 한다.**

두 조건이 그대로 대가로 돌아온다.

**중간에 넣으려면 뒤를 전부 민다.** 빈틈이 없다는 것은 자리를 비우려면 누군가 옮겨야 한다는 뜻이다. 앞쪽에 넣으면 $n$개가 움직인다.

**크기를 바꿀 수 없다.** 뒤 주소가 남의 것일 수 있다. 늘리려면 새 땅을 잡고 이사해야 한다.

**크기가 다른 것은 못 담는다.** 문자열처럼 길이가 제각각인 값은 주소식이 성립하지 않는다. 그래서 실제로 담는 것은 **값이 아니라 값의 주소**다. Python `list`가 정확히 그 구조이고, 그 대가는 원소를 볼 때마다 포인터를 한 번 더 따라가는 것이다.

### 2.2 같은 $O(n)$이 같지 않다

배열이 리스트·트리·해시를 이기는 진짜 이유는 복잡도가 아니라 **하드웨어가 연속 메모리를 좋아한다**는 사실이다. CPU는 메모리를 64바이트 캐시 라인 단위로 읽고, 순차 접근을 감지하면 다음 라인을 미리 가져온다. 배열 순회는 이 두 장치에 정확히 걸린다.

이 차이는 자료구조를 바꾸지 않아도 드러난다. **같은 배열을 같은 횟수만큼 훑으면서 순서만 바꿔도** 시간이 갈린다.

::: perf
4000×4000 `int` 행렬(1,600만 개)을 전부 더한다. 행 우선(`a[r][c]`를 `c`부터 증가)과 열 우선(`r`부터 증가)의 차이는 **더하는 순서뿐**이고 명령어 수는 같다.

| | C++17 `-O2` | Python 3.13 (2000×2000) |
|---|---|---|
| 행 우선 | 0.0113초 | 0.425초 |
| 열 우선 | 0.183초 | 0.693초 |
| 배수 | **16배** | 1.6배 |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/ii1_row_major.cpp` 와 `.py` 다.)

Python 쪽 배수가 훨씬 작은 것이 언어 차이의 크기다. Python `list`는 값이 아니라 포인터를 담으므로 행 우선 순회조차 이미 객체로 한 번 더 건너뛴다. **캐시가 도와줄 여지 자체가 C++보다 작다.** 배열의 이점은 언어가 값을 연속으로 담을 때 최대가 된다.
:::

16배는 알고리즘을 바꿔서 얻은 것이 아니다. 루프 두 줄의 순서를 바꿔서 얻은 것이다. 캐시 라인과 프리페처의 동작은 [0-6 C++ 컨테이너 세트](#/0-6) §2에 있다.

### 2.3 얼마나 늘릴 것인가

이제 §1의 문제로 돌아간다. 꽉 차면 새 배열을 잡고 옮긴다. 정할 것은 **새 용량을 얼마로 하는가** 하나다.

**상수만큼 늘리는 정책**부터 보자. 매번 `step`개씩 늘린다. 재할당은 $n/\text{step}$번 일어나고, $k$번째 재할당에서 옮기는 원소가 $k \cdot \text{step}$개다. 총 복사량은

$$\text{step}(1 + 2 + \dots + n/\text{step}) \approx \frac{n^2}{2\,\text{step}}$$

`step`을 아무리 키워도 $n^2$이 남는다. **상수는 $n^2$을 이기지 못한다.**

**배수로 늘리는 정책**은 다르다. 2배씩 늘리면 재할당 시점의 용량이 $1, 2, 4, \dots, n$이고 그때마다 옮기는 개수가 곧 그 용량이다. 총 복사량은

$$1 + 2 + 4 + \dots + n < 2n$$

등비급수라 **총합이 $n$에 비례한다.** 원소 하나당 평균 복사가 상수다.

::: widget complexity-plot {"show":["n","n2"]}
:::

위젯은 $N$이 커질 때 $O(n)$과 $O(n^2)$이 로그 축에서 벌어지는 폭과 "1초 안에 되는 선"이 어디를 지나는지를 보인다. 슬라이더를 오른쪽으로 밀면 두 곡선의 간격이 계속 벌어지고, $O(n^2)$이 먼저 선을 넘는다. **두 증폭 정책의 총 복사량이 정확히 이 두 곡선이다.** 실측으로도 그대로 나온다.

::: perf
원소 20만 개를 넣는 동안 실제로 옮긴 원소 수를 센 것이다.

| 정책 | 재할당 횟수 | 총 복사 | 원소당 복사 | 시간 |
|---|---|---|---|---|
| 2배 | 19회 | 262,143개 | 1.31개 | 0.0012초 |
| +128 | 1,563회 | 156,249,984개 | 781.2개 | 0.0389초 |

> (같은 환경. 측정 스크립트는 `tools/bench/ii1_growth_policy.cpp`. 복사 횟수는 난수가 없어 실행마다 동일하다.)

`step`을 128로 넉넉히 줬는데도 원소당 781개다. **20만 개를 넣는 데 1억 5천만 번 옮겼다.** 2배 정책은 26만 번이다. 시간 배수 31배보다 복사 배수 596배가 더 정직한 숫자다 — 복사는 연속 메모리 이동이라 하드웨어가 도와주는 쪽이고, 그래서 시간 차이가 오히려 작게 나온다.
:::

### 2.4 "평균"이라고 말하면 안 되는 이유

`push`가 분할상환 $O(1)$이라는 말은 종종 "평균 $O(1)$"으로 번역된다. 틀린 번역이다. 평균은 입력 분포를 가정하지만, **분할상환은 어떤 연산열이 와도 총합을 보장한다.** 최악의 순서로 밀어 넣어도 $n$번의 `push`가 $O(n)$이다.

그 보장을 세는 방법이 **회계 논증**이다. 연산마다 실제 비용보다 많은 값을 청구하고, 남는 것을 저금해 두었다가 비싼 연산이 올 때 꺼내 쓴다. 저금이 한 번도 마이너스가 되지 않으면 청구액의 총합이 실제 비용의 총합보다 크다.

2배 정책에 대입한다. `push` 한 번에 **코인 3개**를 청구한다.

- 1개는 지금 원소를 쓰는 데 즉시 쓴다.
- 2개는 저금한다.

용량이 $c$에서 $2c$로 늘어나는 순간 $c$개를 옮긴다. 그 직전에 용량이 $c/2$에서 $c$로 늘어난 뒤 들어온 `push`가 정확히 $c/2$번이다. 각각이 2개씩 저금했으니 잔고는 $c$개다. **필요한 $c$와 정확히 같다.** 저금은 재할당마다 0으로 리셋되지만 절대 음수가 되지 않는다.

결론은 총비용 $\le 3n$이고, 이것이 분할상환 $O(1)$의 실제 내용이다. 상수 3이 어디서 왔는지도 이제 말할 수 있다 — **쓰기 1 + 자기 자신을 옮길 몫 1 + 앞선 절반 중 하나를 옮길 몫 1**이다.

이 논증이 정직한지는 표를 채워 보면 안다.

**잔고가 음수인 줄이 없다.** 최소값은 3이고, 그 3은 항상 재할당 직후에 나온다. 저금이 방금 전부 쓰였다는 뜻이다. 재할당은 `push` 1, 2, 3, 5, 9, 17…에서 일어난다 — 첫 번째를 빼면 $2^k + 1$이다.

이제 **+2 정책**이다. 용량이 0 → 2 → 4 → 6 → 8 → 10으로 간다.

**9번째 `push`에서 파산한다.** 그리고 뒤로 갈수록 적자가 커진다 — 복사량은 계속 늘어나는데 청구액은 `push`당 3으로 고정이기 때문이다. 어떤 상수를 청구해도 언젠가 파산한다는 것이 곧 **상수 정책이 분할상환 $O(1)$이 아니라는 증명**이다.

==갈림길은 "얼마나 늘리는가"가 아니라 "늘리는 양이 현재 크기에 비례하는가"다.== 1.5배든 2배든 1.125배든 비례하면 등비급수라 총합이 $O(n)$이다. Python이 약 1.125배, C++ libstdc++이 2배를 쓰는 것은 그 안에서의 취사선택일 뿐이다 — 배수가 작으면 메모리 낭비가 적고 재할당이 잦다.

## 4. 구현

동적 배열을 직접 짠다. 표준 컨테이너를 쓰면 정책을 바꿀 수 없어 §3의 표가 재현되지 않는다.

::: dual
```python title="동적 배열 — 증폭 정책을 바꿔 가며 복사량을 센다"
class Dyn:
    def __init__(self, doubling, step=2):
        self.data = [None] * 0     # 고정 크기 버퍼로만 쓴다 — 늘리는 일은 직접 한다
        self.size = 0
        self.cap = 0
        self.copies = 0
        self.doubling = doubling
        self.step = step

    def push(self, v):
        if self.size == self.cap:
            ncap = (self.cap * 2 if self.cap else 1) if self.doubling else self.cap + self.step
            new = [None] * ncap
            for i in range(self.size):     # 재할당의 정체는 이 복사 루프다
                new[i] = self.data[i]
            self.copies += self.size
            self.data = new
            self.cap = ncap
        self.data[self.size] = v
        self.size += 1

    def get(self, i):
        if not 0 <= i < self.size:         # 배열 자신은 범위를 검사해 주지 않는다
            raise IndexError(i)
        return self.data[i]                # 주소 산술 한 번. 크기와 무관하게 같은 비용


n = 1000
for doubling, name in ((True, "2배 "), (False, "+2  ")):
    d = Dyn(doubling)
    for i in range(n):
        d.push(i)
    print(f"{name} size={d.size} cap={d.cap} copies={d.copies}")

d = Dyn(True)
for i in range(10):
    d.push(i * i)
print("get(0)=", d.get(0), " get(9)=", d.get(9))
```
```cpp title="동적 배열 — 증폭 정책을 바꿔 가며 복사량을 센다"
#include <iostream>
#include <stdexcept>
using namespace std;

struct Dyn {
    int* data = nullptr;       // 고정 크기 버퍼로만 쓴다 — 늘리는 일은 직접 한다
    long long size = 0, cap = 0, copies = 0;
    bool doubling;
    long long step;

    Dyn(bool doubling, long long step = 2) : doubling(doubling), step(step) {}
    ~Dyn() { delete[] data; }

    void push(int v) {
        if (size == cap) {
            long long ncap = doubling ? (cap ? cap * 2 : 1) : cap + step;
            int* nw = new int[ncap];
            for (long long i = 0; i < size; i++)   // 재할당의 정체는 이 복사 루프다
                nw[i] = data[i];
            copies += size;
            delete[] data;
            data = nw;
            cap = ncap;
        }
        data[size] = v;
        size += 1;
    }

    int get(long long i) const {
        if (!(0 <= i && i < size))     // 배열 자신은 범위를 검사해 주지 않는다
            throw out_of_range("i");
        return data[i];                // 주소 산술 한 번. 크기와 무관하게 같은 비용
    }
};

int main() {
    int n = 1000;
    for (int k = 0; k < 2; k++) {
        bool doubling = (k == 0);
        const char* name = doubling ? "2배 " : "+2  ";
        Dyn d(doubling);
        for (int i = 0; i < n; i++) d.push(i);
        cout << name << " size=" << d.size << " cap=" << d.cap
             << " copies=" << d.copies << "\n";
    }

    Dyn d(true);
    for (int i = 0; i < 10; i++) d.push(i * i);
    cout << "get(0)= " << d.get(0) << "  get(9)= " << d.get(9) << "\n";
    return 0;
}
```
:::

두 언어의 출력은 같다.

```console
2배  size=1000 cap=1024 copies=1023
+2   size=1000 cap=1000 copies=249500
get(0)= 0  get(9)= 81
```

**복잡도:** `get`은 시간 $O(1)$ — 주소식 계산 한 번이고 원소 수와 무관하다. `push`는 **분할상환 $O(1)$** — §2.4의 회계 논증대로 `push` 하나가 쓰기 1 + 저금 2를 넘지 않아 $n$번의 총비용이 $3n$ 이하다. 다만 **개별 호출의 최악은 $O(n)$**이고, 그 한 번이 하필 제어 주기 안에 걸리면 그때 지연이 튄다. 공간 $O(n)$ — 다만 재할당하는 그 순간에는 옛 배열($n$)과 새 배열($2n$)이 동시에 살아 있어 **순간 사용량이 원소 수의 3배**까지 간다. 메모리 제한이 빠듯한 문제에서 이 순간이 터지는 지점이다.

`+2` 정책의 복사량 249,500은 정확히 $2 + 4 + \dots + 998 = 249{,}500$이고, 이것이 $n^2/(2\cdot\text{step}) = 250{,}000$의 실제 값이다. **§2.3의 식이 그대로 나온 것이다.**

| 언어 차이 | Python | C++ |
|---|---|---|
| 진짜 고정 배열 | 없다. `[None] * n`이 가장 가깝고 원소는 여전히 포인터다 | `int[]`, `std::array`, `vector`의 내부 버퍼가 값을 연속으로 담는다 |
| 범위 밖 접근 | `IndexError` 예외. 음수 인덱스는 뒤에서 세는 정상 문법이다 | 검사가 없다. `a[-1]`도 `a[n]`도 그냥 읽는다 — 정의되지 않은 동작 |
| 원소 하나의 크기 | `int` 객체 28바이트 + 포인터 8바이트 | `int` 4바이트 |
| 실제 증폭 배수 | 약 1.125배 + 상수 | 2배(libstdc++). 표준이 정한 값이 아니다 |
| 미리 잡기 | `[0] * n` | `reserve(n)` |

::: pitfall
- **재할당은 예전 주소를 전부 무효로 만든다.** `push_back` 한 번에 `vector` 원소를 가리키던 포인터·참조·반복자가 죽는다. Python에서는 참조가 객체를 직접 가리키므로 같은 사고가 나지 않는다. C++ 쪽 상세는 [0-6](#/0-6) §4에 있다.
- **`[[0] * m] * n`은 행을 `n`개 만들지 않는다.** 같은 리스트를 `n`번 가리킨다. `a[0][0] = 1`이 모든 행을 바꾼다. [0-2 Python 입출력과 기본 타입](#/0-2)에 있다.
- **앞쪽 삽입·삭제를 배열로 반복한다.** `list.insert(0, x)`와 `vector::erase(begin())`은 매번 $O(n)$이라 $n$번 하면 $O(n^2)$이다. 양쪽 끝이 필요하면 덱([II-5 큐와 덱](#/ii-5))이다.
- **2차원 배열을 열 우선으로 훑는다.** 결과는 맞고 시간만 16배다. 채점기는 이것도 시간 초과로 돌려준다.
- **크기를 아는데 미리 안 잡는다.** 입력 개수 `n`을 먼저 읽는 문제에서 `reserve(n)` 한 줄이면 재할당이 0번이다.
:::

이제 2차원이다. 격자 문제의 `a[r][c]`는 개념일 뿐이고, 밑에서는 1차원 연속 메모리에 인덱스식 하나로 얹혀 있다.

::: dual
```python title="2차원을 1차원에 얹기 — 인덱스식과 순회 순서"
rows, cols = 3, 4
flat = [0] * (rows * cols)          # 진짜 배치는 1차원이다


def at(r, c):
    return r * cols + c             # 행 우선(row-major). 한 행이 통째로 이어 붙는다


for r in range(rows):
    for c in range(cols):
        flat[at(r, c)] = r * 10 + c

print("행 우선 방문:", [at(r, c) for r in range(rows) for c in range(cols)])
print("열 우선 방문:", [at(r, c) for c in range(cols) for r in range(rows)])
print("flat        :", flat)
```
```cpp title="2차원을 1차원에 얹기 — 인덱스식과 순회 순서"
#include <iostream>
#include <vector>
using namespace std;

int rows = 3, cols = 4;

int at(int r, int c) {
    return r * cols + c;            // 행 우선(row-major). 한 행이 통째로 이어 붙는다
}

int main() {
    vector<int> flat(rows * cols, 0);   // 진짜 배치는 1차원이다
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            flat[at(r, c)] = r * 10 + c;

    cout << "행 우선 방문: [";
    for (int r = 0; r < rows; r++)
        for (int c = 0; c < cols; c++)
            cout << at(r, c) << (r == rows - 1 && c == cols - 1 ? "" : ", ");
    cout << "]\n열 우선 방문: [";
    for (int c = 0; c < cols; c++)
        for (int r = 0; r < rows; r++)
            cout << at(r, c) << (c == cols - 1 && r == rows - 1 ? "" : ", ");
    cout << "]\nflat        : [";
    for (size_t i = 0; i < flat.size(); i++)
        cout << flat[i] << (i + 1 == flat.size() ? "" : ", ");
    cout << "]\n";
    return 0;
}
```
:::

**복잡도:** 두 순회 모두 시간 $O(rc)$ — 칸마다 정확히 한 번씩 방문한다. **복잡도가 같은데 실측이 16배 갈린 이유가 출력에 그대로 보인다.** 행 우선은 방문 인덱스가 `0, 1, 2, 3, 4…`로 연속이고, 열 우선은 `0, 4, 8, 1, 5, 9…`로 매번 `cols`만큼 건너뛴다. 건너뛰는 폭이 캐시 라인(`int` 16개)보다 크면 라인 하나를 읽어 원소 하나만 쓰고 버린다.

## 5. 어디에 쓰이는가

**이미지와 프레임 버퍼가 이 구조 그대로다.** 1920×1080 화면은 픽셀 배열 하나이고 `at(r, c) = r * stride + c`로 접근한다. `stride`가 `cols`가 아니라 그보다 클 수 있는 것은 각 행의 시작을 정렬 경계에 맞추기 위해서다. 영상 처리 루프를 열 우선으로 짜면 결과는 맞고 속도만 무너진다 — [XIII-8 이미지 기본 연산](#/xiii-8)의 컨볼루션이 행 우선으로 도는 이유다.

**실시간 코드에서는 분할상환 $O(1)$이 위안이 되지 않는다.** 총합이 $O(n)$이어도 재할당이 걸린 그 한 번은 $O(n)$이고, 제어 주기가 1밀리초인 루프에서는 그 한 번이 곧 마감 위반이다. 대응은 둘이다. **미리 잡거나**(`reserve`), **아예 늘어나지 않는 자료구조를 쓰거나**([XI-1 링 버퍼](#/xi-1)). 링 버퍼가 고정 크기인 것은 기능 부족이 아니라 지연을 상수로 묶기 위한 설계다.

**트리와 그래프도 배열에 얹힌다.** 힙은 부모·자식을 `2i+1`, `2i+2`로 계산해 포인터 없이 트리를 표현하고([II-8 힙과 우선순위 큐](#/ii-8)), 세그먼트 트리도 같은 방식이다([IX-2](#/ix-2)). 대규모 그래프의 CSR 표현은 인접 리스트를 배열 두 개로 접는다([XI-10 그래프의 메모리 표현](#/xi-10)). **포인터를 인덱스로 바꾸면 캐시가 돌아온다**는 것이 공통 동기다.

**값의 범위가 작으면 배열 자체가 조회 테이블이다.** 알파벳 26개, 좌표 1000×1000, 값이 100만 이하인 정수 — 이런 경우 `count[x] += 1`이 해시보다 빠르다. 해시 함수도 충돌 처리도 없이 주소식 하나로 끝나기 때문이다. 범위가 크거나 키가 문자열이면 그때 해시로 간다([II-6 해시](#/ii-6)).

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "i번째", "N개의 수가 주어진다", "R행 C열의 격자", "각 알파벳이 몇 번", "값이 1 이상 1,000,000 이하"
- 제약조건: 인덱스로 쓸 값의 범위가 $10^7$ 이하여서 배열 하나에 들어간다(`int` 1000만 개 = 40MB). 원소 크기가 일정하고, 중간 삽입·삭제가 없거나 드물다
- 혼동 주의: 값의 범위가 $10^9$이거나 키가 문자열이면 해시([II-6](#/ii-6)). 양쪽 끝에서 넣고 빼면 덱([II-5](#/ii-5)). 중간 삽입·삭제가 잦고 위치를 이미 알고 있으면 연결 리스트([II-3](#/ii-3)). 정렬 상태를 유지하며 삽입해야 하면 균형 트리([II-9](#/ii-9))
- 반례 함정: 값에 음수나 0이 섞여 인덱스가 음수가 되는 입력. 좌표가 1부터 시작하는데 배열을 `n`개만 잡는 입력. 인덱싱은 $O(1)$인데 `insert(0)`을 루프 안에서 불러 전체가 $O(n^2)$이 되는 구현
:::

::: interview
**"배열과 연결 리스트의 차이를 말해 보세요."**
"삽입이 $O(1)$이다"로 끝내면 절반이다. 답변 뼈대는 세 층이다. ① **주소식**: 연속이라 `base + i × size`로 임의 접근이 $O(1)$이고, 그 대신 중간을 비우려면 뒤를 민다. ② **캐시**: 복잡도가 같아도 연속 메모리 순회가 수십 배 빠르다. ③ **연결 리스트가 이기는 조건**: 노드 위치를 이미 손에 들고 있을 때의 삭제뿐이다([II-3](#/ii-3)).

**"`vector`의 `push_back`이 $O(1)$이라는데 왜 그렇습니까."**
분할상환 논증을 요구하는 질문이다. "2배로 늘리니까요"는 결론이지 근거가 아니다. 총 복사량이 $1+2+4+\dots+n < 2n$인 등비급수라는 것, 그래서 원소당 상수라는 것, 그리고 **개별 호출의 최악은 여전히 $O(n)$**이라는 단서까지 말하면 완결된다.
:::

::: quiz
전부 **"인덱스를 무엇으로 삼을 것인가"** 가 본체인 문제다.

**1. 백준 10808 알파벳 개수 (브론즈 4)** — https://www.acmicpc.net/problem/10808
- 신호: "각 알파벳이 몇 개 포함되어 있는지". 세는 대상의 종류가 26개로 **작고 고정**이다.
- 상태: 길이 26짜리 정수 배열 하나. `count[ord(ch) - ord('a')]`.
- 자료구조: 배열. 키가 26종뿐이라 해시의 해시 함수·충돌 처리가 전부 낭비다. 문자를 인덱스로 바꾸는 뺄셈 하나면 끝난다.

**2. 백준 2563 색종이 (실버 5)** — https://www.acmicpc.net/problem/2563
- 신호: 100×100 도화지에 10×10 색종이를 붙이고 "검은 영역의 넓이". 좌표가 곧 인덱스다.
- 상태: 100×100 불리언 격자. 겹침을 세는 것이 아니라 **덮인 칸을 표시**하는 것이 요점이다.
- 자료구조: 2차원 배열. 겹치는 넓이를 포함배제로 계산하려 들면 색종이 100장에 경우의 수가 터진다. 격자가 1만 칸뿐이라 그냥 칠하는 쪽이 싸다.

**3. 백준 3273 두 수의 합 (실버 3)** — https://www.acmicpc.net/problem/3273
- 신호: 수열에서 합이 `x`인 쌍의 개수. `n ≤ 100,000`이라 이중 루프 100억은 넘는다. 값이 **1 이상 1,000,000 이하**라는 줄이 핵심이다.
- 상태: 값이 등장했는지를 담는 길이 1,000,001짜리 배열. `a`를 볼 때마다 `x - a`가 이미 있었는지 묻는다.
- 자료구조: 값 범위가 100만이라 값 자체를 인덱스로 쓸 수 있다. 정렬 후 투 포인터([VI-3](#/vi-3))로도 풀리고 그쪽이 정석이지만, **"값 범위가 작으면 배열이 곧 해시다"** 를 확인하기에는 이쪽이 낫다.

**4. 손으로 확인할 것.** `x - a`를 확인하는 시점이 `a`를 배열에 넣기 **전**인가 **후**인가에 따라 답이 달라진다. `x`가 짝수이고 `a = x/2`인 원소가 있을 때 무슨 일이 일어나는지 손으로 따라가라.

::: answer
넣기 **전**에 확인해야 한다. `a`를 먼저 넣고 `x - a`를 물으면 `a = x/2`일 때 자기 자신과 짝을 이뤄 쌍 하나가 더 세어진다. 예를 들어 `x = 10`, 수열에 `5`가 하나 있으면 정답은 0쌍인데 1쌍이 나온다.

넣기 전에 확인하면 각 쌍은 **뒤에 오는 원소를 처리할 때 정확히 한 번** 세어진다. 이것이 `i < j` 조건을 코드 순서로 강제하는 방법이다. 순서를 뒤집으면 자기 자신과의 짝과 중복 계수가 동시에 들어온다.
:::

## 요약

- 배열의 성질은 전부 **연속 메모리** 하나에서 나온다. `base + i × elemsize`가 $O(1)$ 인덱싱의 전부이고, 빈틈이 없다는 사실이 중간 삽입 $O(n)$의 원인이다.
- 복잡도가 같아도 **접근 순서가 시간을 가른다.** 같은 행렬을 행 우선으로 훑으면 열 우선의 16배다(C++ 실측). 알고리즘이 아니라 루프 순서다.
- 동적 배열의 증폭은 **현재 크기에 비례해야** 한다. 상수만큼 늘리면 총 복사가 $O(n^2)$이고, 배수로 늘리면 등비급수라 $O(n)$이다.
- 분할상환 $O(1)$은 평균이 아니라 **어떤 연산열에도 성립하는 총합 보장**이다. 회계 논증으로 `push`당 코인 3개면 충분하고, +2 정책은 9번째 `push`에서 파산한다.
- **개별 `push`의 최악은 여전히 $O(n)$**이다. 실시간 루프에서는 미리 잡거나 고정 크기 자료구조로 간다.
- 값의 범위가 작으면 **배열 자체가 조회 테이블**이다. 해시 함수도 충돌 처리도 없이 주소식 하나로 끝난다.
- 재할당은 옛 주소를 전부 무효로 만든다. C++에서 이것은 포인터·반복자 무효화라는 실제 버그로 나타난다.
