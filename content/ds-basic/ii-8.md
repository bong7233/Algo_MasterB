# II-8 힙과 우선순위 큐

::: lead
전체를 정렬하지 않고 "지금 가장 급한 것 하나"만 계속 꺼내는 방법.
:::

## 1. 문제

작업 20만 개가 큐에 들어 있고 각 작업에는 마감 시각이 있다. 실행기는 한 바퀴마다 두 가지를 한다. **가장 급한 작업 하나를 꺼내 처리하고, 처리 도중 들어온 새 작업 하나를 집어넣는다.** 이 두 줄이 실시간 스케줄러의 뼈대이고, 이벤트 시뮬레이터와 메시지 브로커의 뼈대이기도 하다.

가진 도구가 배열과 정렬뿐이라면 방법은 셋이다.

**매 바퀴 정렬한다.** 정렬하고 맨 앞을 꺼낸다. 한 바퀴가 $O(n \log n)$이고 바퀴가 $n$번이니 $O(n^2 \log n)$이다.

**정렬하지 않고 매번 훑는다.** 최솟값을 찾는 데 $O(n)$, 전체 $O(n^2)$이다. 정렬보다 낫지만 여전히 제곱이다.

**정렬 상태를 유지한다.** 배열을 계속 정렬된 채로 두면 꺼내는 것은 $O(1)$이다. 그런데 새 작업을 제자리에 끼워 넣으려면 뒤쪽 원소를 전부 한 칸씩 민다. 삽입이 $O(n)$이라 결국 $O(n^2)$이다.

::: perf
세 방법을 같은 입력으로 돌린 값이다. 작업 20,000개로 시작해 "꺼내고 넣기"를 20,000번 반복한다.

| | 매 바퀴 정렬 | 선형 최솟값 스캔 | 힙 |
|---|---|---|---|
| Python 3.13 | 2.425초 | 19.403초 | **0.010초** |
| C++17 `-O2` | 3.041초 | 0.246초 | **0.002초** |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/heap_build_cost.py` 와 `.cpp` 다.)

두 언어에서 **1등과 2등의 순서가 뒤집힌 것**을 그냥 넘기지 마라. C++에서는 선형 스캔이 매 바퀴 정렬보다 12배 빠르다. 복잡도가 그렇게 말한다. Python에서는 반대로 매 바퀴 정렬이 선형 스캔보다 8배 빠르다. `sort()`는 C로 구현되어 있고 거의 정렬된 입력을 알아보지만([0-4](#/0-4)의 Timsort), 손으로 짠 스캔 루프는 인터프리터가 한 줄씩 밟기 때문이다. **같은 언어 안에서만 복잡도 비교가 성립한다**는 [0-10](#/0-10)의 명제가 여기서 그대로 나온다.

그리고 어느 쪽이든 힙이 두 자릿수 이상 빠르다. 이 표에서 볼 것은 그것이다.
:::

세 방법이 전부 제곱인 이유는 같다. **우리는 전체 순서를 요구한 적이 없다.** 필요한 것은 최솟값 하나인데, 정렬은 $n$개의 순위를 전부 만들어 준다. 그중 하나만 쓰고 나머지는 다음 바퀴에 버려진다. 과잉 서비스에 대한 요금을 매 바퀴 낸다.

그러면 질문은 이렇게 된다. **"전부 정렬한다"와 "아무 순서도 없다" 사이에 중간 단계가 있는가.** 최솟값 하나만 싸게 보장하고 나머지는 대충 두는 자료구조가 있는가.

## 2. 아이디어

있다. 요구를 딱 하나로 줄인다.

> **부모는 두 자식보다 작거나 같다.**

형제끼리는 아무 관계도 요구하지 않는다. 왼쪽 서브트리와 오른쪽 서브트리 사이에도 아무 약속이 없다. 이 조건 하나만 지키는 이진 트리를 **최소 힙**이라 한다.

이 하나로 무엇이 보장되는가. 아무 노드에서 부모를 따라 위로 올라가면 값이 계속 작아지거나 같고, 그 길은 반드시 루트에서 끝난다. 따라서 **루트가 전체 최솟값이다.** 최솟값을 보는 데 비교가 0회다.

무엇을 포기했는가. 두 번째로 작은 값이 어디 있는지 모른다. 루트의 두 자식 중 하나라는 것까지만 안다. 세 번째부터는 그마저도 없다. ==힙은 정렬이 아니라 부분 순서다.== 그 느슨함이 유지비를 낮춘다. 완전히 정렬된 배열은 $n!$가지 배치 중 하나뿐이지만, 힙 조건을 만족하는 배치는 그보다 훨씬 많다. 지켜야 할 것이 적으니 고치는 데도 적게 든다.

### 2.1 트리는 그림이고 배열이 힙이다

힙을 트리로 그리는 것은 설명을 위해서다. 실제 저장은 **배열 하나**다. 그것이 가능한 이유는 힙이 **완전 이진 트리**이기 때문이다. 마지막 레벨을 뺀 모든 레벨이 꽉 차 있고, 마지막 레벨은 왼쪽부터 빈틈없이 채워진 트리다.

빈틈이 없으니 레벨 순서로 번호를 매기면 번호가 곧 배열 인덱스가 된다. 그러면 부모와 자식의 관계가 산술식이 된다.

```text nolines
   index    0     1     2     3     4     5     6
          +-----+-----+-----+-----+-----+-----+-----+
   heap   |  1  |  4  |  2  |  9  |  8  |  7  |  6  |
          +-----+-----+-----+-----+-----+-----+-----+
             |     |     |
             |     |     +--- children of 2 : 2*2+1 = 5,  2*2+2 = 6
             |     +--------- children of 1 : 2*1+1 = 3,  2*1+2 = 4
             +--------------- root
```

**부모 `(i-1)//2`, 왼쪽 자식 `2i+1`, 오른쪽 자식 `2i+2`.** 이 세 식이 그림과 코드를 잇는 다리 전부다. 포인터도, 노드 객체도, 할당도 없다. 값만 연속 메모리에 늘어서 있어 캐시 지역성도 좋다([0-6](#/0-6)).

높이는 $\lfloor \log_2 n \rfloor$이다. 원소가 100만 개면 19다. **어떤 연산이든 이 19층을 넘어 이동할 수 없다.**

::: widget heap-ops {"values":[9,4,7,1,8,2,6],"kind":"min","ops":[["heapify"],["push",0],["pop"]]}
:::

위젯은 같은 힙을 트리와 배열 두 가지로 동시에 보여주고, 세 연산을 차례로 재생한다. 위젯이 안 뜨는 환경을 위해 말로 옮긴다.

**heapify.** 배열 `[9, 4, 7, 1, 8, 2, 6]`은 아직 힙이 아니다. 인덱스 2부터 0까지 거꾸로 내려가며 각 노드를 제자리로 **내려보낸다**. `i ≥ 3`인 칸은 자식이 없는 잎이라 손대지 않는다.

**push.** 새 값 `0`을 배열 맨 끝에 붙인다. 트리로는 마지막 레벨의 다음 빈자리다. 완전 이진 트리 조건은 그대로 유지된다. 이제 부모와 비교해 자기가 더 작으면 교환하며 **올라간다**(sift-up). 부모가 더 작거나 루트에 닿으면 멈춘다. `0`은 루트까지 올라간다.

**pop.** 루트를 꺼낸다. 그러면 꼭대기에 구멍이 나는데, 이때 **배열의 맨 뒤 원소를 루트로 옮긴다.** 이유는 모양이다. 맨 뒤를 빼야 완전 이진 트리가 완전한 채로 남고 배열에 구멍이 안 생긴다. 옮겨 온 값은 대개 크므로, 두 자식 중 더 작은 쪽과 비교해 교환하며 **내려간다**(sift-down). 자식보다 작거나 잎에 닿으면 멈춘다.

세 연산 모두 한 층씩만 움직이고 층수는 $\lfloor \log_2 n \rfloor$이다. 그래서 push와 pop이 $O(\log n)$이다.

### 2.2 heapify는 왜 $O(n)$인가

배열 하나를 통째로 힙으로 만드는 방법이 둘이다. 빈 힙에 원소를 하나씩 push하거나, 배열을 그대로 두고 아래에서부터 sift-down을 돌리거나. 앞은 $O(n \log n)$이고 뒤는 $O(n)$이다. **같은 결과에 다른 비용이 드는 이유는 어디서 시작하느냐에 있다.**

완전 이진 트리에서 노드의 분포는 심하게 치우쳐 있다. 절반이 잎이고, 4분의 1이 그 바로 위 층이며, 루트는 하나다.

| 위치 | 노드 수 | sift-down으로 내려갈 수 있는 최대 거리 |
|---|---|---|
| 마지막 레벨 (잎) | 약 $n/2$ | 0 |
| 그 위 | 약 $n/4$ | 1 |
| 그 위 | 약 $n/8$ | 2 |
| … | … | … |
| 루트 | 1 | $h$ |

**아래에서 시작하면 노드가 많은 곳이 곧 거리가 짧은 곳이다.** 높이 $h$인 트리에서 깊이 $d$의 노드는 최대 $2^d$개이고 각각 최대 $h - d$만큼 내려간다. 전체 이동량의 상한은

$$\sum_{d=0}^{h} 2^d (h-d) \;=\; \sum_{j=0}^{h} 2^{h-j} \, j \;=\; 2^h \sum_{j=0}^{h} \frac{j}{2^j} \;<\; 2^h \cdot 2 \;\le\; 2n$$

이다. 가운데 변형은 $j = h - d$로 바꿔 쓴 것이고, 마지막 부등호는 $\sum_{j \ge 1} j / 2^j = 2$라는 사실을 쓴다. **결론은 교환 횟수가 $2n$을 넘지 않는다는 것, 즉 $O(n)$이다.**

push를 반복하면 정확히 반대가 된다. 새 원소는 항상 **맨 아래**에 들어가고 거기서 최대 $h$층을 올라간다. 노드가 가장 많은 자리가 이동 거리도 가장 긴 자리다. 합은 $O(n \log n)$이 된다.

::: perf
원소 100만 개로 힙을 만들 때 실제로 일어나는 교환 횟수다. 시간은 캐시와 기기에 흔들리지만 교환 횟수는 입력이 같으면 결정적이다.

| 입력 | push 반복 | heapify | 비율 |
|---|---|---|---|
| 무작위 | 1,277,927회 (원소당 1.28) | 743,031회 (원소당 0.74) | 1.72배 |
| 내림차순(최악) | 17,951,445회 (원소당 **17.95**) | 999,988회 (원소당 **1.00**) | **17.95배** |

> (Linux x86-64 / g++ 13 `-O2` 실측. 측정 스크립트는 `tools/bench/heap_build_cost.cpp` 다.)

무작위 입력에서는 1.72배밖에 안 벌어진다. 무작위로 들어온 값이 기존 원소 대부분보다 작을 확률이 낮아 sift-up이 평균 한두 층에서 멈추기 때문이다. **평균이 좋다는 것과 복잡도가 좋다는 것은 다른 말이다.**

최소 힙에 내림차순으로 넣으면 새 원소가 매번 전체 최솟값이라 루트까지 올라간다. 원소당 17.95회는 $\log_2 10^6 \approx 19.9$에 대응하는 수다. 같은 입력에서 heapify는 원소당 정확히 1.00회다 — 위에서 유도한 $2n$ 상한 안이다. **최악 입력에서 두 방법은 18배로 갈라진다.**

시간으로도 같은 방향이다. 무작위 100만 개 빌드가 Python은 `heappush` 반복 0.107초 대 `heapify` 0.050초(2.13배), C++은 0.016초 대 0.011초(1.42배)다.
:::

## 3. 손으로 따라가기

::: trace
입력 배열 `[9, 4, 7, 1, 8, 2, 6]`을 **최소 힙**으로 만든다(heapify). 0-based 인덱스다.

시작 지점은 `n // 2 - 1 = 7 // 2 - 1 = 2`이고 여기서 0까지 거꾸로 내려가며 sift-down한다. sift-down 한 번이 여러 층을 내려갈 수 있으므로 **한 층 이동할 때마다 한 줄**을 찍는다.

| 스텝 | i | heap[i] | 자식 인덱스 | 자식 값 | 최솟값 위치 | 교환 후 배열 |
|---|---|---|---|---|---|---|
| 0 | 2 | 7 | 5, 6 | 2, 6 | 5 | [9, 4, **2**, 1, 8, **7**, 6] |
| 1 | 1 | 4 | 3, 4 | 1, 8 | 3 | [9, **1**, 2, **4**, 8, 7, 6] |
| 2 | 0 | 9 | 1, 2 |  |  |  |
| 3 |  |  |  |  |  |  |
| 4 |  |  |  |  |  |  |

세 가지를 확인하라.

- [ ] 스텝 2에서 교환한 뒤 **왜 한 스텝이 더 필요한가.** i는 다음에 얼마가 되는가
- [ ] 교환은 전부 몇 번 일어나는가
- [ ] `i = 3, 4, 5, 6`은 왜 한 번도 시작점이 되지 않는가. 그 칸들은 왜 이미 힙인가
:::

::: answer
| 스텝 | i | heap[i] | 자식 인덱스 | 자식 값 | 최솟값 위치 | 교환 후 배열 |
|---|---|---|---|---|---|---|
| 0 | 2 | 7 | 5, 6 | 2, 6 | 5 | [9, 4, **2**, 1, 8, **7**, 6] |
| 1 | 1 | 4 | 3, 4 | 1, 8 | 3 | [9, **1**, 2, **4**, 8, 7, 6] |
| 2 | 0 | 9 | 1, 2 | 1, 2 | 1 | [**1**, **9**, 2, 4, 8, 7, 6] |
| 3 | 1 | 9 | 3, 4 | 4, 8 | 3 | [1, **4**, 2, **9**, 8, 7, 6] |
| 4 | 3 | 9 | 7, 8 | 범위 밖 | — | 잎이므로 멈춘다 |

결과는 `[1, 4, 2, 9, 8, 7, 6]`이고 교환은 **4회**다.

**스텝 2 다음이 스텝 3인 이유.** sift-down은 노드 하나를 제자리로 보내는 절차다. 스텝 2에서 `9`는 인덱스 1로 내려갔을 뿐 아직 제자리가 아니다. 내려간 자리에서 다시 자식과 비교해야 한다. ==한 번 교환했으면 끝난 것이 아니라 따라 내려가야 한다.== sift-down을 `if`가 아니라 `while`로 짜야 하는 이유가 이것이다.

**`i ≥ 3`이 시작점이 되지 않는 이유.** `n = 7`에서 인덱스 3의 왼쪽 자식은 $2 \cdot 3 + 1 = 7$이고 이미 배열 밖이다. 인덱스 3부터 6까지는 전부 자식이 없는 잎이고, ==자식이 없는 노드는 그 자체로 힙 조건을 만족한다.== 손댈 이유가 없다.

이것이 §2.2의 계산을 배열 일곱 칸에서 눈으로 확인한 것이다. **일곱 칸 중 넷은 아예 건드리지 않았다.** $n$이 커져도 비율은 그대로 절반이고, 그 위 4분의 1은 최대 한 층만 움직인다. 여기서 $O(n)$이 나온다.

한편 이 크기에서는 push 반복도 교환 4회로 끝난다. **작은 입력은 점근 차이를 감춘다.** 두 방법이 갈라지는 것은 §2.2의 표처럼 $n$이 크고 입력이 나쁠 때다.
:::

## 4. 구현

세 연산 전부 `sift_up`과 `sift_down` 위에 얹힌다.

::: dual
```python title="최소 힙 — push · pop · heapify"
def sift_up(heap, i):
    while i > 0:
        p = (i - 1) // 2                 # 부모 인덱스
        if heap[i] >= heap[p]:
            break                        # 부모가 더 작으면 힙 조건 성립. 여기서 멈춘다
        heap[i], heap[p] = heap[p], heap[i]
        i = p                            # 올라간 자리에서 다시 본다


def sift_down(heap, i, n):
    while True:
        l, r, best = 2 * i + 1, 2 * i + 2, i
        if l < n and heap[l] < heap[best]:
            best = l
        if r < n and heap[r] < heap[best]:
            best = r
        if best == i:
            break                        # 자기가 제일 작다. 제자리다
        heap[i], heap[best] = heap[best], heap[i]
        i = best                         # 내려간 자리에서 다시 본다


def push(heap, v):
    heap.append(v)                       # 완전 이진 트리를 유지하려면 자리는 맨 끝 하나뿐이다
    sift_up(heap, len(heap) - 1)


def pop(heap):
    top = heap[0]
    last = heap.pop()                    # 맨 뒤를 떼어 루트로 옮긴다. 그래야 구멍이 안 생긴다
    if heap:
        heap[0] = last
        sift_down(heap, 0, len(heap))
    return top


def heapify(a):
    for i in range(len(a) // 2 - 1, -1, -1):   # 마지막 내부 노드부터 거꾸로
        sift_down(a, i, len(a))


heap = [9, 4, 7, 1, 8, 2, 6]
heapify(heap)
print("heapify:", heap)
push(heap, 0)
print("push 0 :", heap)
out = []
while heap:
    out.append(pop(heap))
print("pop all:", out)
```
```cpp title="최소 힙 — push · pop · heapify"
#include <iostream>
#include <vector>
using namespace std;

void sift_up(vector<int>& heap, int i) {
    while (i > 0) {
        int p = (i - 1) / 2;             // 부모 인덱스
        if (heap[i] >= heap[p]) break;   // 부모가 더 작으면 힙 조건 성립. 여기서 멈춘다
        swap(heap[i], heap[p]);
        i = p;                           // 올라간 자리에서 다시 본다
    }
}

void sift_down(vector<int>& heap, int i, int n) {
    while (true) {
        int l = 2 * i + 1, r = 2 * i + 2, best = i;
        if (l < n && heap[l] < heap[best]) best = l;
        if (r < n && heap[r] < heap[best]) best = r;
        if (best == i) break;            // 자기가 제일 작다. 제자리다
        swap(heap[i], heap[best]);
        i = best;                        // 내려간 자리에서 다시 본다
    }
}

void push(vector<int>& heap, int v) {
    heap.push_back(v);                   // 완전 이진 트리를 유지하려면 자리는 맨 끝 하나뿐이다
    sift_up(heap, (int)heap.size() - 1);
}

int pop(vector<int>& heap) {
    int top = heap[0];
    int last = heap.back();              // 맨 뒤를 떼어 루트로 옮긴다. 그래야 구멍이 안 생긴다
    heap.pop_back();
    if (!heap.empty()) {
        heap[0] = last;
        sift_down(heap, 0, (int)heap.size());
    }
    return top;
}

void heapify(vector<int>& a) {
    for (int i = (int)a.size() / 2 - 1; i >= 0; i--)   // 마지막 내부 노드부터 거꾸로
        sift_down(a, i, (int)a.size());
}

void show(const char* tag, const vector<int>& a) {
    cout << tag << " [";
    for (size_t i = 0; i < a.size(); i++) cout << (i ? ", " : "") << a[i];
    cout << "]\n";
}

int main() {
    vector<int> heap = {9, 4, 7, 1, 8, 2, 6};
    heapify(heap);
    show("heapify:", heap);
    push(heap, 0);
    show("push 0 :", heap);
    vector<int> out;
    while (!heap.empty()) out.push_back(pop(heap));
    show("pop all:", out);
    return 0;
}
```
:::

두 구현의 출력은 한 글자도 다르지 않다.

```console
heapify: [1, 4, 2, 9, 8, 7, 6]
push 0 : [0, 1, 2, 4, 8, 7, 6, 9]
pop all: [0, 1, 2, 4, 6, 7, 8, 9]
```

마지막 줄이 정렬 결과라는 점을 짚어 둔다. **힙에서 전부 꺼내면 정렬된다.** 그것이 힙 정렬이고 $O(n \log n)$이다([II-7 정렬](#/ii-7)).

**복잡도:** `push`·`pop`이 각각 시간 $O(\log n)$ — 한 번의 반복이 정확히 한 층 이동이고 완전 이진 트리의 높이가 $\lfloor \log_2 n \rfloor$이라 반복 횟수가 그 값을 넘지 못한다. `heapify`가 시간 $O(n)$ — §2.2의 합 $\sum 2^d (h-d) < 2n$. 최솟값 조회는 $O(1)$ — `heap[0]`을 읽을 뿐 비교가 0회다. 공간은 $O(n)$이고 **추가 공간은 0**이다. 포인터 없이 입력 배열 위에서 제자리로 돌아간다.

상수도 말해 둔다. $O(\log n)$은 100만 개에서 19이지만 **19번의 접근이 배열의 전혀 다른 곳을 찌른다.** 인덱스가 매번 두 배씩 뛰므로 위쪽 몇 층을 지나면 캐시 라인이 재사용되지 않는다. 같은 $O(\log n)$이라도 연속 접근 19회와 비용이 다르다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 표준 힙 방향 | `heapq`는 **최소 힙 고정** | `priority_queue`는 **최대 힙 기본** |
| 뒤집는 법 | 값에 `-1`을 곱해 넣고 꺼낼 때 다시 곱한다 | `priority_queue<T, vector<T>, greater<T>>` |
| 타입 | 별도 타입 없음. `list`를 함수로 다룬다 | 독립 타입. 내부 배열에 손댈 수 없다 |
| 꺼내기 | `heappop`이 값을 **반환**한다 | `top()`으로 읽고 `pop()`으로 버린다. **두 단계다** |
| 여러 키로 비교 | 튜플 `(우선순위, 값)`. 앞부터 차례로 비교 | `pair`/`tuple` 또는 비교자를 직접 준다 |
| 빈 컨테이너에서 꺼내기 | `IndexError`가 난다 | **미정의 동작.** 검사해 주지 않는다 |

표준 라이브러리 사용법 자체는 [0-4](#/0-4)와 [0-6](#/0-6)에 있다. 여기서 알아야 할 것은 그 안이 방금 짠 스무 줄이라는 사실이다.

::: pitfall
- **힙 안의 원소를 직접 고친다.** `heap[i] = new_value`는 불변식을 조용히 깬다. 그 뒤로 루트가 최솟값이라는 보장이 사라지고 증상은 한참 뒤에 엉뚱한 곳에서 나온다. 값이 바뀌면 **새 항목을 넣고, 꺼낼 때 낡은 것을 버려라.** 다익스트라가 그렇게 짜인다([V-1](#/v-1)).
- **최대 힙을 부호 반전으로 흉내 낼 때의 하한.** C++에서 `int`의 최솟값 $-2^{31}$은 부호를 뒤집을 수 없다. 결과가 `int`에 없어 그대로 자기 자신이 된다. Python은 임의 정밀도라 이 함정이 없다 — **언어를 옮길 때 조용히 깨지는 종류다**([0-5](#/0-5)).
- **빈 힙에서 꺼낸다.** Python은 예외로 알려 주지만 C++의 `top()`/`pop()`은 검사하지 않는다. `empty()` 확인이 없으면 쓰레기 값을 읽고 계속 돈다.
- **`heap[1]`이 두 번째로 작다고 가정한다.** 아니다. 두 번째로 작은 값은 `heap[1]`과 `heap[2]` 중 하나이고, 세 번째부터는 이런 규칙조차 없다. 힙은 부분 순서다.
- **`pop`에서 맨 뒤가 아닌 원소를 루트로 올린다.** 완전 이진 트리가 깨져 인덱스 산술이 무효가 된다. 배열에 구멍이 생기는 순간 `2i+1`은 아무 의미가 없다.
:::

## 5. 어디에 쓰이는가

**타이머 큐가 최소 힙이다.** 수만 개의 타임아웃이 걸려 있어도 이벤트 루프가 매 순간 알아야 하는 것은 하나다. "다음에 만료될 타이머는 무엇이고 언제인가." 만료 시각을 키로 한 최소 힙이면 조회가 $O(1)$, 등록과 만료가 $O(\log n)$이다. 타이머가 아주 많고 정밀도를 낮춰도 되는 경우에는 타이머 휠이라는 다른 트레이드오프가 있다([XI-8](#/xi-8)).

**이벤트 기반 시뮬레이션의 심장이다.** 시뮬레이터는 "다음 이벤트 시각"을 반복해서 꺼내고, 처리하면서 새 이벤트를 미래 시각에 등록한다. §1의 루프와 한 글자도 다르지 않다.

**다익스트라의 엔진이다.** 다익스트라가 하는 일은 "아직 확정되지 않은 정점 중 시작점에서의 거리가 가장 작은 것"을 반복해서 꺼내는 것이다. 그 한 문장이 곧 최소 힙의 계약이다. 힙을 빼면 매번 전체를 훑어야 하고 $O(V^2)$가 된다. 힙을 넣으면 $O(E \log V)$다. A\*는 같은 힙에 키를 `f = g + h`로 바꿔 넣은 것이고([V-5](#/v-5)), D\* Lite의 우선순위 큐도 같은 자리에 있다([V-7](#/v-7)). ==최단경로 계보 전체가 이 챕터의 자료구조 위에 서 있다.== [V-1 다익스트라](#/v-1)에서 그대로 이어진다.

**상위 K개를 뽑는 데 쓴다.** 로그 10억 줄에서 응답이 가장 느린 100건을 뽑는 상황이다. 전부 정렬하면 $O(n \log n)$이고 메모리도 $n$만큼 든다. **크기를 K로 고정한 최소 힙**을 들고 다니며 새 값이 루트보다 크면 루트를 버리고 넣으면 $O(n \log K)$에 메모리가 $O(K)$다. 데이터가 메모리에 다 안 들어가는 스트리밍 상황에서는 이쪽만 가능하다([XV-12](#/xv-12)).

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "가장 급한 것부터", "우선순위가 가장 높은", "매번 최솟값을 꺼내", "N번째 큰 수", "그때그때 최댓값"
- 제약조건: N ≤ $10^6$이고, 매 시점 필요한 것이 최솟값 또는 최댓값 **하나뿐**일 것. 전체 순서가 필요 없을 것. 상위 K개만 필요하고 메모리가 빠듯하면 힙 크기를 K로 고정한다
- 혼동 주의: 원소가 전부 주어진 뒤 순서가 **한 번만** 필요하면 정렬([II-7](#/ii-7)). 중앙값·구간·"x 이상인 가장 작은 값"처럼 최솟값 말고 다른 위치가 필요하면 균형 트리([II-9](#/ii-9)). 키로 즉시 찾아야 하면 해시([II-6](#/ii-6))
- 반례 함정: 이미 힙에 들어 있는 원소의 우선순위가 도중에 바뀌는 입력. 표준 힙에는 decrease-key가 없어 갱신본을 새로 넣고 꺼낼 때 낡은 것을 버려야 한다. 이 처리를 빼면 같은 원소를 두 번 처리한다
:::

::: interview
**"우선순위 큐를 어떻게 구현하겠습니까."**
답변 뼈대는 자료구조가 아니라 요구 분석에서 시작한다. "필요한 연산이 삽입·최솟값 조회·최솟값 삭제 셋뿐이면 이진 힙입니다. 배열 하나로 구현되고 삽입·삭제가 $O(\log n)$, 조회가 $O(1)$이며 추가 메모리가 없습니다. 정렬 배열은 조회가 $O(1)$이지만 삽입이 $O(n)$이고, 연결 리스트는 삽입이 $O(1)$이지만 조회가 $O(n)$입니다." 셋을 비교해 놓고 고른 것이 답이다.

**"heapify가 $O(n)$인 이유를 설명해 보세요."**
$O(n \log n)$이라고 답하기 쉬운 자리다. 뼈대는 §2.2다. "노드의 절반이 잎이라 이동 거리가 0이고, 그 위 4분의 1은 최대 1입니다. 깊이 $d$의 노드 $2^d$개가 각각 최대 $h-d$만큼 움직이므로 총합이 $\sum 2^d (h-d) < 2n$입니다." **"노드가 많은 곳일수록 적게 움직인다"** 한 문장이 핵심이고 나머지는 그 정량화다.
:::

## 연습

::: quiz
**1. 백준 11286 절댓값 힙 (실버 1)** — https://www.acmicpc.net/problem/11286
- 신호: 연산이 "넣기"와 "절댓값이 가장 작은 것 꺼내기" 둘뿐이다. 전체 순서를 묻지 않는다.
- 상태: 힙 하나. 비교 기준이 값이 아니라 `(절댓값, 값)`이다.
- 자료구조: 최소 힙. **비교 규칙만 바꾸면 되지 자료구조를 바꿀 일이 아니라는 것**이 이 문제의 요점이다. Python은 튜플을 넣고, C++은 `pair` 또는 비교자를 준다.

**2. 백준 2075 N번째 큰 수 (실버 2)** — https://www.acmicpc.net/problem/2075
- 신호: 수가 $N^2$개인데 메모리 제한이 12MB다. **전부 담을 수 없다**는 제약이 곧 알고리즘 지정이다.
- 상태: 지금까지 본 수 중 큰 것 N개. 그 N개 중 최솟값이 답의 후보다.
- 자료구조: 크기를 N으로 고정한 최소 힙. §5의 상위 K개 패턴 그대로이고, 메모리가 $O(N)$인 것이 핵심이다.

**3. 백준 1655 가운데를 말해요 (골드 2)** — https://www.acmicpc.net/problem/1655
- 신호: 수가 하나 들어올 때마다 중앙값을 다시 묻는다. "매번"이 힙의 신호다.
- 상태: 작은 절반과 큰 절반. 두 덩어리의 크기 차가 1을 넘지 않게 유지한다.
- 자료구조: **최대 힙과 최소 힙 두 개.** 중앙값은 최솟값도 최댓값도 아니지만, 집합을 둘로 쪼개면 두 힙의 꼭대기가 된다. 매번 정렬하면 $O(n^2 \log n)$이고 이쪽은 $O(n \log n)$이다.

**4. 백준 1202 보석 도둑 (골드 2)** — https://www.acmicpc.net/problem/1202
- 신호: 가방을 무게 오름차순으로 처리하면 각 가방이 담을 수 있는 보석 집합이 **커지기만 한다.** 후보 집합이 스텝마다 자라고 매번 그중 최댓값 하나가 필요하다.
- 상태: 지금 가방에 넣을 수 있는 보석들의 가격 집합.
- 자료구조: 최대 힙. 정렬만으로는 안 되는 이유는 후보 집합이 스텝마다 바뀌기 때문이다([I-5](#/i-5)의 사례 3과 같은 구조다).

## 요약

- 힙이 요구하는 것은 **부모 ≤ 자식** 하나뿐이다. 형제 사이에는 아무 약속이 없다. 그 느슨함이 유지비를 $O(\log n)$으로 낮춘다.
- **트리는 그림이고 배열이 힙이다.** 완전 이진 트리라 구멍이 없고, 그래서 부모 `(i-1)//2`·자식 `2i+1`/`2i+2`라는 산술이 포인터를 대신한다.
- push는 맨 끝에 붙이고 올린다(sift-up). pop은 루트를 꺼내고 **맨 뒤를 루트로 옮긴 뒤** 내린다(sift-down). 맨 뒤여야 완전 이진 트리가 유지된다.
- `heapify`는 $O(n)$이다. 근거는 **노드의 절반이 잎이라 0칸, 그 위 4분의 1이 1칸**이라는 분포이고 정량화하면 $\sum 2^d (h-d) < 2n$이다. 최악 입력 100만 개에서 push 반복은 원소당 17.95회, heapify는 1.00회 교환한다.
- 힙은 정렬이 아니다. `heap[1]`이 두 번째로 작다는 보장이 없고, 전체 순서가 필요하면 힙을 고를 이유가 없다.
- 언어 기본값이 반대다. **`heapq`는 최소 힙 고정, `priority_queue`는 최대 힙 기본**이다. 이 책에서 가장 자주 사고를 내는 언어 차이다.
- 타이머 큐, 이벤트 시뮬레이터, 상위 K개, 그리고 **다익스트라와 A\*의 열린 목록**이 전부 이 자료구조다.
