# II-4 스택

::: lead
가장 최근 것부터 되돌아가는 구조. 재귀가 마법이 아닌 이유가 여기서 드러난다.
:::

## 1. 문제

수식 하나를 읽는다.

```text nolines
  3 * ( 4 + ( 5 - 2 ) )
```

괄호가 짝이 맞는지 확인해야 한다. 여는 괄호와 닫는 괄호의 **개수를 세는 것으로는 안 된다** — `)(` 는 개수가 같은데 틀렸다. 왼쪽부터 훑으면서 닫는 괄호를 만날 때마다 물어야 하는 것은 하나다. **"지금 닫아야 할 것은 무엇인가."** 답은 항상 **가장 최근에 열린 것**이다.

같은 질문이 다른 옷을 입고 계속 나온다. 편집기의 실행 취소는 가장 최근 작업부터 되돌린다. 함수가 반환할 때 돌아갈 자리는 가장 최근 호출자다. HTML 태그를 닫는 순서, JSON의 중괄호, 인터럽트에서 복귀하는 순서가 전부 같다.

이 질문에 답하려면 "지금까지 열렸고 아직 안 닫힌 것들"을 **연 순서대로** 들고 있다가 **거꾸로** 꺼내야 한다. 그 자료구조가 스택이다.

그리고 여기에 이 절의 진짜 주제가 붙어 있다. **재귀 함수가 도는 방식이 정확히 이것이다.** 재귀는 언어가 제공하는 기능이 아니라 **호출 스택이라는 자료구조 위에서 돌아가는 반복**이고, 그 사실을 알면 "재귀로는 되는데 반복으로는 못 짜겠다"는 상태가 사라진다.

## 2. 아이디어

### 2.1 뒤에서만 손대는 배열

스택의 연산은 셋뿐이다. 맨 위에 넣기(`push`), 맨 위를 꺼내기(`pop`), 맨 위를 보기(`top`). 중간에 손대는 연산이 없다.

**그래서 배열이면 끝이다.** 배열이 앞쪽에서 약한 이유는 원소를 밀어야 하기 때문인데([II-1](#/ii-1)), 스택은 뒤에서만 손대므로 밀 일이 없다. `push`는 동적 배열의 분할상환 $O(1)$, `pop`은 크기를 하나 줄이는 $O(1)$이다. **연결 리스트로 만들 이유도 거의 없다** — 순회하지 않고 뒤에만 붙이는 접근 패턴은 캐시가 가장 좋아하는 형태다.

자료구조 자체는 이렇게 열 줄이면 끝난다. 이 절이 길어지는 이유는 자료구조가 아니라 **어디에 이 모양이 숨어 있는지를 알아보는 일**이 어렵기 때문이다.

### 2.2 콜 스택이 스택이다

함수를 부르면 CPU는 **스택 프레임**을 하나 쌓는다. 프레임에 들어가는 것은 돌아갈 주소, 인자, 지역 변수다. 반환하면 프레임을 버리고 적어 둔 주소로 돌아간다.

```text nolines
  f(3) calls f(2) calls f(1)

  ┌──────────────┐  <- top
  │ f(1)  n=1    │
  ├──────────────┤
  │ f(2)  n=2    │     each frame keeps: return address, args, locals
  ├──────────────┤
  │ f(3)  n=3    │
  └──────────────┘  <- bottom
```

==재귀는 "함수가 자기를 부른다"가 아니라 "같은 코드의 프레임이 스택에 여러 겹 쌓인다"이다.== 이 문장이 세 가지를 즉시 설명한다.

**깊이에 한계가 있다.** 스택은 유한한 메모리 영역이다. 다 쓰면 스택 오버플로다. Python은 그 전에 자체 한도(기본 1,000)에서 `RecursionError`를 던지고, C++은 대개 세그멘테이션 폴트로 죽는다.

**지역 변수가 호출마다 따로 있다.** 프레임이 따로이기 때문이다. 반면 함수 밖의 배열은 프레임 밖에 있어 모든 호출이 같은 것을 본다 — DFS의 `visited`가 그렇다.

**재귀는 반드시 반복으로 바꿀 수 있다.** 언어가 대신 관리하던 스택을 **직접 들면** 된다. 자동으로 되던 일을 손으로 하는 것뿐이다.

### 2.3 재귀를 손으로 바꾸는 규칙

바꾸는 절차는 기계적이다.

**① 재귀 호출의 인자를 스택에 담는다.** 위 예에서 `n` 하나면 `n`만 담는다.

**② 반복문에서 하나 꺼내 함수 본문을 실행한다.** 재귀 호출이 있던 자리에서는 부르지 않고 `push`한다.

**③ 순서를 뒤집는다.** 스택은 나중에 넣은 것이 먼저 나온다. 왼쪽을 먼저 방문하려면 **오른쪽을 먼저 넣어야** 한다. 변환에서 가장 많이 틀리는 지점이다.

한 가지가 남는다. 재귀 호출에서 **돌아온 뒤에 할 일**이 있는 경우다. 전위 순회는 값을 먼저 쓰고 내려가므로 그냥 변환되지만, 후위 순회는 자식 둘이 끝난 뒤 자기 차례가 온다. 그때는 **"이 노드는 처음인가, 돌아온 것인가"** 를 함께 담아야 한다. 프레임에 있던 "명령 포인터"를 우리가 대신 들고 다니는 셈이다. 자세한 것은 [II-10 트리 순회](#/ii-10)와 [III-1 재귀 사고법](#/iii-1)에 있다.

### 2.4 단조 스택 — 답을 못 찾은 것들을 쌓아 둔다

스택의 쓰임 중 하나만 처음 볼 때 요령처럼 보인다. 문제는 이렇게 생겼다.

> 수열의 각 원소에 대해, **오른쪽에서 처음으로 자기보다 큰 수**를 구하라.

순진하게 짜면 원소마다 오른쪽을 훑어 $O(n^2)$이다. $n$이 100만이면 못 쓴다.

관찰이 하나 있다. `a = [3, 5, ...]`에서 5를 보는 순간 **3의 답이 확정된다.** 그리고 3은 다시 볼 필요가 없다. 반대로 `a = [5, 2, ...]`에서 2를 보면 5의 답은 아직 모르고, **2의 답을 정하는 수는 5의 답이 될 수 없다**(5보다 작으면서 2보다 큰 수일 수 있으므로). 그래서 5는 2 밑에 그대로 남는다.

여기서 자료구조가 결정된다. **아직 답을 못 찾은 원소들을 쌓아 두는데, 그 값들은 항상 감소 순으로 정렬되어 있다.** 새 원소가 들어오면 그보다 작은 것들이 스택 위쪽에 모여 있고, 그것들의 답이 한꺼번에 확정된다.

- **불변식:** 스택에 남은 값들은 아래에서 위로 감소한다.
- **꺼내는 시점:** 새 원소가 스택 맨 위보다 클 때. 그때 맨 위의 답이 새 원소다.
- **끝난 뒤:** 스택에 남은 것들은 오른쪽에 자기보다 큰 수가 없다.

각 원소는 **정확히 한 번 들어가고 최대 한 번 나온다.** 안쪽 `while`이 여러 번 돌아도 총 `pop` 횟수가 $n$을 넘지 않으므로 전체가 $O(n)$이다. 요령처럼 보이던 것이 불변식 한 줄로 설명된다.

## 3. 손으로 따라가기

::: trace
입력: `a = [3, 5, 2, 7, 5]`. 구할 것은 각 원소의 **오른쪽에서 처음으로 자기보다 큰 수**(없으면 −1).

규칙: `i`를 0부터 늘리면서 — 스택이 비어 있지 않고 `a[스택 맨 위] < a[i]`인 동안 맨 위를 꺼내고 그 답을 `a[i]`로 적는다. 그다음 `i`를 넣는다.

스택은 인덱스를 담지만 표에는 **값**으로 적는다(왼쪽이 바닥).

| i | a[i] | 이번에 확정된 답 | 스택(값) | ans |
|---|---|---|---|---|
| 0 | 3 | — | [3] | [-1, -1, -1, -1, -1] |
| 1 | 5 | 3의 답 = 5 | [5] | [5, -1, -1, -1, -1] |
| 2 | 2 | — | [5, 2] | [5, -1, -1, -1, -1] |
| 3 | 7 | | | |
| 4 | 5 | | | |

세 가지를 확인하라.

- [ ] 스택의 값이 **아래에서 위로 감소**하는가. 어느 줄에서든 깨지는가
- [ ] `i = 3`에서는 몇 개가 한꺼번에 나오는가. 그런데도 왜 전체가 $O(n)$인가
- [ ] 루프가 끝난 뒤 스택에 남은 원소들의 답은 무엇이고, 왜 그런가
:::

::: answer
| i | a[i] | 이번에 확정된 답 | 스택(값) | ans |
|---|---|---|---|---|
| 0 | 3 | — | [3] | [-1, -1, -1, -1, -1] |
| 1 | 5 | 3의 답 = 5 | [5] | [5, -1, -1, -1, -1] |
| 2 | 2 | — | [5, 2] | [5, -1, -1, -1, -1] |
| 3 | 7 | 2의 답 = 7, 5의 답 = 7 | [7] | [5, 7, 7, -1, -1] |
| 4 | 5 | — | [7, 5] | [5, 7, 7, -1, -1] |

최종 답은 `[5, 7, 7, -1, -1]`이다.

**스택은 한 줄도 빠짐없이 감소 순이다.** `[5, 2]`도 `[7, 5]`도 그렇다. 증가하는 쌍이 생기려는 순간이 곧 `while`이 도는 순간이고, 그 순간 아래쪽 작은 값이 뽑혀 나가기 때문에 불변식은 유지된다. ==스택에 감소 순으로 남아 있다는 사실 자체가 "이들은 아직 답을 못 찾았다"와 같은 말이다.==

`i = 3`에서 두 개가 한꺼번에 나왔다. 최악에는 한 스텝에서 $n-1$개가 나올 수도 있다(`[1, 2, 3, …, n]`의 마지막 원소 앞까지 쌓였다가 한 번에). 그래도 전체가 $O(n)$인 이유는 **총량으로 세기 때문이다.** 각 원소는 인생에 딱 한 번 `push`되고 한 번 `pop`되면 다시 돌아오지 않는다. `pop`의 총 횟수는 $n$을 넘을 수 없다. [II-1](#/ii-1) §2.4의 분할상환 논증과 같은 형태다 — 개별 스텝의 최악이 아니라 총합을 세면 상수가 나온다.

끝난 뒤 스택에는 `[7, 5]`가 남았고 둘의 답은 −1이다. **오른쪽에 자기보다 큰 수가 있었다면 그때 뽑혀 나갔을 것이기 때문이다.** 남아 있다는 사실이 곧 "그런 수가 없었다"의 증거다. 이 마지막 처리를 빠뜨리면 −1이어야 할 자리에 초기값이 그대로 남거나 쓰레기가 들어간다.
:::

## 4. 구현

### 4.1 괄호 — 스택의 원형

::: dual
```python title="괄호 검사 — 종류가 여럿인 경우"
def is_balanced(s):
    pair = {")": "(", "]": "[", "}": "{"}
    st = []
    for ch in s:
        if ch in "([{":
            st.append(ch)                  # 열린 것은 나중에 닫힐 순서로 쌓인다
        elif ch in pair:
            if not st or st[-1] != pair[ch]:
                return False               # 짝이 안 맞거나 닫을 것이 없다
            st.pop()
    return not st                          # 남아 있으면 안 닫힌 것이 있다


for s in ["(()[])", "(]", "(()", "())(", ""]:
    print(f"{s!r:10s} -> {is_balanced(s)}")
```
```cpp title="괄호 검사 — 종류가 여럿인 경우"
#include <iostream>
#include <map>
#include <string>
#include <vector>
using namespace std;

bool is_balanced(const string& s) {
    map<char, char> pair_of = {{')', '('}, {']', '['}, {'}', '{'}};
    vector<char> st;
    for (char ch : s) {
        if (ch == '(' || ch == '[' || ch == '{') {
            st.push_back(ch);              // 열린 것은 나중에 닫힐 순서로 쌓인다
        } else if (pair_of.count(ch)) {
            if (st.empty() || st.back() != pair_of[ch])
                return false;              // 짝이 안 맞거나 닫을 것이 없다
            st.pop_back();
        }
    }
    return st.empty();                     // 남아 있으면 안 닫힌 것이 있다
}

int main() {
    vector<string> cases = {"(()[])", "(]", "(()", "())(", ""};
    for (const string& s : cases) {
        string q = "'" + s + "'";
        cout << q;
        for (size_t i = q.size(); i < 10; i++) cout << ' ';
        cout << " -> " << (is_balanced(s) ? "True" : "False") << "\n";
    }
    return 0;
}
```
:::

**복잡도:** 시간 $O(n)$ — 문자마다 `push` 또는 `pop`을 최대 한 번씩 하고 되돌아가지 않는다. 공간 $O(n)$ — 최악은 `"((((…"`처럼 전부 열린 경우이고 그때 스택에 $n$개가 쌓인다. **괄호 종류가 하나뿐이면 공간이 $O(1)$로 줄어든다** — 개수만 세면 되고 음수가 되는 순간 실패다. 종류가 둘 이상이면 "무엇이 열렸는지"를 기억해야 해서 카운터로는 안 된다.

```console
'(()[])'   -> True
'(]'       -> False
'(()'      -> False
'())('     -> False
''         -> True
```

`"())("`가 거짓인 것이 개수 세기로는 안 되는 이유다. 여는 것과 닫는 것이 두 개씩인데 순서가 틀렸다.

### 4.2 재귀와 명시적 스택은 같은 것이다

전위 순회를 두 방식으로 짜서 결과가 같은지 본다.

::: dual
```python title="전위 순회 — 재귀와 명시적 스택"
# 노드는 (값, 왼쪽, 오른쪽) 튜플이다.
tree = (1,
        (2, (4, None, None), (5, None, None)),
        (3, None, (6, None, None)))


def preorder_rec(p, out, depth, peak):
    if p is None:
        return peak
    val, left, right = p
    out.append(val)
    peak = max(peak, depth)                # 호출 스택이 지금 몇 겹인가
    peak = preorder_rec(left, out, depth + 1, peak)
    peak = preorder_rec(right, out, depth + 1, peak)
    return peak


def preorder_iter(root):
    out, st, peak = [], [root], 0
    while st:
        peak = max(peak, len(st))          # 명시적 스택이 지금 몇 개인가
        p = st.pop()
        if p is None:
            continue
        val, left, right = p
        out.append(val)
        st.append(right)                   # 나중에 볼 것을 먼저 넣는다
        st.append(left)
    return out, peak


out_rec = []
peak_rec = preorder_rec(tree, out_rec, 1, 0)
out_it, peak_it = preorder_iter(tree)
print("재귀        :", out_rec, "최대 깊이", peak_rec)
print("명시적 스택 :", out_it, "최대 깊이", peak_it)
print("같은 결과   :", out_rec == out_it)
```
```cpp title="전위 순회 — 재귀와 명시적 스택"
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

// 노드는 (값, 왼쪽, 오른쪽) 이다.
struct Node {
    int val;
    Node* left;
    Node* right;
};

int preorder_rec(Node* p, vector<int>& out, int depth, int peak) {
    if (p == nullptr) return peak;
    out.push_back(p->val);
    peak = max(peak, depth);               // 호출 스택이 지금 몇 겹인가
    peak = preorder_rec(p->left, out, depth + 1, peak);
    peak = preorder_rec(p->right, out, depth + 1, peak);
    return peak;
}

pair<vector<int>, int> preorder_iter(Node* root) {
    vector<int> out;
    vector<Node*> st = {root};
    int peak = 0;
    while (!st.empty()) {
        peak = max(peak, (int)st.size());  // 명시적 스택이 지금 몇 개인가
        Node* p = st.back();
        st.pop_back();
        if (p == nullptr) continue;
        out.push_back(p->val);
        st.push_back(p->right);            // 나중에 볼 것을 먼저 넣는다
        st.push_back(p->left);
    }
    return {out, peak};
}

static void dump(const char* tag, const vector<int>& v, int peak) {
    cout << tag << " [";
    for (size_t i = 0; i < v.size(); i++) cout << v[i] << (i + 1 == v.size() ? "" : ", ");
    cout << "] 최대 깊이 " << peak << "\n";
}

int main() {
    Node n4{4, nullptr, nullptr}, n5{5, nullptr, nullptr}, n6{6, nullptr, nullptr};
    Node n2{2, &n4, &n5}, n3{3, nullptr, &n6};
    Node n1{1, &n2, &n3};

    vector<int> out_rec;
    int peak_rec = preorder_rec(&n1, out_rec, 1, 0);
    auto [out_it, peak_it] = preorder_iter(&n1);
    dump("재귀        :", out_rec, peak_rec);
    dump("명시적 스택 :", out_it, peak_it);
    cout << "같은 결과   : " << (out_rec == out_it ? "True" : "False") << "\n";
    return 0;
}
```
:::

**복잡도:** 두 방식 모두 시간 $O(n)$ — 노드마다 정확히 한 번 방문한다. 공간은 둘 다 $O(h)$($h$는 트리 높이) — 재귀는 프레임이 최대 $h$겹 쌓이고, 명시적 스택도 한 경로의 형제들만 담는다. **한쪽만 메모리를 덜 쓰는 것이 아니다.** 균형 트리면 $h = \log n$이지만 한쪽으로만 뻗은 트리에서는 $h = n$이고, 그때 재귀는 스택 한도에 걸린다.

```console
재귀        : [1, 2, 4, 5, 3, 6] 최대 깊이 3
명시적 스택 : [1, 2, 4, 5, 3, 6] 최대 깊이 4
같은 결과   : True
```

방문 순서가 한 글자도 다르지 않다. **깊이만 3과 4로 다른데, 이것이 `None`까지 스택에 넣은 대가다.** 자식이 있는지를 넣기 전에 확인하면 4가 3이 된다.

::: perf
깊이 2,000짜리 한쪽으로만 뻗은 트리를 총 방문 수를 맞춰 순회한 시간이다.

| | 재귀 | 명시적 스택 | |
|---|---|---|---|
| C++17 `-O2` (2천만 방문) | **0.0615초** | 0.0864초 | 재귀가 1.4배 빠름 |
| Python 3.13 (200만 방문) | 0.631초 | **0.297초** | 명시적 스택이 2.1배 빠름 |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/ii4_recursion_cost.cpp` 와 `.py` 다.)

**방향이 반대다.** C++의 함수 호출은 명령어 몇 개라 `vector`에 포인터를 밀어 넣는 것보다 싸다. Python의 함수 호출은 프레임 객체를 만들고 인자를 묶는 무거운 연산이라, `list.append`가 훨씬 싸다. ==반복으로 바꾸면 빨라진다는 통념은 Python에서만 참이다.==

같은 스크립트가 찍는 다른 줄이 실전에서는 더 중요하다. 기본 재귀 한도 1,000에서 깊이 5,000짜리를 재귀로 순회하면 `RecursionError`가 나고, 명시적 스택은 그대로 통과한다. **깊이 $10^5$짜리 DFS는 알고리즘이 옳아도 기본 설정에서 죽는다.**
:::

| 언어 차이 | Python | C++ |
|---|---|---|
| 스택 자료구조 | `list`의 `append`/`pop`. `deque`도 되지만 느리다 | `vector`의 `push_back`/`pop_back`. `std::stack`은 그 위의 어댑터 |
| 맨 위 꺼내기 | `pop()`이 값을 **반환**한다 | `back()`으로 읽고 `pop_back()`으로 버린다. **두 단계다** |
| 빈 스택에서 꺼내기 | `IndexError` 예외 | **정의되지 않은 동작.** 검사하지 않는다 |
| 재귀 깊이 한도 | 기본 1,000. `sys.setrecursionlimit`으로 올린다 | 시스템 스택 한도(기본 8MB)까지. 넘으면 세그폴트 |
| 호출 비용 | 무겁다. 반복이 2배 빠르다 | 가볍다. 재귀가 1.4배 빠르다 |

### 4.3 단조 스택

::: dual
```python title="오큰수 — 단조 스택"
def next_greater(a):
    n = len(a)
    ans = [-1] * n
    st = []                                # 아직 답을 못 찾은 인덱스들. 값은 항상 감소 순
    for i in range(n):
        while st and a[st[-1]] < a[i]:     # a[i] 가 스택 위쪽들의 답이다
            ans[st.pop()] = a[i]
        st.append(i)
        print(f"i={i} a[i]={a[i]} stack={[a[j] for j in st]} ans={ans}")
    return ans                             # 스택에 남은 것들은 -1 그대로다


a = [3, 5, 2, 7, 5]
print("answer =", next_greater(a))
```
```cpp title="오큰수 — 단조 스택"
#include <iostream>
#include <vector>
using namespace std;

static void dump(const char* tag, const vector<int>& v) {
    cout << tag << "[";
    for (size_t i = 0; i < v.size(); i++) cout << v[i] << (i + 1 == v.size() ? "" : ", ");
    cout << "]";
}

vector<int> next_greater(const vector<int>& a) {
    int n = (int)a.size();
    vector<int> ans(n, -1), st;            // 아직 답을 못 찾은 인덱스들. 값은 항상 감소 순
    for (int i = 0; i < n; i++) {
        while (!st.empty() && a[st.back()] < a[i]) {   // a[i] 가 스택 위쪽들의 답이다
            ans[st.back()] = a[i];
            st.pop_back();
        }
        st.push_back(i);
        vector<int> vals;
        for (int j : st) vals.push_back(a[j]);
        cout << "i=" << i << " a[i]=" << a[i] << " ";
        dump("stack=", vals);
        cout << " ";
        dump("ans=", ans);
        cout << "\n";
    }
    return ans;                            // 스택에 남은 것들은 -1 그대로다
}

int main() {
    vector<int> a = {3, 5, 2, 7, 5};
    vector<int> ans = next_greater(a);
    dump("answer = ", ans);
    cout << "\n";
    return 0;
}
```
:::

**복잡도:** 시간 $O(n)$ — 안쪽 `while`이 한 스텝에서 여러 번 돌 수 있지만, **각 인덱스는 평생 한 번 `push`되고 최대 한 번 `pop`된다.** 총 `pop` 횟수가 $n$을 넘지 못하므로 전체 연산이 $2n$ 이하다. 공간 $O(n)$ — 감소 수열이 입력으로 오면 스택에 전부 쌓인다. **이 논증을 못 하면 이중 루프를 보고 $O(n^2)$이라 답하게 된다.** 면접에서 실제로 갈리는 지점이다.

두 언어의 출력은 같다. §3의 표와도 같다.

```console
i=0 a[i]=3 stack=[3] ans=[-1, -1, -1, -1, -1]
i=1 a[i]=5 stack=[5] ans=[5, -1, -1, -1, -1]
i=2 a[i]=2 stack=[5, 2] ans=[5, -1, -1, -1, -1]
i=3 a[i]=7 stack=[7] ans=[5, 7, 7, -1, -1]
i=4 a[i]=5 stack=[7, 5] ans=[5, 7, 7, -1, -1]
answer = [5, 7, 7, -1, -1]
```

::: pitfall
- **빈 스택을 확인하지 않는다.** `st[-1]`은 Python에서 예외지만 C++ `st.back()`은 **정의되지 않은 동작**이다. 조용히 쓰레기를 읽고 다음에 무슨 일이 날지 모른다. `while` 조건에서 `!st.empty()`를 **먼저** 쓴다(단축 평가).
- **루프가 끝난 뒤 남은 것을 처리하지 않는다.** 괄호는 "남으면 실패", 단조 스택은 "남으면 −1"이다. 두 문제 모두 마지막 처리에서 갈린다.
- **명시적 스택 변환에서 순서를 안 뒤집는다.** 왼쪽부터 방문하려면 오른쪽을 먼저 넣는다. 결과가 좌우 대칭으로 뒤집혀 나오는데 예제에서는 안 걸리는 경우가 많다.
- **스택에 값을 담고 인덱스를 안 담는다.** 단조 스택에서 답을 적으려면 위치가 필요하다. 값만 담으면 어디에 적을지 알 수 없다.
- **재귀 깊이를 안 본다.** 노드 $10^5$개짜리 그래프가 한 줄로 이어져 있으면 DFS 깊이가 $10^5$다. Python은 한도를 올려야 하고, 그래도 안 되면 명시적 스택으로 간다([IV-2](#/iv-2)).
- **`while`을 `if`로 쓴다.** 단조 스택에서 한 스텝에 여러 개가 확정되는 경우를 놓친다. §3 표의 `i = 3`이 정확히 그 줄이다.
:::

## 5. 어디에 쓰이는가

**프로그램이 실행되는 방식 자체가 스택이다.** 함수 호출·반환, 지역 변수의 수명, 재귀의 깊이 한계가 전부 콜 스택의 성질이다. C++의 예외 처리도 여기 얹혀 있다 — 예외가 던져지면 런타임이 프레임을 하나씩 되감으면서(**stack unwinding**) 각 프레임의 지역 객체 소멸자를 **쌓인 역순으로** 부른다. RAII가 성립하는 근거가 이 역순 보장이고, 그래서 "락을 잡은 객체가 스코프를 벗어나면 반드시 풀린다"가 예외 상황에서도 참이다([XI-3](#/xi-3)).

**실행 취소는 스택 두 개다.** 실행한 명령을 undo 스택에 쌓고, 되돌린 명령을 redo 스택으로 옮긴다. 새 명령이 실행되면 redo 스택을 비운다 — 분기된 미래는 더 이상 유효하지 않기 때문이다. 명령을 객체로 만들어 이 스택에 담는 형태가 Command 패턴이고([XII-9](#/xii-9)), 같은 객체를 큐에 담으면 작업 큐가 된다.

**컴파일러와 계산기가 스택으로 수식을 읽는다.** 중위 표기를 후위로 바꾸고 후위 표기를 평가하는 것이 각각 스택 하나짜리 알고리즘이다. 괄호와 연산자 우선순위가 곧 §4.1의 중첩 구조다. 더 나아가면 파서의 상태 스택이 되고, 파싱된 결과를 실행하는 가상 머신도 대개 스택 머신이다.

**탐색 알고리즘의 뼈대가 스택이다.** DFS는 스택, BFS는 큐다 — **이 한 글자 차이가 깊이 우선과 너비 우선을 가른다**([IV-2](#/iv-2), [IV-3](#/iv-3)). 백트래킹은 그 스택에 "되돌릴 정보"를 함께 담는 형태다([III-4](#/iii-4)).

**단조 스택은 "다음으로 큰/작은 것"이 필요한 자리에 그대로 나타난다.** 히스토그램에서 가장 큰 직사각형, 주가에서 다음 상승 시점, 그리고 코스트맵 처리처럼 각 셀에서 조건을 만족하는 가장 가까운 지점을 구하는 계산이 전부 같은 골격이다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "괄호", "짝이 맞는", "가장 최근에", "직전의", "왼쪽에서 자기보다 큰 첫 번째", "오른쪽에서 처음으로", "되돌리기", "중첩된"
- 제약조건: $N \le 10^6$이고 각 원소가 **한 번 들어가고 한 번 나오면 끝나는** 구조. 필요한 정보가 "가장 최근 하나"이고, 중간을 들여다볼 필요가 없다
- 혼동 주의: 먼저 온 것부터 처리하면 큐([II-5](#/ii-5)). 가장 큰 것이 필요하면 힙([II-8](#/ii-8)) — 스택은 **최근**이지 **최대**가 아니다. 임의 구간의 최댓값을 반복해 물으면 세그먼트 트리([IX-2](#/ix-2)). 창의 최댓값이 슬라이딩하면 단조 덱([VI-3](#/vi-3))
- 반례 함정: 빈 입력과 닫는 괄호로 시작하는 입력. 루프가 끝난 뒤 스택에 남은 원소들(괄호면 실패, 단조 스택이면 −1). 같은 값이 연속으로 오는 입력 — `<`인지 `<=`인지가 "자기보다 큰"과 "자기 이상"을 가른다
:::

::: interview
**"재귀와 반복 중 무엇이 빠릅니까."**
"반복이요"는 반쪽이다. 답변 뼈대는 셋이다. ① **재귀는 반복 위에 콜 스택 관리가 얹힌 것**이므로 방문 수는 같다. ② **호출 비용이 언어마다 다르다** — C++은 호출이 싸서 재귀가 오히려 1.4배 빨랐고, Python은 프레임 생성이 무거워 반복이 2.1배 빨랐다. ③ **실무에서 갈리는 것은 속도가 아니라 깊이 한계다.** 깊이 $10^5$면 Python은 `RecursionError`, C++은 스택 오버플로다.

**"이 이중 루프의 복잡도가 왜 $O(n)$입니까."**
단조 스택 코드를 보여 주고 묻는 고전적인 질문이다. 답은 총량 논증이다. "안쪽 `while`은 한 번에 여러 개를 뽑을 수 있지만, **각 원소는 평생 한 번만 `push`되고 한 번만 `pop`됩니다.** 따라서 `pop`의 총 횟수가 $n$을 넘지 못하고 전체가 $O(n)$입니다." **개별 스텝의 최악과 총합의 최악은 다르다**는 점을 짚으면 [II-1](#/ii-1)의 분할상환과 같은 논법임까지 보인다.
:::

## 연습

::: quiz
1·2번은 스택의 원형이고, 3·4번은 단조 스택이다.

**1. 백준 9012 괄호 (실버 4)** — https://www.acmicpc.net/problem/9012
- 신호: "올바른 괄호 문자열인지 판단". 종류가 `(`, `)` 하나뿐이다.
- 상태: 아직 안 닫힌 여는 괄호의 **개수**.
- 자료구조: 종류가 하나라 스택 대신 카운터로 충분하다. **음수가 되는 순간 즉시 실패**이고 끝에 0이 아니어도 실패다. 종류가 늘면 그때 스택이 필요해진다 — 왜 그런지를 말할 수 있어야 이 문제를 푼 것이다.

**2. 백준 1874 스택 수열 (실버 2)** — https://www.acmicpc.net/problem/1874
- 신호: 1부터 n까지를 **순서대로만** 넣을 수 있고, 빼는 순서가 주어진 수열이 되는지 묻는다.
- 상태: 다음에 넣을 수 `next`와 스택의 맨 위.
- 자료구조: 스택. 목표 수가 `next`보다 크면 그때까지 밀어 넣고, 작으면 이미 스택 안에 있다는 뜻인데 맨 위가 아니면 **불가능**이다. 이 판정이 곧 "LIFO로 만들 수 있는 순열"의 정의다.

**3. 백준 17298 오큰수 (골드 4)** — https://www.acmicpc.net/problem/17298
- 신호: "오른쪽에 있으면서 A_i보다 큰 수 중 가장 왼쪽". `N ≤ 1,000,000`이라 $O(n^2)$은 배제된다.
- 상태: 아직 답을 못 찾은 인덱스들의 스택. 값이 감소 순이라는 불변식.
- 자료구조: 단조 스택. **값이 아니라 인덱스를 담아야** 답을 적을 자리를 안다. 끝난 뒤 남은 것은 −1이다.

**4. 백준 2493 탑 (골드 5)** — https://www.acmicpc.net/problem/2493
- 신호: 왼쪽으로 발사한 레이저를 받는 **가장 가까운 큰 탑**. 3번과 방향만 반대다.
- 상태: 왼쪽에서 아직 가려지지 않은 탑들의 스택. 역시 감소 순이다.
- 자료구조: 단조 스택. 오른쪽에서 왼쪽으로 훑어도 되고, 왼쪽에서 오른쪽으로 훑으며 "나보다 작은 것들을 버리고 남은 맨 위가 답"으로 해도 된다. **두 방향이 같은 불변식의 두 얼굴**임을 확인할 자리다.
:::

## 요약

- 스택은 **가장 최근 것부터** 꺼내는 구조이고, 뒤에서만 손대므로 동적 배열이면 구현이 끝난다.
- **콜 스택이 스택이다.** 재귀는 같은 코드의 프레임이 여러 겹 쌓이는 것이고, 그래서 깊이 한계·지역 변수의 독립성·반복으로의 변환 가능성이 전부 설명된다.
- 변환 규칙은 기계적이다. 인자를 스택에 담고, 꺼내서 본문을 실행하고, **순서를 뒤집는다.** 돌아온 뒤 할 일이 있으면 "처음인가 돌아온 것인가"를 함께 담는다.
- 재귀와 반복 중 어느 쪽이 빠른지는 **언어가 정한다.** C++은 재귀가 1.4배 빠르고 Python은 반복이 2.1배 빠르다. 실무에서 갈리는 것은 속도가 아니라 깊이 한계다.
- 단조 스택은 요령이 아니라 불변식이다. **아직 답을 못 찾은 것들이 감소 순으로 쌓여 있다.**
- 이중 루프인데 $O(n)$인 이유는 총량 논증이다. 각 원소가 한 번 `push`되고 한 번 `pop`되므로 총 연산이 $2n$ 이하다.
- 스택은 실행 취소, 수식 파싱, 예외 되감기와 RAII, DFS의 뼈대다. **DFS와 BFS의 차이는 이 자료구조 한 글자다.**
