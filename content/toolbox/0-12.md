# 0-12 디버깅과 반례 찾기

::: lead
채점기가 "틀렸습니다" 한 줄만 돌려줄 때, 그 반례를 스스로 만들어 내는 방법.
:::

## 1. 문제

투 포인터를 짰다. 예제 세 개가 전부 맞는다. 제출한다. `틀렸습니다`.

이 상태에서 할 수 있는 일이 별로 없다. 코드를 다시 읽어도 예제는 여전히 맞고, [0-11 손추적](#/0-11)으로 표를 채워도 그 입력에서는 정상이다. **손추적은 "이 입력에서 코드가 무엇을 하는가"를 알려 주지 "어떤 입력에서 틀리는가"는 알려 주지 않는다.** 반례를 손에 쥐기 전까지는 디버깅이 시작되지 않는다.

흔한 대응이 둘 있고 둘 다 비싸다. 하나는 예제를 손으로 더 만드는 것이다. 사람이 만드는 입력은 사람이 생각한 경우만 담기고, 틀린 이유는 대개 생각하지 못한 경우다. 다른 하나는 조건을 바꿔 가며 재제출하는 것이다. 제출 한 번에 정보 한 비트를 얻는다.

그런데 대부분의 문제에는 **틀릴 수 없는 풀이가 하나 존재한다.** 정의를 그대로 옮긴 완전탐색이다. 느려서 제출할 수 없을 뿐이다.

빠른 풀이와 느린 풀이가 둘 다 있으면 반례 찾기는 자동화된다. 무작위 입력을 만들어 둘에 넣고 답이 갈리는 순간을 잡으면 된다. **사람이 반례를 상상할 필요가 없다.**

## 2. 아이디어

하네스는 네 조각이다. 문제가 바뀌어도 이 구조는 바뀌지 않는다.

```text nolines
  gen(rng) ──┬──▶ brute(t) ──┐
             │               ├──▶ same?      <- 다르면 멈추고 t 를 출력
             └──▶ fast(t)  ──┘
```

`brute`가 정답의 정의다. 성능을 생각하지 않고 문제 설명을 그대로 코드로 옮긴다. $O(n^3)$이어도 상관없다 — 어차피 $n$을 6 이하로만 만들 것이다. **`brute`가 짧고 뻔할수록 하네스가 신뢰할 만하다.**

### 2.1 생성기 설계가 절반이다

무작위 입력이면 다 되는 것이 아니다. 두 가지를 지켜야 한다.

**작게 만든다.** 원소를 여섯 개 이하로 둔다. 이유는 두 개다. 첫째, 반례를 눈으로 읽고 손으로 따라갈 수 있어야 한다. 원소가 1,000개인 반례는 반례가 아니라 또 하나의 미해결 문제다. 둘째, 작을수록 **한 초에 던질 수 있는 입력이 많다.** 버그가 특정 형태에서만 나온다면 그 형태를 뽑을 확률을 높이는 것이 전부다.

**값 범위를 좁게 만든다.** 이쪽이 덜 알려져 있고 더 중요하다. 값을 $0 \sim 10^9$에서 뽑으면 **같은 값이 두 번 나오는 일이 사실상 없다.** 그런데 실전 버그의 큰 부분이 중복·동점·경계 일치에서 나온다. 값을 $0 \sim 3$에서 뽑으면 원소 여섯 개 중 중복이 거의 항상 생긴다.

::: warn
"랜덤 테스트를 100만 번 돌렸는데 안 걸렸다"는 말은 대개 생성기가 좁은 영역만 훑었다는 뜻이다. **생성기가 만들지 못하는 입력은 영원히 검사되지 않는다.** 하네스가 통과했다는 사실보다 생성기가 무엇을 만들 수 있는지가 먼저다.
:::

### 2.2 축소가 나머지 절반이다

무작위 입력에서 처음 걸린 반례는 대개 필요 이상으로 크다. 원소 다섯 개 중 버그와 관계있는 것은 셋뿐인데 나머지 둘이 시야를 가린다.

그래서 **실패를 유지하면서 입력을 계속 깎는다.** 한 번에 한 곳만 건드리고, 깎은 뒤에도 여전히 실패하면 채택하고 아니면 되돌린다. 더 이상 어느 방향으로도 못 깎는 지점이 최소 반례다.

여기서 종료가 보장되는 이유가 [0-11 §2.1](#/0-11)의 **측도**다. 채택될 때마다 (원소 개수, 값의 합)이 반드시 줄어들고, 둘 다 음이 아닌 정수라 무한히 줄어들 수 없다. ==실패 판정이 단조롭게 유지되는 축소 연산만 쓰는 것이 조건이다.==

## 3. 손으로 따라가기

::: trace
검증 대상은 "정렬된 배열에서 `a[i] + a[j] == x` (`i < j`)인 쌍의 개수"를 세는 투 포인터다. 하네스가 5회차에 잡은 입력은 `a = [0, 0, 3, 3]`, `x = 3`이고 `brute = 4`, `fast = 2`였다.

축소 연산은 셋이고 위에서부터 순서대로 시도한다.
(a) 원소 하나 지우기 (b) 원소 하나를 1 줄이기 (c) `x`를 1 줄이기

**실패가 유지될 때만 채택한다.** 채택하면 처음(a)부터 다시 시작한다.

| 시도 | 후보 | brute | fast | 실패? | 채택? |
|---|---|---|---|---|---|
| 1 | `a=[0,3,3] x=3` | 2 | 1 | 예 | 예 |
| 2 | `a=[3,3] x=3` | 0 | 0 | 아니오 | 아니오 |
| 3 | `a=[0,3] x=3` | 1 | 1 | 아니오 | 아니오 |
| 4 |  |  |  |  |  |
| 5 |  |  |  |  |  |
| 6 |  |  |  |  |  |
| 7 |  |  |  |  |  |

시도 4는 (a)의 마지막 후보이고, 5~6은 (b), 7은 (c)다.

- [ ] 시도 3과 4는 후보가 같아 보인다. 왜 두 번 시도되는가
- [ ] 최종적으로 남는 최소 반례는 무엇인가
- [ ] 그 반례에서 `fast`가 왜 1을 돌려주는가. 정답 2와 어디서 갈리는가
:::

::: answer
| 시도 | 후보 | brute | fast | 실패? | 채택? |
|---|---|---|---|---|---|
| 1 | `a=[0,3,3] x=3` | 2 | 1 | 예 | 예 |
| 2 | `a=[3,3] x=3` | 0 | 0 | 아니오 | 아니오 |
| 3 | `a=[0,3] x=3` | 1 | 1 | 아니오 | 아니오 |
| 4 | `a=[0,3] x=3` | 1 | 1 | 아니오 | 아니오 |
| 5 | `a=[0,2,3] x=3` | 1 | 1 | 아니오 | 아니오 |
| 6 | `a=[0,2,3] x=3` | 1 | 1 | 아니오 | 아니오 |
| 7 | `a=[0,3,3] x=2` | 0 | 0 | 아니오 | 아니오 |

**답 1.** 인덱스 1을 지운 것과 인덱스 2를 지운 것이다. `a = [0, 3, 3]`에서 두 `3`은 값이 같으므로 결과 배열이 같아진다. 축소기는 값을 보지 않고 위치를 지우므로 중복 시도가 생긴다. 값이 같은 원소를 건너뛰는 최적화를 넣을 수 있지만, **축소는 실패한 뒤에 한 번만 도는 코드다.** 여기에 복잡도를 넣는 것은 손해다.

시도 5와 6도 같은 이유다. `[0,3,3]`에서 두 번째 `3`을 2로 줄인 것과 세 번째 `3`을 2로 줄인 것이 정렬 후 같아진다.

**답 2.** `a = [0, 3, 3]`, `x = 3`이다. 어느 방향으로도 못 깎는다. 원소를 지우면 실패가 사라지고(시도 2~4), 값을 줄여도 사라지고(5~6), `x`를 줄여도 사라진다(7).

**답 3.** `i = 0`, `j = 2`에서 시작한다. `a[0] + a[2] = 0 + 3 = 3`이고 `x`와 같으므로 `cnt`를 1 올리고 **양쪽 포인터를 동시에 안으로 당긴다.** `i = 1`, `j = 1`이 되어 `i < j`가 깨지고 루프가 끝난다.

그런데 정답은 `(0, 3)` 쌍이 둘이다 — 인덱스 (0,1)과 (0,2). ==`0`이 하나인데 `3`이 둘이므로 쌍은 둘이다.== `fast`는 합이 맞을 때마다 한 개만 세고 지나가므로 **같은 값이 여럿인 경우를 통째로 놓친다.**

값이 전부 다른 입력에서는 이 버그가 절대 드러나지 않는다. §2.1이 값 범위를 좁히라고 한 이유가 정확히 이것이다.
:::

## 4. 구현

네 조각을 코드로 옮긴다. `fast`가 검증 대상이고, 나머지 셋은 문제가 바뀌어도 형태가 같다.

::: dual
```python title="스트레스 테스트 하네스 — gen / brute / fast / 비교 루프"
import random
import sys


def gen(rng):
    n = rng.randint(1, 6)          # 작게: 반례를 눈으로 읽을 수 있어야 한다
    x = rng.randint(0, 6)
    a = sorted(rng.randint(0, 3) for _ in range(n))   # 값 범위를 좁혀 중복을 만든다
    return (a, x)


def brute(t):                      # 정의를 그대로 옮긴다. 느려도 상관없다
    a, x = t
    cnt = 0
    for i in range(len(a)):
        for j in range(i + 1, len(a)):
            if a[i] + a[j] == x:
                cnt += 1
    return cnt


def fast(t):                       # 검증 대상
    a, x = t
    i, j, cnt = 0, len(a) - 1, 0
    while i < j:
        s = a[i] + a[j]
        if s == x:
            cnt += 1               # ❌ 같은 값이 여럿이면 한 번만 세고 지나간다
            i += 1
            j -= 1
        elif s < x:
            i += 1
        else:
            j -= 1
    return cnt


def main():
    rng = random.Random(20260804)  # 시드를 고정해야 같은 실패를 다시 볼 수 있다
    for it in range(1, 100001):
        t = gen(rng)
        if brute(t) != fast(t):
            print(f"[{it}회차] 불일치")
            print(f"  입력  a={t[0]} x={t[1]}")
            print(f"  brute {brute(t)}  fast {fast(t)}")
            return 1
    print("전부 일치")
    return 0


sys.exit(main())
```
```cpp title="스트레스 테스트 하네스 — gen / brute / fast / 비교 루프"
#include <algorithm>
#include <cstdio>
#include <random>
#include <vector>
using namespace std;

struct Case {
    vector<int> a;
    int x;
};

Case gen(mt19937& rng) {
    int n = (int)(rng() % 6) + 1;  // 작게: 반례를 눈으로 읽을 수 있어야 한다
    int x = (int)(rng() % 7);
    vector<int> a(n);
    for (int i = 0; i < n; ++i) a[i] = (int)(rng() % 4);  // 값 범위를 좁혀 중복을 만든다
    sort(a.begin(), a.end());
    return {a, x};
}

long long brute(const Case& t) {   // 정의를 그대로 옮긴다. 느려도 상관없다
    long long cnt = 0;
    for (size_t i = 0; i < t.a.size(); ++i)
        for (size_t j = i + 1; j < t.a.size(); ++j)
            if (t.a[i] + t.a[j] == t.x) cnt += 1;
    return cnt;
}

long long fast(const Case& t) {    // 검증 대상
    int i = 0, j = (int)t.a.size() - 1;
    long long cnt = 0;
    while (i < j) {
        int s = t.a[i] + t.a[j];
        if (s == t.x) {
            cnt += 1;              // ❌ 같은 값이 여럿이면 한 번만 세고 지나간다
            i += 1;
            j -= 1;
        } else if (s < t.x) {
            i += 1;
        } else {
            j -= 1;
        }
    }
    return cnt;
}

int main() {
    mt19937 rng(20260804);         // 시드를 고정해야 같은 실패를 다시 볼 수 있다
    for (int it = 1; it <= 100000; ++it) {
        Case t = gen(rng);
        if (brute(t) != fast(t)) {
            printf("[%d회차] 불일치\n", it);
            printf("  입력  a=[");
            for (size_t i = 0; i < t.a.size(); ++i) printf(i ? ", %d" : "%d", t.a[i]);
            printf("] x=%d\n", t.x);
            printf("  brute %lld  fast %lld\n", brute(t), fast(t));
            return 1;
        }
    }
    printf("전부 일치\n");
    return 0;
}
```
:::

**복잡도:** 한 회차가 시간 $O(n^2)$ — `brute`의 이중 루프가 지배한다. $n \le 6$이므로 회차당 36회 미만이고, 10만 회를 돌려도 총 연산이 $4 \times 10^6$ 수준이라 [0-9](#/0-9)의 예산 안에 여유롭게 들어온다. 공간 $O(n)$ — 매 회차 입력 하나만 들고 있다. **`brute`의 복잡도를 걱정할 필요가 없다는 것이 이 구조의 핵심이다.** 입력이 작아서 $O(n^3)$이어도 같은 결론이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 난수 | `random.Random(seed)` — 메르센 트위스터, 인스턴스마다 독립 | `mt19937(seed)` — 같은 알고리즘이지만 **난수열은 다르다** |
| 범위 뽑기 | `rng.randint(1, 6)` — 양끝 포함 | `rng() % 6 + 1` — 나머지 편향이 있으나 작은 범위에서는 무시할 만하다. 엄밀하게는 `uniform_int_distribution` |
| 입력 표현 | 튜플 `(a, x)` | `struct Case` |
| 종료 코드 | `sys.exit(1)` | `return 1` |

**난수열이 다르다는 것이 여기서 중요하다.** 같은 시드를 줘도 두 언어가 처음 잡는 회차와 그때의 입력이 다르다. 실제로 이 하네스는 Python에서 5회차에 `a=[0,0,3,3] x=3`을, C++에서 5회차에 `a=[0,0,0,2,2] x=0`을 잡았다. ==하네스가 재현해야 하는 것은 특정 입력이 아니라 **버그의 존재**다.==

축소는 별도 함수로 둔다. 실패한 뒤 한 번만 돌기 때문에 하네스 본체와 분리하는 편이 읽기 쉽다.

아래 두 블록은 **조각**이다. 앞 하네스의 `brute`, `fast`, `Case` 정의를 그대로 이어받으므로 이것만 떼어 내면 컴파일되지 않는다.

::: dual
```python title="축소 (조각) — 실패를 유지하면서 더 못 깎을 때까지"
def fails(t):
    return brute(t) != fast(t)


def shrink(t):
    a, x = t
    changed = True
    while changed:
        changed = False
        for i in range(len(a)):                  # (a) 원소 하나 지우기
            cand = (a[:i] + a[i + 1:], x)
            if fails(cand):
                a, changed = cand[0], True
                break
        if changed:
            continue
        for i in range(len(a)):                  # (b) 원소 하나 줄이기
            if a[i] > 0:
                b = a[:]
                b[i] -= 1
                cand = (sorted(b), x)            # 정렬 상태는 입력의 전제다
                if fails(cand):
                    a, changed = cand[0], True
                    break
        if changed:
            continue
        if x > 0:                                # (c) x 줄이기
            cand = (a, x - 1)
            if fails(cand):
                x, changed = x - 1, True
    return (a, x)
```
```cpp title="축소 (조각) — 실패를 유지하면서 더 못 깎을 때까지"
bool fails(const Case& t) { return brute(t) != fast(t); }

Case shrink(Case t) {
    bool changed = true;
    while (changed) {
        changed = false;
        for (size_t i = 0; i < t.a.size(); ++i) {      // (a) 원소 하나 지우기
            Case cand = t;
            cand.a.erase(cand.a.begin() + i);
            if (fails(cand)) { t = cand; changed = true; break; }
        }
        if (changed) continue;
        for (size_t i = 0; i < t.a.size(); ++i) {      // (b) 원소 하나 줄이기
            if (t.a[i] == 0) continue;
            Case cand = t;
            cand.a[i] -= 1;
            sort(cand.a.begin(), cand.a.end());        // 정렬 상태는 입력의 전제다
            if (fails(cand)) { t = cand; changed = true; break; }
        }
        if (changed) continue;
        if (t.x > 0) {                                 // (c) x 줄이기
            Case cand = t;
            cand.x -= 1;
            if (fails(cand)) { t = cand; changed = true; }
        }
    }
    return t;
}
```
:::

**복잡도:** 시간 $O(K \cdot (n + 1) \cdot C)$ — 채택이 일어날 때마다 처음부터 다시 훑으므로, 채택 횟수 $K$에 한 바퀴의 후보 수 $n+1$과 판정 비용 $C = O(n^2)$을 곱한다. $K$의 상한은 측도 (원소 개수 + 값의 합)의 초기값이고 생성기가 작게 만들었으므로 수십을 넘지 않는다. 공간 $O(n)$ — 후보 하나를 복사해 들고 판정한다. **이 함수는 실패한 뒤 한 번만 돌기 때문에 상수를 줄일 이유가 없다.**

::: warn
축소 연산은 **입력의 전제를 깨뜨리면 안 된다.** 이 문제의 입력은 정렬된 배열이므로 원소를 줄인 뒤 반드시 다시 정렬한다. 정렬하지 않고 넘기면 `fast`와 `brute`가 둘 다 정의되지 않은 입력을 받고, 그때의 불일치는 **버그가 아니라 하네스의 오류다.** 유효하지 않은 입력으로 최소화된 반례는 시간만 잡아먹는다.
:::

## 5. 하네스가 실제로 잡은 것

`tools/bench/stress_pair_sum.py`와 `.cpp`를 그대로 돌린 출력이다.

```console
$ python3.13 tools/bench/stress_pair_sum.py 200000
검사 대상: fast()
[5회차] 불일치 발견
  입력   a=[0, 0, 3, 3] x=3
  brute  4
  대상   2
  -- 축소 7회 시도 --
  최소 입력 a=[0, 3, 3] x=3
  brute  2
  대상   1
```

```console
$ /tmp/stress 200000
검사 대상: fast()
[5회차] 불일치 발견
  입력   a=[0, 0, 0, 2, 2] x=0
  brute  3
  대상   1
  -- 축소 11회 시도 --
  최소 입력 a=[0, 0, 0] x=0
  brute  3
  대상   1
```

**5회차다.** 사람이 반례를 상상하려 애쓰는 대신 하네스가 밀리초 안에 찾았다. C++이 최소화한 `a = [0, 0, 0]`, `x = 0`은 더 노골적이다. 세 개의 `0` 중 두 개를 고르는 방법이 3가지인데 `fast`는 1을 돌려준다.

원인은 §3의 정답에 있다. 합이 맞을 때마다 한 쌍만 세고 양쪽을 당기므로 **같은 값 덩어리끼리 만드는 조합이 통째로 빠진다.** 고치려면 덩어리 크기를 세서 곱해야 한다.

```python title="고친 판 (조각) — 같은 값 덩어리를 한꺼번에 센다" {5,10-11}
if s < x:
    i += 1
elif s > x:
    j -= 1
elif a[i] == a[j]:         # 남은 구간이 전부 같은 값 -> 조합으로 센다
    m = j - i + 1
    cnt += m * (m - 1) // 2
    break
else:
    ci = 1                 # 왼쪽 덩어리 크기
    while a[i + 1] == a[i]:
        i += 1
        ci += 1
    cj = 1                 # 오른쪽 덩어리 크기
    while a[j - 1] == a[j]:
        j -= 1
        cj += 1
    cnt += ci * cj         # 두 덩어리가 만드는 쌍의 수
    i += 1
    j -= 1
```

같은 하네스로 고친 판을 검사하면 이렇게 된다.

```console
$ python3.13 tools/bench/stress_pair_sum.py 200000 fixed
검사 대상: fixed()
  20000회 통과
  ...
  200000회 통과
200000회 전부 일치
```

::: tip
검사 대상을 바꿔 끼울 수 있게 만들어 두면 이 확인이 한 줄이다. Python은 `TARGET = fixed`, C++은 함수 포인터 하나를 바꾸면 된다. **하네스는 한 번 짜고 문제마다 `gen`/`brute`/`fast` 셋만 갈아 끼우는 물건이다.** 매번 새로 짜면 하네스 자체에 버그가 들어간다.
:::

::: perf
반례가 없는 판(`fixed`)으로 20만 회를 완주하는 데 **Python 0.96초, C++ 0.029초**다. 회차당 `brute`가 $n \le 6$의 이중 루프뿐이라 이렇게 싸다.

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. 스크립트는 `tools/bench/stress_pair_sum.py` 와 `.cpp` 다.)

싸다는 사실이 설계를 바꾼다. **하네스를 짜는 데 3분, 돌리는 데 1초다.** 반례를 상상하려고 10분 고민하는 것보다 거의 언제나 싸다. 그리고 버그가 있으면 20만 회를 다 돌 일도 없다 — 위에서는 5회차에 걸렸다.
:::

## 6. 경계값 체크리스트

하네스를 못 짜는 상황도 있다. `brute`조차 정의하기 어려운 문제이거나, 시간이 없을 때다. 그때는 손으로 만드는 입력의 목록을 고정해 둔다. **여기 있는 것들은 하네스가 없어도 반드시 넣는다.**

| 축 | 넣을 입력 | 무엇이 드러나는가 |
|---|---|---|
| 크기 | $n = 0$, $n = 1$, $n = 2$ | 루프가 한 번도 안 도는 경우, 포인터 둘이 겹치는 경우 |
| 중복 | 전부 같은 값 | 동점 처리, 덩어리 세기 — **§5의 버그가 여기서 나온다** |
| 순서 | 이미 정렬, 역순 정렬 | 최악 입력, 정렬 안정성([0-13](#/0-13)) |
| 부호 | 전부 음수, 0 포함 | 최댓값 초기화를 0으로 한 버그, 음수 나눗셈([0-11](#/0-11)) |
| 극값 | 제약의 최댓값, 최솟값 | 오버플로, 배열 범위 |
| 답의 위치 | 맨 앞, 맨 뒤, 없음 | 오프바이원. 이 셋이 [0-11 §2.5](#/0-11)의 세 입력이다 |
| 형태 | 자기 자신을 가리키는 간선, 중복 간선, 연결되지 않은 그래프 | 그래프 문제의 전제 위반 |

::: danger
**$n = 1$이 가장 많이 빠진다.** 투 포인터는 `i < j`가 처음부터 거짓이고, 이분 탐색은 `mid`가 항상 같은 자리이고, 분할 정복은 기저 조건이 곧바로 걸린다. 코드의 모든 분기가 한 번씩만 실행되거나 아예 실행되지 않는 상태다.

$n = 0$은 문제가 허용하지 않는 경우가 많지만, 허용한다면 **출력이 빈 줄인지 `0`인지**가 갈린다. 지문이 말하지 않으면 둘 다 시도해 볼 가치가 있다.
:::

## 7. 하네스가 못 잡는 것

세 가지가 남는다. 남는다는 사실을 아는 것이 하네스를 신뢰하는 조건이다.

**첫째, 큰 입력에서만 나는 문제.** 정수 오버플로는 값이 커야 나오고, 시간 초과는 $n$이 커야 나오고, 스택 오버플로는 재귀가 깊어야 나온다. 하네스는 $n \le 6$을 던지므로 전부 통과시킨다. ==정확성과 성능은 다른 검사다.== 성능은 [0-9](#/0-9)의 두 배 실험이 본다.

**둘째, `brute`도 같이 틀린 경우.** 문제를 잘못 읽었다면 두 구현이 같은 오해를 공유하고 하네스는 조용히 통과한다. 이것이 하네스의 근본 한계다. **`brute`를 지문에서 직접 옮기고, 예제 입출력으로 `brute`부터 검증하는 것**이 유일한 방어다.

**셋째, 생성기가 만들지 못하는 입력.** 값을 $0 \sim 3$으로 좁히면 중복은 잘 나오지만 큰 값의 상호작용은 영영 안 나온다. 그래서 **생성기를 두세 개 두고 번갈아 돌린다.** 좁은 값의 작은 입력, 넓은 값의 작은 입력, 특수 구조(전부 같은 값 / 정렬된 / 역순) 하나씩이다.

## 8. 어디에 쓰이는가

**속성 기반 테스트가 이 하네스의 산업용 판이다.** 테스트를 "입력 하나와 기대 출력 하나"로 적는 대신 "이 성질이 모든 입력에서 성립한다"로 적고, 도구가 무작위 입력을 만들어 성질을 깨뜨리려 시도한다. 성질이 깨지면 도구가 자동으로 입력을 줄여 최소 반례를 보고한다. **§2.2의 축소가 그 도구의 핵심 기능이고 이름이 shrinking이다.** 하네스를 직접 짜 본 사람은 그 도구의 출력을 읽을 줄 안다.

**퍼징도 같은 뼈대다.** 무작위·변형 입력을 프로그램에 밀어 넣어 크래시나 이상 동작을 찾는다. 다른 것은 판정 기준이다 — 여기서는 `brute`와 비교했지만, 퍼징에서는 "죽지 않는다", "메모리를 넘지 않는다" 같은 성질이 판정이 된다. 보안 취약점의 상당수가 이 방식으로 발견된다.

**참조 구현 대조는 시스템 교체의 표준 절차다.** 오래된 구현을 새 구현으로 바꿀 때, 한동안 둘을 나란히 돌리고 출력이 갈리는 순간을 기록한다. 옛 구현이 `brute`이고 새 구현이 `fast`다. **정답의 정의가 "지금 돌고 있는 것과 같은 답"인 경우가 실무에서는 오히려 흔하다.**

**축소는 버그 리포트 작성의 절차이기도 하다.** 재현 절차 40단계를 3단계로 줄이는 작업이 §2.2와 같은 알고리즘이다. 한 번에 한 단계씩 지우고, 여전히 재현되면 채택한다. 코드 변경 이력에서 원인 커밋을 이분 탐색으로 찾는 것도 같은 발상의 다른 축이다 — **입력을 줄이는 대신 변경 이력을 줄인다.**

## 9. 이 방법이 필요한 신호

::: classify
- 신호어: "틀렸습니다"인데 예제는 전부 통과, "일부 케이스에서만 실패", "로컬에서는 되는데", "특정 조건에서만 값이 다르다"
- 제약조건: 정답의 정의를 완전탐색으로 옮길 수 있는 문제. 입력을 작게 만들어도 문제가 성립하는 문제. 답이 유일하게 결정되는 문제
- 혼동 주의: 시간 초과에는 쓰지 않는다. 하네스는 작은 입력만 던지므로 성능 문제를 통과시킨다 — 그쪽은 [0-9](#/0-9)의 두 배 실험이다. 코드가 무엇을 하는지 모르겠으면 하네스보다 [0-11](#/0-11)의 손추적이 먼저다
- 반례 함정: 답이 여러 개일 수 있는 문제(경로 복원, 사전순 조건이 없는 구성 문제)에서는 출력을 그대로 비교하면 안 된다. **답의 유효성과 최적성을 따로 판정하는 검사기를 `brute` 자리에 둔다.** 부동소수 출력도 같은 이유로 정확한 비교가 아니라 오차 범위 비교여야 한다([X-7](#/x-7))
:::

## 연습

::: quiz
전부 **하네스를 짜서 반례를 찾는** 훈련이다. 먼저 `brute`를 무엇으로 둘지 정하라.

**1. 백준 2470 두 용액 (골드 5)** — https://www.acmicpc.net/problem/2470
- 신호: 정렬 + 투 포인터의 원형이고, 값에 음수가 섞인다. **§6 체크리스트의 "부호" 축이 그대로 걸린다.**
- 상태: 양끝 포인터 둘과 지금까지의 최선. 합의 절댓값이 최소가 되는 쌍을 찾는다.
- 자료구조: 정렬된 배열. `brute`는 모든 쌍을 보는 $O(n^2)$이고 다섯 줄이다. 생성기는 값을 $-3 \sim 3$에서 뽑아 **합이 0이 되는 쌍과 동점 상황**을 만든다.

**2. 백준 1806 부분합 (골드 4)** — https://www.acmicpc.net/problem/1806
- 신호: "합이 S 이상이 되는 가장 짧은 연속 부분수열". 조건을 만족하는 답이 **없을 수 있다**는 것이 함정이다.
- 상태: 창의 왼쪽 끝, 오른쪽 끝, 창 안의 합. 오른쪽을 밀어 조건을 만족시키고 왼쪽을 당겨 줄인다.
- 자료구조: 배열과 정수 셋. `brute`는 모든 시작점에서 끝점을 늘려 보는 $O(n^2)$이다. 생성기는 $n \le 5$, 값 $1 \sim 3$, $S \le 10$으로 두어 **답이 없는 경우를 자주 만든다.**

**3. 백준 10971 외판원 순회 2 (실버 2)** — https://www.acmicpc.net/problem/10971
- 신호: $N \le 10$이라 완전탐색이 정답이다. **`brute`와 `fast`가 같은 것을 보는 문제**이므로 하네스의 대상은 "가지치기를 넣은 판"이 된다.
- 상태: 방문 집합과 현재 도시. 가지치기를 넣으면 "지금까지의 비용이 이미 최선보다 크면 중단"이 붙는다.
- 자료구조: 인접 행렬. `brute`는 가지치기 없는 순열 전탐색, `fast`는 가지치기를 넣은 판이다. **가지치기 조건을 잘못 쓰면 답이 줄어든다 — 그것이 이 하네스가 잡을 버그다.** [III-4 백트래킹과 가지치기](#/iii-4).

**4. 하네스 과제.** [0-11](#/0-11)의 `lower_bound`를 검증하는 하네스를 짜라. `gen`은 정렬된 배열과 찾을 값 `x`를 만들고, `brute`는 앞에서부터 훑어 `a[i] >= x`인 첫 인덱스를 찾는다. `fast`는 이분 탐색이다. 그다음 `fast`의 `lo = mid + 1`을 `lo = mid`로 바꾸면 하네스는 어떻게 되는가.

::: answer
`brute`는 세 줄이다. `for i in range(len(a)): if a[i] >= x: return i` 그리고 못 찾으면 `len(a)`를 돌려준다. **이 함수는 정의 그 자체이므로 틀릴 수 없다.**

`gen`은 `n`을 0~6, 값을 0~3에서 뽑아 정렬하고, `x`도 0~4에서 뽑는다. `n = 0`을 포함시키는 것이 중요하다 — §6 체크리스트의 첫 줄이다. `x`가 모든 원소보다 큰 경우도 자주 나와야 하므로 `x`의 범위를 값의 범위보다 한 칸 넓게 잡는다.

**`lo = mid`로 바꾸면 하네스는 멈추지 않는다.** 정답을 틀리는 것이 아니라 무한 루프에 빠지기 때문이다. `mid`가 `lo`와 같아지는 순간 `lo = mid`는 아무것도 바꾸지 않는다([0-11 §3](#/0-11)).

여기서 하네스의 성질 하나가 드러난다. ==대조 검증은 "답이 다르다"를 잡지 "끝나지 않는다"를 잡지 못한다.== 실패가 응답 없음으로 나타난다면 그것도 정보이긴 하지만, 어느 입력에서 멈췄는지를 알려면 회차와 입력을 매번 출력하거나 시간 제한을 걸어야 한다.

대응은 둘이다. 하네스에 **반복 횟수 상한**을 넣어 초과하면 실패로 판정하거나(측도가 줄지 않았다는 뜻이므로 정당한 판정이다), 애초에 이 종류는 [0-11](#/0-11)의 손추적이 표 다섯 줄에서 잡는다. **두 도구는 겹치지 않고 보완한다.**
:::

## 요약

- 반례를 상상하지 말고 **만들어 내라.** 대부분의 문제에는 틀릴 수 없는 완전탐색 풀이가 있고, 그것과 대조하면 반례 찾기가 자동화된다.
- 하네스는 네 조각이다. `gen` / `brute` / `fast` / 비교 루프. **문제가 바뀌어도 구조는 그대로**이고 셋만 갈아 끼운다.
- 생성기 설계가 절반이다. **작게**(원소 6개 이하, 반례를 눈으로 읽을 수 있게), **값 범위를 좁게**(중복과 동점이 생기게).
- 축소가 나머지 절반이다. 실패를 유지하며 한 번에 한 곳씩 깎는다. 측도가 단조 감소하므로 반드시 끝난다.
- 실제로 이 하네스는 투 포인터의 중복 처리 버그를 **5회차에** 잡았고, 최소 반례는 `a = [0, 0, 0]`, `x = 0`이었다. 값이 전부 다른 입력으로는 절대 나오지 않는 버그다.
- 20만 회 완주가 Python 0.96초, C++ 0.029초다. **하네스를 짜는 3분이 반례를 고민하는 10분보다 거의 언제나 싸다.**
- 못 잡는 것 셋: 큰 입력에서만 나는 문제(오버플로·TLE), `brute`도 같이 틀린 경우(문제 오독), 생성기가 못 만드는 입력. **정확성과 성능은 다른 검사다.**
