# 0-1 이 책 읽는 법

::: lead
이 책을 어느 순서로, 어떤 속도로, 무엇을 손으로 하면서 읽을 것인가.
:::

## 1. 문제

알고리즘 자료를 끝까지 읽고도 문제 앞에서 멈추는 일이 흔하다. BFS 설명을 읽으면 전부 이해된다. 큐를 쓰고, 방문 배열을 두고, 거리가 1씩 늘어난다. 그런데 새 문제를 받으면 두 가지 중 하나가 일어난다. **이게 BFS 문제인지 모르거나, BFS인 줄 알면서도 못 짠다.**

두 실패는 원인이 다르고 처방도 다르다.

- **알아보지 못한다.** 지식이 아니라 **매핑**의 문제다. 머릿속에 알고리즘은 있는데 지문에서 그 알고리즘으로 가는 길이 없다. 이 책이 Part I을 자료구조보다 앞에 둔 이유다.
- **알면서 못 짠다.** 읽을 때는 코드가 상태를 대신 들고 있었고, 짤 때는 그 상태를 머리가 들어야 한다. 실행 모델이 없는 것이다. 이 책이 코드보다 손추적을 먼저 요구하는 이유다.

여기에 세 번째 실패가 겹친다. **한 달 뒤에 사라진다.** 알고리즘은 안 쓰면 즉시 휘발한다. 그리고 휘발하는 것은 "BFS가 무엇인가"가 아니라 "이 지문이 BFS인가"다. 정의는 남고 판별이 먼저 죽는다.

이 책의 구조는 이 세 실패를 각각 겨냥한다. 그래서 **읽는 방식이 결과를 바꾼다.** 처음부터 순서대로 읽는 것은 대개 최선이 아니다.

## 2. 세 가지 경로

목적이 다르면 읽는 순서가 다르다. 세 경로 중 하나를 고르고, 고른 경로를 끝까지 유지하라.

### 2.1 코테 급행

**목표가 정해진 기간 안에 코딩테스트를 통과하는 것일 때.** 실무 파트를 전부 건너뛴다.

```text nolines
   Part 0  ->  Part I  ->  II  ->  III  ->  IV  ->  VII  ->  VI  ->  VIII  ->  V(1-4)  ->  IX  ->  X
     |          |                                                      |
     |          |                                                      +-- 다익스트라까지만. A* 이후는 나중에
     |          +-- 여기가 병목이다. 건너뛰지 마라
     +-- 전부 읽지 말고 §3.1 의 최소 세트만
```

순서에 두 가지 결정이 들어 있다.

**이분 탐색(VII)이 그리디(VI)보다 앞이다.** 이분 탐색은 판별이 기계적이다. "N이 10억인데 답이 수 하나"면 거의 확정이고, 매개변수 탐색은 신호어가 뚜렷하다. 반면 그리디는 **성립 조건을 증명해야** 하고, 성립하지 않는 경우가 DP다. 판별이 쉬운 것부터 채우는 편이 초반 정답률을 빨리 올린다.

**최단경로는 V-4까지만 간다.** 다익스트라·벨만포드·플로이드워셜은 코딩테스트 범위이고, A\* 이후는 아니다. 다만 [V-4 DP와 최단경로는 같은 것이다](#/v-4)는 건너뛰지 마라. DP와 그래프를 한 덩어리로 붙이는 챕터라 VIII의 이해가 여기서 달라진다.

### 2.2 실무 급행

**목표가 시스템을 설계하고 기술 면접에서 설명하는 것일 때.** 문제 풀이 훈련을 줄이고 구조로 간다.

```text nolines
   Part 0(축약)  ->  II  ->  IV  ->  XII  ->  XI  ->  XV  ->  V(5-14)  ->  IX  ->  XIV
                     |               |         |      |        |
                     |               |         |      |        +-- 경로계획 계보
                     |               |         |      +-- B-Tree, LSM, 블룸 필터, 일관성 해싱
                     |               |         +-- 링버퍼, 락, 스케줄링, 상태 기계
                     |               +-- 설계 패턴. 알고리즘과 독립이라 언제 넣어도 된다
                     +-- 자료구조가 전제다. 트리와 해시 없이 XV 는 안 읽힌다
```

[Part XV 시스템 규모의 자료구조](#/xv-1)를 Part II 앞에 두려는 유혹이 있다. B-Tree가 더 재미있어 보이기 때문이다. 하지만 B-Tree는 **이진 탐색 트리의 높이를 낮춘 것**이고 LSM은 **정렬된 배열의 병합**이며 일관성 해싱은 **해시 테이블의 재배치 문제**다. 밑바닥 없이 읽으면 이름만 남는다. 이 책이 존재하는 이유가 바로 그 연결이므로, 순서를 뒤집으면 책의 값어치가 사라진다.

### 2.3 완주

**목표가 둘 다일 때.** 목차 순서를 그대로 따르되, 두 지점에서만 예외를 둔다.

- **Part 0은 통독하지 않는다.** 필요할 때 돌아오는 레퍼런스다(§3.1).
- **Part XII(설계 패턴)는 아무 때나 끼워 넣는다.** 알고리즘 학습과 독립적이라 진도가 막힐 때 기분 전환으로 읽어도 손해가 없다.

::: tip
경로를 고르는 기준은 흥미가 아니라 **마감**이다. 마감이 있으면 코테 급행, 없으면 완주다. 마감이 있는데 완주를 고르면 절반에서 멈추고, 그 절반은 시험 범위와 겹치지 않는 쪽일 확률이 높다.
:::

## 3. 이 책의 장치들

### 3.1 Part 0은 사전이다

[Part 0](#/0-2)은 처음부터 끝까지 읽는 곳이 아니다. 알고리즘을 짜다가 막힌 자리에서 돌아오는 곳이다. 다만 **시작 전에 반드시 읽어야 하는 최소 세트**가 있다.

| 먼저 | 이유 |
|---|---|
| [0-9 N 범위로 알고리즘 역산하기](#/0-9) | 이걸 모르면 유형 판별이 시작되지 않는다. 제약조건이 후보를 절반으로 줄인다 |
| [0-11 손추적 방법론](#/0-11) | 이 책의 모든 `::: trace` 상자가 이 절차를 전제한다 |
| 쓰는 언어 쪽 입출력 한 챕터 | Python이면 [0-2](#/0-2), C++이면 [0-5](#/0-5). 입출력이 막히면 아무것도 제출할 수 없다 |

나머지는 본문에서 처음 만났을 때 배운다. 표준 라이브러리 함수가 본문에 처음 나오면 그 자리에 정의가 붙는다.

```text nolines
   📖 heapq.heappush(heap, item)      <- 시그니처
      최소 힙에 원소 삽입. O(log n).   <- 의미와 비용
      쓰는 곳: 다익스트라(V-1)         <- 어디서 만나는가
      C++ 대응: std::priority_queue    <- 반대 언어
```

이 상자를 만나면 진도를 멈출 필요가 없다. **더 깊이 파고 싶을 때만** Part 0의 해당 챕터로 간다. `sort()`가 안정 정렬이라는 사실은 본문에서 배우고, Timsort가 런을 어떻게 병합하는지는 [0-4](#/0-4)에 있다.

### 3.2 두 언어를 동시에 본다

모든 구현은 `::: dual` 상자 안에서 Python과 C++ 탭으로 나뉜다. 두 코드는 **같은 알고리즘, 같은 변수명, 같은 줄 구조**다. 상단의 언어 토글로 한쪽만 보이게 할 수 있고, 기본값은 둘 다다.

한쪽만 쓸 계획이어도 **반대쪽 탭을 닫지 마라.** 두 언어를 나란히 두는 목적은 두 언어를 배우는 것이 아니라 **알고리즘과 언어를 분리해서 보는 것**이다. 같은 줄이 두 언어에서 다르게 생겼을 때, 다른 부분이 언어이고 같은 부분이 알고리즘이다.

가장 위험한 것은 "비슷해 보이는데 다른 것"이다. 코드 아래 **언어 차이 표**가 붙는 지점이 정확히 거기다.

| 항목 | Python | C++ |
|---|---|---|
| 힙 기본 방향 | `heapq`는 최소 힙 고정 | `priority_queue`는 최대 힙 기본 |
| 정수 오버플로 | 없다 | `int`는 넘친다 |
| 나눗셈 | `//`는 내림 | `/`는 0 방향 절삭 |
| 정렬 안정성 | `sort()` 안정 | `std::sort` 불안정 |

네 줄 전부 **부호가 반대**다. 언어를 오갈 때 무너지는 것은 지식이 아니라 습관이다.

### 3.3 손추적이 코드보다 먼저다

모든 알고리즘 챕터는 **문제 → 아이디어 → 구현** 순서다. 그리고 아이디어와 구현 사이에 `::: trace` 상자가 있다. 입력과 상태 표의 앞 두세 행만 채워져 있고, 나머지는 빈칸이다.

**빈칸을 채우고 나서 코드를 봐라.** 순서를 지키지 않으면 이 책은 다른 자료와 같아진다.

이유는 §1의 두 번째 실패에 있다. 코드를 먼저 보면 그 코드가 상태를 대신 들어 준다. 읽으면 이해되고, 이해됐다고 느끼고, 빈 화면 앞에서 멈춘다. 표를 먼저 채우면 상태를 **당신이** 들게 된다. 그 상태가 곧 실행 모델이고, 실행 모델이 있어야 짤 수 있다.

::: warn
"표를 채우는 게 귀찮으니 눈으로 따라가겠다"는 선택지가 늘 있다. 눈으로 따라가는 것과 손으로 쓰는 것의 차이는 **틀렸을 때 드러나느냐**다. 머릿속에서는 `lo`가 슬쩍 맞는 값으로 바뀌어 있어도 아무도 모른다. 종이 위에서는 그 줄이 남는다.

비용도 싸다. 이분 탐색은 원소 여섯 개면 세 스텝이다. 표 세 줄이 열 번의 제출을 대체한다.
:::

### 3.4 손으로 짜는 원칙

손추적이 종이 위의 규율이라면, 손으로 짜는 것은 키보드 위의 규율이다. 셋으로 압축된다.

**첫째, 복사하지 않는다.** 이 책의 `::: dual` 상자에는 복사 버튼이 있다. 실행해서 출력을 확인하는 용도지 제출용이 아니다. 같은 코드를 처음부터 타이핑하면 세미콜론과 인덱스와 초기값을 전부 한 번씩 결정하게 되고, **결정한 것만 기억에 남는다.** 복사한 코드는 읽은 코드이지 짠 코드가 아니다.

**둘째, 실행 전에 예상 출력을 적는다.** 돌리기 전에 "이 입력이면 3이 나온다"를 먼저 적어 두라. 맞으면 실행 모델이 맞은 것이고, 틀리면 **모델과 코드 중 어느 쪽이 틀렸는지**를 그 자리에서 알 수 있다. 적어 두지 않고 돌리면 출력이 무엇이든 "아 그렇구나"가 되어 아무것도 검증되지 않는다.

**셋째, 통과한 뒤에 한 번 더 짠다.** 정답을 맞힌 문제를 다음 날 빈 화면에서 다시 짜 보는 것이 이 책이 요구하는 유일한 반복 훈련이다. 두 번째 구현은 대개 절반의 시간이 걸리고, 그 차이가 곧 첫 번째에서 **찾느라** 쓴 시간이다.

::: note
"타이핑은 시간 낭비 아닌가"라는 반문이 나온다. 목표가 코드를 얻는 것이라면 맞다. 목표가 **다음에 빈 화면 앞에서 짜는 것**이라면 정반대다. 복사한 코드가 통과한 순간 얻은 것은 채점 결과 한 줄이고, 타이핑한 코드가 통과한 순간 얻은 것은 결정 스무 개다.
:::

### 3.5 정답 코드는 싣지 않는다

각 챕터의 `::: quiz`에는 대표문제 3~5개가 번호·제목·난도로 실린다. **정답 코드는 없다.** 대신 세 가지가 있다.

1. 어떤 신호로 이 유형임을 알아채는가
2. 상태를 무엇으로 정의하는가
3. 왜 이 자료구조인가

목적이 사고과정의 이식이지 코드 암기가 아니기 때문이다. 답이 보이는 순간 사고과정은 죽는다. 코드가 있으면 읽고 넘어가게 되고, 읽고 넘어간 것은 남지 않는다.

### 3.6 유형 판별 상자는 역방향 색인이다

알고리즘 챕터 끝의 `::: classify` 상자는 그 알고리즘을 **거꾸로** 찾는 장치다.

```text nolines
   ::: classify
   - 신호어:      "최소 이동 횟수", "몇 번 만에"
   - 제약조건:    간선 가중치가 전부 1, 정점 <= 10^5
   - 혼동 주의:   가중치가 다르면 -> 다익스트라(V-1)
   - 반례 함정:   시작점이 여러 개면 다중 시작 BFS(IV-4)
   :::
```

챕터를 정방향으로 읽으면 "BFS는 이렇게 동작한다"이고, 이 상자를 역방향으로 읽으면 "이런 지문이면 BFS다"이다. **후자가 실전에서 필요한 방향이다.** 이 상자들은 자동으로 수집되어 [Part I](#/i-1)의 결정 트리 부록과 플래시카드 덱이 된다.

## 4. 복습을 설계에 넣는다

### 4.1 무엇이 휘발하는가

§1의 세 번째 실패로 돌아온다. 한 달 뒤에 남는 것과 사라지는 것은 정해져 있다.

| 남는 것 | 사라지는 것 |
|---|---|
| "BFS는 큐를 쓴다" | "이 지문이 BFS다" |
| "DP는 점화식을 세운다" | "이 문제의 상태를 무엇으로 잡는가" |
| "세그먼트 트리는 구간 쿼리용" | "누적 합으로 될 일인지 세그먼트 트리가 필요한 일인지" |

왼쪽은 한 문장이라 안 잊는다. 오른쪽은 **판단**이라서 반복하지 않으면 죽는다. 그래서 이 책의 복습 큐는 챕터 단위가 아니라 **`::: classify`와 `::: quiz` 항목 단위**로 스케줄링한다. "0-4를 읽었다"를 복습하는 것은 의미가 없고, "이 제약조건을 보고 어떤 알고리즘을 떠올렸는가"를 복습하는 것이 의미가 있다.

### 4.2 복습 큐 쓰는 법

앱 홈에 **"오늘 복습할 N개"** 진입점이 있다. 항목 하나가 뜨면 앞면은 지문 요약과 제약조건이고, 답을 떠올린 뒤 뒤집으면 알고리즘 이름과 근거 한 줄이 나온다. 그리고 네 단계로 평가한다.

| 평가 | 뜻 | 다음 등장 |
|---|---|---|
| 모름 | 답을 못 떠올렸다 | 오늘 다시 |
| 어려움 | 떠올렸지만 오래 걸렸다 | 간격이 줄어든다 |
| 보통 | 떠올렸다 | 간격이 늘어난다 |
| 쉬움 | 즉시 떠올렸다 | 간격이 크게 늘어난다 |

간격은 SM-2 알고리즘으로 정해진다. 맞힐수록 간격이 배수로 늘고, 틀리면 처음으로 돌아간다. 상태는 브라우저의 `localStorage`에 저장되므로 서버도 계정도 필요 없다. 대신 **브라우저를 지우면 진도도 지워진다.**

::: danger
평가를 정직하게 하지 않으면 복습 큐는 즉시 무용지물이 된다. "쉬움"을 남발하면 간격이 폭발적으로 늘어 정작 필요한 항목이 몇 달 뒤로 밀린다.

기준은 하나다. **답이 즉시 떠올랐는가.** 뒷면을 보고 "아 맞다"라고 생각했다면 그것은 "모름"이다. 재인(recognition)과 회상(recall)은 다른 능력이고, 시험장에서 필요한 것은 회상이다.
:::

### 4.3 폰에서 읽기

`build.py --single`이 만드는 `algobook.html` 한 파일에 본문·위젯·검색이 전부 들어 있다. 외부 의존성이 0이라 파일 하나만 옮기면 오프라인에서 그대로 돈다. 위젯도 살아 있다.

`::: classify` 상자는 Anki용 CSV로도 나간다(`dist/anki/`). 이동 중 복습은 이쪽이 편하다. 다만 **덱을 두 벌 굴리지 마라.** 앱의 복습 큐와 Anki 중 하나만 쓴다. 두 곳에 진도가 갈라지면 어느 쪽도 믿을 수 없게 된다.

## 5. 진도가 막혔을 때

막히는 지점은 대개 정해져 있고, 처방도 정해져 있다.

**"지문을 읽어도 무슨 유형인지 모르겠다."** 정상이고, 그것이 병목이다. [I-2 제약조건 역산법](#/i-2)으로 가서 지문보다 N을 먼저 읽는 습관부터 들여라. N이 10만이면 $O(n^2)$은 이미 탈락이고 후보가 절반으로 준다.

**"유형은 알겠는데 코드가 안 나온다."** 코드를 더 읽어도 나아지지 않는다. [0-11 손추적 방법론](#/0-11)의 표를 그려라. 짜지 못하는 이유는 대개 상태 정의가 안 끝났기 때문이고, 표를 그리면 무엇이 안 정해졌는지가 드러난다.

**"짰는데 틀렸다는데 어디가 틀렸는지 모르겠다."** [0-12 디버깅과 반례 찾기](#/0-12)의 브루트포스 대조와 랜덤 스트레스 테스트로 간다. 눈으로 코드를 다시 읽는 것은 가장 비효율적인 방법이다.

**"맞았는데 시간 초과다."** 알고리즘이 틀린 것과 상수가 큰 것은 다른 문제다. [0-9](#/0-9)로 복잡도를 먼저 역산해 보고, 복잡도가 맞는데 느리면 [0-10 언어별 상수와 TLE 대응](#/0-10)이다.

::: note
한 문제에 쓰는 시간의 상한을 정해 두는 편이 낫다. 30분 넘게 막히면 답을 보는 것이 아니라 **유형만 확인하고 다시 덮는다.** 유형을 알고도 못 짜는 것과 유형을 몰라서 못 짜는 것은 다른 훈련이 필요하고, 무엇이 막힌 것인지 모른 채 두 시간을 쓰면 둘 다 훈련되지 않는다.
:::

## 요약

- 알고리즘 학습의 실패는 셋으로 나뉜다. **알아보지 못한다**(매핑), **알면서 못 짠다**(실행 모델), **한 달 뒤 사라진다**(휘발). 이 책의 구조는 각각을 겨냥한다.
- 경로는 셋이다. **코테 급행**은 실무 파트를 버리고 판별→기초→탐색→이분탐색→DP로, **실무 급행**은 자료구조 위에서 패턴·동시성·시스템 규모로, **완주**는 목차 순서다. 기준은 흥미가 아니라 마감이다.
- **Part 0은 통독하지 않는다.** [0-9](#/0-9), [0-11](#/0-11), 쓰는 언어의 입출력 한 챕터만 먼저 읽고 나머지는 막혔을 때 돌아온다.
- **`::: trace`를 채우고 나서 코드를 봐라.** 순서를 뒤집으면 코드가 상태를 대신 들어 주고, "읽으면 이해되는데 못 짜는" 상태가 그대로 재생산된다.
- `::: dual`의 반대 언어 탭을 닫지 마라. **다른 부분이 언어이고 같은 부분이 알고리즘이다.** 언어 차이 표는 부호가 반대인 지점만 모아 둔 것이다.
- 휘발하는 것은 정의가 아니라 **판단**이다. 그래서 복습 큐는 챕터가 아니라 `::: classify` 항목 단위로 돈다. 평가는 정직하게 하고, 재인은 회상이 아니다.
- 막혔을 때의 처방은 정해져 있다. 유형을 모르면 [I-2](#/i-2), 못 짜면 [0-11](#/0-11), 틀렸으면 [0-12](#/0-12), 느리면 [0-9](#/0-9)와 [0-10](#/0-10)이다.
