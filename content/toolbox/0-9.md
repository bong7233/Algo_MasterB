# 0-9 N 범위로 알고리즘 역산하기

::: lead
지문을 다 읽기 전에, 제약조건만 보고 "무엇을 짜면 안 되는지"를 먼저 확정하는 절차.
:::

## 1. 문제

지문에 이렇게 적혀 있다.

```text nolines
  N (1 <= N <= 100,000)
  시간 제한: 1초
  메모리 제한: 256MB
```

이중 루프를 짜면 $10^{10}$번이다. 이 코드는 짜기 전에 이미 죽어 있다. 그런데 제출해 봐야 그 사실을 안다면, 문제 하나에 20분을 쓰고 얻는 정보가 "틀렸다" 한 줄이다.

이 상황이 반복되는 이유는 순서가 뒤집혀 있어서다. 지문 → 아이디어 → 구현 → 제출 → 시간 초과 → 다시 아이디어. 되돌아오는 화살표가 20분짜리다.

바꿀 수 있다. **제약조건은 답의 절반을 이미 말하고 있다.** 위 조건에서 $O(n^2)$은 불가능하고 $O(n \log n)$과 $O(n)$은 가능하다. 후보가 둘로 줄어든 상태에서 지문을 읽는 것과, 아무 제약 없이 읽는 것은 다른 작업이다. 이 챕터는 그 계산을 정확히 하는 법을 다룬다.

정확히 하려면 먼저 알려진 어림 하나를 해체해야 한다.

## 2. "1초 ≈ 10^8 연산"의 실체

이 어림은 널리 통용되고, 널리 틀린다. 문제는 "연산"이라는 단어다. 정수 덧셈 한 번과 해시 테이블 조회 한 번을 같은 단위로 세면 자릿수가 어긋난다.

그래서 산술 명령 하나가 아니라 **알고리즘의 안쪽 루프 한 바퀴**를 쟀다. 배열을 순서대로 읽는 루프, 무작위 위치를 읽는 루프, 해시 조회 루프, DP 갱신 루프, 함수 호출 루프다. 전부 "한 바퀴 = 연산 1회"로 맞췄다.

::: perf
| 안쪽 루프 한 바퀴 | Python 3.13 | 초당 | g++ 13 `-O2` | 초당 |
|---|---|---|---|---|
| 연속 접근 `s += a[i]` | 59.4 ns | $1.7 \times 10^7$ | 1.23 ns | $8.1 \times 10^8$ |
| 무작위 접근 `s += a[idx[i]]` | 507.0 ns | $2.0 \times 10^6$ | 15.74 ns | $6.4 \times 10^7$ |
| 해시 조회 `d[k]` (100만 키) | 507.0 ns | $2.0 \times 10^6$ | 135.70 ns | $7.4 \times 10^6$ |
| DP 갱신 `dp[j] = max(...)` | 137.0 ns | $7.3 \times 10^6$ | 1.29 ns | $7.8 \times 10^8$ |
| 함수 호출 `f(x)` | 72.7 ns | $1.4 \times 10^7$ | 1.55 ns | $6.5 \times 10^8$ |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/ops_budget.py` 와 `.cpp` 다.)
:::

한 언어 안에서만 봐도 **위아래가 100배 넘게 벌어진다.** C++에서 가장 빠른 루프는 초당 8억 바퀴이고 가장 느린 루프는 초당 740만 바퀴다. 같은 "연산 1회"인데 110배 차이다.

$10^8$이라는 숫자가 어디서 나왔는지도 이 표에서 읽힌다. **C++의 무작위 접근 루프($6.4 \times 10^7$)에 우연히 가깝다.** 그래서 C++로 그래프나 트리처럼 포인터를 따라다니는 코드를 짤 때는 이 어림이 그럭저럭 맞고, 연속 배열을 훑는 코드에서는 열 배 비관적이며, Python에서는 **어떤 워크로드에서도 맞지 않는다.**

::: warn
$10^8$을 버리라는 말이 아니다. 자릿수 감각의 출발점으로는 쓸 만하다. 버려야 할 것은 그 숫자를 **정밀한 경계선으로 취급하는 습관**이다. $9 \times 10^7$이라 안전하고 $1.1 \times 10^8$이라 위험하다는 판단에는 근거가 없다. 이 표의 폭이 그 근거 없음의 크기다.
:::

::: deep
표에서 가장 이상해 보이는 줄은 해시 조회다. C++이 Python보다 3.7배밖에 빠르지 않다. 이유는 두 가지가 겹쳐서다.

첫째, 100만 개 키에 무작위로 접근하면 버킷 배열과 노드가 각각 캐시 밖에 있다. **한 번의 조회가 캐시 미스 두 번**이고, 캐시 미스 한 번이 수십 나노초다. 언어가 아니라 메모리가 비용을 정한다.

둘째, Python의 `dict`는 CPython의 C 코드다. 인터프리터는 "조회하라"는 명령 하나를 발행하고 실제 일은 C가 한다. ==Python이 느린 것은 인터프리터 루프이지 표준 라이브러리가 아니다.== 그래서 루프를 라이브러리 안으로 밀어 넣을수록 두 언어의 배수가 줄어든다. 이 성질은 [0-10 언어별 상수와 TLE 대응](#/0-10)의 중심 주제다.

같은 이유로 정렬도 배수가 작다. $n = 10^6$ 정렬은 Python 0.369초, C++ 0.077초로 4.8배다. 반대로 DP 갱신 루프는 106배다 — 여기는 인터프리터가 전부 직접 돈다.
:::

::: danger
C++에서 직접 벤치마크를 짤 때 흔히 나오는 결과가 있다.

```text nolines
  s += i 를 10^9 회: 0.000000s
```

`-O2`가 이 루프를 닫힌 형태로 접어 통째로 지웠다. 실측했는데 0초가 나왔다면 측정에 성공한 것이 아니라 **측정 대상이 사라진 것이다.** 누산 결과를 반드시 출력에 쓰거나, 컴파일러가 예측할 수 없는 데이터에 의존하게 만들어라. `tools/bench/ops_budget.cpp`가 결과를 전부 `g_sink`에 모아 마지막에 쓰는 이유다.
:::

## 3. 역산 표

앞의 단가로 "1초에 이 복잡도면 N이 얼마까지 되는가"를 푼다. 단가를 하나로 정할 수 없으므로 **두 개**를 쓴다. 연속 접근을 최선, 무작위 접근을 최악으로 놓고 구간을 낸다. 실제 코드는 대개 그 사이 어딘가에 있다.

::: perf
| 복잡도 | Python 최선 | Python 최악 | C++ 최선 | C++ 최악 |
|---|---|---|---|---|
| $O(n)$ | $1.7 \times 10^7$ | $2.0 \times 10^6$ | $8.1 \times 10^8$ | $6.4 \times 10^7$ |
| $O(n \log n)$ | 854,000 | 117,000 | $3.2 \times 10^7$ | $3.0 \times 10^6$ |
| $O(n^2)$ | 4,100 | 1,400 | 28,000 | 8,000 |
| $O(n^3)$ | 256 | 125 | 932 | 399 |
| $O(2^n)$ | 24 | 20 | 29 | 25 |
| $O(n!)$ | 10 | 9 | 12 | 11 |

> (같은 환경 실측에서 유도. `tools/bench/ops_budget.py` 가 측정한 단가로 이분 탐색해 최대 N을 역산한다.)
:::

이 표는 거꾸로 읽는 것이 본래 용도다. **N이 주어졌을 때 무엇이 허용되는가.**

| N의 크기 | 허용되는 복잡도 | 떠올릴 것 |
|---|---|---|
| $n \le 11$ | $O(n!)$ | 순열 전탐색([III-2](#/iii-2)) |
| $n \le 22$ | $O(2^n)$, $O(2^n \cdot n)$ | 부분집합 전탐색, 비트마스크 DP([VIII-9](#/viii-9)) |
| $n \le 400$ | $O(n^3)$ | 플로이드-워셜([V-3](#/v-3)), 구간 DP([VIII-7](#/viii-7)) |
| $n \le 5{,}000$ | $O(n^2)$ | 2차원 DP([VIII-4](#/viii-4)), $O(n^2)$ LIS |
| $n \le 10^5$ | $O(n \log n)$ | 정렬, 이분 탐색([VII-1](#/vii-1)), 세그먼트 트리([IX-2](#/ix-2)), 다익스트라([V-1](#/v-1)) |
| $n \le 10^6$ | $O(n)$, $O(n \log \log n)$ | 투 포인터([VI-3](#/vi-3)), 누적 합([VI-4](#/vi-4)), BFS([IV-3](#/iv-3)), 에라토스테네스([X-2](#/x-2)) |
| $n \ge 10^7$ | $O(n)$이되 입출력이 병목 | 읽는 방법부터 바꾼다([0-10](#/0-10)) |

경계값을 외울 필요는 없다. 외울 것은 **자릿수의 계단**이다. $n^2$이 $10^8$을 넘지 않으려면 $n$이 만 언저리이고, $n^3$이면 수백이고, $2^n$이면 스물 몇이다. 이 셋만 있으면 나머지는 그 자리에서 나온다.

::: tip
표에 없는 두 줄이 실전에서 자주 나온다.

**$O(n \sqrt{n})$** — $n = 10^5$에서 $3.2 \times 10^7$이다. C++이면 넉넉하고 Python이면 아슬아슬하다. 소인수분해([X-2](#/x-2))와 평방분할이 여기 있다.

**$O(n \cdot m)$** — 격자 문제의 기본형이다. $1000 \times 1000$이면 $10^6$이라 어느 언어든 통과하고, $2000 \times 2000$이면 $4 \times 10^6$이라 Python에서 상수를 신경 써야 한다.
:::

::: widget complexity-plot {"n":1000000,"curves":["n","n log n","n^2","2^n"],"budget":100000000}
:::

위젯은 N을 밀어 가며 $O(n)$, $O(n \log n)$, $O(n^2)$, $O(2^n)$이 로그 축에서 벌어지는 모습과 "1초 안에 되는 선"이 어디를 지나는지를 보인다. 두 가지가 눈에 남는다. 첫째, $O(n)$과 $O(n \log n)$은 로그 축에서 거의 붙어 있다 — $n = 10^6$에서도 20배 차이일 뿐이다. 둘째, $O(n^2)$은 $n$이 만 근처에서 선을 뚫고 $O(2^n)$은 그보다 훨씬 왼쪽에서 이미 뚫려 있다. ==실전에서 갈리는 것은 대개 $O(n \log n)$과 $O(n^2)$ 사이 하나뿐이다.==

## 4. 손으로 따라가기

복잡도를 코드에서 세지 못할 때가 있다. 라이브러리를 부르고 있거나, 루프가 여러 겹이거나, 조기 종료가 섞여 있을 때다. 그때 쓰는 것이 **두 배 실험**이다. $n$을 두 배로 늘리며 시간을 재고 직전 대비 배수를 본다. $T(n) = c \cdot n^k$이면 $T(2n)/T(n) = 2^k$이므로 **지수는 배수의 로그로 바로 읽힌다.**

::: trace
아래 두 함수는 줄 수가 같고 하는 일도 "리스트에 원소를 하나씩 넣는다"로 같다. 코드를 읽지 말고 시간만으로 판정하라.

측정값(실측, `tools/bench/doubling_test.py`):

**A: 뒤에 붙이기**

| n | T(n) 초 | T(n)/T(n/2) | log2(배수) | 판정 |
|---|---|---|---|---|
| 50,000 | 0.0023 | — | — | (기준) |
| 100,000 | 0.0052 | 2.33 | 1.22 | $O(n)$ |
| 200,000 | 0.0114 |  |  |  |
| 400,000 | 0.0249 |  |  |  |

**B: 앞에 붙이기**

| n | T(n) 초 | T(n)/T(n/2) | log2(배수) | 판정 |
|---|---|---|---|---|
| 12,500 | 0.0213 | — | — | (기준) |
| 25,000 | 0.0807 | 3.78 | 1.92 | $O(n^2)$ |
| 50,000 | 0.3153 |  |  |  |
| 100,000 | 1.2692 |  |  |  |

빈칸을 채운 뒤 세 가지에 답하라.

- [ ] B의 $n = 100{,}000$은 A의 $n = 100{,}000$보다 몇 배 느린가
- [ ] B가 이 추세대로 $n = 10^6$까지 가면 몇 초인가
- [ ] A의 배수가 정확히 2가 아니라 2.2 근처인 이유는 무엇인가
:::

::: answer
| n | T(n) 초 | T(n)/T(n/2) | log2(배수) | 판정 |
|---|---|---|---|---|
| 50,000 | 0.0023 | — | — | (기준) |
| 100,000 | 0.0052 | 2.33 | 1.22 | $O(n)$ |
| 200,000 | 0.0114 | 2.18 | 1.12 | $O(n)$ |
| 400,000 | 0.0249 | 2.18 | 1.12 | $O(n)$ |

| n | T(n) 초 | T(n)/T(n/2) | log2(배수) | 판정 |
|---|---|---|---|---|
| 12,500 | 0.0213 | — | — | (기준) |
| 25,000 | 0.0807 | 3.78 | 1.92 | $O(n^2)$ |
| 50,000 | 0.3153 | 3.91 | 1.97 | $O(n^2)$ |
| 100,000 | 1.2692 | 4.03 | 2.01 | $O(n^2)$ |

A는 `list.append`, B는 `list.insert(0, x)`다. 앞에 넣으면 뒤의 원소를 전부 한 칸씩 밀어야 한다. 왜 그런지는 [0-3 Python 내장 자료구조의 실제 비용](#/0-3)에 있다.

**답 1.** 0.0052초 대 1.2692초로 244배다. 코드 한 줄 차이다.

**답 2.** $n$이 10배면 $n^2$은 100배이므로 약 127초다. 1초 제한 문제라면 127배 초과다. ==두 배 실험은 이 예측을 코드를 읽지 않고 30초 만에 준다.==

**답 3.** 측정에 고정 비용이 섞여 있다. 인터프리터 기동, 리스트 재할당, 첫 접근의 캐시 미스는 $n$에 비례하지 않는다. 그래서 작은 $n$일수록 배수가 2에서 위로 벗어난다. **배수의 절대값이 아니라 배수가 수렴하는 값을 봐야 한다.** A는 2.18로 수렴하고 B는 4.0으로 수렴한다.

여기에 이 방법의 한계가 있다. $O(n \log n)$의 이론 배수는 $2 + 2/\log_2 n$이고 $n = 10^6$에서 2.1이다. **$O(n)$의 2.18과 구분되지 않는다.** 실제로 같은 스크립트에서 `sort`를 재면 배수 2.03~2.15가 나와 $O(n)$으로 판정된다. 두 배 실험은 $O(n)$과 $O(n \log n)$을 가르지 못한다. 대신 ==$O(n)$과 $O(n^2)$은 한 번에 가른다.== 실전에서 필요한 것이 거의 항상 후자다.
:::

## 5. 구현

두 배 실험을 코드로 굳혀 두면 매번 손으로 잴 일이 없다.

::: dual
```python title="두 배 실험 하네스"
import math
import time

REPS = 3


def median(xs):
    return sorted(xs)[len(xs) // 2]


def run(name, fn, sizes):
    print(f"--- {name} ---")
    prev = None
    for n in sizes:
        ts = []
        for _ in range(REPS):          # 한 번만 재면 첫 실행의 캐시 미스가 섞인다
            t = time.perf_counter()
            fn(n)
            ts.append(time.perf_counter() - t)
        el = median(ts)
        if prev is None:
            print(f"n={n:>9} T={el:.4f}s  (기준)")
        else:
            r = el / prev
            k = math.log2(r)           # T(2n)/T(n) = 2^k 이므로 지수는 로그로 읽힌다
            print(f"n={n:>9} T={el:.4f}s  x{r:.2f}  k={k:.2f}")
        prev = el


def build_insert_front(n):
    a = []
    for i in range(n):
        a.insert(0, i)                 # 앞에 넣으면 뒤를 통째로 민다
    return len(a)


run("insert(0)", build_insert_front, [12500, 25000, 50000, 100000])
```
```cpp title="두 배 실험 하네스"
#include <algorithm>
#include <chrono>
#include <cmath>
#include <cstdio>
#include <initializer_list>
#include <vector>
using namespace std;

const int REPS = 3;

double median(double* v) {
    sort(v, v + REPS);
    return v[REPS / 2];
}

template <typename F>
void run(const char* name, F fn, vector<int> sizes) {
    printf("--- %s ---\n", name);
    double prev = -1;
    for (int n : sizes) {
        double ts[REPS];
        for (int r = 0; r < REPS; ++r) {   // 한 번만 재면 첫 실행의 캐시 미스가 섞인다
            auto t0 = chrono::steady_clock::now();
            fn(n);
            auto t1 = chrono::steady_clock::now();
            ts[r] = chrono::duration<double>(t1 - t0).count();
        }
        double el = median(ts);
        if (prev < 0) {
            printf("n=%9d T=%.4fs  (기준)\n", n, el);
        } else {
            double r = el / prev;
            double k = log2(r);           // T(2n)/T(n) = 2^k 이므로 지수는 로그로 읽힌다
            printf("n=%9d T=%.4fs  x%.2f  k=%.2f\n", n, el, r, k);
        }
        prev = el;
    }
}

long long build_insert_front(int n) {
    vector<int> a;
    for (int i = 0; i < n; ++i)
        a.insert(a.begin(), i);           // 앞에 넣으면 뒤를 통째로 민다
    return (long long)a.size();
}

int main() {
    run("insert(begin)", build_insert_front, {25000, 50000, 100000, 200000});
    return 0;
}
```
:::

**복잡도:** 하네스 자체는 시간 $O(\sum_i T(n_i))$ — 마지막 크기가 전체를 지배하므로 사실상 $O(T(n_{\max}))$이고, 크기를 두 배씩 키우면 그 앞의 항 전부를 합쳐도 마지막 항 하나를 넘지 않는다. 공간은 측정 대상이 쓰는 만큼 — 하네스가 따로 잡는 것은 시간 배열 `REPS`개뿐이라 $O(1)$이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 고해상도 시계 | `time.perf_counter()` — 단조 증가, 초 단위 `float` | `chrono::steady_clock` — 단조 증가. `system_clock`은 시각 보정 때 뒤로 갈 수 있다 |
| 앞쪽 삽입 | `list.insert(0, x)` | `vector::insert(begin(), x)` — 둘 다 $O(n)$ |
| 로그 | `math.log2` | `std::log2` (`<cmath>`) |
| 측정 대상 소거 | 인터프리터는 루프를 지우지 않는다 | `-O2`가 결과를 안 쓰는 루프를 통째로 지운다. 반환값을 반드시 소비하라 |
| 시작 크기 | 12,500부터 | 25,000부터 — 같은 크기에서 5밀리초를 밑돌아 시계 오차가 결과를 지배한다. **아래 `::: pitfall`의 세 번째 항목이 그대로 적용된 결과다** |

::: pitfall
- **한 번만 잰다.** 첫 실행은 캐시가 차갑고 페이지 폴트가 섞인다. 3회 중앙값이 최소선이다.
- **크기를 두 배가 아니라 조금씩 늘린다.** 1000, 1200, 1400으로는 배수가 흐려 지수가 안 나온다. 반드시 두 배씩이다.
- **너무 작은 n에서 시작한다.** $T(n)$이 밀리초 미만이면 시계 오차와 고정 비용이 결과를 지배한다. 기준 크기는 최소 10밀리초가 나오는 지점으로 잡는다.
- **최악 입력이 아닌 것으로 잰다.** 퀵 정렬을 이미 정렬된 배열로 재면 $O(n^2)$을 놓친다. 복잡도는 최악 입력에서 정의된다.
- **메모리를 안 본다.** 시간이 남아도 메모리 제한에서 죽는다. $n = 10^6$짜리 `int` 배열은 C++에서 4MB지만 Python `list`는 원소마다 포인터 8바이트에 정수 객체가 따로 붙어 30MB를 넘는다. [0-3](#/0-3)에 있다.
:::

## 6. 어림이 깨지는 다섯 자리

역산은 상한을 준다. 상한이 안전을 뜻하지는 않는다. **같은 복잡도인데 통과와 초과가 갈리는 자리**가 다섯 군데 있다.

**첫째, 메모리 접근 패턴.** §2의 표가 그대로 답이다. 연속 접근과 무작위 접근은 같은 $O(n)$인데 Python에서 8.5배, C++에서 13배 차이가 난다. 인접 리스트를 따라가는 그래프 탐색은 무작위 접근 쪽이고, 배열을 훑는 누적 합은 연속 접근 쪽이다. **$O(n)$이라고 다 같은 $O(n)$이 아니다.**

**둘째, 숨은 상수가 큰 자료구조.** 세그먼트 트리의 구간 질의는 $O(\log n)$이지만 한 번에 노드 $2\log n$개를 만지고 포인터를 따라간다. 같은 문제를 누적 합으로 풀 수 있으면 $O(1)$이고 상수도 작다. ==갱신이 없으면 세그먼트 트리를 쓸 이유가 없다.== 판단 기준은 [IX-2](#/ix-2)에 있다.

**셋째, 입출력.** $n \ge 10^6$이면 읽는 시간이 계산 시간을 넘긴다. Python에서 `input()`으로 정수 100만 개를 읽으면 1.181초로 그 자체가 시간 제한이고, `sys.stdin.readline`이면 0.305초다. 알고리즘을 바꾸기 전에 읽는 방법부터 본다. [0-10](#/0-10)에서 전부 잰다.

**넷째, 최악이 오지 않는 알고리즘.** 유니온 파인드의 상한은 역아커만 함수라 사실상 상수이고([IX-1](#/ix-1)), 가지치기가 잘 드는 백트래킹은 $O(2^n)$ 상한과 실제 탐색량이 자릿수로 다르다([III-4](#/iii-4)). 반대 방향도 있다 — 해시는 평균 $O(1)$이지만 키가 의도적으로 충돌하도록 만들어지면 $O(n)$으로 무너진다([II-6](#/ii-6)).

**다섯째, 제한이 시간이 아닌 경우.** 메모리 256MB에 $O(n^2)$ 테이블을 잡으면 $n = 10^4$에서 이미 `int` 기준 400MB다. 시간은 통과하는데 메모리에서 죽는다. **$O(n^2)$ 시간을 허용하는 N과 $O(n^2)$ 공간을 허용하는 N은 다르다.**

::: note
다섯 자리를 한 문장으로 줄이면 이렇다. **역산은 후보를 지우는 도구이지 확정하는 도구가 아니다.** $O(n^2)$을 지우는 데는 확실하고, 남은 $O(n \log n)$이 통과한다는 보장은 주지 않는다. 확정은 두 배 실험이나 실제 제출이 한다.
:::

## 7. 어디에 쓰이는가

**용량 산정이 같은 계산이다.** "초당 요청 5,000건을 받는 서비스에서 요청마다 이 처리를 해도 되는가"는 단가 곱하기 횟수가 예산 안에 들어오는지를 묻는 질문이고, 형태가 §3의 표와 같다. 다른 것은 예산이 1초가 아니라 SLO(응답 시간 목표)라는 것뿐이다. 요청당 20밀리초 예산에 $O(n^2)$ 정합 루프를 넣으면 $n$의 상한이 그 자리에서 나온다.

**제어 주기 예산도 그렇다.** 100Hz로 도는 루프는 한 바퀴에 10밀리초를 쓴다. 그 안에서 경로를 다시 계획해야 한다면 계획 알고리즘의 허용 복잡도가 10밀리초에서 역산된다. 전역 계획을 매 주기 다시 돌릴 수 없어 지역 계획을 따로 두는 구조([V-12](#/v-12))가 이 계산의 산물이고, 장애물이 하나 늘 때마다 전체를 다시 풀지 않는 증분 알고리즘([V-7](#/v-7))이 나온 이유도 같다.

**데이터 크기가 메모리를 넘는 순간의 판단도 역산이다.** 단가가 나노초에서 밀리초로 바뀌면 — 디스크 접근 한 번이 그렇다 — 같은 $O(\log n)$이라도 상수가 백만 배다. 이 지점에서 자료구조 자체가 갈린다. [XV-1 메모리를 벗어나는 순간](#/xv-1)이 그 계산으로 시작한다.

## 8. 이 판단을 언제 하는가

::: classify
- 신호어: 지문 맨 아래의 "N (1 ≤ N ≤ ...)", "시간 제한 1초", "메모리 제한 256MB". 본문의 "총 M개의 쿼리", "최대 100,000개의 간선"
- 제약조건: N이 명시된 모든 문제. 제약이 이상하게 작으면($n \le 20$) 지수 시간을 허용한다는 신호이고, 이상하게 크면($n \ge 10^7$) 입출력이 본체라는 신호다
- 혼동 주의: 변수가 둘 이상이면 곱을 본다. $N \le 1000$, $M \le 1000$에 $O(NM)$은 $10^6$이라 안전하지만 $O(NM \log M)$은 $10^7$이라 Python에서 위험하다. 쿼리 수 $Q$가 따로 있으면 반드시 $Q$를 곱한다
- 반례 함정: 상한이 여러 개일 때 최악의 조합을 쓰지 않는 것. "정점 $10^5$, 간선 $2 \times 10^5$"에서 인접 행렬을 잡으면 $10^{10}$칸이라 메모리에서 죽는다. 시간만 보고 공간을 안 보는 것이 이 유형의 대표 실패다
:::

::: interview
**"이 코드의 복잡도는 얼마입니까."** 뒤에 거의 항상 따라붙는 질문이 있다.

**"입력이 100만 개면 실제로 몇 초 걸립니까."** 여기서 갈린다. "$O(n \log n)$이니까 빠릅니다"는 답이 아니다. 답의 뼈대는 단가와 횟수다. "안쪽 루프가 배열을 순서대로 훑으니 한 바퀴가 나노초 단위입니다. $n \log n$이 $2 \times 10^7$이니 C++이면 0.1초 안쪽, Python이면 인터프리터 상수가 50배쯤 붙어 수 초입니다." 숫자가 틀려도 **계산의 구조가 있으면 통과한다.**

**"어떻게 확인했습니까."** 두 배 실험을 말하면 된다. $n$을 두 배로 늘려 시간 배수를 보고 지수를 읽었다고 답한다. 프로파일러 이름을 대는 것보다 강하다 — 도구 없이도 판정했다는 뜻이기 때문이다.
:::

## 연습

::: quiz
전부 **지문을 읽기 전에 제약조건만으로 후보를 좁히는** 훈련이다. 코드를 짜지 말고 복잡도부터 확정하라.

**1. 백준 2110 공유기 설치 (골드 4)** — https://www.acmicpc.net/problem/2110
- 신호: 집 $N \le 200{,}000$, 좌표 $\le 10^9$. 좌표를 훑는 것은 불가능하고 집을 훑는 것은 가능하다. **좌표 크기와 개수의 차이가 곧 답의 방향이다.**
- 상태: 답인 "최소 거리"를 값으로 두고 그 값을 이분 탐색한다. 판정은 "거리 $d$로 $C$개를 놓을 수 있는가"이고 $O(N)$이다.
- 자료구조: 정렬된 좌표 배열 하나. 전체가 $O(N \log N + N \log(10^9))$이고 $\log(10^9) \approx 30$이라 $6 \times 10^6$이다. [VII-3 매개변수 탐색](#/vii-3).

**2. 백준 11729 하노이 탑 이동 순서 (실버 1)** — https://www.acmicpc.net/problem/11729
- 신호: $N \le 20$. §3 표에서 $n \le 22$는 $O(2^n)$을 허용한다. **제약이 이상하게 작으면 지수 시간이 정답이라는 신호다.**
- 상태: 원판 $k$개를 출발에서 목표로 옮기는 문제를 $k-1$개 문제 둘로 쪼갠다. 출력 줄 수가 $2^{20} - 1 \approx 10^6$이라 출력 방법이 병목이다.
- 자료구조: 재귀 호출 스택과 출력 버퍼. 줄마다 출력하면 [0-10](#/0-10)에서 재는 대로 초를 넘긴다.

**3. 백준 1929 소수 구하기 (실버 3)** — https://www.acmicpc.net/problem/1929
- 신호: $M, N \le 1{,}000{,}000$. 수마다 나눗셈으로 판정하면 $O(N\sqrt{N}) = 10^9$이라 표에서 이미 탈락이다.
- 상태: 크기 $N+1$의 불리언 배열. 소수를 하나 찾을 때마다 그 배수를 전부 지운다. 총 연산이 $O(N \log \log N)$인 근거는 소수의 역수 합에서 나온다.
- 자료구조: 배열 하나. **연속 접근이라 §2 표의 최선 단가 쪽이다.** 같은 $O(N)$이라도 여기가 빠른 이유다. [X-2 소수](#/x-2).

**4. 역산 과제.** 다음 제약에서 허용 복잡도와 알고리즘 후보를 각각 두 개씩 적어라. 언어는 C++로 가정한다.
(가) $N \le 500$, 시간 1초, "모든 쌍 사이의 최단 거리"
(나) $N \le 10^5$, $M \le 10^5$, 시간 2초, "쿼리마다 구간 합"
(다) $N \le 16$, 시간 1초, "모든 도시를 한 번씩 방문하는 최소 비용"

::: answer
**(가)** $N^3 = 1.25 \times 10^8$. §3 표에서 C++ $O(n^3)$의 상한이 400~900이므로 500은 통과권이다. 후보는 플로이드-워셜([V-3](#/v-3)) 하나, 다익스트라를 모든 정점에서 돌리기($O(N \cdot M \log N)$)가 다른 하나다. 간선이 조밀하면 전자, 희소하면 후자다.

**(나)** 쿼리가 $10^5$개이므로 **쿼리당 비용에 $10^5$을 곱해야 한다.** 쿼리당 $O(N)$이면 $10^{10}$이라 탈락이다. 쿼리당 $O(\log N)$이면 $1.7 \times 10^6$으로 여유롭다. 후보는 갱신이 없으면 누적 합([VI-4](#/vi-4))으로 쿼리당 $O(1)$, 갱신이 있으면 세그먼트 트리나 펜윅 트리([IX-3](#/ix-3))로 $O(\log N)$이다. ==갱신 유무가 자료구조를 가른다.==

**(다)** $N \le 16$은 $2^{16} = 65{,}536$이다. 순열 전탐색은 $16! \approx 2 \times 10^{13}$이라 표에서 즉시 탈락한다. 후보는 비트마스크 DP([VIII-9](#/viii-9))로 상태가 $2^N \cdot N \approx 10^6$개이고 전이가 $O(N)$이라 $1.7 \times 10^7$, 다른 하나는 가지치기를 건 백트래킹([III-4](#/iii-4))이다. **$n \le 22$를 보면 비트마스크를 먼저 떠올리는 것이 이 표를 쓰는 방식이다.**

## 요약

- 제약조건은 답의 절반이다. **지문을 읽기 전에 무엇이 불가능한지부터 확정한다.**
- "1초 ≈ $10^8$"은 C++의 무작위 접근 루프에 우연히 맞는 값이다. 한 언어 안에서도 워크로드에 따라 초당 처리량이 **100배 넘게** 벌어진다.
- 실측 단가는 Python 59.4~507 ns, C++ 1.23~135.7 ns다. 단가를 하나로 정할 수 없으므로 역산은 **최선·최악 두 값으로 구간**을 낸다.
- 외울 것은 경계값이 아니라 자릿수의 계단이다. $n^2$은 만, $n^3$은 수백, $2^n$은 스물 몇.
- 복잡도를 코드에서 못 세면 **두 배 실험**을 한다. $n$을 두 배로 늘려 시간 배수를 보고 $\log_2$로 지수를 읽는다. $O(n)$과 $O(n^2)$은 즉시 갈리고 $O(n)$과 $O(n \log n)$은 갈리지 않는다.
- 같은 복잡도가 갈리는 다섯 자리: 메모리 접근 패턴, 자료구조의 숨은 상수, 입출력, 최악이 오지 않는 알고리즘, 시간이 아니라 메모리가 진짜 제약인 경우.
- **역산은 후보를 지우는 도구다.** 확정은 두 배 실험과 실제 실행이 한다.
