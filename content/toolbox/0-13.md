# 0-13 Python ↔ C++ 대응 치트시트

::: lead
두 언어를 오갈 때 손이 멈추는 자리와, 같아 보이는데 다른 자리를 한 장에 모은다.
:::

## 1. 문제

두 언어를 같이 쓰면 두 종류의 마찰이 생긴다.

**첫째, 이름이 안 떠오른다.** `bisect_left`가 C++에서 무엇인지, `Counter`가 무엇으로 대체되는지. 이건 찾으면 나오고 몇 번 쓰면 붙는다. 이 챕터의 표 절반이 그 목록이다.

**둘째, 같아 보이는데 다르다.** 이쪽이 실제로 사람을 잡는다. `sort`는 양쪽에 다 있고 이름도 같은데 한쪽만 안정 정렬이다. 힙은 양쪽에 다 있는데 기본 방향이 반대다. `-7 / 2`는 양쪽에서 계산되는데 값이 다르다. **문법 오류가 아니라 조용한 오답으로 나타난다.**

두 번째 종류를 표로 적으면 틀린다. 사람이 기억으로 적은 대응표는 검증되지 않은 주장이다. 그래서 이 챕터의 표는 다르게 만들었다. **같은 라벨로 같은 값을 찍는 두 프로그램을 짜고 출력을 `diff` 했다.** 63줄 중 갈린 것은 4줄이다. 그 4줄이 §7이고, 나머지 59줄은 "확인된 대응"이다.

그리고 여기서 나온 부산물이 §8이다. **같은 줄을 내기 위해 C++을 다르게 써야 했던 자리**가 여섯 군데 있었다. `diff`에 안 남으므로 표만 봐서는 안 보이고, 실전에서 가장 자주 틀리는 것이 이쪽이다.

## 2. 검증 방법

두 프로그램의 뼈대다. 전체는 `tools/bench/cheatsheet_verify.py`와 `.cpp`에 있다.

::: dual
```python title="치트시트 검증 — 같은 라벨로 같은 값을 찍는다"
import bisect
import heapq
from itertools import accumulate


def p(label, value):
    print(f"{label:<30}| {value}")


b = [1, 3, 3, 5, 7, 9]
p("lower_bound", bisect.bisect_left(b, 3))
p("upper_bound", bisect.bisect_right(b, 3))
p("count = upper - lower", bisect.bisect_right(b, 3) - bisect.bisect_left(b, 3))

h = []
for v in [5, 1, 4]:
    heapq.heappush(h, v)       # heapq 는 최소 힙 전용
p("heap top", h[0])

ps = [(2, "b"), (1, "c"), (2, "a"), (1, "a")]
p("stable sort by key", sorted(ps, key=lambda t: t[0]))

xs = [10, 20, 30]
p("enumerate", [(i, v) for i, v in enumerate(xs)])
p("accumulate", list(accumulate(xs)))
p("join", "-".join(map(str, xs)))
```
```cpp title="치트시트 검증 — 같은 라벨로 같은 값을 찍는다"
#include <algorithm>
#include <iostream>
#include <numeric>
#include <queue>
#include <string>
#include <vector>
using namespace std;

// 라벨 폭은 코드포인트 수로 센다. printf 의 %-30s 는 바이트로 세기 때문이다.
void p(const string& label, const string& value) {
    size_t n = 0;
    for (unsigned char c : label) if ((c & 0xC0) != 0x80) ++n;
    cout << label << string(n < 30 ? 30 - n : 0, ' ') << "| " << value << "\n";
}
void p(const string& label, long long v) { p(label, to_string(v)); }

int main() {
    vector<int> b = {1, 3, 3, 5, 7, 9};
    auto lo = lower_bound(b.begin(), b.end(), 3);
    auto hi = upper_bound(b.begin(), b.end(), 3);
    p("lower_bound", (long long)(lo - b.begin()));
    p("upper_bound", (long long)(hi - b.begin()));
    p("count = upper - lower", (long long)(hi - lo));

    priority_queue<int, vector<int>, greater<int>> h;  // 기본은 최대 힙이라 뒤집는다
    for (int v : {5, 1, 4}) h.push(v);
    p("heap top", (long long)h.top());

    vector<pair<int, string>> ps = {{2, "b"}, {1, "c"}, {2, "a"}, {1, "a"}};
    stable_sort(ps.begin(), ps.end(),                  // sort 는 안정적이지 않다
                [](const auto& l, const auto& r) { return l.first < r.first; });
    string s = "[";
    for (size_t i = 0; i < ps.size(); ++i)
        s += (i ? ", (" : "(") + to_string(ps[i].first) + ", '" + ps[i].second + "')";
    p("stable sort by key", s + "]");

    vector<int> xs = {10, 20, 30};
    s = "[";
    for (size_t i = 0; i < xs.size(); ++i)
        s += (i ? ", (" : "(") + to_string(i) + ", " + to_string(xs[i]) + ")";
    p("enumerate", s + "]");
    vector<int> acc(xs.size());
    partial_sum(xs.begin(), xs.end(), acc.begin());
    s = "[";
    for (size_t i = 0; i < acc.size(); ++i) s += (i ? ", " : "") + to_string(acc[i]);
    p("accumulate", s + "]");
    s = "";
    for (size_t i = 0; i < xs.size(); ++i) s += (i ? "-" : "") + to_string(xs[i]);
    p("join", s);
    return 0;
}
```
:::

두 출력은 한 글자도 다르지 않다.

```console
lower_bound                   | 1
upper_bound                   | 3
count = upper - lower         | 2
heap top                      | 1
stable sort by key            | [(1, 'c'), (1, 'a'), (2, 'b'), (2, 'a')]
enumerate                     | [(0, 10), (1, 20), (2, 30)]
accumulate                    | [10, 30, 60]
join                          | 10-20-30
```

**복잡도:** 검증 프로그램 자체는 시간 $O(1)$ — 상수 크기 입력에 고정된 개수의 연산을 한다. 의미 있는 것은 각 줄이 대표하는 연산의 복잡도이고 §4의 표에 있다. 공간도 $O(1)$이다. **이 프로그램의 값어치는 성능이 아니라 "표가 거짓말하지 않는다"는 보증이다.**

| 언어 차이 | Python | C++ |
|---|---|---|
| 문자열 폭 | `f"{s:<30}"`은 **코드포인트** 수로 센다 | `%-30s`는 **바이트** 수로 센다. 한글 라벨에서 어긋난다 |
| 컨테이너 출력 | `print(list)`가 곧 `[1, 2, 3]` | 직접 조립해야 한다 |
| 힙 방향 | `heapq` = 최소 힙 고정 | `priority_queue` = **최대 힙 기본**. `greater<int>`로 뒤집는다 |
| 정렬 안정성 | `sorted`/`sort`는 안정 | `sort`는 불안정. `stable_sort`가 대응 |

## 4. 연산과 복잡도

| 연산 | Python | C++ | 복잡도 |
|---|---|---|---|
| 뒤에 추가 | `a.append(x)` | `a.push_back(x)` | 상환 $O(1)$ — 재할당이 두 배씩이라 총 복사가 $O(n)$ |
| 뒤에서 제거 | `a.pop()` | `a.pop_back()` | $O(1)$ |
| 앞에 추가 | `d.appendleft(x)` | `d.push_front(x)` | `deque`면 $O(1)$, `list`/`vector`면 $O(n)$ |
| 앞에서 제거 | `d.popleft()` | `d.pop_front()` | 같음 |
| 길이 | `len(a)` | `a.size()` | $O(1)$ |
| 첫/끝 원소 | `a[0]`, `a[-1]` | `a.front()`, `a.back()` | $O(1)$. **C++에 음수 인덱스는 없다** |
| 부분 복사 | `a[i:j]` | `vector<int>(a.begin()+i, a.begin()+j)` | $O(j-i)$ |
| 정렬 | `a.sort()` / `sorted(a)` | `sort(a.begin(), a.end())` | $O(n \log n)$ — 비교가 $n \log n$회 |
| 안정 정렬 | `a.sort()` (이미 안정) | `stable_sort(...)` | $O(n \log n)$, 추가 공간 $O(n)$ |
| 역순 정렬 | `sorted(a, reverse=True)` | `sort(a.begin(), a.end(), greater<int>())` | 같음 |
| 이분 탐색 | `bisect.bisect_left(a, x)` | `lower_bound(a.begin(), a.end(), x)` | $O(\log n)$ — 구간을 절반씩 접는다 |
| 상계 탐색 | `bisect.bisect_right(a, x)` | `upper_bound(...)` | $O(\log n)$ |
| 힙 삽입 | `heapq.heappush(h, x)` | `pq.push(x)` | $O(\log n)$ — 높이만큼 sift |
| 힙 최소 꺼내기 | `heapq.heappop(h)` | `pq.pop()` + `pq.top()` | $O(\log n)$ |
| 맵 조회 | `d[k]` / `d.get(k, v)` | `m[k]` / `m.count(k)` | 평균 $O(1)$, 최악 $O(n)$ |
| 포함 여부 | `x in a` | `find(a.begin(), a.end(), x) != a.end()` | 리스트면 $O(n)$, 집합/맵이면 평균 $O(1)$ |
| 중복 제거 | `sorted(set(a))` | `sort` → `unique` → `erase` | $O(n \log n)$ |
| 최대·최소 | `max(a)`, `min(a)` | `*max_element(...)`, `*min_element(...)` | $O(n)$ |
| 합 | `sum(a)` | `accumulate(a.begin(), a.end(), 0)` | $O(n)$. **C++은 초기값 타입이 결과 타입이다** |
| 누적 합 | `itertools.accumulate(a)` | `partial_sum(a.begin(), a.end(), out.begin())` | $O(n)$ |
| 개수 | `a.count(x)` | `count(a.begin(), a.end(), x)` | $O(n)$ |
| 뒤집기 | `a[::-1]` / `reversed(a)` | `reverse(a.begin(), a.end())` / `rbegin()` | $O(n)$ |
| 다음 순열 | `itertools.permutations` | `next_permutation(...)` | 순열 하나당 상환 $O(1)$ |
| k번째 원소 | `sorted(a)[k]` | `nth_element(a.begin(), a.begin()+k, a.end())` | C++은 평균 $O(n)$ — [0-7](#/0-7) |

::: danger
`accumulate(a.begin(), a.end(), 0)`은 **초기값 `0`이 `int`라 결과도 `int`다.** 원소가 `long long`이어도 합이 `int`로 계산되어 넘친다. `0LL`을 넣어야 한다. Python에는 이 함정이 없다 — 정수가 임의 정밀도다([0-5](#/0-5)).
:::

## 5. 관용구

| 관용구 | Python | C++ |
|---|---|---|
| 인덱스와 값 | `for i, v in enumerate(a):` | `for (size_t i = 0; i < a.size(); ++i)` |
| 두 배열 나란히 | `for x, y in zip(a, b):` | 인덱스로 동시에 접근 |
| 조건 만족 여부 | `any(...)`, `all(...)` | `any_of`, `all_of` |
| 변환 | `[f(x) for x in a]` | `transform(...)` 또는 그냥 루프 |
| 걸러내기 | `[x for x in a if p(x)]` | `copy_if(...)` 또는 그냥 루프 |
| 키로 정렬 | `sorted(a, key=f)` | `sort(a.begin(), a.end(), cmp)` — **key가 아니라 비교자** |
| 여러 기준 정렬 | `key=lambda t: (-t[0], t[1])` | 비교자 안에서 `if (l.a != r.a) return l.a > r.a; return l.b < r.b;` |
| 2차원 초기화 | `[[0] * m for _ in range(n)]` | `vector<vector<int>>(n, vector<int>(m, 0))` |
| 문자열 쪼개기 | `s.split()` | `istringstream` + `>>` |
| 문자열 잇기 | `"-".join(parts)` | 루프로 누적, 첫 원소만 구분자 생략 |
| 문자열 뒤집기 | `s[::-1]` | `string(s.rbegin(), s.rend())` |
| 정수 ↔ 문자열 | `str(x)`, `int(s)` | `to_string(x)`, `stoi(s)` / `stoll(s)` |
| 문자 코드 | `ord(c)`, `chr(n)` | `(int)c`, `(char)n` |
| 최대공약수 | `math.gcd(a, b)` | `__gcd(a, b)` (GCC 확장) 또는 직접 구현 |
| 거듭제곱 mod | `pow(a, b, m)` | 직접 구현 — [X-3](#/x-3) |
| 무한대 | `float("inf")` | `INT_MAX` / `LLONG_MAX` / `1e18` |
| 스왑 | `a, b = b, a` | `swap(a, b)` |

::: danger
`[[0] * m] * n`은 **행 하나를 n번 참조하는 리스트**를 만든다. `g[0][1] = 7`이 모든 행을 바꾼다. 반드시 `[[0] * m for _ in range(n)]`이다. Python에서 가장 자주 나오는 조용한 버그이고 [0-2](#/0-2)에 있다.

C++의 `INT_MAX`를 무한대로 쓸 때는 `INT_MAX + w`가 넘치는지 본다. 다익스트라에서 `dist[u] + w`를 계산하는 순간 터진다. `1e9` 정도로 두거나 더하기 전에 걸러라([V-1](#/v-1)).
:::

## 7. `diff`가 남긴 네 줄

63개 항목 중 실제로 갈린 것은 넷이다. 이 넷이 **문법이 아니라 의미가 다른** 지점이다.

| 표현 | Python | C++ |
|---|---|---|
| `-7 / 2` | `-4` (`//`는 항상 **내림**) | `-3` (`/`는 **0 방향 절삭**) |
| `-7 % 2` | `1` (나머지 부호가 **제수**를 따른다) | `-1` (나머지 부호가 **피제수**를 따른다) |
| 정수 상한 | 없음 (임의 정밀도) | `9223372036854775807` (`long long`) |
| $2^{64}$ 계산 | `18446744073709551616` | `0` (`unsigned long long`이 한 바퀴 돈다) |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. `tools/bench/cheatsheet_verify.py` 와 `.cpp` 의 출력을 `diff` 한 결과다.)

::: danger
음수 나눗셈이 조용한 오답의 대표다. 좌표를 격자 인덱스로 바꾸는 코드에서 `x / cell`을 쓰면 원점 왼쪽에서 인덱스가 하나 어긋난다. Python으로 검증하고 C++로 옮겼다면 그 순간 결과가 갈린다.

방어는 하나다. **음수가 들어올 수 있으면 나눗셈을 쓰지 말고 좌표를 먼저 양수로 밀어라.** `(x + OFFSET) / cell` 형태로 바꾸면 두 언어가 같아진다. 나머지도 같다 — C++에서 항상 양수 나머지를 원하면 `((x % m) + m) % m`이다.

부호 있는 정수의 넘침은 **정의되지 않은 동작**이라 값이 무엇이 되든 근거가 없다. 위 표의 $2^{64}$가 `0`인 것은 `unsigned long long`을 썼기 때문이고, 부호 없는 정수만 "$2^{64}$로 나눈 나머지"가 표준으로 보장된다([0-5](#/0-5)).
:::

## 8. `diff`에 안 남지만 더 위험한 여섯 자리

같은 줄을 내기 위해 **C++을 다르게 써야 했던** 자리다. 그냥 옮겨 적으면 값이 갈리는데, 표에는 흔적이 남지 않는다.

**1. 힙의 방향.** `heapq`는 최소 힙 전용이고 `priority_queue`는 최대 힙이 기본이다. 그대로 옮기면 다익스트라가 최장 경로를 찾는다. C++에서 최소 힙은 `priority_queue<int, vector<int>, greater<int>>`다.

**2. 정렬 안정성.** `std::sort`는 안정성을 보장하지 않는다. 그런데 **작은 입력에서는 안정적으로 보인다.**

::: perf
| n | Python `list.sort` | C++ `std::sort` | C++ `std::stable_sort` |
|---|---|---|---|
| 4, 8, 16 | 안정 | 안정 | 안정 |
| 32, 40, 64, 1000 | 안정 | **불안정** | 안정 |

> (같은 환경 실측. `tools/bench/sort_stability.py` 와 `.cpp`. introsort가 짧은 구간을 삽입 정렬로 마무리하기 때문에 $n \le 16$에서는 결과가 안정적으로 나온다.)
:::

예제 입력이 작으면 로컬에서 통과하고 채점기에서 깨진다. **동점의 순서가 답에 영향을 주면 `stable_sort`를 쓴다.**

**3. `map::operator[]`가 삽입한다.** `m["z"]`는 없는 키를 **기본값으로 만들어 넣는다.** `d.get("z", 0)`을 그대로 옮기면 맵이 커지고, 순회 결과가 달라지고, `const map`에서는 컴파일조차 안 된다. 조회만 할 때는 `m.count(k)`나 `m.find(k)`를 쓴다.

거꾸로 이 성질이 `defaultdict` 대응이 되기도 한다. `m[k] += 1`은 없는 키를 0으로 만들어 1을 더하므로 Python의 `defaultdict(int)`와 같다. **의도한 것이면 관용구이고 의도하지 않았으면 버그다.**

**4. 비교자는 `const` 참조를 받아야 한다.** `[](pair<int,int>& l, pair<int,int>& r)`로 쓰면 `sort`는 통과하는데 `stable_sort`가 컴파일 오류를 낸다. 내부에서 `const` 원소와 비교하는 경로가 있기 때문이다. 항상 `const auto&`로 받는다.

**5. `next_permutation`은 현재 순열부터 앞으로만 간다.** 모든 순열을 얻으려면 **입력이 오름차순으로 정렬되어 있어야 한다.** `itertools.permutations`는 입력 순서와 무관하게 전부 만든다. 정렬을 빼먹으면 순열의 일부만 나온다.

**6. 비교자는 strict weak ordering이어야 한다.** `<=`로 쓰면 "같은 원소끼리도 앞선다"가 되어 표준이 요구하는 조건을 어긴다. `std::sort`가 배열 밖을 읽고 실제로 크래시한다. Python의 `key`는 값을 뽑을 뿐이라 이 문제가 없다. [0-8](#/0-8)에 있다.

::: note
여섯 자리를 한 문장으로 줄이면 이렇다. ==**컴파일되는 것과 같은 값을 내는 것은 다른 문제다.**== 대응표를 보고 옮긴 코드는 컴파일까지만 보장된다. 값이 같은지는 [0-12](#/0-12)의 하네스가 확인한다 — 양쪽 구현을 `brute`와 `fast` 자리에 놓고 무작위 입력을 던지면, 위 여섯 자리는 전부 몇 회차 안에 걸린다.
:::

## 9. 어디에 쓰이는가

**포팅과 참조 구현 대조가 이 표의 실무 형태다.** 검증된 구현을 다른 언어로 옮길 때, 두 구현을 나란히 돌려 출력이 갈리는 순간을 찾는 절차가 표준이다([0-12 §8](#/0-12)). 이때 갈리는 지점의 목록이 대개 §7과 §8이다 — 나눗셈 부호, 정렬 동점, 정수 상한. **어디를 볼지 알고 있으면 대조 작업이 몇 시간에서 몇 분으로 줄어든다.**

**언어 경계를 가진 시스템의 계약도 같은 목록으로 정해진다.** Python 층과 C++ 층이 정수를 주고받는 인터페이스에서는 "이 값은 `int64`에 들어간다"가 명시되어야 한다. 한쪽에는 상한이 없고 다른 쪽에는 있기 때문이다([0-10 §7](#/0-10)). 해시 순회 순서를 계약에 넣지 않는 것도 같은 이유다 — 두 언어의 순서가 다르고 같은 언어 안에서도 보장되지 않는다.

## 연습

::: quiz
전부 **옮겨 적으면 값이 갈리는** 자리를 확인하는 훈련이다. 코드를 짜기 전에 §7·§8을 보라.

**1. 백준 11004 K번째 수 (실버 5)** — https://www.acmicpc.net/problem/11004
- 신호: $N \le 5{,}000{,}000$에서 K번째로 작은 수. 전부 정렬하면 $O(N \log N)$이고 통과하지만, **부분 정렬만으로 충분하다.**
- 상태: K번째 자리 하나. 그 앞뒤의 순서는 답에 필요 없다.
- 자료구조: C++은 `nth_element`로 평균 $O(N)$이다. Python에는 대응이 없어 `sort` 또는 `heapq.nsmallest`를 쓴다. ==표에서 "대응이 없다"가 나오는 대표 항목이다.== 입력이 500만 개라 읽는 방법도 함께 정해진다([0-10](#/0-10)).

**2. 백준 11650 좌표 정렬하기 (실버 5)** — https://www.acmicpc.net/problem/11650
- 신호: "x가 같으면 y가 증가하는 순서". **여러 기준 정렬**의 원형이다.
- 상태: 좌표 쌍의 배열 하나.
- 자료구조: Python은 `key=lambda p: (p[0], p[1])`이고 `pair`는 이미 사전순 비교라 C++은 `sort`만으로 된다. **§8의 2번(안정성)이 문제가 되는지 스스로 판정하라** — 두 기준으로 완전히 순서가 정해지면 안정성은 답에 영향을 주지 않는다.

**3. 백준 10814 나이순 정렬 (실버 5)** — https://www.acmicpc.net/problem/10814
- 신호: "나이가 같으면 **먼저 가입한 순서**로". 동점의 순서가 곧 답이다. **§8의 2번이 정면으로 걸린다.**
- 상태: (나이, 이름) 배열과 원래 입력 순서.
- 자료구조: Python은 `sort(key=...)`가 이미 안정이라 그대로 끝난다. C++은 `stable_sort`를 쓰거나 인덱스를 비교자의 두 번째 기준으로 넣는다. **`sort`로 짜면 $n \le 16$인 예제는 통과하고 실제 데이터에서 깨진다.**

**4. 대응 과제.** 다음 Python 조각을 C++로 옮기고, §7·§8 중 몇 개가 걸리는지 세라.

```python title="옮길 조각 — data 는 정수 리스트다"
import heapq
h = []
for x in data:
    heapq.heappush(h, (-x, x // 2))
top = heapq.heappop(h)
```

::: answer
**셋이 걸린다.**

**하나, 힙 방향(§8-1).** `heapq`는 최소 힙이고 값에 `-1`을 곱해 최대 힙을 흉내 낸 코드다. C++의 `priority_queue`는 이미 최대 힙이므로 **부호 뒤집기를 그대로 옮기면 이중으로 뒤집혀 최소 힙이 된다.** `priority_queue<pair<int,int>> pq; pq.push({x, x / 2});`가 맞다.

**둘, 음수 나눗셈(§7).** `x // 2`는 내림이고 `x / 2`는 0 방향 절삭이다. `data`에 음수가 있으면 두 언어의 두 번째 원소가 갈린다. 그리고 이 값은 힙 비교의 두 번째 기준이므로 **동점일 때 꺼내는 순서가 달라진다.** 음수가 없다는 보장이 있어야 그냥 옮길 수 있다.

**셋, 정수 상한(§7).** `-x`는 Python에서 안전하지만 C++에서 `x`가 `INT_MIN`이면 `-x`가 `int` 범위 밖이다. 부호 있는 정수의 넘침은 정의되지 않은 동작이다. 애초에 부호를 뒤집을 필요가 없으므로(첫 번째 항목) 이 위험도 함께 사라진다.

==문제 셋 중 둘이 "부호를 뒤집는다"는 한 줄에서 나왔다.== 언어를 옮길 때 가장 먼저 지워야 할 것은 **다른 언어의 제약을 우회하려고 넣은 코드**다.
:::

## 요약

- 이 표는 손으로 적은 것이 아니라 **같은 라벨로 같은 값을 찍는 두 프로그램의 `diff`**로 만들었다. 63줄 중 갈린 것이 4줄이다.
- 갈린 넷: **음수 나눗셈**(`-4` vs `-3`), **음수 나머지**(`1` vs `-1`), 정수 상한의 유무, 부호 없는 정수의 한 바퀴.
- 더 위험한 것은 `diff`에 안 남는 여섯 자리다. **힙 방향이 반대**, `std::sort`는 불안정($n \ge 32$에서 실측으로 확인), `map::operator[]`가 삽입, 비교자의 `const`, `next_permutation`의 정렬 전제, strict weak ordering.
- Python에는 **정렬 상태를 유지하는 맵/집합이 표준에 없다.** `std::set`을 그대로 옮기려 하면 막힌다.
- C++에는 **음수 인덱스가 없고**, `accumulate`의 초기값 타입이 결과 타입이며, `INT_MAX`에 무언가를 더하면 넘친다.
- **컴파일되는 것과 같은 값을 내는 것은 다른 문제다.** 옮긴 코드는 [0-12](#/0-12)의 하네스로 대조한다.
