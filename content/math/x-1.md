# X-1 정수론

::: lead
두 수의 최대공약수를 구하는 데 왜 나눗셈 몇 번이면 충분한가.
:::

## 1. 문제

분수를 다루는 계산기를 짠다고 하자. `84/126`을 입력하면 기약분수 `2/3`을 내놓아야 한다. 분자와 분모를 각각의 **최대공약수(GCD)**로 나누면 되고, `GCD(84, 126) = 42`다.

최대공약수를 구하는 가장 직관적인 방법은 이렇다. `min(a, b)`부터 `1`까지 내려가며 두 수를 동시에 나누는 첫 값을 찾는다. 코드 세 줄로 짜지고, 작은 수에서는 문제없이 돈다.

문제는 수가 커질 때다. 두 수가 각각 천만 근처이고 서로소(공약수가 1뿐)라면, 이 방법은 `min(a, b)`번 가까이 나눗셈을 반복하고서야 `1`에 도달한다. 실제로 재 보면 이렇다.

```console
a=10000019, b=9999991, gcd=1
  순진한 방법     나눗셈   9999991회   시간(중앙값)   676.588 ms
  유클리드 호제법 나눗셈         6회   시간(중앙값)     0.007 ms
  배율: 나눗셈 1,666,665배, 시간 102,591배
```

> (Linux x86-64 / CPython 3.13 실측, 3회 실행의 중앙값. 측정 스크립트는 `tools/bench/x1_gcd_naive_vs_euclid.py`다.)

같은 답을 내는 데 **나눗셈 6번**이면 충분한 방법이 있다. 그리고 이 방법은 새로 발명할 필요가 없다 — 기원전 3세기 유클리드의 저작에 이미 적혀 있고, 지금 표준 라이브러리의 `gcd` 함수 내부가 전부 이것이다.

## 2. 아이디어

핵심 사실 하나만 있으면 된다.

$$\gcd(a, b) = \gcd(b, \; a \bmod b)$$

**왜 성립하는가.** $d$가 $a$와 $b$의 공약수라 하자. $a \bmod b = a - \left\lfloor a/b \right\rfloor \cdot b$이고, 오른쪽 두 항 $a$와 $\left\lfloor a/b \right\rfloor \cdot b$가 둘 다 $d$의 배수이므로 그 차인 $a \bmod b$도 $d$의 배수다. 즉 **$a, b$의 공약수는 전부 $b, a \bmod b$의 공약수이기도 하다.**

거꾸로도 성립한다. $d$가 $b$와 $a \bmod b$의 공약수면, $a = \left\lfloor a/b \right\rfloor \cdot b + (a \bmod b)$가 두 배수의 합이므로 $a$도 $d$의 배수다. **$b, a \bmod b$의 공약수는 전부 $a, b$의 공약수이기도 하다.**

두 집합이 정확히 같다. 같은 집합에서 뽑은 최댓값이니 두 최대공약수도 같다. ==증명에 등장하는 것은 나눗셈의 정의뿐이고, 두 수가 각각 무엇이었는지는 안 쓰인다.== 그래서 이 등식을 반복 적용해도 계속 성립한다.

$$\gcd(a, b) = \gcd(b, a \bmod b) = \gcd(a \bmod b, \; b \bmod (a \bmod b)) = \cdots$$

두 번째 인자는 매 단계 나머지이므로 반드시 첫 번째 인자보다 작다. **엄격히 감소하는 음이 아닌 정수열은 유한하다** — 언젠가 `0`에 도달하고, 그 직전 값이 최대공약수다. `gcd(a, 0) = a`가 종료 조건인 이유가 여기서 나온다. $a$와 $0$의 공약수는 곧 $a$의 약수 전부이고, 그중 최댓값은 $a$ 자신이다.

**왜 빠른가.** 나머지 연산 한 번마다 두 번째 인자가 줄어드는 정도를 보자. $b \le a/2$이면 다음 나머지는 $a \bmod b < b \le a/2$로 이미 절반 이하다. $b > a/2$이면 $a \bmod b = a - b < a/2$로 **한 번 만에** 절반 밑으로 떨어진다. 어느 경우든 **두 단계마다 값이 최소 절반으로 준다.** 그래서 전체 단계 수는 $O(\log(\min(a,b)))$다 — 순진한 방법의 $O(\min(a,b))$와는 자릿수가 다른 오더다.

| 스텝 | a | b | a mod b |

- [ ] `1071 = 2 × 462 + 147`, `462 = 3 × 147 + 21`을 손으로 검산하라. `147`이 `21`의 배수인가
- [ ] `84 = 2² × 3 × 7`, `126 = 2 × 3² × 7`의 소인수분해와 표의 답을 대조하면 [X-2](#/x-2)의 방법과 일치하는가

::: answer
| 스텝 | a | b | a mod b |
|---|---|---|---|
| 0 | 1071 | 462 | 147 |
| 1 | 462 | 147 | 21 |
| 2 | 147 | 21 | 0 |
| 3 | 21 | 0 | — 종료 |

`b`가 `0`이 된 순간의 `a`, 즉 `21`이 `gcd(1071, 462)`다.

검산: $1071 = 2 \times 462 + 147$, $462 = 3 \times 147 + 21$, $147 = 7 \times 21 + 0$. 나머지 `147`은 `21 × 7`이라 확실히 `21`의 배수다.

$84 = 2^2 \times 3 \times 7$, $126 = 2 \times 3^2 \times 7$의 공통 인수는 $2^1 \times 3^1 \times 7^1 = 42$다 — 위 예제와 수는 다르지만 같은 검산 방식으로 `gcd(84, 126) = 42`를 확인할 수 있다.
:::

이 예제는 3스텝 만에 끝났다. 몇 스텝까지 늘어날 수 있는지는 최악의 입력에서 드러난다 — **연속된 두 피보나치 수**를 넣으면 매 스텝에서 나머지가 딱 한 번만 줄어, 절반씩 준다는 §2의 여유가 전혀 없다. 실제로 6자리 피보나치 수 쌍을 넣으면 이렇게 나온다.

```console
피보나치 F(29)=832040, F(28)=514229: 유클리드 호제법 나눗셈 28회 (자릿수 6)
```

여섯 자리 수인데 28스텝이다. 이것이 라메(Lamé)의 정리가 말하는 최악의 경우이고, 그래도 $O(\log(\min(a,b)))$ 오더 안에 있다 — 자릿수가 하나 늘 때마다 스텝 수가 일정하게(약 5개씩) 느는 것이지, 값 자체에 비례해서 늘지 않는다.

## 4. 구현

### 4.1 유클리드 호제법과 최소공배수

최소공배수(LCM)는 최대공약수에서 바로 나온다. $a$와 $b$의 공배수 중 최소는 $\dfrac{a \times b}{\gcd(a,b)}$다 — $a \times b$는 항상 공배수이고, $\gcd(a,b)$로 나눈 만큼 겹친 소인수를 정확히 한 번만 남기기 때문이다.

::: dual
```python title="유클리드 호제법과 최소공배수"
def gcd(a: int, b: int) -> int:
    while b:
        a, b = b, a % b
    return a


def lcm(a: int, b: int) -> int:
    return a // gcd(a, b) * b   # 곱셈보다 나눗셈을 먼저 — 오버플로를 피한다


print(gcd(1071, 462), lcm(1071, 462))
print(gcd(84, 126), lcm(84, 126))
```
```cpp title="유클리드 호제법과 최소공배수"
#include <cstdio>

long long gcd(long long a, long long b) {
    while (b) {
        long long t = a % b;
        a = b;
        b = t;
    }
    return a;
}

long long lcm(long long a, long long b) {
    return a / gcd(a, b) * b;   // 곱셈보다 나눗셈을 먼저 — 오버플로를 피한다
}

int main() {
    printf("%lld %lld\n", gcd(1071, 462), lcm(1071, 462));
    printf("%lld %lld\n", gcd(84, 126), lcm(84, 126));
    return 0;
}
```
:::

**복잡도:** 시간 $O(\log(\min(a,b)))$ — §2에서 본 대로 두 스텝마다 작은 값이 최소 절반으로 줄고, 최악(연속 피보나치 수)에서도 같은 오더다(라메의 정리). 공간 $O(1)$ — 변수 두 개만 오간다.

`a // gcd(a, b) * b` 순서가 이 코드에서 유일하게 신경 써야 할 지점이다. `a * b`를 먼저 계산하면 최종 LCM이 표현 범위 안에 들어와도 **곱셈 중간값이 먼저 넘칠 수 있다.** `gcd(a, b)`로 먼저 나누면 `a`가 줄어든 채로 곱셈에 들어가 그 위험이 줄어든다.

### 4.2 확장 유클리드 호제법

$\gcd(a, b) = d$일 때 $ax + by = d$를 만족하는 정수 $x, y$가 존재한다(베주 항등식). 유클리드 호제법을 거꾸로 되짚으면 그 $x, y$를 실제로 구할 수 있다.

재귀 한 단계를 보자. `gcd(a, b)`가 `gcd(b, a mod b)`를 호출해 그 결과로 $bx_1 + (a \bmod b)y_1 = d$를 얻었다고 하자. $a \bmod b = a - \lfloor a/b \rfloor b$를 대입해 정리하면

$$d = bx_1 + \left(a - \left\lfloor \frac{a}{b} \right\rfloor b\right) y_1 = a \cdot y_1 + b \cdot \left(x_1 - \left\lfloor \frac{a}{b} \right\rfloor y_1\right)$$

즉 $x = y_1$, $y = x_1 - \lfloor a/b \rfloor y_1$이 이번 단계의 답이다. 재귀의 바닥(`b = 0`)에서는 $a \cdot 1 + 0 \cdot 0 = a = d$이므로 $x=1, y=0$에서 시작한다.

::: dual
```python title="확장 유클리드 호제법 — ax + by = gcd(a, b)"
def ext_gcd(a: int, b: int) -> tuple[int, int, int]:
    if b == 0:
        return a, 1, 0
    d, x1, y1 = ext_gcd(b, a % b)
    x, y = y1, x1 - (a // b) * y1
    return d, x, y


d, x, y = ext_gcd(1071, 462)
print(d, x, y, 1071 * x + 462 * y)   # 마지막 값이 d 와 같아야 검산이 끝난다
```
```cpp title="확장 유클리드 호제법 — ax + by = gcd(a, b)"
#include <cstdio>
#include <tuple>
using namespace std;

tuple<long long, long long, long long> ext_gcd(long long a, long long b) {
    if (b == 0) return {a, 1, 0};
    auto [d, x1, y1] = ext_gcd(b, a % b);
    long long x = y1, y = x1 - (a / b) * y1;
    return {d, x, y};
}

int main() {
    auto [d, x, y] = ext_gcd(1071, 462);
    printf("%lld %lld %lld %lld\n", d, x, y, 1071 * x + 462 * y);
    return 0;
}
```
:::

두 언어의 출력은 같다.

```console
21 -3 7 21
```

$1071 \times (-3) + 462 \times 7 = -3213 + 3234 = 21$. `x, y`는 유일하지 않다 — $x$에 $b/d$의 배수를 더하고 $y$에서 $a/d$의 배수를 빼도 등식이 그대로 성립한다. 여기서 나온 값은 재귀가 만든 특정 해 하나일 뿐이다.

**복잡도:** 시간 $O(\log(\min(a,b)))$ — 재귀 호출 구조가 `gcd`와 완전히 같고, 각 단계에서 하는 일도 상수 시간이다. 공간 $O(\log(\min(a,b)))$ — 재귀 호출 스택이 스텝 수만큼 쌓인다. 반복문으로 바꾸면 $O(1)$ 공간으로 줄지만 코드가 덜 직관적이다.

`ax + by = d`에서 $b$를 소수 $p$로, $d$를 $1$로 두면 $ax \equiv 1 \pmod p$의 $x$, 즉 **모듈러 역원**이 된다. 나눗셈이 없는 나머지 연산 체계에서 나눗셈을 대신하는 것이 이 $x$이고, [X-3 모듈러 연산과 분할 정복 거듭제곱](#/x-3)에서 바로 이어받는다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 정수 오버플로 | 임의 정밀도라 `a * b`가 아무리 커져도 값이 그대로 맞다 | `int`는 약 21억에서 넘친다. `gcd`/`lcm`에 `long long`을 썼고, 실제 문제에서 입력이 `int` 범위여도 곱은 넘칠 수 있어 통 크게 잡는다 |
| 나머지의 부호 | `%`는 floor 나눗셈 기준이라 나머지가 **제수와 같은 부호**다. 음수를 넣어도 `-7 % 3 == 2`처럼 항상 `0` 이상이 나온다(제수가 양수일 때) | `%`는 0 방향 절삭이라 나머지가 **피제수와 같은 부호**다. `-7 % 3 == -1`. 음수 입력을 다루려면 `abs(a), abs(b)`로 정규화해야 같은 결과가 나온다 |
| 튜플 반환·구조적 바인딩 | `return a, 1, 0` / `d, x1, y1 = ext_gcd(...)` | `return {a, 1, 0}` (반환형이 `tuple<...>`) / `auto [d, x1, y1] = ext_gcd(...)` — C++17의 구조적 바인딩 |

::: pitfall
- **`a * b`를 먼저 계산해 LCM을 구한다.** 최종 답은 표현 범위 안이어도 곱셈 중간값이 먼저 넘친다. `a // gcd(a, b) * b` 순서를 지킨다.
- **입력에 `0`이나 음수가 섞였는데 그대로 돌린다.** `gcd(0, n) = n`은 종료 조건 자체라 문제없지만, 음수는 나머지 연산의 부호 규칙이 언어마다 달라 `gcd`가 음수를 반환할 수 있다. 최대공약수는 정의상 음수가 아니므로 시작 전에 절댓값을 취한다.
- **확장 유클리드 호제법의 `x, y`가 유일하다고 믿는다.** 재귀가 낸 값은 무수히 많은 해 중 하나다. 특정 범위(예: $0 \le x < b/d$)로 정규화해야 하는 문제라면 그 후처리를 따로 해야 한다.
- **재귀 깊이를 과대평가한다.** $O(\log(\min(a,b)))$는 $a, b$가 $10^{18}$이어도 90 언저리다. 재귀 한도 걱정은 이 알고리즘에서는 근거가 약하다 — 문제가 되는 재귀는 대개 다른 곳(예: 트리 깊이)에 있다.
:::

## 5. 어디에 쓰이는가

**분수 정규화.** 유리수를 분자·분모 쌍으로 들고 있는 자료형은 사칙연산 결과가 나올 때마다 분자와 분모를 `gcd`로 나눠 기약분수 상태를 유지한다. 그렇게 안 하면 덧셈을 반복할수록 분자·분모가 기하급수로 불어난다.

**스케줄링 주기 계산.** 서로 다른 주기로 도는 작업들이 다시 동시에 실행되는 다음 시각은 그 주기들의 LCM이다. 배치 작업 하나가 6시간마다, 다른 하나가 8시간마다 돈다면 둘이 다시 겹치는 시각은 $\text{lcm}(6, 8) = 24$시간 뒤다. 정기 점검 주기를 잡거나, 여러 센서의 샘플링 주기를 동기화할 지점을 찾을 때 같은 계산이 반복된다.

`while b: a, b = b, a % b`로 충분하다. 재귀로 짠 버전과 스택 깊이만 다를 뿐 스텝 수는 같다 — 유클리드 호제법의 재귀는 [$O(\log(\min(a,b)))$ 깊이]로 얕아서 재귀 한도를 걱정할 필요가 거의 없지만, 반복문 버전이 관용적으로 더 많이 쓰인다.

**"확장 유클리드 호제법은 어디에 쓰이는가."**
"$ax \equiv 1 \pmod p$를 만족하는 $x$, 즉 모듈러 역원을 구할 때 씁니다. $b$ 자리에 $p$를, 우변에 $1$을 놓고 확장 유클리드 호제법을 돌리면 나눗셈이 없는 나머지 연산 체계에서 나눗셈을 대신할 수 있습니다."까지 답하면 [X-3](#/x-3)으로 자연스럽게 이어진다.
:::

- 상태: 각 형제 위치와 시작 위치의 차이 배열.

## 요약

- 순진한 GCD(1부터 `min(a,b)`까지 시도)는 $O(\min(a,b))$이고, 두 수가 커지면 즉시 못 쓰게 된다.
- 유클리드 호제법 $\gcd(a,b) = \gcd(b, a \bmod b)$는 "$a,b$의 공약수 집합"과 "$b, a \bmod b$의 공약수 집합"이 정확히 같다는 사실에서 나온다.
- 두 스텝마다 작은 값이 최소 절반으로 줄어 $O(\log(\min(a,b)))$다. 최악(연속 피보나치 수)에서도 같은 오더가 유지된다(라메의 정리).
- LCM은 $a \times b / \gcd(a,b)$다. **나눗셈을 먼저** 해야 곱셈 중간값의 오버플로를 피한다.
- 확장 유클리드 호제법은 $ax + by = \gcd(a,b)$의 $x, y$를 유클리드 호제법의 재귀를 거꾸로 되짚어 구한다. $b$가 소수일 때 이것이 모듈러 역원이 된다.
- 실무에서는 분수 정규화와 여러 주기가 다시 겹치는 시각 계산에 GCD·LCM이 그대로 쓰인다.
