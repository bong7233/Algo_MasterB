# X-5 기하

::: lead
세 점이 왼쪽으로 도는지 오른쪽으로 도는지 하나만 판정할 수 있으면, 선분이 교차하는지도 점이 다각형 안에 있는지도 전부 그 판정 하나로 풀린다.
:::

## 1. 문제

로봇 두 대가 창고 바닥을 오간다. 각 로봇의 이동 경로를 선분으로 표시했을 때, **이 두 경로가 어딘가에서 겹치는가**를 계속 물어야 한다. 겹치면 그 시간대에 한쪽을 멈춰야 한다. 좌표만 놓고 보면 직선의 방정식을 세우고 연립해서 교점을 구하면 될 것 같지만, 두 선분이 평행하거나 겹치거나 끝점에서만 스치는 경우까지 전부 예외 없이 처리하려 하면 분기가 급격히 늘어난다.

점이 창고의 작업 구역 안에 있는지 판정하는 문제도 비슷하다. 작업 구역이 볼록하지 않은 임의의 다각형이면 "x, y가 각각 최소·최댓값 사이에 있는가" 같은 사각형 근사로는 안 된다. 오목한 부분이 있으면 사각형 안이지만 다각형 밖인 점이 생긴다.

두 문제 다 "이 세 점을 이은 두 선분이 왼쪽으로 꺾이는가 오른쪽으로 꺾이는가"라는 더 작은 질문 하나로 환원된다. 그 질문에 답하는 도구를 먼저 만들면, 선분 교차도 다각형 내부 판정도 그 도구를 두세 번 호출하는 문제로 줄어든다.

## 2. 아이디어

### 2.1 CCW — 세 점의 방향

점 $P_1, P_2, P_3$을 순서대로 이었을 때 $P_1 \to P_2 \to P_3$이 반시계 방향으로 꺾이는지, 시계 방향으로 꺾이는지, 아니면 일직선인지를 판정하는 것이 **CCW(Counter-Clockwise)**다. 벡터 $\overrightarrow{P_1P_2}$와 $\overrightarrow{P_1P_3}$의 **외적**을 쓴다.

$$
\text{cross} = (x_2 - x_1)(y_3 - y_1) - (y_2 - y_1)(x_3 - x_1)
$$

이 값의 **부호만** 본다. 양수면 반시계(왼쪽으로 꺾임), 음수면 시계(오른쪽으로 꺾임), 0이면 세 점이 일직선이다.

::: widget complexity-plot {"show":["n"],"wide":false}
:::

이 위젯은 이 절과 직접 관련은 없지만, 여기서 짚을 것은 그래프가 아니라 **연산 횟수**다. CCW는 곱셈 두 번과 뺄셈 세 번으로 끝나는 $O(1)$ 연산이다. 이 저렴한 연산 하나가 아래 두 판정 전부의 기초가 된다.

방향을 좌표평면 위에서 그려 보면 이렇다. $P_1$에서 $P_2$로 걸어간 다음 $P_3$을 향해 몸을 돌린다고 하자. 왼쪽으로 도는 만큼 외적이 양수로 커지고, 오른쪽으로 도는 만큼 음수로 커진다. 세 점이 한 직선 위에 있으면 돌 필요가 없으므로 정확히 0이다. **외적의 절댓값은 $P_1P_2P_3$이 이루는 평행사변형의 넓이와 같다** — 세 점이 이루는 삼각형 넓이의 두 배다. 부호는 방향, 크기는 넓이. 이 두 정보가 CCW 하나에 같이 담겨 있다.

**왜 좌표를 정수로 유지하는가.** 입력이 정수 좌표라면 `cross`도 정수다. 부호만 비교하면 되므로 `cross > 0`, `cross == 0` 같은 정수 비교로 끝난다. 좌표를 실수로 바꾸거나 기울기를 나눗셈으로 구해서 비교하면, 반올림 오차 때문에 진짜 일직선이 아닌데 `== 0`이 나오거나 그 반대가 나올 수 있다. **정수 좌표를 유지할 수 있을 때 실수 비교로 우회하지 않는 것**이 이 판정을 안전하게 만드는 첫 번째 규칙이다 — 이 이유는 [X-7 부동소수점의 함정](#/x-7)에서 정면으로 다룬다.

### 2.2 선분 교차 — CCW 두 번의 조합

선분 $AB$와 선분 $CD$가 교차하는지는 이렇게 본다.

1. $C$와 $D$가 직선 $AB$를 기준으로 **서로 반대쪽**에 있는가 — `CCW(A,B,C)`와 `CCW(A,B,D)`의 부호가 다른가
2. $A$와 $B$가 직선 $CD$를 기준으로 **서로 반대쪽**에 있는가 — `CCW(C,D,A)`와 `CCW(C,D,B)`의 부호가 다른가

두 조건이 **동시에** 성립해야 두 선분이 실제로 교차한다. 한쪽만 반대쪽에 있고 다른 쪽은 아니면, 두 직선은 만나지만 그 교점이 선분 바깥에 있다는 뜻이다.

일직선 위에 놓이는 경우(`CCW == 0`)는 따로 처리해야 한다. 예를 들어 $C$가 정확히 직선 $AB$ 위에 있으면서 선분 $AB$의 범위 안에도 들어와 있는지는 좌표 비교로 추가 확인한다. 이 챕터는 세 점이 일직선에 놓이지 않는 입력을 기본으로 다루고, 겹치는 경우의 완전한 분기는 연습문제 2번에서 스스로 짜 본다.

### 2.3 다각형 내부 판정 — 레이 캐스팅

점 $P$가 다각형 안에 있는지는, $P$에서 다각형 바깥으로 향하는 반직선(레이)을 하나 긋고 **그 반직선이 다각형의 변과 몇 번 만나는지** 센다. 홀수 번 만나면 내부, 짝수 번 만나면 외부다.

직관은 이렇다. 다각형 밖의 한 점에서 시작해 $P$까지 걸어온다고 하자. 변을 하나 넘을 때마다 안팎이 뒤집힌다. 바깥(만난 횟수 0, 짝수)에서 출발했으니, $P$에 도착했을 때 넘은 변의 수가 홀수면 안, 짝수면 밖이다.

구현에서는 $P$에서 오른쪽으로 무한히 뻗는 수평 반직선을 쓰는 것이 흔하다. 다각형의 각 변에 대해 "이 변이 $P$의 $y$좌표를 가로지르면서, 그 교차 $x$좌표가 $P$의 $x$좌표보다 오른쪽인가"를 판정하면 된다. 이때도 변의 끝점이 정확히 $P$의 $y$좌표와 같은 경우, 즉 반직선이 꼭짓점을 스치는 경우를 이중으로 세지 않도록 부등호 방향을 한쪽만 포함하게 잡는 것이 관례다 — 아래 구현의 `y1 <= py < y2` 조건이 그 장치다.

## 3. 손으로 따라가기

::: trace
`cross(A, B, C) = (Bx-Ax)(Cy-Ay) - (By-Ay)(Cx-Ax)`로 CCW 부호를 구한다. 아래 네 개의 세 점 조합을 판정한다.

| # | A | B | C | cross 값 | 부호(방향) |
|---|---|---|---|---|---|
| 1 | (0,0) | (4,0) | (2,3) | $4 \times 3 - 0 \times 2 = 12$ | 양수(반시계) |
| 2 | (0,0) | (4,0) | (2,-3) | $4 \times (-3) - 0 \times 2 = -12$ | 음수(시계) |
| 3 | (0,0) | (4,0) | (2,0) | | |
| 4 | (0,0) | (4,4) | (2,2) | | |

세 가지를 확인하라.

- [ ] `#3`에서 `C`가 선분 `AB` 위에 정확히 놓여 있다. `cross` 값이 무엇이어야 하는가
- [ ] `#4`에서 `C = (2,2)`는 `A=(0,0)`와 `B=(4,4)`를 잇는 직선 `y=x` 위에 있다. `cross` 값을 계산해 `#3`과 같은 결론이 나오는지 확인하라
- [ ] `#1`과 `#2`는 `C`의 `y`좌표 부호만 바뀌었다. `cross`의 부호가 정확히 반대로 뒤집히는가 — 이것이 "직선 위쪽/아래쪽"을 구분하는 원리다
:::

::: answer
| # | A | B | C | cross 값 | 부호(방향) |
|---|---|---|---|---|---|
| 1 | (0,0) | (4,0) | (2,3) | $4 \times 3 - 0 \times 2 = 12$ | 양수(반시계) |
| 2 | (0,0) | (4,0) | (2,-3) | $4 \times (-3) - 0 \times 2 = -12$ | 음수(시계) |
| 3 | (0,0) | (4,0) | (2,0) | $4 \times 0 - 0 \times 2 = 0$ | 0(일직선) |
| 4 | (0,0) | (4,4) | (2,2) | $4 \times 2 - 4 \times 2 = 0$ | 0(일직선) |

`#3`은 `C`가 선분 `AB`의 연장선인 $x$축 위에 있으므로 `cross = 0`이 나온다 — 세 점이 한 직선 위에 있다는 판정과 정확히 일치한다.

`#4`는 `A`, `B`, `C`가 전부 직선 `y = x` 위에 있다. 좌표는 `#1`, `#2`와 전혀 다르지만 "일직선"이라는 결론은 같은 방식(`cross = 0`)으로 나온다 — CCW는 특정 직선의 방정식이 아니라 세 점의 **상대적 배치**만 본다.

`#1`과 `#2`는 `C`의 `y`좌표만 `3`에서 `-3`으로 바뀌었는데 `cross`가 `12`에서 `-12`로 정확히 부호가 뒤집힌다. `cross` 식에서 `C`의 좌표가 `(Cy-Ay)`와 `(Cx-Ax)` 항에 선형으로만 들어가기 때문에, `C`가 직선 `AB`를 기준으로 위쪽에 있느냐 아래쪽에 있느냐가 부호 하나로 정확히 갈린다. 선분 교차 판정의 "반대쪽에 있는가"가 바로 이 부호 비교다.
:::

## 4. 구현

### 4.1 CCW와 선분 교차

::: dual
```python title="CCW와 선분 교차 판정"
def ccw(a, b, c):
    cross = (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])
    if cross > 0:
        return 1        # 반시계
    if cross < 0:
        return -1       # 시계
    return 0             # 일직선


def segments_intersect(a, b, c, d):
    ab_c = ccw(a, b, c)
    ab_d = ccw(a, b, d)
    cd_a = ccw(c, d, a)
    cd_b = ccw(c, d, b)
    return ab_c * ab_d < 0 and cd_a * cd_b < 0


p1, p2, p3 = (0, 0), (4, 0), (2, 3)
print(ccw(p1, p2, p3))
a, b, c, d = (0, 0), (4, 4), (0, 4), (4, 0)
print(segments_intersect(a, b, c, d))
```
```cpp title="CCW와 선분 교차 판정"
#include <cstdio>
using namespace std;

struct Point { long long x, y; };

int ccw(Point a, Point b, Point c) {
    long long cross = (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);
    if (cross > 0) return 1;        // 반시계
    if (cross < 0) return -1;       // 시계
    return 0;                       // 일직선
}

bool segments_intersect(Point a, Point b, Point c, Point d) {
    int ab_c = ccw(a, b, c);
    int ab_d = ccw(a, b, d);
    int cd_a = ccw(c, d, a);
    int cd_b = ccw(c, d, b);
    return ab_c * ab_d < 0 && cd_a * cd_b < 0;
}

int main() {
    Point p1{0, 0}, p2{4, 0}, p3{2, 3};
    printf("%d\n", ccw(p1, p2, p3));
    Point a{0, 0}, b{4, 4}, c{0, 4}, d{4, 0};
    printf("%s\n", segments_intersect(a, b, c, d) ? "True" : "False");
    return 0;
}
```
:::

```console
1
True
```

**복잡도:** 시간 $O(1)$ — `ccw` 하나가 곱셈 두 번, 뺄셈 세 번뿐이고 `segments_intersect`는 `ccw`를 정확히 네 번 호출한다. 입력 크기와 무관하게 상수 시간이다. 공간 $O(1)$.

| 언어 차이 | Python | C++ |
|---|---|---|
| 좌표 오버플로 | 정수는 임의 정밀도라 좌표가 아무리 커도 `cross` 값이 그대로 맞다 | 좌표가 $10^4$ 근처만 되어도 `(b.x-a.x)*(c.y-a.y)`가 $10^8$ 자리라 `int`로는 위험하다. `long long`으로 미리 잡는다 |
| 튜플과 구조체 | `a[0]`, `a[1]`로 튜플 원소에 접근 | `Point` 구조체로 `x`, `y`에 이름을 붙인다. 튜플도 되지만 좌표 코드에서는 구조체가 관용적이다 |

📖 `struct Point { long long x, y; }` — C++에서 좌표 쌍을 이름 붙은 필드로 묶는 관용구. `pair<long long,long long>`도 되지만 `.first`/`.second`보다 `.x`/`.y`가 기하 코드에서 훨씬 읽기 쉽다.
   쓰는 곳: 이 챕터 전체, [X-6 볼록 껍질](#/x-6).
   Python 대응: 튜플 `(x, y)`이나 `collections.namedtuple`. 이 챕터는 튜플을 그대로 쓴다 — 인덱스 두 개뿐이라 이름 붙이는 비용이 안 남는다.

::: pitfall
- **좌표를 `float`/`double`로 받아 `cross == 0`으로 일직선을 판정한다.** 입력이 정수라면 애초에 정수로 유지해야 한다. 실수로 바꾸는 순간 반올림 오차가 끼어들어 진짜 일직선이 `== 0`을 벗어나거나, 일직선이 아닌데 `== 0`이 나올 수 있다 — [X-7](#/x-7)에서 이 문제를 정면으로 다룬다.
- **`cross`의 부호만 보지 않고 크기까지 비교에 섞는다.** CCW는 방향 판정 도구다. 넓이가 필요하면 크기를(그것도 정수 그대로) 쓰고, 방향 판정에는 부호만 쓴다. 둘을 섞으면 판정 로직이 불필요하게 복잡해진다.
- **선분 교차에서 `ab_c * ab_d <= 0`으로 판정한다.** `<= 0`은 `0`인 경우(한 점이 직선 위에 있는 경우)까지 통과시킨다. 세 점이 일직선에 놓이는 경우를 별도로 처리하지 않을 거라면 반드시 `< 0`으로 엄격하게 잡아야 한다.
:::

### 4.2 다각형 내부 판정 — 레이 캐스팅

::: dual
```python title="레이 캐스팅으로 다각형 내부 판정"
def point_in_polygon(poly, p):
    n = len(poly)
    inside = False
    px, py = p
    for i in range(n):
        x1, y1 = poly[i]
        x2, y2 = poly[(i + 1) % n]
        if (y1 <= py < y2) or (y2 <= py < y1):
            x_cross = x1 + (py - y1) * (x2 - x1) / (y2 - y1)
            if px < x_cross:
                inside = not inside
    return inside


square = [(0, 0), (4, 0), (4, 4), (0, 4)]
print(point_in_polygon(square, (2, 2)))
print(point_in_polygon(square, (5, 2)))
```
```cpp title="레이 캐스팅으로 다각형 내부 판정"
#include <cstdio>
#include <vector>
using namespace std;

struct Point { double x, y; };

bool point_in_polygon(const vector<Point>& poly, Point p) {
    int n = poly.size();
    bool inside = false;
    for (int i = 0; i < n; i++) {
        double x1 = poly[i].x, y1 = poly[i].y;
        double x2 = poly[(i + 1) % n].x, y2 = poly[(i + 1) % n].y;
        if ((y1 <= p.y && p.y < y2) || (y2 <= p.y && p.y < y1)) {
            double x_cross = x1 + (p.y - y1) * (x2 - x1) / (y2 - y1);
            if (p.x < x_cross) inside = !inside;
        }
    }
    return inside;
}

int main() {
    vector<Point> square{{0, 0}, {4, 0}, {4, 4}, {0, 4}};
    printf("%s\n", point_in_polygon(square, {2, 2}) ? "True" : "False");
    printf("%s\n", point_in_polygon(square, {5, 2}) ? "True" : "False");
    return 0;
}
```
:::

```console
True
False
```

**복잡도:** 시간 $O(n)$ — 다각형의 변 $n$개를 한 번씩 순회하며 각 변에서 $O(1)$ 판정을 한다. 공간 $O(1)$(입력 다각형 제외).

| 언어 차이 | Python | C++ |
|---|---|---|
| 좌표 타입 | 정수 좌표를 받아도 `x_cross` 계산에서 `/`가 자동으로 실수 나눗셈이 된다 | `Point`를 `double`로 선언해야 `/`가 실수 나눗셈이다. `long long`으로 두면 정수 나눗셈이 되어 `x_cross`가 잘려서 틀린다 |

📖 위 표의 `x_cross` 계산 자체가 **이 챕터가 CCW로 정수 우회를 못 하는 유일한 지점**이다. 변이 $P$의 $y$좌표를 가로지르는 정확한 $x$좌표는 나눗셈 없이 구할 수 없다. 다만 비교는 "부호"가 아니라 "좌표 하나"이므로, 여기서는 오차를 감수하고 실수를 쓰거나 분수를 통분해 정수 비교로 바꾼다 — 후자는 코드가 길어져 이 챕터에서는 다루지 않는다. **판정을 정수 부호 비교로 끝낼 수 있는 CCW·선분 교차와, 좌표 값 자체가 필요한 레이 캐스팅은 오차에 대한 태도가 다르다**는 것이 이 절의 핵심 관찰이다.

::: pitfall
- **레이가 다각형의 꼭짓점을 정확히 지날 때 교차를 두 번 세거나 한 번도 안 센다.** `y1 <= py < y2` 처럼 한쪽 끝점만 포함하는 부등호를 쓰지 않으면, 레이가 꼭짓점을 스칠 때 인접한 두 변이 동시에 "가로지른다"고 판정되어 짝수여야 할 것이 홀수가 된다.
- **오목한 다각형에 사각형 경계(min/max) 판정을 쓴다.** 오목한 부분의 바깥쪽인데 사각형 경계 안에 있는 점을 내부로 잘못 판정한다. 레이 캐스팅은 다각형이 볼록이든 오목이든 그대로 성립한다는 것이 이 방법을 쓰는 이유다.
- **경계선 위의 점을 별도로 처리하지 않는다.** 위 구현은 점이 변 위에 정확히 있을 때 결과가 구현에 따라 안이나 밖 어느 쪽으로도 나올 수 있다. 문제가 "경계 포함"을 요구하면 경계 판정을 `ccw == 0` and 범위 검사로 따로 넣어야 한다.
:::

## 5. 어디에 쓰이는가

**충돌 검사가 이 챕터의 판정을 그대로 쓴다.** 로봇이나 캐릭터의 이동 경로를 선분으로 표시하고, 장애물이나 다른 에이전트의 경로와 겹치는지를 매 스텝 확인하는 것이 선분 교차 판정이다. 로봇의 작업 반경이나 지오펜스(geofence, 가상 경계 구역)에 현재 위치가 들어와 있는지 확인하는 것이 다각형 내부 판정이다. 두 판정 모두 CCW 하나를 반복 호출하는 것으로 끝나기 때문에, 초당 수백~수천 번씩 불려도 부담이 크지 않다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "세 점이 이루는 방향", "두 선분이 만나는가", "점이 다각형 내부에 있는가", "시계/반시계 방향으로"
- 제약조건: 좌표가 정수 범위(대개 $-10^4 \sim 10^4$ 또는 $-10^9 \sim 10^9$)로 주어지면 정수 연산으로 끝난다. 다각형 변의 개수 $n \le 10^4 \sim 10^5$까지는 $O(n)$ 판정이 여유롭다
- 혼동 주의: 다각형의 **넓이**를 구하는 문제는 신발끈 공식(CCW의 외적을 전체 변에 합산)으로 별도로 접근한다 — 이 챕터의 판정 함수와 식은 같지만 목적이 "부호"가 아니라 "합"이라는 점이 다르다. 점 집합을 감싸는 다각형 자체를 **구성**해야 하면 [X-6 볼록 껍질](#/x-6)로 간다
- 반례 함정: 좌표를 실수로 받아 CCW를 실수 비교로 짜면, 진짜 일직선인 입력에서 오차 때문에 `cross`가 정확히 `0`이 아니게 나와 판정이 흔들린다. 선분 교차에서 `<=` 대신 `<`를 써야 하는 자리를 반대로 쓰는 것도 흔한 실수다
:::

::: interview
**"CCW는 왜 나눗셈이나 각도 계산 없이 방향을 판정할 수 있습니까."**
"외적의 부호가 두 벡터 사이의 회전 방향과 정확히 대응하기 때문입니다. $\overrightarrow{AB}$에서 $\overrightarrow{AC}$로 반시계 방향으로 돌면 외적이 양수, 시계 방향이면 음수, 평행(일직선)이면 0입니다. 각도를 구하려면 삼각함수와 나눗셈이 필요하지만, 부호만 필요하면 곱셈과 뺄셈만으로 끝납니다 — 그래서 좌표가 정수면 오차 없이 정수 연산으로 판정할 수 있습니다."
:::

## 연습

::: quiz
**1. 백준 11758 CCW (실버)** — https://www.acmicpc.net/problem/11758
- 신호: 세 점 $P_1, P_2, P_3$을 순서대로 입력받아 방향(반시계/시계/일직선)을 그대로 묻는다. 이 챕터의 원형 문제다.
- 상태: 없다. 세 점을 받아 §4.1의 `ccw` 함수 하나를 호출하고 부호에 따라 `1`, `-1`, `0`을 출력한다.
- 자료구조: 정수 좌표 세 쌍. 좌표 범위가 작아 오버플로 걱정 없이 바로 정수 연산으로 끝난다.

**2. 백준 17386 선분 교차 1 (실버)** — https://www.acmicpc.net/problem/17386
- 신호: 두 선분이 교차하는지 묻고, "세 점이 한 직선 위에 있는 경우는 없다"는 단서가 붙는다. 일직선 예외를 걱정할 필요가 없는 가장 단순한 형태다.
- 상태: 없다. 네 점을 받아 §4.1의 `segments_intersect`를 그대로 적용한다.
- 자료구조: 정수 좌표 네 쌍. 이 문제가 CCW 두 번의 조합이 왜 필요한지(직선 하나만으로는 부족한 이유)를 체감하기 가장 좋은 원형이다.

**3. 백준 17387 선분 교차 2 (골드)** — https://www.acmicpc.net/problem/17387
- 신호: 17386과 같은 질문이지만 "세 점이 한 직선 위에 있을 수 있다"로 조건이 바뀐다. 한 선분의 끝점이 다른 선분 위에 정확히 놓이는 경우까지 맞혀야 한다.
- 상태: 없다. 다만 `ccw` 결과가 `0`인 경우마다 "그 점이 상대 선분의 범위 안에 들어오는가"를 좌표 비교로 추가 확인해야 한다.
- 자료구조: 정수 좌표 네 쌍 + 경계 포함 판정. §4.1의 `pitfall`에서 언급한 "`< 0`이 아니라 `<= 0`으로 잘못 짜는" 실수를 정확히 반대로, **의도적으로** 처리해야 하는 문제다.
:::

## 요약

- CCW는 세 점 $A, B, C$가 이루는 방향을 외적의 부호 하나로 판정한다. 양수는 반시계, 음수는 시계, 0은 일직선이다.
- 외적의 절댓값은 세 점이 이루는 삼각형 넓이의 두 배다 — 부호는 방향, 크기는 넓이라는 두 정보가 한 식에 담긴다.
- 선분 교차는 CCW를 네 번(양쪽 선분에서 각각 두 번씩) 호출해, 두 끝점이 상대 선분의 서로 반대쪽에 있는지로 판정한다.
- 다각형 내부 판정은 레이 캐스팅으로, 점에서 뻗은 반직선이 다각형 변과 만나는 횟수의 홀짝으로 안팎을 가른다.
- **좌표가 정수라면 CCW와 선분 교차는 끝까지 정수 연산으로 끝난다.** 부호 비교만 필요하기 때문이다. 실수 비교로 바꾸는 순간 오차가 끼어든다 — 이 원칙은 [X-7](#/x-7)에서 일반화된다.
- 레이 캐스팅의 교차 $x$좌표 계산은 나눗셈을 피할 수 없다 — 판정을 정수 부호 비교로 끝낼 수 있는 경우와 좌표 값 자체가 필요한 경우는 오차에 대한 태도가 다르다.
- 충돌 검사, 지오펜스 판정처럼 실시간으로 반복 호출되는 자리에서 CCW의 $O(1)$ 비용이 그대로 성능이 된다.
