# X-6 볼록 껍질

::: lead
점이 수만 개 흩어져 있을 때, 그 전부를 감싸는 가장 작은 볼록 다각형의 꼭짓점만 골라내려면 무엇을 기준으로 골라야 하는가.
:::

## 1. 문제

로봇의 실제 형태는 울퉁불퉁하다. 팔이 튀어나와 있고 센서가 돌출되어 있다. 그런데 충돌 검사나 경로 계획에서 매 스텝 그 정확한 형태를 다 대조하면 계산이 무겁다. 실무에서는 로봇의 **footprint**(바닥에 투영한 대략의 외곽선)를 볼록 다각형 하나로 단순화해서 쓴다 — 로봇을 이루는 점(관절, 팔 끝, 몸체 모서리)들을 전부 감싸는 가장 작은 볼록 다각형이 그 footprint다.

점이 몇 개면 손으로 그려도 되지만, 점이 수천~수만 개면 이야기가 다르다. "모든 점 쌍을 잇는 선분 중 다른 모든 점이 그 선분의 한쪽에만 있는 선분들을 모아라" 같은 정의를 그대로 코드로 옮기면, 선분 쌍마다 나머지 점 전부를 검사해야 해서 $O(n^3)$이다. 점이 만 개만 되어도 $10^{12}$ 번 검사이고, 시간 제한 안에 들어오지 않는다.

**볼록 껍질(convex hull)**을 구하는 문제는 이 다각형의 꼭짓점만 골라내는 문제다. [X-5](#/x-5)에서 만든 CCW 판정 하나로 이 문제를 $O(n \log n)$까지 끌어내릴 수 있다.

## 2. 아이디어

### 2.1 왜 정렬이 먼저인가

점들을 $x$좌표 기준(같으면 $y$좌표 기준)으로 정렬해 놓으면, 볼록 껍질을 "아래쪽 경계"와 "위쪽 경계" 두 조각으로 나눠서 만들 수 있다. 가장 왼쪽 점에서 가장 오른쪽 점까지 아래로 훑는 경계가 **아래쪽 껍질**, 같은 두 점 사이를 위로 훑는 경계가 **위쪽 껍질**이다. 이 두 조각을 이어 붙이면 전체 볼록 껍질이 닫힌 다각형이 된다.

이 방법을 **모노톤 체인(monotone chain)**이라 부른다. 점을 각도로 정렬하는 그라함 스캔과 답은 같지만, 각도 계산이나 기준점 선택의 예외(같은 각도의 점이 여러 개인 경우)가 없어 구현이 더 안정적이다. 정렬 기준이 $x, y$ 좌표뿐이라 표준 정렬 함수 하나로 끝난다.

### 2.2 스택으로 아래쪽 껍질을 쌓는다

정렬된 점을 순서대로 하나씩 스택에 넣는다고 하자. 새 점을 넣기 전에, **스택의 마지막 두 점과 새 점이 시계 방향으로 꺾이는지**(또는 일직선인지) 확인한다. 시계 방향이거나 일직선이면 그 마지막 점은 볼록 껍질의 꼭짓점이 아니다 — 스택에서 빼낸다. 이 pop을 스택 끝의 방향이 반시계(왼쪽으로 꺾임)가 될 때까지 반복한 뒤에야 새 점을 넣는다.

::: widget complexity-plot {"show":["n","nlogn"],"wide":false}
:::

이 위젯의 $n \log n$ 곡선이 이 절에서 의미하는 것은 정렬 비용이다. 정렬에 $O(n \log n)$, 그 뒤 스택을 쌓고 빼는 과정은 각 점이 최대 한 번 들어가고 한 번 나오므로 $O(n)$이다. 전체가 정렬에 지배되어 $O(n \log n)$으로 끝난다.

**왜 이 규칙이 통하는가.** 볼록 껍질의 경계를 따라 걸으면 방향이 계속 같은 쪽(예: 왼쪽)으로만 꺾여야 한다 — 오목한 지점이 있으면 그 다각형은 볼록이 아니다. 새 점을 넣었을 때 직전 꺾임이 반대 방향이면, 그 직전 점은 "안쪽으로 파인" 지점이라는 뜻이고 볼록 껍질에서 제외해야 한다. pop은 이 오목한 지점을 제거하는 동작이다.

아래쪽 껍질은 왼쪽에서 오른쪽으로 훑으며 CCW가 시계 방향(또는 0)일 때 pop한다. 위쪽 껍질은 반대로, 오른쪽에서 왼쪽으로 훑으며 같은 판정을 반복한다. 두 방향 모두 "새 점을 넣기 전, 오목해지는 이전 점들을 걷어낸다"는 동작은 완전히 같다.

### 2.3 왜 $O(n \log n)$ 이하로는 잘 안 내려가는가

볼록 껍질을 구하는 또 다른 방법으로 **기프트 래핑(gift wrapping, Jarvis march)**이 있다. 가장 왼쪽 점에서 시작해, "지금까지 온 방향에서 가장 시계 방향으로 덜 꺾이는 다음 점"을 매번 골라 실을 감듯이 경계를 따라간다. 이 방법은 껍질의 꼭짓점 수를 $h$라 할 때 $O(nh)$다 — 점 전체를 훑는 과정을 꼭짓점 하나를 확정할 때마다 반복하기 때문이다.

$h$가 작으면(점이 대부분 안쪽에 몰려 있으면) 기프트 래핑이 모노톤 체인보다 빠를 수 있다. 그런데 $h$가 $n$에 가까우면(점이 대부분 볼록 껍질 위에 있으면) $O(nh)$는 $O(n^2)$에 근접해 모노톤 체인의 $O(n \log n)$보다 느려진다. **최악의 경우를 기준으로 하면 모노톤 체인이 항상 안전한 선택이고, 이 챕터가 모노톤 체인을 권장하는 이유이기도 하다.** 볼록 껍질은 정렬 기반 알고리즘으로 $O(n \log n)$이 이론적 하한이라는 사실도 알려져 있다 — 정렬 문제 자체를 볼록 껍질 계산으로 환원할 수 있기 때문이다. 이 하한의 증명은 이 책의 범위 밖이지만, "왜 이보다 더 빠른 범용 알고리즘을 찾으려 하지 않는가"에 대한 답은 된다.

## 3. 손으로 따라가기

::: trace
점 6개: `A(0,0) B(1,1) C(2,2) D(3,1) E(4,4) F(2,0)`을 $x$좌표(동률이면 $y$)로 정렬하면 `A(0,0) B(1,1) F(2,0) C(2,2) D(3,1) E(4,4)`가 된다. 이 순서로 **아래쪽 껍질**을 쌓는다. 규칙: 새 점을 넣기 전, 스택 끝 두 점과 새 점이 시계 방향이거나 일직선(`ccw <= 0`)이면 끝 점을 pop한다.

| 처리한 점 | 스택(넣기 전 pop 완료 후) | 이번에 pop된 점 |
|---|---|---|
| A | [A] | 없음(스택 크기 < 2) |
| B | [A, B] | 없음(스택 크기 < 2) |
| F | | |
| C | | |
| D | | |
| E | | |

세 가지를 확인하라.

- [ ] `F(2,0)`을 넣기 직전, 스택 끝 두 점 `A, B`와 `F`로 `ccw(A, B, F)`를 계산하라. 양수인가 음수인가 — pop이 일어나는가
- [ ] `C(2,2)`를 넣기 직전 스택 상태를 보고, `ccw`가 양수(반시계)가 나올 때까지 pop이 몇 번 일어나는지 세어라
- [ ] 아래쪽 껍질을 다 쌓은 뒤 최종 스택에 남는 점이 몇 개인지, 그 점들이 육안으로 봤을 때 실제로 다각형의 "아래쪽 경계"를 이루는지 좌표를 그려서 확인하라
:::

::: answer
| 처리한 점 | 스택(넣기 전 pop 완료 후) | 이번에 pop된 점 |
|---|---|---|
| A | [A] | 없음(스택 크기 < 2) |
| B | [A, B] | 없음(스택 크기 < 2) |
| F | [A, F] | B — `ccw(A,B,F) = (1)(0-0) - (1)(2-0) = -2 < 0`(시계)라 B를 뺀다 |
| C | [A, F, C] | 없음 — `ccw(A,F,C) = (2)(2-0) - (0)(2-0) = 4 > 0`(반시계), pop 없이 넣는다 |
| D | [A, F, D] | C — `ccw(F,C,D) = (0)(1-0) - (2)(3-2) = -2 < 0`(시계)라 C를 뺀다 |
| E | [A, F, D, E] | 없음 — `ccw(F,D,E) = (1)(4-0) - (1)(4-2) = 2 > 0`(반시계), pop 없이 넣는다 |

아래쪽 껍질은 최종적으로 `A(0,0) → F(2,0) → D(3,1) → E(4,4)` 네 점이다.

`B(1,1)`이 pop된 이유는 `A → B → F`로 이었을 때 `B`에서 오른쪽(시계 방향)으로 꺾이기 때문이다 — `A`에서 `F`로 곧장 가는 직선 아래에 `B`가 있지 않고 그 직선 **위**에 있다는 뜻이므로, `B`는 "아래쪽 경계"에서 안쪽으로 들어간 점이라 제외된다. `C(2,2)`도 같은 이유로 `F → C → D`가 시계 방향이라 pop된다.

좌표를 그려 보면 `A(0,0)`에서 `F(2,0)`으로, `F`에서 `D(3,1)`로, `D`에서 `E(4,4)`로 이어지는 선이 실제로 이 여섯 점의 가장 아래쪽 경계와 일치한다. `B`와 `C`는 이 경계보다 위쪽(다각형 안쪽)에 있어 제외되는 것이 맞다.
:::

## 4. 구현

### 4.1 모노톤 체인

::: dual
```python title="모노톤 체인 볼록 껍질"
def ccw(a, b, c):
    return (b[0] - a[0]) * (c[1] - a[1]) - (b[1] - a[1]) * (c[0] - a[0])


def convex_hull(points):
    pts = sorted(set(points))
    if len(pts) <= 2:
        return pts

    lower = []
    for p in pts:
        while len(lower) >= 2 and ccw(lower[-2], lower[-1], p) <= 0:
            lower.pop()          # 시계 방향(또는 일직선)이면 오목한 점을 제거
        lower.append(p)

    upper = []
    for p in reversed(pts):
        while len(upper) >= 2 and ccw(upper[-2], upper[-1], p) <= 0:
            upper.pop()
        upper.append(p)

    return lower[:-1] + upper[:-1]   # 양 끝점이 두 조각에 겹치므로 하나씩 뺀다


points = [(0, 0), (1, 1), (2, 2), (3, 1), (4, 4), (2, 0)]
print(convex_hull(points))
```
```cpp title="모노톤 체인 볼록 껍질"
#include <cstdio>
#include <vector>
#include <algorithm>
using namespace std;

struct Point {
    long long x, y;
    bool operator<(const Point& o) const {
        return x != o.x ? x < o.x : y < o.y;
    }
    bool operator==(const Point& o) const { return x == o.x && y == o.y; }
};

long long ccw(Point a, Point b, Point c) {
    return (b.x - a.x) * (c.y - a.y) - (b.y - a.y) * (c.x - a.x);
}

vector<Point> convex_hull(vector<Point> pts) {
    sort(pts.begin(), pts.end());
    pts.erase(unique(pts.begin(), pts.end()), pts.end());
    if (pts.size() <= 2) return pts;

    vector<Point> lower;
    for (auto& p : pts) {
        while (lower.size() >= 2 &&
               ccw(lower[lower.size() - 2], lower.back(), p) <= 0)
            lower.pop_back();          // 시계 방향(또는 일직선)이면 오목한 점을 제거
        lower.push_back(p);
    }

    vector<Point> upper;
    for (auto it = pts.rbegin(); it != pts.rend(); ++it) {
        while (upper.size() >= 2 &&
               ccw(upper[upper.size() - 2], upper.back(), *it) <= 0)
            upper.pop_back();
        upper.push_back(*it);
    }

    lower.pop_back();
    upper.pop_back();
    lower.insert(lower.end(), upper.begin(), upper.end());   // 양 끝점이 겹치므로 하나씩 뺀다
    return lower;
}

int main() {
    vector<Point> points{{0, 0}, {1, 1}, {2, 2}, {3, 1}, {4, 4}, {2, 0}};
    auto hull = convex_hull(points);
    printf("[");
    for (size_t i = 0; i < hull.size(); i++)
        printf("%s(%lld, %lld)", i ? ", " : "", hull[i].x, hull[i].y);
    printf("]\n");
    return 0;
}
```
:::

```console
[(0, 0), (2, 0), (3, 1), (4, 4)]
```

**복잡도:** 시간 $O(n \log n)$ — 정렬이 $O(n \log n)$이고, 아래쪽·위쪽 껍질을 쌓는 두 번의 순회에서 각 점은 최대 한 번 push되고 최대 한 번 pop된다(pop되면 다시 push되지 않는다). 그래서 순회 자체는 $O(n)$이고 정렬이 전체를 지배한다. 공간 $O(n)$ — 정렬된 점 배열과 두 스택.

`ccw`가 [X-5](#/x-5)의 함수와 정확히 같다는 것에 주목하라. 이 챕터는 그 판정 함수를 **정렬 뒤의 볼록성 검사 도구**로 재사용할 뿐, 새로운 기하 연산을 만들지 않는다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 중복 점 제거 | `sorted(set(points))` — 집합으로 중복을 없애고 정렬까지 한 번에 | `sort` 후 `unique` + `erase` — STL은 정렬된 상태에서만 인접 중복을 지운다([0-7](#/0-7)) |
| 좌표 비교 연산자 | 튜플은 사전식 비교를 기본 제공한다 | `Point`에 `operator<`를 직접 정의해야 `sort`가 동작한다 |
| 좌표 오버플로 | 임의 정밀도라 걱정 없음 | `ccw` 내부 곱이 좌표 범위의 제곱이라 `long long`을 미리 잡는다([X-5](#/x-5)와 같은 이유) |

::: pitfall
- **pop 조건에 `<= 0` 대신 `< 0`을 쓴다.** 일직선(`ccw == 0`)인 점을 볼록 껍질에 남기고 싶은지 빼고 싶은지는 문제마다 다르다. "변 위의 점은 세지 않는다"는 요구(예: [X-6 연습문제 1번](#/x-6))에서는 `<= 0`이 맞지만, 일직선 위의 중간 점도 꼭짓점으로 세야 하면 `< 0`으로 바꿔야 한다. 두 경우를 구분하지 않고 하나만 외워서 쓰면 반례가 나온다.
- **`lower[:-1] + upper[:-1]` 대신 두 리스트를 통째로 이어 붙인다.** 정렬의 양 끝점(가장 왼쪽 점과 가장 오른쪽 점)은 아래쪽 껍질과 위쪽 껍질 모두에 나타난다. 끝을 하나씩 자르지 않으면 이 두 점이 결과에 중복으로 들어간다.
- **좌표 중복을 제거하지 않고 그대로 정렬한다.** 같은 점이 여러 번 들어오면 `ccw`가 `0`을 반환하는 자리가 늘어나 스택 로직이 불필요하게 꼬인다. 정렬 전에 중복을 없애는 것이 안전하다.
- **아래쪽·위쪽 껍질을 따로 만든다는 것을 잊고 한 번의 순회로 끝내려 한다.** 정렬된 순서 그대로 한 방향 스택만 쌓으면 위쪽 경계가 통째로 빠진다. 두 번 쌓고 이어 붙이는 구조 자체가 이 알고리즘의 핵심이다.
:::

## 5. 어디에 쓰이는가

**로봇 footprint 생성이 이 챕터의 직접적인 응용이다.** 로봇의 각 관절·모서리 좌표를 3차원에서 바닥 평면으로 투영하면 점 집합이 되고, 그 점들의 볼록 껍질이 로봇을 감싸는 최소 다각형이다. 경로 계획기는 로봇의 정확한 형태 대신 이 다각형 하나로 충돌 검사를 하는 경우가 많다 — 다각형이 원래 형태보다 크게 감싸는 대신([X-5](#/x-5)의 선분 교차·내부 판정이 이 다각형에 대해서만 반복되면 되므로) 계산이 단순해지고 빨라진다. 여러 개의 로봇이나 장애물을 하나의 안전 여유 구역으로 합칠 때도 각 점들을 모아 볼록 껍질을 다시 구하는 방식이 쓰인다.

이 단순화는 항상 **실제 형태보다 크게** 감싼다는 대가를 치른다는 것도 같이 알아 둬야 한다. 오목한 로봇(예: ㄷ자 형태의 팔)이라면 볼록 껍질은 그 오목한 틈까지 채워서 감싸므로, 그 틈으로 지나갈 수 있는 장애물과의 충돌을 실제보다 더 자주 "충돌"로 판정한다. 실무에서는 이 여유를 안전 마진으로 받아들이거나, 로봇을 여러 개의 볼록 부분으로 나눠 각각의 볼록 껍질을 따로 쓰는 절충을 택한다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "모든 점을 포함하는 가장 작은 볼록 다각형", "볼록 껍질을 이루는 점의 개수", "외곽선을 이루는 점"
- 제약조건: 점 개수 $n \le 10^5$ 안팎이면 $O(n \log n)$ 정렬 기반이 여유롭다. $n^3$ 무차별 대조는 $n$이 수백 개를 넘는 순간 시간 제한을 넘긴다
- 혼동 주의: 세 점의 방향 판정 하나만 필요하면 [X-5](#/x-5)로 충분하다 — 다각형 자체를 **구성**해야 할 때만 이 챕터로 온다. 점들 사이의 최대 거리(지름)나 최소 폭을 구하는 문제는 볼록 껍질을 구한 뒤 회전하는 캘리퍼스로 이어지는데, 이 책의 목표 난도 밖이다
- 반례 함정: 모든 점이 일직선 위에 있거나, 점이 3개 미만이면 "볼록 다각형"이라는 정의 자체가 흔들린다. `pts` 정렬 뒤 크기가 2 이하인 경우를 특수 처리하지 않으면 스택 인덱스 접근에서 예외가 난다
:::

::: interview
**"그라함 스캔과 모노톤 체인의 차이는 무엇입니까."**
"둘 다 $O(n \log n)$이고 결과도 같습니다. 그라함 스캔은 기준점 하나를 고르고 나머지 점을 그 기준점에서 본 각도로 정렬하는데, 같은 각도의 점이 여러 개면 별도 처리가 필요합니다. 모노톤 체인은 각도 대신 $x, y$ 좌표만으로 정렬하기 때문에 그 예외가 없고 구현이 더 단순합니다."

**"기프트 래핑은 왜 항상 쓰지 않습니까."**
"시간 복잡도가 $O(nh)$라 껍질의 꼭짓점 수 $h$에 좌우되기 때문입니다. $h$가 작을 것이라는 보장이 없는 입력에서는 $O(n^2)$에 가까워질 수 있어, 최악의 경우를 기준으로 하면 $O(n \log n)$인 모노톤 체인이 더 안전합니다."
:::

## 연습

::: quiz
**1. 백준 1708 볼록 껍질 (골드)** — https://www.acmicpc.net/problem/1708
- 신호: "볼록 껍질을 이루는 점의 개수를 구하는 프로그램"을 그대로 요구한다. 이 챕터의 원형 문제다.
- 상태: 없다. 점 집합을 받아 §4.1의 `convex_hull`을 적용하고 길이만 출력한다.
- 자료구조: 정수 좌표 배열. "볼록 껍질의 변 위에 여러 점이 있으면 양 끝 점만 센다"는 단서가 pop 조건을 `<= 0`으로 잡아야 하는 이유다 — 변 위의 중간 점은 꼭짓점으로 세지 않는다.

**2. 백준 2166 다각형의 면적 (골드 5)** — https://www.acmicpc.net/problem/2166
- 신호: 다각형 꼭짓점이 순서대로 주어지고 넓이를 구하라고 한다. 볼록 껍질을 구하는 문제는 아니지만, 이 챕터에서 구한 볼록 다각형의 "크기"를 재는 자연스러운 다음 단계다.
- 상태: 없다. 꼭짓점을 순서대로 순회하며 CCW의 외적(신발끈 공식)을 누적한다.
- 자료구조: 정수 좌표 배열. [X-5](#/x-5)에서 "CCW의 절댓값은 삼각형 넓이의 두 배"라고 짚은 사실을 다각형 전체로 확장하면, 원점과 각 변이 이루는 부호 있는 넓이의 합이 다각형 전체 넓이의 두 배가 된다는 것이 이 문제의 핵심이다.
:::

## 요약

- 볼록 껍질은 점 집합을 감싸는 가장 작은 볼록 다각형이다. 무차별 대조는 $O(n^3)$이라 점이 수천 개만 되어도 못 쓴다.
- 모노톤 체인은 점을 $x, y$ 좌표로 정렬한 뒤 **아래쪽 껍질**과 **위쪽 껍질**을 따로 쌓아 이어 붙인다. 그라함 스캔과 결과는 같지만 각도 정렬의 동률 예외가 없어 더 안정적이다.
- 새 점을 스택에 넣기 전, 끝 두 점과 새 점이 시계 방향(또는 일직선)이면 pop한다 — [X-5](#/x-5)의 CCW를 그대로 재사용하는 자리다.
- pop이 일어나는 조건(`<= 0` 대 `< 0`)은 변 위의 점을 볼록 껍질에 포함할지 여부에 따라 문제마다 달라진다.
- 시간 $O(n \log n)$은 정렬이 지배한다. 스택을 쌓고 비우는 과정 자체는 각 점이 최대 한 번씩만 오가므로 $O(n)$이다.
- 로봇 footprint 생성이 이 알고리즘의 직접적인 실무 응용이다 — 복잡한 실제 형태 대신 볼록 껍질 하나로 충돌 검사를 단순화한다.
