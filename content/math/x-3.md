# X-3 모듈러 연산과 분할 정복 거듭제곱

::: lead
답이 정수 하나인데 그 정수가 수만 자리다. 이 문제를 실제로 풀 수 있는 크기로 접는 두 가지 기법을 본다.
:::

## 1. 문제

지문이 이렇게 끝난다. **"경우의 수를 $1{,}000{,}000{,}007$로 나눈 나머지를 구하라."** 처음 보면 이상한 요구다. 나머지를 왜 물을까. 답이 궁금하면 그냥 답을 내놓으면 될 텐데.

이유는 크기다. 순열 $20!$은 이미 19자리다. 조합론 문제의 답은 종종 지수적으로 불어나서 수천 자리, 수만 자리가 된다. Python은 임의 정밀도 정수라 계산 자체는 되지만 출력에 그 큰 수를 그대로 요구하면 채점이 문자열 비교로 느려지고, C++은 애초에 `long long`도 못 담는다. **나머지 연산은 이 문제를 우회한다.** $10^9+7$로 나눈 나머지는 항상 10자리 이하이고, 두 언어 모두 고정폭 정수 하나로 담긴다.

문제는 나머지 연산이 공짜가 아니라는 데 있다. `(a + b) % m`과 `(a * b) % m`은 각 항을 미리 줄여 두면 그대로 성립한다 — 곱셈 전에 두 인자를 $m$ 미만으로 만들면 곱해도 오버플로를 피할 수 있다. 그런데 **거듭제곱** $a^n \bmod m$을 "$n$번 곱하고 그때마다 나머지를 취한다"로 짜면 $n$이 크다는 문제 자체가 그대로 남는다. $n \le 10^9$인 문제에서 반복 곱셈은 $10^9$번 도는 루프이고, 시간 제한 1~2초에 걸린다([0-9 N 범위로 알고리즘 역산하기](#/0-9)). **지수를 줄이는 방법이 따로 필요하다.**

두 번째 문제는 나눗셈이다. 조합 $\binom{n}{k} = n! / (k! (n-k)!)$처럼 답에 나눗셈이 들어 있는데, 나머지 연산에는 일반적인 나눗셈이 없다. $(a / b) \bmod m$은 $(a \bmod m) / (b \bmod m)$과 같지 않다 — 정수 나눗셈이 나머지를 취하는 순서와 안 맞는다. 분자를 나머지로 줄인 순간 원래 나눗셈이 무엇을 의미했는지가 사라진다. **곱셈으로 바꿔치기할 방법**이 필요하고, 그것이 모듈러 역원이다.

## 2. 아이디어

### 2.1 분할 정복 거듭제곱 — 지수를 반으로 접는다

$a^8$을 구한다고 하자. 순진하게 짜면 $a \times a \times \cdots \times a$를 일곱 번 곱한다. 그런데 $a^8 = (a^4)^2$이고, $a^4 = (a^2)^2$이고, $a^2 = a \times a$다. 곱셈은 **세 번**으로 끝난다.

일반화하면 이렇다.

$$
a^n =
\begin{cases}
1 & n = 0 \\
(a^{n/2})^2 & n \text{이 짝수} \\
a \times a^{n-1} & n \text{이 홀수}
\end{cases}
$$

짝수면 지수를 절반으로 접고, 홀수면 밑을 하나 떼어 짝수로 만든다. **접는 동작은 [VIII-1 DP 사고 절차](#/viii-1)의 분할 정복 점화식과 뼈대가 같다** — 큰 문제 하나를 절반 크기 문제 하나로 줄이는 것이지, DP처럼 여러 부분 문제로 쪼개는 것이 아니다. 이진 탐색이나 이진 탐색 트리의 높이가 $\log n$인 것과 같은 이유로, 지수가 반으로 계속 접히면 접는 횟수는 $n$의 이진수 자릿수를 넘지 않는다.

::: widget complexity-plot {"show":["log","n"],"wide":true}
:::

위젯의 두 곡선이 이 절의 핵심을 보여준다. $n$번 곱하는 판은 직선으로 오르고, 절반씩 접는 판은 로그 곡선으로 거의 눕는다. $n = 10^9$에서 직선은 $10^9$이고 로그 곡선은 30 언저리다 — **여덟 자릿수 차이**다. 이 격차가 시간 제한 안에 들어가느냐를 가른다.

### 2.2 모듈러 역원 — 나눗셈을 곱셈으로 바꾼다

"$b$로 나누기"를 정수 나머지 연산 안에서 하려면, **$b$에 곱하면 $1 \bmod m$이 되는 수** $b^{-1}$을 찾아 그것을 곱하면 된다. $b \times b^{-1} \equiv 1 \pmod m$을 만족하는 $b^{-1}$을 $b$의 **모듈러 역원**이라 부른다. 역원이 존재하는 조건은 $\gcd(b, m) = 1$, 즉 $b$와 $m$이 서로소일 때뿐이다([X-1 정수론](#/x-1)의 GCD가 여기서 다시 쓰인다).

역원을 구하는 방법은 두 갈래다.

**$m$이 소수일 때 — 페르마의 소정리.** $m$이 소수이고 $b$가 $m$의 배수가 아니면 $b^{m-1} \equiv 1 \pmod m$이 항상 성립한다. 양변을 $b$로 나누면 $b^{m-2} \equiv b^{-1} \pmod m$이다. **역원이 거듭제곱 하나로 바뀐다.** $10^9+7$처럼 문제에서 미리 소수 $m$을 준다면, §2.1의 분할 정복 거듭제곱을 $a^{m-2} \bmod m$에 그대로 적용하면 끝이다. 새 알고리즘이 필요 없다.

**$m$이 소수가 아니거나 소수 여부를 모를 때 — 확장 유클리드.** 유클리드 호제법([X-1](#/x-1))을 거꾸로 추적하면 $bs + mt = \gcd(b, m)$을 만족하는 정수 $s, t$를 계산할 수 있다. $\gcd(b, m) = 1$이면 이 식은 $bs \equiv 1 \pmod m$이 되고, $s$가 곧 역원이다. 이 방법은 $m$이 소수인지 여부와 무관하게 서로소이기만 하면 항상 된다 — **더 일반적이지만 코드가 한 단계 더 길다.**

실전에서는 $m$이 소수로 주어지는 경우가 압도적으로 많고(문제 대부분이 $10^9+7$이나 $998244353$을 쓴다), 그럴 때는 페르마의 소정리 쪽이 짧고 이미 만들어 둔 거듭제곱 함수를 재사용한다. $m$이 합성수이거나 애초에 소수성을 보장할 수 없는 문제에서만 확장 유클리드로 넘어간다.

## 3. 손으로 따라가기

::: trace
$3^{13} \bmod 1000$을 분할 정복으로 구한다. 규칙: `n`이 짝수면 `half = power(a, n//2, m)`을 구해 `half * half % m`을 돌려주고, 홀수면 `a * power(a, n-1, m) % m`을 돌려준다. `n == 0`이면 `1`을 돌려준다.

먼저 **호출이 파고드는 순서**대로 `n`을 적는다(내려가는 방향). 맨 밑에서 기저에 닿으면, 이번에는 **거슬러 올라오며** 각 호출의 반환값을 채운다. 관찰할 것은 이 둘이다 — `n`이 반으로 접히는 속도, 그리고 그 접힘이 실제 곱셈으로 되돌아오는 값.

|---|---|---|---|---|

| 1 | 12 | 짝 | 6 | |

세 가지를 확인하라.

- [ ] `n`이 13에서 0까지 내려가는 데 호출이 몇 번 걸리는가. $\log_2 13 \approx 3.7$과 비교하라
- [ ] 기저(`n=0`, 반환값 1)부터 거슬러 올라가며 반환값 열을 전부 채워라. `3^13 = 1{,}594{,}323`의 마지막 세 자리와 맨 위 행의 답을 대조하라

| 깊이 | n | 홀/짝 | 다음에 부르는 n | 반환값(거슬러 올라올 때 채운다) |
|---|---|---|---|---|
| 0 | 13 | 홀 | 12 | $3 \times 441 \bmod 1000 = 323$ |
| 1 | 12 | 짝 | 6 | $729^2 \bmod 1000 = 441$ |
| 2 | 6 | 짝 | 3 | $27^2 \bmod 1000 = 729$ |
| 3 | 3 | 홀 | 2 | $3 \times 9 \bmod 1000 = 27$ |
| 4 | 2 | 짝 | 1 | $3^2 \bmod 1000 = 9$ |
| 5 | 1 | 홀 | 0 | $3 \times 1 \bmod 1000 = 3$ |
| 6 | 0 | 기저 | — | $1$ |

내려가는 길에 `n`은 $13 \to 12 \to 6 \to 3 \to 2 \to 1 \to 0$으로 움직인다. 짝수 칸에서는 정확히 절반이 되고, 홀수 칸에서는 1이 줄어 바로 다음 칸에서 짝수로 접힌다 — **홀수가 두 번 연달아 나오지 않는다.**

거슬러 올라오는 값은 맨 아래(`n=0`, 반환값 1)에서 시작해 위로 채운다. `n=1`은 $3 \times 1 = 3$, `n=2`는 그 값을 제곱해 $3^2 = 9$, `n=3`은 밑을 하나 더 곱해 $3 \times 9 = 27$, `n=6`은 제곱해 $27^2 = 729$, `n=12`는 다시 제곱해 $729^2 = 531{,}441 \equiv 441$, 마지막 `n=13`은 $3 \times 441 = 1{,}323 \equiv 323$.

실제로 $3^{13} = 1{,}594{,}323$이고 마지막 세 자리는 **323**이다. 표의 맨 위 행과 일치한다.

**첫 번째.** $n=13$에서 $n=0$까지 호출이 7번(위 표의 행 수)이다. $\log_2 13 \approx 3.7$인데 홀수 보정이 세 번 끼어들어(13, 3, 1이 홀수) 7이 됐다 — 그래도 자릿수 감각은 $\log_2 n$ 그대로다.

**세 번째.** $10^9 \approx 2^{30}$이므로 $\log_2(10^9) \approx 30$이다. 홀수 보정을 다 더해도 60을 넘지 않는다. 반복 곱셈이었다면 $10^9$줄이었을 표가 60줄 안으로 줄어드는 것, 이것이 §2.1의 로그 곡선이 의미하는 전부다.
:::

## 4. 구현

### 4.1 분할 정복 거듭제곱

::: dual
```python title="분할 정복 거듭제곱"
def power(a, n, m):
    if n == 0:                    # 기저: 아무것도 안 곱한 값
        return 1
    if n % 2 == 0:                # 짝수: 지수를 절반으로 접는다
        half = power(a, n // 2, m)
        return half * half % m
    return a * power(a, n - 1, m) % m   # 홀수: 밑을 하나 떼어 짝수로 만든다


print(power(3, 13, 1000))         # 1,594,323 의 마지막 세 자리
print(power(2, 1_000_000_000, 1_000_000_007))
```
```cpp title="분할 정복 거듭제곱"
#include <cstdio>
using namespace std;

long long power(long long a, long long n, long long m) {
    if (n == 0) return 1;                    // 기저: 아무것도 안 곱한 값
    if (n % 2 == 0) {                         // 짝수: 지수를 절반으로 접는다
        long long half = power(a, n / 2, m);
        return half * half % m;
    }
    return a * power(a, n - 1, m) % m;        // 홀수: 밑을 하나 떼어 짝수로 만든다
}

int main() {
    printf("%lld\n", power(3, 13, 1000));
    printf("%lld\n", power(2, 1000000000LL, 1000000007LL));
    return 0;
}
```
:::

```console
323
140625001
```

**복잡도:** 시간 $O(\log n)$ — `n`이 짝수 갈래를 지날 때마다 절반이 되고, 홀수 갈래는 짝수로 넘어가기 위한 보정이라 연속으로 두 번 이상 나오지 않는다. 재귀 깊이가 $n$의 이진수 자릿수를 넘지 않으므로 곱셈 횟수도 $O(\log n)$이다. 공간은 재귀 호출 스택이 $O(\log n)$.

| 언어 차이 | Python | C++ |
|---|---|---|
| 정수 오버플로 | 없음. `a`, `m`이 아무리 커도 `half * half`가 그대로 계산된다 | `long long` 기준 약 $9.2 \times 10^{18}$이 한도다. `m < 10^9`이면 `half * half`가 약 $10^{18}$로 한도 안이지만, `m`을 더 키우면 `__int128`이 필요하다 |
| 재귀 깊이 | 기본 1000, $n \le 10^9$이면 깊이 60 안팎이라 문제없다([0-11](#/0-11)) | 스택 한도까지. 같은 깊이라 문제없다 |
| 내장 지원 | `pow(a, n, m)`이 같은 알고리즘을 C로 구현해 제공한다 | 표준에 없다. 직접 짜거나 라이브러리를 쓴다 |

📖 `pow(base, exp, mod=None)` — 세 번째 인자를 주면 분할 정복 거듭제곱을 **C 레벨에서** 수행한다. $O(\log n)$, 위 재귀와 같은 알고리즘이고 재귀 호출 오버헤드가 없어 더 빠르다.
   쓰는 곳: 이 절 전체, 페르마의 소정리 역원.
   C++ 대응: 없음. 위 함수를 직접 쓰거나 반복문으로 다시 짠다(아래 `pitfall` 참고).

::: pitfall
- **`a ** n % m`으로 쓴다.** Python은 임의 정밀도라 돌기는 하지만 `a ** n`이 나머지를 취하기 전에 **완전한 크기로** 계산된다. $n$이 커지면 이 중간값 자체가 느려진다. 나머지를 취할 자리를 뒤로 미루지 마라 — `pow(a, n, m)`을 써라.
- **재귀를 반복문 없이 홀수마다 한 단계씩 늘린다고 착각한다.** 홀수 처리는 지수를 1만 줄이지만, 그 뒤에 바로 짝수가 되어 절반으로 접힌다. 홀수 갈래가 연속으로 반복되지 않는다는 것을 손추적에서 직접 확인하라.
- **곱셈 중간에 나머지를 안 취한다.** `half * half`를 구한 뒤에 `% m`을 빠뜨리면 다음 재귀 단계에서 값이 계속 불어나 C++에서는 오버플로로 조용히 틀린 답을 낸다.
:::

### 4.2 모듈러 역원 — 페르마의 소정리와 확장 유클리드

::: dual
```python title="모듈러 역원 — 두 가지 방법"
def power(a, n, m):
    if n == 0:
        return 1
    if n % 2 == 0:
        half = power(a, n // 2, m)
        return half * half % m
    return a * power(a, n - 1, m) % m


def inv_fermat(b, m):
    """m 이 소수일 때. b^(m-2) mod m 이 곧 역원이다."""
    return power(b, m - 2, m)


def ext_gcd(a, b):
    """a*s + b*t = gcd(a, b) 를 만족하는 (gcd, s, t)."""
    if b == 0:
        return a, 1, 0
    g, s1, t1 = ext_gcd(b, a % b)
    return g, t1, s1 - (a // b) * t1


def inv_extgcd(b, m):
    """m 이 소수가 아니어도 gcd(b, m) == 1 이면 동작한다."""
    g, s, _ = ext_gcd(b, m)
    if g != 1:
        raise ValueError("역원이 존재하지 않는다 — b와 m이 서로소가 아니다")
    return s % m


MOD = 1_000_000_007
print(inv_fermat(3, MOD), inv_extgcd(3, MOD))       # 소수 나머지: 두 값이 같다
print(inv_extgcd(3, 10))                            # 10은 합성수라 페르마는 못 쓴다
```
```cpp title="모듈러 역원 — 두 가지 방법"
#include <cstdio>
#include <stdexcept>
using namespace std;

long long power(long long a, long long n, long long m) {
    if (n == 0) return 1;
    if (n % 2 == 0) {
        long long half = power(a, n / 2, m);
        return half * half % m;
    }
    return a * power(a, n - 1, m) % m;
}

// m 이 소수일 때. b^(m-2) mod m 이 곧 역원이다.
long long inv_fermat(long long b, long long m) {
    return power(b, m - 2, m);
}

// a*s + b*t = gcd(a, b) 를 만족하는 (gcd, s, t).
long long ext_gcd(long long a, long long b, long long& s, long long& t) {
    if (b == 0) { s = 1; t = 0; return a; }
    long long s1, t1;
    long long g = ext_gcd(b, a % b, s1, t1);
    s = t1;
    t = s1 - (a / b) * t1;
    return g;
}

// m 이 소수가 아니어도 gcd(b, m) == 1 이면 동작한다.
long long inv_extgcd(long long b, long long m) {
    long long s, t;
    long long g = ext_gcd(b, m, s, t);
    if (g != 1) throw runtime_error("역원이 존재하지 않는다 — b와 m이 서로소가 아니다");
    return ((s % m) + m) % m;
}

int main() {
    const long long MOD = 1000000007LL;
    printf("%lld %lld\n", inv_fermat(3, MOD), inv_extgcd(3, MOD));
    printf("%lld\n", inv_extgcd(3, 10));
    return 0;
}
```
:::

```console
333333336 333333336
7
```

$3 \times 333{,}333{,}336 \bmod (10^9+7) = 1$이고, $3 \times 7 \bmod 10 = 21 \bmod 10 = 1$이다. 두 값 다 검산이 된다.

**복잡도:** 페르마의 역원은 시간 $O(\log m)$ — 내부가 §4.1의 거듭제곱 그대로다. 확장 유클리드는 시간 $O(\log(\min(b, m)))$ — 일반 유클리드 호제법과 같은 재귀 깊이이고, 각 단계가 나눗셈 한 번이라 상수도 같다([X-1](#/x-1)). 둘 다 로그 시간이라 어느 쪽을 써도 성능 차이는 크지 않다 — **선택 기준은 속도가 아니라 $m$이 소수인지 여부다.**

| 언어 차이 | Python | C++ |
|---|---|---|
| 음수 나머지 | `%`가 항상 `m`과 같은 부호를 낸다. `s % m`이 자동으로 양수 | `%`가 피제수의 부호를 따른다. `s`가 음수면 결과도 음수라 **`(s % m + m) % m`으로 보정해야 한다** — [0-5](#/0-5)의 나눗셈 규칙과 같은 함정 |
| 참조 반환 | `ext_gcd`가 튜플 `(g, s, t)`를 그대로 반환 | 참조 매개변수 `s, t`로 값을 밖으로 내보내고 `g`만 반환값으로 쓴다. 튜플 대신 관용적으로 이렇게 짠다 |
| 예외 | `raise ValueError(...)` | `throw runtime_error(...)` — 잡지 않으면 프로그램이 종료된다 |

::: pitfall
- **음수 나머지를 그대로 둔다.** C++에서 확장 유클리드가 낸 `s`가 음수이면 `% m`을 취해도 부호가 안 바뀐다. `(s % m + m) % m`을 습관으로 붙여라.
- **$m$이 소수인지 확인하지 않고 페르마의 소정리를 쓴다.** $m$이 합성수면 $b^{m-2} \bmod m$은 역원이 아닌 아무 값이다. 예제가 우연히 맞아도 다른 입력에서 틀린다. 문제가 준 $m$이 소수라고 **명시**했는지 지문에서 확인하라 — $10^9+7$과 $998{,}244{,}353$은 소수이고 자주 나온다.
- **$\gcd(b, m) \ne 1$인 입력을 거른다.** 역원이 아예 없는 경우다. 확장 유클리드 판에서는 `g != 1`을 반드시 검사해야 하고, 페르마 판에서는 $b$가 $m$의 배수이면 $b^{m-2} \bmod m = 0$이 나와 조용히 틀린다.
:::

## 5. 어디에 쓰이는가

**RSA를 비롯한 공개키 암호의 핵심 연산이 모듈러 거듭제곱이다.** 암호화·복호화가 전부 $c \equiv m^e \pmod n$ 형태의 계산이고, $e$나 개인 키에 해당하는 지수가 수백~수천 비트인 정수라 순진한 반복 곱셈은 애초에 불가능하다. 분할 정복 거듭제곱이 그 계산을 실용적인 시간으로 끌어내린다. 암호학 자체의 안전성 증명이나 키 생성 절차는 이 책의 범위 밖이지만, **크기가 감당 안 되는 지수를 로그 시간으로 접는다는 이 절의 아이디어는 그대로 재사용된다.**

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "나머지를 구하라", "$10^9+7$로 나눈 나머지", "매우 커질 수 있으므로", 지수나 항의 개수가 $10^9$ 이상으로 큰 수
- 제약조건: 지수 $n \le 10^{18}$ 정도까지도 $O(\log n)$이면 통과한다. 나눗셈이 섞여 있고 나머지가 소수면 페르마, 소수가 아니거나 소수 여부가 불확실하면 확장 유클리드
- 혼동 주의: 밑과 지수가 둘 다 작고 나머지 요구도 없으면 그냥 반복 곱셈으로 충분하다 — 분할 정복은 지수가 커서 반복이 시간 제한을 넘길 때 쓰는 최적화다. 행렬이나 선형 점화식의 거듭제곱은 같은 뼈대를 밑이 행렬인 곱셈에 적용한 것뿐이다
- 반례 함정: $m$이 소수인지 확인하지 않고 페르마의 소정리로 역원을 구하면, 예제의 $m$이 소수라서 통과하고 다른 테스트 케이스에서 조용히 틀린다. 확장 유클리드에서 음수 나머지를 보정하지 않는 것도 같은 부류다
:::

::: interview
**"$a^n \bmod m$을 왜 반복 곱셈으로 짜면 안 됩니까."**
"$n$이 커지면 곱셈 횟수가 $n$에 비례해 늘어서 $n$이 $10^9$쯤이면 시간 제한을 넘깁니다. 지수를 절반으로 접으면 $a^n = (a^{n/2})^2$이 되어 곱셈 횟수가 $\log_2 n$으로 줄고, $n = 10^9$이면 30번 안팎이면 끝납니다." 이어서 **"나눗셈이 섞이면 나머지 연산에서 바로 나눌 수 없으니 모듈러 역원을 구해서 곱셈으로 바꾼다"**를 붙이면 완성이다.
:::

## 요약

- 나머지 연산은 답이 지수적으로 커지는 문제를 고정폭 정수로 담기 위한 장치다. 곱셈·덧셈은 매 단계 나머지를 취해도 되지만 거듭제곱은 지수 자체가 문제다.
- **분할 정복 거듭제곱**은 $a^n = (a^{n/2})^2$(짝수) 또는 $a \cdot a^{n-1}$(홀수)로 지수를 접어 $O(\log n)$에 계산한다. [VIII](#/viii-1)의 분할 정복 DP와 같은 "문제를 절반으로 줄인다"는 뼈대다.
- 나머지 연산에는 일반적인 나눗셈이 없다. **모듈러 역원**을 곱하는 것으로 나눗셈을 대신한다.
- $m$이 소수면 **페르마의 소정리**로 $b^{m-2} \bmod m$이 역원이다 — 이미 만든 거듭제곱 함수를 그대로 재사용한다.
- $m$이 소수가 아니거나 소수 여부가 불확실하면 **확장 유클리드**로 $bs + mt = \gcd(b, m)$의 $s$를 구한다. 역원이 존재하려면 $\gcd(b, m) = 1$이어야 한다.
- Python `pow(a, n, m)`은 분할 정복 거듭제곱을 C 레벨로 제공한다. C++에는 대응 함수가 없어 직접 짠다.
- C++에서 확장 유클리드가 낸 역원은 음수일 수 있다. `(s % m + m) % m`으로 항상 보정하라.
