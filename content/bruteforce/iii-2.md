# III-2 순열·조합·부분집합 생성

::: lead
"N개 중에서 고르는 모든 경우"를 만들어야 할 때, 언제 라이브러리를 부르고 언제 직접 짜는가.
:::

## 1. 문제

지문이 이렇게 끝난다고 하자. **"N명을 두 팀으로 나누는 모든 방법을 시도해 능력치 차이의 최솟값을 구하라."** N은 20 이하다.

여기에 알고리즘은 없다. 모든 경우를 만들어 하나씩 계산하면 된다. 그런데 코드를 열면 손이 멈춘다. N이 4면 팀을 고르는 `for`가 몇 겹 필요한가. 2명씩이면 두 겹이고 3명씩이면 세 겹이다. **몇 겹인지가 입력에 달렸다.** [III-1 재귀 사고법](#/iii-1)에서 본 그 벽이다.

두 번째 벽은 중복이다. 4명 중 2명을 뽑는 코드를 두 겹 `for`로 짜면 `(1,2)`와 `(2,1)`이 둘 다 나오고 `(1,1)`도 나온다. 팀을 나누는 문제에서 `{1,2}`와 `{2,1}`은 같은 답이다. 세는 대상이 6개인데 16개를 만들어 놓고 세면 답이 두 배 넘게 부풀거나, 중복 제거를 얹느라 코드가 두 배가 된다.

세 번째 벽은 크기다. 만들 것이 몇 개인지 모르고 시작하면 시간이 어디서 터지는지도 모른다. 순열은 $n!$, 조합은 $\binom{n}{k}$, 부분집합은 $2^n$이다. $10! = 3{,}628{,}800$이고 $11! = 39{,}916{,}800$이다. **한 칸 늘리는 데 열한 배가 든다.** 이 숫자를 먼저 보지 않으면 완전탐색으로 풀 수 있는 문제인지조차 판정할 수 없다.

## 2. 아이디어

::: widget complexity-plot {"show":["n","n2","2n","fact"],"wide":true}
:::

위젯의 로그 축에서 $O(n)$과 $O(n^2)$은 완만한 직선이지만 $O(2^n)$과 $O(n!)$은 거의 수직으로 선다. "1초 안에 되는 선"을 $O(n^2)$은 $n \approx 10^4$에서 넘고, $O(2^n)$은 $n \approx 27$에서, $O(n!)$은 $n \approx 11$에서 넘는다. **완전탐색이 가능한 N의 범위가 이 세 곡선으로 정해진다.** 표로 옮기면 이렇다. 자세한 역산은 [0-9 N 범위로 알고리즘 역산하기](#/0-9)에 있다.

| 지문의 N | 만들 수 있는 것 | 개수 |
|---|---|---|
| N ≤ 8 | 순열 $n!$ | 40,320 |
| N ≤ 10 | 순열 $n!$ (경계) | 3,628,800 |
| N ≤ 20 | 부분집합 $2^n$ | 1,048,576 |
| N ≤ 25 | 부분집합 $2^n$ (경계) | 33,554,432 |
| N ≤ 40 | 절반씩 나눠서 $2^{n/2}$ | — |

==지문에 `N ≤ 8`이 적혀 있으면 그것은 제약이 아니라 힌트다.== 그 숫자로 할 수 있는 것이 순열 전수 조사밖에 없기 때문이다.

### 2.1 세 대상은 관점 두 개에서 나온다

순열·조합·부분집합은 서로 다른 세 알고리즘이 아니다. **선택 트리를 어떤 축으로 세우느냐**의 차이다.

**자리 중심.** 첫째 자리에 무엇을 놓을지, 둘째 자리에 무엇을 놓을지를 정해 나간다. 자리마다 남은 원소 전부가 후보이므로 트리의 갈래가 $n, n-1, n-2, \dots$로 줄고 잎이 $n!$개다. 이것이 **순열**이다. 순서가 결과에 반영된다.

**원소 중심.** 원소를 하나씩 보며 "넣는다 / 뺀다"를 정한다. 원소마다 갈래가 둘이므로 잎이 $2^n$개다. 이것이 **부분집합**이다. 순서 개념이 아예 없다.

**조합은 부분집합에 크기 제한을 건 것**이고, 동시에 순열에서 순서를 죽인 것이기도 하다. 구현에서 순서를 죽이는 장치는 하나뿐이다. `start` 인덱스를 넘겨 **자기보다 앞의 원소는 다시 보지 않게** 만든다. `{1,2}`를 만든 가지에서는 `{2,1}`이 아예 생기지 않는다. 중복을 만들어 놓고 지우는 것이 아니라 처음부터 안 만드는 것이다.

```text nolines
   place-centric      pos0: 1 2 3 4        <- 4 ways
                      pos1:   2 3 4        <- 3 ways      leaves = 4! = 24
                      pos2:     3 4

   item-centric       item1: in / out      <- 2 ways
                      item2: in / out      <- 2 ways      leaves = 2^4 = 16
                      item3: in / out
```

### 2.2 라이브러리를 부를 것인가

두 언어 모두 표준 라이브러리에 순열 생성이 있다. 그런데 갈라지는 지점이 뚜렷하다.

**라이브러리가 이기는 경우:** 만들 것을 전부 만들고 하나씩 평가하면 되는 경우다. 코드가 한 줄이고 C로 구현되어 있어 직접 짠 재귀보다 몇 배 빠르다. 대회장에서 3초에 끝난다.

**직접 짜야 하는 경우:** ==중간에 자를 수 있을 때다.== 라이브러리는 전부 만들어서 준다. "앞의 세 자리를 이렇게 놓은 순간 이미 답이 될 수 없다"를 알아도 그 아래 $n!$ 가지를 전부 받아야 한다. 자르려면 트리를 내가 들고 있어야 하고, 그것이 [III-4 백트래킹과 가지치기](#/iii-4)다. 조건이 붙은 순열(중복 원소, 사전순 K번째, 특정 인접 금지)도 직접 짜는 쪽이다.

📖 `itertools.permutations(a, r=None)` — `a`에서 `r`개를 골라 만든 모든 순열을 게으르게 내놓는다. 총 $n!/(n-r)!$개.
   원소의 **값이 아니라 위치**로 구분한다. `a`에 같은 값이 둘 있으면 같아 보이는 순열이 두 번 나온다.
   쓰는 곳: 이 절, 완전탐색형 문제 전반, [0-12 디버깅과 반례 찾기](#/0-12)의 브루트포스 대조 코드.
   C++ 대응: `std::next_permutation` — 이쪽은 **정렬된 상태에서 시작해야** 전부 나오고, 같은 값이 있으면 중복을 알아서 건너뛴다. 반대 성질이다.

📖 `itertools.combinations(a, r)` — `a`에서 `r`개를 고른 조합. 총 $\binom{n}{r}$개. 인덱스 사전순으로 나온다.
   쓰는 곳: 이 절, [III-4](#/iii-4).
   C++ 대응: **없다.** `vector`에 1을 `r`개 채운 마스크를 만들고 `prev_permutation`으로 돌리는 것이 관용구다.

## 3. 손으로 따라가기

::: trace
입력: `a = [1, 2, 3, 4]`, `k = 2`. 조합 생성 재귀를 손으로 따라간다.

규칙: `go(start)`는 `cur`의 길이가 `k`면 출력하고 반환한다. 아니면 `i`를 `start`부터 `3`까지 돌며 `a[i]`를 `cur`에 넣고 `go(i+1)`을 부른 뒤 다시 뺀다.

관찰할 것은 **호출 인자 `start`**와 **그 시점의 `cur`**다. 둘이 조합 생성의 불변식을 들고 있다 — `cur`는 인덱스가 증가하는 순서로만 채워진다.

| 스텝 | 호출 | cur | 하는 일 |
|---|---|---|---|
| 0 | `go(0)` | `[]` | `i = 0..3` 순회 시작 |
| 1 | `go(1)` | `[1]` | `i = 1..3` 순회 시작 |
| 2 | `go(2)` | `[1, 2]` | 기저 → `(1, 2)` 출력, 반환 |
| 3 |  |  |  |
| 4 |  |  |  |

끝까지 채운 뒤 세 가지를 확인하라.

- [ ] 호출은 총 몇 번인가. 출력된 조합은 몇 개인가
- [ ] `cur = [4]`인 호출이 나오는가. 그 호출은 무엇을 출력하는가
- [ ] `go(i + 1)` 대신 `go(start + 1)`로 쓰면 무엇이 달라지는가
:::

::: answer
| 스텝 | 호출 | cur | 하는 일 |
|---|---|---|---|
| 0 | `go(0)` | `[]` | `i = 0..3` 순회 시작 |
| 1 | `go(1)` | `[1]` | `i = 1..3` 순회 시작 |
| 2 | `go(2)` | `[1, 2]` | 기저 → `(1, 2)` 출력, 반환 |
| 3 | `go(3)` | `[1, 3]` | 기저 → `(1, 3)` 출력, 반환 |
| 4 | `go(4)` | `[1, 4]` | 기저 → `(1, 4)` 출력, 반환 |
| 5 | `go(2)` | `[2]` | `i = 2..3` 순회 시작 |
| 6 | `go(3)` | `[2, 3]` | 기저 → `(2, 3)` 출력, 반환 |
| 7 | `go(4)` | `[2, 4]` | 기저 → `(2, 4)` 출력, 반환 |
| 8 | `go(3)` | `[3]` | `i = 3..3` 순회 시작 |
| 9 | `go(4)` | `[3, 4]` | 기저 → `(3, 4)` 출력, 반환 |
| 10 | `go(4)` | `[4]` | `i = 4..3` — 루프가 한 번도 안 돈다. 반환 |

**호출 11번에 조합 6개다.** 잎이 6개인 트리에 내부 노드가 5개 붙어 있다는 뜻이다.

**스텝 10이 눈여겨볼 자리다.** `cur = [4]`에서 남은 원소가 없으므로 이 가지는 아무것도 만들지 못한다. 그런데도 호출은 일어났다. 들어가기 전에 "남은 원소 수 `n - start`가 아직 필요한 개수 `k - len(cur)`보다 적으면 자른다"는 한 줄을 넣으면 이 호출은 사라진다. **이것이 가지치기의 가장 작은 형태다.** N이 4라 한 번이지만, N이 20이면 이런 헛가지가 대부분을 차지한다. [III-4](#/iii-4)의 주제가 이것이다.

**`go(i + 1)`을 `go(start + 1)`로 바꾸면 조합이 아니게 된다.** `i`가 아니라 `start`를 기준으로 내려가면 `cur = [1]`에서 `i = 2`(값 3)를 고른 뒤에도 다음 호출이 `go(1)`이라 값 2를 다시 볼 수 있다. `(1,3)` 다음에 `(3,2)` 같은 것이 나오고, 같은 조합이 순서만 바꿔 여러 번 나온다. **`i + 1`을 넘기는 한 줄이 순서를 죽이는 장치의 전부다.**
:::

## 4. 구현

### 4.1 라이브러리 판

::: dual
```python title="순열과 조합 — 라이브러리"
from itertools import combinations, permutations

a = [1, 2, 3, 4]
k = 2

perms = list(permutations(a))             # n! = 24개. 입력 순서를 그대로 사전순으로 본다
print("perm", len(perms), perms[0], perms[1], perms[-1])

combs = list(combinations(a, k))          # nCk = 6개. 인덱스 사전순
print("comb", len(combs), combs[0], combs[1], combs[-1])
```
```cpp title="순열과 조합 — 라이브러리"
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

void show(const vector<int>& v) {
    cout << "(";
    for (size_t i = 0; i < v.size(); i++) cout << v[i] << (i + 1 < v.size() ? ", " : "");
    cout << ")";
}

int main() {
    vector<int> a = {1, 2, 3, 4};
    int k = 2;

    vector<vector<int>> perms;
    vector<int> p = a;
    sort(p.begin(), p.end());             // 정렬된 상태에서 시작해야 전부 나온다
    do { perms.push_back(p); } while (next_permutation(p.begin(), p.end()));
    cout << "perm " << perms.size() << " ";
    show(perms[0]); cout << " "; show(perms[1]); cout << " "; show(perms.back()); cout << "\n";

    vector<vector<int>> combs;
    vector<int> sel(a.size(), 0);
    fill(sel.begin(), sel.begin() + k, 1);   // 1이 k개인 마스크에서 시작한다
    do {
        vector<int> cur;
        for (size_t i = 0; i < a.size(); i++) if (sel[i]) cur.push_back(a[i]);
        combs.push_back(cur);
    } while (prev_permutation(sel.begin(), sel.end()));
    cout << "comb " << combs.size() << " ";
    show(combs[0]); cout << " "; show(combs[1]); cout << " "; show(combs.back()); cout << "\n";
    return 0;
}
```
:::

```console
perm 24 (1, 2, 3, 4) (1, 2, 4, 3) (4, 3, 2, 1)
comb 6 (1, 2) (1, 3) (3, 4)
```

**복잡도:** 순열 생성은 시간 $O(n! \cdot n)$ — 순열이 $n!$개이고 하나를 만들어 넘기는 데 길이 `n`만큼의 일이 든다. 조합은 $O(\binom{n}{k} \cdot n)$이다. 공간은 전부 리스트에 담으면 개수만큼 들고, 게으르게 하나씩 소비하면 $O(n)$이다. **`list(...)`로 감싸는 순간 $n!$개가 메모리에 올라온다** — `n = 11`이면 4천만 개의 튜플이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 시작 상태 | `permutations`는 입력 순서를 1번째로 본다. 정렬 불필요 | `next_permutation`은 **정렬된 상태에서 시작**해야 전부 나온다. 안 하면 중간부터 시작해 일부만 본다 |
| 중복 원소 | 값이 같아도 위치가 다르면 **다른 순열로 취급**해 중복 출력 | 값 기준이라 같은 순열을 **한 번만** 낸다. `[1,1,2]`가 Python은 6개, C++은 3개 |
| 조합 | `combinations(a, k)` 한 줄 | 표준에 없다. 1이 `k`개인 마스크 + `prev_permutation` |
| 게으름 | 생성기라 하나씩 만든다. 메모리 $O(n)$ | `do-while` 루프 자체가 게으르다. 담지 않으면 $O(n)$ |
| 반환 | 튜플을 돌려준다 (불변) | 원본 컨테이너를 **제자리에서 바꾼다**. 원본이 필요하면 복사해 두어야 한다 |

::: warn
중복 원소 행이 실제 사고를 낸다. `[1, 1, 2]`의 서로 다른 순열은 3개인데 `itertools.permutations`는 6개를 내놓는다. 개수를 세는 문제에서 답이 정확히 두 배가 되고, 예제가 전부 서로 다른 값이면 예제는 통과한다. Python에서 값 기준으로 중복을 없애려면 `set()`으로 감싸거나 정렬 후 인접 중복을 건너뛰는 조건을 직접 넣어야 한다.
:::

### 4.2 직접 짜는 판

::: dual
```python title="조합과 부분집합 — 직접 재귀"
def fmt(v):
    return "(" + ", ".join(str(x) for x in v) + ")"


def combinations_rec(a, k):
    n, out, cur = len(a), [], []

    def go(start):
        if len(cur) == k:                 # 기저: k개를 다 골랐다
            out.append(list(cur))
            return
        for i in range(start, n):         # start 아래로는 다시 안 본다 — 이것이 중복을 죽인다
            cur.append(a[i])
            go(i + 1)
            cur.pop()                     # 되돌리기: 다음 후보를 위해 원상 복구한다

    go(0)
    return out


def subsets_rec(a):
    n, out, cur = len(a), [], []

    def go(i):
        if i == n:                        # 기저: 원소를 전부 결정했다
            out.append(list(cur))
            return
        go(i + 1)                         # i번째를 빼는 가지
        cur.append(a[i])
        go(i + 1)                         # i번째를 넣는 가지
        cur.pop()

    go(0)
    return out


a = [1, 2, 3, 4]
combs = combinations_rec(a, 2)
subs = subsets_rec(a)
print("comb", len(combs), fmt(combs[0]), fmt(combs[1]), fmt(combs[-1]))
print("subset", len(subs), fmt(subs[0]), fmt(subs[1]), fmt(subs[-1]))
```
```cpp title="조합과 부분집합 — 직접 재귀"
#include <functional>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

string fmt(const vector<int>& v) {
    string s = "(";
    for (size_t i = 0; i < v.size(); i++)
        s += to_string(v[i]) + (i + 1 < v.size() ? ", " : "");
    return s + ")";
}

vector<vector<int>> combinations_rec(const vector<int>& a, int k) {
    int n = (int)a.size();
    vector<vector<int>> out;
    vector<int> cur;

    function<void(int)> go = [&](int start) {
        if ((int)cur.size() == k) {       // 기저: k개를 다 골랐다
            out.push_back(cur);
            return;
        }
        for (int i = start; i < n; i++) { // start 아래로는 다시 안 본다 — 이것이 중복을 죽인다
            cur.push_back(a[i]);
            go(i + 1);
            cur.pop_back();               // 되돌리기: 다음 후보를 위해 원상 복구한다
        }
    };
    go(0);
    return out;
}

vector<vector<int>> subsets_rec(const vector<int>& a) {
    int n = (int)a.size();
    vector<vector<int>> out;
    vector<int> cur;

    function<void(int)> go = [&](int i) {
        if (i == n) {                     // 기저: 원소를 전부 결정했다
            out.push_back(cur);
            return;
        }
        go(i + 1);                        // i번째를 빼는 가지
        cur.push_back(a[i]);
        go(i + 1);                        // i번째를 넣는 가지
        cur.pop_back();
    };
    go(0);
    return out;
}

int main() {
    vector<int> a = {1, 2, 3, 4};
    auto combs = combinations_rec(a, 2);
    auto subs = subsets_rec(a);
    cout << "comb " << combs.size() << " " << fmt(combs[0]) << " " << fmt(combs[1])
         << " " << fmt(combs.back()) << "\n";
    cout << "subset " << subs.size() << " " << fmt(subs[0]) << " " << fmt(subs[1])
         << " " << fmt(subs.back()) << "\n";
    return 0;
}
```
:::

```console
comb 6 (1, 2) (1, 3) (3, 4)
subset 16 () (4) (1, 2, 3, 4)
```

**복잡도:** 조합은 시간 $O(\binom{n}{k} \cdot k)$ — 잎이 $\binom{n}{k}$개이고 잎마다 길이 `k`짜리 결과를 복사한다. 부분집합은 $O(2^n \cdot n)$ — 잎이 $2^n$개다. 공간은 결과를 빼면 $O(n)$ — 동시에 살아 있는 것은 `cur` 하나와 깊이 `n`짜리 프레임뿐이다. **`cur`를 매 호출 새로 만들지 않고 넣었다 빼는 것**이 이 $O(n)$의 근거다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 중첩 함수 | 안쪽 `def`가 바깥 지역 변수를 그대로 읽는다 | 람다 + `[&]` 캡처. 재귀 람다는 `std::function`으로 이름을 먼저 만들어야 한다 |
| 결과 복사 | `list(cur)`로 명시적 복사. 안 하면 전부 같은 리스트를 가리킨다 | `out.push_back(cur)`가 값 복사라 자동으로 안전하다 |
| 되돌리기 | `cur.pop()` | `cur.pop_back()` |

::: danger
Python에서 `out.append(cur)`라고 쓰면 **리스트 참조가 들어간다.** `cur`는 계속 바뀌므로 모든 결과가 같은 객체를 가리키고, 마지막에 전부 빈 리스트가 된다. 예제에서는 개수만 세면 통과하고 내용을 출력할 때 터진다. `list(cur)` 또는 `cur[:]` 또는 `tuple(cur)`로 **복사해서** 넣어라. C++의 `push_back`은 값 복사라 이 함정이 없다 — 언어를 오가는 사람이 정확히 이 지점에서 틀린다.
:::

::: perf
같은 $n!$개를 만드는 세 방법의 시간이다. 측정 스크립트는 `tools/bench/permgen_cost.py` 와 `tools/bench/permgen_cost.cpp` 다.

|---|---|

세 가지가 읽힌다. **첫째, 라이브러리가 직접 재귀보다 7배 빠르다** — C로 짜여 있고 파이썬 프레임을 만들지 않는다. **둘째, 한 칸마다 열 배다.** $n!$은 $n$을 곱해 늘어나므로 `n=11`에서 3.5초면 `n=12`는 42초다. **셋째, 언어가 한 칸을 벌어 준다.** 순열 전수 조사에서 Python은 10, C++은 11~12가 실질 상한이다([0-10 언어별 상수와 TLE 대응](#/0-10)).
:::

::: pitfall
- **`list()`로 감싼다.** 게으른 생성기를 리스트로 만드는 순간 $n!$개가 메모리에 올라온다. `for p in permutations(a):`로 바로 소비하라.
- **중복 원소를 잊는다.** Python은 값이 같아도 중복 출력한다. 개수를 세는 문제에서 답이 배수로 틀린다.
- **`next_permutation` 전에 정렬을 안 한다.** 사전순으로 중간부터 시작해 일부만 훑고 끝난다. 개수가 모자란데 코드는 정상 종료한다.
- **`start`를 잘못 넘긴다.** `go(i + 1)`이 아니라 `go(start + 1)`이면 조합이 아니라 중복 있는 나열이 된다.
- **결과를 복사하지 않고 담는다.** Python 한정. `list(cur)`을 빠뜨리면 전부 같은 객체가 된다.
:::

## 5. 어디에 쓰이는가

**테스트 매트릭스 생성이 조합 생성 그 자체다.** 옵션이 다섯 개이고 각각 켜고 끌 수 있으면 설정이 $2^5$가지다. CI에서 "OS 3종 × 컴파일러 2종 × 빌드 타입 2종"을 도는 잡 목록은 곱집합(`itertools.product`)이고, 조합 폭발을 감당할 수 없을 때 전수 대신 **모든 두 옵션 쌍이 한 번씩은 함께 나오도록** 줄이는 것이 페어와이즈 테스트다. 전수와 페어와이즈의 갈림이 이 챕터의 개수 계산에서 나온다.

**브루트포스 대조 코드가 순열 생성으로 짜인다.** 빠른 알고리즘의 정확성을 확인할 때, 작은 입력에서 모든 경우를 만들어 정답을 구하는 코드를 따로 두고 두 결과를 비교한다. 이때 느린 쪽은 느려도 되고 **의심의 여지 없이 옳기만 하면 된다.** `itertools.permutations`가 그 자리에 정확히 맞는다. 방법은 [0-12 디버깅과 반례 찾기](#/0-12)에 있다.

**작업 할당의 기준값도 여기서 나온다.** 로봇 5대에 작업 5개를 배정하는 최적 조합은 순열 120가지를 전부 계산하면 나온다. 대수가 늘면 $n!$이 감당이 안 되어 헝가리안 알고리즘 같은 다항 시간 해법으로 갈아타지만([V-11 할당 문제](#/v-11)), **그 해법이 옳은지 확인하는 기준은 여전히 작은 `n`에서의 전수 조사**다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "모든 경우", "가능한 모든 방법", "N명을 두 팀으로", "순서를 바꿔 가며", "K개를 골라"
- 제약조건: N ≤ 8~10이면 순열($n!$), N ≤ 20~25면 부분집합($2^n$), K가 작고 고정이면 조합($\binom{n}{k}$). 지문의 N이 유난히 작으면 그 자체가 완전탐색 지시다
- 혼동 주의: 중간에 자를 조건이 있으면 [III-4 백트래킹과 가지치기](#/iii-4), 부분집합을 상태로 들고 다녀야 하면 [III-3 비트마스크로 집합 다루기](#/iii-3)와 [VIII-9 비트마스크 DP](#/viii-9). 같은 부분 문제가 반복되면 완전탐색이 아니라 DP다
- 반례 함정: 입력에 **같은 값이 두 개 이상** 들어 있는 경우. `itertools.permutations`는 중복 순열을 그대로 내놓고 `next_permutation`은 걸러 낸다. 두 언어의 답이 갈리는 지점이 여기다
:::

## 연습

::: quiz
**1. 백준 10974 모든 순열 (실버 3)** — https://www.acmicpc.net/problem/10974
- 신호: "N! 개의 수열을 사전 순으로 출력". 만들 것이 지문에 그대로 적혀 있다. `N ≤ 8`이 $n!$을 허가한다.
- 상태: 지금까지 고른 자리들과 각 값의 사용 여부.
- 자료구조: `used` 불린 배열 하나. 라이브러리로도 두 줄이지만, **사전순이 왜 자동으로 나오는지**를 설명할 수 있어야 한다.

**2. 백준 15650 N과 M (2) (실버 3)** — https://www.acmicpc.net/problem/15650
- 신호: "고른 수열은 오름차순이어야 한다". 이 한 줄이 순열을 조합으로 바꾼다.
- 상태: `(지금까지 고른 것, 다음에 볼 수 있는 최소 인덱스)`.
- 자료구조: `cur` 리스트 하나. `start`를 넘기는 것과 `used` 배열을 쓰는 것의 차이를 손으로 확인하라. 이 문제가 §3 손추적의 원형이다.

**3. 백준 6603 로또 (실버 2)** — https://www.acmicpc.net/problem/6603
- 신호: "K개 중에서 6개를 고르는 모든 방법". $K \le 13$이라 $\binom{13}{6} = 1716$이다.
- 상태: 15650과 같다. 고를 개수가 6으로 고정된 것뿐이다.
- 자료구조: 정렬된 입력 배열. 입력이 이미 오름차순이라는 조건이 출력 정렬을 공짜로 만들어 준다.

**4. 백준 14889 스타트와 링크 (실버 1)** — https://www.acmicpc.net/problem/14889
- 신호: "N명을 두 팀으로 나눈다", `N ≤ 20`이고 짝수. 절반을 고르면 나머지는 자동으로 정해진다.
- 상태: 한쪽 팀의 멤버 집합. **집합 하나가 상태 전부**다.
- 자료구조: 크기 `N/2`의 조합. 절반을 고르면 상대 팀이 결정되므로 $\binom{20}{10} = 184{,}756$가지만 보면 된다. 같은 문제를 정수 하나로 접는 방법이 [III-3](#/iii-3)에 있다.

## 요약

- 순열 $n!$, 조합 $\binom{n}{k}$, 부분집합 $2^n$. **개수를 먼저 계산하는 것이 완전탐색 판정의 전부다.** N ≤ 8이면 순열, N ≤ 20이면 부분집합이 기준선이다.
- 세 대상은 선택 트리의 축이 다를 뿐이다. **자리 중심이면 순열, 원소 중심이면 부분집합**, 조합은 부분집합에 크기를 건 것이다.
- 조합에서 중복을 없애는 장치는 `start` 인덱스 하나다. 만들어 놓고 지우는 것이 아니라 **처음부터 안 만든다.**
- 라이브러리는 전부 만들어서 준다. **중간에 자를 조건이 있으면 직접 짠다.** 그것이 백트래킹으로 가는 갈림길이다.
- Python은 값이 같아도 중복 순열을 내고, C++ `next_permutation`은 걸러 낸다. 정렬 없이 시작하면 일부만 훑는다.
- Python에서 결과를 담을 때 `list(cur)`로 **복사**하지 않으면 전부 같은 객체가 된다.
- 실측으로 Python은 `n=11`이 3.5초, C++은 `n=12`가 1.4초다. 순열 전수 조사의 실질 상한이 그 언저리다.

**다음 절**: [III-3 비트마스크로 집합 다루기](#/iii-3) — 부분집합을 리스트가 아니라 정수 하나로 들고 다니면 무엇이 가능해지는지, 그리고 그 정수가 왜 DP의 상태가 될 수 있는지를 본다.
