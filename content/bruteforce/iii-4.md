# III-4 백트래킹과 가지치기

::: lead
전수 조사의 탐색 트리에서, 어느 가지를 언제 잘라야 노드 1,900만 개가 2,000개가 되는가.
:::

## 1. 문제

8×8 체스판에 퀸 8개를 서로 공격하지 못하게 놓는 방법의 수를 센다. 퀸은 같은 행·열·대각선에 있는 것을 전부 공격한다.

가장 순진한 방법은 64칸 중 8칸을 고르는 모든 경우를 만들어 하나씩 검사하는 것이다. $\binom{64}{8} = 4{,}426{,}165{,}368$가지다. 44억이면 [0-9 N 범위로 알고리즘 역산하기](#/0-9)의 기준선을 한참 넘는다.

한 번 줄여 보자. 퀸 둘이 같은 행에 있으면 무조건 공격하므로 **행마다 정확히 하나씩** 놓아야 한다. 그러면 각 행이 열 8개 중 하나를 고르는 문제가 되고, 경우의 수가 $8^8 = 16{,}777{,}216$으로 준다. 264배 줄었다. 그런데 실측하면 파이썬으로 **14.9초**다. 여전히 안 된다.

문제가 어디에 있는지 보자. 0행에 퀸을 0열, 1행에 퀸을 1열에 놓았다고 하자. 이 둘은 대각선으로 마주 본다. **이미 틀렸다.** 그런데 순진한 코드는 이 상태에서 2행, 3행, …, 7행까지 계속 놓는다. 아무 의미 없는 $8^6 = 262{,}144$가지를 만들고 나서야 잎에서 "대각선 충돌"을 발견한다.

==실패는 이미 두 번째 행에서 확정됐는데, 발견은 여덟 번째 행에서 한다.== 이 격차가 전부다. 확정된 실패를 즉시 알아채고 그 아래를 통째로 버리는 것이 백트래킹이다.

## 2. 아이디어

::: widget backtracking-tree {"problem":"nqueens","n":4,"prune":true,"caption":"4-퀸: 가지치기 있는 탐색 트리"}
:::

위젯은 4-퀸의 탐색 트리를 한 스텝씩 펼친다. 뿌리에서 아래로 한 층이 한 행이고, 한 노드의 자식이 그 행에서 시도하는 열들이다. 충돌이 확정된 자식은 뻗기 전에 붉게 표시되며 사라지고, 잎까지 살아남은 경로가 해다. **가지치기를 끄면 같은 트리가 잎 256개짜리로 부풀고, 켜면 노드 17개로 줄어든다.** 잘려 나간 자리에 원래 무엇이 매달려 있었는지가 이 위젯이 보여 주는 것이다.

### 2.1 백트래킹은 DFS에 되돌리기를 붙인 것이다

절차는 네 줄이다.

```text nolines
   1. choose    place one piece / assign one variable
   2. check     if the partial solution is already impossible, stop here
   3. recurse   go one level deeper
   4. undo      remove the piece, then try the next candidate
```

1·3번만 있으면 그냥 DFS다. **4번이 백트래킹의 이름이 나온 자리**이고, 2번이 이 챕터의 주제다. 되돌리기가 필요한 이유는 상태를 공유하기 때문이다. 후보마다 판을 새로 복사하면 되돌릴 것이 없지만 복사 비용이 붙는다. 비용 비교는 [III-5 구현·시뮬레이션형](#/iii-5)에 있다.

### 2.2 무엇을 잘라야 하는가

자를 수 있는 근거는 세 종류다.

**① 유효성 가지치기.** 지금까지 놓은 것만으로 이미 제약을 어겼으면 자른다. 8-퀸의 열·대각선 충돌이 여기다. **부분해가 규칙을 어기면, 그것을 확장한 어떤 완성해도 규칙을 어긴다.** 이 명제가 성립할 때만 잘라도 된다.

**② 경계 가지치기.** 최적화 문제에서 쓴다. 지금까지의 비용이 이미 찾아 둔 최선보다 나쁘면, 남은 선택이 비용을 줄일 수 없는 한 자른다. 외판원 순회에서 "지금까지의 경로 길이 + 남은 구간의 하한"이 최선보다 크면 버리는 것이 그것이다. 하한을 잘 계산할수록 많이 잘린다.

**③ 대칭성 가지치기.** 답이 대칭으로 짝지어지면 한쪽만 센다. 8-퀸에서 0행의 퀸을 왼쪽 절반에만 놓고 결과를 두 배 하면 절반이 준다. **틀리기 쉬운 가지치기다** — 홀수 크기 판의 가운데 열처럼 자기 자신과 대칭인 경우를 두 번 세거나 빠뜨린다.

### 2.3 가지치기는 언제 검사하는가

같은 조건이라도 **검사 시점**에 따라 잘리는 양이 다르다.

| 시점 | 하는 일 | 8-퀸의 노드 수 |
|---|---|---|
| 잎에서 검사 | 전부 놓고 나서 유효한지 본다 | 19,173,961 |
| 놓기 전에 열만 검사 | 열 충돌만 미리 막는다 | 109,601 |
| 놓기 전에 열과 대각선 검사 | 확정된 실패를 즉시 자른다 | **2,057** |

세 줄 모두 같은 답(92)을 낸다. 다른 것은 **틀렸다는 사실을 얼마나 일찍 아느냐**뿐이고, 그 차이가 9,300배다. 실측 근거는 §4의 `::: perf`에 있다.

여기서 나오는 원칙이 하나 있다. ==검사는 가능한 한 위에서, 그리고 상수 시간에.== 검사 자체가 비싸면 자른 이득이 사라진다. 8-퀸에서 "이 칸이 공격받는가"를 이미 놓인 퀸들과 일일이 비교하면 $O(n)$이지만, 열·대각선 사용 여부를 배열 세 개에 기록해 두면 $O(1)$이다. 대각선의 번호가 `r + c`와 `r - c`로 정해진다는 관찰이 그 $O(1)$을 만든다.

```text nolines
   r + c  is constant along one diagonal      (0,2) (1,1) (2,0)  ->  2
   r - c  is constant along the other         (0,0) (1,1) (2,2)  ->  0
```

`r - c`는 음수가 될 수 있으므로 배열 첨자로 쓰려면 `+ n`을 더해 0 이상으로 민다.

## 3. 손으로 따라가기

::: trace
입력: `N = 4`. 열과 대각선을 놓기 **전에** 검사하는 판이다. 0행의 퀸을 0열에 놓은 가지만 따라간다.

관찰할 것은 **현재 행**, **지금까지 놓은 열들**, **시도한 열과 그 판정**이다. 세 열이 백트래킹의 불변식을 드러낸다 — `지금까지 놓은 열들`은 항상 유효한 부분해다.

| 1 | 1 | `[0]` | 0 | 열 충돌 | 다음 열 |
| 2 | 1 | `[0]` | 1 | 대각 충돌 | 다음 열 |

**0열에서 시작한 가지에는 해가 없다.** 4-퀸의 해 두 개는 0행이 1열과 2열일 때 나온다.

**되돌아가기는 열이 소진된 순간마다 일어난다.** 스텝 7, 14, 16, 17이 그 자리다. 되돌아가면서 하는 일이 §2.1의 4번, 즉 그 행에 놓았던 표시를 지우는 것이다. 지우지 않으면 다음 가지에서 있지도 않은 퀸과 충돌한다.

**`place()` 호출은 5번이다.** 행 0에서 1번, 행 1에서 1번(0행 0열 아래), 행 2에서 2번(`[0,2]`와 `[0,3]`), 행 3에서 1번(`[0,3,1]`)이다. 표의 18줄은 **시도한 열**의 수이고 노드는 그중 "가능" 판정을 받아 실제로 내려간 것에만 생긴다. 잘린 시도는 노드를 만들지 않는다 — 이것이 가지치기가 노드 수를 줄이는 방식이다. N=4 전체로는 노드 17개, 해 2개다.
:::

## 4. 구현

`prune` 인자 하나로 세 전략을 한 코드에 담았다. 노드 수를 함께 세어 트리가 실제로 얼마나 줄어드는지 눈으로 확인한다.

::: dual
```python title="N-퀸 — 가지치기 세 단계와 노드 수"
import sys


def solve(n, prune):
    """(해의 개수, 방문한 노드 수). 노드 = place() 호출 1회."""
    col = [False] * n
    diag1 = [False] * (2 * n)             # r + c 가 같으면 같은 대각선
    diag2 = [False] * (2 * n)             # r - c 가 같으면 같은 대각선. 음수 방지로 +n
    pos = [0] * n
    stat = [0, 0]                         # [해, 노드]

    def valid_all():                      # 가지치기를 안 하면 잎에서 전부 검사한다
        for i in range(n):
            for j in range(i + 1, n):
                if pos[i] == pos[j] or j - i == abs(pos[j] - pos[i]):
                    return False
        return True

    def place(row):
        stat[1] += 1                      # 이 호출 자체가 노드 하나다
        if row == n:
            if prune == "full" or valid_all():
                stat[0] += 1
            return
        for c in range(n):
            if prune != "none" and col[c]:
                continue                  # 열 충돌 — 이 아래는 볼 필요가 없다
            if prune == "full" and (diag1[row + c] or diag2[row - c + n]):
                continue                  # 대각 충돌 — 여기서 한 번 더 자른다
            col[c] = diag1[row + c] = diag2[row - c + n] = True
            pos[row] = c
            place(row + 1)
            col[c] = diag1[row + c] = diag2[row - c + n] = False   # 되돌리기

    place(0)
    return stat[0], stat[1]


n = 6
sys.setrecursionlimit(10000)
print("N =", n)
for prune in ("none", "col", "full"):
    sols, nodes = solve(n, prune)
    print(f"{prune:<5} 해 {sols}  노드 {nodes}")
```
```cpp title="N-퀸 — 가지치기 세 단계와 노드 수"
#include <cstdlib>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int N;
string prune;
vector<char> col, diag1, diag2;
vector<int> pos_;
long long sols, nodes;

bool valid_all() {                        // 가지치기를 안 하면 잎에서 전부 검사한다
    for (int i = 0; i < N; i++)
        for (int j = i + 1; j < N; j++)
            if (pos_[i] == pos_[j] || j - i == abs(pos_[j] - pos_[i])) return false;
    return true;
}

void place(int row) {
    nodes += 1;                           // 이 호출 자체가 노드 하나다
    if (row == N) {
        if (prune == "full" || valid_all()) sols += 1;
        return;
    }
    for (int c = 0; c < N; c++) {
        if (prune != "none" && col[c])
            continue;                     // 열 충돌 — 이 아래는 볼 필요가 없다
        if (prune == "full" && (diag1[row + c] || diag2[row - c + N]))
            continue;                     // 대각 충돌 — 여기서 한 번 더 자른다
        col[c] = diag1[row + c] = diag2[row - c + N] = 1;
        pos_[row] = c;
        place(row + 1);
        col[c] = diag1[row + c] = diag2[row - c + N] = 0;   // 되돌리기
    }
}

int main() {
    N = 6;
    cout << "N = " << N << "\n";
    for (string p : {"none", "col", "full"}) {
        prune = p;
        col.assign(N, 0);
        diag1.assign(2 * N, 0);           // r + c 가 같으면 같은 대각선
        diag2.assign(2 * N, 0);           // r - c 가 같으면 같은 대각선. 음수 방지로 +N
        pos_.assign(N, 0);
        sols = nodes = 0;
        place(0);
        cout << p;
        for (int i = (int)p.size(); i < 5; i++) cout << " ";
        cout << " 해 " << sols << "  노드 " << nodes << "\n";
    }
    return 0;
}
```

**복잡도:** 최악 시간 $O(n^n)$ — 가지치기가 없으면 행마다 열 `n`개를 시도하므로 잎이 $n^n$개다. 열 가지치기만 넣으면 $O(n!)$ — 서로 다른 열을 고르는 순열이다. 대각선까지 넣으면 상한은 여전히 $O(n!)$이지만 **실제 노드 수는 그보다 훨씬 작다.** 이것이 백트래킹의 성질이다. 최악 복잡도는 안 줄고 실측이 준다. 그래서 이 유형은 복잡도 표기만으로 판단할 수 없고 노드 수를 세어 봐야 한다. 공간은 $O(n)$ — 배열 세 개와 깊이 `n`짜리 콜 스택.

| 언어 차이 | Python | C++ |
|---|---|---|
| 다중 대입 | `col[c] = diag1[...] = diag2[...] = True` 가 그대로 된다 | 같은 문법이 되지만 대입 결과가 왼쪽으로 흐르므로 타입이 섞이면 조용히 변환된다. `char` 배열에 `1` 대입 |
| 불린 배열 | `[False] * n`. 원소가 객체 참조라 메모리가 크다 | `vector<char>` 권장. `vector<bool>`은 비트 압축 특수화라 참조를 못 얻고 느릴 수 있다 |
| 재귀 깊이 | `n`이 깊이라 문제없지만 한도 기본 1000 | 8 MB 스택에 깊이 `n`은 무시할 수준 |
| 카운터 | 중첩 함수에서 정수를 수정하려면 `nonlocal` 또는 리스트 | 전역/참조 캡처로 그대로 |

::: perf

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

**노드가 9,300배 줄었고 시간이 7,000배 줄었다.** 두 배수가 비슷한 것이 중요하다 — 가지치기의 이득이 노드 수에 거의 그대로 비례한다는 뜻이고, 그래서 백트래킹 코드를 튜닝할 때 먼저 세야 하는 것은 시간이 아니라 **노드 수**다. 노드 수는 기계와 언어에 무관하다.

언어 차이도 읽어 둘 값어치가 있다. C++의 `none`(0.20초)이 Python의 `col`(0.09초)보다 느리다. ==언어를 바꿔 얻는 것은 상수 배수이고 가지치기로 얻는 것은 자릿수다.== 순서를 뒤집으면 안 된다([0-10 언어별 상수와 TLE 대응](#/0-10)).
:::

::: pitfall
- **되돌리기를 빠뜨린다.** 백트래킹 오답의 대부분이다. `place(row + 1)` 다음 줄에서 표시를 지워야 한다. 지우지 않으면 다음 가지가 유령 퀸과 충돌해 해가 줄어든다.
- **`continue`와 `return`을 혼동한다.** 한 열이 막혔을 때 `return`하면 그 행의 나머지 열을 아예 안 본다. 자를 것은 **그 후보 하나**이지 그 행 전체가 아니다.
- **대각선 첨자가 음수가 된다.** `r - c`는 `-(n-1)`까지 내려간다. `+ n`을 빼먹으면 Python은 뒤에서부터 인덱싱해 **틀린 답이 조용히** 나오고, C++은 범위 밖 접근이라 무엇이 깨질지 알 수 없다.
- **검사가 비싸다.** 놓을 때마다 기존 퀸 전부와 비교하면 $O(n)$이 붙는다. 배열 세 개로 $O(1)$을 만들어라. 가지치기의 이득을 검사 비용이 먹는다.
- **가지치기 조건이 너무 강하다.** 답이 될 수 있는 가지를 자르면 답이 줄어드는데 프로그램은 정상 종료한다. 가지치기를 넣기 전후의 **해의 개수가 같은지** 반드시 확인하라. 코드에서 `prune` 세 판이 모두 92를 내는 것이 그 검증이다.
- **최적화 문제에서 최선을 갱신하지 않는다.** 경계 가지치기는 지금까지의 최선이 좋을수록 많이 자른다. 좋은 답을 **먼저** 찾도록 후보 순서를 정렬하면 훨씬 많이 잘린다.
:::

## 5. 어디에 쓰이는가

**정규식 엔진이 백트래킹으로 만들어져 있고, 그것이 실제 서비스 장애를 낸다.** PCRE 계열(Perl, Java, JavaScript, Python `re`)은 `(a+)+$` 같은 패턴을 만나면 부분 일치를 여러 방식으로 쪼개 가며 되돌아간다. 입력이 `aaaa...aaab`면 쪼개는 방법이 지수로 늘어 문자 몇십 개에 CPU가 몇 분씩 묶인다. 이것이 **ReDoS**이고, 사용자 입력을 정규식에 넣는 서버가 이 한 줄로 멎는다. 방어는 두 가지다. 백트래킹하지 않는 엔진(RE2 계열)을 쓰거나, 패턴에서 중첩 수량자를 없앤다. **백트래킹의 최악 복잡도가 왜 안 줄어드는지**를 아는 것이 이 사고를 예방한다.

**SAT 솔버의 뼈대가 백트래킹이다.** DPLL 알고리즘은 변수 하나에 참/거짓을 배정하고(choose), 그 배정으로 어떤 절이 거짓이 되면 즉시 되돌아간다(check + undo). 여기에 단위 전파와 학습 절 같은 가지치기를 얹은 것이 현대 CDCL 솔버이고, 그것으로 변수 수십만 개짜리 검증 문제를 푼다. 하드웨어 검증, 의존성 해결(패키지 매니저가 버전 조합을 푸는 일)이 이 위에 올라가 있다.

**제약 만족 문제 전반이 같은 틀이다.** 스도쿠, 시간표 배정, 좌석 배치, 회로 배치가 "변수마다 값을 고르고, 제약을 어기면 되돌린다"로 서술된다. 실무 솔버가 추가로 하는 일은 순서 결정이다. **남은 후보가 가장 적은 변수부터 채우면** 트리가 훨씬 일찍 좁아진다. 스도쿠에서 빈칸이 적은 줄부터 채우는 것이 사람이 하는 그 요령이고, 이름이 붙어 있다(minimum remaining values).

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "가능한 모든 경우 중 조건을 만족하는", "서로 공격할 수 없게", "겹치지 않게 배치", "모든 칸을 한 번씩", "경우의 수를 구하시오" + 제약이 여러 개
- 제약조건: 완전탐색의 규모가 $10^8$을 넘는데 **부분해만 보고 실패를 확정할 수 있을 때.** N ≤ 15 정도의 배치·선택 문제가 전형이다. 상태가 정수 하나로 접히면 [III-3 비트마스크로 집합 다루기](#/iii-3)와 함께 쓴다
- 혼동 주의: 자를 조건이 없으면 그냥 [III-2 순열·조합·부분집합 생성](#/iii-2)의 전수 조사다. 같은 부분 상태가 여러 경로로 반복되면 백트래킹이 아니라 [VIII-9 비트마스크 DP](#/viii-9)다. 최적해가 아니라 아무 해나 하나면 그리디나 휴리스틱이 더 싸다
- 반례 함정: 가지치기 조건을 너무 강하게 잡아 **답이 될 수 있는 가지를 자르는** 경우. 답의 개수가 줄어드는데 프로그램은 정상 종료한다. 가지치기 전후로 작은 N에서 답이 같은지 대조하는 것이 유일한 방어다
:::

::: interview
**"완전탐색과 백트래킹의 차이는 무엇입니까."**
탐색 트리는 같고 **방문하는 노드의 수가 다르다**고 답한다. 백트래킹은 부분해만 보고 실패가 확정되면 그 서브트리를 통째로 버린다. 최악 복잡도는 그대로이고 실측 노드 수가 준다는 점까지 말하면 정확한 답이다. 8-퀸에서 1,900만 대 2,000이라는 구체적인 수를 들 수 있으면 더 좋다.

**"가지치기를 넣었는데 답이 틀립니다. 무엇을 의심합니까."**
두 가지다. 되돌리기를 빠뜨렸거나, 가지치기 조건이 답이 될 수 있는 가지를 자른다. 확인 방법은 하나다. **가지치기를 끈 판과 켠 판의 답을 작은 입력에서 대조한다.** 이 대조 코드가 [0-12 디버깅과 반례 찾기](#/0-12)의 브루트포스 대조와 같은 장치다.
:::

**1. 백준 9663 N-Queen (골드 4)** — https://www.acmicpc.net/problem/9663
- 신호: 이 챕터 그대로다. `N ≤ 15`가 지수 시간을 허가하면서 동시에 가지치기를 강제한다.
- 상태: `(현재 행, 사용한 열 집합, 사용한 두 대각선 집합)`.
- 자료구조: 불린 배열 세 개, 또는 정수 마스크 세 개. 마스크로 바꾸면 검사가 비트 연산 세 번이 되고 [III-3](#/iii-3)의 어휘가 그대로 쓰인다. `N = 15`에서 파이썬은 시간이 빠듯하다 — 그 자체가 좋은 훈련이다.

**2. 백준 14888 연산자 끼워넣기 (실버 1)** — https://www.acmicpc.net/problem/14888
- 신호: "N-1개의 연산자를 끼워 넣는 모든 경우". `N ≤ 11`이라 최악 $4^{10}$이지만 연산자 개수 제한이 가지를 자른다.
- 상태: `(지금까지 계산한 값, 남은 연산자 개수 4개)`.
- 자료구조: 개수 배열 4칸. 남은 개수가 0인 연산자는 시도하지 않는 것이 가지치기의 전부다. **음수 나눗셈 처리**가 이 문제의 함정이고, 두 언어의 `//`와 `/`가 다르다([0-5 C++ 입출력과 기본 타입](#/0-5)).

**3. 백준 2580 스도쿠 (골드 4)** — https://www.acmicpc.net/problem/2580
- 신호: 제약이 세 종류(행·열·3×3 박스)이고 빈칸을 채우는 문제다. 제약 만족 문제의 원형.
- 상태: `(다음에 채울 빈칸의 인덱스, 세 종류의 사용 표시)`.
- 자료구조: 사용 여부 배열 세 벌 — `row[9][10]`, `col[9][10]`, `box[9][10]`. 빈칸을 순서대로 채우는 것보다 **후보가 적은 칸부터** 채우면 트리가 급격히 좁아진다. 두 방식의 노드 수를 세어 비교해 보라.

**4. 백준 1987 알파벳 (골드 4)** — https://www.acmicpc.net/problem/1987
- 신호: "같은 알파벳을 두 번 지날 수 없다". 경로를 따라가며 **지나온 것을 기억해야** 하고, 되돌아올 때 잊어야 한다.
- 상태: `(현재 좌표, 지금까지 쓴 알파벳 집합)`.
- 자료구조: 알파벳 26개의 사용 표시 — 배열이나 26비트 마스크. DFS와 백트래킹의 차이가 가장 선명하게 드러나는 문제다. `visited`를 되돌리지 않으면 최댓값이 작게 나온다.

## 요약

- 백트래킹은 **DFS + 되돌리기 + 조기 실패 판정**이다. 탐색 트리는 완전탐색과 같고 방문하는 노드 수가 다르다.
- 잘라야 하는 근거는 셋이다. **유효성**(이미 규칙 위반), **경계**(이미 최선보다 나쁨), **대칭성**(같은 답의 반복).
- 검사는 **가능한 한 위에서, 상수 시간에** 한다. 검사 비용이 크면 자른 이득이 사라진다. 대각선 번호가 `r+c`와 `r-c`라는 관찰이 $O(1)$을 만든다.
- 8-퀸 실측: 잎에서 검사 19,173,961노드 / 열만 109,601 / 열+대각선 **2,057**. 답은 셋 다 92다.
- **튜닝할 때 먼저 세는 것은 시간이 아니라 노드 수다.** 노드 수는 기계와 언어에 무관하다. 언어 교체는 상수 배수, 가지치기는 자릿수다.
- 되돌리기 누락과 과도한 가지치기가 두 대표 오답이다. 둘 다 **가지치기 전후의 답을 작은 입력에서 대조**하면 잡힌다.
- 최악 복잡도는 가지치기로 안 줄어든다. 정규식 엔진의 ReDoS가 그 사실이 실무에서 청구되는 자리다.
