# III-1 재귀 사고법

::: lead
자기 자신을 호출하는 함수를 짤 때, 그 호출이 이미 옳다고 믿어도 되는 근거는 무엇인가.
:::

## 1. 문제

디렉터리 하나의 전체 크기를 구한다고 하자. 안에 파일이 있고 폴더가 있고, 그 폴더 안에 또 파일과 폴더가 있다. 반복문으로 짜려면 몇 겹인지를 코드를 쓰는 시점에 알아야 한다. 두 겹이면 `for` 두 개, 세 겹이면 세 개다. **그런데 몇 겹인지는 실행해 봐야 안다.** 겹의 수가 입력에 달렸는데 `for`의 개수는 소스 코드에 박혀 있다. 여기서 반복문은 표현력이 모자란다.

반복문이 다루는 것은 **폭**이다. 같은 층에 늘어선 것들을 훑는 데는 완벽하다. 재귀가 다루는 것은 **깊이**다. 층이 몇 개인지 모르는 구조에서 층을 내려가는 일은 재귀가 아니면 명시적인 스택을 손으로 관리해야 한다.

문제는 그다음이다. 재귀 함수를 읽을 때 대부분 머릿속에서 호출을 펼치려고 한다. `f(5)`가 `f(4)`를 부르고 그게 `f(3)`을 부르고… 세 겹까지 가면 무엇이 어디까지 계산됐는지 놓친다. 다섯 겹이면 종이가 필요하고, 호출이 두 갈래로 갈라지면 종이도 모자란다. 하노이 탑에서 원반 20개면 호출이 100만 개다.

==펼쳐서 이해하려는 시도가 재귀를 어렵게 만든다.== 재귀를 짜는 사람은 호출을 펼치지 않는다. 대신 **아직 짜지도 않은 그 함수가 이미 옳게 동작한다고 가정하고** 한 줄을 쓴다. 이 가정이 정당한 이유와, 그 정당성을 확보하는 절차가 이 챕터의 내용이다.

## 2. 아이디어

::: widget backtracking-tree {"problem":"hanoi","n":3,"prune":false,"caption":"hanoi(3) 의 호출 트리"}
:::

위젯은 `hanoi(3)`이 만드는 호출 트리를 한 스텝씩 펼친다. 뿌리는 `hanoi(3, A→C)` 하나이고, 그 아래로 `hanoi(2, A→B)`와 `hanoi(2, B→C)` 두 갈래가 뻗는다. 각각이 다시 두 갈래를 만들고, 원반이 0개가 되는 자리에서 가지가 멈춘다. 멈춘 자리가 기저 조건이고, 트리의 잎에서 뿌리로 되돌아오는 길이 곧 반환 경로다. **한 노드에서 보이는 것은 자기 자신과 자식 둘뿐이다.** 트리 전체가 아니다. 재귀를 짤 때 머리에 담아야 하는 것도 딱 이만큼이다.

### 2.1 신뢰의 도약

원반 `n`개를 A에서 C로 옮기는 절차를 생각해 보자. 가장 큰 원반은 맨 아래에 있으니, 그것을 C로 옮기려면 **그 위의 `n-1`개가 먼저 B로 비켜나 있어야 한다.** 비켜났다고 치면 큰 것을 A에서 C로 한 번 옮기고, 이제 B에 쌓인 `n-1`개를 C로 옮기면 끝난다.

여기서 "`n-1`개를 B로 옮긴다"를 어떻게 하느냐고 되묻는 순간 이해가 멈춘다. 되묻지 않는 것이 요령이 아니라 **방법**이다. `hanoi(n-1, ...)`이 옳게 동작한다고 믿고 그 한 줄을 쓴다. 이것이 신뢰의 도약이다.

믿음이라고 부르지만 근거 없는 믿음이 아니다. 구조가 수학적 귀납법과 같다.

```text nolines
   base    P(0) is true                     <- 기저: 직접 확인한다
   step    P(k-1) implies P(k)              <- 귀납: 작은 것이 맞으면 큰 것도 맞다
   ------------------------------------
   then    P(n) is true for all n           <- 결론: 모든 n 에서 옳다
```

`hanoi(0)`은 아무 일도 안 하고 그것이 옳다. 그리고 `hanoi(n-1)`이 옳으면 위의 세 줄짜리 절차가 `hanoi(n)`을 옳게 만든다. 두 가지를 확인하면 모든 `n`에 대해 옳다는 결론이 따라온다. **재귀 함수를 짠다는 것은 귀납 증명의 두 칸을 채우는 일이다.** 호출을 펼치는 일이 아니다.

### 2.2 네 가지 질문

새 재귀 함수를 쓸 때마다 같은 네 가지를 순서대로 답한다. 이 절차는 기계적이고, 답이 안 나오는 칸이 곧 아직 이해하지 못한 부분이다.

| # | 질문 | 하노이의 답 |
|---|---|---|
| 1 | **기저** — 가장 작은 경우는 무엇이고 그때 답은 무엇인가 | 원반 0개. 할 일이 없다 |
| 2 | **감소** — 한 스텝이 문제를 무엇으로 줄이는가 | 원반 수가 1 준다 |
| 3 | **조립** — 줄어든 문제의 답으로 원래 답을 어떻게 만드는가 | `n-1`개를 비켜 놓고, 큰 것 하나를 옮기고, `n-1`개를 다시 얹는다 |
| 4 | **종료** — 모든 경로가 기저에 닿는가 | 원반 수는 매 호출 1씩 줄고 음수가 될 수 없다 |

네 번째 칸이 [0-11 손추적 방법론](#/0-11)의 **측도**와 같은 것이다. 매 호출 반드시 줄어드는 음이 아닌 정수량이 있어야 한다. 재귀에서 무한 루프에 해당하는 사고는 이 칸을 안 채웠을 때 일어난다. `f(n)`이 `f(n)`을 부르거나, 짝수에서만 줄어들거나, 리스트를 자르지 않고 넘기는 코드가 전부 여기서 걸린다.

### 2.3 깊이는 메모리다

함수가 함수를 부르면 지역 변수와 돌아갈 주소가 **콜 스택**에 쌓인다. 콜 스택은 이름 그대로 스택이고, 그 자료구조는 [II-4 스택](#/ii-4)에서 다룬 것과 같다. 재귀 깊이가 1,000이면 프레임이 1,000개 쌓여 있다는 뜻이고, 그것은 곧 메모리다.

그래서 재귀에는 반복문에 없는 상한이 따라붙는다. Python은 **기본 재귀 한도가 1000**이고, 넘으면 `RecursionError`를 던진다. 정점이 10만 개인 그래프를 DFS로 훑는 코드는 이 한도에 먼저 부딪힌다. C++에는 그런 숫자가 없는 대신 OS가 준 스택을 다 쓰면 프로그램이 그냥 죽는다. 예외도 메시지도 없이 세그먼테이션 폴트다. 한도의 실제 값은 §4의 측정에 있다.

## 3. 손으로 따라가기

::: trace
입력: `hanoi(3, A→C, 보조 B)`. 관찰할 것은 **호출 인자**와 **깊이**, 그리고 **그 호출이 반환되기 전까지 만들어진 이동**이다.

규칙은 세 줄이다. `n == 0`이면 즉시 반환. 아니면 `hanoi(n-1, src→via)` → `src에서 dst로 한 번 이동` → `hanoi(n-1, via→dst)`.

| 스텝 | 깊이 | 호출 | 지금 하는 일 | 누적 이동 |
|---|---|---|---|---|
| 0 | 0 | `hanoi(3, A→C, B)` | 먼저 2개를 A→B 로 보낸다 | — |
| 1 | 1 | `hanoi(2, A→B, C)` | 먼저 1개를 A→C 로 보낸다 | — |
| 2 | 2 | `hanoi(1, A→C, B)` | 먼저 0개를 A→B 로 보낸다 | — |
| 3 | 3 | `hanoi(0, ...)` | 기저. 즉시 반환 | — |
| 4 | 2 | `hanoi(1, A→C, B)` | A→C 이동을 찍는다 | A→C |
| 5 |  |  |  |  |
| 6 |  |  |  |  |

세 가지를 확인하라.

- [ ] 깊이가 3을 넘는 스텝이 있는가. 없다면 그 이유는 무엇인가
- [ ] 전체 이동 횟수는 몇 번인가. `n`이 4면 몇 번이 되겠는가
- [ ] 스텝 3에서 아무 일도 안 하고 반환했는데, 그 호출을 지우면 무엇이 깨지는가
:::

::: answer
| 스텝 | 깊이 | 호출 | 지금 하는 일 | 누적 이동 |
|---|---|---|---|---|
| 0 | 0 | `hanoi(3, A→C, B)` | 먼저 2개를 A→B 로 보낸다 | — |
| 1 | 1 | `hanoi(2, A→B, C)` | 먼저 1개를 A→C 로 보낸다 | — |
| 2 | 2 | `hanoi(1, A→C, B)` | 먼저 0개를 A→B 로 보낸다 | — |
| 3 | 3 | `hanoi(0, ...)` | 기저. 즉시 반환 | — |
| 4 | 2 | `hanoi(1, A→C, B)` | A→C 이동을 찍는다 | A→C |
| 5 | 2 | `hanoi(1, A→C, B)` | 나머지 0개를 B→C 로. 기저 → 반환 | A→C |
| 6 | 1 | `hanoi(2, A→B, C)` | A→B 이동을 찍는다 | A→C, A→B |
| 7 | 2 | `hanoi(1, C→B, A)` | 두 기저 사이에서 C→B 를 찍는다 | …, C→B |
| 8 | 0 | `hanoi(3, A→C, B)` | A→C 이동을 찍는다 | …, A→C |
| 9 | 1 | `hanoi(2, B→C, A)` | 남은 2개를 B→C 로. 그 안에서 B→A, B→C, A→C | 총 7회 |

**깊이는 3을 넘지 않는다.** 인자 `n`이 매 호출 정확히 1씩 줄고 0에서 멈추므로 가장 깊은 사슬이 `3 → 2 → 1 → 0`이다. 깊이의 상한이 곧 `n`이고, 이것이 §2.3의 "깊이는 메모리다"가 뜻하는 그 깊이다.

**이동 횟수는 7이다.** 점화식은 $T(n) = 2T(n-1) + 1$, $T(0) = 0$이고 풀면 $T(n) = 2^n - 1$이다. `n=4`면 15회다. 호출 트리의 잎이 아니라 **가운데 줄**이 이동을 만든다는 점에 주의하라. 노드 하나가 이동 하나를 찍는다.

**스텝 3의 호출을 지우면 종료가 깨진다.** `n == 0`에서 반환하지 않으면 `hanoi(-1)`, `hanoi(-2)`로 끝없이 내려간다. 측도가 0 밑으로 내려가는 것을 막는 것이 기저의 역할이다. 기저는 "가장 작은 경우의 답"이면서 동시에 **재귀가 멈추는 유일한 지점**이다.
:::

## 4. 구현

::: dual
```python title="하노이 탑 — 재귀"
def hanoi(n, src, dst, via, moves):
    if n == 0:                            # 기저: 옮길 원반이 없으면 할 일이 없다
        return
    hanoi(n - 1, src, via, dst, moves)    # 믿는다 — 위 n-1개는 이미 via 로 옮겨져 있다
    moves.append((src, dst))              # 직접 하는 일은 큰 원반 하나뿐이다
    hanoi(n - 1, via, dst, src, moves)    # 믿는다 — via 의 n-1개도 dst 로 옮겨진다


moves = []
hanoi(3, "A", "C", "B", moves)
print(len(moves))
for a, b in moves:
    print(a, b)
```
```cpp title="하노이 탑 — 재귀"
#include <iostream>
#include <utility>
#include <vector>
using namespace std;

void hanoi(int n, char src, char dst, char via, vector<pair<char, char>>& moves) {
    if (n == 0)                           // 기저: 옮길 원반이 없으면 할 일이 없다
        return;
    hanoi(n - 1, src, via, dst, moves);   // 믿는다 — 위 n-1개는 이미 via 로 옮겨져 있다
    moves.push_back({src, dst});          // 직접 하는 일은 큰 원반 하나뿐이다
    hanoi(n - 1, via, dst, src, moves);   // 믿는다 — via 의 n-1개도 dst 로 옮겨진다
}

int main() {
    vector<pair<char, char>> moves;
    hanoi(3, 'A', 'C', 'B', moves);
    cout << moves.size() << "\n";
    for (auto [a, b] : moves)
        cout << a << " " << b << "\n";
    return 0;
}
```

**복잡도:** 시간 $O(2^n)$ — 호출 하나가 자기보다 하나 작은 호출 둘을 만들므로 호출 수가 $T(n) = 2T(n-1) + 1 = 2^n - 1$이다. 공간 $O(n)$ — 동시에 살아 있는 프레임은 가장 깊은 사슬 하나뿐이고 그 길이가 `n`이다. **호출은 지수로 늘어도 메모리는 선형이다.** 이 둘을 혼동하면 "재귀는 메모리를 많이 쓴다"는 잘못된 결론에 닿는다. 메모리를 정하는 것은 호출 수가 아니라 깊이다.

### 4.1 같은 함수의 반복문 판

재귀는 콜 스택이라는 스택을 **공짜로 빌려 쓰는 것**이다. 빌리지 않겠다면 같은 스택을 손으로 만들면 된다. 프레임 하나에 들어 있는 것은 인자와 **재개 지점**이다. 재귀 호출에서 돌아왔을 때 어디부터 이어서 할지를 기억해야 하므로, 손으로 만든 프레임에도 그 칸이 필요하다.

::: dual
```python title="하노이 탑 — 명시적 스택"
def hanoi_iter(n, src, dst, via):
    moves = []
    stack = [(n, src, dst, via, 0)]       # 마지막 칸이 재개 지점 — 재귀 호출에서 돌아올 자리
    while stack:
        n, src, dst, via, stage = stack.pop()
        if n == 0:                        # 기저: 아무것도 쌓지 않고 버린다
            continue
        if stage == 0:
            stack.append((n, src, dst, via, 1))   # 돌아올 자리를 먼저 깔아 둔다
            stack.append((n - 1, src, via, dst, 0))
        else:
            moves.append((src, dst))
            stack.append((n - 1, via, dst, src, 0))
    return moves


moves = hanoi_iter(3, "A", "C", "B")
print(len(moves))
for a, b in moves:
    print(a, b)
```
```cpp title="하노이 탑 — 명시적 스택"
#include <iostream>
#include <tuple>
#include <utility>
#include <vector>
using namespace std;

vector<pair<char, char>> hanoi_iter(int n, char src, char dst, char via) {
    vector<pair<char, char>> moves;
    // 마지막 칸이 재개 지점 — 재귀 호출에서 돌아올 자리
    vector<tuple<int, char, char, char, int>> stack{{n, src, dst, via, 0}};
    while (!stack.empty()) {
        auto [m, s, d, v, stage] = stack.back();
        stack.pop_back();
        if (m == 0)                       // 기저: 아무것도 쌓지 않고 버린다
            continue;
        if (stage == 0) {
            stack.push_back({m, s, d, v, 1});      // 돌아올 자리를 먼저 깔아 둔다
            stack.push_back({m - 1, s, v, d, 0});
        } else {
            moves.push_back({s, d});
            stack.push_back({m - 1, v, d, s, 0});
        }
    }
    return moves;
}

int main() {
    auto moves = hanoi_iter(3, 'A', 'C', 'B');
    cout << moves.size() << "\n";
    for (auto [a, b] : moves)
        cout << a << " " << b << "\n";
    return 0;
}
```
:::

출력은 재귀판과 한 글자도 다르지 않다. **복잡도도 같다.** 시간 $O(2^n)$ — 스택에 들어갔다 나오는 항목 수가 호출 수와 같다. 공간 $O(n)$ — 스택에 동시에 쌓이는 항목은 한 사슬 분량뿐이다. 바뀐 것은 프레임을 누가 관리하느냐 하나이고, 그래서 이 변환은 **Python의 재귀 한도를 우회하는 표준 수단**이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 깊이 한도 | 기본 1000. `sys.setrecursionlimit(n)`으로 올린다 | 숫자로 된 한도가 없다. OS 스택(`ulimit -s`, 보통 8 MB)을 다 쓰면 죽는다 |
| 한도 초과 | `RecursionError` 예외 — 잡을 수 있다 | 세그먼테이션 폴트 — 메시지도 없다 |
| 프레임 비용 | 프레임이 힙 객체에 가깝다. 깊이 100만이면 200 MB대 | 지역 변수 크기에 비례. 작은 함수면 100바이트 안팎 |
| 튜플 분해 | `n, src, dst, via, stage = stack.pop()` | C++17 구조적 바인딩 `auto [m, s, d, v, stage] = ...` |
| 스택 컨테이너 | `list`의 `append`/`pop` (끝쪽 $O(1)$) | `vector`의 `push_back`/`pop_back`. `std::stack`도 같다 |

::: perf

| 측정 | 결과 |

| C++ 기본 스택 8 MB, 프레임 96바이트짜리 함수 | 깊이 **약 87,000**에서 SIGSEGV |
| 1부터 20,000까지 합, 20회 (Python) | 재귀 0.074초 / 반복 0.018초 — **4.2배** |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

두 번째 줄이 중요하다. CPython 3.12부터 파이썬 함수끼리의 호출은 C 스택을 쓰지 않는다. 그래서 한도를 올려도 예전처럼 인터프리터가 죽지 않는다. **한도가 사라진 것이 아니라 한도의 종류가 바뀐 것이다** — 이제는 메모리가 먼저 찬다. 깊이 100만에 218 MB가 더 들었고, 메모리 제한 256 MB인 채점 환경에서는 그것만으로 끝이다.
:::

::: pitfall
- **기저를 빠뜨린다.** 가장 흔하다. 재귀 호출부터 쓰고 기저를 나중에 붙이려다 잊는다. 순서를 뒤집어라. 함수를 열면 **기저부터 쓴다.**
- **줄지 않는 인자를 넘긴다.** `f(n)` 안에서 `f(n)`을 부르거나, 리스트를 슬라이스하지 않고 그대로 넘기는 코드다. 네 번째 질문(측도)을 안 채운 결과다.
- **`sys.setrecursionlimit`만 올리고 끝낸다.** 깊이 10만짜리 DFS는 한도를 올려도 메모리에서 막힌다. 반복문 판으로 바꾸는 것이 정답이다.
- **깊이와 호출 수를 혼동한다.** 하노이는 호출이 $2^n$개지만 깊이는 `n`이다. 메모리를 정하는 것은 깊이다.
- **재귀 안에서 큰 값을 복사한다.** 인자로 리스트를 통째로 넘기면 깊이마다 복사본이 생긴다. 인덱스만 넘기고 배열은 공유하라. 되돌리기 규율은 [III-5 구현·시뮬레이션형](#/iii-5)에 있다.
:::

## 5. 어디에 쓰이는가

**파일시스템 순회가 그대로 이 구조다.** `du`, `find`, 빌드 도구의 소스 수집이 전부 "디렉터리 하나를 처리하는 함수가 하위 디렉터리에 대해 자기 자신을 부른다"로 짜여 있다. 그리고 이 코드에는 실제 장애가 하나 붙어 있다. **심볼릭 링크가 자기 조상을 가리키면 측도가 줄지 않는다.** 깊이가 무한히 늘어 스택이 터지거나 디스크 사용량이 무한대로 계산된다. `find`에 링크를 따라가지 않는 기본값이 있는 이유이고, §2.2의 네 번째 질문이 실무에서 어떤 모습으로 나타나는지 보여 주는 사례다.

**설정 파일 파서와 컴파일러의 문법 분석기도 재귀다.** JSON의 값 안에 객체가 들어가고 그 안에 다시 배열이 들어간다. 중첩 깊이가 문법으로는 무제한이므로 `parse_value()`가 `parse_object()`를 부르고 그것이 다시 `parse_value()`를 부르는 재귀 하강(recursive descent) 구조가 된다. 이때 깊이 한도는 안전 장치이기도 하다. 악의적으로 만든 `[[[[[...]]]]]` 입력으로 파서의 스택을 터뜨리는 공격이 실재하고, 그래서 실무 파서에는 최대 중첩 깊이 상한이 설정으로 들어 있다.

**트리 구조를 쓰는 모든 곳이 재귀의 자리다.** 씬 그래프의 좌표 변환은 부모의 변환을 자식에 곱해 내려가는 재귀이고([II-10 트리 순회](#/ii-10)), UI의 렌더 트리, 디렉터리 기반 라우팅, 조직도 집계가 같은 모양이다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "자기 자신과 같은 모양의 부분 문제", "N번째 항은 앞의 두 항의 합", "폴더 안에 폴더", "괄호 안에 괄호", "절반으로 나눠서"
- 제약조건: 중첩 깊이가 입력에 따라 달라져 `for` 개수를 코드에 못 박을 수 없을 때. 깊이 상한이 $10^3$을 넘으면 Python은 한도 조정 또는 반복문 전환이 필요하고, $10^5$을 넘으면 두 언어 모두 명시적 스택으로 간다
- 혼동 주의: 같은 부분 문제가 **여러 번** 나오면 그냥 재귀가 아니라 메모이제이션이다([VIII-2 메모이제이션 vs 타뷸레이션](#/viii-2)). 부분 문제가 겹치지 않고 절반씩 나뉘면 분할 정복, 상태 공간을 훑으며 되돌아가면 [III-4 백트래킹과 가지치기](#/iii-4)
- 반례 함정: 측도가 줄지 않는 입력. 그래프의 사이클, 심볼릭 링크, `n`이 0 이하로 내려가는 경계가 대표적이다. 기저를 `n == 0`으로만 두고 `n < 0`을 안 막으면 음수 입력에서 무한 재귀다
:::

::: interview
**"재귀 함수가 무한히 돌지 않는다는 것을 어떻게 보장합니까."**
답변 뼈대는 측도다. 매 호출 반드시 줄어드는 음이 아닌 정수량을 지목하고, 그것이 0이 되는 지점이 기저와 일치함을 보인다. "인자 `n`이 호출마다 1씩 줄고 `n == 0`에서 기저로 끝납니다. 음수로는 내려갈 수 없습니다."

**"재귀를 반복문으로 바꿔 보세요."**
묻는 것은 콜 스택의 정체다. 프레임에 무엇이 들어 있는지 — 인자와 재개 지점 — 를 먼저 말하고, 그 둘을 담은 튜플을 손으로 만든 스택에 넣으면 된다고 답한다. 꼬리 재귀면 재개 지점이 필요 없어 그냥 루프가 된다는 것까지 말하면 충분하다.
:::

## 연습

::: quiz
**1. 백준 17478 재귀함수가 뭔가요? (실버 5)** — https://www.acmicpc.net/problem/17478
- 신호: 출력 자체가 재귀 구조다. 들여쓰기가 깊이에 비례해 늘어난다.
- 상태: 남은 깊이 하나. 들여쓰기 문자열은 깊이에서 계산하거나 인자로 물려준다.
- 자료구조: 없다. 문자열과 정수뿐이다. 이 문제의 목적은 **호출 전에 찍는 줄과 호출 후에 찍는 줄이 다르다**는 것을 손에 익히는 것이다.

**2. 백준 10870 피보나치 수 5 (브론즈 2)** — https://www.acmicpc.net/problem/10870
- 신호: 점화식이 지문에 그대로 적혀 있다. 기저도 두 개(`n=0`, `n=1`) 적혀 있다.
- 상태: `n` 하나.
- 자료구조: 없다. 단 `n`이 커지면 같은 부분 문제를 몇 번 다시 계산하는지 세어 보라. 그 관찰이 [VIII-2](#/viii-2)의 출발점이다.

**3. 백준 2630 색종이 만들기 (실버 2)** — https://www.acmicpc.net/problem/2630
- 신호: "전부 같은 색이 아니면 네 개로 자른다". 감소 단계가 지문에 적혀 있다.
- 상태: 정사각형 하나 = (왼쪽 위 좌표, 한 변 길이). 세 개의 정수다.
- 자료구조: 2차원 배열 하나를 공유한다. **잘라서 새 배열을 만들면 안 된다** — 깊이마다 복사본이 쌓인다.

**4. 백준 1992 쿼드트리 (실버 1)** — https://www.acmicpc.net/problem/1992
- 신호: 2630과 같은 분할인데 출력이 괄호로 중첩된다. 조립 단계가 문자열 이어붙이기다.
- 상태: 2630과 동일.
- 자료구조: 문자열. 네 자식의 결과를 받아 앞뒤에 괄호를 붙여 돌려준다. **자식의 반환값을 조립하는 것**이 이 문제의 훈련 지점이다.
:::

## 요약

- 반복문은 폭을, 재귀는 깊이를 다룬다. 중첩 깊이가 입력에 달렸으면 `for`의 개수를 소스에 못 박을 수 없다.
- **재귀는 호출을 펼쳐서 이해하는 것이 아니다.** 자기 호출이 이미 옳다고 가정하고 한 스텝만 쓴다. 그 가정을 정당화하는 것이 기저이고, 구조는 수학적 귀납법과 같다.
- 새 재귀 함수마다 네 칸을 채운다. **기저 · 감소 · 조립 · 종료.** 종료 칸이 곧 측도이고, 무한 재귀는 전부 이 칸을 비웠을 때 나온다.
- 함수를 열면 **기저부터 쓴다.** 재귀 호출을 먼저 쓰면 기저를 잊는다.
- 깊이는 메모리다. 호출 수가 아니라 **깊이**가 콜 스택을 정한다. 하노이는 호출 $2^n$개, 깊이 `n`이다.
- Python은 기본 한도 1000에서 `RecursionError`, C++은 8 MB 스택에서 약 87,000 깊이에 세그먼테이션 폴트다. 깊이 10만짜리는 명시적 스택으로 바꾼다.
- 재귀를 반복문으로 바꾸는 일반 절차는 **프레임(인자 + 재개 지점)을 튜플로 만들어 손수 스택에 넣는 것**이다. 출력도 복잡도도 그대로다.
