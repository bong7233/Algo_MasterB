# III-3 비트마스크로 집합 다루기

::: lead
원소 20개짜리 집합 100만 개를 들고 다녀야 할 때, 집합 하나를 무엇으로 표현할 것인가.
:::

## 1. 문제

도시 20개를 모두 한 번씩 방문하는 최소 비용 경로를 구한다고 하자. 탐색 중의 상태는 **"지금 어느 도시에 있는가"** 와 **"어떤 도시들을 이미 방문했는가"** 두 가지다. 앞은 정수 하나로 끝난다. 뒤가 문제다. 방문한 도시의 집합이 상태의 일부이고, 그 집합의 가짓수는 $2^{20} = 1{,}048{,}576$이다.

파이썬의 `set`으로 들고 다니면 어떻게 되는가. 상태를 표에 기록하려면 집합을 딕셔너리의 키로 써야 하는데 `set`은 변경 가능해서 키가 못 된다. `frozenset`으로 바꾸면 키는 되지만 만들 때마다 새 객체가 생기고 해시를 계산해야 한다. 상태 하나를 만들 때마다 원소 수에 비례하는 일이 붙는다. 그리고 메모리가 있다. 원소 13개짜리 `set` 하나가 **728바이트**다. 100만 개면 700 MB다. 메모리 제한 256 MB인 채점 환경에서 계산이 끝나기 전에 죽는다.

C++의 `set<int>`나 `vector<bool>`도 사정이 같다. 상태를 배열 인덱스로 쓸 수 없다는 것이 결정적이다. **DP 표의 첨자가 되려면 상태가 정수여야 한다.**

원소가 20개뿐이라는 사실을 다시 보자. 각 원소에 대해 필요한 정보는 "있다 / 없다" 한 비트다. 20비트면 집합 하나가 완전히 표현된다. 그리고 32비트 정수 안에 20비트가 들어간다. ==집합 하나가 정수 하나가 된다.== 그 순간 집합은 배열의 첨자가 되고, 딕셔너리 키가 되고, 비교가 한 번의 정수 비교가 된다.

## 2. 아이디어

원소 `i`가 집합에 있으면 `i`번 비트를 1로 둔다. 원소 5개짜리 우주에서 `{1, 2, 4}`는 이렇게 생겼다.

```text nolines
   bit index    4 3 2 1 0
   value        1 0 1 1 0     <- binary 10110 = 22
                ^     ^ ^
                |     | +---- element 1 is in
                |     +------ element 2 is in
                +------------ element 4 is in
```

비트 번호가 오른쪽에서 왼쪽으로 늘어난다는 점만 주의하면 된다. 이진수를 적을 때의 자리 순서와 배열 인덱스의 방향이 반대다.

### 2.1 집합 연산이 곧 비트 연산이다

집합 연산과 비트 연산이 일대일로 대응한다. 이 표가 이 챕터의 어휘 전체다.

| 집합 연산 | 비트 연산 | 비용 |
|---|---|---|
| 합집합 $A \cup B$ | `A \| B` | 명령 1개 |
| 교집합 $A \cap B$ | `A & B` | 명령 1개 |
| 차집합 $A \setminus B$ | `A & ~B` | 명령 2개. 상위 비트를 잘라야 할 때가 있다 |
| 대칭차 | `A ^ B` | 명령 1개 |
| 원소 `i` 포함 여부 | `(A >> i) & 1` | 명령 2개 |
| 원소 `i` 추가 | `A \| (1 << i)` | 명령 2개 |
| 원소 `i` 제거 | `A & ~(1 << i)` | 명령 3개 |
| 원소 `i` 뒤집기 | `A ^ (1 << i)` | 명령 2개 |
| 가장 낮은 원소만 | `A & -A` | 명령 2개 |
| 가장 낮은 원소 제거 | `A & (A - 1)` | 명령 2개 |
| 원소 개수 | popcount | 전용 명령 1개 |
| 공집합인가 | `A == 0` | 명령 1개 |
| $A \subseteq B$ 인가 | `(A & B) == A` | 명령 2개 |

`A & -A`가 왜 최하위 1비트만 남기는지는 2의 보수를 펼치면 보인다. `-A`는 `~A + 1`이고, `~A`는 모든 비트를 뒤집으므로 최하위 1비트 아래의 0들이 1이 된다. 거기에 1을 더하면 자리올림이 그 1들을 타고 올라가 최하위 1비트 자리에서 멈춘다. 결과적으로 `A`와 `-A`는 **그 한 비트에서만 함께 1이다.**

```text nolines
   A       0 1 0 1 1 0 0 0
   ~A      1 0 1 0 0 1 1 1
   -A      1 0 1 0 1 0 0 0     <- ~A + 1
   A & -A  0 0 0 0 1 0 0 0     <- only the lowest set bit survives
```

### 2.2 부분집합의 부분집합 — 마법처럼 보이는 한 줄

집합 하나가 아니라 **어떤 마스크 `m`의 모든 부분집합**을 훑어야 하는 경우가 있다. 집합을 두 조각으로 쪼개는 DP가 전부 이 모양이다. 관용구는 이것이다.

```text nolines
   s = m
   loop:  use(s)
          if s == 0: stop
          s = (s - 1) & m
```

`s - 1`은 `s`의 최하위 1비트를 0으로 만들고 **그 아래를 전부 1로 채운다.** 그 상태에서 `& m`을 하면 `m` 밖의 비트가 지워진다. 남는 것은 `m`의 부분집합 중 `s`보다 작은 것들 가운데 가장 큰 것이다. 그래서 이 한 줄이 `m`의 부분집합을 **큰 것부터 하나도 빠뜨리지 않고 내림차순으로** 준다.

멈추는 조건이 뒤에 있는 것도 이유가 있다. 공집합도 부분집합이므로 `s == 0`을 한 번 쓰고 나서 끝내야 한다. 조건을 앞에 두면 공집합이 빠진다.

비용도 계산해 두자. 마스크 `m`의 부분집합은 $2^{|m|}$개다. 크기가 `k`인 마스크는 $\binom{n}{k}$개 있으므로 전체 순회 횟수는

$$\sum_{k=0}^{n} \binom{n}{k} 2^k = 3^n$$

이다. $4^n$이 아니라 $3^n$이라는 것이 요점이다. **모든 쌍 `(s, m)`을 만들어 `s ⊆ m`을 검사하면 $4^n$이고, 이 관용구는 $3^n$이다.** $n = 16$에서 43,046,721과 4,294,967,296의 차이, 즉 100배다.

## 3. 손으로 따라가기

::: trace
입력: `m = 1011`(십진수 11). `s = m`에서 시작해 `s = (s - 1) & m`을 반복한다.

관찰할 것은 `s`, 중간값 `s - 1`, 그리고 `& m`이 무엇을 지웠는지다. 세 열이 이 관용구의 동작 전부를 드러낸다.

| 스텝 | s | s - 1 | (s-1) & m | 집합으로 |
|---|---|---|---|---|
| 0 | 1011 | 1010 | 1010 | {0,1,3} |
| 1 | 1010 | 1001 | 1001 | {1,3} |
| 2 | 1001 | 1000 | 1000 | {0,3} |
| 3 |  |  |  |  |
| 4 |  |  |  |  |

끝까지 채운 뒤 확인하라.

- [ ] 나온 부분집합은 몇 개인가. $2^{|m|}$과 맞는가
- [ ] `s = 1000`에서 `s - 1 = 0111`인데 결과가 `0011`이다. `& m`이 지운 비트는 무엇이고 왜 지워야 하는가
- [ ] 마지막 스텝에서 멈추지 않으면 `s`는 무엇이 되는가
:::

::: answer
| 스텝 | s | s - 1 | (s-1) & m | 집합으로 |
|---|---|---|---|---|
| 0 | 1011 | 1010 | 1010 | {0,1,3} |
| 1 | 1010 | 1001 | 1001 | {1,3} |
| 2 | 1001 | 1000 | 1000 | {0,3} |
| 3 | 1000 | 0111 | 0011 | {3} |
| 4 | 0011 | 0010 | 0010 | {0,1} |
| 5 | 0010 | 0001 | 0001 | {1} |
| 6 | 0001 | 0000 | 0000 | {0} |
| 7 | 0000 | — | — | 공집합. 여기서 멈춘다 |

**부분집합은 8개다.** `m = 1011`의 켜진 비트가 3개이므로 $2^3 = 8$이고 정확히 맞는다. 세는 순서는 `m`의 켜진 비트만 모아 만든 3비트 수를 7부터 0까지 내려세는 것과 같다. **`m`의 켜진 자리만 남긴 좌표계에서의 카운트다운**이라고 보면 이 관용구가 마법이 아니게 된다.

**스텝 3에서 `& m`이 지운 것은 1번 비트다.** `s - 1 = 0111`에는 `m`에 없는 1번 비트가 켜져 있다. 그대로 두면 `m`의 부분집합이 아닌 것이 나온다. `& m`은 매 스텝 "우리 우주 밖으로 새어 나간 비트"를 잘라 내는 장치다. 이 한 번의 AND가 없으면 관용구 전체가 성립하지 않는다.

**멈추지 않으면 `s = (0 - 1) & m = -1 & m = m`이 되어 처음으로 돌아간다.** 무한 루프다. C++에서 `-1`은 모든 비트가 1이므로 `& m`이 `m`을 그대로 돌려준다. Python도 임의 정밀도 정수에서 같은 결과다. **종료 조건을 루프 끝에 두는 이유가 공집합을 포함하기 위해서만은 아니다.**
:::

## 4. 구현

### 4.1 연산 세트

::: dual
```python title="집합을 정수로 — 연산 세트"
N = 5
FULL = (1 << N) - 1          # 11111 — 전체 집합. 차집합·여집합에서 반드시 필요하다
A = 0b10110                  # {1, 2, 4}
B = 0b01110                  # {1, 2, 3}


def fmt(mask):
    return "{" + ",".join(str(i) for i in range(N) if (mask >> i) & 1) + "}"


print("A         ", fmt(A))
print("B         ", fmt(B))
print("union     ", fmt(A | B))
print("intersect ", fmt(A & B))
print("diff A-B  ", fmt(A & ~B & FULL))    # ~B 는 상위 비트가 전부 1이라 FULL 로 자른다
print("symdiff   ", fmt(A ^ B))
print("has 2     ", (A >> 2) & 1)
print("add 0     ", fmt(A | (1 << 0)))
print("remove 1  ", fmt(A & ~(1 << 1)))
print("toggle 4  ", fmt(A ^ (1 << 4)))
print("lowest bit", fmt(A & -A))
print("size      ", A.bit_count())         # 3.10+
```
```cpp title="집합을 정수로 — 연산 세트"
#include <iostream>
#include <string>
using namespace std;

const int N = 5;
const int FULL = (1 << N) - 1;   // 11111 — 전체 집합. 차집합·여집합에서 반드시 필요하다

string fmt(int mask) {
    string s = "{";
    bool first = true;
    for (int i = 0; i < N; i++)
        if ((mask >> i) & 1) { if (!first) s += ","; s += to_string(i); first = false; }
    return s + "}";
}

int main() {
    int A = 0b10110;             // {1, 2, 4}
    int B = 0b01110;             // {1, 2, 3}

    cout << "A          " << fmt(A) << "\n";
    cout << "B          " << fmt(B) << "\n";
    cout << "union      " << fmt(A | B) << "\n";
    cout << "intersect  " << fmt(A & B) << "\n";
    cout << "diff A-B   " << fmt(A & ~B & FULL) << "\n";   // ~B 의 상위 비트를 FULL 로 자른다
    cout << "symdiff    " << fmt(A ^ B) << "\n";
    cout << "has 2      " << ((A >> 2) & 1) << "\n";
    cout << "add 0      " << fmt(A | (1 << 0)) << "\n";
    cout << "remove 1   " << fmt(A & ~(1 << 1)) << "\n";
    cout << "toggle 4   " << fmt(A ^ (1 << 4)) << "\n";
    cout << "lowest bit " << fmt(A & -A) << "\n";
    cout << "size       " << __builtin_popcount(A) << "\n";
    return 0;
}
```
:::

```console
A          {1,2,4}
B          {1,2,3}
union      {1,2,3,4}
intersect  {1,2}
diff A-B   {4}
symdiff    {3,4}
has 2      1
add 0      {0,1,2,4}
remove 1   {2,4}
toggle 4   {1,2}
lowest bit {1}
size       3
```

**복잡도:** 모든 연산이 시간 $O(1)$ — 정수 하나에 대한 기계 명령 한두 개다. 단 상수를 말해야 한다. **원소 수가 워드 크기(32 또는 64)를 넘으면 $O(1)$이 깨진다.** Python은 임의 정밀도라 원소가 100개여도 동작하지만 그때는 내부적으로 여러 워드를 훑으므로 $O(n/64)$다. C++의 `int`는 32비트, `long long`은 64비트이고 그 이상은 `bitset`이나 배열이다. 공간은 $O(1)$ 워드 — 원소 20개 집합이 4바이트다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 정수 폭 | 임의 정밀도. `1 << 100`이 그냥 된다 | `int`는 32비트. `1 << 31`은 **부호 있는 오버플로(UB)** 이고 `1 << 32`는 정의되지 않는다. 31비트를 넘으면 `1LL << i` |
| `~` 결과 | `~B`가 무한히 이어지는 1이라 **반드시 `& FULL`** 로 잘라야 한다 | `~B`도 상위 비트가 1이라 `& FULL` 이 필요하다. 다만 폭이 32로 정해져 있다 |
| popcount | `int.bit_count()` (3.10+). 이전 버전은 `bin(x).count("1")` | `__builtin_popcount` / `__builtin_popcountll`. `std::popcount`는 **C++20**이라 C++17에서는 못 쓴다 |
| 음수 시프트 | `-1 >> 1 == -1` (산술 시프트, 무한 1) | `-1 >> 1`은 구현 정의였고 C++20에서 산술 시프트로 확정됐다. 음수를 마스크로 쓰지 마라 |
| 이진 리터럴 | `0b10110` | `0b10110` (C++14부터) |

::: danger
`1 << 31`은 C++에서 실제 장애를 만든다. `int`가 32비트 부호 있는 정수라 31번 비트가 부호 비트이고, 여기에 1을 밀어 넣는 것은 **정의되지 않은 동작**이다. `-O2`에서 컴파일러가 "오버플로는 일어나지 않는다"를 전제로 코드를 재배치하면 조건문이 통째로 사라지는 일이 생긴다. 원소가 31개를 넘으면 예외 없이 `1LL << i`를 쓰고 마스크 변수도 `long long`으로 둬라. Python은 이 함정이 없고, 그래서 **C++로 옮길 때 조용히 깨진다.**
:::

### 4.2 부분집합 열거

::: dual
```python title="부분집합 열거 — s = (s - 1) & m"
def subsets_of(m):
    out = []
    s = m
    while True:
        out.append(s)
        if s == 0:                 # 공집합도 부분집합이다. 그래서 검사를 뒤에 둔다
            break
        s = (s - 1) & m            # m 의 부분집합 중 s 바로 다음으로 작은 것
    return out


m = 0b1011
subs = subsets_of(m)
print("m =", format(m, "04b"), "부분집합", len(subs), "개")
print(" ".join(format(x, "04b") for x in subs))

n = 4
total = sum(len(subsets_of(mask)) for mask in range(1 << n))
print("모든 마스크의 부분집합 총합 =", total, "= 3^4")
```
```cpp title="부분집합 열거 — s = (s - 1) & m"
#include <bitset>
#include <iostream>
#include <vector>
using namespace std;

vector<int> subsets_of(int m) {
    vector<int> out;
    int s = m;
    while (true) {
        out.push_back(s);
        if (s == 0)                // 공집합도 부분집합이다. 그래서 검사를 뒤에 둔다
            break;
        s = (s - 1) & m;           // m 의 부분집합 중 s 바로 다음으로 작은 것
    }
    return out;
}

int main() {
    int m = 0b1011;
    vector<int> subs = subsets_of(m);
    cout << "m = " << bitset<4>(m) << " 부분집합 " << subs.size() << " 개\n";
    for (size_t i = 0; i < subs.size(); i++)
        cout << bitset<4>(subs[i]) << (i + 1 < subs.size() ? " " : "\n");

    int n = 4, total = 0;
    for (int mask = 0; mask < (1 << n); mask++) total += (int)subsets_of(mask).size();
    cout << "모든 마스크의 부분집합 총합 = " << total << " = 3^4\n";
    return 0;
}
```
:::

```console
m = 1011 부분집합 8 개
1011 1010 1001 1000 0011 0010 0001 0000
모든 마스크의 부분집합 총합 = 81 = 3^4
```

**복잡도:** 마스크 하나의 부분집합 열거는 시간 $O(2^{|m|})$ — 스텝마다 서로 다른 부분집합 하나를 정확히 한 번 낸다. 모든 마스크에 대해 돌리면 $O(3^n)$ — §2.2의 이항 전개대로다. 공간은 결과를 담지 않으면 $O(1)$이다. **$3^n$과 $4^n$의 차이가 이 관용구의 존재 이유**이고, $n = 16$에서 이미 100배다.

| 집합 하나의 메모리 | 정수 **28바이트** / `set` **728바이트** — 26배 |
| `n = 12`, 부분집합의 부분집합 열거 | `s = (s-1) & m`으로 **531,441회 = $3^{12}$**, 0.044초 |
| 같은 결과를 모든 쌍 검사로 | $4^{12} = 16{,}777{,}216$쌍을 훑어 0.901초 — **21배** |

> (Linux x86-64 / CPython 3.13 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다.)

메모리 26배가 시간 3.3배보다 중요하다. 상태 100만 개를 표에 담아야 하는 [VIII-9 비트마스크 DP](#/viii-9)에서, `set`은 700 MB이고 정수 배열은 4 MB다. **정수화는 속도 최적화이기 전에 그 문제를 풀 수 있게 만드는 조건이다.**
:::

::: pitfall
- **`1 << i`의 `i`가 31을 넘는다.** C++에서 UB다. `1LL << i`로 쓰고 변수도 `long long`으로.
- **`~mask`를 자르지 않는다.** 두 언어 모두 상위 비트가 켜져 나온다. 여집합은 `~mask & FULL`이다.
- **연산자 우선순위.** `A & 1 << i`는 `A & (1 << i)`가 아니라 의도대로 읽히지만, `A & B == C`는 `A & (B == C)`로 묶인다. 비교와 섞을 때는 **항상 괄호를 쳐라.**
- **`for i in range(n)`으로 원소를 훑는다.** 켜진 비트가 두 개뿐인데 20번 도는 코드다. `while m: low = m & -m; ...; m -= low`로 켜진 비트 수만큼만 돈다.
- **부분집합 열거에서 종료 조건을 앞에 둔다.** 공집합이 빠진다. 그리고 뒤에 안 두면 `s = 0`에서 `m`으로 되돌아가 무한 루프다.
- **비트 번호와 배열 인덱스를 뒤집어 쓴다.** 이진수 표기의 왼쪽이 높은 비트이고 배열의 왼쪽은 인덱스 0이다. 출력만 뒤집혀 나오고 계산은 맞는 버그가 자주 나온다.
:::

## 5. 어디에 쓰이는가

**권한과 플래그가 전부 비트마스크다.** 유닉스 파일 권한 `0755`는 세 비트씩 묶인 마스크이고, `chmod`의 인자가 곧 이 챕터의 `add`/`remove` 연산이다. 커널의 `epoll`은 관심 있는 이벤트를 `EPOLLIN | EPOLLOUT`처럼 OR로 합쳐 받고, 발생한 이벤트를 같은 마스크로 돌려준다. **함수 인자 하나에 열 가지 옵션을 실어 보내는 표준 수단**이고, 그래서 C 계열 API의 시그니처에 `int flags`가 그렇게 자주 보인다.

**체스 엔진의 비트보드가 같은 발상의 극단이다.** 체스판이 64칸이므로 `uint64_t` 하나가 판 전체의 "여기에 폰이 있는가"를 담는다. 기물 종류별로 마스크를 두면 "백의 모든 기물"은 OR 몇 번이고, "흑이 공격하는 칸과 겹치는가"는 AND 한 번이다. 칸마다 반복문을 도는 구현과 비교해 자릿수가 다르다.

**확률적 자료구조의 바닥에도 비트 배열이 있다.** 블룸 필터는 원소를 여러 해시 함수에 넣어 비트 배열의 여러 자리를 켜고, 조회는 그 자리들이 전부 켜져 있는지를 AND로 확인한다([XV-4 블룸 필터와 쿠쿠 필터](#/xv-4)). "집합을 비트로 표현하면 메모리가 자릿수로 줄어든다"는 이 챕터의 명제가 시스템 규모에서 다시 나타나는 자리다.

**그리고 DP의 상태가 된다.** 방문 집합을 정수로 접는 순간 `dp[mask][last]`라는 2차원 배열이 성립한다. 외판원 순회가 $O(2^n \cdot n^2)$에 풀리는 근거 전체가 이 표현이다([VIII-9 비트마스크 DP](#/viii-9)).

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "모든 도시를 한 번씩", "이미 방문한", "부분집합으로 나누어", "각 원소를 넣거나 빼거나", "N개의 스위치를 켜고 끈다"
- 제약조건: 원소 수 N ≤ 20이면 $2^n$ 상태가 100만이라 배열에 들어간다. N ≤ 25가 경계이고, 부분집합의 부분집합까지 훑어야 하면 $3^n$이라 N ≤ 16이 한계다. C++에서 N > 31이면 `long long` 필수
- 혼동 주의: 집합을 만들기만 하고 상태로 재사용하지 않으면 [III-2 순열·조합·부분집합 생성](#/iii-2)의 재귀로 충분하다. 같은 부분집합이 여러 경로로 다시 나오면 [VIII-9 비트마스크 DP](#/viii-9)다. 원소 수가 40 근처면 절반씩 나누는 기법으로 간다
- 반례 함정: 원소 수가 32 이상인 입력. Python으로 짜고 통과한 코드를 C++로 옮기면 `1 << 32`에서 조용히 깨진다. 그리고 `~mask`를 `FULL`로 자르지 않은 코드는 원소 수가 워드 폭보다 작을 때만 티가 난다
:::

::: interview
**"20개짜리 집합을 100만 개 다뤄야 합니다. 어떻게 표현하겠습니까."**
답변 뼈대는 세 문장이다. 원소마다 필요한 정보가 1비트이므로 20비트 정수 하나로 접는다. 그러면 집합 연산이 기계 명령 한두 개가 되고, 무엇보다 **배열의 첨자와 해시 키가 된다.** 메모리는 집합당 4바이트로 `set`의 728바이트 대비 자릿수가 줄어든다.

**"`x & (x - 1)`은 무엇을 합니까."**
최하위 1비트를 끈다. 이어지는 질문은 대개 "그럼 이걸 반복하면?"이고, 답은 popcount다. 켜진 비트 수만큼만 도는 루프라 32번 도는 순진한 구현보다 빠르다. `x & -x`(최하위 비트만 남기기)와 짝으로 외워 두면 둘 다 즉답할 수 있다.
:::

::: quiz
**1. 백준 11723 집합 (실버 5)** — https://www.acmicpc.net/problem/11723
- 신호: 원소가 1부터 20까지로 못 박혀 있고 연산이 `add`, `remove`, `check`, `toggle`, `all`, `empty`다. **§2.1의 표를 그대로 읽어 주는 지문**이다.
- 상태: 정수 하나.
- 자료구조: 비트마스크. 연산 수가 300만이라 연산당 상수 시간이 필요하고, `all`은 `FULL`, `empty`는 `0` 대입 한 번이다.

**2. 백준 1182 부분수열의 합 (실버 2)** — https://www.acmicpc.net/problem/1182
- 신호: "부분수열의 합이 S가 되는 경우의 수", `N ≤ 20`. 부분집합 전수 조사의 원형이다.
- 상태: 부분집합 하나 = 마스크 하나.
- 자료구조: `for mask in range(1 << n)` 한 줄. 크기가 양수여야 한다는 조건 때문에 **공집합을 빼는 처리**가 필요하고, 그것을 잊는 것이 이 문제의 대표 오답이다.

**3. 백준 14225 부분수열의 합 (실버 1)** — https://www.acmicpc.net/problem/14225
- 신호: "만들 수 없는 가장 작은 자연수". $N \le 20$이라 부분집합 합을 전부 만들어도 100만 개다.
- 상태: 마스크 → 그 부분집합의 합.
- 자료구조: 합을 표시하는 불린 배열. 합의 상한이 $20 \times 100{,}000$이라 배열이 들어간다. **만들어진 합을 배열에 찍고 1부터 훑는 것**이 핵심이다.

**4. 백준 2961 도영이가 만든 맛있는 음식 (실버 2)** — https://www.acmicpc.net/problem/2961
- 신호: "재료를 하나 이상 사용", `N ≤ 10`. 신맛은 곱하고 쓴맛은 더한다.
- 상태: 사용한 재료 집합 = 마스크.
- 자료구조: 마스크 순회 + 켜진 비트만 훑기. `while m: low = m & -m` 관용구를 쓰면 재료 수만큼만 돈다. 곱이 커지므로 C++에서는 `long long`을 확인하라.
:::

## 요약

- 원소가 20개 안팎이면 **집합 하나를 정수 하나로 접는다.** 그 순간 집합이 배열 첨자와 해시 키가 되고, 이것이 DP를 가능하게 만드는 조건이다.
- 집합 연산은 비트 연산과 일대일 대응이다. 합집합 `|`, 교집합 `&`, 차집합 `& ~`, 포함 검사 `(A >> i) & 1`, 부분집합 판정 `(A & B) == A`.
- `A & -A`는 최하위 1비트만 남기고 `A & (A - 1)`은 그것을 끈다. 두 관용구로 **켜진 비트 수만큼만 도는 루프**를 짠다.
- 부분집합 열거는 `s = (s - 1) & m`이다. `s - 1`이 아래를 1로 채우고 `& m`이 우주 밖을 잘라 낸다. 종료 검사는 **루프 끝**에 둔다.
- 모든 마스크의 모든 부분집합은 $3^n$이지 $4^n$이 아니다. 실측으로 $n = 12$에서 21배 차이다.
- C++에서 `1 << 31`은 정의되지 않은 동작이다. 원소가 31개를 넘으면 `1LL << i`. Python에는 없는 함정이라 이식할 때 깨진다.
- `~mask`는 두 언어 모두 상위 비트가 켜진다. 여집합은 항상 `~mask & FULL`이다.
