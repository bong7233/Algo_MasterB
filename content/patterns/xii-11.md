# XII-11 Mediator

::: lead
개체 스무 개가 서로를 직접 알면 결합이 190쌍이 된다. 그것을 20으로 되돌리는 대가는 무엇인가.
:::

## 1. 문제

창고 바닥에 좁은 통로 하나가 있다. 통로는 셀 두 칸짜리이고 양쪽에서 로봇이 들어온다. 두 대가 동시에 들어가면 지나갈 수 없으므로, 로봇들은 진입 전에 서로 이야기해서 순서를 정한다.

처음 구현은 자연스럽다. 로봇이 통로 앞에 서면 **다른 로봇 전부에게 물어본다.** "그 칸 지금 쓰고 있나?" 아무도 쓰고 있지 않다고 하면 들어간다. 로봇이 두 대일 때 이 코드는 완벽하게 동작한다.

로봇이 늘면 두 가지가 동시에 나빠진다.

**첫째, 알아야 할 상대가 는다.** 로봇 하나가 다른 전부를 안다면 연결의 수는 쌍의 수, 즉 $n(n-1)/2$다. 숫자를 직접 놓아 보면 이 함수가 어떤 속도로 자라는지가 보인다.

| n | 직접 연결(쌍) | 로봇 하나 추가 시 새 링크 |
|---|---|---|
| 4 | 6 | 4 |
| 5 | 10 | 5 |
| 8 | 28 | 8 |
| 20 | 190 | 20 |
| 21 | 210 | 21 |

$n$대에서 $n+1$대로 갈 때 새로 생기는 링크는 $n$개다. **로봇 한 대를 추가하는 비용이 이미 있는 로봇 수에 비례한다.** 20대 현장에 21번째를 넣는 작업은 20개의 새 관계를 만드는 작업이고, 기존 20대 전부가 새 이웃의 존재를 알아야 하므로 20대의 코드나 설정이 전부 영향을 받는다. 총 결합은 $\Theta(n^2)$으로 자란다.

여기에 협상 규칙까지 각 로봇 안에 복제되어 있다. 규칙이 하나 바뀌면 $n$대를 전부 고쳐야 한다 — [XII-10](#/xii-10)에서 본 것과 같은 형태의 곱셈이다.

**둘째, 그리고 더 나쁜 것 — 쌍끼리의 협상으로는 교착을 막을 수 없다.** 이쪽이 진짜 문제다.

R1은 통로를 X→Y 방향으로 지나고 R2는 Y→X 방향으로 지난다. R1이 X를 잡고 R2가 Y를 잡는 데는 아무 문제가 없다. 각자 자기 앞의 빈 칸에 들어갔을 뿐이다. 그다음 R1은 Y를 요청하는데 R2가 쥐고 있고, R2는 X를 요청하는데 R1이 쥐고 있다. 둘 다 자기가 쥔 것을 놓지 않고 기다린다.

이것은 구현 실수가 아니다. [V-10 교착 검출과 회피](#/v-10)의 코프만 네 조건이 그대로 성립한 결과다. 셀은 한 번에 한 대만 쓰고(상호배제), 쥔 채로 다음을 기다리고(점유대기), 남의 것을 뺏지 못하고(비선점), 대기 관계가 원을 이룬다(순환대기). **쌍끼리 물어보는 프로토콜에는 이 네 조건 중 하나라도 깰 장치가 없다.** 각 로봇은 자기 이웃만 보므로 원이 생겼다는 사실을 볼 수 있는 위치에 아무도 없다.

::: danger
교착은 아무것도 부수지 않는다. 예외도 없고 오류 로그도 없다. 두 로봇이 서로를 보며 멈춰 있고, 통로 뒤로 대기열이 쌓이고, 관제 화면에는 전부 "정상 · 대기 중"으로 표시된다. **아무 일도 일어나지 않는 것이 이 버그의 증상이다.**
:::

## 2. 무엇이 달라져야 하는가

두 문제의 뿌리는 하나다. **판단에 필요한 정보를 아무도 전부 가지고 있지 않다.**

각 로봇은 자기가 쥔 것과 이웃이 쥔 것만 안다. "지금 통로 전체가 어떤 상태인가"는 어느 로봇의 머릿속에도 없다. 그런데 순환대기가 생겼는지는 전체를 봐야만 알 수 있다. 국소 정보만으로 전역 성질을 보장하려는 시도가 실패한 것이다.

그러면 방향은 둘 중 하나다. 모두가 전체를 알게 하거나, **전체를 아는 하나를 두고 나머지는 그것하고만 말하게 하거나.** 첫 번째는 결합을 더 늘리는 길이므로 남는 것은 두 번째다.

```text nolines
  직접 연결 (n=4)              전담 조율자 (n=4)

    R1 ─────── R2                R1      R2
     │ \     / │                   \    /
     │   \ /   │                    [TM]
     │   / \   │                   /    \
    R4 ─────── R3                R3      R4

    링크 6개                     링크 4개
```

링크가 $n(n-1)/2$에서 $n$으로 바뀐다. 로봇 추가 비용은 $n$개에서 **1개**로 바뀐다. 새 로봇은 조율자 하나만 알면 되고, 기존 로봇들은 새 로봇이 생겼다는 사실조차 몰라도 된다.

그리고 조율자는 전체를 보므로 **할당 방식 자체를 바꿀 수 있다.** 셀을 하나씩 주는 대신 **통로 구역 전체를 한 대에게 통째로 준다.** 이 한 줄이 교착을 구조적으로 없앤다. 로봇은 자원을 쥔 채로 다른 자원을 기다릴 일이 없다 — 필요한 것을 전부 받거나 아무것도 못 받거나 둘 중 하나이기 때문이다. 코프만 조건 중 **점유대기가 깨지고**, 그러면 순환대기가 만들어질 수 없다.

::: note
이것은 [V-10](#/v-10)의 교착 회피와 같은 아이디어다. 은행가 알고리즘도 "요청을 승인하면 안전 순열이 남는가"를 **전체 상태를 아는 한 주체가** 판정한다. 전역 판정자가 없으면 회피 자체가 불가능하다. 조율자를 두는 것은 설계 취향이 아니라 그 알고리즘을 놓을 자리를 만드는 일이다.
:::

## 3. 구현

### 3.1 서로에게 직접 묻는 판

각 로봇이 `peers` 목록을 들고 이웃 전부에게 직접 물어본다. 5스텝을 돌려 본다.

::: dual
```python title="직접 협상 — 다섯 스텝 뒤 아무도 지나가지 못한다"
STEPS = 5

class Robot:
    def __init__(self, name, route):
        self.name = name
        self.route = route          # 지나갈 셀 순서
        self.i = 0                  # 다음에 들어갈 셀의 인덱스
        self.held = []              # 지금 점유 중인 셀
        self.peers = []             # 다른 로봇 전부를 안다. 이것이 비용이다

    def step(self):
        if self.i >= len(self.route):
            return self.name + " 통과 완료"
        cell = self.route[self.i]
        for p in self.peers:        # 이웃 전부에게 직접 물어본다
            if cell in p.held:
                return self.name + " " + cell + " 대기"   # 내 것은 안 놓는다
        self.held.append(cell)
        self.i += 1
        return self.name + " " + cell + " 획득"

r1 = Robot("R1", ["X", "Y"])
r2 = Robot("R2", ["Y", "X"])
r1.peers = [r2]                     # 서로를 직접 안다
r2.peers = [r1]

print("[직접 협상] R1 은 X->Y, R2 는 Y->X 로 교차로를 지난다")
for step in range(1, STEPS + 1):
    a = r1.step()
    b = r2.step()
    print(f"  step {step}: {a} | {b}")
print(f"  {STEPS}스텝 뒤 통과: R1 {r1.i}/2, R2 {r2.i}/2")

print("[결합 링크 수] 직접 연결은 쌍의 수, 조율자는 로봇의 수")
for n in (4, 8, 20, 21):
    print(f"  n={n:3d} : 직접 {n * (n - 1) // 2:4d} 쌍 / 조율자 {n:3d} 링크")
```
```cpp title="직접 협상 — 다섯 스텝 뒤 아무도 지나가지 못한다"
#include <algorithm>
#include <iomanip>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

const int STEPS = 5;

struct Robot {
    string name;
    vector<string> route;           // 지나갈 셀 순서
    size_t i = 0;                   // 다음에 들어갈 셀의 인덱스
    vector<string> held;            // 지금 점유 중인 셀
    vector<Robot*> peers;           // 다른 로봇 전부를 안다. 이것이 비용이다

    string step() {
        if (i >= route.size())
            return name + " 통과 완료";
        string cell = route[i];
        for (Robot* p : peers) {    // 이웃 전부에게 직접 물어본다
            if (find(p->held.begin(), p->held.end(), cell) != p->held.end())
                return name + " " + cell + " 대기";   // 내 것은 안 놓는다
        }
        held.push_back(cell);
        i += 1;
        return name + " " + cell + " 획득";
    }
};

int main() {
    Robot r1{"R1", {"X", "Y"}};
    Robot r2{"R2", {"Y", "X"}};
    r1.peers = {&r2};               // 서로를 직접 안다
    r2.peers = {&r1};

    cout << "[직접 협상] R1 은 X->Y, R2 는 Y->X 로 교차로를 지난다\n";
    for (int step = 1; step <= STEPS; step++) {
        string a = r1.step();
        string b = r2.step();
        cout << "  step " << step << ": " << a << " | " << b << "\n";
    }
    cout << "  " << STEPS << "스텝 뒤 통과: R1 " << r1.i << "/2, R2 " << r2.i << "/2\n";

    cout << "[결합 링크 수] 직접 연결은 쌍의 수, 조율자는 로봇의 수\n";
    for (int n : {4, 8, 20, 21})
        cout << "  n=" << setw(3) << n << " : 직접 " << setw(4) << n * (n - 1) / 2
             << " 쌍 / 조율자 " << setw(3) << n << " 링크\n";
    return 0;
}
```
:::

**비용:** 한 스텝의 판정이 시간 $O(n \cdot c)$ — 로봇 $n$대에게 각각 물어보고, 각자의 점유 목록 $c$개를 훑는다. 이보다 중요한 것은 **구조의 비용**이다. 결합 링크가 $\Theta(n^2)$이므로 로봇 한 대를 추가할 때 손대야 할 곳이 $O(n)$이다. 그리고 아래 출력이 보이듯 이 구조는 교착에 대해 **어떤 복잡도도 지불하지 않는다** — 검출도 회피도 하지 않기 때문이다.

두 언어의 출력은 같다.

```console
[직접 협상] R1 은 X->Y, R2 는 Y->X 로 교차로를 지난다
  step 1: R1 X 획득 | R2 Y 획득
  step 2: R1 Y 대기 | R2 X 대기
  step 3: R1 Y 대기 | R2 X 대기
  step 4: R1 Y 대기 | R2 X 대기
  step 5: R1 Y 대기 | R2 X 대기
  5스텝 뒤 통과: R1 1/2, R2 1/2
[결합 링크 수] 직접 연결은 쌍의 수, 조율자는 로봇의 수
  n=  4 : 직접    6 쌍 / 조율자   4 링크
  n=  8 : 직접   28 쌍 / 조율자   8 링크
  n= 20 : 직접  190 쌍 / 조율자  20 링크
  n= 21 : 직접  210 쌍 / 조율자  21 링크
```

step 1에서 각자 한 칸씩 잡았고, step 2부터는 영원히 같은 줄이 반복된다. **50스텝을 돌려도 5스텝과 같다.** 두 로봇 다 `1/2`에서 멈춰 있다. 출력 뒤쪽의 표가 이 구조의 두 번째 비용이다 — 로봇 20대에서 21대로 갈 때 새 링크가 20개 생긴다.

### 3.2 조율자를 하나 두는 판

로봇은 이제 `peers`를 갖지 않는다. 매니저 하나만 안다. 매니저는 통로 구역 전체를 한 대에게 통째로 주고, 그 로봇이 다 지나간 뒤 다음에게 넘긴다.

::: dual
```python title="조율자 한 명 — 다섯 스텝 안에 둘 다 통과한다"
from collections import deque

STEPS = 5

class TrafficManager:
    """교차로 구역 하나를 통째로 배타 제어한다. 로봇끼리는 서로를 모른다."""
    def __init__(self):
        self.owner = None
        self.queue = deque()

    def request(self, name):
        if self.owner == name:
            return True
        if self.owner is None:
            self.owner = name
            return True
        if name not in self.queue:
            self.queue.append(name)
        return False

    def release(self, name):
        if self.owner == name:
            self.owner = self.queue.popleft() if self.queue else None

class Robot:
    def __init__(self, name, route, mgr):
        self.name = name
        self.route = route
        self.i = 0
        self.mgr = mgr              # 조율자 하나만 안다. 이웃 목록이 없다

    def step(self):
        if self.i >= len(self.route):
            return self.name + " 통과 완료"
        if not self.mgr.request(self.name):
            return self.name + " 허가 대기"
        cell = self.route[self.i]
        self.i += 1
        if self.i >= len(self.route):
            self.mgr.release(self.name)
            return self.name + " " + cell + " 통과, 구역 반납"
        return self.name + " " + cell + " 통과"

mgr = TrafficManager()
r1 = Robot("R1", ["X", "Y"], mgr)
r2 = Robot("R2", ["Y", "X"], mgr)

print("[조율자] 로봇은 매니저에게만 말한다")
for step in range(1, STEPS + 1):
    a = r1.step()
    b = r2.step()
    print(f"  step {step}: {a} | {b}")
print(f"  {STEPS}스텝 뒤 통과: R1 {r1.i}/2, R2 {r2.i}/2")
```
```cpp title="조율자 한 명 — 다섯 스텝 안에 둘 다 통과한다"
#include <algorithm>
#include <deque>
#include <iostream>
#include <string>
#include <vector>
using namespace std;

const int STEPS = 5;

// 교차로 구역 하나를 통째로 배타 제어한다. 로봇끼리는 서로를 모른다.
struct TrafficManager {
    string owner;                   // 빈 문자열이면 주인이 없다
    deque<string> queue;

    bool request(const string& name) {
        if (owner == name)
            return true;
        if (owner.empty()) {
            owner = name;
            return true;
        }
        if (find(queue.begin(), queue.end(), name) == queue.end())
            queue.push_back(name);
        return false;
    }

    void release(const string& name) {
        if (owner != name)
            return;
        if (queue.empty()) {
            owner.clear();
        } else {
            owner = queue.front();
            queue.pop_front();
        }
    }
};

struct Robot {
    string name;
    vector<string> route;
    size_t i = 0;
    TrafficManager* mgr;            // 조율자 하나만 안다. 이웃 목록이 없다

    string step() {
        if (i >= route.size())
            return name + " 통과 완료";
        if (!mgr->request(name))
            return name + " 허가 대기";
        string cell = route[i];
        i += 1;
        if (i >= route.size()) {
            mgr->release(name);
            return name + " " + cell + " 통과, 구역 반납";
        }
        return name + " " + cell + " 통과";
    }
};

int main() {
    TrafficManager mgr;
    Robot r1{"R1", {"X", "Y"}, 0, &mgr};
    Robot r2{"R2", {"Y", "X"}, 0, &mgr};

    cout << "[조율자] 로봇은 매니저에게만 말한다\n";
    for (int step = 1; step <= STEPS; step++) {
        string a = r1.step();
        string b = r2.step();
        cout << "  step " << step << ": " << a << " | " << b << "\n";
    }
    cout << "  " << STEPS << "스텝 뒤 통과: R1 " << r1.i << "/2, R2 " << r2.i << "/2\n";
    return 0;
}
```
:::

```console
[조율자] 로봇은 매니저에게만 말한다
  step 1: R1 X 통과 | R2 허가 대기
  step 2: R1 Y 통과, 구역 반납 | R2 Y 통과
  step 3: R1 통과 완료 | R2 X 통과, 구역 반납
  step 4: R1 통과 완료 | R2 통과 완료
  step 5: R1 통과 완료 | R2 통과 완료
  5스텝 뒤 통과: R1 2/2, R2 2/2
```

`1/2, 1/2`가 `2/2, 2/2`로 바뀌었다. 로봇 코드에서 사라진 것은 `peers` 목록과 그것을 훑는 반복문이다. 로봇은 이제 자기가 몇 대 중 한 대인지 모른다.

**비용:** 한 요청의 판정이 시간 $O(1)$ — 주인 한 명과 비교하고 대기열 끝에 넣는다(중복 방지 검사를 대기열 길이 $O(n)$ 훑기로 했으므로 엄밀히는 $O(n)$이고, 집합을 하나 곁들이면 $O(1)$이 된다). 결합은 링크 $n$개, 로봇 추가 비용 $O(1)$. 대신 **모든 요청이 한 지점을 지나므로 그 지점의 처리량이 시스템 전체의 상한**이 되고, 한 번의 통신 홉이 추가된다. 이것이 §6의 주제다.

| 언어 차이 | Python | C++ |
|---|---|---|
| "주인 없음" 표현 | `None` | `std::string`은 널이 없다. 빈 문자열을 표식으로 쓰거나 `optional<string>` |
| 대기열 | `collections.deque` — 양끝 $O(1)$ | `std::deque` — 같은 성질. 다만 내부는 청크 배열이라 메모리 배치가 다르다 |
| 대기열 안 검색 | `name not in self.queue` | `find(queue.begin(), queue.end(), name)`. 멤버 함수가 없다 |
| 로봇이 매니저를 참조 | 그냥 대입. 수명은 GC | `TrafficManager*` — 소유하지 않는 포인터. **매니저가 로봇보다 오래 살아야 한다** |

::: warn
C++판에서 `Robot`이 매니저를 원시 포인터로 들고 있는 것은 의도적이다. 로봇은 매니저를 **소유하지 않는다.** 여기서 `shared_ptr`를 쓰면 로봇이 매니저의 수명을 붙잡게 되고, 매니저가 로봇 목록을 들고 있는 설계로 확장되는 순간 순환 참조가 된다. 수명 관계는 [XI-11 순환 참조와 소유권](#/xi-11)에서 다룬다.
:::

::: pitfall
- **조율자가 죽으면 전부 멈춘다.** 직접 협상판에서는 한 대가 죽어도 나머지가 돈다. 조율자를 두는 순간 그것이 단일 실패점이 된다.
- **대기열이 FIFO가 아니면 기아가 생긴다.** 우선순위로 주면 낮은 우선순위 로봇이 영원히 못 들어갈 수 있다. [V-10](#/v-10)의 기아 문제 그대로다.
- **구역을 너무 크게 잡으면 처리량이 죽는다.** 통로 전체를 한 대에게 주면 교착은 없어지지만 병렬성도 없어진다. 구역 크기가 안전성과 처리량의 손잡이다.
- **반납을 잊으면 영구 점유다.** 로봇이 구역 안에서 고장 나면 아무도 그 구역을 못 쓴다. 조율자 쪽에 타임아웃이 필요하고, 그 타임아웃은 [XI-8 타이머 휠과 지연 큐](#/xi-8)의 문제가 된다.
:::

## 4. 이제 이름을 붙인다

**Mediator**(중재자)다. 객체 집합이 서로를 직접 참조하지 않게 하고, 그들 사이의 상호작용을 별도의 객체 하나에 모은다. 참여자를 **Colleague**라 부른다.

구조는 단순하다. 각 Colleague는 Mediator 참조 하나만 갖는다. Colleague는 다른 Colleague의 존재도, 개수도, 타입도 모른다. 무언가 필요하면 Mediator에게 말하고, Mediator가 누구에게 무엇을 시킬지 정한다.

의도는 두 가지가 겹쳐 있다. **결합을 $n^2$에서 $n$으로 줄이는 것**과 **흩어져 있던 상호작용 규칙을 한 곳에 모으는 것**이다. 앞의 것만 보고 쓰면 절반만 얻는다. 실제로 값을 하는 쪽은 뒤의 것이다 — 규칙이 한 곳에 있어야 그 규칙을 읽을 수 있고, 검사할 수 있고, 교착 회피 같은 전역 알고리즘을 놓을 수 있다.

::: note
[XII-7 Observer / Publish-Subscribe](#/xii-7)와 헷갈리기 쉽다. 둘 다 가운데에 무언가를 두고 직접 참조를 끊는다. **차이는 가운데 있는 것이 판단을 하느냐다.** 이벤트 버스는 받은 것을 구독자에게 그대로 배달할 뿐 내용을 보고 결정하지 않는다. 중재자는 **결정한다** — 누가 먼저 지나갈지, 누구에게 거절할지. 배달만 하면 Observer고, 판정하면 Mediator다.
:::

::: interview
**"Mediator와 Observer의 차이가 뭔가요?"** 는 둘 다 "중간에 무언가를 둔다"로 설명되기 때문에 자주 나온다. 뼈대는 세 겹이다.

1. **방향.** Observer는 단방향 통지다. 발행자는 누가 듣는지 모르고 응답도 받지 않는다. Mediator는 양방향 조율이다 — 참여자가 요청하고 중재자가 허가·거절로 답한다.
2. **판단의 유무.** 이벤트 버스는 배달만 한다. 중재자는 전체 상태를 보고 결정한다. **"이 요청을 지금 승인하면 안전한가"라는 질문을 던질 수 있으면 중재자다.**
3. **결합의 이동.** Observer는 결합을 없애는 쪽에 가깝고, Mediator는 결합을 한 곳으로 **옮긴다.** 그래서 Mediator에는 God Object로 자랄 위험이 따라오고 Observer에는 "누가 이 이벤트를 듣는지 추적할 수 없다"는 다른 위험이 따라온다.

한 문장으로 닫는다 — **배달이면 Observer, 판정이면 Mediator다.** 실제 시스템에서는 한 컴포넌트가 둘 다 하는 경우가 많고, 그때는 배달 경로와 판정 경로를 분리해 두었는지를 보면 설계의 질이 드러난다.
:::

## 5. 어디에 박혀 있는가

**데이터베이스의 락 매니저**가 가장 정확한 사례다. 트랜잭션끼리 "그 행 지금 쓰고 있나"를 직접 묻지 않는다. 전부 락 매니저에게 요청하고 락 매니저가 허가·대기·거절을 정한다. 교착 검출도 락 매니저가 한다 — 대기 관계를 방향 그래프로 만들고 사이클을 찾는다. **그 그래프를 만들 수 있는 이유가 락 매니저 하나가 모든 대기 관계를 보기 때문**이고, 트랜잭션끼리 직접 협상하는 설계였다면 이 검출 자체가 불가능하다. [V-10](#/v-10)의 자원 할당 그래프가 실제 시스템에 박혀 있는 자리다.

**창고·항만의 트래픽 매니저**가 3절의 예제 그대로다. 교차로와 좁은 통로를 구역으로 나누고, 관제가 구역 통행권을 한 대씩 발급한다. 로봇 대수가 수백 대로 늘어도 각 로봇의 코드는 그대로다. 여러 로봇의 경로를 한꺼번에 푸는 [V-9 CBS와 우선순위 기반 계획](#/v-9)도 중재자가 있어야 놓을 수 있다 — 각 로봇이 자기 경로만 아는 구조에서는 충돌을 정의할 주체가 없다.

**작업 배차 시스템**도 마찬가지다. 로봇이 서로 "이 주문 네가 할래"를 흥정하면 국소 최적에 갇힌다. 중재자가 전체 주문과 전체 로봇 상태를 보면 [V-11 할당 문제](#/v-11)의 헝가리안 알고리즘을 그대로 얹어 전역 최적 할당을 계산할 수 있다. **전역 알고리즘은 전역을 보는 자리를 먼저 만들어야 놓인다.**

**GUI 대화상자 컨트롤러**는 이 패턴이 원래 태어난 자리다. 체크박스가 꺼지면 텍스트 필드 세 개가 비활성화되고 확인 버튼이 잠긴다는 규칙을, 위젯끼리 서로를 참조해 구현하면 위젯 하나를 추가할 때마다 여러 위젯을 고쳐야 한다. 규칙을 컨트롤러 하나에 모으면 위젯은 "내가 바뀌었다"만 알린다.

**멀티플레이어 게임의 권위 서버**도 같은 구조다. 클라이언트끼리 "네가 나를 맞췄나"를 협상하지 않는다. 전부 서버에 보고하고 서버가 판정한다. 판정 주체가 하나여야 하는 이유는 성능이 아니라 **일관성**이고, 이 점에서 락 매니저와 정확히 같은 문제다.

## 6. 언제 쓰지 말아야 하는가

**참여자가 두셋일 때.** $n=3$이면 직접 링크가 3개고 중재자 링크도 3개다. 얻는 것이 없이 클래스 하나와 홉 하나가 는다. $n^2$이 $n$을 실제로 이기기 시작하는 지점은 참여자가 대여섯을 넘고 **관계가 실제로 조밀할 때**다. 참여자가 20개여도 각자 이웃 둘하고만 말한다면 링크는 이미 $O(n)$이고 중재자는 순손실이다.

**중재자가 자라는 것을 방치할 때.** 이것이 이 패턴의 진짜 위험이다. 결합은 사라지지 않았다 — **위치가 옮겨졌을 뿐이다.** 참여자 사이의 $n^2$개 관계가 중재자 내부의 분기로 접힌다. 중재자가 참여자 타입별로 `if`를 늘려 가면 몇 달 뒤 그것은 시스템 전체의 규칙을 다 아는 수천 줄짜리 클래스가 된다. God Object의 표준 발생 경로이고, [XII-15 안티패턴](#/xii-15)에서 다시 다룬다.

경계선은 이렇게 잡는다. **중재자가 "누가 무엇을 언제"만 정하면 건강하고, 참여자가 무엇을 어떻게 하는지까지 알기 시작하면 병들었다.** 트래픽 매니저가 통행권을 발급하는 것은 전자고, 트래픽 매니저가 로봇의 감속 프로파일을 계산하기 시작하면 후자다.

**실시간 제어 루프의 안쪽일 때.** 중재자는 홉을 하나 더한다. 100Hz 제어 루프 안에서 매 주기 중재자를 거치면 그 왕복 지연이 그대로 주기에 실린다. 이 계층에서는 조율을 상위 주기(1Hz의 관제)에 두고, 하위 주기는 이미 받은 허가 안에서 자율로 도는 구조가 맞다. 전역과 지역의 역할 분담은 [V-12 지역 경로계획](#/v-12)의 주제와 같다.

**단일 실패점을 감당할 수 없을 때.** 중재자가 멈추면 전부 멈춘다. 이 위험을 낮추려면 중재자를 이중화해야 하고, 그 순간 "누가 진짜 중재자인가"라는 합의 문제가 새로 생긴다. [XV-11 복제와 합의 입문](#/xv-11)이 그 문제다. **중재자를 도입하는 비용에는 이 문제를 언젠가 풀어야 한다는 부채가 포함되어 있다.**

## 연습

::: quiz
**1. 로봇 대수가 6대에서 60대로 늘었다**

- 상황: 6대일 때 잘 돌던 직접 협상 코드가 60대에서 진입 판정에만 프레임 시간의 절반을 쓴다.
- 무엇이 변하고 무엇이 고정인가: 통로의 물리적 구조와 통행 규칙은 고정이다. 참여자 수만 변한다.
- 어떤 구조이고 무엇을 대가로 치르는가: 조율자를 두면 판정이 $O(n)$에서 $O(1)$이 되고 결합이 $\Theta(n^2)$에서 $\Theta(n)$이 된다. 대가는 그 조율자가 초당 몇 건을 처리할 수 있느냐가 시스템 전체의 상한이 된다는 것이다. 도입 전에 그 상한을 먼저 재라.

**2. 중재자가 2,000줄이 됐다**

- 상황: 트래픽 매니저에 로봇 기종별 분기가 쌓여 2,000줄이다. 새 기종을 넣을 때마다 이 파일을 고친다.
- 무엇이 변하고 무엇이 고정인가: "구역은 한 번에 한 대"라는 조율 규칙은 고정이고, 기종별 능력(회전 반경, 감속 특성)이 변한다.
- 어떤 구조이고 무엇을 대가로 치르는가: 기종별 지식은 중재자가 알 것이 아니다. 참여자 쪽 인터페이스로 밀어내고([XII-2 Adapter](#/xii-2)) 중재자에는 조율 규칙만 남긴다. 대가는 인터페이스를 하나 더 정의해야 한다는 것이고, 그것이 2,000줄짜리 분기보다 싸다.

**3. 조율자를 이중화하라는 요구**

- 상황: 트래픽 매니저가 재시작되는 30초 동안 현장 전체가 멈춘다. 이중화하라는 요구가 들어왔다.
- 무엇이 변하고 무엇이 고정인가: 조율 규칙은 고정이고, "조율자가 하나"라는 전제가 변한다.
- 어떤 구조이고 무엇을 대가로 치르는가: 두 대를 띄우면 "지금 누가 발급 권한을 갖는가"를 정해야 하고 그것이 리더 선출 문제다. 대가는 시스템의 난도가 한 단계 올라간다는 것이다. 그전에 물어야 할 것 — 발급 상태를 잃지 않고 빠르게 재시작하는 것으로 충분한가.
:::

## 요약

- $n$개 개체가 서로를 직접 알면 링크가 $n(n-1)/2$개이고, 개체 하나를 추가하는 비용이 $n$에 비례한다. $n$이 20이면 190쌍, 21번째를 넣는 데 20개의 새 관계가 생긴다.
- 조율자를 하나 두면 링크가 $n$개가 되고 추가 비용이 $O(1)$이 된다. 이것이 **Mediator**다.
- 링크 수보다 중요한 것은 **전역을 보는 자리가 생긴다**는 점이다. 쌍끼리의 협상으로는 순환대기를 볼 수 없어 교착을 막지 못한다. 3절의 직접 협상판은 실제로 다섯 스텝 뒤 둘 다 `1/2`에서 멈춘다.
- 조율자가 자원을 통째로 주면 점유대기가 깨지고 교착이 구조적으로 불가능해진다. 같은 판에서 결과가 `2/2, 2/2`가 된다.
- 결합은 사라진 것이 아니라 조율자 안으로 옮겨졌다. 조율자가 "누가 무엇을 언제"를 넘어 "어떻게"까지 알기 시작하면 God Object로 자란다.
- 참여자가 두셋이거나 관계가 이미 성긴 구조에서는 순손실이다. 실시간 루프 안쪽에서는 홉 하나가 주기에 실린다.
- 조율자는 단일 실패점이다. 도입하는 순간 이중화와 합의라는 부채가 함께 생긴다.
