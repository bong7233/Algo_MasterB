# I-6 5분 프로토콜

::: lead
지문을 펼친 순간부터 유형을 확정할 때까지, 무엇을 어떤 순서로 몇 분씩 하는가.
:::

## 1. 문제

판별에 필요한 재료는 앞의 세 절에 다 있다. 제약을 복잡도로 되돌리는 산술이 [I-2](#/i-2)에, 지문의 표현과 알고리즘을 잇는 표가 [I-3](#/i-3)에, 입력 형태와 묻는 것의 2축 매트릭스가 [I-4](#/i-4)에 있다.

그런데 재료가 있다고 요리가 되지 않는다. 실제 지문 앞에서는 세 가지가 순서 없이 동시에 떠오르고, 그 상태로 5분이 지나면 대개 둘 중 하나가 되어 있다.

- **너무 일찍 확정한다.** 첫인상으로 떠오른 알고리즘 하나를 그대로 들고 에디터를 연다. 검증 단계가 통째로 빠진다.
- **끝없이 미확정이다.** 지문을 세 번 읽고 네 가지 접근을 떠올렸다가 지운다. 20분째 종이에 아무것도 없다.

두 실패의 공통점은 **진행 중에 자각되지 않는다**는 것이다. 첫 후보에 착수하는 사람은 자기가 검증을 건너뛰었다고 느끼지 않는다. 세 번째로 지문을 읽는 사람도 자기가 시간을 쓰고 있다고 느끼지 않는다. ==자각되지 않는 실패는 의지로 못 고친다. 고칠 수 있는 것은 단계와 예산뿐이다.==

::: note
5분이라는 숫자는 **상한이지 목표가 아니다.** 판별에 최적인 시간이 정확히 5분이라는 실험 근거는 없다. 5분의 역할은 타이머다 — 그 시각에 종이에 무엇이 있는지 확인하고, 없으면 다음 문제로 넘어갈지 판단하는 지점을 만든다. 총 시험 시간과 문제 수에 맞춰 이 값을 조정하는 산술은 [I-7 실전 운영 전략](#/i-7)에 있다.
:::

## 2. 프로토콜

다섯 단계이고 각 단계에는 예산과 **종이에 남는 산출물**이 있다. 산출물이 없는 단계는 하지 않은 것으로 친다.

| 단계 | 예산 | 무엇을 보는가 | 종이에 남는 것 |
|---|---|---|---|
| **0. 제약 역산** | 0:00–0:45 | N, 시간·메모리 제한, 값의 범위와 부호 | 허용 복잡도 한 줄 |
| **1. 지문 1회독** | 0:45–2:15 | 입력 형태, 묻는 것 | 신호어 밑줄 3개 이하 |
| **2. 후보 2개** | 2:15–3:15 | [I-4](#/i-4)의 2축 매트릭스 | 후보 A·B와 각각의 예상 복잡도 |
| **3. 반례 던지기** | 3:15–4:30 | 각 후보를 죽일 입력 | 살아남은 후보 |
| **4. 확정** | 4:30–5:00 | 상태·전이·자료구조 | 착수 가능한 세 줄 |

### 0단계 — 제약을 먼저 읽는다 (45초)

**지문 본문보다 제약을 먼저 읽는 이유는 순서를 바꾸면 제약이 하는 일이 달라지기 때문이다.** 제약을 먼저 보면 후보 집합을 자른다. 지문을 먼저 보면 첫인상이 후보를 정해 버리고, 그 뒤에 읽는 제약은 이미 정한 후보를 정당화하는 데만 쓰인다. 같은 정보인데 순서가 역할을 바꾼다.

남기는 것은 한 줄이다. `N ≤ 10^5 → O(N log N)까지`. 역산 표는 [I-2](#/i-2)와 [0-9 N 범위로 알고리즘 역산하기](#/0-9)에 있다.

여기서 같이 보는 것이 **값의 범위와 부호**다. "자연수"인지 그냥 "정수"인지, 합이 32비트를 넘는지. [I-5](#/i-5)의 다섯 사례 중 셋이 이 줄에서 갈렸다.

### 1단계 — 지문을 한 번만 읽는다 (90초)

목표는 이해가 아니다. **분류에 필요한 두 좌표를 뽑는 것**이다.

```text nolines
   input shape   grid / graph / sequence / string / geometry
   question      exists? / how many? / optimum / construct one
```

이 두 축이 [I-4](#/i-4)의 매트릭스이고, 좌표 두 개가 정해지면 후보군이 대여섯 개로 줄어든다.

밑줄은 **3개 이하**로 긋는다. 신호어를 다섯 개 이상 긋는 것은 하나도 안 긋는 것과 같다. 그리고 **두 번 읽지 않는다.** 한 번 읽고 모르는 부분이 남으면 그대로 2단계로 가서 후보를 세우다가 필요할 때 그 부분만 다시 본다. 통독을 반복하는 것이 미확정 상태를 가장 길게 끄는 습관이다.

### 2단계 — 후보를 정확히 두 개 세운다 (60초)

**하나여도 안 되고 셋이어도 안 된다.** 하나면 비교 대상이 없어 그대로 착수하게 되고, 셋 이상이면 3단계의 반례 만들기가 예산을 넘는다. 둘은 비교를 강제하는 최소 수이자 75초 안에 검증 가능한 최대 수다.

두 후보에는 **예상 복잡도를 붙여 적는다.** 0단계의 허용 복잡도를 넘는 후보는 그 자리에서 탈락이고, 그것만으로 판별이 끝나는 경우가 실제로 흔하다.

그리고 두 후보는 **이웃이어야 한다.** 그리디와 DP, BFS와 다익스트라, 정렬과 힙처럼 지문이 같으면 헷갈릴 만한 쌍이다. 완전히 다른 두 개(예: DP와 유니온 파인드)를 적었다면 3단계가 아니라 1단계로 돌아가야 한다. 입력 형태를 잘못 읽었다는 뜻이기 때문이다.

### 3단계 — 반례를 던진다 (75초)

**이 단계가 프로토콜의 본체다.** 하는 일은 하나다. 각 후보에 대해 **그 후보가 틀리는 입력을 만들려고 시도한다.** 만들어지면 후보가 죽고, 못 만들면 산다.

반례는 작게 만든다. 원소 서너 개면 충분하다. [I-5](#/i-5)의 반례가 전부 그 크기다. 그리고 던지는 방향은 후보마다 정해져 있다.

| 후보 | 무엇으로 죽이는가 |
|---|---|
| 그리디 | 지금의 최선을 나중에 무르고 싶어지는 입력 |
| 정렬 한 번 | 가치가 큰 원소가 **뒤에** 등장하는 입력 |
| 투 포인터 | 음수 원소 하나. 단조성을 깬다 |
| BFS | 비용이 다른 간선 하나 |
| 한 방향 DP | 상태 값을 **줄이는** 전이. 계산 순서를 없앤다 |
| 완전탐색 | 제약의 상한값을 그대로 대입 |

결과는 셋 중 하나다.

- **하나만 살았다** → 4단계로 간다.
- **둘 다 죽었다** → 1단계로 돌아간다. 입력 형태나 묻는 것을 잘못 읽었다.
- **둘 다 살았다** → 싼 쪽으로 착수한다. 다만 ==반례를 못 만든 것은 옳다는 증거가 아니다.== 이 구분을 메모에 남겨 두면, 구현 중에 답이 어긋났을 때 코드가 아니라 판별로 돌아갈 줄 안다.

### 4단계 — 확정한다 (30초)

세 줄을 적는다.

1. **상태** — 무엇을 값으로 들고 다니는가.
2. **전이 또는 진행 규칙** — 상태가 어떻게 다음 상태가 되는가.
3. **자료구조** — 그 진행에 필요한 연산이 무엇이고 어느 구조가 그 연산을 싸게 하는가.

**이 세 줄이 안 써지면 확정된 것이 아니다.** "코드를 치면서 정하겠다"는 판별이 안 끝났다는 뜻이고, 그 상태로 에디터를 열면 구현 시간이 판별 시간을 겸하게 된다. 그것이 이 Part 전체가 막으려는 상황이다.

## 3. 실제로 돌려 본다

### 예 1 — 백준 2178 미로 탐색 (실버 1)

> N×M 미로에서 1은 이동할 수 있는 칸, 0은 이동할 수 없는 칸이다. (1,1)에서 (N,M)까지 지나야 하는 최소의 칸 수를 구하라. `2 ≤ N, M ≤ 100`

| 단계 | 관찰 | 산출물 |
|---|---|---|
| 0 | `N, M ≤ 100` → 칸이 $10^4$개 | 무엇을 해도 든다. **제약이 후보를 자르지 않는다** |
| 1 | 입력 형태 = 격자, 묻는 것 = 최적 | 밑줄: "최소의 칸 수", "인접한 칸으로만" |
| 2 | A = BFS $O(NM)$ / B = DFS로 모든 경로 열거 후 최소 | 둘 다 적는다 |
| 3 | B: 100×100 격자의 경로 수는 지수. 0단계의 $10^4$을 넘는다 → 사망. A: 비용이 다른 간선이 있는가? 모든 이동이 한 칸이다 → 생존 | A |
| 4 | 상태 = `(r, c)` / 전이 = 4방향 중 벽이 아니고 미방문 / 자료구조 = 큐 + `dist` 격자 | 착수 |

1분 안에 끝난다. **제약이 후보를 안 잘라 주는 문제에서는 신호어가 일한다.** 0단계가 빈손으로 끝났다고 프로토콜이 실패한 것이 아니다.

### 예 2 — 백준 1654 랜선 자르기 (실버 2)

> 이미 가지고 있는 K개의 랜선을 잘라 길이가 같은 랜선 N개를 만들려 한다. 만들 수 있는 랜선의 최대 길이를 구하라. `1 ≤ K ≤ 10,000`, `K ≤ N ≤ 1,000,000`, 랜선 길이는 $2^{31}-1$ 이하

| 단계 | 관찰 | 산출물 |
|---|---|---|
| 0 | 랜선은 1만 개인데 **답의 후보 범위는 21억**이다. 길이 합은 32비트를 넘는다 | 답 범위 ≫ 입력 개수. C++는 `long long` |
| 1 | 입력 형태 = 수열, 묻는 것 = 최적 | 밑줄: "만들 수 있는 최대 길이" |
| 2 | A = 길이 1부터 21억까지 시도 / B = **답을 이분 탐색** $O(K \log 2^{31})$ | 둘 다 적는다 |
| 3 | A: 21억 × 1만 → 0단계에서 즉시 사망. B: "길이 H로 자르면 N개 이상 나오는가"가 H에 대해 단조인가? H가 커지면 나오는 개수는 절대 늘지 않는다 → 생존 | B |
| 4 | 상태 = 답의 후보 구간 `[lo, hi)` / 진행 = 중앙값 H로 개수를 세어 N 이상이면 `lo`를 올린다 / 자료구조 = 배열 + 64비트 누적 | 착수 |

0단계의 **비대칭**이 이 문제의 전부다. 답의 범위가 입력 개수보다 압도적으로 크면 "입력을 훑는" 알고리즘이 아니라 "답을 좁히는" 알고리즘이다. 이것이 매개변수 탐색이고 [VII-3](#/vii-3)에서 정면으로 다룬다.

### 예 3 — 백준 13549 숨바꼭질 3 (골드 5)

> 수빈이는 점 N에, 동생은 점 K에 있다. 걸으면 1초 후에 X-1 또는 X+1로, 순간이동하면 **0초 후에** 2X로 이동한다. 가장 빠른 시간을 구하라. `0 ≤ N, K ≤ 100,000`

| 단계 | 관찰 | 산출물 |
|---|---|---|
| 0 | 상태 공간 $10^5$. $O(V)$도 $O(V \log V)$도 든다 | **제약이 자르지 않는다** |
| 1 | 입력 형태 = 암묵 그래프(정수 좌표), 묻는 것 = 최적 | 밑줄: "가장 빠른 시간", "0초 후에" |
| 2 | A = BFS $O(V)$ / B = 다익스트라 $O(V \log V)$ | 둘 다 적는다 |
| 3 | A: BFS의 전제는 "모든 간선 비용이 같다"이다. 걷기 1초, 순간이동 **0초** → 전제가 깨진다. **사망.** B: 비용이 음수가 아니다 → 생존 | B |
| 4 | 비용이 0과 1 두 가지뿐이다 → 힙 대신 덱으로 $O(V)$. 상태 = 좌표 / 전이 = ±1은 비용 1(뒤에 넣기), ×2는 비용 0(앞에 넣기) / 자료구조 = 덱 + `dist` 배열 | 착수 |

**이 예가 3단계의 존재 이유다.** 3단계가 없었다면 A로 착수해 구현을 마치고 제출한 뒤에야 틀렸다는 것을 알았을 것이다. 여기서 A를 죽이는 데 든 것은 반례조차 아니었다 — **"이 알고리즘이 기대는 전제가 무엇인가"** 를 한 번 소리 내어 말한 것이 전부다. 이런 기각은 대개 10초 안에 끝난다.

4단계에서 후보 B가 그대로 확정되지 않았다는 점도 보라. 살아남은 후보를 적는 순간 "그런데 비용이 두 종류뿐이네"가 보인다. **확정 단계는 후보를 베끼는 곳이 아니라 다듬는 곳이다**([IV-4](#/iv-4)).

## 4. 손으로 돌려 보라

::: trace
**백준 12865 평범한 배낭 (골드 5)** — https://www.acmicpc.net/problem/12865

> 물건 N개가 있고 각각 무게 W와 가치 V를 가진다. 최대 K만큼의 무게만 넣을 수 있는 배낭에 담아 얻을 수 있는 가치의 최댓값을 구하라. `1 ≤ N ≤ 100`, `1 ≤ K ≤ 100,000`, 무게와 가치는 각각 100,000 이하

앞 두 줄은 채워 두었다. **나머지 세 줄을 직접 채워라.**

| 단계 | 무엇을 관찰했는가 | 산출물 |
|---|---|---|
| 0 제약 역산 | `N ≤ 100`, `K ≤ 100,000`. 곱이 $10^7$ | $O(NK)$까지 허용 |
| 1 지문 1회독 | 입력 형태 = 물건 목록, 묻는 것 = 최적 | 밑줄: "가치의 최댓값", "넣을 수 있는" |
| 2 후보 2개 |  |  |
| 3 반례 던지기 |  |  |
| 4 확정 |  |  |

세 가지 힌트를 준다.

- 후보 하나는 **반드시 그리디**여야 한다. 가장 싸므로 먼저 검토된다. 그리디의 기준으로 자연스러운 것은 가치/무게 비율이다.
- 반례는 **물건 세 개, 배낭 용량 10**으로 만들어진다.
- 0단계에서 두 후보가 다 살아남으면 3단계가 일해야 한다.
:::

::: answer
| 단계 | 무엇을 관찰했는가 | 산출물 |
|---|---|---|
| 2 후보 2개 | A = 가치/무게 비율 그리디 $O(N \log N)$ / B = 0/1 배낭 DP $O(NK) = 10^7$ | **둘 다 0단계를 통과한다.** 제약으로는 안 갈린다 |
| 3 반례 던지기 | 용량 10, 물건 `(6, 12) (5, 9) (5, 9)`. 비율은 2.0, 1.8, 1.8. 그리디는 비율 2.0인 것을 먼저 담고 용량 4가 남아 아무것도 못 넣는다 → **12**. 최적은 `(5,9) + (5,9) = 18` | A 사망, B 생존 |
| 4 확정 | 상태 = `dp[c]` = 용량 c로 얻는 최대 가치 / 전이 = 물건마다 `c`를 K에서 w까지 **내려가며** `dp[c] = max(dp[c], dp[c-w] + v)` / 자료구조 = 길이 K+1 정수 배열 | 착수 |

**반례가 12와 18을 낸다.** 물건이 세 개라 종이에서 30초면 확인된다. 그리디가 지는 이유도 한 문장이다 — 비율이 높은 것을 먼저 담으면 **자리가 애매하게 남고**, 남은 자리는 가치를 전혀 못 만든다.

4단계의 "내려가며"에도 이유가 있다. 올라가며 돌면 방금 갱신한 `dp[c-w]`를 다시 써서 같은 물건을 여러 번 담게 되고, 그것은 0/1 배낭이 아니라 무한 배낭이다. 이 구분은 [VIII-5 배낭 문제](#/viii-5)에서 다룬다.

이 문제의 요점은 **0단계가 빈손으로 끝났다는 것**이다. 두 후보 모두 시간 안에 들어서 제약 역산이 아무것도 못 잘랐다. 그때 판별을 끝내는 것은 3단계뿐이고, 3단계에 든 비용은 물건 세 개짜리 반례 하나였다.

기계로 다시 확인하려면 `tools/bench/misclassify_cases.py`를 실행하라. 마지막 줄이 이 반례의 12와 18을 출력한다.
:::

## 5. 5분이 지났는데 확정이 안 되면

프로토콜이 항상 확정을 내는 것은 아니다. 그때 하는 일은 두 가지다.

**첫째, 지금까지의 메모를 남기고 넘긴다.** 메모가 있으면 돌아왔을 때 0분이 아니라 4분 지점에서 시작한다. 이것이 메모를 종이에 남기라고 강조한 이유다.

**둘째, 어디서 막혔는지 한 단어로 적는다.** 실패한 단계에 따라 대응이 다르기 때문이다.

| 적는 말 | 실패한 단계 | 뜻과 대응 |
|---|---|---|
| **후보 없음** | 1~2단계 | 입력 형태와 묻는 것으로 후보군이 안 좁혀졌다. 지금 이 문제를 풀 수 없다는 신호에 가깝다. 넘긴다 |
| **둘 다 생존** | 3단계 | 반례를 못 만들었다. 싼 쪽으로 착수하되 판별이 미확정임을 메모에 남긴다 |
| **둘 다 사망** | 1단계 | 입력 형태나 묻는 것을 오독했다. 지문의 그 부분만 다시 읽는다 |
| **상태 정의 안 됨** | 4단계 | 유형은 맞는데 상태에 축이 하나 모자란 경우가 많다. 시간, 남은 횟수, 방문한 집합을 후보 축으로 넣어 본다 |

넘길지 붙들지의 기준 자체는 [I-7 실전 운영 전략](#/i-7)에서 정한다.

::: pitfall
- **지문을 먼저 읽고 제약을 나중에 읽는다.** 순서를 바꾸는 것만으로 제약이 "후보를 자르는 도구"에서 "첫인상을 정당화하는 도구"로 바뀐다.
- **후보를 하나만 세운다.** 검증할 대상이 없으면 3단계가 통째로 사라진다. 가장 흔한 실패다.
- **반례를 크게 만들려 한다.** 이 절의 반례는 물건 세 개다. 크게 만들려는 생각이 반례 만들기 자체를 포기하게 한다.
- **"이해했다"를 "확정했다"로 착각한다.** 4단계의 세 줄이 안 써지면 확정이 아니다.
- **프로토콜을 에디터에서 돌린다.** 다섯 단계 전부 종이 위에서 돈다. 에디터를 여는 것은 4단계 이후다.
:::

::: interview
"이 문제를 어떻게 접근하시겠어요"라는 질문에 대한 가장 좋은 답은 **프로토콜을 소리 내어 실행하는 것**이다.

"먼저 제약을 보면 N이 10만이니 $O(N \log N)$까지 됩니다. 입력이 격자이고 최소 이동 횟수를 묻고 있으니 후보는 BFS와 다익스트라 둘입니다. 간선 비용이 전부 1이면 BFS가 맞는데, 지문에 벽을 부수는 비용이 따로 있으니 상태에 축이 하나 더 필요합니다. 상태를 (좌표, 남은 부수기 횟수)로 두면 다시 비용이 균일해져서 BFS로 돌아옵니다."

이 답변이 좋은 이유는 정답을 맞혀서가 아니라 **판단의 근거가 전부 밖으로 나와 있기 때문이다.** 전제가 틀렸다면 면접관이 그 자리에서 짚을 수 있고, 후보가 둘이라는 것은 다른 가능성을 검토했다는 표시다. "BFS로 풀겠습니다"만 말하면 맞아도 검증 과정이 보이지 않는다.
:::

## 연습

::: quiz
각 문제에 대해 **프로토콜 다섯 단계를 표로 채워라.** 코드는 짜지 않는다. 3단계에서 후보 하나를 죽이는 입력을 실제로 적는 것이 이 연습의 핵심이다.

**1. 백준 1932 정수 삼각형 (실버 1)** — https://www.acmicpc.net/problem/1932
- 지문: 삼각형 맨 위에서 아래로 내려오며 아래층의 왼쪽 또는 오른쪽 수를 고른다. 합의 최댓값. `삼각형 크기 ≤ 500`
- 후보 하나는 "매 층에서 더 큰 쪽을 고르는 그리디"로 세워라. 그것을 죽이는 삼각형을 네 줄 이하로 만들 수 있는가.

**2. 백준 11399 ATM (실버 3)** — https://www.acmicpc.net/problem/11399
- 지문: N명이 ATM 앞에 줄을 선다. i번 사람이 걸리는 시간이 P_i일 때, 각자가 기다린 시간의 합을 최소로 하는 순서를 찾아라. `N ≤ 1,000`
- 여기서는 그리디가 **산다.** 왜 죽지 않는지를 반례를 못 만드는 이유로 설명하라. 앞사람의 시간이 뒤의 몇 명에게 더해지는가.

**3. 백준 1339 단어 수학 (골드 4)** — https://www.acmicpc.net/problem/1339
- 지문: 알파벳 대문자로 된 N개의 단어를 0~9 숫자로 바꿔 합을 최대로 만든다. 같은 문자는 같은 숫자, 서로 다른 문자는 다른 숫자다. `N ≤ 10`, 단어 길이 ≤ 8
- 0단계에서 완전탐색의 규모를 실제로 계산하라. 서로 다른 문자가 최대 10개일 때 배정의 가짓수는 몇인가.

::: answer
**1.** 0단계: 층이 500이면 칸이 약 12만 개, $O(n^2)$이 여유 있게 든다. 1단계: 입력 형태 = 격자(삼각형), 묻는 것 = 최적. 2단계: A = 층마다 더 큰 쪽을 고르는 그리디 $O(n)$ / B = 2차원 DP $O(n^2)$. 3단계: A를 죽이는 삼각형은 세 줄이면 된다.

```text nolines
        1
       9 1
      0 0 100
```

그리디는 1에서 9를 골라 `1 + 9 + 0 = 10`으로 끝난다. 오른쪽으로 내려가면 `1 + 1 + 100 = 102`다. **지금 큰 수를 고른 것이 다음 층의 선택지를 나쁜 쪽으로 가둔다.** A 사망. 4단계: 상태 = `dp[i][j]` = (i,j)까지의 최대 합 / 전이 = 위층의 두 후보 중 큰 쪽 + 현재 값 / 자료구조 = 2차원 배열(한 줄만 굴려도 된다).

**2.** 0단계: `N ≤ 1,000`이라 $O(N^2)$도 들지만 정렬 $O(N \log N)$이면 충분하다. 1단계: 입력 형태 = 수열, 묻는 것 = 최적. 2단계: A = 짧은 사람부터 세우는 그리디 / B = 순열 전체 탐색. B는 $1000!$이라 0단계에서 즉사한다. 3단계: A를 죽이려면 "짧은 사람을 앞에 세운 것을 무르고 싶어지는 입력"이 필요한데, 만들 수 없다. 이유가 구조에 있다. **앞에서 k번째 사람의 시간은 뒤의 `N - k + 1`명 전부의 대기 시간에 더해진다.** 즉 앞자리일수록 가중치가 크므로 작은 값을 앞에 두는 것이 항상 낫고, 두 사람의 순서를 바꿔 보면 손해가 즉시 계산된다. 이 논증이 교환 논법이고 [VI-1](#/vi-1)에서 다룬다. 4단계: 상태 = 정렬된 순서 / 진행 = 누적합 / 자료구조 = 배열 하나.

**3.** 0단계: 서로 다른 문자가 최대 10개이므로 배정의 가짓수는 $10! = 3{,}628{,}800$이다. **이것은 실제로 시간 안에 든다** — 완전탐색이 죽지 않는 드문 경우다. 그래서 3단계에서 후보가 둘 다 살아남는다. 2단계: A = 문자 배정 완전탐색 $O(10! \cdot N)$ / B = 자리값 그리디 $O(N \cdot L + 26 \log 26)$. 3단계: B를 죽이려면 "자리값이 큰 문자에 큰 숫자를 준 것을 무르고 싶어지는 입력"이 필요한데 만들 수 없다. 각 문자의 기여는 **그 문자가 놓인 모든 자리의 자리값 합 × 배정한 숫자**로 정확히 분해되고, 두 문자의 숫자를 맞바꾸면 손해가 바로 계산되기 때문이다. 4단계: 상태 = 문자별 자리값 가중치 / 진행 = 가중치 내림차순으로 9부터 배정 / 자료구조 = 길이 26 정수 배열. **둘 다 살아남았을 때 싼 쪽으로 가는 규칙**이 여기서 그대로 적용된다.
:::
:::

## 요약

- 판별의 실패는 두 방향이다. **너무 일찍 확정**하거나 **끝없이 미확정**이거나. 둘 다 진행 중에 자각되지 않으므로 의지가 아니라 **단계와 예산**으로 고친다.
- 다섯 단계: **제약 역산(45초) → 지문 1회독(90초) → 후보 2개(60초) → 반례 던지기(75초) → 확정(30초).** 각 단계에는 종이에 남는 산출물이 있고, 산출물이 없으면 그 단계는 하지 않은 것이다.
- **제약을 지문보다 먼저 읽는다.** 순서를 바꾸면 제약이 후보를 자르는 대신 첫인상을 정당화한다.
- **후보는 정확히 둘, 그리고 이웃이어야 한다.** 하나면 검증이 사라지고 셋이면 예산을 넘는다. 완전히 다른 둘을 적었다면 1단계가 실패한 것이다.
- **3단계가 프로토콜의 본체다.** 후보를 죽이는 입력을 만들려고 시도한다. 후보마다 죽이는 방향이 정해져 있고, 반례는 원소 서너 개면 된다.
- **4단계의 세 줄(상태·전이·자료구조)이 안 써지면 확정이 아니다.** 그 상태로 에디터를 열면 구현 시간이 판별 시간을 겸하게 된다.
- 5분에 확정이 안 되면 **어느 단계에서 막혔는지를 한 단어로 적고** 넘긴다. 단계별로 대응이 다르다.
