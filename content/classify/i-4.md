# I-4 결정 트리 전문

::: lead
신호어가 후보를 부르고 나면, 무엇이 그중 하나를 고르는가.
:::

## 1. 문제

신호어만으로는 끝나지 않는 지문이 있다.

> $N$개의 도시가 있고 도시 사이를 이동하는 비용이 주어진다. 한 도시에서 출발해 **모든 도시를 정확히 한 번씩** 들르고 출발한 도시로 돌아오는 최소 비용을 구하라.

"최소 비용"이 나왔고 대상이 도시와 이동 비용이니 그래프다. [I-3 신호어 사전](#/i-3)의 표는 여기서 다익스트라를 1순위로 부른다. 그런데 다익스트라를 아무리 잘 짜도 이 문제는 풀리지 않는다.

이유는 **묻는 것이 다르기 때문이다.** 다익스트라가 답하는 질문은 "한 정점에서 다른 한 정점까지의 최소 비용"이다. 이 문제가 묻는 것은 "모든 정점을 한 번씩 도는 **순서** 중 최소 비용"이다. 앞쪽의 상태는 "지금 어느 정점에 있는가" 하나로 충분하지만, 뒤쪽은 "지금 어디에 있는가"와 "지금까지 어디를 들렀는가"를 같이 들어야 한다. 상태의 모양이 다르면 알고리즘이 다르다.

==입력이 무엇인가와 묻는 것이 무엇인가, 이 두 축이 정해져야 알고리즘이 하나로 좁혀진다.== 신호어는 축 하나만 건드린다. 이 절은 나머지 축을 세운다.

## 2. 두 축

### 축 1 — 입력 형태

지문이 주는 데이터의 모양이다. 입력 형식 부분만 읽어도 결정된다.

| 형태 | 어떻게 알아보는가 |
|---|---|
| **격자** | $N \times M$ 크기의 2차원 배열이 통째로 들어온다 |
| **그래프** | 정점 수와 간선 수가 따로 주어지고 간선 목록이 이어진다 |
| **수열** | 수 $N$개가 한 줄로 들어온다. 순서에 의미가 있다 |
| **문자열** | 문자열이 하나 또는 둘 들어온다 |
| **기하** | 좌표 쌍이 들어온다 |
| **수 하나** | 입력이 몇 개의 수뿐이다. $N \le 10^{18}$ 같은 큰 값이 많다 |

::: note
형태는 겉모습이지 본질이 아니다. **격자는 각 칸을 정점으로, 인접 관계를 간선으로 보면 그래프다.** 수열도 인덱스를 정점으로 보면 그래프다. 그래서 이 축은 "무엇으로 볼 수 있는가"가 아니라 "지문이 무엇을 주는가"로 읽는다. 변환은 그다음 단계에서 한다([IV-1 그래프 표현](#/iv-1)).
:::

### 축 2 — 묻는 것

**출력 문장 한 줄이 결정한다.** 지문의 마지막 문단만 보면 된다.

| 묻는 것 | 출력 문장의 모양 | 성질 |
|---|---|---|
| **존재** | "가능하면 YES, 아니면 NO" · "만들 수 있는가" | 답이 두 값 중 하나다. 하나만 찾으면 즉시 끝낼 수 있다 |
| **개수** | "경우의 수를 출력" · "몇 개인가" · "나눈 나머지" | 중복을 세지 않는 것이 본체다 |
| **최적** | "최솟값을 출력" · "최대 몇 개" | 값 하나만 필요하고 그 값을 만든 방법은 필요 없다 |
| **구성** | "순서를 출력" · "경로를 출력" · "어떻게 나누는지 출력" | 답을 실제로 복원해야 한다 |

이 축이 중요한 이유는 **비용의 순서가 있기 때문이다.**

$$\text{존재} \;\le\; \text{최적} \;\le\; \text{구성}, \qquad \text{개수는 따로 어렵다}$$

- **존재는 가장 싸다.** 하나를 찾는 순간 멈춘다. 도달 가능성만 물으면 DFS로 충분하고 BFS의 거리 계산이 필요 없다.
- **구성은 최적보다 한 단계 비싸다.** 최적값만 구하면 표 한 줄만 굴려도 되지만, 답을 복원하려면 **어디에서 왔는지를 기록해야 한다.** DP의 역추적 배열, BFS의 부모 배열이 그것이다. 메모리가 차원 하나만큼 늘어난다.
- **개수는 다른 축이다.** 최적값 계산은 `min`이나 `max`를 쓰지만 개수 계산은 합을 쓴다. 그래서 **같은 상태 정의로 최적은 되는데 개수는 안 되는 경우가 생긴다.** 서로 다른 경로가 같은 상태를 지나면 최적값은 문제없지만 개수는 중복으로 세어진다. 상태 정의를 다시 해야 한다([VIII-11 DP 상태 정의 실패 사례집](#/viii-11)).

마지막 항목은 말로만 들으면 추상적이니 상황 하나로 고정해 두자. 동전 1원과 2원으로 3원을 만드는 방법을 센다고 하자. 상태를 "만든 금액"으로만 두고 각 금액마다 모든 동전을 시도하면 `1+2`와 `2+1`이 서로 다른 방법으로 세어진다. 순서를 구별하지 않는 답을 원했다면 이것은 틀린 수다. 최솟값을 물었다면 두 경로가 같은 값을 주므로 아무 문제도 드러나지 않는다. ==개수 문제에서 상태 정의의 실패는 조용히 틀린 수를 낸다.== 고치는 방법은 동전을 바깥 루프로 빼서 "어떤 동전까지 쓸 수 있는가"를 상태에 넣는 것이고, 그 순간 상태가 한 차원 늘어난다.

::: warn
"최솟값과 그때의 경로를 함께 출력하시오"는 최적이 아니라 **구성**이다. 문장 뒤쪽의 조건절을 놓치면 다 짜 놓고 역추적을 추가하느라 구조를 갈아엎게 된다. 출력 문장은 끝까지 읽는다.
:::

## 3. 2축 매트릭스

행이 입력 형태, 열이 묻는 것이다. 각 칸이 곧 후보군이다.

| | 존재 | 개수 | 최적 | 구성 |
|---|---|---|---|---|
| **격자** | 도달 가능성 DFS·BFS([IV-2](#/iv-2)) | 연결 요소 개수·플러드필([IV-5](#/iv-5)), 경로 수 DP | BFS 최단 거리([IV-3](#/iv-3)), 0-1 BFS([IV-4](#/iv-4)), 격자 DP([VIII-4](#/viii-4)) | BFS + 부모 배열로 경로 복원, 백트래킹([III-4](#/iii-4)) |
| **그래프** | 연결성 DFS, 유니온 파인드([IX-1](#/ix-1)), 이분 그래프([IV-7](#/iv-7)), 사이클 검출 | 연결 요소 수, DAG 경로 수 DP | 다익스트라([V-1](#/v-1)), 벨만-포드([V-2](#/v-2)), 플로이드-워셜([V-3](#/v-3)), MST([IX-4](#/ix-4)) | 최단 경로 복원, 위상 정렬 순서([IV-6](#/iv-6)), MST 간선 목록 |
| **수열** | 이분 탐색([VII-1](#/vii-1)), 해시 집합([II-6](#/ii-6)), 투 포인터([VI-3](#/vi-3)) | 누적 합 + 해시, 조합([X-4](#/x-4)), DP | LIS([VIII-6](#/viii-6)), 최대 부분합([VIII-3](#/viii-3)), 슬라이딩 윈도우, 매개변수 탐색([VII-3](#/vii-3)), 그리디([VI-1](#/vi-1)) | LIS 역추적, DP 역추적, 그리디 선택 목록 |
| **문자열** | KMP([IX-7](#/ix-7)), 트라이([IX-6](#/ix-6)) | 등장 횟수 KMP, 부분 문자열 개수 DP | LCS([VIII-6](#/viii-6)), 편집 거리([VIII-4](#/viii-4)) | LCS 문자열 복원, 편집 연산 목록 |
| **기하** | CCW 선분 교차([X-5](#/x-5)), 내부 판정 | 교차 쌍의 수·스위핑([VI-6](#/vi-6)) | 볼록 껍질([X-6](#/x-6)), 최근접 점 쌍 | 볼록 껍질의 점 목록 |
| **수 하나** | 소수 판정([X-2](#/x-2)), 정수해 존재 | 조합·모듈러([X-3](#/x-3)), 자릿수 DP | 매개변수 탐색([VII-3](#/vii-3)), 수학적 최적화 | 소인수분해 결과([X-2](#/x-2)) |

칸을 하나 고르면 후보가 두세 개로 줄어든다. 남은 선택은 제약조건([I-2 제약조건 역산법](#/i-2))이 마무리한다. 예를 들어 **수열 × 최적** 칸에서 $N \le 5{,}000$이면 $O(N^2)$ LIS이고 $N \le 10^6$이면 이분 탐색을 쓰는 $O(N \log N)$ LIS다. 유형은 같고 구현이 갈린다.

## 4. 걸어 다니는 트리

매트릭스는 조회용이고, 실제 판별은 질문에 답하며 내려간다.

```text nolines
  STEP 1   what does the input look like ?
    ├── grid            ──▶ go to 4.1
    ├── graph           ──▶ go to 4.2
    ├── sequence        ──▶ go to 4.3
    ├── string          ──▶ 3.8 signal table
    ├── geometry        ──▶ CCW first                       (X-5)
    └── a few numbers   ──▶ number theory / parametric       (X-1, VII-3)

  STEP 2   what does the last sentence ask ?
    ├── EXIST   ──▶ stop as soon as one is found
    ├── COUNT   ──▶ define state so that nothing is counted twice
    ├── OPT     ──▶ one value is enough
    └── BUILD   ──▶ OPT + parent / choice table
```

### 4.1 입력이 격자일 때

```text nolines
  grid
   ├── no movement, only labeling
   │     └──▶ flood fill                                     (IV-5)
   ├── move cost is uniform
   │     ├── one start        ──▶ BFS                        (IV-3)
   │     └── many starts      ──▶ multi-source BFS           (IV-4)
   ├── move cost is 0 or 1    ──▶ 0-1 BFS with a deque       (IV-4)
   ├── move cost is any positive ─▶ Dijkstra                 (V-1)
   ├── direction is one-way (only down / right)
   │     └──▶ grid DP                                        (VIII-4)
   └── state needs more than the cell
         ├── walls broken so far  ──▶ BFS on (cell, k)       (IV-3)
         └── items collected      ──▶ BFS on (cell, bitmask) (VIII-9)
```

마지막 갈래가 이 트리의 핵심이다. **칸 하나로 상태가 부족하면 상태를 늘린다.** 벽을 $K$번까지 부술 수 있으면 상태는 (칸, 지금까지 부순 횟수)이고, 방문 배열도 그만큼 차원이 늘어난다. 이 확장은 시간 축을 상태에 더하는 [V-8 시공간 A\*와 예약 테이블](#/v-8)까지 같은 발상으로 이어진다.

### 4.2 입력이 그래프일 때

```text nolines
  graph
   ├── only connectivity matters
   │     ├── edges arrive one by one ──▶ union-find          (IX-1)
   │     └── graph is fixed          ──▶ DFS / BFS           (IV-2)
   ├── edges have direction and mean "before"
   │     └──▶ topological sort                               (IV-6)
   ├── shortest path between two vertices
   │     ├── all weights equal   ──▶ BFS                     (IV-3)
   │     ├── weights positive    ──▶ Dijkstra                (V-1)
   │     ├── some weight negative ─▶ Bellman-Ford            (V-2)
   │     └── all pairs, V <= 500 ──▶ Floyd-Warshall          (V-3)
   ├── connect everything at minimum cost
   │     └──▶ MST: Kruskal / Prim                            (IX-4)
   └── visit every vertex once, N <= 20
         └──▶ bitmask DP (TSP)                               (VIII-9)
```

그래프 쪽 트리에서 첫 갈래가 가장 자주 틀린다. **연결 여부만 필요한지, 경로 자체가 필요한지를 먼저 가른다.** "두 사람이 같은 팀인가"만 물으면 유니온 파인드가 압도적으로 싸다. 대표만 비교하면 되고 경로를 만들지 않는다. 반대로 "몇 다리를 건너야 하는가"를 물으면 유니온 파인드로는 답할 수 없다. 유니온 파인드는 **소속을 알지 거리를 모르기 때문이다.** 이 구분이 [IX-1 유니온 파인드](#/ix-1)와 [IV-3 BFS와 최단 거리](#/iv-3)를 가른다.

두 번째로 자주 틀리는 지점은 세 번째 갈래의 마지막 줄이다. 모든 쌍의 최단 거리를 물었다고 무조건 플로이드-워셜은 아니다. 정점이 $10^4$이면 $O(V^3) = 10^{12}$라 죽고, 대신 다익스트라를 정점 수만큼 돌리는 $O(V \cdot E \log V)$가 이긴다. **알고리즘의 이름이 아니라 정점 수가 고른다.**

### 4.3 입력이 수열일 때

```text nolines
  sequence
   ├── a contiguous window is asked
   │     ├── window grows and shrinks monotonically
   │     │     └──▶ two pointer / sliding window             (VI-3)
   │     └── the same range is asked many times
   │           ├── no update  ──▶ prefix sum                 (VI-4)
   │           └── has update ──▶ segment tree / BIT          (IX-2, IX-3)
   ├── a subsequence (gaps allowed) is asked
   │     └──▶ DP: LIS / LCS                                  (VIII-6)
   ├── the answer itself is a number with monotone check
   │     └──▶ parametric search                              (VII-3)
   └── order can be changed freely
         └──▶ sort first, then greedy                        (VI-1)
```

수열 쪽 트리의 첫 질문은 **"연속인가"** 하나다. 연속 구간이면 양 끝을 미는 두 포인터가 성립하고, 띄엄띄엄 골라도 되면 그 순간 조합이 폭발해 DP로 넘어간다. 그다음 질문은 **"같은 구간을 여러 번 묻는가"** 다. 한 번이면 그냥 더하면 되고, 여러 번이면 전처리가 필요하다. 그리고 전처리 방식은 갱신의 유무가 정한다.

세 번째 갈래는 모양이 특이해서 알아보기 쉽다. **답 자체가 탐색 대상이 되는 경우다.** 배열의 원소를 찾는 것이 아니라 "답이 $x$일 때 조건을 만족하는가"를 판정하며 $x$를 이분한다. 수열 문제인데 정렬해도 아무 소용이 없고 DP 상태도 안 잡히면 이 갈래를 의심한다([VII-3 매개변수 탐색](#/vii-3)).

## 5. 절차를 한 번 끝까지 밟기

도입부의 도시 문제를 트리로 내려가 보자. 제약은 $N \le 16$이다.

1. **제약 역산.** $16! \approx 2 \times 10^{13}$은 불가능하고 $2^{16} \times 16 \times 16 \approx 1.7 \times 10^7$은 가능하다. 후보는 지수 시간이되 $2^N$ 쪽이다.
2. **입력 형태.** 정점과 비용 행렬이 들어온다. 그래프다.
3. **묻는 것.** 마지막 문장이 "최소 비용을 출력"이므로 최적이다. 순서를 출력하라고 했다면 구성이 되어 역추적 표가 하나 더 붙는다.
4. **매트릭스 칸.** 그래프 × 최적. 후보는 다익스트라, 벨만-포드, 플로이드-워셜, MST, 비트마스크 DP.
5. **후보 거르기.** 앞의 넷은 전부 상태가 "정점 하나"다. 이 문제는 "이미 들른 도시들"을 기억하지 않으면 같은 도시를 두 번 밟는 답을 막을 수 없다. **상태에 집합이 들어가야 한다는 요구가 앞의 넷을 전부 탈락시킨다.** 그리고 $N \le 16$은 집합을 정수 하나로 표현하라는 지시다.

결론은 비트마스크 DP다. 여기서 결정적인 것은 5번이었고, 그 판단의 근거는 신호어가 아니라 **상태의 모양**이었다.

::: tip
후보를 거르는 가장 강력한 질문은 언제나 같다. **"이 알고리즘의 상태 하나로 이 문제를 구별할 수 있는가."** 구별되지 않는 두 상황이 같은 상태로 뭉개지면 그 알고리즘은 틀린다. 상태를 늘려서 구별되게 만드는 것이 다음 단계이고, 늘린 상태가 감당 못 할 크기면 유형 자체가 바뀐다.
:::

- 신호어: "가능한지 판별하시오", "만들 수 있는가", "YES 또는 NO를 출력"
- 제약조건: 답이 두 값 중 하나다. 하나를 찾는 순간 중단할 수 있어 최악과 평균의 차이가 크다
- 혼동 주의: 존재만 물으면 DFS로 충분하다. BFS를 쓰는 것은 최소 거리가 필요할 때뿐이다([IV-3](#/iv-3)). 개수를 물으면 조기 종료가 불가능해져 전혀 다른 문제가 된다
- 반례 함정: 찾자마자 멈추는 최적화 때문에 방문 처리나 상태 복원이 빠지는 실수가 잦다. 백트래킹에서 조기 종료할 때 되돌리기를 건너뛰면 다음 탐색이 오염된다([III-4](#/iii-4))
:::

::: classify
- 신호어: "경로를 출력하시오", "순서를 출력하시오", "어떻게 나누는지 출력", "최솟값과 그때의 방법을"
- 제약조건: 답을 복원해야 하므로 상태마다 "어디에서 왔는가"를 저장한다. 메모리가 상태 수만큼 더 든다. 최적값만 구할 때 쓰던 차원 축소 기법을 쓸 수 없다
- 혼동 주의: 최적값만 묻는 문제와 구현이 다르다([VIII-2](#/viii-2)). 답이 여러 개일 때 아무거나 되는지 사전순으로 가장 빠른 것인지 확인한다. 후자면 탐색 순서 자체를 정렬해야 한다
- 반례 함정: 역추적 배열을 갱신하지 않은 채 값만 갱신하면 값은 맞고 경로는 틀린다. 경로를 뒤에서부터 쌓았으면 출력 전에 뒤집는 것을 잊지 않는다
:::

::: pitfall
- **축 하나로 결정한다.** "그래프"만 보고 다익스트라를, "최소"만 보고 BFS를 부르면 도입부의 도시 문제에서 그대로 틀린다. 두 축이 다 서야 한다.
- **출력 문장을 끝까지 안 읽는다.** "그리고 그 경로를 출력하시오"가 뒤에 붙어 있으면 최적이 아니라 구성이다.
- **개수 문제에 최적 상태 정의를 그대로 쓴다.** 서로 다른 경로가 같은 상태로 모이면 최적값은 맞고 개수는 틀린다.
- **입력 형태를 겉모습으로만 본다.** 좌표가 들어온다고 전부 기하가 아니다. 좌표가 그저 정점의 이름이면 그래프다.
- **상태를 늘려야 하는데 늘리지 않는다.** 벽을 부술 수 있는 격자에서 방문 배열을 2차원으로 두면 조건이 다른 두 상황이 같은 칸으로 뭉개진다.
:::

## 6. 어디에 쓰이는가

같은 두 축이 설계 결정에도 그대로 쓰인다. 자료의 모양(축 1)과 시스템이 답해야 하는 질문(축 2)이 자료구조를 결정한다.

| 자료의 모양 | 답해야 하는 질문 | 결과 |
|---|---|---|
| 정렬된 키의 큰 집합 | "이 키가 있는가"(존재) | 해시 또는 블룸 필터([XV-4](#/xv-4)) |
| 정렬된 키의 큰 집합 | "이 범위의 키를 전부"(구성) | B+Tree — 리프가 연결되어 범위 스캔이 된다([XV-2](#/xv-2)) |
| 이벤트 스트림 | "고유 방문자가 몇 명인가"(개수) | HyperLogLog([XV-6](#/xv-6)) |
| 작업 목록과 의존 관계 | "실행 순서"(구성) | 위상 정렬([IV-6](#/iv-6)) |
| 지도와 로봇의 현재 위치 | "목표까지의 경로"(구성) | A\* 후 경로 복원([V-5](#/v-5)) |

두 번째 줄이 이 축의 값어치를 보여 준다. 같은 자료에 대해 **존재만 물으면 해시가 이기고 범위를 물으면 트리가 이긴다.** 해시는 순서를 버리는 대신 조회를 $O(1)$로 만들었기 때문이다. 묻는 것이 바뀌면 자료구조가 바뀐다.

## 연습

::: quiz
코드를 짜지 마라. **두 축을 각각 답하고 매트릭스의 어느 칸인지 적어라.**

**1. 백준 2667 단지번호붙이기 (실버 1)** — https://www.acmicpc.net/problem/2667
- 축: 격자 × 개수(그리고 각 단지의 크기까지 요구하므로 구성이 약간 섞인다).
- 상태: 아직 방문하지 않은 1의 칸 하나. 거기서 연결된 칸을 전부 소진하면 단지 하나가 끝난다.
- 왜 그 자료구조인가: 방문 배열과 큐. 거리 정보가 필요 없으므로 BFS의 거리 계산은 쓰지 않는다. 단지 크기를 오름차순으로 출력하라는 조건이 마지막에 정렬을 하나 더 요구한다.

**2. 백준 1753 최단경로 (골드 4)** — https://www.acmicpc.net/problem/1753
- 축: 그래프 × 최적. 간선 가중치가 10 이하의 자연수라 전부 양수다.
- 상태: 각 정점까지의 최단 거리 하나. 정점 하나로 상태가 충분하다는 것이 확인되는 지점이다.
- 왜 그 자료구조인가: 최소 힙. 정점 $2 \times 10^4$, 간선 $3 \times 10^5$에서 $O(E \log V)$면 충분하다. 경로까지 출력하라고 했다면 부모 배열이 하나 더 붙어 구성 문제가 된다.

**3. 백준 11053 가장 긴 증가하는 부분 수열 (실버 2)** — https://www.acmicpc.net/problem/11053
- 축: 수열 × 최적. "부분 수열"이므로 연속이 아니다. 이 한 단어가 투 포인터를 배제한다.
- 상태: $i$번째 수로 **끝나는** 증가 부분 수열의 최대 길이. "끝나는"이 상태 정의의 전부다.
- 왜 그 자료구조인가: 1차원 배열. $N \le 1{,}000$이라 $O(N^2)$이 허용된다. 상한이 $10^6$이었다면 같은 유형이 이분 탐색을 쓰는 $O(N \log N)$ 구현으로 바뀐다.

**4. 백준 9251 LCS (골드 5)** — https://www.acmicpc.net/problem/9251
- 축: 문자열 × 최적. 두 문자열이고 "부분 수열"이다.
- 상태: 첫 문자열의 앞 $i$글자와 둘째 문자열의 앞 $j$글자까지 봤을 때의 답. 문자열이 둘이라 상태도 2차원이다.
- 왜 그 자료구조인가: 2차원 표. 길이가 각각 1,000이면 $10^6$칸이라 들어간다. **LCS 문자열 자체를 출력하라고 하면 같은 표에 역추적이 붙어 구성 문제가 된다.**

**5. 백준 1197 최소 스패닝 트리 (골드 4)** — https://www.acmicpc.net/problem/1197
- 축: 그래프 × 최적. 다만 "두 정점 사이"가 아니라 "모든 정점을 연결"이다. 이 차이가 최단경로를 배제한다.
- 상태: 지금까지 고른 간선들이 만드는 연결 관계. 간선을 하나 고를 때마다 "이미 연결되어 있는가"를 물어야 한다.
- 왜 그 자료구조인가: 정렬된 간선 목록 + 유니온 파인드. 사이클 검사를 매번 DFS로 하면 간선마다 $O(V+E)$가 들어 전체가 무너진다.
:::

## 요약

- 신호어는 축 하나만 건드린다. **입력 형태와 묻는 것 두 축이 서야 알고리즘이 하나로 좁혀진다.**
- 입력 형태는 입력 형식만 봐도 정해지고, 묻는 것은 **출력 문장 한 줄**이 정한다.
- 묻는 것에는 비용의 순서가 있다. 존재 ≤ 최적 ≤ 구성이고, **개수는 별도의 어려움**을 갖는다. 중복을 세지 않는 상태 정의가 본체다.
- 구성은 최적에 역추적 배열이 붙은 것이다. 그래서 최적값 계산에서 쓰던 차원 축소를 쓸 수 없다.
- 매트릭스로 칸을 고르면 후보가 두셋으로 줄고, 나머지는 제약조건이 마무리한다.
- 후보를 거르는 가장 강한 질문은 **"이 알고리즘의 상태 하나로 이 문제를 구별할 수 있는가"** 다. 구별이 안 되면 상태를 늘리고, 늘린 상태가 감당 못 할 크기면 유형이 바뀐다.
- 같은 두 축이 설계에도 쓰인다. 존재만 물으면 해시가 이기고 범위를 물으면 트리가 이긴다.
