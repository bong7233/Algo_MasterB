# VII-2 lower_bound / upper_bound / bisect

::: lead
경계를 두 개 잡으면 개수·구간·순위가 전부 뺄셈 한 번으로 나온다. 그리고 그 두 개는 이미 표준 라이브러리에 있다.
:::

## 1. 문제

정렬된 배열 `a = [1, 3, 3, 3, 5, 7, 7, 9]`가 있다. 질문 네 개가 들어온다.

1. 3이 몇 개인가
2. 3 이상 7 이하가 몇 개인가
3. 5보다 작은 값 중 가장 큰 것은 무엇인가
4. 4를 넣으면 몇 번째 자리인가

전부 이분 탐색으로 푸는 문제인데, 넷을 각각 짜기 시작하면 함수가 네 개가 되고 부등호가 여덟 군데가 된다. [VII-1](#/vii-1)에서 본 네 자리의 실수가 함수마다 반복된다.

실제로는 **경계 함수 두 개면 넷이 전부 파생된다.** 하나는 "x 이상인 첫 위치", 다른 하나는 "x 초과인 첫 위치"다. 둘의 차이는 부등호 하나뿐이고, 나머지는 두 위치의 뺄셈과 인덱스 하나 조정으로 끝난다.

그리고 그 두 함수는 Python의 `bisect`와 C++의 `<algorithm>`에 이미 들어 있다. ==여기서 실력은 직접 짜는 능력이 아니라 **어느 쪽을 부를지 아는 능력**이다.== 부등호를 잘못 고르면 라이브러리는 조용히 다른 답을 준다.

## 2. 아이디어

### 2.1 두 함수를 "위치"로 정의한다

📖 `lower_bound(a, x)` — `a[i] >= x`인 **첫 위치**. 곧 `x`를 끼워 넣어도 정렬이 유지되는 **가장 왼쪽** 자리. $O(\log n)$.
　 Python 대응: `bisect.bisect_left(a, x)`. 이름만 다르고 의미가 같다.

📖 `upper_bound(a, x)` — `a[i] > x`인 **첫 위치**. 곧 `x`를 끼워 넣어도 정렬이 유지되는 **가장 오른쪽** 자리. $O(\log n)$.
　 Python 대응: `bisect.bisect_right(a, x)` (별칭 `bisect.bisect`).

정의를 "탐색"이 아니라 **위치**로 외워야 조합이 된다. "3을 찾는다"로 외우면 3이 없을 때 무슨 값이 나오는지 매번 다시 생각해야 하지만, "3이 들어갈 자리"로 외우면 3이 없어도 답이 하나로 정해진다.

```text nolines
  index      0    1    2    3    4    5    6    7        8
  a[i]       1    3    3    3    5    7    7    9
                 ^                   ^
                 |                   +-- upper_bound(a, 3) = 4
                 +---------------------- lower_bound(a, 3) = 1

  왼쪽 구간 [0, 1)  : x 보다 작은 값들
  가운데   [1, 4)  : x 와 같은 값들      <- 길이가 곧 개수다
  오른쪽   [4, 8)  : x 보다 큰 값들
```

두 위치가 배열을 세 토막으로 자른다. **가운데 토막의 길이가 곧 `x`의 개수**이고, 이것이 두 함수를 따로 배우지 않고 한 쌍으로 배우는 이유다.

위젯은 같은 배열 위에서 두 탐색을 나란히 재생한다. 위쪽 줄이 `lower_bound`, 아래쪽 줄이 `upper_bound`이고, 스텝 버튼을 누르면 두 구간이 동시에 좁혀진다. 술어 열만 다르고 나머지 세 줄(루프 조건·`mid` 계산·갱신 규칙)은 글자 하나 다르지 않다는 것이 화면에서 보여야 한다. 두 탐색이 끝나면 배열이 세 색 구간으로 칠해지고, 가운데 구간 위에 `upper - lower` 값이 배지로 붙는다. 목표값을 배열에 없는 값(예: 4)으로 바꾸면 두 경계가 같은 자리에서 만나 가운데 구간이 사라진다 — 개수 0이다.

### 2.2 나머지는 전부 조합이다

| 묻는 것 | 식 | 왜 |
|---|---|---|
| `x`의 개수 | `upper(x) - lower(x)` | 가운데 토막의 길이 |
| `x`가 있는가 | `lower(x) < n and a[lower(x)] == x` | 경계 위치에서 파생 |
| `[L, R]` 안의 개수 | `upper(R) - lower(L)` | 두 경계 사이의 길이 |
| `x` 미만 중 최댓값 | `a[lower(x) - 1]` (단 `lower(x) > 0`) | 경계 바로 왼쪽 |
| `x` 초과 중 최솟값 | `a[upper(x)]` (단 `upper(x) < n`) | 경계 그 자리 |
| `x`의 순위(0-기반) | `lower(x)` | 자기보다 작은 원소의 개수 |

여섯 줄 전부 경계 두 개의 산술이다. ==새 함수를 짜야 할 것 같은 느낌이 들면, 대개는 두 경계 중 하나를 잘못 골랐거나 인덱스를 하나 덜 조정한 것이다.==

경계 조정에서 반드시 붙는 단서가 있다. `lower(x) - 1`은 `lower(x) == 0`일 때 `-1`이 된다. Python에서 `a[-1]`은 예외가 아니라 **마지막 원소**라 그대로 틀린 답이 나온다. C++에서는 정의되지 않은 동작이다. 두 언어 모두 조건을 먼저 확인해야 하고, 위험한 쪽은 조용히 답을 주는 Python이다.

### 2.3 `bisect_right`가 기본값인 이유

Python에서 `bisect.bisect`는 `bisect_right`의 별칭이다. 왼쪽이 아니라 오른쪽이 기본이 된 이유는 `insort`와 짝이기 때문이다. 같은 값이 이미 있을 때 **뒤에 넣는 것**이 삽입 순서를 보존한다. 정렬 안정성과 같은 사고방식이다([II-7 정렬](#/ii-7)).

📖 `bisect.insort(a, x)` — 정렬을 유지하며 삽입. 위치 찾기는 $O(\log n)$이지만 **삽입 자체가 $O(n)$**이다. 리스트 중간 삽입이 뒤를 전부 밀기 때문이다([0-3 Python 내장 자료구조의 실제 비용](#/0-3)).
　 C++ 대응: `v.insert(std::lower_bound(...), x)` — 역시 $O(n)$이다.

계속 삽입하면서 계속 조회해야 한다면 이 조합은 답이 아니다. 균형 트리([II-9](#/ii-9))나 [XV-5 스킵 리스트](#/xv-5)로 간다. 반대로 **삽입이 다 끝난 뒤에만 조회한다면 전부 넣고 한 번 정렬하는 쪽**이 거의 항상 낫다.

## 3. 손으로 따라가기

::: trace
입력: `a = [1, 3, 3, 3, 5, 7, 7, 9]` (n = 8), `x = 3`. 구할 것은 `upper_bound`, 즉 `a[i] > 3`인 첫 위치.

[VII-1](#/vii-1)의 `lower_bound`와 **술어 한 글자만 다르다.** 불변식도 갱신 규칙도 그대로다.

| 스텝 | lo | hi | 폭 | mid | a[mid] | a[mid] > 3 | 갱신 |
|---|---|---|---|---|---|---|---|
| 0 | 0 | 8 | 8 | 4 | 5 | 예 | hi = 4 |
| 1 | 0 | 4 | 4 | 2 | 3 | 아니오 | lo = 3 |
| 2 |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |

채운 뒤 답하라.

- [ ] 최종 `lo`는 얼마인가
- [ ] 같은 배열에서 `lower_bound(a, 3) = 1`이다. 두 값의 차는 무엇을 뜻하는가
- [ ] 술어를 `>=`로 되돌리면 스텝 1의 갱신은 어떻게 달라지는가
:::

::: answer
| 스텝 | lo | hi | 폭 | mid | a[mid] | a[mid] > 3 | 갱신 |
|---|---|---|---|---|---|---|---|
| 0 | 0 | 8 | 8 | 4 | 5 | 예 | hi = 4 |
| 1 | 0 | 4 | 4 | 2 | 3 | 아니오 | lo = 3 |
| 2 | 3 | 4 | 1 | 3 | 3 | 아니오 | lo = 4 |
| 3 | 4 | 4 | 0 | — | — | — | `lo < hi`가 거짓, 종료 |

`upper_bound = 4`다. `lower_bound = 1`이므로 차는 3이고, 이것이 배열 안 3의 개수다. 실제로 `a[1] = a[2] = a[3] = 3`이다.

세 번째 질문이 이 절의 핵심이다. 스텝 1에서 `a[2] = 3`을 만났을 때, 술어가 `>`이면 거짓이라 `lo = mid + 1`로 **오른쪽으로 간다.** 술어가 `>=`이면 참이라 `hi = mid`로 **왼쪽에 남는다.** 같은 값을 만났을 때 어느 쪽으로 미느냐가 두 함수의 전부다. ==같은 값을 왼쪽에 남기면 첫 위치, 오른쪽으로 밀면 마지막 다음 위치다.==

중복이 없는 배열에서는 두 함수의 차가 0 아니면 1이라 어느 쪽을 써도 대개 통과한다. **중복이 있는 입력에서만 갈라진다.** 그래서 테스트 입력에 같은 값을 두 개 이상 넣지 않으면 이 버그는 채점기에서 처음 만난다.
:::

## 4. 구현

::: dual
```python title="경계 두 개와 그 조합 — 라이브러리와 대조까지"
from bisect import bisect_left, bisect_right


def lower_bound(a, x):
    """a[i] >= x 인 첫 위치. x 를 넣어도 정렬이 유지되는 가장 왼쪽 자리."""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] >= x:
            hi = mid
        else:
            lo = mid + 1
    return lo


def upper_bound(a, x):
    """a[i] > x 인 첫 위치. 부등호 하나만 바뀐다."""
    lo, hi = 0, len(a)
    while lo < hi:
        mid = lo + (hi - lo) // 2
        if a[mid] > x:
            hi = mid
        else:
            lo = mid + 1
    return lo


a = [1, 3, 3, 3, 5, 7, 7, 9]
for x in (3, 4, 9, 0):
    lb, ub = lower_bound(a, x), upper_bound(a, x)
    print(f"x={x}  lower={lb} upper={ub}  count={ub - lb}"
          f"  lib=({bisect_left(a, x)},{bisect_right(a, x)})")

L, R = 3, 7
print(f"[{L},{R}] 안의 원소 수 = {upper_bound(a, R) - lower_bound(a, L)}")
```
```cpp title="경계 두 개와 그 조합 — 라이브러리와 대조까지"
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

// a[i] >= x 인 첫 위치. x 를 넣어도 정렬이 유지되는 가장 왼쪽 자리.
int lower_bound(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size();
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= x)
            hi = mid;
        else
            lo = mid + 1;
    }
    return lo;
}

// a[i] > x 인 첫 위치. 부등호 하나만 바뀐다.
int upper_bound(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size();
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] > x)
            hi = mid;
        else
            lo = mid + 1;
    }
    return lo;
}

int main() {
    vector<int> a = {1, 3, 3, 3, 5, 7, 7, 9};
    for (int x : {3, 4, 9, 0}) {
        int lb = lower_bound(a, x), ub = upper_bound(a, x);
        cout << "x=" << x << "  lower=" << lb << " upper=" << ub
             << "  count=" << ub - lb
             << "  lib=(" << lower_bound(a.begin(), a.end(), x) - a.begin()
             << "," << upper_bound(a.begin(), a.end(), x) - a.begin() << ")\n";
    }
    int L = 3, R = 7;
    cout << "[" << L << "," << R << "] 안의 원소 수 = "
         << upper_bound(a, R) - lower_bound(a, L) << "\n";
    return 0;
}
```
:::

출력은 양쪽이 같다. 직접 짠 값과 라이브러리 값이 모든 질의에서 일치한다.

```console
x=3  lower=1 upper=4  count=3  lib=(1,4)
x=4  lower=4 upper=4  count=0  lib=(4,4)
x=9  lower=7 upper=8  count=1  lib=(7,8)
x=0  lower=0 upper=0  count=0  lib=(0,0)
[3,7] 안의 원소 수 = 6
```

**복잡도:** 시간 $O(\log n)$ — 폭이 매 반복 절반 이하로 줄고 폭 0에서 끝나므로 반복 횟수가 $\lceil \log_2 n \rceil$ 이하다. 개수 질의는 경계 두 개이므로 $2\log n$이고 상수 2가 붙을 뿐 차수는 같다. 공간 $O(1)$.

라이브러리를 쓸 이유는 언어마다 다르다. [VII-1](#/vii-1)의 실측에서 Python은 `bisect_left`가 손으로 짠 판보다 **약 5.7배 빨랐고**(2.44 μs → 0.43 μs), C++은 `std::lower_bound`와 직접 짠 판이 사실상 같았다(0.101 μs → 0.095 μs). Python 쪽 차이는 알고리즘이 아니라 **루프가 인터프리터에서 도는가 C에서 도는가**의 차이다. C++ 쪽은 같은 기계어로 컴파일되니 차이가 날 이유가 없다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 이름 | `bisect_left` / `bisect_right` | `lower_bound` / `upper_bound` |
| 반환 | 정수 인덱스 | 이터레이터. 인덱스가 필요하면 `- a.begin()` |
| 둘을 한 번에 | 없음. 두 번 부른다 | `equal_range`가 쌍으로 돌려준다 |
| 비교 기준 바꾸기 | `key=` 인자 (3.10+). 비교자는 못 받는다 | 네 번째 인자로 비교자를 받는다 |
| 정렬 기준 불일치 | 조용히 틀린 위치 | 정렬 기준과 다른 비교자를 주면 UB |
| `set`·`map`에서 | 애초에 쓸 수 없다 | 자유 함수를 쓰면 $O(n)$. 멤버 함수를 써야 한다 |

::: danger
C++에서 가장 비싼 실수는 컴파일 에러를 내지 않는다.

`std::lower_bound`는 정렬된 구간이면 어떤 이터레이터에도 쓸 수 있어서 `std::set`에도 **컴파일된다.** 그리고 $O(n)$이 된다. `set`의 이터레이터는 중간으로 점프하지 못하고 한 칸씩 걸어야 하기 때문이다. [0-7 C++ 알고리즘 함수 세트](#/0-7)의 실측에서 원소 100만 개의 `set`에 질의 20만 번을 던졌을 때 자유 함수는 10.74초, 멤버 함수 `s.lower_bound(x)`는 0.0010초였다. **약 1만 배다.**

==`set`과 `map`에는 반드시 멤버 함수를 써라.== 이유는 [0-8 C++ 반복자·람다·비교자](#/0-8)의 반복자 카테고리에 있다.
:::

::: pitfall
- **`bisect_right`를 기본값으로 쓴다.** `bisect.bisect`가 `bisect_right`라서 아무 생각 없이 부르면 "첫 위치"가 필요한 자리에 "마지막 다음 위치"가 들어간다. 중복이 없는 테스트 입력에서는 티가 나지 않는다.
- **내림차순 배열에 그대로 쓴다.** 두 함수 모두 오름차순을 전제한다. 내림차순이면 값의 부호를 뒤집어 넣거나(가장 값싸다) C++이라면 비교자를 넘긴다. 정렬 기준과 다른 비교자를 주면 C++에서는 UB다([0-8](#/0-8)).
- **경계 -1 을 검사하지 않는다.** `a[lower(x) - 1]`은 `lower(x) == 0`에서 Python이면 마지막 원소를 조용히 돌려주고 C++이면 UB다.
- **개수를 세려고 세 번 이상 부른다.** 두 번이면 끝난다. 세 번째 호출이 생겼다면 조합식을 다시 보라.
- **정렬을 안 한 채 부른다.** 정렬되지 않은 배열에 부르면 예외도 경고도 없이 아무 값이나 돌려준다. 이 버그는 입력이 우연히 거의 정렬되어 있을 때 가장 오래 살아남는다.
:::

## 5. 어디에 쓰이는가

**좌표 압축이 `lower_bound` 그 자체다.** 값의 범위가 $10^9$인데 실제로 등장하는 값은 $10^5$개일 때, 정렬하고 중복을 지운 배열에서 각 값의 `lower_bound`를 취하면 그것이 곧 압축된 좌표다. 순위 질의와 압축이 같은 함수인 이유는 §2.2의 마지막 줄에 있다 — `lower_bound(x)`는 "자기보다 작은 원소의 개수"다. 세그먼트 트리와 스위핑이 전부 이 전처리 위에서 돈다([VI-5 좌표 압축](#/vi-5), [IX-2 세그먼트 트리와 lazy propagation](#/ix-2)).

**가중치 랜덤 선택이 누적 합 위의 `bisect`다.** 확률이 `[0.1, 0.3, 0.6]`인 세 항목 중 하나를 뽑으려면 누적 합 `[0.1, 0.4, 1.0]`을 만들어 두고 $[0, 1)$ 난수 하나에 `bisect_right`를 부르면 끝난다. Python 표준 라이브러리의 `random.choices`가 정확히 이 구조로 구현되어 있다. A/B 테스트 트래픽 분배, 샘플링, 파티클 필터의 리샘플링([XIII-4 파티클 필터](#/xiii-4))이 같은 코드를 쓴다.

**시계열 저장소의 범위 질의는 경계 두 개다.** 타임스탬프로 정렬된 블록에서 `[t1, t2]` 구간을 뽑는 일은 `lower_bound(t1)`부터 `upper_bound(t2)`까지를 통째로 읽는 것으로 끝난다. SSTable의 블록 인덱스가 이 형태이고([XV-3 LSM Tree와 SSTable](#/xv-3)), 관계형 DB의 범위 스캔도 인덱스 리프에서 시작 경계를 이분 탐색으로 잡은 뒤 리프 링크를 따라가는 구조다([XV-2 B-Tree와 B+Tree](#/xv-2)).

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "몇 개인가", "이상 이하의 개수", "가장 가까운 값", "바로 앞의 값", "몇 번째로 작은지", "정렬을 유지하며 삽입"
- 제약조건: 정렬된 배열 또는 정렬 가능한 배열. 값의 범위가 커서 배열 카운팅이 불가능한 경우($10^9$). 질의 수 $Q$가 $10^5$ 이상이라 질의당 $O(\log n)$이 필요한 경우
- 혼동 주의: 갱신이 섞이면 → 펜윅 트리([IX-3](#/ix-3))나 세그먼트 트리([IX-2](#/ix-2)). 값의 범위가 작으면 → 누적 합 카운팅([VI-4](#/vi-4))이 더 빠르다. 찾는 것이 배열 원소가 아니라 답의 값이면 → 매개변수 탐색([VII-3](#/vii-3))
- 반례 함정: 중복 원소가 있어야 두 함수가 갈라진다. 중복 없는 입력만 시험하면 부등호를 틀린 채로 통과한다. C++에서 `set`에 자유 함수 `std::lower_bound`를 쓰면 컴파일은 되고 $O(n)$이 된다
:::

::: interview
**"`lower_bound`와 `upper_bound`의 차이를 설명해 보세요."**
값이 아니라 위치로 답한다. "`lower_bound`는 `x` 이상인 첫 위치, `upper_bound`는 `x` 초과인 첫 위치입니다. 둘 다 `x`를 넣어도 정렬이 유지되는 자리이고, 각각 가장 왼쪽과 가장 오른쪽입니다. 그래서 두 값의 차가 `x`의 개수입니다." 구현 차이를 물으면 "술어의 부등호 하나"라고 답하면 된다.

**"`std::lower_bound`를 `set`에 써도 되나요."**
이 질문은 반복자 카테고리를 아는지 보는 질문이다. "컴파일은 되지만 `set`의 이터레이터가 임의 접근이 아니라 양방향이라 중간으로 점프하지 못합니다. 비교 횟수는 여전히 $\log n$이지만 이동이 $O(n)$이라 사실상 선형입니다. 멤버 함수를 써야 합니다."
:::

## 연습

::: quiz
셋 다 "직접 짜기"가 아니라 "어느 경계를 부를지"를 고르는 훈련이다.

**1. 백준 7795 먹을 것인가 먹힐 것인가 (실버 3)** — https://www.acmicpc.net/problem/7795
- 신호: "A의 크기가 B보다 큰 쌍의 개수". 두 배열의 모든 쌍이므로 $N \times M$은 400만이고 테스트 케이스가 여러 개면 넘어간다.
- 상태: B를 정렬해 두고, A의 원소 하나마다 "그보다 작은 B의 개수".
- 자료구조: 정렬 배열 + `lower_bound`. **`lower_bound`인가 `upper_bound`인가가 이 문제의 전부다.** 크기가 같은 쌍은 세지 않으므로 "미만"이고, 미만의 개수는 `lower_bound`다.

**2. 백준 3020 개똥벌레 (골드 5)** — https://www.acmicpc.net/problem/3020
- 신호: "장애물의 최소 개수와 그러한 구간이 몇 개인지" + $N \le 200{,}000$, 높이 $H \le 500{,}000$. 높이마다 전 장애물을 세면 $O(NH)$라 1,000억이다.
- 상태: 석순 길이 배열과 종유석 길이 배열을 각각 정렬해 두고, 높이 `h`에서 부딪히는 개수를 두 번의 경계 질의로 얻는다.
- 자료구조: 정렬 배열 두 개 + 경계 탐색. 누적 합으로도 풀리고([VI-4](#/vi-4)) 그쪽이 더 빠르다. 두 풀이의 복잡도를 비교해 보는 것이 이 문제의 값어치다.

**3. 백준 2143 두 배열의 합 (골드 3)** — https://www.acmicpc.net/problem/2143
- 신호: "부 배열의 쌍의 개수" + 두 배열의 길이가 각각 1,000. 부분합이 각각 최대 50만 개이므로 모든 쌍은 2,500억이다.
- 상태: 두 배열의 모든 부분합 목록. 한쪽을 정렬해 두고 다른 쪽의 각 값 `s`에 대해 `T - s`의 개수를 센다.
- 자료구조: 정렬 배열 + `upper_bound - lower_bound`. **개수를 세는 질의라 경계 두 개가 다 필요하다.** 해시맵으로도 풀리지만 부분합이 50만 개라 상수와 메모리를 따져 봐야 한다.
:::

## 요약

- 두 함수를 **위치**로 정의한다. `lower_bound`는 `x` 이상인 첫 위치, `upper_bound`는 `x` 초과인 첫 위치다. 둘 다 "정렬을 유지한 채 넣을 자리"이고 각각 가장 왼쪽과 가장 오른쪽이다.
- 구현 차이는 **술어의 부등호 하나**뿐이다. 같은 값을 만났을 때 왼쪽에 남기면 첫 위치, 오른쪽으로 밀면 마지막 다음 위치다.
- 개수·구간 개수·순위·직전 값·직후 값이 전부 두 경계의 산술로 나온다. 새 함수를 짜고 싶어지면 경계를 잘못 고른 것이다.
- Python은 `bisect_left`/`bisect_right`, C++은 `lower_bound`/`upper_bound`. 이름만 다르고 의미는 같다. `bisect`의 기본값이 `bisect_right`라는 점이 함정이다.
- Python에서는 라이브러리가 손코딩보다 약 5.7배 빠르고, C++에서는 차이가 없다. 이유는 알고리즘이 아니라 루프가 도는 곳이다.
- C++에서 `set`·`map`에는 **멤버 함수**를 써라. 자유 함수는 컴파일되고 약 1만 배 느려진다.
- 중복 원소가 없으면 두 함수의 차이가 드러나지 않는다. 테스트 입력에 같은 값을 반드시 두 개 이상 넣어라.
