# VII-1 정렬된 배열에서의 이분 탐색

::: lead
열 줄짜리 코드가 왜 매번 하나씩 어긋나는가. 그리고 어떻게 하면 다시는 어긋나지 않는가.
:::

## 1. 문제

서버가 하루에 남기는 접속 로그가 100만 줄이고 타임스탬프 오름차순으로 쌓여 있다. 여기에 "09:31:00 이후 첫 줄은 어디인가"라는 질의가 초당 수천 번 들어온다. 앞에서부터 훑으면 질의 하나에 최대 100만 줄을 읽는다.

정렬되어 있다는 사실을 쓰면 20번 안에 끝난다. 로그가 정렬되어 있다는 것은 **중간 한 줄만 봐도 답이 어느 쪽에 있는지 알 수 있다**는 뜻이고, 매번 후보를 절반으로 버릴 수 있다는 뜻이다. $2^{20} > 10^6$이므로 20번이면 100만 줄이 한 줄로 줄어든다.

::: perf
정렬된 배열 $N = 100{,}000$에 무작위 질의를 던져 **질의 1회당** 비용을 잰 값이다.

| | 선형 탐색 | 직접 짠 이분 탐색 | 표준 라이브러리 |
|---|---|---|---|
| Python 3.13 | 4,500 μs | 3.2 μs | 0.62 μs (`bisect_left`) |
| C++17 `-O2` | 14.2 μs | 0.12 μs | 0.10 μs (`std::lower_bound`) |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측, 10회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/binsearch_vs_linear.py` 와 `.cpp` 다.)

**유효숫자를 두 자리로 끊었고 5회가 아니라 10회를 잰 이유가 있다.** 질의 1회당 비용이 마이크로초 단위라 실행마다 크게 흔들린다. 10회에서 Python 선형 탐색은 3,580\~5,560 μs, 직접 짠 이분 탐색은 2.8\~4.3 μs를 오갔고, C++ 쪽도 선형 13.9\~14.5 μs, 이분 0.119\~0.156 μs였다. ==끝자리를 더 적는 것은 측정하지 않은 정밀도를 주장하는 것이다.==

배수로 읽으면 Python에서 약 1,400배, C++에서 약 120배다. 이 배수 자체도 흔들린다 — 위 범위의 양 끝을 조합하면 Python 배수는 900배에서 2,000배 사이를 오간다. **자릿수는 흔들리지 않는다.** 배수가 두 언어에서 다른 이유는 이분 탐색이 언어를 타서가 아니라 **선형 탐색 쪽이 언어를 심하게 타기 때문**이다. 100만 번의 인터프리터 루프와 100만 번의 기계어 비교는 비용이 다르다([0-10 언어별 상수와 TLE 대응](#/0-10)).
:::

문제는 아이디어가 아니다. 절반씩 버린다는 발상은 한 문장이면 끝난다. 그런데 직접 짜면 셋 중 하나가 일어난다. 답이 하나 어긋나거나, 배열 범위를 벗어나거나, 프로그램이 끝나지 않는다.

원인은 **관례를 섞어 쓰는 것**이다. 탐색 구간을 닫힌 구간 `[lo, hi]`로 잡은 코드와 반열림 구간 `[lo, hi)`로 잡은 코드는 네 군데가 다르다.

- 초기값이 `hi = n`인가 `hi = n - 1`인가
- 루프 조건이 `lo < hi`인가 `lo <= hi`인가
- 갱신이 `hi = mid`인가 `hi = mid - 1`인가
- 끝나고 돌려주는 것이 `lo`인가 `hi`인가 별도의 `ans`인가

네 자리가 각각 두 갈래면 조합이 16가지다. 문제마다 다른 조합을 골라 쓰면 어느 하나는 반드시 틀린다. ==그러므로 이 챕터의 결론은 기억할 규칙을 늘리는 것이 아니라 줄이는 것이다. 관례를 **하나**로 고정한다.==

이 책은 예외 없이 **반열림 구간 `[lo, hi)`** 만 쓴다. 이유는 취향이 아니다. 구간의 폭이 정확히 `hi - lo`이고, 빈 구간이 `lo == hi` 하나로 표현되며, 구간을 둘로 쪼갤 때 경계가 겹치지도 벌어지지도 않는다. Python의 슬라이스와 `range`, C++의 반복자 쌍이 전부 이 규약을 따르는 것도 같은 이유다.

## 2. 아이디어

### 2.1 값을 찾지 말고 경계를 찾아라

"x를 찾는다"로 생각하면 x가 없는 입력에서 코드가 무너진다. 대신 **술어의 경계**를 찾는 것으로 문제를 바꾼다.

배열 `a`가 오름차순이면 술어 `p(i) = (a[i] >= x)`는 앞에서 거짓, 뒤에서 참이고, 한 번만 뒤집힌다. 뒤집히는 위치 하나가 곧 답이다.

```text nolines
  index   0    1    2    3    4    5    6
  a[i]   10   20   20   30   40   50   60
  p(i)    F    F    F    F    T    T    T       <- p(i) = (a[i] >= 35)
                            ^
                            +-- 찾을 것은 이 경계 하나뿐이다
```

이 관점의 값어치는 **x가 배열에 없어도 답이 정의된다**는 데 있다. 위 그림에서 35는 배열에 없지만 경계는 4로 멀쩡히 존재한다. 4는 "35 이상인 첫 원소의 위치"이자 "35를 끼워 넣어도 정렬이 유지되는 가장 왼쪽 자리"다. 존재 여부는 그다음에 파생된다 — `a[4]`가 35인지 한 번 보면 된다.

위젯은 배열 위에 살아 있는 구간 `[lo, hi)`를 색으로 칠하고, 버려진 절반을 회색으로 지운다. 각 스텝마다 `lo`·`hi`·폭·`mid`·`a[mid]`·술어 값이 표에 한 줄씩 쌓이고, 표 위에는 불변식 문장이 그대로 박혀 있다. 위쪽 탭으로 세 변형을 갈아 끼울 수 있다 — 반열림, 닫힘, 그리고 갱신을 `lo = mid`로 바꾼 무한 루프판이다. 세 번째를 고르면 폭이 1에서 멈추고 같은 줄이 계속 쌓이며, 폭 열이 빨갛게 굳는다. **위젯의 중심은 배열 그림이 아니라 폭 열이다.**

### 2.2 불변식 하나, 측도 하나

반열림으로 짠 이분 탐색은 문장 두 개로 전부 설명된다.

- **불변식(정확성 담당):** ==답은 항상 구간 `[lo, hi)` 안에 있다.== 루프 머리에 도달할 때마다 참이다.
- **측도(종료 담당):** ==폭 `hi - lo`는 매 반복 엄격히 줄어든다.== 0 밑으로 내려갈 수 없으므로 루프는 반드시 끝난다.

불변식이 갱신 규칙을 결정한다. `mid`를 검사해서 `p(mid)`가 참이면 `mid`는 답의 후보이므로 남겨야 한다. 오른쪽 끝은 열려 있으니 `hi = mid`로 두면 `mid`가 구간 안에 남는다. 거짓이면 `mid`는 답이 될 수 없고 그 왼쪽도 전부 거짓이므로 `lo = mid + 1`로 버린다. **후보를 남길 때는 `mid`, 버릴 때는 `mid + 1`.** 이 비대칭이 전부다.

측도가 줄어드는 것은 계산으로 확인된다. `mid = lo + (hi - lo) // 2`는 `lo <= mid < hi`를 보장한다(폭이 1 이상일 때 `(hi-lo)//2 < hi-lo`이므로). 그러면

- `hi = mid`일 때 새 폭은 `mid - lo`이고 `mid < hi`이므로 줄어든다.
- `lo = mid + 1`일 때 새 폭은 `hi - mid - 1`이고 `mid >= lo`이므로 줄어든다.

두 갈래 다 줄어든다. 만약 `lo = mid`로 쓰면 폭이 1일 때 `mid == lo`가 되어 아무것도 바뀌지 않고, 그 순간 무한 루프다. 이 현상은 [0-11 손추적 방법론](#/0-11)이 표 다섯 줄로 잡아낸 그 버그다.

### 2.3 끝났을 때 무엇을 돌려주는가

루프가 끝나면 `lo == hi`다. 불변식은 여전히 참이므로 "답은 폭 0인 구간 `[lo, lo)` 안에 있다"가 되고, 폭 0 구간이 가리키는 위치는 `lo` 하나뿐이다. **그래서 `lo`를 돌려준다.** `hi`를 돌려줘도 값은 같지만, 의미로 답을 고르는 습관이 남아야 한다.

`lo`가 가질 수 있는 값의 범위는 `0`부터 `n`까지다. `n`은 "모든 원소가 x보다 작다"는 뜻이고, 이때 `a[lo]`를 읽으면 범위를 벗어난다. ==반환값을 인덱스로 쓰기 전에 `lo < n`을 검사하는 것은 선택이 아니다.==

### 2.4 `mid`를 왜 저렇게 쓰는가

`mid = (lo + hi) // 2`가 더 짧은데도 `mid = lo + (hi - lo) // 2`를 쓴다. Python에서는 두 표기가 완전히 같다. 정수가 임의 정밀도라 합이 아무리 커져도 넘치지 않는다. C++에서는 다르다. `lo`와 `hi`가 각각 20억 근처면 합이 `int` 범위를 넘어 음수가 되고, 음수 인덱스로 배열을 읽는다. 정의되지 않은 동작이라 크래시할 수도, 조용히 쓰레기를 읽을 수도 있다([0-5 C++ 입출력과 기본 타입](#/0-5)).

뺄셈을 먼저 하면 중간값이 원래 두 값보다 커지지 않으므로 안전하다. **Python에서도 같은 표기를 쓰는 이유는 언어를 오갈 때 무너지는 것이 지식이 아니라 습관이기 때문이다.**

나눗셈이 내림이라는 점도 우연이 아니다. 내림이라야 `mid < hi`가 보장되고, 그래야 `hi = mid`가 폭을 줄인다. 올림으로 바꾸면 이 이분 탐색은 그 자리에서 무한 루프가 된다.

## 3. 손으로 따라가기

::: trace
입력: `a = [10, 20, 20, 30, 40, 50, 60]` (n = 7), `x = 35`. 구할 것은 `a[i] >= 35`인 가장 왼쪽 `i`.

불변식: 답은 항상 `[lo, hi)` 안에 있다. 시작은 `lo = 0`, `hi = 7`.
갱신: `mid = lo + (hi - lo) // 2`. `a[mid] >= 35`이면 `hi = mid`, 아니면 `lo = mid + 1`.

| 스텝 | lo | hi | 폭 | mid | a[mid] | a[mid] >= 35 | 갱신 |
|---|---|---|---|---|---|---|---|
| 0 | 0 | 7 | 7 | 3 | 30 | 아니오 | lo = 4 |
| 1 | 4 | 7 | 3 | 5 | 50 | 예 | hi = 5 |
| 2 |  |  |  |  |  |  |  |
| 3 |  |  |  |  |  |  |  |

끝까지 채운 뒤 세 가지에 답하라.

- [ ] 폭 열이 매 스텝 **실제로** 줄어드는가
- [ ] 루프가 멈추는 순간의 `lo`는 얼마이고, `a[lo]`는 35인가
- [ ] 35가 배열에 없는데도 답이 존재하는 이유는 무엇인가

::: answer
| 스텝 | lo | hi | 폭 | mid | a[mid] | a[mid] >= 35 | 갱신 |
|---|---|---|---|---|---|---|---|
| 0 | 0 | 7 | 7 | 3 | 30 | 아니오 | lo = 4 |
| 1 | 4 | 7 | 3 | 5 | 50 | 예 | hi = 5 |
| 2 | 4 | 5 | 1 | 4 | 40 | 예 | hi = 4 |
| 3 | 4 | 4 | 0 | — | — | — | `lo < hi`가 거짓, 종료 |

답은 `lo = 4`다.

폭이 `7 → 3 → 1 → 0`으로 매 스텝 엄격히 줄었다. 이것이 이 루프가 끝난다는 증거이고, 표에서 이 열만 눈으로 따라가면 무한 루프는 종이 위에서 잡힌다.

`a[4] = 40`이라 35와 같지 않다. 즉 **35는 배열에 없다.** 그래도 답 4는 의미가 있다. 35를 4번 자리에 끼워 넣으면 `[10, 20, 20, 30, 35, 40, 50, 60]`으로 정렬이 유지된다. 반환값은 "찾은 위치"가 아니라 **"경계 위치"** 이고, 존재 여부는 `a[4] == 35`를 한 번 더 확인해야 나온다. 이 둘을 같은 것으로 착각하는 순간 없는 값을 찾았다고 답하는 버그가 나온다.

한 번 더 확인할 것이 있다. 스텝 2에서 `hi = mid`가 아니라 `hi = mid - 1`이었다면 `hi = 3`이 되어 `lo = 4 > hi = 3`이고, 반열림 규약에서 이 구간은 폭이 음수인 유령 구간이다. **닫힌 구간의 갱신 규칙을 반열림 코드에 섞으면 정확히 이렇게 무너진다.**
:::

## 4. 구현

::: dual
```python title="반열림 이분 탐색 — 불변식 하나로 고정한다"
def lower_bound(a, x):
    """a[i] >= x 를 만족하는 가장 왼쪽 i. 없으면 len(a)."""
    lo, hi = 0, len(a)              # 불변식: 답은 항상 [lo, hi) 안에 있다
    while lo < hi:                  # 측도: hi - lo 가 매 반복 반드시 줄어든다
        mid = lo + (hi - lo) // 2   # lo <= mid < hi 가 보장된다
        if a[mid] >= x:
            hi = mid                # mid 는 조건을 만족한다. 후보로 남긴다
        else:
            lo = mid + 1            # mid 는 조건을 만족하지 못한다. 버린다
    return lo                       # lo == hi. 폭 0 구간의 위치가 답이다


def contains(a, x):
    """존재 여부는 경계 위치에서 파생된다. 따로 짜지 않는다."""
    i = lower_bound(a, x)
    return i < len(a) and a[i] == x


a = [10, 20, 20, 30, 40, 50, 60]
for x in (35, 10, 60, 20, 5, 100):
    i = lower_bound(a, x)
    print(f"x={x:3d}  lower_bound={i}  contains={int(contains(a, x))}")
```
```cpp title="반열림 이분 탐색 — 불변식 하나로 고정한다"
#include <iomanip>
#include <iostream>
#include <vector>
using namespace std;

// a[i] >= x 를 만족하는 가장 왼쪽 i. 없으면 a.size().
int lower_bound(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size();   // 불변식: 답은 항상 [lo, hi) 안에 있다
    while (lo < hi) {                 // 측도: hi - lo 가 매 반복 반드시 줄어든다
        int mid = lo + (hi - lo) / 2; // lo <= mid < hi 가 보장된다
        if (a[mid] >= x)
            hi = mid;                 // mid 는 조건을 만족한다. 후보로 남긴다
        else
            lo = mid + 1;             // mid 는 조건을 만족하지 못한다. 버린다
    }
    return lo;                        // lo == hi. 폭 0 구간의 위치가 답이다
}

// 존재 여부는 경계 위치에서 파생된다. 따로 짜지 않는다.
bool contains(const vector<int>& a, int x) {
    int i = lower_bound(a, x);
    return i < (int)a.size() && a[i] == x;
}

int main() {
    vector<int> a = {10, 20, 20, 30, 40, 50, 60};
    for (int x : {35, 10, 60, 20, 5, 100}) {
        int i = lower_bound(a, x);
        cout << "x=" << setw(3) << x << "  lower_bound=" << i
             << "  contains=" << (int)contains(a, x) << "\n";
    }
    return 0;
}
```

```console
x=100  lower_bound=7  contains=0
```

**복잡도:** 시간 $O(\log n)$ — 매 반복 폭이 절반 이하로 줄고 폭 0에서 끝나므로, 반복 횟수는 $n$을 1까지 반으로 접는 횟수 $\lceil \log_2 n \rceil$을 넘지 않는다. $n = 10^6$이면 20회다. 공간 $O(1)$ — 재귀 없이 정수 변수 세 개만 쓴다.

상수도 말해 둔다. 같은 20회라도 **매 스텝이 배열의 전혀 다른 곳을 찌른다.** 위치가 절반씩 뛰므로 캐시 라인이 재사용되지 않고 초반 스텝은 사실상 매번 캐시 미스다. 배열이 작아 통째로 캐시에 들어가는 경우와 수백 MB인 경우의 실제 비용은 상수가 크게 다르다([0-6 C++ 컨테이너 세트](#/0-6)).

| 언어 차이 | Python | C++ |
|---|---|---|
| `(lo + hi)` 오버플로 | 임의 정밀도라 발생하지 않는다 | `int` 범위를 넘으면 UB. `lo + (hi - lo) / 2`를 쓰는 이유 |
| 정수 나눗셈 | `//`는 항상 내림 | `/`는 0 방향 절삭. 양수 구간에서는 결과가 같다 |
| 배열 길이 타입 | `len(a)`는 `int` | `a.size()`는 부호 없는 `size_t`. `int`와 섞으면 비교가 뒤집힌다 |
| 표준 대응 | `bisect.bisect_left(a, x)` | `std::lower_bound(a.begin(), a.end(), x)` |
| 이름 충돌 | 없음 | `using namespace std`에서 같은 이름을 정의해도 인자 개수가 달라 구분된다 |

닫힌 구간으로 짜도 답은 같다. 다만 **다른 곳이 네 군데**이고, 그 넷을 매번 다시 맞춰야 한다. 아래 블록은 앞 블록의 `lower_bound`를 그대로 이어받아, 닫힌 구간판과 선형 탐색판을 함께 세워 두고 셋의 답을 대조한다.

::: dual
```python title="닫힌 구간판과 선형 탐색 심판 (조각)"
def lower_bound_closed(a, x):
    """같은 함수를 닫힌 구간 [lo, hi] 로. 다른 곳이 네 군데다."""
    lo, hi = 0, len(a) - 1          # ① 초기 hi 가 n 이 아니라 n-1
    ans = len(a)                    # ② 답 후보를 따로 들고 다녀야 한다
    while lo <= hi:                 # ③ 조건이 <= 다
        mid = lo + (hi - lo) // 2
        if a[mid] >= x:
            ans = mid
            hi = mid - 1            # ④ mid 를 버려야 폭이 줄어든다
        else:
            lo = mid + 1
    return ans


def lower_bound_linear(a, x):
    """심판. 느리지만 틀릴 수 없다."""
    for i, v in enumerate(a):
        if v >= x:
            return i
    return len(a)


cases = [[], [7], [2, 2, 2], [1, 3, 5, 7], [10, 20, 20, 30, 40, 50, 60]]
bad = tried = 0
for arr in cases:
    for x in range(-1, 13):
        want = lower_bound_linear(arr, x)
        tried += 1
        if lower_bound(arr, x) != want or lower_bound_closed(arr, x) != want:
            bad += 1
print(f"cases = {tried}  mismatch = {bad}")
```
```cpp title="닫힌 구간판과 선형 탐색 심판 (조각)"
// 같은 함수를 닫힌 구간 [lo, hi] 로. 다른 곳이 네 군데다.
int lower_bound_closed(const vector<int>& a, int x) {
    int lo = 0, hi = (int)a.size() - 1;   // ① 초기 hi 가 n 이 아니라 n-1
    int ans = (int)a.size();              // ② 답 후보를 따로 들고 다녀야 한다
    while (lo <= hi) {                    // ③ 조건이 <= 다
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= x) {
            ans = mid;
            hi = mid - 1;                 // ④ mid 를 버려야 폭이 줄어든다
        } else {
            lo = mid + 1;
        }
    }
    return ans;
}

// 심판. 느리지만 틀릴 수 없다.
int lower_bound_linear(const vector<int>& a, int x) {
    for (int i = 0; i < (int)a.size(); i++)
        if (a[i] >= x) return i;
    return (int)a.size();
}

int main() {
    vector<vector<int>> cases = {{}, {7}, {2, 2, 2}, {1, 3, 5, 7},
                                 {10, 20, 20, 30, 40, 50, 60}};
    int bad = 0, tried = 0;
    for (const auto& arr : cases)
        for (int x = -1; x <= 12; x++) {
            int want = lower_bound_linear(arr, x);
            tried++;
            if (lower_bound(arr, x) != want || lower_bound_closed(arr, x) != want) bad++;
        }
    cout << "cases = " << tried << "  mismatch = " << bad << "\n";
    return 0;
}
```
:::

출력은 양쪽 다 `cases = 70  mismatch = 0`이다. 케이스 목록에 **빈 배열, 원소 하나, 전부 같은 값**을 일부러 넣었다. 이 셋에서만 깨지는 구현이 대부분이고, 중간 크기의 평범한 배열만 돌려 보면 전부 통과한다.

**복잡도:** 닫힌 구간판도 시간 $O(\log n)$·공간 $O(1)$로 반열림판과 같다 — 폭이 매 반복 절반 이하로 준다는 사실이 같기 때문이다. 대조 코드 자체는 케이스 수 $C$, 질의 수 $Q$에 대해 $O(C \cdot Q \cdot n)$인데, 심판이 선형이라 그렇다. 심판은 느려도 된다.

::: pitfall
실제로 틀리는 자리는 넷뿐이다. 넷 다 앞 절의 불변식 한 문장으로 판정된다.

- **`<` 와 `<=` 를 섞는다.** 반열림에 `while lo <= hi`를 쓰면 `lo == hi == n`일 때 `a[n]`을 읽는다. 반열림이면 `<`, 닫힘이면 `<=`. 초기값과 세트다.
- **`mid` 와 `mid + 1` 을 뒤집는다.** 조건을 만족한 `mid`를 `lo = mid + 1`로 버리면 답을 건너뛰고, 만족하지 못한 `mid`를 `lo = mid`로 남기면 폭이 줄지 않아 무한 루프다. **검사한 `mid`는 반드시 어느 한쪽에서 사라져야 한다.**
- **`lo` 대신 `hi` 를 돌려준다.** 반열림에서는 끝나면 둘이 같아 우연히 맞지만, 닫힌 구간판을 섞어 쓰면 `hi = lo - 1`이 되어 하나 어긋난다.
- **"찾았다"와 "여기 넣으면 된다"를 혼동한다.** `lower_bound`는 경계 위치를 돌려줄 뿐 존재 여부를 말하지 않는다. `lo < n and a[lo] == x`를 확인하지 않으면 없는 값을 찾았다고 답한다. `lo == n`인 채로 `a[lo]`를 읽으면 그대로 터진다.
:::

## 5. 어디에 쓰이는가

**디스크에서 블록 하나를 읽어 온 다음이 전부 이분 탐색이다.** B+Tree의 노드 하나는 수백 개의 키를 정렬된 채로 담고 있고, 노드를 메모리로 올린 뒤 그 안에서 자식 포인터를 고르는 일이 바로 `lower_bound`다. 디스크 읽기 횟수를 줄이는 것이 트리의 몫이고, 읽어 온 블록 안에서 위치를 찾는 것이 이분 탐색의 몫이다([XV-2 B-Tree와 B+Tree](#/xv-2)). LSM Tree의 SSTable도 같다. 블록 인덱스에서 이분 탐색으로 후보 블록을 고른 뒤 그 블록 안에서 다시 이분 탐색한다([XV-3 LSM Tree와 SSTable](#/xv-3)).

**`git bisect`는 이 알고리즘 그 자체다.** 커밋 이력을 시간순으로 늘어놓으면 "이 커밋에 버그가 있는가"라는 술어가 거짓…거짓 참…참으로 한 번만 뒤집힌다 — 정확히 §2.1의 그림이다. 커밋 1,024개 중 처음 버그가 들어간 지점을 찾을 때 빌드·테스트를 10번만 돌리면 된다. 여기서 술어는 배열 조회가 아니라 **빌드 한 번**이라 한 번의 판정이 몇 분씩 걸리고, 그래서 판정 횟수를 로그로 줄이는 것이 곧 반나절과 10분의 차이가 된다.

**시계열 데이터의 구간 조회도 경계 두 개다.** 타임스탬프 오름차순으로 쌓인 로그에서 "09:31부터 09:35까지"를 뽑는 일은 시작 경계와 끝 경계를 각각 이분 탐색으로 찾아 그 사이를 통째로 읽는 것으로 끝난다. 경계를 두 개 쓰는 방법이 [VII-2 lower_bound / upper_bound / bisect](#/vii-2)의 주제다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "정렬되어 있다", "오름차순으로 주어진다", "이상인 첫", "이하인 마지막", "존재하는지", "몇 번째 위치에 들어가는가"
- 제약조건: 정렬된 배열이 이미 있거나 정렬해도 되는 입력. $N \le 10^6$이고 질의 수 $Q$가 커서 $O(NQ)$가 $10^8$을 넘는 경우. 값이 갱신되지 않고 조회만 하는 경우
- 혼동 주의: 배열이 정렬되지 않았고 정렬도 못 하면 → 해시([II-6](#/ii-6)). 조회 중간에 삽입·삭제가 섞이면 → 균형 트리([II-9](#/ii-9)). 찾는 것이 배열 원소가 아니라 답의 값이면 → 매개변수 탐색([VII-3](#/vii-3))
- 반례 함정: 중복 원소가 있으면 "찾았다"만으로는 부족하다. 첫 위치인지 마지막 다음 위치인지를 지문이 요구한다([VII-2](#/vii-2)). 그리고 답이 배열에 없을 때 반환값을 그대로 인덱스로 쓰면 `a[n]`을 읽는다
:::

::: interview
경계가 있는 루프를 화이트보드에 짜게 한 뒤 따라오는 질문은 대개 둘이다.

**"이 루프가 무한 루프에 빠지지 않는 이유를 설명해 보세요."**
측도로 답한다. "폭 `hi - lo`가 매 반복 최소 1 줄고 음수가 될 수 없습니다. 그래서 최대 초기 폭만큼만 돌고 끝납니다." 여기에 `mid < hi`가 왜 보장되는지(내림 나눗셈) 한 줄을 덧붙이면 답이 닫힌다.

**"이 함수가 옳은 값을 돌려준다는 것을 어떻게 압니까."**
불변식으로 답한다. "답은 항상 `[lo, hi)` 안에 있고, 루프가 끝나면 `lo == hi`이므로 답은 `lo`입니다." 코드를 다시 읽지 않고 나오는 답이어야 한다.

여기서 한 번 더 들어오는 질문이 `mid = (lo + hi) / 2`의 오버플로다. Java 표준 라이브러리의 이분 탐색에서 실제로 발견된 버그라는 사실까지 말할 수 있으면 충분하다.
:::

## 연습

::: quiz
전부 경계 조건이 본체인 유형이다. **코드를 짜기 전에 손추적 표부터 그려라.**

**1. 백준 2776 암기왕 (실버 4)** — https://www.acmicpc.net/problem/2776
- 신호: "적어 놓은 수인지 아닌지" + N과 M이 각각 100만, 테스트 케이스 여러 개. 질의마다 선형 스캔이면 $10^{12}$이라 넘는다.
- 상태: 정렬된 수첩 배열 하나와 탐색 구간 `[lo, hi)`.
- 자료구조: 정렬 배열 + `lower_bound`. 해시 집합으로도 풀리고 실제로 더 빠르지만, 이 문제의 훈련 가치는 존재 판정을 **경계 위치에서 파생**시키는 데 있다.

**2. 백준 2467 용액 (골드 5)** — https://www.acmicpc.net/problem/2467
- 신호: "특성값이 0에 가장 가까운" + 이미 오름차순으로 주어진다는 조건. 두 수의 합이므로 $O(N^2)$는 100억이라 불가능하다.
- 상태: 각 원소 `a[i]`에 대해 `-a[i]`가 들어갈 경계 위치. 그 위치와 그 앞 위치, 둘만 후보다.
- 자료구조: 정렬 배열 + `lower_bound`. **경계의 양옆을 둘 다 봐야 한다는 것**이 이 문제의 함정이다. 투 포인터로도 같은 답이 나온다([VI-3](#/vi-3)).

**3. 손추적 과제 — 빈 배열과 한 원소.** `a = []`와 `a = [5]`에 대해 `x = 5`로 위 `lower_bound`의 표를 채워라. 각각 몇 스텝 도는가. 반환값을 그대로 `a[i]`에 넣으면 어느 쪽이 터지는가.

**4. 손추적 과제 — 관례 섞기.** `a = [10, 20, 20, 30, 40, 50, 60]`, `x = 20`으로 표를 채우되 `hi = mid`를 `hi = mid - 1`로만 바꿔라. 어느 스텝에서 답을 건너뛰는가. 그 스텝에서 불변식의 어느 부분이 깨졌는지 한 문장으로 적어라.

::: answer
3번. 빈 배열은 `lo = hi = 0`이라 루프를 **한 번도 돌지 않고** 0을 돌려준다. `a[0]`을 읽으면 그 자리에서 터진다. 원소 하나짜리는 한 스텝만 돈다 — `mid = 0`, `a[0] = 5 >= 5`이므로 `hi = 0`, 종료. 답 0이고 `a[0] == 5`이므로 존재한다. **빈 배열에서 루프가 0회 도는 것이 반열림의 성질이다.** 닫힌 구간판은 `hi = -1`로 시작해 같은 결과를 내지만, 그 `-1`을 만들어 내기 위해 초기값을 한 번 더 생각해야 한다.

4번. 스텝 0에서 `mid = 3`, `a[3] = 30 >= 20`이므로 참이고 `hi = 2`가 된다. 이 순간 답인 위치 1은 여전히 구간 안에 있으므로 아직 괜찮다. 문제는 참인 `mid`를 버렸다는 데 있다. `mid` 자신이 답인 경우 — 예를 들어 `x = 30`으로 같은 실험을 하면 스텝 0에서 `hi = 2`가 되어 **답 3이 구간 밖으로 나간다.** 깨진 것은 "답은 항상 `[lo, hi)` 안에 있다"의 앞부분이다. 조건을 만족한 `mid`는 답 후보이므로 구간에 남겨야 하고, 그래서 반열림의 갱신은 `hi = mid`다.
:::

## 요약

- 이분 탐색이 어려운 것은 발상이 아니라 **경계 관례를 섞어 쓰기 때문**이다. 초기값·루프 조건·갱신·반환 네 자리가 한 세트로 움직인다.
- 이 책은 **반열림 `[lo, hi)`** 하나만 쓴다. 폭이 `hi - lo`이고 빈 구간이 `lo == hi` 하나로 표현되는 것이 오프바이원에 대한 가장 값싼 방어다.
- 불변식은 "답은 항상 `[lo, hi)` 안에 있다"이고, 측도는 "`hi - lo`가 매 반복 엄격히 줄어든다"다. **불변식이 정확성을, 측도가 종료를 맡는다.**
- 갱신은 비대칭이다. 조건을 만족한 `mid`는 `hi = mid`로 남기고, 만족하지 못한 `mid`는 `lo = mid + 1`로 버린다.
- `mid = lo + (hi - lo) // 2`. C++에서 `(lo + hi) / 2`는 오버플로하고, 내림 나눗셈이라야 `mid < hi`가 보장된다.
- 반환값은 **경계 위치**이지 "찾은 위치"가 아니다. 존재 여부는 `lo < n and a[lo] == x`로 따로 확인한다.
- 검증은 빈 배열·원소 하나·전부 같은 값·답이 양 끝, 이 네 입력에서 선형 탐색과 대조하면 끝난다.
