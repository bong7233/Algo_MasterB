# VII-4 실수 이분 탐색과 종료 조건

::: lead
`lo == hi`가 영원히 오지 않는 루프를 무엇으로 멈추는가.
:::

## 1. 문제

두 건물 사이에 사다리 두 개가 X자로 걸쳐 있다. 하나는 길이 $x$, 다른 하나는 길이 $y$, 둘이 교차하는 높이가 $c$다. 건물 사이의 거리 $w$를 구하라. $w$를 정하면 $c$는 계산으로 나오고, $w$가 커지면 $c$는 작아진다 — 단조다. 그러니 [VII-3](#/vii-3)의 매개변수 탐색이 그대로 적용된다.

문제는 답이 정수가 아니라는 것이다. 답은 `7.2937...` 같은 실수이고, 채점기는 소수점 아래 셋째 자리까지 맞기를 요구한다. 여기서 [VII-1](#/vii-1)에서 고정한 관례가 **두 군데 다 무너진다.**

- `lo = mid + 1`을 쓸 수 없다. 실수에는 "다음 값"이 없다.
- `while lo < hi`로 끝나지 않는다. 두 실수가 정확히 같아지는 일은 좀처럼 오지 않는다.

그래서 거의 모든 자료가 이렇게 쓴다.

```text nolines
  while (hi - lo > 1e-9) { ... }
```

이 줄이 이 챕터의 표적이다. ==이 조건은 입력에 따라 끝나지 않는다.== 다음은 구간 $[0, 10^{18}]$에서 실제로 돌려 본 결과다.

```console
while (hi-lo > 1e-9): 54회에서 폭이 1.280e+02 로 멈췄다. 조건 만족? False
```

폭이 128에서 더 이상 줄지 않는다. 조건은 `128 > 1e-9`이므로 영원히 참이다. 무한 루프이고, 채점기에서는 시간 초과로 나타난다. 코드에는 아무 잘못이 없어 보이는데도 그렇다.

## 2. 아이디어

### 2.1 실수판은 정수판에서 세 줄이 바뀐다

먼저 무엇이 바뀌는지 정확히 못 박는다.

| | 정수판 ([VII-1](#/vii-1)) | 실수판 |
|---|---|---|
| 구간 | 반열림 `[lo, hi)` | 닫힘 `[lo, hi]`. 폭이 0이 되지 않으므로 반열림의 이점이 없다 |
| 참일 때 | `hi = mid` | `hi = mid` (같다) |
| 거짓일 때 | `lo = mid + 1` | `lo = mid`. **`+1`이 없다** |
| 종료 | `lo == hi` | 폭 조건 또는 **반복 횟수** |
| 반환 | `lo` | `lo` 또는 `(lo + hi) / 2` |

정수판에서 `lo = mid`는 폭 1에서 영원히 멈추는 **버그**였다. 실수판에서는 그것이 정상이다. 실수에서는 `mid`가 항상 `lo`와 `hi`의 정중앙이라 폭이 정확히 절반씩 줄기 때문이다 — **어느 지점까지는**.

### 2.2 폭은 0으로 가지 않는다

`double`은 유효숫자를 53비트만 들고 있다. 그래서 표현할 수 있는 값들의 간격이 **값의 크기에 비례해 벌어진다.** 이 간격을 ULP(unit in the last place)라 부른다.

| 값 근처 | double의 간격(ULP) | `EPS = 1e-9`를 만족할 수 있는가 |
|---|---|---|
| 1 | $2.220 \times 10^{-16}$ | 가능 |
| $10^6$ | $1.164 \times 10^{-10}$ | 가능 |
| $1.4 \times 10^9$ | $2.384 \times 10^{-7}$ | **불가능** |
| $10^{15}$ | $0.125$ | **불가능** |
| $10^{18}$ | $128$ | **불가능** |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. 측정 스크립트는 `tools/bench/vii4_real_bisect_error.py` 와 `.cpp` 다. 두 언어가 같은 IEEE 754 `double`을 쓰므로 값이 마지막 자리까지 같다.)

$1.4 \times 10^9$ 근처에서 두 `double` 사이의 최소 간격이 이미 $2.4 \times 10^{-7}$이다. 폭이 이 값 밑으로 내려가려면 그 사이에 표현 가능한 수가 있어야 하는데 없다. ==`lo`와 `hi`가 이웃한 두 `double`이 되는 순간 `mid`는 둘 중 하나와 같아지고, 폭은 그 자리에서 굳는다.== 그 폭이 `EPS`보다 크면 루프는 끝나지 않는다.

위젯의 중심은 배열도 구간도 아니라 **로그 축에 그려지는 폭 곡선**이다. 스텝을 누를 때마다 폭이 정확히 절반으로 떨어지므로 로그 축에서는 직선으로 내려간다. 그 직선이 어느 높이에서 수평으로 꺾이는데, 그 높이에 ULP 선이 점선으로 그어져 있다. 위쪽 슬라이더로 탐색 구간의 크기를 $2$에서 $10^{54}$까지 바꾸면 ULP 선이 통째로 위아래로 움직이고, `EPS` 슬라이더로 그은 선이 ULP 선보다 아래로 내려가는 순간 정지 배지가 붉게 켜진다 — 그 조합이 곧 무한 루프다. 옆에는 "이번 스텝에서 확정된 유효숫자 자릿수"가 함께 찍혀서, 한 번 반복이 십진 약 0.3자리를 벌어 준다는 것이 숫자로 보인다.

### 2.3 그래서 반복 횟수를 고정한다

폭이 매 반복 정확히 절반이므로 **필요한 반복 횟수는 미리 계산된다.**

$$k = \left\lceil \log_2 \frac{\text{초기 폭}}{\text{허용 오차}} \right\rceil$$

초기 폭이 $10^{18}$이고 절대오차 $10^{-9}$가 목표면 $\log_2 10^{27} \approx 89.7$이라 90회다. 실측에서도 정확히 90회에 끝났다. 그래서 **100회**라는 숫자가 관용구처럼 쓰인다 — 웬만한 구간에서 충분하고, 100회가 걸리는 비용은 어차피 무시할 만하기 때문이다.

::: warn
100회는 마법의 수가 아니다. **초기 폭이 크면 100회로 모자란다.** 구간을 $[0, 10^{54}]$로 잡고 100회를 돌린 실측에서 상대 잔차는 $1.0$이었다 — 답 근처에도 못 갔다는 뜻이다. 필요 횟수는 위 식으로 계산하고, ==구간을 필요 이상으로 크게 잡지 마라.== 초기 폭을 줄이는 것이 반복을 늘리는 것보다 언제나 싸다.
:::

### 2.4 절대오차와 상대오차

채점기가 요구하는 것이 무엇인지 먼저 읽어야 한다.

- **절대오차** $|x - x^*| \le \varepsilon$ — 답의 크기가 1 근처일 때만 쓸 수 있다.
- **상대오차** $|x - x^*| / |x^*| \le \varepsilon$ — 답이 크든 작든 같은 의미를 가진다.

§2.2의 표가 말하는 것이 이것이다. 답이 $10^{15}$ 근처인데 절대오차 $10^{-9}$를 요구하는 것은 `double`로 **표현 자체가 불가능한** 요구다. 반대로 답이 $10^{-12}$ 근처인데 절대오차 $10^{-9}$를 만족한다고 안심하면, 답이 0이어도 통과한다.

종료 조건도 같은 갈래다. `hi - lo > eps * max(1, |lo|)`로 쓰면 값이 커질수록 허용 폭도 함께 커지므로 **어떤 크기에서도 반드시 끝난다.** 정확도가 필요한 자리에서 상대 종료 조건은 고정 횟수 다음가는 안전한 선택이다. 부동소수점 비교 일반은 [X-7 부동소수점의 함정](#/x-7)에서 끝까지 다룬다.

8스텝 뒤 `lo = 1.2578125`이고 정답 `1.2599210...`과의 차는 약 $2.1 \times 10^{-3}$이다. 확정된 것은 `1.2`까지, 십진 두 자리다. **한 번의 반복이 이진 한 자리, 십진 약 0.301자리를 준다.** 소수점 아래 12자리, 즉 오차 $10^{-12}$까지 가려면 $\log_2(2 / 10^{-12}) \approx 40.9$이므로 41회다. 실측에서도 상대 종료 조건이 41회에 멈췄다.

여기서 폭이 절반씩 준다는 사실만 보고 "0으로 수렴한다"고 결론 내리면 §2.2를 놓친 것이다. 이 예에서는 `1.26` 근처의 ULP가 $2.22 \times 10^{-16}$이라 **54회에서 폭이 굳는다.** 그 뒤로는 몇 번을 더 돌려도 `lo`도 `hi`도 움직이지 않는다.

## 4. 구현

::: dual
```python title="실수 이분 탐색 — 반복 횟수를 고정한다"
def cbrt_bisect(y, iters=100):
    """y 의 세제곱근. 폭 조건이 아니라 반복 횟수를 고정한다."""
    lo, hi = 0.0, max(1.0, y)       # 불변식: 답은 항상 [lo, hi] 안에 있다
    for _ in range(iters):
        mid = lo + (hi - lo) / 2
        if mid * mid * mid >= y:
            hi = mid                # mid 는 답 이상. 오른쪽 끝을 당긴다
        else:
            lo = mid                # 실수에는 mid + 1 이 없다. mid 를 그대로 쓴다
    return lo


def stalled_loop(y, eps=1e-9, cap=1000):
    """while (hi - lo > eps) 판. 폭이 더 줄지 않는 순간을 잡아 멈춘다."""
    lo, hi = 0.0, 1e18
    prev, k = hi - lo, 0
    while hi - lo > eps:
        k += 1
        mid = lo + (hi - lo) / 2
        if mid * mid * mid >= y:
            hi = mid
        else:
            lo = mid
        if hi - lo == prev:         # 측도가 죽었다. 이 검사가 없으면 영원히 돈다
            return k, hi - lo, False
        prev = hi - lo
        if k >= cap:
            return k, hi - lo, False
    return k, hi - lo, True


for y in (2.0, 27.0, 1e-6, 1e18):
    x = cbrt_bisect(y)
    print(f"y={y:>9.1e}  x={x:.12e}  |x^3-y|/y = {abs(x * x * x - y) / y:.1e}")

k, w, done = stalled_loop(1e54)
print(f"\nwhile (hi-lo > 1e-9): {k}회에서 폭이 {w:.3e} 로 멈췄다. 조건 만족? {done}")
```
```cpp title="실수 이분 탐색 — 반복 횟수를 고정한다"
#include <algorithm>
#include <cmath>
#include <cstdio>
using namespace std;

// y 의 세제곱근. 폭 조건이 아니라 반복 횟수를 고정한다.
double cbrt_bisect(double y, int iters = 100) {
    double lo = 0.0, hi = max(1.0, y);   // 불변식: 답은 항상 [lo, hi] 안에 있다
    for (int i = 0; i < iters; i++) {
        double mid = lo + (hi - lo) / 2;
        if (mid * mid * mid >= y)
            hi = mid;                    // mid 는 답 이상. 오른쪽 끝을 당긴다
        else
            lo = mid;                    // 실수에는 mid + 1 이 없다. mid 를 그대로 쓴다
    }
    return lo;
}

// while (hi - lo > eps) 판. 폭이 더 줄지 않는 순간을 잡아 멈춘다.
int stalled_loop(double y, double eps, double& width, bool& done, int cap = 1000) {
    double lo = 0.0, hi = 1e18, prev = hi - lo;
    int k = 0;
    while (hi - lo > eps) {
        k++;
        double mid = lo + (hi - lo) / 2;
        if (mid * mid * mid >= y) hi = mid;
        else lo = mid;
        if (hi - lo == prev) { width = hi - lo; done = false; return k; }
        prev = hi - lo;
        if (k >= cap) { width = hi - lo; done = false; return k; }
    }
    width = hi - lo;
    done = true;
    return k;
}

int main() {
    double ys[] = {2.0, 27.0, 1e-6, 1e18};
    for (double y : ys) {
        double x = cbrt_bisect(y);
        printf("y=%9.1e  x=%.12e  |x^3-y|/y = %.1e\n", y, x, fabs(x * x * x - y) / y);
    }
    double w;
    bool done;
    int k = stalled_loop(1e54, 1e-9, w, done);
    printf("\nwhile (hi-lo > 1e-9): %d회에서 폭이 %.3e 로 멈췄다. 조건 만족? %s\n",
           k, w, done ? "True" : "False");
    return 0;
}
```

**복잡도:** 시간 $O(k \times C)$ — $k$는 고정 반복 횟수, $C$는 판정 한 번의 비용이다. $k$가 상수라서 $O(C)$처럼 보이지만 그 상수가 100이라는 사실을 숨기면 안 된다. 판정이 $O(N)$이면 총 $100N$이고, $N = 10^5$이면 $10^7$이다([0-9](#/0-9)). 매개변수 탐색에서 $\log R$이던 자리에 여기서는 $\lceil \log_2(\text{초기폭}/\varepsilon) \rceil$이 들어간 것뿐이다. 공간 $O(1)$ — 실수 변수 세 개.

::: deep
위 코드의 잔차 $|x^3 - y| / y$가 전부 $10^{-16}$ 언저리인 것은 우연이 아니라 `double`의 한계값이다. 유효숫자 53비트는 십진 약 15.95자리이므로 상대오차를 그보다 줄일 방법이 없다.

같은 이유로 **"정확한 답"이라는 것도 라이브러리마다 1 ULP 다르다.** `tools/bench/vii4_real_bisect_error.py`와 `.cpp`를 나란히 돌리면 `cbrt(2)`가 Python에서 `1.2599210498948734`, C++에서 `1.2599210498948732`로 나온다. 정확한 값은 `1.25992104989487316...`이라 C++ 쪽이 올바르게 반올림된 값이고 Python 쪽이 1 ULP 크다. ==그래서 실수 답을 비교할 때는 `==`가 아니라 허용 오차를 쓴다.== 심판으로 쓸 라이브러리 함수조차 마지막 자리는 믿을 수 없다.
:::

```python title="종료 조건 세 가지를 나란히 재 본다"
CAP = 300  # 안 끝나는 루프를 실험하기 위한 안전장치. 실전 코드에 이런 것은 없다


def cube_ge(mid, y):
    return mid * mid * mid >= y


def by_absolute(y, eps=1e-9):
    """while (hi - lo > eps). eps 가 그 자리의 double 간격보다 작으면 끝나지 않는다."""
    lo, hi, k = 0.0, max(1.0, y), 0
    while hi - lo > eps and k < CAP:
        k += 1
        mid = lo + (hi - lo) / 2
        if cube_ge(mid, y):
            hi = mid
        else:
            lo = mid
    return lo, k


def by_relative(y, eps=1e-12):
    """폭을 값의 크기로 나눠 본다. 큰 값에서도 반드시 끝난다."""
    lo, hi, k = 0.0, max(1.0, y), 0
    while hi - lo > eps * max(1.0, abs(lo)) and k < CAP:
        k += 1
        mid = lo + (hi - lo) / 2
        if cube_ge(mid, y):
            hi = mid
        else:
            lo = mid
    return lo, k


def by_fixed(y, iters=100):
    """폭을 아예 보지 않는다. 100번이면 초기 폭이 2^100 배로 줄어든다."""
    lo, hi = 0.0, max(1.0, y)
    for _ in range(iters):
        mid = lo + (hi - lo) / 2
        if cube_ge(mid, y):
            hi = mid
        else:
            lo = mid
    return lo, iters
```

```cpp title="종료 조건 세 가지를 나란히 재 본다"
#include <algorithm>
#include <cmath>
#include <cstdio>
using namespace std;

const int CAP = 300;  // 안 끝나는 루프를 실험하기 위한 안전장치. 실전 코드에 이런 것은 없다

bool cube_ge(double mid, double y) { return mid * mid * mid >= y; }

// while (hi - lo > eps). eps 가 그 자리의 double 간격보다 작으면 끝나지 않는다.
double by_absolute(double y, int& k, double eps = 1e-9) {
    double lo = 0.0, hi = max(1.0, y);
    k = 0;
    while (hi - lo > eps && k < CAP) {
        k++;
        double mid = lo + (hi - lo) / 2;
        if (cube_ge(mid, y)) hi = mid;
        else lo = mid;
    }
    return lo;
}

// 폭을 값의 크기로 나눠 본다. 큰 값에서도 반드시 끝난다.
double by_relative(double y, int& k, double eps = 1e-12) {
    double lo = 0.0, hi = max(1.0, y);
    k = 0;
    while (hi - lo > eps * max(1.0, fabs(lo)) && k < CAP) {
        k++;
        double mid = lo + (hi - lo) / 2;
        if (cube_ge(mid, y)) hi = mid;
        else lo = mid;
    }
    return lo;
}

// 폭을 아예 보지 않는다. 100번이면 초기 폭이 2^100 배로 줄어든다.
double by_fixed(double y, int& k, int iters = 100) {
    double lo = 0.0, hi = max(1.0, y);
    for (int i = 0; i < iters; i++) {
        double mid = lo + (hi - lo) / 2;
        if (cube_ge(mid, y)) hi = mid;
        else lo = mid;
    }
    k = iters;
    return lo;
}

int main() {
    printf("     y     |  절대 1e-9      |  상대 1e-12     |  고정 100회\n");
    double ys[] = {2.0, 1e6, 1e18, 1e54};
    for (double y : ys) {
        char cells[3][64];
        int k;
        double x;
        x = by_absolute(y, k);
        snprintf(cells[0], 64, "%4d회 %8.1e", k, fabs(x * x * x - y) / y);
        x = by_relative(y, k);
        snprintf(cells[1], 64, "%4d회 %8.1e", k, fabs(x * x * x - y) / y);
        x = by_fixed(y, k);
        snprintf(cells[2], 64, "%4d회 %8.1e", k, fabs(x * x * x - y) / y);
        printf("%10.0e | %s | %s | %s\n", y, cells[0], cells[1], cells[2]);
    }
    printf("\n300 회는 상한이다 — 그 값이 찍힌 칸은 조건으로 끝나지 못한 것이다.\n");
    return 0;
}
```

**복잡도:** 세 방식 모두 반복당 판정 한 번이므로 시간은 (반복 횟수) × (판정 비용)이다. 다른 것은 반복 횟수가 **무엇으로 정해지는가**다 — 절대 조건은 답의 크기에 따라 30회에서 무한대까지 흔들리고, 상대 조건은 $\log_2(\text{초기폭}/(\varepsilon \cdot |x|))$로 안정적이며, 고정 횟수는 상수다. 마지막 줄이 이 표의 결론이다. **절대 조건은 끝나지 못했고, 고정 100회는 답 근처에도 못 갔다.** 초기 폭 $10^{54}$에는 100회가 모자란다($\lceil \log_2 10^{54} \rceil = 180$).

|---|---|---|
| 부동소수 타입 | `float`는 곧 `double`(64비트) | `float`(32비트)와 `double`이 따로. **반드시 `double`** |
| 정수 나눗셈 혼입 | `1 / 2`는 `0.5` | `1 / 2`는 `0`. `1.0 / 2`로 써야 한다 |
| 세제곱근 | `math.cbrt` (3.11+) | `std::cbrt` (`<cmath>`). 값이 1 ULP 다를 수 있다 |
| 출력 자릿수 | `f"{x:.12f}"` | `printf("%.12f")` 또는 `setprecision(12)` |

| 컴파일러 최적화 | 없음 | `-ffast-math`는 결합법칙을 바꿔 결과를 흔든다. 쓰지 마라 |

::: pitfall
- **`while (hi - lo > EPS)`를 조건 없이 쓴다.** 답이 큰 문제에서 무한 루프다. 반복 횟수를 고정하거나 상대 조건을 써라.
- **`lo = mid + 1`을 실수에 그대로 옮긴다.** 답을 건너뛴다. 실수에서는 `lo = mid`다.
- **초기 구간을 필요 이상으로 크게 잡는다.** `hi = 1e18`로 두면 100회로도 부족한 경우가 생긴다. 폭이 곧 반복 횟수다.
- **`float`를 쓴다.** C++에서 `float`는 유효숫자 24비트, 십진 약 7자리다. 소수점 아래 6자리를 요구하는 문제에서 그대로 틀린다.
- **답 대신 판정값을 비교한다.** `mid * mid * mid == y`처럼 실수를 `==`로 비교하면 거의 항상 거짓이다. 부등호로만 판정하라([X-7](#/x-7)).
- **출력에서 자릿수를 자른다.** 계산은 맞는데 `print(x)`가 기본 자릿수로 줄여 찍어 틀리는 경우가 있다. 요구 자릿수보다 두세 자리 더 찍어라.
:::

## 5. 어디에 쓰이는가

**물리 엔진의 연속 충돌 감지가 실수 이분 탐색이다.** 빠르게 움직이는 물체는 한 프레임 사이에 벽을 통과해 버린다. 그래서 프레임 구간 $[0, 1]$에서 "시각 $t$에 두 물체가 겹치는가"를 판정으로 놓고 **첫 충돌 시각**을 이분 탐색한다. 겹침 판정은 $t$에 대해 단조가 아닐 수 있어서 구간을 먼저 잘게 쪼갠 뒤 각 조각에서 이분 탐색하는 방식이 쓰인다 — §2.2의 단조성 요구가 실무에서 어떻게 다뤄지는지 보여 주는 사례다. 여기서 반복 횟수는 정확도가 아니라 **프레임 예산**이 정한다. 20회면 $10^{-6}$ 프레임 정밀도이고, 그 이상은 화면에 보이지 않는다.

**수치 해석의 이분법(bisection method)은 지금도 표준 도구다.** 뉴턴법이 훨씬 빨리 수렴하지만 초기값이 나쁘면 발산한다. 이분법은 느린 대신 **부호가 다른 두 점만 주어지면 반드시 수렴한다.** 그래서 실무 라이브러리는 뉴턴법이나 할선법을 쓰다가 구간을 벗어나면 이분법으로 되돌아오는 혼합 전략(브렌트법)을 쓴다. 보장된 수렴이 필요한 자리에서 이분 탐색은 대체재가 없다.

**센서 캘리브레이션의 파라미터 탐색도 같은 형태다.** "이 임계값에서 오검출률이 목표 이하인가"를 판정으로 놓고 임계값을 이분 탐색한다. 판정 한 번이 데이터셋 전체를 도는 일이라 비싸고, 그래서 [VII-3](#/vii-3) §5의 부하 시험과 정확히 같은 이유로 이분 탐색이 이긴다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "소수점 아래 셋째 자리까지 출력한다", "오차는 $10^{-6}$까지 허용한다", "실수로 출력", "절대/상대 오차", "거리를 구하시오"처럼 답이 정수로 떨어지지 않는 서술
- 제약조건: 답이 실수이고 단조 판정이 있는 경우. 반복 횟수 $k = \lceil \log_2(\text{초기폭}/\varepsilon) \rceil$에 대해 $k \times (\text{판정 비용})$이 $10^8$ 이하([0-9](#/0-9)). 초기 구간의 폭을 지문에서 읽어낼 수 있어야 한다
- 혼동 주의: 답이 정수면 반열림 정수 이분 탐색([VII-3](#/vii-3))이 언제나 낫다. 실수처럼 보여도 분모를 곱해 정수로 바꿀 수 있으면 그렇게 하라. 판정이 그리디면 → [VII-5](#/vii-5). 볼록 함수의 극값을 찾는 문제는 이분 탐색이 아니라 삼분 탐색이다
- 반례 함정: `while (hi - lo > EPS)`는 답이 $10^9$ 이상이면 무한 루프다. 고정 횟수 100회는 초기 폭이 $10^{30}$을 넘으면 부족하다. C++에서 `float`를 쓰면 유효숫자 7자리에서 멈춘다. 답을 `==`로 비교하면 언제나 거짓이다
:::

::: interview
**"실수 이분 탐색의 종료 조건을 어떻게 정합니까."**
무한 루프부터 말해야 답이 닫힌다. "`hi - lo > EPS`는 답이 클 때 끝나지 않습니다. `double`의 간격이 값의 크기에 비례해서, 예를 들어 $10^{18}$ 근처에서는 두 수 사이의 최소 간격이 이미 128입니다. 그래서 반복 횟수를 고정합니다. 필요한 횟수는 $\lceil \log_2(\text{초기폭}/\text{허용오차}) \rceil$로 계산되고, 보통 100회면 충분합니다." 여기에 "다만 초기 구간이 크면 100회로도 모자랍니다"를 덧붙이면 외운 답이 아니라는 것이 드러난다.

이어서 **절대오차와 상대오차의 차이**를 물어 오는 경우가 많다. "답의 크기가 1 근처면 절대오차로 충분하지만, 답이 크면 절대오차 $10^{-9}$는 `double`로 표현조차 불가능한 요구입니다. 그때는 상대오차로 판단해야 합니다."
:::

- 신호: "소수점 셋째 자리까지 출력" + 거리 `w`를 정하면 교차 높이 `c`가 계산되고, `w`가 커지면 `c`가 작아진다. 단조가 지문에서 바로 읽힌다.

- 자료구조: 실수 세 개. 판정은 피타고라스 두 번과 나눗셈 한 번. **반복을 100회로 고정하면 종료 조건 문제가 통째로 사라진다.**

**2. 백준 1072 게임 (실버 3)** — https://www.acmicpc.net/problem/1072
- 신호: "승률이 변하려면 최소 몇 판을 더 이겨야 하는가" + 승률이라는 실수가 등장한다.
- 상태: 답 후보는 **판 수**다. 실수가 아니라 정수다.
- 자료구조: 정수 두 개. **이 문제의 함정은 승률을 실수로 계산하는 순간 오차 때문에 경계에서 틀린다는 것이다.** `100 * win / game`을 정수 나눗셈으로 계산하면 부동소수점이 아예 개입하지 않는다. ==실수로 보이면 먼저 정수로 바꿀 수 있는지 확인하라==는 §6의 혼동 주의가 그대로 걸리는 문제다.

**4. 손추적 과제 — 필요 반복 횟수 계산.** 초기 구간이 $[0, 10^9]$이고 상대오차 $10^{-9}$를 요구할 때, 필요한 반복 횟수를 §2.3의 식으로 계산하라. 같은 구간에서 **절대**오차 $10^{-9}$를 요구하면 몇 회가 필요하고, 그 요구가 `double`로 가능한가.

3번. 목표가 $2 \times 10^{18}$일 때는 답이 $1.414 \times 10^9$ 근처라 **83회**에서 폭이 $2.384 \times 10^{-7}$로 굳고 `EPS = 1e-9`는 끝내 만족되지 않는다. 목표를 2로 바꾸면 답이 $1.414$ 근처가 되어 **112회**에서 폭이 $2.220 \times 10^{-16}$까지 내려가고 조건이 만족된다. ==코드는 한 글자도 바뀌지 않았고 달라진 것은 답의 크기뿐이다.== ULP 표의 첫 줄과 셋째 줄이 그 차이의 전부다. 종료 조건의 안전성이 코드가 아니라 **입력**에 달려 있다는 것이 이 실험의 결론이다.

4번. 답이 $10^9$ 근처라고 하면 상대오차 $10^{-9}$는 절대오차 $1$에 해당한다. $\lceil \log_2(10^9 / 1) \rceil = 30$회다.

## 요약

- 실수판에서는 정수판의 두 장치가 죽는다. `lo = mid + 1`이 없고 `lo == hi`로 끝나지 않는다. 갱신은 `lo = mid`, 구간은 닫힘 `[lo, hi]`다.
- `while (hi - lo > EPS)`는 **입력에 따라 끝나지 않는다.** `double`의 간격은 값의 크기에 비례하고, $10^{18}$ 근처에서는 이미 128이다.
- 그래서 **반복 횟수를 고정한다.** 필요 횟수는 $\lceil \log_2(\text{초기폭} / \text{허용오차}) \rceil$로 계산된다. 100회가 관용구인 이유가 이 식에 있다.
- 100회는 만능이 아니다. 초기 폭이 $10^{54}$면 100회로 답 근처에도 못 간다. **초기 구간을 좁게 잡는 것이 반복을 늘리는 것보다 싸다.**
- 반복 한 번이 이진 한 자리, 십진 약 0.301자리를 준다. 소수점 12자리는 41회다.
- 답이 크면 절대오차 요구는 `double`로 **표현조차 불가능**하다. 상대오차로 판단하고, 상대 종료 조건 `hi - lo > eps * max(1, |lo|)`는 어떤 크기에서도 끝난다.
- 라이브러리의 "정확한 답"조차 1 ULP 다르다. 실수는 `==`로 비교하지 않는다.
- **실수처럼 보이면 먼저 정수로 바꿀 수 있는지 확인하라.** 바꿀 수 있으면 이 챕터의 함정이 통째로 사라진다.
