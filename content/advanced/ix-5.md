# IX-5 LCA와 희소 배열

::: lead
두 노드의 공통 조상을 매번 뿌리부터 찾는 대신, 전처리 한 번으로 모든 질의를 $O(\log n)$에 답하려면 무엇을 저장해 둬야 하는가.
:::

## 1. 문제

로봇 팔이 여러 개의 관절로 이어져 있다고 하자. 각 관절, 각 센서, 각 손끝은 저마다의 **좌표 프레임**을 가지고 있고, 이 프레임들은 트리 구조로 연결된다 — 몸통 프레임 아래 어깨, 어깨 아래 팔꿈치, 팔꿈치 아래 손목, 손목 아래 카메라와 손끝. 카메라가 찍은 점 하나를 손끝 좌표계로 옮기려면 카메라에서 뿌리까지 올라가는 변환과 뿌리에서 손끝까지 내려가는 변환을 합성해야 하는데, **실제로는 뿌리까지 갈 필요가 없다.** 카메라와 손끝이 갈라지는 지점, 즉 **두 프레임의 가장 가까운 공통 조상**까지만 올라갔다가 내려오면 된다. 그 지점 위쪽의 변환은 카메라 쪽과 손끝 쪽에서 서로 상쇄되기 때문이다.

문제는 이 계산이 **한 번으로 끝나지 않는다는 것**이다. 제어 루프는 초당 수백에서 수천 번 돈다. 관절이 늘어나 프레임 트리가 깊어지거나, 여러 센서 프레임 사이의 상대 위치를 매 주기 다시 구해야 하는 시스템이라면, 질의 하나하나가 공통 조상 찾기이고 그 질의가 끊임없이 들어온다. **온라인 질의** — 질의가 하나씩 실시간으로 들어오고, 다음 질의가 무엇일지 미리 알 수 없는 상황 — 라는 뜻이다.

가장 단순한 방법은 두 노드에서 각각 뿌리까지 조상을 한 칸씩 타고 올라가며 경로를 기록하고, 두 경로가 처음 겹치는 지점을 찾는 것이다. 이 방법의 비용은 **트리의 깊이**에 비례한다. 균형 잡힌 트리라면 깊이가 $\log n$이라 문제가 없지만, 관절이 직렬로 길게 이어진 로봇 팔이나 한쪽으로 치우쳐 자란 트리라면 깊이가 노드 수 $n$까지 간다. 질의가 $Q$번 들어오면 총 비용은 $O(nQ)$이고, $n, Q$가 각각 $10^5$ 근처면 $10^{10}$ 연산이라 어떤 방식으로도 1초 안에 못 끝낸다([0-9](#/0-9)). **트리는 한 번 만들어지면 안 바뀐다. 바뀌는 것은 질의뿐이다.** 그렇다면 트리를 한 번 전처리해 두고, 질의 하나를 뿌리부터 다시 훑지 않고 답할 방법이 있어야 한다.

## 2. 아이디어

```text nolines
   1
   ├── 2
   │    ├── 4
   │    │    ├── 7
   │    │    │    ├── 11
   │    │    │    └── 12
   │    │    └── 8
   │    └── 5
   │         └── 9
   └── 3
        └── 6
             └── 10
                  └── 13
```

이 트리에서 11과 9의 공통 조상을 뿌리부터 다시 찾지 않고 구하고 싶다. 11의 조상 경로는 `11-7-4-2-1`이고 9의 조상 경로는 `9-5-2-1`이다. 답은 2다. 두 경로를 전부 만들지 않고 이 답에 도달하려면, **"한 칸씩"이 아니라 "몇 칸씩" 뛸 수 있어야 한다.**

### 2.1 $2^k$번째 조상을 미리 저장한다

핵심 자료구조는 `up[k][v]` — **v에서 조상 방향으로 $2^k$번 올라간 노드**다. `up[0][v]`는 그냥 부모다. `up[1][v]`는 조부모, `up[2][v]`는 4대 위 조상이다. 이 표를 **희소 배열(sparse table)**이라 부른다. 채우는 방법은 재귀적이다.

$$\text{up}[k][v] = \text{up}[k-1][\,\text{up}[k-1][v]\,]$$

$2^{k-1}$칸을 두 번 뛰면 $2^k$칸이다. `up[0]`만 DFS나 BFS로 채우면, 그 위 칸은 전부 아래 칸을 두 번 읽어서 채워진다.

이 "거리를 두 배씩 늘려가며 채운다"는 발상은 낯설지 않다. [X-3 분할 정복 거듭제곱](#/x-3)에서 $a^n$을 구할 때 지수 $n$을 이진수로 쪼개 $a^1, a^2, a^4, \dots$를 미리 두고 필요한 것만 곱한 것과 **정확히 같은 뼈대**다. 그쪽은 거듭제곱의 지수를, 이쪽은 트리 위에서의 이동 거리를 이진수로 분해한다. 임의의 정수는 2의 거듭제곱의 합으로 유일하게 표현되고, 그 사실이 두 챕터를 같은 기법으로 묶는다.

### 2.2 질의는 두 단계다

**첫째, 깊이를 맞춘다.** 두 노드의 깊이가 다르면 얕은 쪽 답이 나올 수 없으므로, 더 깊은 노드를 얕은 노드와 같은 깊이까지 끌어올린다. 끌어올릴 칸 수(깊이 차이)를 이진수로 분해해 `up[k]`를 필요한 자리만 골라 쓰면 $O(\log n)$번의 점프로 끝난다.

**둘째, 같은 깊이에서 함께 올라가되 절대 지나치지 않는다.** 큰 점프($k$가 큰 쪽)부터 시도한다. `up[k][u]`와 `up[k][v]`가 **같으면 그 칸으로 점프하지 않는다** — 두 노드가 이미 같은 조상 아래 있다는 뜻이고, 그 조상이 공통 조상 자체이거나 공통 조상보다 위일 수 있어서, 점프하면 진짜 공통 조상을 지나쳐 버릴 위험이 있다. `up[k][u]`와 `up[k][v]`가 **다르면** 그만큼 안전하게 뛸 수 있다는 뜻이므로 둘 다 그 칸으로 옮긴다. $k$를 0까지 다 시도하고 나면 $u$와 $v$는 공통 조상의 바로 아래, 서로 다른 자식에 서 있다. **그 부모가 공통 조상이다.**

::: note
`up[k][u] == up[k][v]`일 때 뛰지 않는 이유를 거꾸로 생각하면 쉽다. 뛰어서 겹쳐 버리면 그 지점이 공통 조상인지, 아니면 공통 조상의 조상인지 더 이상 구별할 수 없다. **점프는 "아직 갈라져 있다"는 확신이 있을 때만 한다.**
:::

## 3. 손으로 따라가기

::: trace
§2의 트리에서 `LCA(11, 9)`를 구한다. $n=13$이므로 `LOG` $= 13$의 비트 길이 $= 4$이고, $k$는 3, 2, 1, 0 네 자리를 쓴다.

**깊이 맞추기.** depth(11) = 4, depth(9) = 3, 차이는 1이다. 이진수로 `1`은 비트 0 하나뿐이므로 11을 $2^0=1$칸 올린다. `up[0][11] = 7`이므로 이제 u = 7, v = 9이고 둘 다 깊이 3이다.

**함께 올라가기.** $k$를 3부터 내려가며 `up[k][u]`와 `up[k][v]`를 비교한다. 다르면 그 칸으로 옮긴다.

| k | $2^k$ | up[k][u] | up[k][v] | 같은가 | 다음 u, v |
|---|---|---|---|---|---|
| 3 | 8 | 0 | 0 | 같음 | u=7, v=9 (유지) |
| 2 | 4 | 0 | 0 | 같음 | u=7, v=9 (유지) |
| 1 | 2 | | | | |
| 0 | 1 | | | | |

세 가지를 확인하라.

- [ ] `up[3][7]`과 `up[3][9]`가 왜 둘 다 0인가. 깊이 3인 노드에서 8칸을 더 올라가면 무엇을 넘어서는가
- [ ] $k=1$ 행에서 `up[1][7]`과 `up[1][9]`는 각각 무엇인가. 두 값이 같다는 것은 7과 9가 이미 같은 조상 아래 있다는 뜻인데, 그 조상이 곧바로 답이 아닌 이유는 무엇인가
- [ ] $k=0$ 행에서 u, v가 옮겨진 뒤, 답은 그 두 값의 무엇으로 구하는가
:::

::: answer
| k | $2^k$ | up[k][u] | up[k][v] | 같은가 | 다음 u, v |
|---|---|---|---|---|---|
| 3 | 8 | 0 | 0 | 같음 | u=7, v=9 (유지) |
| 2 | 4 | 0 | 0 | 같음 | u=7, v=9 (유지) |
| 1 | 2 | 2 | 2 | 같음 | u=7, v=9 (유지) |
| 0 | 1 | 4 | 5 | 다름 | u=4, v=5 |

첫 번째. `up[3][7]`은 7에서 8칸 위 조상인데 7의 깊이가 3이라 8칸을 오르면 뿌리(깊이 0)를 아득히 지나친다. 이 구현은 그런 "존재하지 않는 조상"을 0(sentinel)으로 채워 두므로, 8칸 위 조상은 7과 9 양쪽 다 0이다. **0과 0이 같다고 판정되어 점프하지 않는 것이 옳다** — 애초에 그 칸에는 아무것도 없다.

두 번째. `up[1][7] = 2`, `up[1][9] = 2`다. 두 값이 같다는 것은 7과 9가 둘 다 2 아래 있다는 뜻이지만, **2가 정확히 공통 조상인지 아니면 공통 조상의 위쪽인지는 이 시점에서 알 수 없다.** 그래서 이 칸에서는 뛰지 않고 더 작은 $k$로 내려가 확인을 계속한다. 실제로 2가 답이지만, 그것은 다음 단계에서 밝혀진다.

세 번째. $k=0$에서 `up[0][7] = 4`, `up[0][9] = 5`로 서로 다르므로 u, v를 각각 4와 5로 옮긴다. 이제 $k$ 자리가 다 끝났고, u=4와 v=5는 부모가 같다 — `up[0][4] = up[0][5] = 2`. **루프가 끝난 뒤 u의 바로 위 조상이 곧 공통 조상이다.** 답은 2다.
:::

## 4. 구현

::: dual
```python title="LCA — 희소 배열과 이진 상승"
from collections import deque


def build_lca(n, edges, root=1):
    """up[k][v] = v 에서 2^k 번 조상으로 올라간 노드. 없으면 0(sentinel)."""
    LOG = n.bit_length()                      # 2^LOG > n 을 보장하는 최소 값
    adj = [[] for _ in range(n + 1)]
    for u, v in edges:
        adj[u].append(v)
        adj[v].append(u)

    depth = [0] * (n + 1)
    up = [[0] * (n + 1) for _ in range(LOG)]   # up[*][0] 은 항상 0 — "조상 없음"
    visited = [False] * (n + 1)
    visited[root] = True
    q = deque([root])
    while q:                                   # 재귀 대신 BFS — 깊이가 n까지 갈 수 있다(IV-8)
        v = q.popleft()
        for nx in adj[v]:
            if not visited[nx]:
                visited[nx] = True
                depth[nx] = depth[v] + 1
                up[0][nx] = v
                q.append(nx)

    for k in range(1, LOG):
        for v in range(1, n + 1):
            up[k][v] = up[k - 1][up[k - 1][v]]  # 2^(k-1) 을 두 번 뛰면 2^k
    return up, depth, LOG


def lca(u, v, up, depth, LOG):
    if depth[u] < depth[v]:
        u, v = v, u
    diff = depth[u] - depth[v]
    for k in range(LOG):                        # 깊이 차이를 이진수로 분해해 끌어올린다
        if diff >> k & 1:
            u = up[k][u]
    if u == v:
        return u
    for k in range(LOG - 1, -1, -1):             # 큰 점프부터, 겹치면 뛰지 않는다
        if up[k][u] != up[k][v]:
            u, v = up[k][u], up[k][v]
    return up[0][u]


n = 13
edges = [(1, 2), (1, 3), (2, 4), (2, 5), (4, 7), (4, 8), (5, 9),
         (3, 6), (6, 10), (10, 13), (7, 11), (7, 12)]
up, depth, LOG = build_lca(n, edges, 1)
for u, v in [(11, 9), (7, 8), (12, 13)]:
    print(f"LCA({u}, {v}) = {lca(u, v, up, depth, LOG)}")
```
```cpp title="LCA — 희소 배열과 이진 상승"
#include <cstdio>
#include <queue>
#include <vector>
using namespace std;

// up[k][v] = v 에서 2^k 번 조상으로 올라간 노드. 없으면 0(sentinel)
void build_lca(int n, const vector<pair<int, int>>& edges, int root,
                vector<vector<int>>& up, vector<int>& depth, int& LOG) {
    LOG = 1;
    while ((1 << LOG) <= n) LOG++;             // C++17 에는 bit_length 가 없다 — 직접 센다
    vector<vector<int>> adj(n + 1);
    for (auto [u, v] : edges) {
        adj[u].push_back(v);
        adj[v].push_back(u);
    }

    depth.assign(n + 1, 0);
    up.assign(LOG, vector<int>(n + 1, 0));     // up[*][0] 은 항상 0 — "조상 없음"
    vector<bool> visited(n + 1, false);
    visited[root] = true;
    queue<int> q;
    q.push(root);
    while (!q.empty()) {                        // 재귀 대신 BFS — 깊이가 n까지 갈 수 있다(IV-8)
        int v = q.front();
        q.pop();
        for (int nx : adj[v]) {
            if (!visited[nx]) {
                visited[nx] = true;
                depth[nx] = depth[v] + 1;
                up[0][nx] = v;
                q.push(nx);
            }
        }
    }

    for (int k = 1; k < LOG; k++)
        for (int v = 1; v <= n; v++)
            up[k][v] = up[k - 1][up[k - 1][v]];  // 2^(k-1) 을 두 번 뛰면 2^k
}

int lca(int u, int v, vector<vector<int>>& up, vector<int>& depth, int LOG) {
    if (depth[u] < depth[v]) swap(u, v);
    int diff = depth[u] - depth[v];
    for (int k = 0; k < LOG; k++)                // 깊이 차이를 이진수로 분해해 끌어올린다
        if (diff >> k & 1) u = up[k][u];
    if (u == v) return u;
    for (int k = LOG - 1; k >= 0; k--)           // 큰 점프부터, 겹치면 뛰지 않는다
        if (up[k][u] != up[k][v]) { u = up[k][u]; v = up[k][v]; }
    return up[0][u];
}

int main() {
    int n = 13;
    vector<pair<int, int>> edges = {{1, 2}, {1, 3}, {2, 4}, {2, 5}, {4, 7}, {4, 8}, {5, 9},
                                     {3, 6}, {6, 10}, {10, 13}, {7, 11}, {7, 12}};
    vector<vector<int>> up;
    vector<int> depth;
    int LOG;
    build_lca(n, edges, 1, up, depth, LOG);
    vector<pair<int, int>> queries = {{11, 9}, {7, 8}, {12, 13}};
    for (auto [u, v] : queries)
        printf("LCA(%d, %d) = %d\n", u, v, lca(u, v, up, depth, LOG));
    return 0;
}
```

```console
LCA(11, 9) = 2
LCA(7, 8) = 4
LCA(12, 13) = 1
```

**복잡도:** 전처리 시간 $O(n \log n)$ — 노드 $n$개마다 `LOG`단계를 채우고 각 칸이 $O(1)$이므로 $n \times \log n$. 공간도 $O(n \log n)$ — `up` 표 자체가 $n \times \log n$ 칸이다. 질의 시간 $O(\log n)$ — 깊이 맞추기가 `LOG`번의 비트 검사, 함께 올라가기가 `LOG`번의 비교이므로 둘 다 $O(\log n)$이고 합쳐도 $O(\log n)$이다. **트리를 한 번 짓는 데 $O(n \log n)$을 쓰고, 그 뒤로는 질의당 $O(\log n)$이다** — 질의가 $Q$번이면 총 $O((n+Q)\log n)$이고, §1에서 계산한 $O(nQ)$와는 $Q$가 커질수록 차이가 벌어진다.

| 언어 차이 | Python | C++ |
|---|---|---|
| `LOG` 계산 | `n.bit_length()` — 내장 함수 | `bit_width`는 C++20부터다. C++17에서는 `while ((1 << LOG) <= n) LOG++;`로 직접 센다 |
| 2차원 배열의 메모리 배치 | 리스트의 리스트. 각 행이 별도 객체이고 정수도 각각 박싱된다([0-3](#/0-3)) | `vector<vector<int>>`. 각 행 안은 `int` 4바이트가 연속으로 붙어 있어 캐시 지역성이 훨씬 좋다 |
| `swap` | 튜플 언패킹 `u, v = v, u` | `std::swap(u, v)` — `<algorithm>` |

::: pitfall
- **`up` 배열의 크기를 `n+1`로 안 잡는다.** 인덱스 0을 "조상 없음" sentinel로 쓰므로, 0번 칸이 존재해야 하고 그 칸은 절대 갱신되지 않아야 한다. 정점 번호가 1부터 시작한다는 전제가 깨지면(0번 정점이 실제로 존재하면) sentinel이 겹쳐 조용히 틀린다.
- **`LOG`를 너무 작게 잡는다.** $2^{\text{LOG}} \le n$이면 가장 깊은 조상 점프가 표현되지 않아 깊이 맞추기 단계에서 못 올라가고 멈춘다. `bit_length()`(Python) 또는 `while ((1<<LOG)<=n) LOG++`(C++)로 **여유 있게** 잡아야 한다.
- **`up[k][u] == up[k][v]`일 때 점프한다.** §2.2의 "지나치지 않는다"는 규칙을 반대로 짜면, 겹쳐도 되는 순간에 뛰어 버려 공통 조상보다 위로 올라가고 답이 항상 뿌리 쪽으로 쏠린다.
- **깊이 맞추기에서 어느 쪽을 올릴지 헷갈린다.** 항상 **더 깊은 쪽**을 얕은 쪽 깊이까지 올린다. 방향을 반대로 짜면 이미 얕은 노드를 음수 칸만큼 올리려는 코드가 되어 조용히 틀린다.
- **경로 모양 트리에서 전처리를 재귀 DFS로 짠다.** 깊이가 $n$까지 갈 수 있으므로 [IV-8 트리에서의 DFS](#/iv-8)의 경고가 그대로 적용된다. 이 절의 구현이 BFS를 쓰는 이유가 그것이다.
:::

## 5. 어디에 쓰이는가

**좌표 프레임 트리의 공통 조상**이 §1의 로봇 예시를 그대로 잇는다. 관절이 많은 매니퓰레이터나 여러 팔이 달린 로봇은 프레임 트리가 깊어지고, 손끝과 카메라처럼 서로 다른 가지에 달린 두 프레임 사이의 상대 변환을 매 제어 주기 다시 구해야 한다. 두 프레임의 조상 경로를 매번 뿌리까지 만들어 비교하는 대신, 희소 배열로 전처리해 두면 관절이 아무리 늘어나도 질의당 $O(\log n)$을 유지한다. 실제 로봇 미들웨어의 좌표 변환 라이브러리들은 프레임을 트리로 관리하고, 두 프레임 사이의 변환을 요청받으면 정확히 이 문제 — **두 프레임의 가장 가까운 공통 조상까지 거슬러 올라갔다가 내려오는 경로** — 를 풀어서 답한다. 프레임 수가 수십 개 수준이면 단순히 한 칸씩 걸어 올라가도 충분하지만, 조립형 로봇이나 다중 로봇 편대처럼 프레임 트리가 수백~수천 개로 커지고 변환 조회가 고빈도로 반복되는 시스템에서는 이 절의 이진 상승이 실질적인 차이를 만든다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "두 정점의 최소 공통 조상", "가장 가까운 공통 조상", "두 노드를 모두 자손으로 가지면서 깊이가 가장 깊은 노드", 그리고 **"M개의 쌍이 주어질 때"**처럼 질의가 여러 개라는 조건
- 제약조건: 정점 수 $N$, 질의 수 $M$이 각각 $10^5$ 안팎이고 트리(간선 $N-1$개)다. 질의가 하나씩 실시간으로 들어오는 **온라인** 상황이면 이 절의 이진 상승이 필요하고, $M$이 아주 작으면(수백 이하) 뿌리까지 매번 걷는 $O(\text{depth})$ 방식도 시간 안에 통과한다 — 그 경계가 [IX-5 §1](#/ix-5)에서 다룬 $O(nQ)$의 실제 크기다
- 혼동 주의: 질의를 **모두 미리 알고 있다면**(오프라인) [IX-1 유니온 파인드](#/ix-1)를 이용한 오프라인 LCA(타잔의 방법)로도 풀린다 — 이쪽은 희소 배열 없이 $O((n+m)\,\alpha(n))$에 끝나지만, 질의를 다 모은 뒤에만 답이 나온다는 제약이 있다. "서브트리 크기"나 "루트로부터의 거리"만 묻는다면 희소 배열 없이 [IV-8 트리에서의 DFS](#/iv-8) 한 번으로 충분하다
- 반례 함정: 한쪽으로 치우쳐 자란 **경로 모양 트리**에서 naive 방식(뿌리까지 한 칸씩)의 깊이가 $n$까지 벌어져 $O(nQ)$가 실제로 터진다. 그리고 `up` 표를 재귀 DFS로 채우면 같은 트리에서 재귀 깊이도 함께 터진다 — 두 함정이 같은 입력에서 동시에 온다
:::

## 연습

::: quiz
**1. 백준 11437 LCA (골드 3)** — https://www.acmicpc.net/problem/11437
- 신호: "가장 가까운 공통 조상이 몇 번인지 출력". 정점·질의 수가 각각 5만, 10만 이하라 뿌리까지 매번 걷는 $O(\text{depth})$ 방식도 시간 안에 들어온다.
- 상태: `parent[v]`, `depth[v]`. 희소 배열 없이 두 노드의 깊이를 맞추고 한 칸씩 같이 올라가도 통과한다.
- 자료구조: 인접 리스트 + 부모·깊이 배열. **이 문제부터 풀어야** 다음 문제에서 무엇이 느려지는지 몸으로 확인된다.

**2. 백준 11438 LCA 2 (플래티넘 5)** — https://www.acmicpc.net/problem/11438
- 신호: 11437과 지문이 사실상 같은데 질의 수 상한이 훨씬 크다. 뿌리까지 걷는 방식을 그대로 제출하면 시간 초과가 난다.
- 상태: `up[k][v]`. **질의 수가 문제를 바꾼다** — 같은 질문이라도 몇 번 물어보는지가 어떤 자료구조를 요구하는지를 정한다는 것이 이 두 문제의 핵심 대비다.
- 자료구조: $O(n \log n)$ 크기의 희소 배열. 이 절의 구현이 정확히 이 문제를 겨냥한다.

**3. 백준 1761 정점들의 거리 (플래티넘 5)** — https://www.acmicpc.net/problem/1761
- 신호: "두 정점을 잇는 가장 짧은 경로의 길이"를 가중치 있는 트리에서 여러 번 묻는다.
- 상태: 뿌리로부터의 누적 거리 `dist[v]`와 `up[k][v]`를 함께 전처리한다. 두 정점 사이 거리는 $\text{dist}[u] + \text{dist}[v] - 2 \cdot \text{dist}[\text{lca}(u,v)]$로, LCA를 구하는 문제가 아니라 **LCA를 부품으로 쓰는 문제**다.
- 자료구조: 가중치 인접 리스트 + `dist` 배열 + 희소 배열. LCA 자체가 아니라 "LCA를 알면 무엇을 더 계산할 수 있는가"를 묻는 전형이다.
:::

## 요약

- 두 노드의 공통 조상을 매 질의마다 뿌리부터 찾으면 트리 깊이가 $n$까지 갈 수 있어 질의 $Q$번에 $O(nQ)$다.
- **희소 배열** `up[k][v]` = $v$에서 $2^k$번 위 조상. `up[0]`만 BFS로 채우면 나머지는 `up[k][v] = up[k-1][up[k-1][v]]`로 채워진다. [X-3](#/x-3)의 분할 정복 거듭제곱과 같은 "거리를 이진수로 분해한다"는 뼈대다.
- 질의는 두 단계다. **깊이를 맞추고**(더 깊은 쪽을 끌어올린다), **함께 올라가되 `up[k][u]`와 `up[k][v]`가 같으면 뛰지 않는다**(지나치지 않기 위해서다).
- 전처리 $O(n \log n)$, 질의 $O(\log n)$. 정점이 1000자리 트리든 로봇 프레임 100개짜리 트리든 질의 비용은 로그로만 자란다.
- sentinel 0은 "조상 없음"을 뜻하고, `up` 배열이 인덱스 0을 포함해야 이 규칙이 저절로 성립한다.
- 전처리를 재귀로 짜면 경로 모양 트리에서 [IV-8](#/iv-8)과 같은 재귀 깊이 문제가 그대로 재현된다. BFS로 짜는 이유다.
- 질의를 전부 미리 안다면 희소 배열 없이 [IX-1](#/ix-1)의 유니온 파인드로 오프라인 LCA를 풀 수도 있다. 이 절은 질의가 실시간으로 들어오는 온라인 상황을 다룬다.
