# IX-8 네트워크 플로우 입문

::: lead
여러 경로로 갈라진 네트워크에서, 한쪽 끝에서 다른 쪽 끝까지 동시에 흘려보낼 수 있는 최대량은 얼마인가?
:::

## 1. 문제

물류창고 `S`에서 집하장 `T`까지 물건을 보내야 한다. 중간에 두 개의 분류 허브 `A`, `B`가 있고, 각 구간은 시간당 옮길 수 있는 최대 개수(용량)가 정해져 있다.

```text nolines
   S ──2──▶ A                 <- 시간당 최대 2대
   S ──2──▶ B
   A ──1──▶ B                 <- 두 허브를 잇는 다리
   A ──2──▶ T
   B ──2──▶ T
```

질문은 하나다. **S에서 T까지 시간당 최대 몇 대를 보낼 수 있는가.** 각 구간의 용량을 넘지 않으면서, 경로를 몇 갈래로 나누든 상관없다.

떠오르는 방법은 경로를 하나씩 잡아 최대한 채우는 것이다. `S→A→T`를 먼저 잡으면 `min(2,2)=2`대를 보낼 수 있다. 이어서 `S→B→T`를 잡으면 또 `min(2,2)=2`대. 합쳐서 4대이고, `S`에서 나가는 용량 합(`2+2=4`)과 같으니 더는 못 보낼 것 같다.

그런데 경로를 하나씩 확정하고 절대 되돌리지 않는 방식은, 먼저 잡은 경로가 나중의 더 나은 조합을 막아 버리는 경우에 문제가 생긴다. 이 그래프도 예외가 아니다 — §3에서 직접 확인하겠지만, **경로 하나를 이미 확정한 뒤에도 그 결정의 일부를 "취소"해야 진짜 최댓값에 도달하는 경우가 있다.** 취소를 못 하는 알고리즘은 최댓값을 놓칠 수 있다.

## 2. 아이디어

경로를 확정한 뒤 취소할 수 있으려면, **각 간선에 "거꾸로 갈 수 있는 용량"을 함께 들고 다녀야 한다.** 어떤 간선 `u→v`에 유량 `f`를 흘려보냈다면, 그 순간 가상의 반대 방향 간선 `v→u`에 용량 `f`짜리 여유가 생긴다고 본다. 이 반대 방향 간선을 **역간선**이라 부르고, 원래 간선의 남은 용량과 역간선을 합쳐서 그린 그래프를 **잔여 그래프**라 한다.

역간선이 하는 일은 하나뿐이다. **이 구간에 흘려보낸 유량 중 일부를 무르고 다른 경로로 돌린다.** 나중에 `v`에서 `u`로 가는 경로를 찾았다면, 그 경로는 실제로 물건을 거꾸로 보내는 것이 아니라 **원래 `u→v`로 보내려던 유량 중 일부를 취소하는 것**과 같은 효과를 낸다. 이 취소 덕분에 어떤 순서로 경로를 잡든 알고리즘은 결국 최댓값에 도달한다 — "잘못된 선택"이라는 개념 자체가 사라진다. 잘못 잡아도 나중에 역간선으로 되돌리면 그만이기 때문이다.

Ford-Fulkerson 방법은 이 아이디어를 그대로 절차로 만든다.

1. 잔여 그래프에서 `S`부터 `T`까지 가는 아무 경로나 하나 찾는다(**증가 경로**). 없으면 끝난다.
2. 그 경로 위 간선들의 남은 용량 중 최솟값(**병목**)만큼 유량을 흘려보낸다.
3. 지나간 정방향 간선은 용량을 병목만큼 줄이고, 역간선은 병목만큼 늘린다.
4. 1로 돌아간다.

증가 경로를 찾는 방법은 DFS든 BFS든 상관없다 — DFS로 아무 경로나 찾으면 **Ford-Fulkerson**, 매번 BFS로 가장 짧은 증가 경로를 찾으면 **Edmonds-Karp**라 부른다. §4의 구현은 DFS를 쓴다. 어느 쪽을 쓰든 도착하는 최댓값은 같다.

이 절차가 언제 멈추는지 보면 **최대 유량과 최소 컷이 같다**는 사실이 자연스럽게 드러난다. 알고리즘이 멈추는 순간은 잔여 그래프에서 `S`에서 `T`로 가는 경로가 더 이상 없을 때다. 그 시점에 `S`에서 잔여 용량을 타고 갈 수 있는 정점들의 집합을 `X`, 나머지를 `Y`라 하면, `X`와 `Y` 사이의 모든 정방향 간선은 잔여 용량이 0(포화)이어야 한다 — 하나라도 남아 있었다면 아직 경로가 있었을 것이다. 이 포화된 간선들의 원래 용량 합이 하나의 **컷**(S와 T를 끊는 간선 집합의 용량 합)이고, 그 값이 지금까지 흘려보낸 총 유량과 같다. 어떤 컷을 지나는 유량도 그 컷의 용량 합을 넘을 수 없으므로(모든 S-T 경로가 그 컷의 간선을 반드시 하나는 지나야 한다), 이 컷은 가장 작은 컷이면서 동시에 지금 유량이 가장 큰 유량이라는 뜻이 된다. 증명은 이 챕터의 범위를 넘지만, **알고리즘이 멈추는 지점 자체가 최소 컷이라는 그림**은 기억해 둘 만하다.

## 3. 손으로 따라가기

::: trace
그래프: `S→A`(2), `S→B`(2), `A→B`(1), `A→T`(2), `B→T`(2). DFS는 매번 `S`에서 시작해 **이웃을 번호 오름차순**(S<A<B<T)으로 시도하고, 처음 찾은 S-T 경로를 증가 경로로 쓴다.

| 반복 | 경로 | 병목 | 잔여 (S→A, S→B, A→B, B→A역, A→T, B→T) | 누적 유량 |

| 0(초기) | — | — | 2, 2, 1, 0, 2, 2 | 0 |
| 1 | S→A→B→T | 1 | 1, 2, 0, 1, 2, 1 | 1 |
| 2 | S→A→T | 1 | 0, 2, 0, 1, 1, 1 | 2 |
| 3 | | | | |
| 4 | | | | |

반복3에서 DFS가 `S→A`(잔여0, 막힘) 대신 `S→B`로 간다는 것까지는 쉽다. `B`에서 그다음 어디로 가는지, 그리고 **왜 그 경로가 정방향 간선만으로는 설명이 안 되는지**를 채워라.

::: answer
| 반복 | 경로 | 병목 | 잔여 (S→A, S→B, A→B, B→A역, A→T, B→T) | 누적 유량 |
|---|---|---|---|---|
| 0(초기) | — | — | 2, 2, 1, 0, 2, 2 | 0 |
| 1 | S→A→B→T | 1 | 1, 2, 0, 1, 2, 1 | 1 |
| 2 | S→A→T | 1 | 0, 2, 0, 1, 1, 1 | 2 |
| 3 | S→B→A→T | 1 | 0, 1, 1, 0, 0, 1 | 3 |
| 4 | S→B→T | 1 | 0, 0, 1, 0, 0, 0 | 4 |

반복3이 이 챕터의 핵심이다. `S→A`는 이미 0(반복2에서 소진)이라 DFS는 `S→B`로 간다. `B`에서 번호가 더 낮은 이웃부터 시도하는 규칙대로 `A`를 먼저 본다 — `A→B` 정방향은 반복1에서 이미 0이 됐지만, **그때 생긴 역간선 `B→A`가 잔여 1을 들고 있다.** DFS는 이 역간선을 타고 `A`로 건너간 뒤 `A→T`의 남은 용량 1을 써서 `T`에 닿는다.

경로 `S→B→A→T`는 실제로 아무것도 "거꾸로" 흐르지 않는다 — 반복1에서 `A→B`로 보냈던 1만큼을 취소하고, 그만큼을 `B`에서 곧장 `T`로 보내는 것과 정확히 같은 효과를 낸다. 최종 잔여값에서 순유량을 거꾸로 셈해 보면(`A→B` 정방향 잔여1=미사용, `A→T` 잔여0=포화, `B→T` 잔여0=포화) `A→B`는 순유량 0이고, `S-A-T`에 2, `S-B-T`에 2를 흘린 것과 **정확히 같은 최종 상태**다. 역간선이 반복1의 비효율적인 선택을 되돌려 최적해로 데려간 것이다.

반복5에서는 `S→A`, `S→B`가 모두 0이라 DFS가 `S`에서 한 발짝도 못 나가고 끝난다. 이 시점의 컷은 `{S}` 대 `{A,B,T}`이고, `S`를 떠나는 간선 용량 합(`2+2=4`)이 §2에서 말한 최소 컷이며 최종 유량 4와 일치한다.
:::

## 4. 구현

::: dual
```python title="Ford-Fulkerson — 잔여 그래프와 증가 경로"
def max_flow(n, cap, s, t):
    """DFS 로 증가 경로를 찾는다. 이웃은 정점 번호 오름차순으로 시도한다."""
    total = 0
    while True:
        visited = [False] * n
        parent = [-1] * n
        visited[s] = True

        def dfs(u):
            if u == t:
                return True
            for v in range(n):
                if cap[u][v] > 0 and not visited[v]:
                    visited[v] = True
                    parent[v] = u
                    if dfs(v):
                        return True
            return False

        if not dfs(s):
            break                                 # 잔여 그래프에 더 이상 경로가 없다
        v, bottleneck = t, float("inf")
        while v != s:
            u = parent[v]
            bottleneck = min(bottleneck, cap[u][v])
            v = u
        v = t
        while v != s:                             # 정방향은 줄이고 역방향은 늘린다
            u = parent[v]
            cap[u][v] -= bottleneck
            cap[v][u] += bottleneck
            v = u
        total += bottleneck
    return total


n = 4                                              # S=0, A=1, B=2, T=3
cap = [[0] * n for _ in range(n)]
cap[0][1] = 2   # S->A
cap[0][2] = 2   # S->B
cap[1][2] = 1   # A->B
cap[1][3] = 2   # A->T
cap[2][3] = 2   # B->T

result = max_flow(n, cap, 0, 3)
print("max flow =", result)
```
```cpp title="Ford-Fulkerson — 잔여 그래프와 증가 경로"
#include <climits>
#include <cstdio>
#include <functional>
#include <vector>
using namespace std;

long long max_flow(int n, vector<vector<long long>>& cap, int s, int t) {
    // DFS 로 증가 경로를 찾는다. 이웃은 정점 번호 오름차순으로 시도한다.
    long long total = 0;
    while (true) {
        vector<bool> visited(n, false);
        vector<int> parent(n, -1);
        visited[s] = true;
        function<bool(int)> dfs = [&](int u) -> bool {
            if (u == t) return true;
            for (int v = 0; v < n; v++) {
                if (cap[u][v] > 0 && !visited[v]) {
                    visited[v] = true;
                    parent[v] = u;
                    if (dfs(v)) return true;
                }
            }
            return false;
        };
        if (!dfs(s)) break;                        // 잔여 그래프에 더 이상 경로가 없다
        long long bottleneck = LLONG_MAX;
        for (int v = t; v != s; v = parent[v])
            bottleneck = min(bottleneck, cap[parent[v]][v]);
        for (int v = t; v != s; v = parent[v]) {    // 정방향은 줄이고 역방향은 늘린다
            cap[parent[v]][v] -= bottleneck;
            cap[v][parent[v]] += bottleneck;
        }
        total += bottleneck;
    }
    return total;
}

int main() {
    int n = 4;                                      // S=0, A=1, B=2, T=3
    vector<vector<long long>> cap(n, vector<long long>(n, 0));
    cap[0][1] = 2;   // S->A
    cap[0][2] = 2;   // S->B
    cap[1][2] = 1;   // A->B
    cap[1][3] = 2;   // A->T
    cap[2][3] = 2;   // B->T

    long long result = max_flow(n, cap, 0, 3);
    printf("max flow = %lld\n", result);
    return 0;
}
```
:::

```console
max flow = 4
```

**복잡도:** 시간 $O(Ef)$ — `f`는 최대 유량의 값이다. 매 반복이 유량을 최소 1(정수 용량 가정)씩 늘리므로 반복 횟수가 최대 `f`번이고, 매 반복의 DFS가 인접 행렬에서 각 정점의 이웃 전체를 스캔하므로 반복당 $O(V^2)$다. 공간 $O(V^2)$ — 용량을 인접 행렬로 들기 때문이다(간선이 성긴 그래프라면 인접 리스트로 $O(V+E)$까지 줄어든다).

| 언어 차이 | Python | C++ |
|---|---|---|
| 재귀 DFS 클로저 | 중첩 함수 `dfs`가 바깥 스코프의 `visited`, `parent`를 그대로 참조 | `function<bool(int)>`에 `[&]` 캡처로 같은 효과를 낸다 — 재귀 람다는 이렇게 `std::function`으로 감싸야 한다 |
| 오버플로 | 임의 정밀도라 용량이 커도 안전 | 용량 합이 `int` 범위를 넘을 수 있어 `long long`을 쓴다 |

::: pitfall
- **역간선을 빼먹는다.** 정방향 용량만 관리하면 §3의 반복3 같은 취소가 원천적으로 불가능해지고, 그래프 구조에 따라 최댓값에 못 미치는 값에서 멈춘다.
- **역간선의 초기 용량을 0이 아닌 값으로 둔다.** 역간선은 "아직 아무것도 안 보냈다"는 뜻으로 0에서 시작해야 한다. 원래 간선과 같은 용량으로 시작하면 존재하지 않는 용량을 만들어낸 것이다.
- **DFS 기반 Ford-Fulkerson을 큰 정수 용량에 그대로 쓴다.** 반복마다 유량이 **최소 1**만 늘어난다는 보장만 있으므로, 용량이 $10^9$짜리 정수라면 최악의 경우 반복 횟수가 유량 크기에 비례해 늘어날 수 있다 — 복잡도 $O(Ef)$의 `f`가 그대로 발목을 잡는다. 매번 **가장 짧은** 증가 경로를 BFS로 찾는 Edmonds-Karp는 반복 횟수를 $O(VE)$로 묶어 용량 크기와 무관하게 만든다. 더 빠른 $O(V^2E)$ Dinic 알고리즘도 있으나 이 챕터는 입문까지만 다룬다.
- **양방향으로 흐르는 간선을 역간선과 혼동한다.** 실제로 양방향 파이프라면 `u→v`와 `v→u`를 **각각 원래 용량으로** 추가해야지, 역간선(용량 0에서 시작)으로 대신하면 안 된다.
:::

## 5. 이분 매칭 — 용량 1로 특수화하기

[IV-7 이분 그래프](#/iv-7)에서 본 매칭 문제를 최대 유량으로 그대로 풀 수 있다. 왼쪽 정점 집합(예: 작업자)과 오른쪽 정점 집합(예: 작업)이 있고, 매칭 가능한 쌍마다 간선이 있을 때 — **소스 `S`를 만들어 왼쪽 정점 전부에 용량 1 간선을 잇고, 오른쪽 정점 전부에서 싱크 `T`로 용량 1 간선을 잇는다.** 원래 있던 매칭 가능 간선도 용량 1로 둔다.

이 그래프의 최대 유량이 곧 **최대 이분 매칭의 크기**다. 용량이 전부 1이라는 데서 그대로 나온다 — `S`에서 나가는 간선이 용량 1이므로 작업자 하나는 유량을 최대 1만 받을 수 있고, 즉 최대 한 작업에만 배정된다. 대칭적으로 작업 하나도 최대 한 작업자에게서만 유량을 받는다. **정확히 이분 매칭의 정의다.**

::: dual
```python title="이분 매칭 = 유량 (조각) — §4의 max_flow 를 그대로 재사용한다"
workers = ["W1", "W2", "W3"]
jobs = ["J1", "J2", "J3"]
able = [("W1", "J1"), ("W1", "J2"), ("W2", "J1"), ("W3", "J2"), ("W3", "J3")]

nw, nj = len(workers), len(jobs)
S, T = 0, nw + nj + 1
n = nw + nj + 2
w_id = {w: i + 1 for i, w in enumerate(workers)}
j_id = {j: nw + 1 + i for i, j in enumerate(jobs)}

cap = [[0] * n for _ in range(n)]
for w in workers:
    cap[S][w_id[w]] = 1                # 소스 -> 작업자, 용량 1
for j in jobs:
    cap[j_id[j]][T] = 1                # 작업 -> 싱크, 용량 1
for w, j in able:
    cap[w_id[w]][j_id[j]] = 1          # 매칭 가능 간선, 용량 1

matching = max_flow(n, cap, S, T)      # §4 에서 정의한 함수를 그대로 쓴다
print("최대 매칭 크기 =", matching)
assigned = [(w, j) for w, j in able if cap[w_id[w]][j_id[j]] == 0]  # 정방향 용량 0 = 그 간선을 썼다
print("배정:", assigned)
```
```cpp title="이분 매칭 = 유량 (조각) — §4의 max_flow 를 그대로 재사용한다"
vector<string> workers = {"W1", "W2", "W3"};
vector<string> jobs = {"J1", "J2", "J3"};
vector<pair<string, string>> able = {
    {"W1", "J1"}, {"W1", "J2"}, {"W2", "J1"}, {"W3", "J2"}, {"W3", "J3"}};

int nw = (int)workers.size(), nj = (int)jobs.size();
int S = 0, T = nw + nj + 1, n = nw + nj + 2;
map<string, int> w_id, j_id;
for (int i = 0; i < nw; i++) w_id[workers[i]] = i + 1;
for (int i = 0; i < nj; i++) j_id[jobs[i]] = nw + 1 + i;

vector<vector<long long>> cap(n, vector<long long>(n, 0));
for (auto& w : workers) cap[S][w_id[w]] = 1;        // 소스 -> 작업자, 용량 1
for (auto& j : jobs) cap[j_id[j]][T] = 1;            // 작업 -> 싱크, 용량 1
for (auto& [w, j] : able) cap[w_id[w]][j_id[j]] = 1; // 매칭 가능 간선, 용량 1

long long matching = max_flow(n, cap, S, T);         // §4 에서 정의한 함수를 그대로 쓴다
printf("최대 매칭 크기 = %lld\n", matching);
printf("배정: ");
for (auto& [w, j] : able)
    if (cap[w_id[w]][j_id[j]] == 0)                  // 정방향 용량 0 = 그 간선을 썼다
        printf("(%s,%s) ", w.c_str(), j.c_str());
printf("\n");
```
:::

```console
최대 매칭 크기 = 3
배정: [('W1', 'J2'), ('W2', 'J1'), ('W3', 'J3')]
```

`W2`는 `J1`밖에 못 하므로 `W2→J1`이 강제되고, 나머지는 `W1→J2`, `W3→J3`로 자연히 결정된다 — 완전 매칭이다. 소스·싱크와 용량 1이라는 틀만 씌우면 §4의 유량 함수가 손도 안 대고 매칭을 풀어낸다.

**복잡도:** §4의 `max_flow`를 그대로 쓰므로 $O(Ef)$가 그대로 적용된다. 여기서는 용량이 전부 1이므로 최대 유량 `f`가 왼쪽 정점 수를 못 넘고, 반복마다 유량이 정확히 1씩만 늘어 반복 횟수 자체가 매칭 크기와 같다 — 이분 매칭에서는 $O(Ef)$가 곧 $O(VE)$로 좁혀진다.

## 6. 어디에 쓰이는가

**작업 할당이 첫 번째 자리다.** [V-11 할당 문제](#/v-11)의 헝가리안 알고리즘은 **비용이 붙은** 일대일 완전 매칭을 풀었다. 비용 없이 "짝지을 수 있는가"만 묻는 순수 이분 매칭은 이 챕터가 그 특수 사례이고, **한쪽이 여러 개를 맡을 수 있으면** 용량을 1보다 크게 잡은 일반 유량 문제로 넘어간다 — 할당·매칭·유량은 같은 계보에서 제약이 하나씩 풀리는 순서로 이어진다.

**네트워크 대역폭 할당도 같은 모델이다.** 여러 서비스가 공유 링크를 지나갈 때 각 구간의 대역폭이 간선 용량이고, 특정 두 지점 사이에 보장 가능한 최대 처리량을 구하는 문제가 그대로 최대 유량이다. 중간에 회선이 여러 갈래로 갈라지는 실제 백본 구조를 그대로 그래프로 옮기면, 어느 구간이 전체 처리량을 묶어 두는 병목인지가 §2의 최소 컷으로 바로 드러난다.

**이미지 분할의 그래프 컷 기법도 최소 컷을 쓴다.** 픽셀을 정점으로, 인접 픽셀 사이의 유사도를 간선 용량으로 두면 "전경과 배경을 가르는 가장 싼 경계선"이 곧 최소 컷이고, 최대 유량 알고리즘으로 계산한다.

## 7. 이 유형을 알아보는 법

::: classify
- 신호어: "최대 몇 개를 보낼 수 있는가", "동시에 처리할 수 있는 최대 개수", "파이프의 최대 유량", "각자 하나씩만 맡을 수 있다"(매칭), "S에서 T까지 서로 겹치지 않는 경로의 최대 개수"
- 제약조건: 정점 $V$가 수백~수천, 간선 $E$가 비슷한 규모면 $O(VE^2)$급(Edmonds-Karp)도 여유롭다. 유량 값 `f` 자체가 매우 크면(용량이 $10^9$대) 단순 Ford-Fulkerson은 위험하다
- 혼동 주의: 비용이 붙어 있고 **일대일**이면 할당 문제([V-11](#/v-11), 헝가리안). "짝지을 수 있는가"만 물으면 이 챕터의 이분 매칭(용량 1). 방향·용량 없이 단순히 "연결되어 있는가"만 물으면 유량이 아니라 [IX-1 유니온 파인드](#/ix-1)나 DFS다
- 반례 함정: 경로를 하나씩 확정하고 되돌리지 않는 탐욕은 최댓값을 놓칠 수 있다(§1, §3의 예). 역간선 없이 짠 코드는 작은 그래프의 우연한 순서에서는 맞다가 그래프가 조금만 복잡해지면 조용히 최댓값보다 작은 값을 낸다
:::

## 연습

::: quiz
**1. 백준 6086 최대 유량 (골드 5)** — https://www.acmicpc.net/problem/6086
- 신호: "우물에서 외양간까지 보낼 수 있는 물의 최대 유량". 파이프가 양방향으로 흐를 수 있다는 조건이 있다.
- 상태: 정점은 알파벳 하나당 하나, 간선 용량은 파이프 유량. 같은 두 지점 사이에 파이프가 여러 개면 용량을 더해서 하나로 합친다.
- 자료구조: 인접 행렬(정점이 최대 26개라 $O(V^2)$가 전혀 부담 없다). 양방향 파이프는 두 방향 각각에 원래 용량을 넣는다 — 역간선(용량 0)과 헷갈리지 않는다.

**2. 백준 11375 열혈강호 (골드 4)** — https://www.acmicpc.net/problem/11375
- 신호: "직원마다 할 수 있는 일 목록이 있고 각자 하나씩만 맡는다. 최대 몇 개의 일을 처리할 수 있는가."
- 상태: §5의 소스·싱크 구성 그대로 — 직원 쪽에 소스, 일 쪽에 싱크, 전부 용량 1.
- 자료구조: 직원·일 수가 각각 최대 1000이라 인접 행렬(정점 2000개 이상)은 메모리가 빠듯하다. 인접 리스트 기반 유량이나, 이분 매칭 전용으로 각 작업자마다 DFS를 한 번씩만 돌리는 표준 매칭 코드로 좁혀 푸는 것이 일반적이다.

**3. 백준 2188 축사 배정 (골드 4)** — https://www.acmicpc.net/problem/2188
- 신호: "소마다 들어갈 수 있는 축사 목록이 있고, 축사 하나에는 최대 한 마리". 11375와 구조가 동일하다.
- 상태: 소를 왼쪽, 축사를 오른쪽에 두는 이분 매칭. 이 문제를 **명시적으로 소스·싱크가 있는 유량 그래프로** 만들어 풀어 보면, 다음부터는 소스·싱크를 생략한 이분 매칭 전용 코드가 왜 같은 답을 내는지 연결이 된다.
:::

## 요약

- 유량은 각 간선의 용량을 넘지 않으면서 소스에서 싱크로 보낼 수 있는 최대량을 구하는 문제다.
- 경로를 확정하고 되돌리지 못하는 탐욕은 실패할 수 있다. **역간선**이 있어야 이전 선택의 일부를 취소하고 최댓값에 도달한다.
- Ford-Fulkerson: 잔여 그래프에서 증가 경로를 찾아 병목만큼 흘리고, 정방향은 줄이고 역간선은 늘리기를 반복한다. 시간 $O(Ef)$.
- S,A,B,T 예제에서 세 번째 반복이 역간선 `B→A`를 타고 지나가며, 첫 반복의 낭비를 되돌려 최종 유량 4(=최소 컷)에 도달한다.
- 매번 BFS로 최단 증가 경로를 찾으면 Edmonds-Karp이고, 반복 횟수가 용량 크기와 무관하게 $O(VE)$로 묶인다.
- **최대 유량 = 최소 컷.** 알고리즘이 멈추는 자리가 곧 S와 T를 가르는 가장 싼 절단이다.
- 용량을 전부 1로 두고 좌우 정점 + 소스·싱크를 구성하면 **이분 매칭이 최대 유량의 특수 사례**가 된다. 비용이 붙은 일대일 매칭은 [V-11 할당 문제](#/v-11)로 이어진다.
