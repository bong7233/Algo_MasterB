# IX-4 최소 신장 트리

::: lead
모든 정점을 연결하는 가장 싼 방법 하나를 무엇이 보장하는가?
:::

## 1. 문제

[IX-1 유니온 파인드](#/ix-1)는 "이 두 정점이 이미 연결되어 있는가"를 거의 상수 시간에 답한다. 이제 질문을 뒤집는다. 아직 아무것도 연결되지 않은 정점들이 있고, 정점 쌍마다 연결 비용(간선 가중치)이 다르게 매겨져 있다. **모든 정점을 연결하되 비용의 합을 최소로 하려면 어떤 간선들을 골라야 하는가.**

간선을 무작정 다 쓰면 안 된다 — 사이클이 생긴 부분은 비용만 늘릴 뿐 연결에 아무 기여도 안 한다. 정점이 $n$개면 사이클 없이 전부 연결하는 데 필요한 간선은 정확히 $n-1$개다(하나라도 적으면 어딘가 끊기고, 하나라도 많으면 반드시 사이클이 생긴다). 그러니 문제는 "$n-1$개의 간선을 어떻게 골라야 총 비용이 최소인 트리가 되는가"로 좁혀진다.

후보는 많다. 정점 $n$개의 완전그래프에는 스패닝 트리가 $n^{n-2}$개나 있다(케일리 공식). $n=10$만 되어도 $10^8$개다. 전부 만들어서 비교하는 것은 애초에 선택지가 아니다.

## 2. 아이디어

이 문제를 그리디로 풀 수 있다는 것을 보장하는 것이 **컷 속성(cut property)**이다. 정점 집합을 임의로 두 그룹 $S$와 나머지로 나누는 경계를 컷이라 부른다. 컷 속성은 이렇게 말한다 — **어떤 컷을 잡든, 그 컷을 가로지르는 간선 중 가장 싼 것은 반드시 어떤 최소 신장 트리에 속한다.**

증명은 [VI-1 그리디가 성립하는 조건](#/vi-1)의 교환 논법과 같은 모양이다. 최소 신장 트리 $T$가 그 최소 간선 $e$를 안 썼다고 하자. $T$에서 $e$의 양 끝을 잇는 경로를 따라가면, 그 경로도 언젠가 한 번은 컷을 가로지른다 — 그 간선을 $f$라 하자. $e$가 $f$보다 싸거나 같으므로, $T$에서 $f$를 빼고 $e$를 넣어도 여전히 트리이고 비용은 늘지 않는다. **바꿔도 손해가 없다면, $e$를 포함한 트리도 이미 최소였거나 방금 최소가 됐다.** 이 논증이 모든 컷에 대해 성립하므로, "지금까지 만든 것과 아직 안 쓴 것 사이의 최소 간선을 계속 골라도 된다"는 그리디가 정당화된다.

이 하나의 성질에서 서로 다른 두 알고리즘이 갈라져 나온다. 컷을 어떻게 매 순간 다시 잡느냐의 차이다.

**크루스칼**은 컷을 신경 쓰지 않는다. 그냥 전역에서 가장 싼 간선부터 순서대로 보면서, 사이클만 만들지 않으면 무조건 담는다. "사이클을 만드는가"는 두 끝점이 이미 같은 컴포넌트에 있는가로 판정되고, 그 판정이 정확히 [IX-1](#/ix-1)의 유니온 파인드다. 간선이 어느 컷을 가로지르는지는 몰라도, 사이클만 안 생기면 그 순간 존재하는 어떤 컷에 대해서도 그 간선이 최소이기 때문에 정당하다.

**프림**은 반대로 컷을 명시적으로 관리한다. 지금까지 고른 간선들이 이미 트리 하나(연결된 덩어리 하나)를 이루고 있다고 하고, 그 덩어리를 $S$, 컷을 "덩어리 안 vs 밖"으로 고정한다. 이 컷을 가로지르는 간선 중 가장 싼 것을 하나 골라 덩어리에 편입시키고, 컷을 다시 그린다. 매번 "지금 덩어리에 새로 인접한 정점들 중 가장 싼 연결"을 골라야 하므로, 이 최소값 관리를 [II-8 힙과 우선순위 큐](#/ii-8)가 맡는다.

**어느 쪽을 쓸지는 그래프의 밀도가 정한다.** 간선이 이미 리스트로 주어지고 희소하면($E$가 $V$의 몇 배 수준) 크루스칼이 자연스럽다 — 정렬 한 번과 사실상 상수 시간인 유니온 파인드 연산만으로 끝난다. 반대로 좌표들만 주어지고 사실상 모든 쌍이 후보 간선인 밀집 그래프라면, 간선을 전부 만들어 정렬하는 일 자체가 $O(V^2 \log V)$로 무겁다 — 이럴 때는 힙도 정렬도 없이 인접 행렬에서 "아직 안 붙은 정점 중 최소 연결 비용"을 매번 선형 탐색하는 배열 기반 프림이 $O(V^2)$로 그 낭비를 피한다.

| 3 | 1-2 (3) | 아니오 | 선택 | {0,1,2,3} {4} | 6 |
| 4 | 0-2 (4) | **예** (둘 다 {0,1,2,3}) | **거부(사이클)** | {0,1,2,3} {4} | 6 |
| 5 | 3-4 (4) | 아니오 | 선택 | {0,1,2,3,4} | 10 |

5스텝에서 간선 4개(=$n-1$)가 모여 종료한다. 4번 스텝의 `0-2`는 두 끝점이 이미 같은 컴포넌트라 사이클을 만들기 때문에 거부됐다 — 컷 속성이 "이 간선은 어느 컷에 대해서도 최소가 아니다"라고 이미 말해 준 것과 같다. 남은 간선 `2-3(5)`, `2-4(6)`은 볼 필요도 없이 알고리즘이 끝난다.

**최소 신장 트리 비용은 10**이고, 간선은 `0-1, 1-3, 1-2, 3-4`다. 프림을 정점 0에서 시작해 돌려도(각 단계에서 지금 덩어리에 인접한 최소 간선을 고름) 같은 비용 10에 도달한다 — 트리를 이루는 간선 집합은 다를 수 있어도 총 비용은 항상 같다. 최소 신장 트리의 **비용**은 유일하다.

## 4. 구현

::: dual
```python title="크루스칼 — 간선 정렬 + 유니온 파인드"
class DSU:
    """경로 압축 + 랭크 유니온. IX-1 과 같은 구조다."""

    def __init__(self, n):
        self.parent = list(range(n))
        self.rank = [0] * n

    def find(self, x):
        while self.parent[x] != x:
            self.parent[x] = self.parent[self.parent[x]]
            x = self.parent[x]
        return x

    def union(self, a, b):
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return False
        if self.rank[ra] < self.rank[rb]:
            ra, rb = rb, ra
        self.parent[rb] = ra
        if self.rank[ra] == self.rank[rb]:
            self.rank[ra] += 1
        return True


def kruskal(n, edges):
    """edges: (weight, u, v) 목록. 오름차순으로 보며 사이클만 피해서 담는다."""
    dsu = DSU(n)
    total, picked = 0, []
    for w, u, v in sorted(edges):
        if dsu.union(u, v):
            total += w
            picked.append((u, v, w))
            if len(picked) == n - 1:
                break
    return total, picked


EDGES = [(1, 0, 1), (3, 1, 2), (2, 1, 3), (4, 0, 2), (4, 3, 4), (5, 2, 3), (6, 2, 4)]
total, picked = kruskal(5, EDGES)
print("크루스칼 총 비용 =", total)
print("선택된 간선 =", picked)
```
```cpp title="크루스칼 — 간선 정렬 + 유니온 파인드"
#include <algorithm>
#include <cstdio>
#include <tuple>
#include <vector>
using namespace std;

struct DSU {
    vector<int> parent, rank_;

    // 경로 압축 + 랭크 유니온. IX-1 과 같은 구조다.
    DSU(int n) : parent(n), rank_(n, 0) {
        for (int i = 0; i < n; i++) parent[i] = i;
    }

    int find(int x) {
        while (parent[x] != x) {
            parent[x] = parent[parent[x]];
            x = parent[x];
        }
        return x;
    }

    bool unite(int a, int b) {
        int ra = find(a), rb = find(b);
        if (ra == rb) return false;
        if (rank_[ra] < rank_[rb]) swap(ra, rb);
        parent[rb] = ra;
        if (rank_[ra] == rank_[rb]) rank_[ra]++;
        return true;
    }
};

// edges: (weight, u, v) 목록. 오름차순으로 보며 사이클만 피해서 담는다.
pair<long long, vector<tuple<int, int, int>>> kruskal(int n, vector<tuple<int, int, int>> edges) {
    sort(edges.begin(), edges.end());
    DSU dsu(n);
    long long total = 0;
    vector<tuple<int, int, int>> picked;
    for (auto& [w, u, v] : edges) {
        if (dsu.unite(u, v)) {
            total += w;
            picked.push_back({u, v, w});
            if ((int)picked.size() == n - 1) break;
        }
    }
    return {total, picked};
}

int main() {
    vector<tuple<int, int, int>> edges = {
        {1, 0, 1}, {3, 1, 2}, {2, 1, 3}, {4, 0, 2}, {4, 3, 4}, {5, 2, 3}, {6, 2, 4}};
    auto [total, picked] = kruskal(5, edges);
    printf("크루스칼 총 비용 = %lld\n", total);
    printf("선택된 간선 = [");
    for (size_t i = 0; i < picked.size(); i++) {
        auto& [u, v, w] = picked[i];
        printf("%s(%d, %d, %d)", i ? ", " : "", u, v, w);
    }
    printf("]\n");
    return 0;
}
```

크루스칼의 시간 복잡도는 $O(E \log E)$다 — 간선 정렬이 지배적이고, 유니온 파인드 연산 $E$번은 경로 압축과 랭크를 함께 쓰면 사실상 상수 시간이다. 프림과 나란히 놓고 근거를 마저 보자.

::: dual
```python title="프림 — 힙으로 경계를 확장"
import heapq


def prim(n, adj, start=0):
    """adj[u] = [(v, w), ...]. II-8 의 힙 sift 구조를 그대로 쓴다."""
    visited = [False] * n
    heap = [(0, start)]
    total, used, picked = 0, 0, []
    while heap and used < n:
        w, u = heapq.heappop(heap)
        if visited[u]:
            continue
        visited[u] = True
        total += w
        used += 1
        if u != start:
            picked.append((u, w))
        for v, vw in adj[u]:
            if not visited[v]:
                heapq.heappush(heap, (vw, v))
    return total, picked


def to_adj(n, edges):
    adj = [[] for _ in range(n)]
    for w, u, v in edges:
        adj[u].append((v, w))
        adj[v].append((u, w))
    return adj


EDGES = [(1, 0, 1), (3, 1, 2), (2, 1, 3), (4, 0, 2), (4, 3, 4), (5, 2, 3), (6, 2, 4)]
total, picked = prim(5, to_adj(5, EDGES))
print("프림 총 비용 =", total)
```
```cpp title="프림 — 힙으로 경계를 확장"
#include <cstdio>
#include <queue>
#include <tuple>
#include <vector>
using namespace std;

// adj[u] = [(v, w), ...]. II-8 의 힙 sift 구조를 그대로 쓴다.
long long prim(int n, vector<vector<pair<int, int>>>& adj, int start = 0) {
    vector<bool> visited(n, false);
    priority_queue<pair<int, int>, vector<pair<int, int>>, greater<>> heap;
    heap.push({0, start});
    long long total = 0;
    int used = 0;
    while (!heap.empty() && used < n) {
        auto [w, u] = heap.top();
        heap.pop();
        if (visited[u]) continue;
        visited[u] = true;
        total += w;
        used++;
        for (auto& [v, vw] : adj[u])
            if (!visited[v]) heap.push({vw, v});
    }
    return total;
}

int main() {
    vector<tuple<int, int, int>> edges = {
        {1, 0, 1}, {3, 1, 2}, {2, 1, 3}, {4, 0, 2}, {4, 3, 4}, {5, 2, 3}, {6, 2, 4}};
    vector<vector<pair<int, int>>> adj(5);
    for (auto& [w, u, v] : edges) {
        adj[u].push_back({v, w});
        adj[v].push_back({u, w});
    }
    printf("프림 총 비용 = %lld\n", prim(5, adj));
    return 0;
}
```

**복잡도:** 크루스칼은 시간 $O(E \log E)$ — 간선 정렬이 지배적이고, 이후 유니온 파인드 연산 $E$번은 경로 압축과 랭크를 함께 쓰면 사실상 상수 시간(역 아커만 함수)이다. 프림(힙)은 시간 $O(E \log V)$ — 간선마다 힙에 최대 한 번 push되고 각 push·pop이 $O(\log V)$다. 둘 다 공간 $O(V+E)$.

$E \le V^2$이므로 $\log E \le 2\log V$라, 두 복잡도는 사실상 같은 급이다. 그래서 실측에서도 희소 그래프에서는 둘의 차이가 크지 않다(`tools/bench/ix4_mst.py`, $V{=}4{,}000$, $E{\approx}8{,}000$, 3회 측정 중앙값).

| | 크루스칼 | 프림(힙) | 프림(배열, 인접 행렬) |
|---|---|---|---|
| 희소 $V{=}4{,}000, E{\approx}8{,}000$ | 0.0075s | 0.0073s | — |
| 밀집(완전그래프) $V{=}700, E{\approx}244{,}650$ | 0.1077s | 0.1384s | **0.0565s** |

(Linux x86-64 / CPython 3.13 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/ix4_mst.py`다.) 밀집 그래프에서는 힙 기반 프림이 오히려 크루스칼보다 느리다 — 간선 $24$만 개를 전부 힙에 push하는 비용이 정렬과 다를 바 없어서다. 이 구간에서 실제로 이기는 것은 **힙도 정렬도 없이 인접 행렬에서 최솟값을 선형 탐색하는 배열 기반 프림**이다. $O(V^2)$이 $O(E \log V) \approx O(V^2 \log V)$를 이긴다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 간선 정렬 | `sorted(edges)`가 튜플을 사전식으로 비교한다 | `tuple`도 사전식 비교라 `sort`가 그대로 같은 순서를 낸다 |
| 힙 방향 | `heapq`는 최소 힙 고정 | `priority_queue`는 최대 힙이 기본이라 `greater<>`로 뒤집어야 최소 힙이 된다 |
| 총 비용 자료형 | 정수 오버플로가 없다 | 간선이 많고 가중치가 크면 `int` 합이 넘칠 수 있어 `long long`을 쓴다 |

::: pitfall
- **그래프가 애초에 비연결이면 스패닝 트리가 없다.** 크루스칼이 끝났는데 선택된 간선이 $n-1$개 미만이면 "연결 불가능"으로 처리해야 한다. `len(picked) == n-1`을 확인하지 않고 `total`만 반환하면 이 경우를 조용히 틀린 답으로 넘긴다.
- **간선에 음수 가중치가 있어도 두 알고리즘 모두 그대로 작동한다.** 최소 신장 트리에는 "음수 사이클" 개념 자체가 없다 — 벨만-포드([V-2](#/v-2))와 헷갈려서 "음수면 못 쓴다"고 넘겨짚지 마라.
- **가중치가 같은 간선이 여럿이면 최소 신장 트리를 이루는 간선 집합이 여러 개일 수 있다.** 다만 트리의 총 비용은 항상 같다 — 위 트레이스처럼 크루스칼과 프림이 서로 다른 간선을 고를 수 있어도 비용 10은 같다.
- **프림에서 `visited` 체크를 힙에 넣을 때 하면** 오래된(더 비싼) 항목이 나중에 팝되며 중복 처리된다. 반드시 팝한 직후, 그 정점을 확정하기 직전에 체크한다.
:::

## 5. 어디에 쓰이는가

**통신망·배관망 설계가 최소 신장 트리 그 자체다.** 여러 거점을 케이블이나 배관으로 전부 연결하되 부설 비용(길이 또는 공사비)의 합을 최소로 해야 하는 문제는 정점을 거점으로, 간선 가중치를 부설 비용으로 두면 곧바로 이 챕터의 문제가 된다. 지도에서 도로망의 중복 구간을 쳐내 **최소한의 도로로 모든 지점을 잇는 로드맵**을 만들 때도 같은 구조가 쓰인다 — 실제 도로를 다 유지하되 "이 이상 줄이면 어딘가 끊긴다"는 골격만 별도로 뽑아 두면, 그 위에서 경로 탐색([V-1](#/v-1) 이후)을 훨씬 가볍게 돌릴 수 있다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "모든 정점을 연결하는 데 드는 최소 비용", "네트워크를 구성하는 최소 비용", "모든 지점을 잇는 가장 저렴한 방법"
- 제약조건: 무방향 가중치 그래프. 간선이 이미 리스트로 주어지고 희소($E = O(V)$)하면 크루스칼, 좌표만 주어지고 사실상 완전그래프($V \le$ 수천)면 배열 기반 프림([0-9](#/0-9))
- 혼동 주의: "두 특정 정점 사이"의 최소 비용을 물으면 최단경로([V-1](#/v-1) 다익스트라)다 — MST는 항상 **모든 정점**을 대상으로 한다. 최대 신장 트리가 필요하면 간선을 내림차순으로 정렬하거나 가중치 부호를 뒤집으면 크루스칼을 그대로 쓸 수 있다
- 반례 함정: 그래프가 비연결이면 스패닝 트리 자체가 없다 — 종료 후 선택된 간선 수를 반드시 확인하라. 음수 가중치가 있어도 알고리즘은 그대로 맞다
:::

::: interview
**"크루스칼과 프림 중 언제 무엇을 씁니까."**
"간선이 이미 리스트로 주어지고 희소하면 크루스칼을 씁니다. 정렬 한 번과 사실상 상수 시간인 유니온 파인드로 끝나기 때문입니다. 좌표만 주어지고 사실상 완전그래프인 밀집 그래프라면, 간선을 전부 만들어 정렬하는 것 자체가 $O(V^2 \log V)$로 무겁습니다. 이때는 힙도 정렬도 없이 인접 행렬에서 최솟값을 선형 탐색하는 배열 기반 프림이 $O(V^2)$로 이깁니다." 실측으로는 완전그래프에서 배열 기반 프림이 크루스칼보다 약 두 배 빠르다는 것까지 붙이면 좋다.
:::

## 연습

::: quiz
**1. 백준 1197 최소 스패닝 트리 (골드 4)** — https://www.acmicpc.net/problem/1197
- 신호: "최소 스패닝 트리의 최소 비용을 구하라"는 문장 그대로 문제 이름이다. 이 챕터의 원형.
- 상태: 간선 리스트 그대로. 별도의 상태 압축이 필요 없다.
- 왜 이 자료구조인가: $V \le 10{,}000$, $E \le 100{,}000$으로 희소하다. 간선이 이미 주어져 있으니 정렬 + 유니온 파인드인 크루스칼이 가장 짧고 빠르다.

**2. 백준 1922 네트워크 연결 (골드 4)** — https://www.acmicpc.net/problem/1922
- 신호: "모든 컴퓨터를 연결하는 최소 비용"을 컴퓨터 수와 간선(연결 가능한 두 컴퓨터, 비용)으로 묻는다. 실무 시나리오를 그대로 옮긴 문제다.
- 상태: 간선 리스트. 1197과 같은 골격이라 신호어만으로 즉시 확정된다.
- 왜 이 자료구조인가: 크루스칼이든 프림이든 되지만, 간선이 리스트로 주어지므로 크루스칼이 더 직접적이다.

**3. 백준 4386 별자리 만들기 (골드 4)** — https://www.acmicpc.net/problem/4386
- 신호: 별의 좌표만 주어지고 "모든 별을 연결하는 최소 비용"을 묻는다. 간선이 명시되지 않고, 두 별 사이의 거리(유클리드)가 곧 간선 비용이라 사실상 완전그래프다.
- 상태: 좌표 목록. 간선은 두 점의 거리를 계산해서 그때그때 만든다.
- 왜 이 자료구조인가: $n \le 100$이라 $O(n^2)$ 간선이 몇천 개뿐이라 크루스칼로도 통과하지만, 좌표만으로 그래프가 암묵적으로 주어지는 전형적인 "밀집 그래프" 신호다. 배열 기반 프림이 간선을 아예 만들지 않고도 풀리는 이유를 확인하기 좋은 문제다.

**4. 백준 1647 도시 분할 계획 (골드 4)** — https://www.acmicpc.net/problem/1647
- 신호: "두 마을로 분할하되 각 마을 안은 모두 연결되어야 하고, 나머지 유지비의 합을 최소로 하라."
- 상태: 최소 신장 트리를 먼저 완성한 뒤, 그 트리에서 **가장 비싼 간선 하나를 끊는다**는 결정이 추가된다.
- 왜 이 자료구조인가: 신장 트리에서 간선 하나를 끊으면 정확히 두 개의 연결 컴포넌트로 나뉜다 — 트리라는 성질(사이클이 없다) 덕분에 성립하는 사실이다. 가장 비싼 간선을 끊는 것이 총 비용을 가장 많이 줄인다는 것을 컷 속성으로 설명할 수 있어야 한다.
:::

## 요약

- $n$개의 정점을 사이클 없이 전부 연결하려면 간선이 정확히 $n-1$개 필요하다. 그 조합 중 총 비용이 최소인 것을 찾는 문제다.
- **컷 속성**이 그리디를 정당화한다 — 어떤 컷을 가로지르는 간선 중 가장 싼 것은 항상 어떤 최소 신장 트리에 속한다.
- **크루스칼**은 전역에서 싼 간선부터 보며 사이클만 [유니온 파인드](#/ix-1)로 피한다. 간선이 희소할 때 유리하다.
- **프림**은 지금까지 만든 덩어리의 경계를 [힙](#/ii-8)으로 확장한다. 힙 기반 프림은 밀집 그래프에서 크루스칼과 비슷하거나 오히려 느릴 수 있다 — 실제로 밀집 그래프에서 이기는 것은 힙도 정렬도 없는 $O(V^2)$ 배열 기반 프림이다.
- 최소 신장 트리를 이루는 간선의 **집합**은 여러 개일 수 있어도 **총 비용은 항상 유일하다.**
- 그래프가 비연결이면 스패닝 트리가 없다. 선택된 간선 수가 $n-1$에 못 미치면 그 경우다.
- 음수 가중치가 있어도 두 알고리즘 모두 그대로 맞다 — 최단경로의 음수 사이클 문제와는 무관하다.
