# IX-3 펜윅 트리(BIT)

::: lead
구간 합과 점 갱신을 O(log n)에 처리하는 데, [IX-2](#/ix-2)처럼 트리를 통째로 세워야만 하는가?
:::

## 1. 문제

[IX-2 세그먼트 트리](#/ix-2)는 "값을 하나 바꾼다"와 "구간의 합을 구한다"가 번갈아 오는 문제를 O(log n)/O(log n)으로 푼다. 배열 하나로 O(1) 갱신·O(n) 질의를 하거나, 프리픽스 합 배열로 O(1) 질의·O(n) 갱신을 하는 두 극단 사이에서, 트리 하나를 세워 양쪽을 다 로그 시간으로 만든 것이다.

그런데 그 대가를 다시 보자. 세그먼트 트리는 크기 $4n$짜리 배열을 만들고, 재귀로 트리를 채우는 `build` 함수를 짜고, 갱신과 질의도 각각 재귀 함수로 짠다. 노드 번호가 `2*node`, `2*node+1`로 뻗어 나가는 구조를 관리해야 하고, 구간이 겹치는지 포함되는지를 매 호출마다 판정해야 한다. 백준 2042 구간 합 구하기 같은 문제 — 수 $N \le 10^6$개에 값 변경과 구간 합 질의를 합쳐 $2 \times 10^4$번 — 는 세그먼트 트리로 풀리지만, 코드는 30줄을 넘는다.

여기서 필요한 연산은 딱 둘이다. **점 하나를 바꾼다. 구간의 합을 구한다.** 트리가 다루는 연산이 "합"이라는 한 가지뿐이라면, 트리 구조를 명시적으로 세우지 않고도 같은 로그 시간을 낼 방법이 있다. 그 답이 펜윅 트리, 다른 이름으로 이진 인덱스 트리(Binary Indexed Tree, BIT)다.

## 2. 아이디어

세그먼트 트리는 각 노드에 "이 노드가 담당하는 구간"을 명시적으로 저장하고 부모-자식 포인터(또는 그 역할을 하는 배열 인덱스 `2*node`)로 트리를 만든다. 펜윅 트리는 그 트리를 **배열 인덱스의 이진수 표현 자체에 숨긴다.** 별도의 트리 구조가 없다 — 크기 $n+1$짜리 배열 하나가 전부다.

핵심은 인덱스 $i$의 최하위 비트다. $i$를 이진수로 쓰고 가장 오른쪽의 1비트만 남긴 값을 `lowbit(i)`라 하면, 이 값이 코드에서는 `i & -i`로 나온다. 2의 보수 표현에서 $-i$는 $i$의 모든 비트를 뒤집고 1을 더한 것이므로, $i$의 최하위 1비트보다 아래는 $-i$에서도 0이 그대로 남고 그 자리 자체는 두 수 모두 1이다. 그래서 AND를 취하면 그 비트 하나만 남는다.

```text nolines
   i = 6  = 0110
  -i = ...1010   (0110 을 뒤집으면 1001, +1 하면 1010)
 i&-i =    0010  = 2
```

`tree[i]`는 **길이가 정확히 `lowbit(i)`인 구간, 즉 $(i - \text{lowbit}(i),\; i]$ 의 합**을 담아 둔다. $i=1..8$에서 이 대응을 전부 적으면 이렇다.

| i (십진) | 이진 | lowbit(i) | tree[i] 가 담당하는 구간 |
|---|---|---|---|
| 1 | 0001 | 1 | [1, 1] |
| 2 | 0010 | 2 | [1, 2] |
| 3 | 0011 | 1 | [3, 3] |
| 4 | 0100 | 4 | [1, 4] |
| 5 | 0101 | 1 | [5, 5] |
| 6 | 0110 | 2 | [5, 6] |
| 7 | 0111 | 1 | [7, 7] |
| 8 | 1000 | 8 | [1, 8] |

담당 구간의 길이가 인덱스마다 다르고, 그 길이가 **인덱스의 이진 표현에 이미 적혀 있다.** 이것이 세그먼트 트리가 명시적으로 들고 다니는 "이 노드는 이 구간을 담당한다"는 정보를 배열 인덱스 하나로 대신하는 방법이다.

**갱신**은 $a[i]$가 바뀌었을 때, $i$를 포함하는 모든 담당 구간의 `tree` 값을 고쳐야 한다. 위 표에서 인덱스 3을 포함하는 구간은 $[3,3]$(tree[3]), $[1,4]$(tree[4]), $[1,8]$(tree[8])이다. 이 인덱스들은 $3 \to 4 \to 8$로 이어지는데, 매 단계 `i += i & -i`로 얻어진다 — 지금 담당 구간을 완전히 포함하는, 바로 다음으로 큰 담당 구간으로 건너뛰는 것이다.

**질의**는 $[1, i]$의 합을 구할 때, $i$부터 시작해 `i -= i & -i`로 내려가며 만나는 `tree[i]`들을 더한다. 이 값들은 서로 겹치지 않고 $[1,i]$를 정확히 나눠 덮는다 — $i$의 이진 표현에서 켜진 비트 하나하나가 담당 구간 하나에 대응하기 때문이다. $i=7=0111$이면 $[7,7]+[5,6]+[1,4]$로 세 조각, 즉 켜진 비트 수(3개)만큼의 덧셈으로 끝난다.

**왜 합(과 XOR)만 되고 최솟값·최댓값은 안 되는가.** 질의가 성립하는 이유는 합에 **뺄셈이라는 역원**이 있어서다. $[1,7]$의 합에서 $[1,4]$의 합을 빼면 $[5,7]$의 합이 나온다 — 세그먼트 트리라면 두 자식을 각각 봐야 할 상황을, 펜윅 트리는 프리픽스 두 개의 차로 대신한다. 갱신도 마찬가지다. $a[3]$에 $\delta$를 더하면, $3$을 포함하는 모든 담당 구간의 합에 그냥 $\delta$를 **더하기만** 하면 된다.

최솟값에는 이 두 성질이 둘 다 없다. $[1,7]$의 최솟값과 $[1,4]$의 최솟값을 알아도 $[5,7]$의 최솟값은 알 수 없다 — 뺄셈에 대응하는 역연산이 없다. 갱신도 안 된다. $a[3]$이 커지면, $3$을 포함하던 어떤 담당 구간의 최솟값이 하필 $a[3]$이었을 경우 그 구간의 새 최솟값을 구해야 하는데, 펜윅 트리의 `tree[i]`는 그 구간에 있던 **다른** 원소들의 값을 하나도 기억하지 않는다. 세그먼트 트리는 이 문제가 없다 — 모든 내부 노드가 두 자식의 실제 값을 들고 있어서, 자식 하나가 바뀌면 그 값만 다시 합치면 된다. 펜윅 트리는 그 여분의 정보를 아예 버리고 "더하고 빼면 언제나 정확한 값이 나온다"는 보장 위에서만 성립하는 압축이다. XOR가 되는 이유도 같다 — $a \oplus a = 0$, 즉 XOR는 스스로가 자신의 역원이다.

## 3. 손으로 따라가기

::: trace
배열 `a[1..8] = [3, 1, 4, 1, 5, 9, 2, 6]`을 담은 펜윅 트리가 있다. `tree` 배열은 이미 위 표대로 채워져 있다 — `tree[1]=3, tree[2]=4, tree[3]=4, tree[4]=9, tree[5]=5, tree[6]=14, tree[7]=2, tree[8]=31`.

**갱신** `update(3, +3)` — $a[3]$에 3을 더한다. `i`가 `i += i & -i`로 올라간다.

| 스텝 | i (이진) | i & -i | tree[i] 갱신 전 → 후 | 다음 i |
|---|---|---|---|---|
| 1 | 3 (0011) | 1 | 4 → 7 | 3+1=4 |
| 2 | 4 (0100) | 4 | 9 → 12 | 4+4=8 |
| 3 | | | | |
| — | (다음 i가 n=8을 넘으면 종료) | | | |

**질의** `query(6)` — $[1,6]$의 합. `i`가 `i -= i & -i`로 내려간다. (갱신 전 상태로 되돌아가 계산한다.)

| 스텝 | i (이진) | i & -i | tree[i] | 누적 합 | 다음 i |
|---|---|---|---|---|---|
| 1 | 6 (0110) | 2 | 14 | 14 | 6-2=4 |
| 2 | | | | | |
| — | (i=0 이 되면 종료) | | | | |

빈칸을 채워라. `update(3, +3)` 이후 `query(6)`을 다시 하면 얼마가 나오는가? $[1,6]$에 인덱스 3이 들어가므로 원래 값에서 3만큼 늘어나야 한다.
:::

::: answer
**갱신** `update(3, +3)`

| 스텝 | i (이진) | i & -i | tree[i] 갱신 전 → 후 | 다음 i |
|---|---|---|---|---|
| 1 | 3 (0011) | 1 | 4 → 7 | 4 |
| 2 | 4 (0100) | 4 | 9 → 12 | 8 |
| 3 | 8 (1000) | 8 | 31 → 34 | 16 |
| — | 16 > 8, 종료 | | | |

**질의** `query(6)` (갱신 전)

| 스텝 | i (이진) | i & -i | tree[i] | 누적 합 | 다음 i |
|---|---|---|---|---|---|
| 1 | 6 (0110) | 2 | 14 | 14 | 4 |
| 2 | 4 (0100) | 4 | 9 | 23 | 0 |
| — | i=0, 종료. 답 = 23 | | | | |

$a[1..6] = 3+1+4+1+5+9 = 23$과 일치한다. `update(3, +3)` 이후 `query(6)`을 다시 하면 `tree[6]`은 그대로 14(구간 $[5,6]$은 인덱스 3을 포함하지 않는다)지만 `tree[4]`는 12로 늘어나 있으므로 $14+12=26$이다. 원래 23에서 정확히 3만큼 늘었다 — $a[3]$의 변화가 인덱스 3을 포함하는 담당 구간에만, 그리고 정확히 그만큼만 반영됐다는 뜻이다.
:::

## 4. 구현

::: dual
```python title="펜윅 트리 — 점 갱신과 구간 합"
class Fenwick:
    """1-indexed 펜윅 트리. tree[i] 는 (i - (i & -i), i] 구간의 합을 들고 있다."""

    def __init__(self, n):
        self.n = n
        self.tree = [0] * (n + 1)

    def update(self, i, delta):
        while i <= self.n:
            self.tree[i] += delta
            i += i & -i

    def prefix(self, i):
        s = 0
        while i > 0:
            s += self.tree[i]
            i -= i & -i
        return s

    def range_sum(self, l, r):
        return self.prefix(r) - self.prefix(l - 1)


a = [3, 1, 4, 1, 5, 9, 2, 6]
ft = Fenwick(len(a))
for i, v in enumerate(a, start=1):
    ft.update(i, v)

print("query(6) =", ft.prefix(6))
print("query(7) =", ft.prefix(7))
ft.update(3, 3)
print("update(3, +3) 이후 query(6) =", ft.prefix(6))
print("range_sum(4, 7) =", ft.range_sum(4, 7))
```
```cpp title="펜윅 트리 — 점 갱신과 구간 합"
#include <cstdio>
#include <vector>
using namespace std;

struct Fenwick {
    int n;
    vector<long long> tree;

    // 1-indexed 펜윅 트리. tree[i] 는 (i - (i & -i), i] 구간의 합을 들고 있다.
    Fenwick(int n) : n(n), tree(n + 1, 0) {}

    void update(int i, long long delta) {
        while (i <= n) {
            tree[i] += delta;
            i += i & -i;
        }
    }

    long long prefix(int i) {
        long long s = 0;
        while (i > 0) {
            s += tree[i];
            i -= i & -i;
        }
        return s;
    }

    long long range_sum(int l, int r) {
        return prefix(r) - prefix(l - 1);
    }
};

int main() {
    vector<int> a = {3, 1, 4, 1, 5, 9, 2, 6};
    Fenwick ft(a.size());
    for (int i = 0; i < (int)a.size(); i++) ft.update(i + 1, a[i]);

    printf("query(6) = %lld\n", ft.prefix(6));
    printf("query(7) = %lld\n", ft.prefix(7));
    ft.update(3, 3);
    printf("update(3, +3) 이후 query(6) = %lld\n", ft.prefix(6));
    printf("range_sum(4, 7) = %lld\n", ft.range_sum(4, 7));
    return 0;
}
```
:::

두 언어의 출력은 같다.

```console
query(6) = 23
query(7) = 25
update(3, +3) 이후 query(6) = 26
range_sum(4, 7) = 17
```

**복잡도:** 시간 $O(\log n)$ — `update`와 `prefix` 모두 매 스텝 `i`의 최하위 1비트 위치가 최소 한 자리 위(갱신) 또는 아래(질의)로 옮겨 간다. $n$을 이진수로 쓰면 비트 수가 $\lfloor \log_2 n \rfloor + 1$이므로, 이 스텝은 그 이상 반복될 수 없다. 공간 $O(n)$ — 배열 하나.

[IX-2 세그먼트 트리](#/ix-2)와 같은 일(점 갱신 + 구간 합)을 시켜 놓고 코드 줄 수와 실행 시간을 재면 이렇다(`tools/bench/ix3_fenwick.py`, 클래스 본문에서 빈 줄·주석을 뺀 순수 코드 줄 수와 $N{=}200{,}000$·연산 $10^5$회 3회 측정 중앙값).

| | 펜윅 트리 | 세그먼트 트리(재귀) |
|---|---|---|
| 핵심 로직 줄 수 | 15줄 | 33줄 |
| 실행 시간(중앙값) | 0.466s | 1.083s |

(Linux x86-64 / CPython 3.13 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/ix3_fenwick.py`다.) 줄 수가 절반을 조금 넘고, 속도는 두 배 이상 차이 난다. 재귀 호출 오버헤드와 노드 경계 판정이 사라진 값이다. 대신 펜윅 트리는 **합·XOR처럼 역원이 있는 연산만** 다룬다 — 그 제약과 맞바꾼 결과다.

| 언어 차이 | Python | C++ |
|---|---|---|
| `-i` 계산 | 임의 정밀도 정수지만 비트 연산은 무한 자리 2의 보수로 정의되어 있어 `i & -i` 결과가 C++과 같다 | 부호 있는 정수의 비트 표현은 C++20부터 2의 보수가 표준이지만, C++17에서도 g++ 등 실제 컴파일러는 전부 2의 보수를 쓴다. 여기서 다루는 `i`는 항상 양수라 문제되지 않는다 |
| 합의 자료형 | 정수 오버플로가 없다 | 원소 값과 개수가 크면 `int` 합이 넘친다. `long long`을 쓴다 |
| 인덱스 시작 | `range(n+1)`로 0번 칸을 비워 둔다 | `vector<long long> tree(n+1, 0)`도 같은 이유로 크기를 `n+1`로 잡는다 |

::: pitfall
- **0-인덱스 배열을 그대로 쓰면 무한 루프에 빠진다.** `i=0`일 때 `i & -i`는 0이라 `update`가 절대 끝나지 않는다. 펜윅 트리는 반드시 1-인덱스로 쓴다.
- **펜윅 트리는 "더하기"가 기본이다.** "이 값을 X로 바꿔라"는 갱신이 필요하면 이전 값을 따로 배열에 저장해 두고 `delta = X - old`를 넣어야 한다. `update(i, X)`를 그대로 호출하면 값이 계속 쌓인다.
- **`range_sum(l, r)`에서 `prefix(l-1)`을 빠뜨리면** 구간 합이 아니라 그냥 프리픽스 합이 나온다. $l=1$일 때 `prefix(0)`이 0을 반환하는지 확인하라 — 위 구현은 `i>0`일 때만 루프를 돌므로 자동으로 0이 나온다.
- **좌표 압축 없이 값 자체를 인덱스로 쓰면** 배열 크기가 값의 범위만큼 커진다. 값이 $10^9$까지 간다면 좌표를 순위로 압축한 뒤 펜윅 트리에 올려야 한다.
:::

## 5. 어디에 쓰이는가

**순위 집계 시스템이 실제로 이 구조를 쓴다.** 점수가 실시간으로 바뀌는 리더보드에서 "이 점수보다 낮은 참가자가 몇 명인가"(순위) 또는 "$k$번째로 높은 점수는 얼마인가"를 자주 물어야 할 때, 점수를 구간으로 나눠 각 구간에 몇 명이 있는지를 펜윅 트리로 관리한다. 점수 하나가 바뀔 때마다 옛 구간에서 빼고 새 구간에 더하는 것이 갱신이고, "이 값 이하가 몇 명인가"가 프리픽스 합 질의다. 두 연산 모두 세그먼트 트리를 통째로 세울 필요 없이, 배열 하나와 `i & -i`만으로 끝난다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "특정 위치의 값을 바꾼다"와 "구간의 합을 구하라"는 질의가 섞여서 온다. "1번부터 $k$번까지의 합", "이 값보다 작은 원소의 개수"
- 제약조건: $N, Q \le 10^5 \sim 10^6$([0-9](#/0-9)). 연산이 **역원을 가져야** 한다 — 합, XOR, 곱(0이 없다면). 좌표 압축을 곁들이면 값의 범위가 커도 된다
- 혼동 주의: 구간 최솟값·최댓값이면 역원이 없으므로 [IX-2 세그먼트 트리](#/ix-2)로 가야 한다. 갱신이 전혀 없이 정적인 배열이면 펜윅 트리도 과하다 — 그냥 프리픽스 합 배열이면 충분하다
- 반례 함정: "구간 갱신 + 구간 질의"(둘 다 range)는 펜윅 트리 하나로 안 된다. 차분 배열과 펜윅 트리를 결합하면 "구간 갱신 + 점 질의"까지는 되지만, "구간 갱신 + 구간 질의"를 펜윅 트리로 하려면 트리를 두 개 겹쳐야 해서 세그먼트 트리의 lazy propagation보다 이해하기 번거로워진다. 이 경우는 처음부터 세그먼트 트리로 가는 편이 낫다
:::

::: interview
**"세그먼트 트리와 펜윅 트리의 차이는?"**
"세그먼트 트리는 임의의 결합 연산(최솟값, 최댓값, 합, gcd 등)을 다루는 범용 구조이고, 명시적인 이진 트리를 배열에 얹는다. 펜윅 트리는 합처럼 역원이 있는 연산만 다루는 대신, 트리 구조를 인덱스의 이진 표현에 숨겨서 배열 하나로 구현이 끝난다. 코드가 짧고 상수가 작지만 최솟값·최댓값 같은 질의에는 쓸 수 없다."
:::

## 연습

::: quiz
**1. 백준 2042 구간 합 구하기 (골드 1)** — https://www.acmicpc.net/problem/2042
- 신호: "1번째 수부터 b번째 수까지 합을 구하라"와 "a번째 수를 b로 바꾼다"가 섞여서 온다. 점 갱신 + 구간 합의 원형이다.
- 상태: 배열 `tree[1..n]`. 인덱스 자체가 "이 위치가 어느 담당 구간에 속하는가"를 이미 표현한다.
- 왜 이 자료구조인가: $N \le 10^6$, 질의·갱신 합쳐 $2\times10^4$번. 프리픽스 합 배열은 갱신마다 $O(n)$이라 못 버틴다. 세그먼트 트리도 되지만 펜윅 트리가 더 짧고 빠르다.

**2. 백준 1517 버블 소트 (플래티넘 5)** — https://www.acmicpc.net/problem/1517
- 신호: "버블 소트를 할 때 Swap이 몇 번 일어나는가"를 묻는다. 버블 정렬을 그대로 돌리면 $O(n^2)$이라 $n \le 5\times10^5$에서 터진다.
- 상태: Swap 횟수는 수열의 **역순 쌍(inversion)** 개수와 같다. 왼쪽에서 오른쪽으로 훑으며, 지금 원소보다 **먼저 나왔지만 값이 더 큰** 원소의 개수를 세야 한다.
- 왜 이 자료구조인가: 좌표 압축한 값을 인덱스로 삼아 "지금까지 등장한 값 중 이 값보다 큰 것이 몇 개인가"를 펜윅 트리의 구간 합(프리픽스 합의 여집합)으로 센다. 합만 필요하지 순서를 바꾸는 연산은 없어서 펜윅 트리가 맞는다.

**3. 백준 2517 달리기 (골드~플래티넘)** — https://www.acmicpc.net/problem/2517
- 신호: "자신보다 평소 실력이 좋은 선수는 추월할 수 없다"는 조건 아래, 각 선수가 앞지를 수 있는 최대 인원을 구한다.
- 상태: 실력을 좌표 압축한 뒤, 각 선수 앞에 "그 선수보다 실력이 낮은" 선수가 몇 명 있었는지를 센다. 사례 2의 역순 쌍 세기와 같은 골격이다.
- 왜 이 자료구조인가: 선수를 실력 순으로(또는 등장 순으로) 훑으며 프리픽스 합을 갱신·질의하는 패턴이 그대로 들어맞는다. 최솟값이 아니라 "개수"이므로 합의 역원 성질이 성립한다.
:::

## 요약

- 세그먼트 트리는 임의의 결합 연산을 다루는 범용 구조이고, 펜윅 트리는 **합·XOR처럼 역원이 있는 연산만** 다루는 대신 트리를 인덱스의 이진 표현에 숨긴다.
- `i & -i`(lowbit)는 인덱스 $i$가 담당하는 구간의 길이다. `tree[i]`는 $(i-\text{lowbit}(i),\, i]$ 구간의 합을 들고 있다.
- 갱신은 `i += i & -i`로 올라가며 이 인덱스를 포함하는 모든 담당 구간을 고친다. 질의는 `i -= i & -i`로 내려가며 겹치지 않는 담당 구간들을 모아 프리픽스 합을 만든다.
- 최솟값·최댓값이 안 되는 이유는 뺄셈에 대응하는 역연산이 없어서다. 프리픽스 두 개의 차로 구간을 복원할 수 없고, 갱신을 되돌릴 방법도 없다.
- 같은 일(점 갱신 + 구간 합)을 시키면 펜윅 트리가 세그먼트 트리보다 코드가 절반 이하로 짧고 실측 속도도 두 배 이상 빠르다(`tools/bench/ix3_fenwick.py`).
- 1-인덱스가 강제된다. 0번 인덱스에서 `i & -i`가 0이라 무한 루프에 빠진다.
- 구간 최솟값이거나 구간 갱신 + 구간 질의가 함께 필요하면 [IX-2 세그먼트 트리](#/ix-2)로 돌아가야 한다.
