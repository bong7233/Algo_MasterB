# V-11 할당 문제

::: lead
경로를 다 구한 다음에도 남는 질문 — 누가 어디로 갈 것인가.
:::

## 1. 문제

물류창고에 AGV 두 대가 있고 픽업 요청 두 건이 동시에 들어왔다. 각 차량이 각 요청 지점까지 가는 데 드는 비용은 이미 안다. [V-1 다익스트라](#/v-1)를 차량 수만큼 돌렸거나 [V-3 플로이드-워셜](#/v-3)로 모든 쌍 거리를 미리 깔아 뒀기 때문이다. 값은 이렇다(단위 초).

|  | P1 | P2 |
|---|---|---|
| **A** | 10 | 12 |
| **B** | 11 | **40** |

B에서 P2로 가는 길만 유독 비싸다. 그 구간에 컨베이어가 지나가 우회로밖에 없기 때문이고, 그 사실은 최단경로 계산 결과에 이미 40이라는 숫자로 들어와 있다.

이제 배차한다. 가장 자연스러운 규칙은 **요청마다 가장 가까운 유휴 차량을 붙이는 것**이다. P1을 먼저 처리하면 A가 10으로 가장 가깝다. A를 보낸다. P2에는 B만 남았으니 B가 간다. 40이다. **합계 50초, 마지막 작업이 끝나는 시각 40초.**

규칙을 바꿔서 "전체에서 가장 싼 조합부터 확정"으로 해도 같다. 표에서 가장 작은 값이 10(A-P1)이므로 그것부터 잡히고, 나머지는 자동으로 B-P2가 된다. 역시 50이다.

정답은 다른 곳에 있다.

|  | 배정 | 합계 | 최대 |
|---|---|---|---|
| 탐욕 | A→P1(10), B→P2(40) | 50 | 40 |
| **최적** | A→P2(12), B→P1(11) | **23** | **12** |

합계가 **2.17배** 차이 나고, 마지막 작업 완료 시각은 **3.3배** 차이 난다. A를 2초 더 먼 곳으로 보내는 대신 B가 29초를 아꼈다.

무엇이 잘못됐는지는 분명하다. 탐욕은 A-P1이 10이라는 것만 보고 확정했고, **그 확정이 B에게 무엇을 남기는지는 보지 않았다.** P2에 갈 수 있는 차량은 사실상 A뿐이었다. 희소한 자원을 흔한 용도에 먼저 써 버린 것이다.

==이것은 최단경로 문제가 아니다.== 각 칸의 값은 이미 최단경로다. 남은 질문은 **표에서 각 행과 각 열을 정확히 하나씩 골라 합을 최소로 만드는 것**이고, 이것을 할당 문제라고 한다. 경로를 아무리 잘 뽑아도 배차가 틀리면 전체 시스템은 두 배 느리다.

그러면 전부 시도하면 되지 않는가. n대 n건이면 경우의 수는 $n!$이다.

| n | $n!$ | 1억 회/초 기준 |
|---|---|---|
| 8 | 40,320 | 즉시 |
| 12 | 479,001,600 | 4.8초 |
| 15 | 1,307,674,368,000 | 3.6시간 |
| 20 | $2.4 \times 10^{18}$ | 771년 |

차량 20대는 중형 창고의 평범한 규모다. 그리고 배차는 **작업이 들어올 때마다** 다시 해야 한다. 완전탐색은 시작도 못 한다.

## 2. 아이디어

### 2.1 행렬 하나로 줄이기

n대의 로봇과 n건의 작업, 그리고 $n \times n$ 비용 행렬 `a[i][j]`. 이 구조를 그림으로 두면 이렇다.

```text nolines
   R1 ──── 7 ────▶ T1
   R1 ──── 4 ────▶ T2       <- 로봇마다 작업마다 간선이 하나씩
   R1 ──── 9 ────▶ T3
   R2 ──── 6 ────▶ T1
    :                       <- 양쪽을 정확히 하나씩 짝지어야 한다
```

한쪽 집합의 정점과 다른 쪽 집합의 정점을 짝짓는 그래프를 이분 그래프라 하고([IV-7](#/iv-7)), 겹치지 않는 짝짓기를 매칭이라 한다. 할당 문제는 **비용이 붙은 이분 그래프에서 최소 비용 완전 매칭**이다. 가중치가 없는 순수 이분 매칭은 [IX-8 네트워크 플로우 입문](#/ix-8)에 있고, 여기는 거기에 비용이 붙은 판이다.

### 2.2 상수를 빼도 답은 그대로다

핵심은 한 줄이다.

> **어떤 한 행 전체에서 같은 상수 c를 빼면, 모든 완전 할당의 비용이 정확히 c만큼 줄어든다.**

이유가 간단하다. 완전 할당은 각 행에서 정확히 한 칸을 쓴다. i행에서 어떤 칸을 골랐든 그 칸은 c만큼 작아졌으므로 총합도 c만큼 작아진다. **모든 할당이 똑같이 줄었으니 순위가 안 바뀐다.** 열에 대해서도 같다. 각 열에서도 정확히 한 칸씩 쓰기 때문이다.

그래서 다음이 성립한다.

- 원래 행렬에서 최적인 할당은 축소된 행렬에서도 최적이다.
- 축소를 아무리 반복해도 최적 할당은 안 변한다.
- 축소된 행렬의 모든 칸을 **0 이상**으로 유지하면, ==비용이 0인 칸만으로 완전 할당이 만들어지는 순간 그것이 최적이다.== 총합이 0이고 더 낮을 수 없기 때문이다.

이것이 헝가리안 알고리즘의 전부다. **0인 칸만으로 완전 매칭이 될 때까지 행과 열에서 상수를 뺀다.**

### 2.3 0이 모자랄 때

행 축소와 열 축소를 한 번씩 하면 각 행과 각 열에 0이 최소 하나씩 생긴다. 그래도 0만으로 완전 매칭이 안 될 수 있다. 0이 몇 개 열에 몰려 있으면 그렇다.

이때는 **0을 전부 덮는 최소 개수의 가로·세로 선**을 긋는다. 선의 개수가 매칭의 최대 크기와 같다는 사실이 쾨니그 정리이고, 그 개수가 n보다 작다는 것이 곧 "아직 완전 매칭이 아니다"라는 뜻이다.

그다음 조정이 이 알고리즘에서 가장 볼 만한 부분이다. 선에 안 덮인 칸 중 최솟값을 δ라 하면,

```text nolines
   uncovered      -= delta      <- 안 덮인 칸: 새 0 이 생긴다
   covered once    unchanged    <- 한 번 덮인 칸: 그대로
   covered twice  += delta      <- 두 번 덮인 칸: 되돌려 준다
```

이 조작은 "덮이지 않은 행들에서 δ를 빼고, 덮인 열들에 δ를 더한다"와 같다. 행과 열에 상수를 더하고 빼는 것뿐이므로 **2.2에 의해 최적 할당은 그대로**이고, 안 덮인 칸에는 새 0이 생긴다. 최솟값을 골랐으므로 음수가 되는 칸도 없다.

**선의 개수는 이 조정을 반복할 때마다 반드시 하나 이상 늘어난다.** n이 되면 끝난다. 그래서 이 절차는 유한하다.

::: note
구현에서는 선을 직접 긋지 않는다. `u[i]`와 `v[j]`라는 값을 두고 "지금까지 i행과 j열에서 뺀 상수의 누계"를 기록한다. 그러면 축소된 비용은 `a[i][j] - u[i] - v[j]`로 언제든 계산되고, 행렬을 실제로 고쳐 쓸 필요가 없다. 이 두 배열을 쌍대 변수 또는 잠재값이라 부른다. §4의 코드에 그대로 나온다.
:::

## 3. 손으로 따라가기

::: trace
로봇 3대, 작업 3건. 비용 행렬은 이것이다.

```text nolines
        T1   T2   T3
   R1    7    4    9
   R2    6    8    5
   R3    9    5    7
```

절차: **① 행 축소**(각 행에서 그 행의 최솟값을 뺀다) → **② 열 축소**(각 열에서 그 열의 최솟값을 뺀다) → **③ 0인 칸만으로 매칭을 최대한 만든다** → ④ 크기가 3이 아니면 최소 선으로 0을 덮고 조정한다.

| 단계 | 1행 | 2행 | 3행 | 비고 |
|---|---|---|---|---|
| 원본 | 7 4 9 | 6 8 5 | 9 5 7 | |
| ① 행 축소 (뺀 값 4, 5, 5) | 3 0 5 | 1 3 0 | 4 0 2 | 각 행에 0이 하나씩 |
| ② 열 축소 (뺀 값 ?, ?, ?) | | | | |
| ③ 0만으로 만든 최대 매칭 | | | | 크기는? |
| ④ 조정 후 | | | | δ는? |
| 최종 할당 | | | | 총비용은? |

③에서 막히는 지점을 직접 보라. **R1과 R3의 0이 같은 열에 있다.**
:::

::: answer
| 단계 | 1행 | 2행 | 3행 | 비고 |
|---|---|---|---|---|
| 원본 | 7 4 9 | 6 8 5 | 9 5 7 | |
| ① 행 축소 (뺀 값 4, 5, 5) | 3 0 5 | 1 3 0 | 4 0 2 | 각 행에 0이 하나씩 |
| ② 열 축소 (뺀 값 1, 0, 0) | 2 0 5 | 0 3 0 | 3 0 2 | 1열에만 0이 없었다 |
| ③ 0만으로 만든 최대 매칭 | R1→T2 | R2→T1 | — | **크기 2.** R3의 0은 T2뿐인데 이미 찼다 |
| ④ 조정 후 (δ=2) | 0 0 3 | 0 5 0 | 1 0 0 | 새 0이 (R1,T1)과 (R3,T3)에 생겼다 |
| 최종 할당 | R1→T1 | R2→T3 | R3→T2 | 7 + 5 + 5 = **17** |

④의 계산을 확인하라. 선은 2열과 2행에 긋는다(0 네 개를 이 두 줄이 전부 덮는다). 안 덮인 칸은 (R1,T1)=2, (R1,T3)=5, (R3,T1)=3, (R3,T3)=2이고 그중 최솟값 δ=2다. 안 덮인 네 칸에서 2를 빼고, 두 번 덮인 (R2,T2)=3에 2를 더해 5로 만든다. 한 번만 덮인 칸은 손대지 않는다.

**탐욕으로 풀면 어떻게 되는지도 같이 보라.** 가장 싼 칸은 (R1,T2)=4다. 확정. 남은 것 중 가장 싼 것은 (R2,T3)=5. 확정. 마지막은 (R3,T1)=9밖에 없다. **4 + 5 + 9 = 18.** 최적보다 1 크다. 실패의 모양이 §1과 똑같다 — R3에게 남은 선택지를 보지 않고 R1이 T2를 가져갔다.
:::

## 4. 구현

행렬을 실제로 고쳐 쓰는 대신 잠재값 `u`, `v`를 옮긴다. 행을 하나씩 추가하면서 **매번 증가 경로를 하나 찾는** 형태이고, 이 구조 덕에 $O(n^3)$이 된다.

::: dual
```python title="탐욕적 할당과 헝가리안"
INF = float("inf")


def greedy(a):
    """남은 칸 중 가장 싼 것부터 확정한다. 한 번 정한 것은 되돌리지 않는다."""
    n = len(a)
    rows, cols = set(range(n)), set(range(n))
    assign = [-1] * n
    while rows:
        cost, i, j = min((a[i][j], i, j) for i in rows for j in cols)
        assign[i] = j
        rows.discard(i)
        cols.discard(j)
    return sum(a[i][assign[i]] for i in range(n)), assign


def hungarian(a):
    """최소 비용 완전 할당. u[i], v[j] 가 i 행·j 열에서 뺀 상수의 누계다."""
    n = len(a)
    u = [0] * (n + 1)          # 행 잠재값
    v = [0] * (n + 1)          # 열 잠재값
    p = [0] * (n + 1)          # p[j] = j 열에 배정된 행. 0 이면 비어 있다
    way = [0] * (n + 1)        # 증가 경로 복원용 — 각 열에 직전 열을 적어 둔다
    for i in range(1, n + 1):  # 행을 하나씩 추가하며 매번 증가 경로를 하나 찾는다
        p[0] = i
        j0 = 0
        minv = [INF] * (n + 1)
        used = [False] * (n + 1)
        while True:
            used[j0] = True
            i0, delta, j1 = p[j0], INF, 0
            for j in range(1, n + 1):          # 축소 비용이 가장 작은 열을 고른다
                if used[j]:
                    continue
                cur = a[i0 - 1][j - 1] - u[i0] - v[j]
                if cur < minv[j]:
                    minv[j], way[j] = cur, j0
                if minv[j] < delta:
                    delta, j1 = minv[j], j
            for j in range(n + 1):             # 잠재값을 delta 만큼 옮긴다 = 행·열에서 상수를 뺀다
                if used[j]:
                    u[p[j]] += delta
                    v[j] -= delta
                else:
                    minv[j] -= delta
            j0 = j1
            if p[j0] == 0:                     # 빈 열에 닿았다 = 증가 경로 완성
                break
        while j0:                              # 경로를 거꾸로 따라가며 배정을 한 칸씩 민다
            j1 = way[j0]
            p[j0] = p[j1]
            j0 = j1
    assign = [0] * n
    for j in range(1, n + 1):
        assign[p[j] - 1] = j - 1
    return sum(a[i][assign[i]] for i in range(n)), assign


cost = [[7, 4, 9],
        [6, 8, 5],
        [9, 5, 7]]
g_total, g_assign = greedy(cost)
h_total, h_assign = hungarian(cost)
print("greedy    =", g_total, g_assign)
print("hungarian =", h_total, h_assign)
```
```cpp title="탐욕적 할당과 헝가리안"
#include <algorithm>
#include <iostream>
#include <set>
#include <vector>
using namespace std;

const int INF = 1000000000;

pair<int, vector<int>> greedy(const vector<vector<int>>& a) {
    int n = a.size();
    set<int> rows, cols;
    for (int i = 0; i < n; i++) { rows.insert(i); cols.insert(i); }
    vector<int> assign(n, -1);
    while (!rows.empty()) {
        int cost = INF, bi = -1, bj = -1;
        for (int i : rows)
            for (int j : cols)
                if (a[i][j] < cost) { cost = a[i][j]; bi = i; bj = j; }
        assign[bi] = bj;
        rows.erase(bi);
        cols.erase(bj);
    }
    int total = 0;
    for (int i = 0; i < n; i++) total += a[i][assign[i]];
    return {total, assign};
}

pair<int, vector<int>> hungarian(const vector<vector<int>>& a) {
    int n = a.size();
    vector<int> u(n + 1, 0), v(n + 1, 0), p(n + 1, 0), way(n + 1, 0);
    for (int i = 1; i <= n; i++) {      // 행을 하나씩 추가하며 매번 증가 경로를 하나 찾는다
        p[0] = i;
        int j0 = 0;
        vector<int> minv(n + 1, INF);
        vector<char> used(n + 1, false);
        while (true) {
            used[j0] = true;
            int i0 = p[j0], delta = INF, j1 = 0;
            for (int j = 1; j <= n; j++) {          // 축소 비용이 가장 작은 열을 고른다
                if (used[j]) continue;
                int cur = a[i0 - 1][j - 1] - u[i0] - v[j];
                if (cur < minv[j]) { minv[j] = cur; way[j] = j0; }
                if (minv[j] < delta) { delta = minv[j]; j1 = j; }
            }
            for (int j = 0; j <= n; j++) {          // 잠재값을 delta 만큼 옮긴다
                if (used[j]) { u[p[j]] += delta; v[j] -= delta; }
                else minv[j] -= delta;
            }
            j0 = j1;
            if (p[j0] == 0) break;                  // 빈 열에 닿았다 = 증가 경로 완성
        }
        while (j0) {                                // 경로를 거꾸로 따라가며 배정을 민다
            int j1 = way[j0];
            p[j0] = p[j1];
            j0 = j1;
        }
    }
    vector<int> assign(n, 0);
    for (int j = 1; j <= n; j++) assign[p[j] - 1] = j - 1;
    int total = 0;
    for (int i = 0; i < n; i++) total += a[i][assign[i]];
    return {total, assign};
}

int main() {
    vector<vector<int>> cost = {{7, 4, 9},
                                {6, 8, 5},
                                {9, 5, 7}};
    auto [g_total, g_assign] = greedy(cost);
    auto [h_total, h_assign] = hungarian(cost);
    cout << "greedy    = " << g_total << " [";
    for (int i = 0; i < 3; i++) cout << g_assign[i] << (i < 2 ? ", " : "]\n");
    cout << "hungarian = " << h_total << " [";
    for (int i = 0; i < 3; i++) cout << h_assign[i] << (i < 2 ? ", " : "]\n");
    return 0;
}
```

```console
greedy    = 18 [1, 2, 0]
hungarian = 17 [0, 2, 1]
```

§3에서 손으로 낸 17과 18이 그대로 나온다. 배정 `[0, 2, 1]`은 R1→T1, R2→T3, R3→T2다.

**복잡도:** 시간 $O(n^3)$ — 바깥 루프가 행마다 한 번씩 총 n회 돌고, 한 번의 증가 경로 탐색이 최대 n개 열을 확정하며, 열 하나를 확정할 때마다 남은 열 전체를 훑어 최솟값을 갱신하므로 $n \times n \times n$이다. 공간 $O(n^2)$ — 비용 행렬이 지배하고 나머지 배열은 전부 $O(n)$이다. 탐욕은 시간 $O(n^3)$(매번 남은 칸 전체를 훑는다)에 답이 더 나쁘다. **더 비싸면서 더 틀린다.**

무작위 비용 행렬로 둘을 붙여 본 결과가 이렇다(`tools/bench/v11_hungarian_vs_greedy.py`).

| 크기 | 시행 | 헝가리안 ≤ 탐욕 | 탐욕이 더 비쌌던 비율 | 그때 초과 비용 평균 |
|---|---|---|---|---|
| 5×5 | 200회 | 항상 성립 | 70.5% | +29.9% |
| 8×8 | 200회 | 항상 성립 | 87.5% | +33.6% |

> (Linux x86-64 / CPython 3.13 실측. 비용은 1~99 균등 난수. 절대값은 난수에 따라 다르지만 방향은 어디서나 같다.)

**크기가 커질수록 탐욕이 지는 빈도가 올라간다.** 로봇이 많아질수록 "희소한 자원을 흔한 용도에 먼저 써 버릴" 기회가 늘기 때문이다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 무한대 | `float("inf")`. 정수와 섞여도 비교는 된다 | `INT_MAX`는 `+delta`에서 오버플로한다. $10^9$을 쓴다 |
| 집합에서 최솟값 | `min(...)`이 튜플 비교로 동점까지 결정한다 | 직접 루프. 첫 최솟값이 남도록 `<`를 쓴다 |
| 다중 반환 | 튜플 | `pair`/`struct` + 구조적 바인딩(C++17) |
| `bool` 벡터 | `[False] * n` | `vector<char>`. `vector<bool>`은 비트 압축이라 느리다 |

::: pitfall
- **정사각이 아닌 경우.** 로봇 5대에 작업 3건이면 남는 열을 비용 0(또는 아주 큰 값)으로 채워 정사각으로 만든다. 0으로 채우면 "아무 일도 안 하는" 배정이고, 큰 값으로 채우면 "가능하면 놀지 마라"가 된다. **둘은 다른 문제다.** 무엇을 원하는지 정하고 채워라.
- **합의 최소와 최대의 최소는 다르다.** 헝가리안이 최소화하는 것은 **합**이다. §1의 표에서 합 23이 최대 12와 우연히 같이 갔을 뿐이다. "마지막 작업이 끝나는 시각"을 줄이려면 목적함수가 바뀌고, 그것은 이분 탐색으로 상한 T를 두고 "비용 ≤ T인 간선만으로 완전 매칭이 되는가"를 묻는 병목 할당 문제가 된다([VII-3](#/vii-3), [IX-8](#/ix-8)).
- **도달 불가능한 칸을 0으로 두는 것.** 갈 수 없는 조합은 0이 아니라 아주 큰 값이다. 0으로 두면 알고리즘이 가장 좋아하는 칸이 된다.
- **큰 값으로 `INF`를 쓰는 것.** `a[i][j] - u[i] - v[j]` 계산에 섞이므로 실제 비용의 합보다 크되 오버플로하지 않는 값이어야 한다.
:::

## 5. 중앙 조정자가 없을 때 — auction

헝가리안에는 약점이 하나 있다. **행렬 전체를 한 곳에서 봐야 한다.** 로봇 200대가 각자 통신하는 시스템에서 매 초 $200 \times 200$ 행렬을 한 노드에 모으는 것은 그 자체가 병목이고, 그 노드가 죽으면 배차가 멈춘다.

경매(auction) 알고리즘은 같은 문제를 반대로 푼다. 각 작업에 **가격**을 붙인다. 로봇은 자기 행만 보고 `비용 + 가격`이 가장 싼 작업을 고르고, 그 작업의 가격을 **2등과의 차이만큼** 올려 낙찰받는다. 쥐고 있던 로봇은 쫓겨나 다시 입찰한다. 인기 있는 작업의 가격이 올라가면서 수요가 흩어진다.

문제는 두 로봇이 같은 작업을 놓고 가격을 0씩 올리며 무한히 주고받을 수 있다는 것이다. 그래서 매 입찰에 **최소 인상폭 ε**을 강제한다. 그 대가로 최적성을 잃는다. ε-상보 여유 조건에서 나오는 보장은 이것이다.

> 최종 비용 ≤ 최적 비용 + $n \varepsilon$

::: dual
```python title="경매 알고리즘 — eps 를 키우면 무엇을 잃는가"
INF = float("inf")


def auction(a, eps):
    """행이 입찰하고 열의 가격이 오른다. 전역 행렬을 보는 주체가 없다."""
    n = len(a)
    price = [0.0] * n          # 열마다 붙은 가격. 인기 있는 열이 비싸진다
    owner = [-1] * n           # owner[j] = 지금 j 열을 쥔 행
    assign = [-1] * n
    free_rows = list(range(n))  # 아직 아무 열도 못 쥔 행들
    bids = 0
    while free_rows:
        i = free_rows.pop()
        best, second, bj = INF, INF, -1
        for j in range(n):                  # 각 행은 자기 행만 본다 — 전역 정보가 필요 없다
            val = a[i][j] + price[j]
            if val < best:
                second, best, bj = best, val, j
            elif val < second:
                second = val
        price[bj] += (second - best) + eps   # 2등과의 차이만큼 더 낸다. eps 가 없으면 안 끝난다
        if owner[bj] != -1:                  # 쥐고 있던 행은 쫓겨나 다시 입찰한다
            assign[owner[bj]] = -1
            free_rows.append(owner[bj])
        owner[bj], assign[i] = i, bj
        bids += 1
    return sum(a[i][assign[i]] for i in range(n)), bids, assign


cost = [[6, 20, 4, 16],
        [2, 7, 10, 5],
        [8, 13, 13, 16],
        [3, 6, 15, 13]]
for eps in (0.2, 1.0, 2.0, 5.0):
    total, bids, assign = auction(cost, eps)
    print(f"eps={eps:.1f}  total={total}  bids={bids}  assign={assign}")
```
```cpp title="경매 알고리즘 — eps 를 키우면 무엇을 잃는가"
#include <cstdio>
#include <vector>
using namespace std;

const double INF = 1e18;

struct Result { int total, bids; vector<int> assign; };

Result auction(const vector<vector<int>>& a, double eps) {
    int n = a.size();
    vector<double> price(n, 0.0);      // 열마다 붙은 가격. 인기 있는 열이 비싸진다
    vector<int> owner(n, -1);          // owner[j] = 지금 j 열을 쥔 행
    vector<int> assign(n, -1), free_rows;
    for (int i = 0; i < n; i++) free_rows.push_back(i);
    int bids = 0;
    while (!free_rows.empty()) {
        int i = free_rows.back();
        free_rows.pop_back();
        double best = INF, second = INF;
        int bj = -1;
        for (int j = 0; j < n; j++) {       // 각 행은 자기 행만 본다
            double val = a[i][j] + price[j];
            if (val < best) { second = best; best = val; bj = j; }
            else if (val < second) second = val;
        }
        price[bj] += (second - best) + eps;  // eps 가 없으면 안 끝난다
        if (owner[bj] != -1) {               // 쥐고 있던 행은 쫓겨나 다시 입찰한다
            assign[owner[bj]] = -1;
            free_rows.push_back(owner[bj]);
        }
        owner[bj] = i;
        assign[i] = bj;
        bids++;
    }
    int total = 0;
    for (int i = 0; i < n; i++) total += a[i][assign[i]];
    return {total, bids, assign};
}

int main() {
    vector<vector<int>> cost = {{6, 20, 4, 16},
                                {2, 7, 10, 5},
                                {8, 13, 13, 16},
                                {3, 6, 15, 13}};
    for (double eps : {0.2, 1.0, 2.0, 5.0}) {
        Result r = auction(cost, eps);
        printf("eps=%.1f  total=%d  bids=%d  assign=[%d, %d, %d, %d]\n",
               eps, r.total, r.bids, r.assign[0], r.assign[1], r.assign[2], r.assign[3]);
    }
    return 0;
}
```

eps=1.0  total=23  bids=5  assign=[2, 3, 0, 1]
eps=2.0  total=23  bids=5  assign=[2, 3, 0, 1]
eps=5.0  total=25  bids=4  assign=[2, 3, 1, 0]

**복잡도:** 시간은 $O(n^2 \cdot C / \varepsilon)$ 꼴이다 — 입찰 한 번이 자기 행 n칸을 훑어 $O(n)$이고, 가격은 매 입찰마다 최소 ε씩 오르되 최대 비용폭 C를 넘으면 아무도 그 열에 입찰하지 않으므로 전체 입찰 횟수가 $n C / \varepsilon$으로 묶인다. **ε가 복잡도에 직접 들어간다.** 공간 $O(n^2)$ — 비용 행렬 외에는 가격·소유자 배열 $O(n)$뿐이다.

이 출력이 ε의 정체를 그대로 보여 준다. 최적은 23이고, ε가 2.0까지는 최적을 찾는다. ε=5.0에서 입찰이 5회에서 4회로 줄고 답은 25가 된다. **빨라진 만큼 나빠졌다.** 보장은 $23 + 4 \times 5 = 43$ 이하이고 실제 25는 그보다 훨씬 좋다 — 이 상한은 느슨하다.

::: tip
비용이 전부 정수이면 $\varepsilon < 1/n$일 때 결과가 **정확히 최적**이 된다. 정수 비용의 서로 다른 두 할당은 최소 1만큼 차이 나는데 오차 상한이 $n\varepsilon < 1$이라 최적 아닌 답이 들어올 자리가 없다. 실무에서는 ε를 크게 시작해 점점 줄이는 ε-scaling으로 속도와 정확도를 같이 잡는다.
:::

경매가 헝가리안을 대체하는 것이 아니다. **행렬을 한 곳에 모을 수 있으면 헝가리안이 낫다.** 모을 수 없거나, 모으는 비용이 아까울 때, 또는 로봇이 계속 들어오고 나갈 때 경매가 산다. 입찰은 서로 독립이므로 병렬화되고, 로봇 하나가 통신에서 빠져도 나머지 입찰은 계속된다.

## 6. 어디에 쓰이는가

**다중 로봇 작업 배차가 첫 번째다.** 비용 행렬의 각 칸은 §1에서 본 대로 최단경로 거리이고, 그래서 이 챕터가 Part V에 있다. 배차 주기마다 최단경로 계산 → 비용 행렬 → 헝가리안 → 각 로봇에 목표 지정 → [V-8 시공간 A\*](#/v-8)로 충돌 없는 경로 생성이 한 파이프라인으로 붙는다.

**차량 호출 서비스의 기사-호출 매칭이 같은 문제다.** 행이 기사, 열이 호출이고 칸은 예상 도착 시간이다. 가장 가까운 기사에게 배정하는 탐욕이 전체 대기 시간을 어떻게 망가뜨리는지가 §1의 표 그대로다. 규모가 커서 지역별로 쪼개 풀거나 경매 계열을 쓴다.

**다중 표적 추적의 데이터 연관도 할당 문제다.** 이번 프레임에서 검출된 물체 m개를 지난 프레임까지 추적하던 표적 n개 중 무엇에 이어 붙일 것인가. 비용은 예측 위치와 검출 위치의 거리이고, 여기서 탐욕을 쓰면 두 물체가 교차할 때 ID가 서로 바뀐다. 예측을 만드는 필터는 [XIII-3 칼만 필터와 EKF](#/xiii-3)에, 그 필터를 여러 개 돌리는 구조는 [XIII-4 파티클 필터](#/xiii-4)에 있다.

**작업 스케줄링에서도 같은 행렬이 나온다.** 행이 워커, 열이 태스크, 칸이 예상 처리 시간이다. 다만 워커 하나가 여러 태스크를 받는 순간 이것은 할당 문제가 아니라 스케줄링 문제가 되고 답이 달라진다([XI-4](#/xi-4)).

## 7. 이 유형을 알아보는 법

::: classify
- 신호어: "각 로봇에 작업을 하나씩", "겹치지 않게 짝지어", "전체 이동 거리를 최소로", "한 사람이 한 건만 맡는다"
- 제약조건: 양쪽이 **일대일**이고, 비용이 각 쌍마다 독립으로 정해진다. $n \le 1000$ 이면 $O(n^3)$이 든다($10^9$은 C++에서 수 초). 그 위는 분할하거나 경매로 간다
- 혼동 주의: 한쪽이 여러 개를 맡을 수 있으면 할당 문제가 아니라 플로우 문제다([IX-8](#/ix-8)). 비용 없이 "짝지을 수 있는가"만 물으면 순수 이분 매칭이다. 합이 아니라 **가장 늦게 끝나는 것**을 최소화하면 병목 할당이고 이분 탐색이 붙는다([VII-3](#/vii-3))
- 반례 함정: 가장 가까운 것부터 붙이는 탐욕. 5×5 무작위 행렬에서 70.5%가 최적보다 나쁘고 평균 29.9% 비싸다. 그리고 **행렬이 정사각이 아닐 때** 남는 행을 0으로 채울지 큰 값으로 채울지가 문제의 의미를 바꾼다
:::

::: interview
**"가장 가까운 로봇에게 배정하면 되지 않나요?"** — 이 질문은 거의 항상 나온다. 답의 뼈대는 세 단계다. ① 반례를 즉석에서 만든다: 2×2로 `[[10, 12], [11, 40]]`이면 탐욕 50, 최적 23. ② 실패의 이유를 한 문장으로 말한다: 탐욕은 자기 선택이 남은 사람들에게 무엇을 남기는지 보지 않는다. ③ 대안과 비용을 말한다: $O(n^3)$ 헝가리안이면 n이 수백까지 실시간이고, 분산이 필요하면 경매로 최적성 일부를 ε만큼 판다. **반례를 숫자로 즉시 만들 수 있는가가 이 답변의 전부다.**
:::

## 연습

::: quiz
코드를 짜지 마라. 세 가지를 적어라. **① 무엇을 상태(행·열·비용)로 두는가 ② 왜 이 알고리즘인가 ③ 무엇을 포기하는가.**

**1. 충전 스테이션 배정**
- 상황: 배터리 잔량이 서로 다른 로봇 12대와 충전기 8대가 있다. 잔량이 20% 아래인 로봇이 5대, 그중 2대는 15% 아래다. 충전기까지의 거리는 제각각이다.
- 확인할 것: 행과 열의 개수가 다르다. 어떻게 정사각으로 만들 것인가. 그리고 **거리만으로 비용을 정하면 무슨 일이 생기는가** — 잔량 15%인 로봇이 먼 충전기로 밀려나면 도중에 멈춘다. 비용에 잔량을 어떻게 섞을 것인가.

**2. 교대 시간의 재배차**
- 상황: 작업이 진행 중인 상태에서 로봇 3대가 정비를 위해 빠진다. 남은 로봇에 작업을 다시 나눠야 하는데, 이미 절반쯤 이동한 로봇의 작업을 뺏으면 그 이동이 통째로 낭비된다.
- 확인할 것: 비용 행렬에 "이미 투입한 이동"을 어떻게 반영하는가. 매몰 비용을 그대로 더하면 안 되는 이유는 무엇인가. 전면 재계산과 [V-7 D\* Lite](#/v-7)식 부분 갱신 중 어느 쪽이 이 문제에 맞는가.

**3. 100대 규모의 분산 배차**
- 상황: 로봇 100대, 작업 100건. 중앙 서버가 있지만 로봇과의 통신이 초당 한 번뿐이고 가끔 끊긴다. 배차는 2초 안에 나와야 한다.
- 확인할 것: $100^3 = 10^6$이라 헝가리안 자체는 즉시 끝난다. **그럼에도 경매를 고려할 이유가 있는가** — 병목이 계산이 아니라 통신일 때 무엇이 달라지는가. ε를 어떻게 정하고, 그 선택으로 무엇을 잃는지 숫자로 말하라.
:::

## 요약

- 경로를 다 구한 뒤에 남는 질문이 **누가 어디로 가는가**다. 칸의 값이 이미 최단경로 거리이므로 이 챕터가 Part V에 있다.
- **가장 가까운 것부터 붙이는 탐욕은 무너진다.** `[[10, 12], [11, 40]]`에서 탐욕 50, 최적 23. 무작위 5×5에서 70.5%가 최적보다 나쁘고 평균 29.9% 비싸다.
- **한 행이나 한 열 전체에서 상수를 빼도 최적 할당은 안 바뀐다.** 모든 완전 할당이 똑같이 줄기 때문이다. 이 한 줄이 헝가리안의 전부다.
- 0인 칸만으로 완전 매칭이 만들어지면 그것이 최적이다. 안 되면 최소 선으로 0을 덮고 δ만큼 조정해 새 0을 만든다. 선의 개수는 반드시 늘어난다.
- 구현은 행렬을 고쳐 쓰지 않고 잠재값 `u`, `v`를 옮긴다. **시간 $O(n^3)$** — 행 n회 × 열 확정 n회 × 최솟값 갱신 n회.
- **경매**는 같은 문제를 가격으로 푼다. 행이 자기 행만 보므로 분산·병렬이 되고, 대가로 최적에서 $n\varepsilon$까지 벗어난다. 정수 비용에 $\varepsilon < 1/n$이면 정확히 최적이다.
- 합의 최소와 **가장 늦게 끝나는 시각**의 최소는 다른 문제다. 후자는 병목 할당이고 이분 탐색이 붙는다.
