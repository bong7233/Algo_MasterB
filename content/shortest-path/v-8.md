# V-8 시공간 A*와 예약 테이블

::: lead
지도는 그대로인데 다른 로봇이 움직인다. 상태에 시각 하나를 더하면 그 문제가 다시 최단경로 문제가 된다.
:::

## 1. 문제

창고에 AMR 두 대가 있다. A는 서쪽 통로를 따라 동쪽 적재장으로 가고, B는 북쪽에서 남쪽 충전소로 간다. 두 대 모두 [V-5 A*](#/v-5)로 자기 경로를 뽑는다. 두 경로는 각각 완벽하다. 벽을 넘지 않고, 최단이며, 휴리스틱까지 잘 먹었다.

그런데 4초 뒤 둘은 교차로 한복판에서 서로를 들이받는다.

A\*가 이 사고를 막지 못한 이유는 버그가 아니다. **A\*가 답하는 질문 자체가 다르다.** A\*는 "이 칸을 지나도 되는가"에 답한다. 여러 대가 도는 현장에서 필요한 답은 "이 칸을 **이 시각에** 지나도 되는가"다. 질문에 시각이 들어 있는데 상태에는 시각이 없다. 없는 것은 답할 수 없다.

가장 먼저 떠오르는 우회는 상대를 지도에 그려 넣는 것이다. B가 지나갈 칸을 전부 벽으로 찍고 A를 계획한다. 이것은 두 가지 이유로 무너진다.

**첫째, 통로가 영구히 사라진다.** 창고 통로는 대개 폭이 하나다. B의 경로가 통로를 한 번 지나가면 그 통로 전체가 벽이 되고, A에게는 갈 길이 없어진다. 실제로는 B가 3초 뒤에 빠져나가므로 A는 4초에 그 칸을 쓸 수 있다. **정적 지도는 "지금은 막혔지만 곧 열린다"를 표현하지 못한다.**

**둘째, 시간이 어긋난 충돌을 못 막는다.** 반대로 B의 경로를 벽으로 찍지 않으면, A가 B보다 먼저 그 칸을 밟는 경우는 걸러지지 않는다. 지도는 어떤 칸이 언제 비는지를 모른다.

지도를 고치는 방향은 여기서 끝이다. 고쳐야 하는 것은 지도가 아니라 **상태**다.

### 2.1 상태에 시각을 넣는다

[V-5](#/v-5)의 A\*에서 상태는 칸 하나였다. 여기서는 상태가 **`(칸, 시각)`** 이다. 바뀐 것은 그것뿐이고, 나머지 계보는 그대로 따라온다.

상태가 바뀌면 행동도 바뀐다. 상하좌우 네 이동에 **대기**가 추가된다. 제자리에 머무는 것은 공간에서는 아무 일도 아니지만 시간 축에서는 `(v, t)`에서 `(v, t+1)`로 가는 엄연한 이동이고, 비용 1이 붙는다. **다른 로봇을 피하는 유일한 수단이 이 대기다.** 대기가 없으면 시간 축을 넣어도 할 수 있는 일이 없다.

여기서 작은 선물이 딸려 온다. 모든 행동의 비용이 1이므로 **`g` 값이 곧 시각이다.** 상태의 두 번째 성분을 우선순위 계산에 그대로 쓸 수 있어서 `f = t + h`가 된다. 시간 축과 비용 축이 같은 축이다.

### 2.2 예약 테이블

여러 대를 한꺼번에 최적으로 푸는 것은 뒤로 미룬다([V-9](#/v-9)). 먼저 가장 단순한 방식을 본다. **순서를 정해 한 대씩 계획하고, 계획이 끝난 대의 경로를 표에 적어 둔다.**

그 표가 예약 테이블이다. 적는 것은 두 가지다.

```text nolines
   vertex : ((r, c), t)             "이 칸은 이 시각에 이미 임자가 있다"
   edge   : ((r1,c1), (r2,c2), t)   "이 이동은 이 시각에 하면 안 된다"
```

뒤에 계획하는 에이전트는 이 표를 **장애물처럼** 쓴다. 다른 점은 하나다. 벽은 모든 시각에 막혀 있고 예약은 특정 시각에만 막혀 있다. `(2,2)`가 `t=2`에 예약되어 있어도 `t=3`에는 비어 있다.

::: hist
예약 테이블이라는 자료구조는 Silver, 2005, *Cooperative Pathfinding* 에서 정리됐고, 순서를 정해 한 대씩 계획하는 발상 자체는 그보다 훨씬 앞선 Erdmann & Lozano-Pérez, 1987, *On Multiple Moving Objects* 로 거슬러 올라간다. **40년 가까이 살아남은 이유는 단순함이다** — 단일 에이전트 계획기 하나만 있으면 다중 에이전트 계획기가 된다.
:::

한 가지 함정이 있다. 도착한 로봇은 사라지지 않는다. **경로의 마지막 칸은 도착 시각부터 계획 지평 끝까지 전부 예약해야 한다.** 이것을 빠뜨리면 먼저 도착해 가만히 서 있는 로봇 위로 다음 로봇이 지나간다.

### 2.3 충돌은 두 종류다

::: warn
정점 충돌만 검사하는 구현이 흔하고, 그 구현은 **정확히 절반만 맞는다.**
:::

**정점 충돌(vertex conflict)** 은 두 에이전트가 같은 칸에 같은 시각에 있는 것이다. `(칸, 시각)` 쌍이 겹치는지 보면 잡힌다.

**맞바꿈 충돌(edge conflict, swap conflict)** 은 다르다. 인접한 두 에이전트가 서로의 칸으로 동시에 옮겨 가는 경우다.

```text nolines
   t = 1        t = 2
   . A B .      . B A .
       ^            ^
```

`t=1`에 A가 두 번째 칸, B가 세 번째 칸에 있고, `t=2`에 A가 세 번째, B가 두 번째로 간다. **어느 시각에도 두 로봇이 같은 칸에 있은 적이 없다.** 정점 검사는 이것을 통과시킨다. 그런데 물리적으로 둘은 서로를 관통했다.

그래서 예약 테이블에 이동도 적는다. A가 `u`에서 `v`로 가는 이동을 예약하면, 같은 시각에 **`v`에서 `u`로 가는 이동**이 금지된다. 방향이 반대인 짝 하나만 막으면 된다. `u`에서 `v`로 가는 이동을 둘이 동시에 하는 것은 애초에 정점 예약이 막는다 — 둘 다 `t`에 `u`에 있어야 하기 때문이다.

### 2.4 휴리스틱은 그대로 쓴다

시간 축이 생겼는데 맨해튼 거리를 그대로 써도 되는가. 된다. 그리고 이유가 중요하다.

휴리스틱이 admissible 하려면 **남은 실제 비용을 넘지 않아야** 한다([V-5](#/v-5)). 시간 축이 생기면서 늘어난 행동은 대기뿐이고, 대기는 목표까지의 거리를 **줄이지 않으면서** 비용을 1 더한다. 즉 새 행동은 실제 비용을 늘리기만 한다. 원래 비용을 넘지 않던 추정치는 늘어난 비용도 넘지 않는다. **admissible 은 공짜로 유지된다.** consistent 도 같은 논리로 유지된다. 대기 간선의 비용 1과 휴리스틱 변화량 0 사이에서 삼각부등식 `h(n) ≤ c(n, n') + h(n')`이 `h ≤ 1 + h`가 되어 성립한다.

::: note
휴리스틱이 시간을 전혀 모른다는 점은 약점이 아니라 설계다. 시간을 아는 휴리스틱, 예를 들어 "앞에 로봇이 있으니 두 스텝 더 걸릴 것"을 넣으면 추정이 실제를 넘을 위험이 생기고 최적성이 깨진다. 공간 거리는 **언제나 하한**이다.
:::

### 2.5 대가는 메모리다

상태가 `(칸, 시각)`이 되면 상태 공간이 계획 지평 `T`를 곱한 만큼 불어난다. 이것은 추상적인 걱정이 아니다.

> (Linux x86-64 / CPython 3.13 실측, 3회 실행의 중앙값. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/spacetime_state_growth.py` 다.)

820개였던 상태가 `T = 100`에서 58,630개, 메모리는 54KiB에서 12MB가 된다. **71배다.** `T`를 곱한 101배가 안 되는 이유는 시작점에서 `t`스텝 안에 닿을 수 있는 칸이 마름모꼴로 제한되기 때문이고, 격자가 작아질수록 곱셈에 가까워진다.

여기서 나오는 실무 규칙 하나. **`T`는 필요한 만큼만 잡는다.** 흔한 기준은 "혼자 갔을 때의 거리 + 여유"이고, 그 여유가 모자라면 해가 있는데도 못 찾는다.

## 3. 손으로 따라가기

::: trace
격자는 위 위젯과 같다. `#`은 벽이다.

```text nolines
   # # . # #
   # # . # #
   . . . . .
   # # . # #
   # # . # #
```

A는 `(2,0)`에서 `(2,4)`로 이미 계획을 끝냈다. A의 경로는 `(2,0) (2,1) (2,2) (2,3) (2,4)`이고, 예약 테이블에는 `(2,0)@0 (2,1)@1 (2,2)@2 (2,3)@3`과 도착 칸 `(2,4)@4` 이후 전부가 들어 있다.

이제 B를 계획한다. 시작 `(0,2)`, 목표 `(4,2)`. `f = t + h`이고 `h`는 맨해튼 거리다. 우선순위가 같으면 `t`가 작은 쪽, 그다음 칸 번호가 작은 쪽을 먼저 꺼낸다. 이웃은 대기·상하·좌우 순으로 본다.

| 스텝 | 꺼낸 상태 | f = t + h | 새로 연 상태 | 예약 때문에 버린 것 |
|---|---|---|---|---|
| 0 | (0,2)@0 | 4 | (0,2)@1 (1,2)@1 | - |
| 1 | (1,2)@1 | 4 | (1,2)@2 (0,2)@2 | (2,2)@2 |
| 2 | (0,2)@1 | 5 | | |
| 3 | | | | |
| 4 | | | | |
| 5 | | | | |
| 6 | | | | |

스텝 2에서 `(0,2)@1`은 이웃을 하나도 새로 열지 못한다. **왜 그런지가 이 표의 핵심이다.**
:::

::: answer
| 스텝 | 꺼낸 상태 | f = t + h | 새로 연 상태 | 예약 때문에 버린 것 |
|---|---|---|---|---|
| 0 | (0,2)@0 | 4 | (0,2)@1 (1,2)@1 | - |
| 1 | (1,2)@1 | 4 | (1,2)@2 (0,2)@2 | (2,2)@2 |
| 2 | (0,2)@1 | 5 | 없음 | - |
| 3 | (1,2)@2 | 5 | (1,2)@3 (0,2)@3 (2,2)@3 | - |
| 4 | (2,2)@3 | 5 | (2,2)@4 (1,2)@4 (3,2)@4 (2,1)@4 (2,3)@4 | - |
| 5 | (3,2)@4 | 5 | (3,2)@5 (2,2)@5 (4,2)@5 | - |
| 6 | (4,2)@5 | 5 | 목표 도달 | - |

B의 경로는 `(0,2) (1,2) (1,2) (2,2) (3,2) (4,2)`, 비용 5다. 두 번째와 세 번째가 같은 칸이다 — 그것이 대기다.

**스텝 2가 아무것도 열지 못한 이유:** `(0,2)@1`의 이웃은 `(0,2)@2`와 `(1,2)@2`인데 둘 다 스텝 1에서 이미 열렸다. 상태의 `g` 값이 곧 시각이므로 **같은 `(칸, 시각)`에 두 번째로 닿는 경로는 절대 더 싸지 않다.** 그래서 이미 연 상태는 다시 볼 필요가 없다. 다익스트라·A\*에서 닫힌 목록이 하던 역할을 여기서는 시각이 대신한다.

**스텝 1에서 버린 `(2,2)@2`가 사고를 막은 지점이다.** 예약이 없었다면 B는 `t=2`에 가운데로 내려가 A와 정면으로 만났을 것이다.

스텝 4에서 갑자기 다섯 개가 열리는 것도 볼 것. `t=3`에는 A가 이미 `(2,3)`으로 빠졌기 때문에 가운데 통로가 전부 비어 있다. **예약은 시각과 함께 사라진다.**
:::

## 4. 구현

세 장면을 한 번에 돌린다. ① 십자 교차로에서 우선순위 기반 계획이 대기 하나로 충돌을 푸는 장면, ② 맞바꿈 검사를 껐을 때 두 로봇이 서로를 통과해 버리는 장면, ③ 우선순위 기반 계획이 **해가 있는데도 못 찾는** 장면이다.

::: dual
```python title="시공간 A* — 예약 테이블과 우선순위 기반 계획"
from heapq import heappush, heappop

# 대기가 첫 번째다 — 시간 축이 생기는 순간 제자리에 머무는 것도 비용 1짜리 행동이 된다.
MOVES = [(0, 0), (-1, 0), (1, 0), (0, -1), (0, 1)]
HORIZON = 20                       # 시간 축의 상한. 상태 공간이 이 배수만큼 불어난다
NAME = "AB"


def walkable(grid, cell):
    r, c = cell
    return 0 <= r < len(grid) and 0 <= c < len(grid[0]) and grid[r][c] != '#'


def manhattan(a, b):
    return abs(a[0] - b[0]) + abs(a[1] - b[1])


def plan(grid, start, goal, vertex, edge):
    """상태는 (칸, 시각)이다. vertex·edge 는 내가 하면 안 되는 것의 집합이다."""
    open_ = [(manhattan(start, goal), 0, start)]
    came = {(start, 0): None}
    while open_:
        f, t, cell = heappop(open_)
        if cell == goal and all((goal, tt) not in vertex for tt in range(t, HORIZON + 1)):
            return rebuild(came, cell, t)
        if t >= HORIZON:
            continue
        for dr, dc in MOVES:
            nxt = (cell[0] + dr, cell[1] + dc)
            if not walkable(grid, nxt):
                continue
            if (nxt, t + 1) in vertex:          # 정점 충돌 — 같은 칸, 같은 시각
                continue
            if (cell, nxt, t) in edge:          # 맞바꿈 충돌 — 서로를 통과한다
                continue
            if (nxt, t + 1) in came:            # g == t 이므로 처음 닿은 것이 최선이다
                continue
            came[(nxt, t + 1)] = (cell, t)
            heappush(open_, (t + 1 + manhattan(nxt, goal), t + 1, nxt))
    return None


def rebuild(came, cell, t):
    path, node = [], (cell, t)
    while node is not None:
        path.append(node[0])
        node = came[node]
    path.reverse()
    return path


def reserve(path, vertex, edge):
    """뽑은 경로를 예약 테이블에 적는다. 뒤에 계획하는 에이전트가 이것을 피한다."""
    for t, cell in enumerate(path):
        vertex.add((cell, t))
    for t in range(len(path) - 1):
        edge.add((path[t + 1], path[t], t))     # 역방향 이동을 막는다 = 맞바꿈 금지
    for t in range(len(path), HORIZON + 1):
        vertex.add((path[-1], t))               # 도착한 뒤에도 그 칸에 서 있다


def prioritized(grid, agents, use_edge=True):
    """우선순위 기반 계획 — 앞의 에이전트를 고정하고 뒤의 에이전트가 피한다."""
    vertex, edge = set(), set()
    paths = []
    for start, goal in agents:
        path = plan(grid, start, goal, vertex, edge if use_edge else set())
        if path is None:
            return paths, len(paths)            # 실패한 에이전트의 번호
        reserve(path, vertex, edge)
        paths.append(path)
    return paths, -1


def at(path, t):
    return path[t] if t < len(path) else path[-1]


def first_conflict(paths):
    """가장 이른 충돌 하나. (종류, i, j, 칸i, 칸j, 시각)."""
    span = max(len(p) for p in paths)
    for t in range(span):
        for i in range(len(paths)):
            for j in range(i + 1, len(paths)):
                a, b = at(paths[i], t), at(paths[j], t)
                if a == b:
                    return ("vertex", i, j, a, b, t)
                if at(paths[i], t + 1) == b and at(paths[j], t + 1) == a:
                    return ("swap", i, j, a, b, t)
    return ("none", 0, 0, (0, 0), (0, 0), 0)


def describe(conflict):
    kind, i, j, a, b, t = conflict
    if kind == "none":
        return "없음"
    if kind == "vertex":
        return "정점 충돌 %s%s (%d,%d) t=%d" % (NAME[i], NAME[j], a[0], a[1], t)
    return "맞바꿈 충돌 %s(%d,%d) <-> %s(%d,%d) t=%d->%d" % (
        NAME[i], a[0], a[1], NAME[j], b[0], b[1], t, t + 1)


def show(path):
    return " ".join("(%d,%d)" % cell for cell in path)
```

```cpp title="시공간 A* — 예약 테이블과 우선순위 기반 계획"
#include <algorithm>
#include <iostream>
#include <map>
#include <queue>
#include <set>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

using Cell = pair<int, int>;
using Path = vector<Cell>;
using VertexSet = set<pair<Cell, int>>;              // 금지된 (칸, 시각)
using EdgeSet = set<tuple<Cell, Cell, int>>;         // 금지된 (이동, 시각)

// 대기가 첫 번째다 — 시간 축이 생기는 순간 제자리에 머무는 것도 비용 1짜리 행동이 된다.
const vector<Cell> MOVES = {{0, 0}, {-1, 0}, {1, 0}, {0, -1}, {0, 1}};
const int HORIZON = 20;            // 시간 축의 상한. 상태 공간이 이 배수만큼 불어난다
const string NAME = "AB";

bool walkable(const vector<string> &grid, Cell cell) {
    int r = cell.first, c = cell.second;
    return 0 <= r && r < (int)grid.size() && 0 <= c && c < (int)grid[0].size() &&
           grid[r][c] != '#';
}

int manhattan(Cell a, Cell b) {
    return abs(a.first - b.first) + abs(a.second - b.second);
}

Path rebuild(map<pair<Cell, int>, pair<Cell, int>> &came, Cell cell, int t) {
    Path path;
    pair<Cell, int> node = {cell, t};
    while (node.second >= 0) {
        path.push_back(node.first);
        node = came[node];
    }
    reverse(path.begin(), path.end());
    return path;
}

Path plan(const vector<string> &grid, Cell start, Cell goal,
          const VertexSet &vertex, const EdgeSet &edge) {
    // 상태는 (칸, 시각)이다. vertex·edge 는 내가 하면 안 되는 것의 집합이다.
    priority_queue<tuple<int, int, Cell>, vector<tuple<int, int, Cell>>,
                   greater<tuple<int, int, Cell>>> open_;
    open_.push({manhattan(start, goal), 0, start});
    map<pair<Cell, int>, pair<Cell, int>> came;
    came[{start, 0}] = {{-1, -1}, -1};
    while (!open_.empty()) {
        auto [f, t, cell] = open_.top();
        open_.pop();
        bool clear = true;
        for (int tt = t; tt <= HORIZON; tt++)
            if (vertex.count({goal, tt})) clear = false;
        if (cell == goal && clear) return rebuild(came, cell, t);
        if (t >= HORIZON) continue;
        for (auto [dr, dc] : MOVES) {
            Cell nxt = {cell.first + dr, cell.second + dc};
            if (!walkable(grid, nxt)) continue;
            if (vertex.count({nxt, t + 1})) continue;    // 정점 충돌 — 같은 칸, 같은 시각
            if (edge.count({cell, nxt, t})) continue;    // 맞바꿈 충돌 — 서로를 통과한다
            if (came.count({nxt, t + 1})) continue;      // g == t 이므로 처음 닿은 것이 최선이다
            came[{nxt, t + 1}] = {cell, t};
            open_.push({t + 1 + manhattan(nxt, goal), t + 1, nxt});
        }
    }
    return {};
}

void reserve_path(const Path &path, VertexSet &vertex, EdgeSet &edge) {
    // 뽑은 경로를 예약 테이블에 적는다. 뒤에 계획하는 에이전트가 이것을 피한다.
    for (int t = 0; t < (int)path.size(); t++) vertex.insert({path[t], t});
    for (int t = 0; t + 1 < (int)path.size(); t++)
        edge.insert({path[t + 1], path[t], t});          // 역방향 이동을 막는다 = 맞바꿈 금지
    for (int t = path.size(); t <= HORIZON; t++)
        vertex.insert({path.back(), t});                 // 도착한 뒤에도 그 칸에 서 있다
}

pair<vector<Path>, int> prioritized(const vector<string> &grid,
                                    const vector<pair<Cell, Cell>> &agents,
                                    bool use_edge = true) {
    // 우선순위 기반 계획 — 앞의 에이전트를 고정하고 뒤의 에이전트가 피한다.
    VertexSet vertex;
    EdgeSet edge;
    vector<Path> paths;
    for (auto [start, goal] : agents) {
        Path path = plan(grid, start, goal, vertex, use_edge ? edge : EdgeSet());
        if (path.empty()) return {paths, (int)paths.size()};   // 실패한 에이전트의 번호
        reserve_path(path, vertex, edge);
        paths.push_back(path);
    }
    return {paths, -1};
}

Cell at(const Path &path, int t) {
    return t < (int)path.size() ? path[t] : path.back();
}

struct Conflict { string kind; int i, j; Cell a, b; int t; };

Conflict first_conflict(const vector<Path> &paths) {
    // 가장 이른 충돌 하나.
    int span = 0;
    for (auto &p : paths) span = max(span, (int)p.size());
    for (int t = 0; t < span; t++)
        for (int i = 0; i < (int)paths.size(); i++)
            for (int j = i + 1; j < (int)paths.size(); j++) {
                Cell a = at(paths[i], t), b = at(paths[j], t);
                if (a == b) return {"vertex", i, j, a, b, t};
                if (at(paths[i], t + 1) == b && at(paths[j], t + 1) == a)
                    return {"swap", i, j, a, b, t};
            }
    return {"none", 0, 0, {0, 0}, {0, 0}, 0};
}

string describe(const Conflict &conflict) {
    char buf[128];
    if (conflict.kind == "none") return "없음";
    if (conflict.kind == "vertex") {
        snprintf(buf, sizeof buf, "정점 충돌 %c%c (%d,%d) t=%d", NAME[conflict.i],
                 NAME[conflict.j], conflict.a.first, conflict.a.second, conflict.t);
        return buf;
    }
    snprintf(buf, sizeof buf, "맞바꿈 충돌 %c(%d,%d) <-> %c(%d,%d) t=%d->%d",
             NAME[conflict.i], conflict.a.first, conflict.a.second, NAME[conflict.j],
             conflict.b.first, conflict.b.second, conflict.t, conflict.t + 1);
    return buf;
}

string show(const Path &path) {
    string s;
    char buf[32];
    for (size_t k = 0; k < path.size(); k++) {
        snprintf(buf, sizeof buf, "(%d,%d)", path[k].first, path[k].second);
        if (k) s += " ";
        s += buf;
    }
    return s;
}

int main() {
    cout << "[1] 십자 교차로 — 우선순위 기반 계획\n";
    vector<string> grid = {"##.##", "##.##", ".....", "##.##", "##.##"};
    vector<pair<Cell, Cell>> agents = {{{2, 0}, {2, 4}}, {{0, 2}, {4, 2}}};
    auto [paths, failed] = prioritized(grid, agents);
    for (int i = 0; i < (int)paths.size(); i++)
        cout << "  " << NAME[i] << ": " << show(paths[i]) << "  비용 "
             << paths[i].size() - 1 << "\n";
    cout << "  충돌: " << describe(first_conflict(paths)) << "\n";

    cout << "[2] 맞바꿈 충돌 — 1행짜리 복도\n";
    grid = {"...."};
    agents = {{{0, 0}, {0, 3}}, {{0, 3}, {0, 0}}};
    tie(paths, failed) = prioritized(grid, agents, false);
    cout << "  간선 검사 없음 -> B: " << (failed < 0 ? show(paths[1]) : "해 없음") << "\n";
    cout << "  충돌: " << describe(first_conflict(paths)) << "\n";
    tie(paths, failed) = prioritized(grid, agents, true);
    cout << "  간선 검사 있음 -> B: " << (failed < 0 ? show(paths[1]) : "해 없음") << "\n";

    cout << "[3] 우선순위 기반 계획의 불완전성 — 대피 공간이 하나뿐인 복도\n";
    grid = {"#.###", "....."};
    agents = {{{1, 0}, {1, 4}}, {{1, 4}, {1, 0}}};
    tie(paths, failed) = prioritized(grid, agents);
    cout << "  A: " << show(paths[0]) << "\n";
    cout << "  B: 실패 (에이전트 " << failed << " 에서 막힘)\n";
    vector<Path> joint = {{{1, 0}, {1, 1}, {0, 1}, {0, 1}, {1, 1}, {1, 2}, {1, 3}, {1, 4}},
                          {{1, 4}, {1, 3}, {1, 2}, {1, 1}, {1, 0}}};
    cout << "  손으로 만든 동시 해 A: " << show(joint[0]) << "\n";
    cout << "  손으로 만든 동시 해 B: " << show(joint[1]) << "\n";
    int total = 0;
    for (auto &p : joint) total += p.size() - 1;
    cout << "  충돌: " << describe(first_conflict(joint)) << " / 비용 합 " << total << "\n";
    return 0;
}
```

**복잡도:** 한 에이전트의 계획이 시간 $O(|V| \cdot T \log(|V| \cdot T))$ — 상태가 `(칸, 시각)` 쌍이라 최대 $|V| \cdot T$개이고, 각 상태가 힙에 최대 한 번 들어가며 힙 연산이 $O(\log(|V| \cdot T))$다. 공간도 $O(|V| \cdot T)$ — `came`가 상태마다 부모를 하나씩 들고 있다. 에이전트가 $k$대면 $k$번 반복하므로 전체는 그 $k$배다. **상수 항에 `T`가 통째로 곱해진다는 것이 이 알고리즘의 실질 비용이다**(§2.5의 실측).

[2]가 §2.3의 그림 그대로다. 간선 검사를 끄면 B는 `(0,3) (0,2) (0,1) (0,0)`이라는 **정점 충돌이 하나도 없는** 경로를 얻는다. `t=1`에 A는 `(0,1)`, B는 `(0,2)`에 있고 `t=2`에 자리를 맞바꾼다. 검사를 켜면 B는 해를 찾지 못한다 — 폭이 하나인 복도에서 마주 오는 둘은 실제로 지나갈 수 없기 때문이고, **"해 없음"이 옳은 답이다.**

| 언어 차이 | Python | C++ |
|---|---|---|
| 힙 방향 | `heapq`는 최소 힙 고정 | `priority_queue`는 최대 힙 기본. `greater<...>`를 세 번째 인자로 명시해야 최소 힙이다 |
| 튜플 비교 | `(f, t, cell)` 튜플이 사전순 비교된다 | `tuple<int,int,Cell>`도 같다. `Cell = pair<int,int>`라 안쪽까지 사전순이다 |
| 부모 없음 표시 | `came[(start, 0)] = None` | `None`이 없다. `{{-1,-1}, -1}`을 뿌리 표시로 쓰고 `node.second >= 0`으로 멈춘다 |
| 실패 표현 | `return None` | 빈 `vector`를 반환하고 `path.empty()`로 본다 |
| 집합 원소 | `set`에 튜플을 그대로 넣는다(해시) | `set<tuple<...>>`는 정렬 트리다. 조회가 $O(\log n)$이라 상수가 더 붙는다 |
| 함수 이름 | `reserve` | `reserve`는 `vector`의 멤버 이름과 겹쳐 혼동을 부른다. `reserve_path`로 쓴다 |

::: pitfall
- **맞바꿈 검사 누락.** 정점만 검사한 코드는 위 [2]처럼 조용히 서로를 통과시킨다. 시뮬레이터에서는 아무 일도 안 일어나고 실물에서만 부딪힌다.
- **도착 칸을 지평 끝까지 예약하지 않음.** 먼저 도착해 서 있는 로봇 위로 다음 로봇이 지나간다. `reserve`의 마지막 루프가 그 자리다.
- **목표 도달 판정에서 미래 예약을 안 봄.** 목표 칸이 나중에 예약되어 있으면 그 자리에 눌러앉을 수 없다. `plan`의 `all(... for tt in range(t, HORIZON + 1))`이 그것을 본다. 이 검사는 [V-9](#/v-9)의 CBS에서 훨씬 더 중요해진다.
- **`HORIZON`을 너무 짧게 잡음.** 대기가 필요한 만큼 못 들어가 해가 있는데도 실패한다. 실패와 "해 없음"이 구별되지 않는 것이 이 방식의 고약한 점이다.
- **`visited`를 칸 단위로 둠.** `(칸, 시각)`이 아니라 칸으로 방문을 찍으면 대기와 우회가 전부 막혀 시간 축을 넣은 의미가 사라진다.
:::

## 5. 우선순위 기반 계획은 불완전하다

::: widget multi-agv-conflict {"scenario":"corridor-alcove","grid":["#.###","....."],"agents":[{"id":"A","start":[1,0],"goal":[1,4],"priority":1},{"id":"B","start":[1,4],"goal":[1,0],"priority":2}],"mode":"prioritized","phases":["independent","reserve","blocked"],"show":["grid","timeline","reservation-table"],"outcome":"failure","annotate":"joint-solution-exists","counters":["expanded","waits","deadEnd"],"controls":"step"}
:::

두 번째 위젯은 같은 네 단계를 밟다가 마지막에 멈춘다. 폭이 하나인 복도에 대피 공간이 `(0,1)` 한 칸뿐이고, A는 왼쪽 끝에서 오른쪽 끝으로, B는 반대로 가야 한다. **① A가 먼저 계획한다** — 복도를 직진해 `t=4`에 도착하고 그 자리에 눌러앉는다. **② 예약이 채워진다** — 복도의 다섯 칸이 시각 0부터 4까지 대각선으로 찍힌다. **③ B가 막힌다** — B가 열 수 있는 상태가 전부 소진되고 격자 전체가 회색이 된다. 그리고 위젯은 **손으로 만든 동시 해**를 겹쳐 보여준다. A가 대피 공간으로 들어가 B를 보내고 나오는 경로다.

출력 [3]이 그 장면이다. 우선순위 기반 계획은 실패하고, 비용 합 11짜리 해는 실재한다. `first_conflict`가 그 해에 충돌이 없음을 확인해 준다.

왜 실패하는지는 한 줄로 말할 수 있다. **A의 경로를 고정한 순간 A가 대피 공간에 들어가는 선택지가 사라졌기 때문이다.** 이 문제의 유일한 해는 **먼저 계획한 쪽이 양보하는** 해인데, 우선순위 기반 계획에서 앞 순번은 절대 양보하지 않는다.

::: deep
이 실패가 순서 문제가 아니라는 점이 중요하다. B를 먼저 계획해도 대칭적으로 같은 일이 일어난다. B가 직진하고 A가 막힌다. **어떤 순서로도 못 푼다.**

우선순위를 바꿔 가며 재시도하는 개선(순서를 무작위로 섞어 여러 번 시도하는 방식)이 실무에서 널리 쓰이고 대부분의 배치에서 통한다. 그러나 그것은 **성공 확률을 올리는 것이지 보장을 만드는 것이 아니다.** 위 배치에서는 $2! = 2$가지 순서를 모두 시도해도 전부 실패한다.

핵심은 이렇다. 우선순위 기반 계획이 탐색하는 공간은 **"각자의 단일 에이전트 최적 경로에 대기와 우회를 얹은 것"의 순차적 조합**이고, 동시 해 전체 공간의 진부분집합이다. 그 밖에 놓인 해는 원리적으로 닿을 수 없다.

그래서 두 가지 성질이 갈린다. 우선순위 기반 계획은 **빠르지만 불완전하고 최적도 아니다.** 반대편에 있는 것이 [V-9 CBS](#/v-9)다 — 충돌을 제약으로 바꿔 되먹임으로써 **완전하고 최적**이 된다. 대가는 지수적으로 자랄 수 있는 탐색 트리다.
:::

## 6. 어디에 쓰이는가

**물류 창고의 AMR 관제기가 이 자료구조 위에 서 있다.** 수십에서 수백 대가 도는 현장에서 관제기는 로봇별 경로가 아니라 **`(칸, 시각)` 예약 장부**를 관리한다. 로봇이 경로를 요청하면 장부를 보고 계획해 주고, 뽑힌 경로를 다시 장부에 적는다. 로봇이 늦어지면 그 뒤의 예약이 전부 밀리므로 실제 시스템은 예약에 여유 시간을 넣고 주기적으로 다시 계획한다. **예약 테이블은 계획의 산출물이 아니라 관제기가 들고 있는 상태 그 자체다.**

**컨테이너 터미널의 AGV도 같다.** 안벽 크레인과 야드 사이를 오가는 차량들이 교차로에서 만나는 문제가 격자만 다를 뿐 동일하다.

**철도 운행 계획이 이 문제의 오래된 형태다.** 선로 구간을 시간과 함께 잡는 것 — 어느 열차가 어느 폐색 구간을 몇 시 몇 분에 점유하는가 — 이 곧 `(자원, 시각)` 예약이다. 단선 구간에서 마주 오는 두 열차가 대피선에서 교행하는 장면은 §5의 복도와 정확히 같은 구조다. **대피선이 대피 공간이다.**

이 장부를 누가 들고 있느냐는 설계 문제이기도 하다. 로봇끼리 서로의 계획을 직접 주고받게 만들면 통신이 대수 개로 늘고 일관성이 깨진다. 중앙에 하나를 두고 모두가 그것을 통해 말하게 하는 구조가 [XII-11 Mediator](#/xii-11)이고, 관제기라는 이름이 그 패턴의 실물이다.

## 7. 이 유형을 알아보는 법

::: classify
- 신호어: "여러 대가 같은 통로를 쓴다", "서로 부딪히면 안 된다", "먼저 지나간 뒤에는 비어 있다", "기다렸다 가도 된다", "출발 시각이 정해져 있다"
- 제약조건: 에이전트 수 $k$가 수십 이하, 격자 칸 $|V| \le 10^5$, 계획 지평 $T$가 경로 길이의 두세 배 이내. 상태가 $|V| \cdot T$이므로 $|V| \cdot T \le 10^7$이 실질 한계다
- 혼동 주의: 한 대뿐이면 시간 축이 필요 없다 → [V-5 A\*](#/v-5). 지도가 실행 중에 바뀌는 것이 문제면 → [V-7 D\* Lite](#/v-7). 최적 해나 완전성이 필요하면 우선순위 기반으로는 안 된다 → [V-9 CBS](#/v-9). 누가 어느 작업을 맡을지가 문제면 경로가 아니라 할당이다 → [V-11](#/v-11)
- 반례 함정: 맞바꿈 충돌. 정점 충돌만 검사하면 마주 오는 두 대가 서로를 통과하고, 시뮬레이터에서는 정상으로 보인다. 그리고 도착한 에이전트를 예약에서 빼면 그 위로 다른 에이전트가 지나간다
:::

::: interview
**"로봇 여러 대의 경로를 어떻게 겹치지 않게 계획합니까."**
답의 뼈대는 상태 정의다. "상태를 칸이 아니라 `(칸, 시각)`으로 두고 대기를 행동에 추가합니다. 먼저 계획한 로봇의 경로를 `(칸, 시각)` 예약 테이블에 적고, 다음 로봇은 그 표를 시간에 따라 열리고 닫히는 장애물로 씁니다." 여기까지가 절반이다. **"충돌은 두 종류이고 맞바꿈을 따로 막아야 합니다"** 를 덧붙이면 실제로 만들어 본 답이 된다. 마지막으로 **"이 방식은 빠르지만 완전하지 않습니다"** 와 반례 한 줄까지 가면 끝이다.

## 연습

::: quiz
코드를 짜지 마라. 세 가지를 적어라. **① 상황에서 무엇이 상태인가 ② 왜 이 알고리즘인가 ③ 무엇을 포기하는가.**

**1. 좁은 통로가 있는 창고**
- 상황: 30대의 AMR이 도는 창고에 폭이 하나인 통로가 다섯 군데 있다. 관제기는 로봇의 작업 요청을 받을 때마다 경로를 하나씩 내준다. 이미 도는 로봇의 계획은 바꾸지 않는다.
- 확인할 것: 예약 테이블의 키는 무엇인가. `T`를 얼마로 잡을 것인가. 이 구조가 원리적으로 못 푸는 배치는 어떤 모양인가.

**2. 로봇이 늦었다**
- 상황: 계획대로면 `t=7`에 교차로를 비웠어야 할 로봇이 짐이 걸려 3초 늦었다. 뒤따르던 로봇 네 대의 예약이 전부 어긋난다.
- 확인할 것: 전부 다시 계획할 것인가, 늦은 만큼 뒤 예약을 밀 것인가. 미는 방식이 새로운 충돌을 만들 수 있는가. 예약에 처음부터 여유를 넣는 방식은 무엇을 잃는가.

**3. 출발 시각을 고를 수 있다면**
- 상황: 작업 지시가 "지금 당장"이 아니라 "10초 안에 시작"으로 들어온다. 계획기는 출발 시각도 정할 수 있다.
- 확인할 것: 출발 시각을 상태에 넣을 것인가 탐색 밖에서 고를 것인가. 대기와 늦은 출발은 비용이 같은가, 다르다면 비용 함수를 어떻게 쓸 것인가.

**4. 우선순위를 무엇으로 정할 것인가**
- 상황: 우선순위 기반 계획을 쓰기로 했다. 남은 결정은 순서다. 후보는 작업 마감이 임박한 순, 경로가 긴 순, 로봇 번호 순이다.
- 확인할 것: 순서가 해의 존재 여부를 바꾸는가, 품질만 바꾸는가. §5의 복도 배치에서 세 후보 중 답을 내는 것이 있는가. 순서를 바꿔 재시도하는 전략의 한계는 무엇인가.
:::

## 요약

- 시공간 A\*는 [A\*](#/v-5)에서 **상태를 `(칸, 시각)`으로 바꾼 것**이다. 그 외에는 전부 같다.
- 행동에 **대기**가 추가된다. 다른 로봇을 피하는 유일한 수단이고, 모든 행동 비용이 1이므로 `g`가 곧 시각이라 `f = t + h`가 된다.
- **예약 테이블**은 `(칸, 시각)`과 `(이동, 시각)` 두 종류를 적는다. 뒤에 계획하는 에이전트에게는 **시간에 따라 열리고 닫히는 장애물**이다.
- 충돌은 두 종류다. 정점 충돌과 **맞바꿈 충돌**. 후자를 빠뜨리면 마주 오는 두 대가 서로를 관통하고, 정점 검사는 그것을 통과시킨다.
- 맨해튼 휴리스틱은 시간 축에서도 admissible 하다. 대기가 **거리를 줄이지 않으면서 비용만 더하기** 때문이다.
- 대가는 메모리다. 상태가 $|V| \cdot T$로 불어난다 — 41×41 격자에서 `T = 100`이면 상태 820개가 58,630개, 54KiB가 12MB가 된다.
- 우선순위 기반 계획은 **불완전하다.** 대피 공간이 하나뿐인 복도에서 해가 있는데도 실패하고, 순서를 바꿔도 마찬가지다. 먼저 계획한 쪽이 양보하는 해에 닿을 수 없기 때문이다.
