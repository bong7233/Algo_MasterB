# V-1 다익스트라

::: lead
BFS의 큐를 우선순위 큐로 갈아 끼우면 무엇이 되는가.
:::

## 1. 문제

[IV-3](#/iv-3)은 한 줄에 매달려 끝났다. **"새로 찍는 값은 항상 지금 값 + 1이다."** 모든 간선의 비용이 같아야 큐가 거리 순으로 정렬되고, 그래야 처음 찍은 값이 최단이 된다. 비용이 갈리는 순간 그 논증이 통째로 무너진다.

비용이 갈리는 상황은 예외가 아니라 기본이다. 도시 네 곳과 길 네 개를 놓는다.

```text nolines
             1        1        1
      0 ─────▶ 1 ─────▶ 2 ─────▶ 3
      │                          ▲
      └──────────────────────────┘
                   10
```

`0`에서 `3`으로 간다. BFS는 간선을 한 번 타면 거리 1을 더하므로 `0 → 3` 직행을 **1**로 보고 그것을 최단으로 확정한다. 실제 비용은 10이다. 국도로 세 번 갈아타면 `1 + 1 + 1 = 3`이고 이쪽이 세 배 넘게 싸다. ==BFS가 세는 것은 간선의 **개수**지 간선의 **비용**이 아니다.== 두 값이 갈리는 순간 BFS는 틀린 답을 확신을 갖고 내놓는다.

이 격차는 문제를 조금만 실물에 가깝게 만들면 바로 나타난다. 로봇의 점유 격자 지도에서 칸마다 통행 비용이 다르면(평지 1, 자갈 3, 진창 6) "몇 칸인가"와 "얼마인가"는 다른 질문이다. 도로망에서 거리 대신 소요 시간을 쓰면 신호 대기가 있는 짧은 길이 우회로보다 비쌀 수 있다.

그렇다고 BFS를 버릴 이유는 없다. 필요한 것은 **BFS가 잃어버린 성질 하나를 되찾는 것**이다.

## 2. 아이디어

### 2.1 잃은 것은 정렬이다

BFS의 불변식을 다시 적는다. 큐 안의 `dist` 값은 비내림차순이고 값의 종류가 최대 둘($d$와 $d+1$)이다. 유지되는 이유는 뒤에 붙는 값이 항상 $d+1$ 하나뿐이기 때문이다.

가중치가 붙으면 뒤에 붙는 값이 $d + w$가 된다. $w$가 제각각이면 큐 뒤쪽에 앞쪽보다 작은 값이 붙는다. 그 순간 큐는 정렬된 자료구조가 아니게 되고, "앞에서 꺼낸 것이 가장 가깝다"가 거짓이 된다.

**잃은 것이 정렬이라면 되찾는 방법은 하나다. 항상 가장 작은 것을 꺼내 주는 자료구조로 바꾼다.** 그것이 힙이고, 그 위에 얹은 것이 우선순위 큐다([II-8](#/ii-8)).

바뀌는 코드는 두 줄이다.

| 무엇 | BFS | 다익스트라 |
|---|---|---|
| 열린 목록 | `deque` | 힙(우선순위 큐) |
| 꺼내는 것 | 가장 먼저 들어온 것 | `dist`가 가장 작은 것 |
| 새 거리 | `dist[u] + 1` | `dist[u] + w(u, v)` |

나머지는 그대로다. 이웃을 훑고, 더 좋으면 갱신하고, 큐에 넣는다. ==다익스트라는 새 알고리즘이 아니라 BFS의 큐를 우선순위 큐로 갈아 끼운 것이다.== 이 문장이 [V-5 A\*](#/v-5)까지 이어지는 계보의 두 번째 칸이다.

:::

위젯은 지형 비용이 있는 격자에서 BFS와 다익스트라를 나란히 재생한다. 칸 안의 점 개수가 그 칸에 들어가는 비용이고(점 없음 1, 하나 3, 둘 6), 각 패널의 숫자가 확장한 칸 수와 찾아낸 경로의 **비용**이다.

- **BFS**는 여전히 동심원으로 번지고 경로도 곧게 뻗는다. 비싼 칸을 그대로 통과한다. 칸 수는 최소지만 비용은 최소가 아니다.
- **다익스트라**는 원이 아니라 **등비용 등고선**으로 번진다. 비싼 지형 쪽으로는 천천히, 싼 지형 쪽으로는 빨리 밀려 나간다. 경로가 비싼 칸을 피해 휘어진다.

두 패널의 경로 비용을 비교하면 BFS 쪽이 크다. 확장 순서를 결정하는 규칙 하나만 바꿨는데 답이 달라진다.

### 2.2 왜 가장 작은 것부터 꺼내면 맞는가

"싼 것부터 확정하면 되지 않느냐"는 직관이지 증명이 아니다. 무엇이 참이어서 맞는지 적는다.

기호를 정한다. $\delta(v)$는 시작점 $s$에서 $v$까지의 **진짜** 최단 비용이고, `dist[v]`는 지금까지 발견한 최선이다. `dist[v]`는 실제로 존재하는 경로 하나의 비용이므로 항상 `dist[v]` $\ge \delta(v)$다.

**확정 불변식.** 힙에서 $(d, u)$를 꺼냈고 그 $d$가 아직 유효하다면(`dist[u]` $= d$), 그 순간 $d = \delta(u)$다. 즉 **꺼내는 순간 그 정점의 답이 끝난다.**

귀류법으로 본다. 이 성질을 어기는 첫 정점을 $u$라 하자. 꺼낸 값 $d$에 대해 $\delta(u) < d$다. $s$에서 $u$까지의 진짜 최단경로 $P$를 따라가면, $P$ 위에는 이미 확정된 정점과 아직 확정되지 않은 정점이 섞여 있다. $P$를 따라가다 처음 만나는 미확정 정점을 $y$, 그 직전 정점을 $x$라 하자($x$는 확정됐고, $s$ 자신일 수도 있다).

$x$는 $u$보다 먼저 확정됐고 $u$가 규칙을 어기는 첫 정점이므로 `dist[x]` $= \delta(x)$였다. $x$를 꺼낼 때 간선 $x \to y$를 완화했으므로

$$\text{dist}[y] \le \delta(x) + w(x, y) = \delta(y)$$

이고, 부등호의 반대 방향은 언제나 참이므로 `dist[y]` $= \delta(y)$다. 그리고 $y$는 그 값으로 힙 안에 들어 있다.

$y$는 최단경로 $P$ 위에서 $u$보다 앞에 있다. $y$에서 $u$까지 남은 구간의 비용을 $R$이라 하면 $\delta(u) = \delta(y) + R$이다. **모든 간선 비용이 0 이상이므로 $R \ge 0$이고, 따라서 $\delta(y) \le \delta(u) < d$다.** 힙 안에 $d$보다 작은 값 $\delta(y)$를 가진 항목이 있는데 힙이 $(d, u)$를 먼저 내줄 수는 없다. 모순이다.

::: warn
논증 전체가 **$R \ge 0$** 한 줄에 매달려 있다. 남은 구간의 비용이 음수일 수 있으면 $\delta(y) \le \delta(u)$가 깨지고, 방금 꺼낸 $u$의 값이 나중에 더 줄어들 수 있다. 그러면 "꺼낼 때 확정"이 거짓이 된다.

==BFS의 논증이 "간선 비용이 전부 같다"에 매달렸다면, 다익스트라의 논증은 "간선 비용이 음수가 아니다"에 매달린다.== 조건이 느슨해진 만큼 쓸 수 있는 그래프가 넓어졌고, 정확히 그 경계에서 [V-2 벨만-포드](#/v-2)가 필요해진다.
:::

여기서 따라 나오는 결론이 하나 더 있다. **꺼낸 값들의 수열은 비내림차순이다.** 확정된 정점의 값이 $\delta$이고 그 이후에 힙에 들어가는 값은 전부 $\delta + w \ge \delta$이기 때문이다. BFS에서 "값의 종류가 최대 둘"이던 것이 여기서는 "정렬되어 있다"로 약해졌다. 약해진 대신 임의의 비음수 가중치를 견딘다.

### 2.3 낡은 항목을 어떻게 치우는가

한 가지가 남는다. 정점 $v$의 `dist`가 4에서 3으로 줄었을 때, 힙 안에 이미 들어 있는 `(4, v)`는 어떻게 되는가.

**정공법은 감소 키(decrease-key)다.** 힙 안에서 $v$가 있는 자리를 찾아 값을 3으로 내리고 위로 sift-up 한다. 정점마다 항목이 정확히 하나뿐이라 힙 크기가 $O(V)$로 유지된다. 대가는 **정점 → 힙 인덱스 대응표를 따로 들고, 힙이 원소를 옮길 때마다 그 표를 갱신해야 한다**는 것이다. `heapq`도 `std::priority_queue`도 이 기능을 제공하지 않는다. 직접 힙을 짜야 한다.

**실전에서 쓰는 것은 게으른 삭제(lazy deletion)다.** 낡은 항목을 지우지 않는다. 새 값 `(3, v)`를 그냥 하나 더 넣는다. 대신 **꺼낼 때 검사한다** — 꺼낸 $(d, u)$의 $d$가 `dist[u]`보다 크면 그것은 이미 갱신되어 버려진 값이므로 아무 일도 하지 않고 버린다.

```text nolines
    heap:  (3,v) (4,v) ...      <- (4,v) 는 낡았지만 그대로 둔다
    pop -> (3,v)   d == dist[v] -> 확정. 이웃 완화
    pop -> (4,v)   d >  dist[v] -> 버린다. 여기서 끝
```

이쪽이 이기는 이유는 세 가지다.

1. **표준 라이브러리로 끝난다.** `heapq.heappush` 한 줄, `pq.push` 한 줄이다. 감소 키는 힙 구현을 통째로 들고 다녀야 한다.
2. **복잡도가 같다.** 힙에 들어가는 항목 수가 완화 성공 횟수이므로 최대 $E$개다. 힙 크기가 $O(E)$이고 $E \le V^2$이므로 $\log E \le 2 \log V$다. $O(E \log E) = O(E \log V)$로 감소 키 판과 같은 급이다.
3. **틀릴 여지가 적다.** 인덱스 대응표는 힙이 원소를 옮길 때마다 갱신해야 하고, 한 군데만 빠뜨려도 조용히 틀린 답이 나온다.

::: note
게으른 삭제 대신 **확정 배열**(`done[]`)을 두고 "이미 꺼낸 정점이면 건너뛴다"로 짜는 판도 흔하다. 비음수 가중치에서는 두 판이 **완전히 같은 답과 같은 확장 순서**를 낸다. §2.2가 "한 번 유효하게 꺼낸 정점은 다시 줄지 않는다"를 보장하기 때문이다.

두 판이 갈라지는 곳은 음수 간선이 섞였을 때다. 그때 무엇이 어떻게 달라지는지는 [V-2](#/v-2)에서 숫자로 확인한다.
:::

## 3. 손으로 따라가기

::: trace
유향 그래프. 정점 6개, 간선 9개다. 시작은 0이다.

```text nolines
    0 →1 : 4      2 →1 : 2      2 →4 : 10     3 →5 : 6
    0 →2 : 1      1 →3 : 5      3 →4 : 2      4 →5 : 3
                  2 →3 : 8
```

힙은 `(거리, 정점)` 쌍을 담는 최소 힙이다. `dist`는 처음에 시작점만 0이고 나머지는 `∞`다. **완화가 성공한 간선만 힙에 넣는다.**

세 번째. 정점 3은 두 번 들어갔다. 스텝 2에서 `2 →3` 을 타고 9로, 스텝 3에서 `1 →3` 을 타고 8로. 앞의 것이 쓸모없어졌다. **낡은 항목이 생기는 이유는 하나다 — 더 짧은 길이 나중에 발견되기 때문이다.** 다익스트라는 이 "나중에"가 확정 이전에만 일어난다는 것을 보장하는 알고리즘이다.

네 번째가 이 절의 핵심이다. 큐라면 스텝 2에서 `(4, 1)`이 `(1, 2)`보다 먼저 들어왔으므로 정점 1을 **4로 확정**하고 넘어간다. 그러면 `1 →3` 이 `4 + 5 = 9`가 되고, 정점 3의 답이 8이 아니라 9가 된다. 오차가 그 뒤로 전부 전파된다. ==거리 순으로 꺼내는 것이 편의가 아니라 정확성의 조건이다.==

```python title="다익스트라 — 게으른 삭제와 경로 복원"
import heapq

N = 6
EDGES = [(0, 1, 4), (0, 2, 1), (2, 1, 2), (1, 3, 5), (2, 3, 8),
         (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)]
INF = float("inf")

adj = [[] for _ in range(N)]
for u, v, w in EDGES:
    adj[u].append((v, w))


def dijkstra(src):
    dist = [INF] * N
    par = [-1] * N
    dist[src] = 0
    pq = [(0, src)]                      # (거리, 정점) — 거리가 앞이라 거리로 정렬된다
    settled = []                         # 확정된 순서. 이 순서가 곧 알고리즘이다
    push, pop, stale = 1, 0, 0
    while pq:
        d, u = heapq.heappop(pq)
        pop += 1
        if d > dist[u]:                  # 낡은 항목이다. 게으른 삭제
            stale += 1
            continue
        settled.append(u)
        for v, w in adj[u]:
            if d + w < dist[v]:          # 완화가 되는 간선만 힙에 넣는다
                dist[v] = d + w
                par[v] = u
                heapq.heappush(pq, (dist[v], v))
                push += 1
    return dist, par, settled, (push, pop, stale)


def restore(par, dst):
    out = []
    v = dst
    while v != -1:
        out.append(v)
        v = par[v]
    out.reverse()
    return out


dist, par, settled, (push, pop, stale) = dijkstra(0)
print("dist    =", [int(x) for x in dist])
print("확정 순서 =", " ".join(str(v) for v in settled))
path = " → ".join(str(v) for v in restore(par, 5))
print(f"경로 0→5 = {path} (비용 {int(dist[5])})")
print(f"push {push} / pop {pop} / 낡은 항목 {stale}")
```
```cpp title="다익스트라 — 게으른 삭제와 경로 복원"
#include <algorithm>
#include <iostream>
#include <queue>
#include <tuple>
#include <vector>
using namespace std;

const int N = 6;
const long long INF = (1LL << 60);
vector<tuple<int, int, int>> EDGES = {{0, 1, 4}, {0, 2, 1}, {2, 1, 2}, {1, 3, 5}, {2, 3, 8},
                                      {2, 4, 10}, {3, 4, 2}, {3, 5, 6}, {4, 5, 3}};
vector<vector<pair<int, int>>> adj(N);

vector<long long> dist_(N, INF);
vector<int> par(N, -1), settled;
int push_ = 0, pop_ = 0, stale = 0;

void dijkstra(int src) {
    priority_queue<pair<long long, int>, vector<pair<long long, int>>, greater<>> pq;
    dist_[src] = 0;
    pq.push({0, src});                   // (거리, 정점) — 거리가 앞이라 거리로 정렬된다
    push_ = 1;
    while (!pq.empty()) {
        auto [d, u] = pq.top();
        pq.pop();
        pop_++;
        if (d > dist_[u]) {              // 낡은 항목이다. 게으른 삭제
            stale++;
            continue;
        }
        settled.push_back(u);
        for (auto [v, w] : adj[u]) {
            if (d + w < dist_[v]) {      // 완화가 되는 간선만 힙에 넣는다
                dist_[v] = d + w;
                par[v] = u;
                pq.push({dist_[v], v});
                push_++;
            }
        }
    }
}

vector<int> restore(int dst) {
    vector<int> out;
    for (int v = dst; v != -1; v = par[v]) out.push_back(v);
    reverse(out.begin(), out.end());
    return out;
}

int main() {
    for (auto [u, v, w] : EDGES) adj[u].push_back({v, w});
    dijkstra(0);
    cout << "dist    = [";
    for (int i = 0; i < N; i++) cout << (i ? ", " : "") << dist_[i];
    cout << "]\n확정 순서 =";
    for (int v : settled) cout << " " << v;
    cout << "\n경로 0→5 =";
    auto p = restore(5);
    for (size_t i = 0; i < p.size(); i++) cout << (i ? " → " : " ") << p[i];
    cout << " (비용 " << dist_[5] << ")\n";
    cout << "push " << push_ << " / pop " << pop_ << " / 낡은 항목 " << stale << "\n";
    return 0;
}
```

두 언어의 출력은 같고, §3의 손추적과도 정확히 일치한다.

```console

확정 순서 = 0 2 1 3 4 5
경로 0→5 = 0 → 2 → 1 → 3 → 4 → 5 (비용 13)
```

**복잡도:** 시간 $O(E \log V)$ — 힙에 들어가는 항목은 **완화가 성공한 횟수**이고 간선 하나가 완화에 성공하는 것은 최대 한 번씩이므로 push가 $O(E)$회다. pop도 push한 만큼이니 $O(E)$회이고, 각 힙 연산이 $O(\log E)$다. $E \le V^2$이므로 $\log E \le 2\log V$이고 $O(E \log E) = O(E \log V)$가 된다. 공간 $O(V + E)$ — 인접 리스트가 $O(V+E)$, 힙이 최대 $O(E)$다.

**상수는 낡은 항목이 정한다.** 위 그래프에서 정점은 6개인데 힙에는 10개가 들어갔다. 완화가 자주 성공하는 그래프일수록 이 비율이 커지고, 그만큼 힙이 깊어진다. 그래도 $E$를 넘지는 않는다.

| 언어 차이 | Python | C++ |
|---|---|---|
| 힙 방향 | `heapq`는 **최소 힙 고정** | `priority_queue`는 **최대 힙 기본**. `greater<>`를 세 번째 인자로 넘겨야 최소 힙 |
| 힙 선언 | `pq = []` 리스트 그대로 | `priority_queue<pair<ll,int>, vector<pair<ll,int>>, greater<>>` — 비교자를 주려면 컨테이너까지 적어야 한다 |
| 꺼내기 | `heappop`이 값을 돌려준다 | `top()`으로 읽고 `pop()`으로 버리는 **두 단계** |
| 무한대 | `float("inf")`. 더해도 `inf` | `1LL << 60`. **`INT_MAX`를 쓰면 `INT_MAX + w`가 오버플로**한다 |
| 거리 타입 | 임의 정밀도 정수 | 간선 10만 개 × 가중치 10만이면 $10^{10}$ → `long long` |
| 튜플 비교 | `(3, 1) < (4, 1)` 사전식 자동 | `pair`도 사전식 자동. `tuple`도 같다 |

**완전 그래프에 가까운 마지막 줄에서도 힙 판이 이겼다.** $O(V^2)$ 판은 매 라운드 `dist` 배열 전체를 훑는데 그 $V^2$번의 메모리 접근이 힙의 $\log$보다 비싸다. Python은 격차가 더 크다 — `heapq`는 C로 구현되어 있고 배열 훑기는 파이썬 루프이기 때문이다(`tools/bench/dijkstra_heap_vs_scan.py`, 같은 환경에서 V=4,000·E=8,000 기준 4.7 ms 대 885.3 ms). ==두 언어 모두 힙 판 하나만 외워도 된다.==
:::

::: pitfall
- **낡은 항목 검사를 빠뜨린다.** `if d > dist[u]: continue`가 없으면 답은 맞지만 이미 확정된 정점의 이웃을 다시 전부 훑는다. 완화에 성공하지는 않으므로 무한 루프는 아니고, 조용히 느려진다.
- **힙에 넣을 때 `dist[v]`가 아니라 `d + w`를 다시 계산해 넣는다.** 값은 같지만 두 군데서 계산하면 한쪽만 고치는 버그가 생긴다. 갱신과 push를 한 쌍으로 붙여라.
- **C++에서 `greater<>`를 빠뜨린다.** 최대 힙이 되어 **가장 먼 정점부터** 꺼낸다. 컴파일은 되고 답만 틀린다.
- **거리를 `int`로 잡는다.** 정점 $10^5$, 간선 $10^5$, 가중치 $10^5$면 최단거리가 $10^{10}$까지 간다. `long long`이다.
- **시작점의 `dist`를 0으로 안 찍고 힙에만 넣는다.** 첫 pop에서 `0 > INF`가 거짓이 아니라 참이 되어 시작점이 버려진다.
- **가중치가 전부 1인데 다익스트라를 쓴다.** 답은 맞지만 $\log$가 공짜로 붙는다. 그런 문제는 BFS다([IV-3](#/iv-3)). 0과 1 두 종류면 0-1 BFS다([IV-4](#/iv-4)).
- **음수 간선이 있는데 다익스트라를 쓴다.** §2.2가 깨진다. [V-2](#/v-2)로 간다.
:::

## 5. 어디에 쓰이는가

**링크 상태 라우팅 프로토콜의 심장이 다익스트라다.** OSPF와 IS-IS에서 각 라우터는 네트워크 전체의 토폴로지 데이터베이스를 갖고, 자기를 시작점으로 최단경로 트리를 계산해 포워딩 테이블을 만든다. 이 계산을 프로토콜 문서가 SPF(Shortest Path First) 계산이라 부르고, 그 실체가 이 절의 코드다. 간선 가중치는 링크 대역폭에서 유도한 비용이고 언제나 양수다 — 음수 가중치를 허용하지 않는 것이 프로토콜 설계 단계에서 정해진 제약이며, 그래야 다익스트라를 쓸 수 있다. 링크가 하나 끊기면 전체를 다시 계산하는데, **그 재계산 비용을 줄이려는 것이 [V-7 D\* Lite](#/v-7)가 푸는 문제와 정확히 같은 문제다.**

**로봇의 전역 경로계획이 가중 격자 위의 다익스트라다.** 점유 격자 지도에 장애물로부터의 거리에 따라 비용을 부풀린 코스트맵을 얹으면, 벽에 붙어 지나가는 경로가 비싸져서 자연스럽게 여유를 두고 돌아간다. 벽 근처를 "못 가는 곳"이 아니라 "비싼 곳"으로 표현하는 것이 핵심이고, 그래서 좁은 통로밖에 없으면 비싸도 통과한다. 여기에 목표 방향 휴리스틱을 더한 것이 [V-5 A\*](#/v-5)이고, 실제 로봇 스택은 거의 A\*를 쓴다.

**내비게이션의 경로 탐색도 뿌리는 같다.** 도로망에서 간선 가중치를 거리가 아니라 예상 소요 시간으로 두면 "가장 짧은 길"이 아니라 "가장 빠른 길"이 나온다. 대륙 규모 도로망에서는 다익스트라를 그대로 돌리기에 정점이 너무 많아 전처리 기법을 얹지만, 그 전처리들도 전부 다익스트라를 부분 루틴으로 쓴다.

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "최소 비용", "가장 빠른 시간", "요금의 합이 최소", "거리의 합을 최소로", "A에서 B까지 가는 데 드는 최소" + 간선마다 값이 다르게 주어짐
- 제약조건: 간선 가중치가 **전부 0 이상**이고 제각각. 정점 $V \le 10^5$, 간선 $E \le 5 \times 10^5$ 수준이면 $O(E \log V)$가 넉넉히 들어간다. 거리 합이 $2^{31}$을 넘을 수 있으면 64비트
- 혼동 주의: 가중치가 전부 1이면 → [IV-3 BFS](#/iv-3)(로그가 낭비다). 0과 1 두 종류뿐이면 → [IV-4 0-1 BFS](#/iv-4). 음수가 하나라도 있으면 → [V-2 벨만-포드](#/v-2). 모든 쌍을 다 물으면서 $V \le 400$이면 → [V-3 플로이드-워셜](#/v-3). 목표가 하나뿐이고 격자에서 휴리스틱을 만들 수 있으면 → [V-5 A\*](#/v-5)
- 반례 함정: 상태를 정점 번호 하나로만 잡는 것. "동전을 $K$개까지 쓸 수 있다", "한 번은 공짜로 탈 수 있다" 같은 조건이 붙으면 정점은 `(도시, 남은 횟수)`다. 그리고 **역방향 최단거리**를 물으면 간선을 전부 뒤집어 한 번 더 돌린다 — 도착점마다 다익스트라를 돌리면 시간 초과다
:::

::: interview
**"다익스트라가 음수 간선에서 왜 안 됩니까."**
"그리디 확정이 성립하는 근거가 무너지기 때문입니다"까지는 누구나 말한다. 답의 뼈대는 §2.2의 마지막 줄이다. "최단경로 위의 미확정 정점 $y$에 대해 $\delta(y) \le \delta(u)$여야 힙이 $u$보다 $y$를 먼저 내준다는 모순이 성립합니다. 이 부등식은 $y$에서 $u$까지 남은 구간 비용이 0 이상이라는 데서 나옵니다. 음수 간선이 있으면 그 부등식이 깨집니다." 반례 그래프를 그 자리에서 그릴 수 있으면 [V-2](#/v-2) 질문으로 그대로 넘어간다.

**"힙에 같은 정점이 여러 번 들어가는데 괜찮습니까."**
"괜찮습니다. 꺼낼 때 `d > dist[u]`면 버립니다"가 절반이다. 나머지 절반은 비용 분석이다. "힙 항목 수는 완화 성공 횟수라 최대 $E$개이고, $\log E \le 2\log V$이므로 복잡도는 감소 키 판과 같은 $O(E\log V)$입니다. 감소 키는 힙 인덱스 대응표를 직접 관리해야 해서 표준 라이브러리로 안 됩니다."
:::

## 연습

::: quiz
전부 **간선 가중치가 0 이상이고 제각각**인 최단경로다. 코드를 짜기 전에 "정점 하나가 무엇인가"와 "가중치가 음수일 수 있는가"를 먼저 적어라.

**1. 백준 1753 최단경로 (골드 4)** — https://www.acmicpc.net/problem/1753
- 신호: "시작점에서 다른 모든 정점까지의 최단 경로". 가중치가 10 이하의 자연수라고 못 박는다. $V \le 20{,}000$, $E \le 300{,}000$.
- 상태: 정점 번호 하나. 이 유형의 원형이다.
- 자료구조: 인접 리스트 + 최소 힙. **같은 정점 쌍에 간선이 여러 개** 주어질 수 있으므로 인접 행렬로 받으면 안 되고, 받더라도 최솟값만 남겨야 한다. 도달 못 하는 정점은 `INF`로 남는다.

**2. 백준 1916 최소비용 구하기 (골드 5)** — https://www.acmicpc.net/problem/1916
- 신호: "A번째 도시에서 B번째 도시까지 가는데 드는 버스 비용을 최소화". 출발지와 도착지가 하나씩이다.
- 상태: 도시 번호 하나. 목표가 하나라도 다익스트라는 그냥 전체를 구하고 하나만 읽는다 — 조기 종료를 넣어도 되지만 복잡도는 그대로다.
- 자료구조: 인접 리스트 + 최소 힙. 시간 제한이 빡빡하므로 **선형 탐색 판을 쓰면 위험하다.** 왜 힙이어야 하는지 §4의 실측으로 설명할 수 있어야 한다.

**3. 백준 4485 녹색 옷 입은 애가 젤다지? (골드 4)** — https://www.acmicpc.net/problem/4485
- 신호: 격자인데 "잃는 금액을 최소로". 한 칸 이동의 비용이 **칸마다 다르다.** 이 한 줄이 BFS와 다익스트라를 가른다.
- 상태: 칸 `(r, c)` 하나. 암묵 그래프이고 간선 비용은 **들어가는 칸**의 값이다. 시작 칸의 값도 세는지가 오프바이원의 자리다.
- 자료구조: 거리 배열 `dist[r][c]` + 최소 힙. 이 문제를 BFS로 풀면 왜 틀리는지 §1의 그래프로 설명할 수 있어야 한다.

**4. 백준 1238 파티 (골드 3)** — https://www.acmicpc.net/problem/1238
- 신호: "$X$로 갔다가 다시 자기 마을로 돌아온다". 왕복이고, 도로가 **단방향**이라 갈 때와 올 때의 비용이 다르다.
- 상태: 마을 번호 하나. 다만 "모든 $i$에서 $X$까지"와 "$X$에서 모든 $i$까지" 두 방향이 필요하다.
- 자료구조: 인접 리스트 두 벌 — 원본과 **간선을 전부 뒤집은 것.** 각각에서 $X$를 시작점으로 한 번씩 돌리면 다익스트라 두 번으로 끝난다. 마을마다 한 번씩 돌리면 $N$배가 되어 터진다. **"모든 정점에서 한 점으로"를 "한 점에서 모든 정점으로"로 뒤집는 것**이 이 문제의 전부다.
:::

## 요약

- 다익스트라는 새 알고리즘이 아니다. **BFS의 큐를 우선순위 큐로 갈아 끼운 것**이다. 나머지 코드는 그대로다.
- BFS가 잃은 것은 큐의 정렬이고, 힙이 그것을 되돌려 준다. 그래서 **꺼내는 순서가 다시 거리 순**이 된다.
- **확정 불변식:** 유효한 항목 $(d, u)$를 꺼내는 순간 $d = \delta(u)$다. 증명은 최단경로 위 첫 미확정 정점 $y$에 대해 $\delta(y) \le \delta(u)$라는 데 기댄다.
- 그 부등식은 **남은 구간 비용이 0 이상**이라는 데서 나온다. 음수 간선이 하나라도 있으면 무너지고, 거기서 [V-2](#/v-2)가 시작된다.
- **게으른 삭제**가 실전의 관용구다. 낡은 항목을 지우지 않고 새 값을 push한 뒤, 꺼낼 때 `d > dist[u]`면 버린다. 힙 항목이 $O(E)$개로 늘지만 복잡도는 $O(E \log V)$로 같다.
- 감소 키 판은 힙 크기를 $O(V)$로 줄이지만 정점 → 힙 인덱스 대응표를 직접 관리해야 하고, 표준 라이브러리로는 안 된다.
- Python `heapq`는 최소 힙 고정, C++ `priority_queue`는 최대 힙 기본이다. **방향이 반대다.**
- 세 최단경로 알고리즘은 같은 벨만 방정식을 서로 다른 순서로 푼다. 다익스트라의 순서는 **"확정된 거리가 작은 것부터"**다 — [V-4](#/v-4)에서 이 관계를 정면으로 다룬다.
