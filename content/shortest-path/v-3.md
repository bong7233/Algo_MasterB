# V-3 플로이드-워셜

::: lead
삼중 루프의 가장 바깥이 왜 `k` 여야 하는가. 이것은 구현 관례가 아니라 계산 순서의 문제다.
:::

## 1. 문제

[V-1](#/v-1)과 [V-2](#/v-2)는 둘 다 **시작점 하나**를 받는다. `dist[v]`는 언제나 "그 시작점에서 $v$까지"다.

묻는 것이 달라지는 문제가 있다. 도시 $n$개에 버스 노선이 있고, **모든 도시 쌍 $(A, B)$에 대해** 최소 비용을 다 출력하라고 한다. 또는 사람 $n$명의 친구 관계에서 "각 사람이 나머지 전원과 몇 다리 건너 이어지는지의 합"을 구해 최솟값을 가진 사람을 찾으라고 한다. 어느 쪽도 시작점이 하나가 아니다.

가장 먼저 떠오르는 답은 **모든 정점을 시작점으로 다익스트라를 $V$번 돌리는 것**이고, 이것은 실제로 옳은 방법이다. 비용은 $O(V \cdot E \log V)$다. 그런데 두 군데서 걸린다.

첫째, **음수 간선이 있으면 다익스트라를 못 쓴다.** 벨만-포드를 $V$번 돌리면 $O(V^2 E)$이고, 조밀 그래프($E \approx V^2$)에서는 $V^4$다.

둘째, **조밀 그래프에서 $E \log V$가 $V^2 \log V$가 된다.** $V$번 돌리면 $V^3 \log V$다. 로그가 곱해진 만큼 손해다.

정점 수가 작고($V \le 400$ 정도) 그래프가 조밀하거나 음수 간선이 섞였을 때, **$V$번 반복이 아니라 처음부터 전 쌍을 대상으로 하는 알고리즘**이 필요하다. 그리고 그것은 세 줄로 짜인다.

## 2. 아이디어

### 2.1 무엇을 상태로 둘 것인가

[V-1](#/v-1)의 상태는 "정점 $v$까지의 최단 비용"이었다. 전 쌍이면 자연스럽게 "$i$에서 $j$까지의 최단 비용"이 된다. 그런데 그것만으로는 점화식이 안 써진다. **$i \to j$ 최단경로를 무엇으로 쪼갤 것인지가 정해지지 않았기 때문이다.**

쪼개는 축을 하나 더 넣는다.

$$D_k[i][j] = \text{정점 } 0, 1, \ldots, k-1 \text{ 만 중간 경유지로 써서 } i \to j \text{ 로 가는 최소 비용}$$

"중간 경유지"라는 말이 정확해야 한다. **양 끝 $i$와 $j$는 이 제한을 받지 않는다.** $i$나 $j$가 $k$ 이상이어도 상관없다. 제한을 받는 것은 경로 안쪽에 끼어 있는 정점들뿐이다.

$k = 0$이면 아무 정점도 경유할 수 없으니 $D_0[i][j]$는 **간선 하나로 직행할 때의 비용**이다($i = j$면 0). 이것이 초기값이다.

$k = V$면 모든 정점을 경유지로 쓸 수 있으니 $D_V[i][j]$가 진짜 최단 비용이다. 이것이 답이다.

### 2.2 한 정점을 허락하면 무슨 일이 생기는가

$D_k$에서 $D_{k+1}$로 간다. 새로 허락되는 것은 정점 $k$ 하나뿐이다. $i \to j$ 경로를 두 종류로 나눈다.

- **정점 $k$를 안 지나는 경로.** 그러면 여전히 $k$ 미만만 경유하므로 최선은 $D_k[i][j]$다.
- **정점 $k$를 지나는 경로.** $k$에서 한 번 잘라 $i \to k$와 $k \to j$로 나눈다. 두 조각 각각은 중간에 $k$를 다시 지나지 않는다(지나면 사이클이고, 음수 사이클이 없으면 잘라내는 편이 낫다). 그러므로 두 조각 모두 $k$ 미만만 경유하고, 최선은 $D_k[i][k] + D_k[k][j]$다.

둘 중 작은 것이 답이다.

$$D_{k+1}[i][j] = \min\big(D_k[i][j],\; D_k[i][k] + D_k[k][j]\big)$$

이것이 전부다. **세 줄짜리 알고리즘의 정체는 정점 하나를 허락할 때마다 표 전체를 한 번 갱신하는 DP다.**

::: note
$D_k[i][k]$와 $D_k[k][j]$에서 **$k$가 양 끝에 있다**는 점을 보라. $k$가 끝점이므로 "$k$ 미만만 경유"라는 제한에 걸리지 않는다. §2.1에서 "양 끝은 제한을 받지 않는다"고 못 박은 것이 여기서 쓰인다. 이 정의를 대충 잡으면 점화식이 성립하지 않는다.
:::

### 2.3 왜 `k` 가 가장 바깥이어야 하는가

점화식은 $D_{k+1}$을 $D_k$로부터 만든다. 표가 $k$마다 한 장씩, 총 $V+1$장 있는 셈이다. 그런데 구현은 표 한 장만 쓰고 덮어쓴다.

덮어써도 되는 이유가 있다. $k$번째 층을 계산할 때 읽는 칸은 $[i][k]$와 $[k][j]$뿐인데, **그 두 칸은 $k$번째 층에서 값이 바뀌지 않는다.**

$$D_{k+1}[i][k] = \min(D_k[i][k],\; D_k[i][k] + D_k[k][k]) = D_k[i][k]$$

$D_k[k][k] = 0$이기 때문이다(음수 사이클이 없다는 가정 아래). $[k][j]$도 같다. 그래서 $k$번째 층 안에서는 읽는 칸이 이미 갱신됐든 아직 아니든 값이 같고, 표 한 장으로 덮어써도 안전하다.

**여기서 요구되는 것은 하나다. $k$번째 층 전체를 끝낸 뒤에 $k+1$번째 층을 시작해야 한다.** 그것이 `k` 를 가장 바깥에 두는 이유다. 안쪽 두 루프 `i` 와 `j` 는 서로 순서를 바꿔도 되고, 같은 층 안에서는 어느 칸을 먼저 채우든 결과가 같다.

`k` 를 안쪽에 두면 무슨 일이 벌어지는가. `i` 가 바깥이면 **$i$ 행 하나에 대해 $k$를 0부터 $V-1$까지 한 번씩만 훑고 그 행을 영영 떠난다.** 그 한 번의 훑기 동안 참조하는 $D[i][k]$가 아직 안 채워졌을 수 있고, 다시 돌아올 기회가 없다.

::: danger
사슬 하나로 확인한다. 간선은 `0 →3`, `3 →2`, `2 →1` 셋이고 비용은 전부 1이다. **정점 번호가 경로 진행 방향과 거꾸로 붙어 있다는 점이 전부다.**

```text nolines
              1        1        1
      0 ─────▶ 3 ─────▶ 2 ─────▶ 1
```

`d[0][1]`의 참값은 3이다. `k` 를 안쪽에 둔 판(`i → j → k`)을 손으로 돌린다. $i = 0$ 행에서 $j$를 0부터 훑는다.

- $j = 1$: $k$를 훑는다. $d[0][2] = \infty$, $d[0][3] = 1$이지만 $d[3][1] = \infty$다. **아무것도 못 줄인다.**
- $j = 2$: $k = 3$에서 $d[0][3] + d[3][2] = 1 + 1 = 2$. $d[0][2] = 2$가 된다.
- $j = 3$: 이미 1이다.

$i = 0$ 행이 끝났다. `d[0][1]`은 여전히 $\infty$다. $j$가 1일 때는 $d[0][2]$가 아직 $\infty$였고, $d[0][2]$가 2로 채워졌을 때는 이미 $j = 1$을 지나쳐 버렸다. ==필요한 값이 필요한 시점보다 늦게 만들어진다.== 그리고 $i = 0$ 행으로 다시 돌아오지 않는다.

```console

  k 가 바깥 (kij) — 정답
      0   3   2   1
    INF   0 INF INF
    INF   1   0 INF
    INF   2   1   0
  k 가 안쪽 (ijk) — 오답
      0 INF   2   1
    INF   0 INF INF
    INF   1   0 INF
    INF   2   1   0
  d[0][1] : 정답 3 / k 안쪽 inf
```

**같은 사슬을 `0 →1 →2 →3` 으로 번호만 바꿔 붙이면 `k` 를 안쪽에 두고도 답이 맞는다.** $j$가 커지는 순서와 경로가 진행하는 순서가 우연히 같기 때문이다. 이것이 이 버그가 오래 사는 이유다 — 예제에서 맞고 채점에서 틀린다.

여섯 가지 루프 순서를 무작위 그래프 300개에서 전부 돌린 결과다.

|---|---|
| `k i j` | 0 / 300 |
| `k j i` | 0 / 300 |
| `i k j` | 51 / 300 |

:::

### 2.4 경로를 복원하려면

`d` 배열은 비용만 답한다. 경로를 뽑으려면 **`nxt[i][j]` — $i$에서 $j$로 갈 때 첫 걸음으로 갈 정점**을 함께 관리한다.

초기값은 간선 $i \to j$가 있으면 `nxt[i][j] = j`다. 갱신할 때는 이렇게 쓴다.

```text nolines
    d[i][j] > d[i][k] + d[k][j]  ->  d[i][j]   = d[i][k] + d[k][j]
                                     nxt[i][j] = nxt[i][k]
```

$i \to j$가 $k$를 경유하기로 정해졌다면 **첫 걸음은 $i \to k$ 경로의 첫 걸음과 같다.** $j$가 무엇이든 상관없다. 복원은 $i$에서 시작해 `nxt`를 따라 $j$에 닿을 때까지 걸으면 된다.

[IV-3](#/iv-3)이나 [V-1](#/v-1)의 부모 배열과 방향이 반대라는 점을 보라. 그쪽은 목표에서 거꾸로 올라갔고 이쪽은 시작에서 앞으로 걷는다. **한 쌍의 경로가 아니라 $V^2$쌍의 경로를 동시에 들고 있어야 하므로 앞 방향이 자연스럽다.**

### 2.5 비용을 지우면 도달 가능성이 된다

가중치를 버리고 `d[i][j]`를 "$i$에서 $j$로 갈 수 있는가"의 참·거짓으로 바꾸면 점화식이 이렇게 된다.

$$R[i][j] \leftarrow R[i][j] \;\lor\; \big(R[i][k] \land R[k][j]\big)$$

`min`이 `or`로, `+`가 `and`로 바뀌었을 뿐 구조가 같다. 이것을 **이행 폐포**(transitive closure)라 하고, 위상 정렬로 안 풀리는 "누가 누구보다 앞선다" 류의 질의에 그대로 쓴다. 도달 가능성만 묻는 문제는 [IV-1](#/iv-1)에서 이미 만났다.

비트 연산으로 접으면 안쪽 `j` 루프가 통째로 사라진다. 행 하나를 비트셋으로 들고 `R[i] |= R[k]`를 한 번 하면 64칸씩 처리된다. $V = 1{,}000$에서도 $10^9 / 64 \approx 1.6 \times 10^7$이라 돈다.

::: widget complexity-plot {"show":["nlogn","n2","n3"]}
:::

위젯의 세 곡선이 이 절의 판단 기준이다. 플로이드-워셜은 $O(V^3)$ 곡선 위에 있고, 다익스트라를 $V$번 돌리는 것은 희소 그래프에서 $O(V^2 \log V)$이므로 $O(N^2)$ 곡선 바로 위다.

$V = 400$이면 $V^3 = 6.4 \times 10^7$로 1초 선 아래다. $V = 1{,}000$이면 $10^9$으로 선을 넘는다. ==$V \le 400$ 정도가 플로이드-워셜의 실질 상한이고, 그 숫자가 문제의 제약조건에 그대로 적혀 나온다.== 제약조건에 $n \le 100$이나 $n \le 400$이 보이면서 전 쌍을 물으면 이 알고리즘이다([0-9](#/0-9)).

## 3. 손으로 따라가기

::: trace
유향 그래프. 정점 4개다.

```text nolines
    0 →1 : 8      1 →2 : 1      2 →3 : 2      3 →1 : 3
```

$D_0$은 간선 그대로다(대각선은 0, 없는 간선은 `∞`).

| $D_0$ | j=0 | j=1 | j=2 | j=3 |
|---|---|---|---|---|
| **i=0** | 0 | 8 | ∞ | ∞ |
| **i=1** | ∞ | 0 | 1 | ∞ |
| **i=2** | ∞ | ∞ | 0 | 2 |
| **i=3** | ∞ | 3 | ∞ | 0 |

`k` 를 0부터 3까지 올리면서 표가 어떻게 바뀌는지 채운다. **매 층에서 바뀐 칸만 적어도 된다.**

| k | 이 층에서 바뀐 칸 | 근거 |
|---|---|---|
| 0 | 없음 | 0으로 들어오는 간선이 없다 |
| 1 | `d[0][2] = 9` | `d[0][1] + d[1][2] = 8 + 1` |
| 2 | | |
| 3 | | |

세 가지를 확인하라.

- [ ] $k = 1$ 층에서 `d[3][2]`도 바뀌어야 한다. 왜 위 표에 안 적혔는지 확인하라(힌트: `d[3][1]`은 얼마인가)
- [ ] $k = 2$ 층이 끝났을 때 `d[0][3]`은 얼마인가. 그 값이 $k = 1$ 층의 결과에 의존하는가
- [ ] $k = 3$ 층에서 `d[2][1]`이 바뀐다. 이 값은 `2 → 3 → 1` 경로다. 만약 `k` 를 `3, 2, 1, 0` 순으로 내려가며 돌렸다면 최종 표가 달라지는가
:::

::: answer
| k | 이 층에서 바뀐 칸 | 근거 |
|---|---|---|
| 0 | 없음 | 0으로 들어오는 간선이 없다 |
| 1 | `d[0][2] = 9`, `d[3][2] = 4` | `8 + 1`, `3 + 1` |
| 2 | `d[0][3] = 11`, `d[1][3] = 3` | `9 + 2`, `1 + 2` |
| 3 | `d[2][1] = 5` | `2 + 3` |

최종 표다.

| $D_4$ | j=0 | j=1 | j=2 | j=3 |
|---|---|---|---|---|
| **i=0** | 0 | 8 | 9 | 11 |
| **i=1** | ∞ | 0 | 1 | 3 |
| **i=2** | ∞ | 5 | 0 | 2 |
| **i=3** | ∞ | 3 | 4 | 0 |

대각선이 전부 0으로 남았다는 점을 보라. `1 → 2 → 3 → 1` 은 비용 $1 + 2 + 3 = 6$짜리 사이클인데 `d[1][1]`은 여전히 0이다. **초기값 0이 6보다 작아 갱신이 안 되기 때문이다.** §4의 함정 목록에서 "최소 사이클을 구하려면 대각선을 $\infty$로 두라"고 하는 이유가 이것이다.

첫 번째. `d[3][2]`도 $k = 1$ 층에서 바뀐다. `d[3][1] + d[1][2] = 3 + 1 = 4`다. 위 표의 예시 줄이 일부러 하나만 적어 둔 것이고, **한 층에서 바뀌는 칸은 여러 개다.** 한 층이 표 전체를 훑는다는 것을 놓치면 이 문제가 생긴다.

두 번째. $k = 2$ 층이 끝나면 `d[0][3] = 11`이다. 이 값은 `d[0][2] + d[2][3] = 9 + 2`인데, **그 `d[0][2] = 9`는 $k = 1$ 층에서 만들어진 값이다.** $k = 1$ 층이 끝나지 않은 상태로 $k = 2$를 시작했다면 `d[0][2]`가 아직 $\infty$라 `d[0][3]`을 못 만든다. ==§2.3이 요구하는 "층을 끝내고 다음 층"이 여기서 눈에 보인다.==

세 번째. `k` 를 `3, 2, 1, 0` 순으로 내려가도 **최종 표는 같다.** $D_k$의 정의에서 "경유 가능한 정점 집합"이 한 번에 하나씩 커지기만 하면 되고, 어느 정점을 먼저 허락하느냐는 상관없기 때문이다. 층의 **순서**가 아니라 층을 **끝내고 넘어간다**는 것이 요구조건이다.

다만 중간 표는 다르다. `3` 부터 허락하면 $k$ 첫 층에서 `d[2][1] = 5`가 먼저 생기고 `d[0][2]`는 아직 $\infty$다. **중간 표를 답으로 쓰면 안 되는 이유가 이것이다** — 의미가 있는 것은 $D_0$과 $D_V$뿐이다.
:::

## 4. 구현

전 쌍이므로 인접 리스트가 아니라 **$V \times V$ 인접 행렬**이 입력이다. 같은 쌍에 간선이 여러 개면 최솟값만 남긴다.

::: dual
```python title="플로이드-워셜 — 전 쌍 최단경로와 경로 복원"
INF = float("inf")

N = 6
EDGES = [(0, 1, 4), (0, 2, 1), (2, 1, 2), (1, 3, 5), (2, 3, 8),
         (2, 4, 10), (3, 4, 2), (3, 5, 6), (4, 5, 3)]

d = [[INF] * N for _ in range(N)]
nxt = [[-1] * N for _ in range(N)]       # nxt[i][j] = i 에서 j 로 갈 때 **다음** 정점
for i in range(N):
    d[i][i] = 0
for u, v, w in EDGES:
    if w < d[u][v]:                      # 다중 간선은 최솟값만 남긴다
        d[u][v] = w
        nxt[u][v] = v

for k in range(N):                       # k 가 가장 바깥이다. 계산 순서의 요구다
    for i in range(N):
        if d[i][k] == INF:               # k 를 못 거치면 이 행은 볼 것이 없다
            continue
        for j in range(N):
            if d[i][k] + d[k][j] < d[i][j]:
                d[i][j] = d[i][k] + d[k][j]
                nxt[i][j] = nxt[i][k]    # i 의 첫 걸음은 i→k 경로의 첫 걸음과 같다


def path(i, j):
    if nxt[i][j] == -1:
        return []
    out = [i]
    while i != j:
        i = nxt[i][j]
        out.append(i)
    return out


for i in range(N):
    print(" ".join(f"{'INF' if d[i][j] == INF else int(d[i][j]):>4}" for j in range(N)))
```

```cpp title="플로이드-워셜 — 전 쌍 최단경로와 경로 복원"
#include <iomanip>
#include <iostream>
#include <string>
#include <tuple>
#include <vector>
using namespace std;

const long long INF = (1LL << 60);
const int N = 6;
vector<tuple<int, int, int>> EDGES = {{0, 1, 4}, {0, 2, 1}, {2, 1, 2}, {1, 3, 5}, {2, 3, 8},
                                      {2, 4, 10}, {3, 4, 2}, {3, 5, 6}, {4, 5, 3}};

vector<vector<long long>> d(N, vector<long long>(N, INF));
vector<vector<int>> nxt(N, vector<int>(N, -1));   // nxt[i][j] = i 에서 j 로 갈 때 **다음** 정점

vector<int> path(int i, int j) {
    if (nxt[i][j] == -1) return {};
    vector<int> out = {i};
    while (i != j) {
        i = nxt[i][j];
        out.push_back(i);
    }
    return out;
}

int main() {
    for (int i = 0; i < N; i++) d[i][i] = 0;
    for (auto [u, v, w] : EDGES)
        if (w < d[u][v]) {                        // 다중 간선은 최솟값만 남긴다
            d[u][v] = w;
            nxt[u][v] = v;
        }

    for (int k = 0; k < N; k++)                   // k 가 가장 바깥이다. 계산 순서의 요구다
        for (int i = 0; i < N; i++) {
            if (d[i][k] == INF) continue;         // k 를 못 거치면 이 행은 볼 것이 없다
            for (int j = 0; j < N; j++)
                if (d[i][k] + d[k][j] < d[i][j]) {
                    d[i][j] = d[i][k] + d[k][j];
                    nxt[i][j] = nxt[i][k];        // i 의 첫 걸음은 i→k 경로의 첫 걸음과 같다
                }
        }

    for (int i = 0; i < N; i++) {
        for (int j = 0; j < N; j++)
            cout << (j ? " " : "") << setw(4) << (d[i][j] == INF ? "INF" : to_string(d[i][j]));
        cout << "\n";
    }
    cout << "경로 0→5 =";
    auto p = path(0, 5);
    for (size_t i = 0; i < p.size(); i++) cout << (i ? " → " : " ") << p[i];
    cout << "\n경로 2→5 =";
    auto q = path(2, 5);
    for (size_t i = 0; i < q.size(); i++) cout << (i ? " → " : " ") << q[i];
    cout << "\n경로 5→0 =";
    auto r = path(5, 0);
    if (r.empty()) cout << " (없음)";
    for (size_t i = 0; i < r.size(); i++) cout << (i ? " → " : " ") << r[i];
    cout << "\n";
    return 0;
}
```
:::

두 언어의 출력은 같다. 입력 그래프는 [V-1](#/v-1)과 같은 것이고, **0행이 V-1의 `dist`와 정확히 일치한다** — 같은 방정식을 다른 순서로 푼 결과이기 때문이다.

```console
   0    3    1    8   10   13
 INF    0  INF    5    7   10
 INF    2    0    7    9   12
 INF  INF  INF    0    2    5
 INF  INF  INF  INF    0    3
 INF  INF  INF  INF  INF    0
경로 0→5 = 0 → 2 → 1 → 3 → 4 → 5
경로 2→5 = 2 → 1 → 3 → 4 → 5
경로 5→0 = (없음)
```

**복잡도:** 시간 $O(V^3)$ — 층이 $V$개이고 한 층이 $V \times V$ 표 전체를 한 번 훑는다. 간선 수와 무관하다는 점이 특징이다. 간선이 하나든 $V^2$개든 같은 시간이 걸린다. 공간 $O(V^2)$ — 거리 행렬과 `nxt` 행렬. $V = 1{,}000$이면 8바이트 정수 행렬 하나가 8 MB이고 두 장이면 16 MB다. **메모리가 시간보다 먼저 걸리는 경우가 있다.**

`if d[i][k] == INF: continue` 한 줄이 실전 최적화다. $i$에서 $k$로 못 가면 그 $i$ 행에서 $k$를 경유하는 경로가 아예 없다. 안쪽 $V$번 루프를 통째로 건너뛴다.

::: perf
$V^3$은 상수가 아니라 지수가 문제다. $V$가 두 배면 여덟 배다.

|---|---|---|---|---|
| 100 | 1,000,000 | 60 | 76 | 1 |
| 200 | 8,000,000 | 446 | 566 | 9 |
| 400 | 64,000,000 | 5,493 | 6,387 | 65 |
| 800 | 512,000,000 | 50,337 | 56,774 | 493 |

> (Linux x86-64 / CPython 3.13 / g++ 13 `-O2` 실측. 절대값은 기기마다 다르지만 자릿수 차이는 어디서나 같다. 측정 스크립트는 `tools/bench/floyd_warshall_cost.py` 와 `.cpp` 다.)

**$n = 400$에서 Python이 5.5초, C++이 65 ms다. 85배다.** 삼중 루프의 안쪽이 순수 연산뿐이라 인터프리터 오버헤드가 그대로 곱해진다. ==플로이드-워셜은 이 책에서 언어 선택이 가장 크게 갈리는 알고리즘 중 하나다.== $n \le 100$이면 Python도 여유롭고, $n = 400$이면 C++로 가는 편이 안전하다([0-10](#/0-10)).

가운데 두 열의 차이가 Python 쪽 관용구다. `dk = d[k]`, `di = d[i]`로 행을 지역 변수에 뽑아 두면 안쪽 루프에서 이중 인덱싱이 사라져 **1.13~1.27배** 빨라진다. 자릿수를 바꾸지는 못한다 — 상수 최적화로 $V^3$을 이길 수는 없다.
:::

| 언어 차이 | Python | C++ |
|---|---|---|
| 무한대 | `float("inf")`. `inf + inf`도 `inf` | `1LL << 60`. **`INF + INF`가 `2^61`로 여전히 `long long` 안**이라 안전하다. `INT_MAX`를 쓰면 오버플로한다 |
| 2차원 배열 | `[[INF] * N for _ in range(N)]`. **`[[INF] * N] * N`은 전 행이 같은 객체다** | `vector<vector<long long>>(N, vector<long long>(N, INF))` |
| 행 캐시 | 안쪽 루프 앞에 `dk = d[k]`, `di = d[i]`로 뽑아 두면 1.13~1.27배 빨라진다(§4 실측) | 컴파일러가 알아서 한다. 대신 **행 단위 `vector`는 메모리가 흩어져** 1차원 배열보다 느릴 수 있다 |
| 표 출력 | f-string 정렬 `f"{x:>4}"` | `setw(4)`. 숫자와 문자열을 섞으려면 `to_string`이 필요하다 |

::: pitfall
- **`k` 를 안쪽에 둔다.** §2.3의 실측대로 무작위 그래프의 13~17%에서 틀린다. 예제에서는 맞는 경우가 많아 늦게 발견된다.
- **대각선을 0으로 초기화하지 않는다.** `d[i][i]`가 $\infty$면 $k = i$ 층에서 아무것도 못 한다. 반대로 **최소 사이클을 구하는 문제에서는 대각선을 일부러 $\infty$로 두어야 한다** — `d[i][i]`가 0이면 사이클이 안 잡힌다.
- **다중 간선을 덮어쓴다.** `d[u][v] = w`로 대입하면 나중에 읽은 비싼 간선이 싼 간선을 지운다. `min`으로 넣어라.
- **자기 자신으로의 간선을 그냥 넣는다.** `d[i][i]`에 양수가 들어가면 대각선 0이 깨진다.
- **음수 사이클이 있는데 그대로 돌린다.** `d[i][i] < 0`인 $i$가 생기고, 그 $i$를 경유하는 모든 쌍의 값이 의미를 잃는다. 사이클 검출이 필요하면 **`d[i][i] < 0`인 $i$가 있는지** 확인한다.
- **$V$가 큰데 쓴다.** $V = 1{,}000$이면 $10^9$이다. 그때는 다익스트라를 $V$번 돌리는 쪽이 빠르다([V-1](#/v-1)).
:::

## 5. 어디에 쓰이는가

**관계형 데이터베이스의 재귀 질의 계획에 이행 폐포가 들어간다.** 조직도나 부품 구성표(BOM)처럼 "A가 B를 포함하고 B가 C를 포함하면 A는 C를 포함한다"를 묻는 질의는 §2.5의 점화식 그 자체다. 표준 SQL의 재귀 CTE가 이 계산을 반복 방식으로 수행하고, 노드 수가 작고 관계가 조밀하면 폐포 행렬을 미리 만들어 두는 편이 매번 재귀를 도는 것보다 싸다.

**컴파일러의 데이터플로 분석이 같은 구조를 쓴다.** 제어 흐름 그래프에서 "이 지점에서 저 지점으로 도달 가능한가"는 이행 폐포이고, 도달 정의(reaching definitions) 분석은 비트 벡터에 대한 `or`/`and` 반복이다. 기본 블록 수가 수백 개 규모라 $O(V^3)$이 부담되지 않고, 비트셋으로 접으면 안쪽 루프가 통째로 사라진다.

**네트워크의 지름과 중심성 계산이 전 쌍 최단경로다.** 그래프의 지름(가장 먼 두 정점 사이의 최단거리)이나 매개 중심성 같은 지표는 정의상 모든 쌍의 최단경로를 요구한다. 정점 수백 개짜리 네트워크에서는 플로이드-워셜 세 줄이 가장 짧은 답이고, 그보다 커지면 정점마다 BFS나 다익스트라를 돌리는 쪽으로 넘어간다 — **넘어가는 경계가 $V \approx 400$이라는 것이 §2.5 위젯의 곡선이 말하는 바다.**

## 6. 이 유형을 알아보는 법

::: classify
- 신호어: "모든 도시의 쌍에 대해", "모든 (A, B)에 대해서", "임의의 두 사람이 몇 단계 만에", "각 정점에서 나머지 전부까지의 합", "가장 작은 길이의 사이클" — 시작점이 하나로 지정되지 않는다
- 제약조건: 정점 $V \le 400$ 정도. $V^3$이 $6.4 \times 10^7$이다. 간선 수는 상관없다 — 조밀할수록 유리하다. 음수 간선은 허용되고 음수 사이클만 없으면 된다. 메모리는 $V^2$개의 64비트 정수, $V = 1{,}000$이면 8 MB
- 혼동 주의: 시작점이 하나면 → [V-1 다익스트라](#/v-1). 시작점이 하나이고 음수 간선이 있으면 → [V-2 벨만-포드](#/v-2). $V$가 크고 쌍이 몇 개 안 되면 → 그 시작점마다 다익스트라. 가중치 없이 도달 여부만 물으면 → 이행 폐포(§2.5)이거나 [IV-2 DFS](#/iv-2) 반복
- 반례 함정: 대각선 초기화. 보통은 `d[i][i] = 0`이지만 **최소 사이클을 구하는 문제에서는 $\infty$로 두어야** `d[i][i]`가 사이클 비용이 된다. 그리고 같은 쌍에 간선이 여러 개일 때 `min`이 아니라 대입으로 받으면 조용히 틀린다
:::

::: interview
**"플로이드-워셜의 삼중 루프에서 `k` 가 왜 가장 바깥입니까."**
"관례가 아니라 DP의 계산 순서 요구입니다"로 시작한다. 뼈대는 세 문장이다. "상태가 `정점 0..k-1 만 경유해서 i에서 j로 가는 최소 비용`이고, $D_{k+1}$은 $D_k$ 전체에서 만들어집니다. 그래서 $k$ 층을 끝낸 뒤 $k+1$ 층을 시작해야 합니다. `k` 를 안쪽에 두면 한 행을 한 번 훑고 떠나므로 나중에 채워질 값을 못 씁니다." **반례를 그 자리에서 그릴 수 있으면 결정적이다** — 사슬 `0 →3 →2 →1` 에서 `d[0][1]`이 $\infty$로 남는다.

**"$V$번 다익스트라와 어느 쪽이 낫습니까."**
"밀도와 $V$가 정합니다"가 답이다. "플로이드-워셜은 $O(V^3)$으로 간선 수와 무관하고, 다익스트라 $V$번은 $O(VE\log V)$입니다. 희소하면 후자가, 조밀하거나 $V$가 400 이하면 전자가 낫습니다. 음수 간선이 있으면 다익스트라는 아예 못 씁니다." 코드 길이 차이(세 줄 대 수십 줄)도 실무에서는 근거가 된다.
:::

## 연습

::: quiz
전부 **시작점이 하나로 지정되지 않는** 문제다. 코드를 짜기 전에 정점 수를 확인하고 $V^3$을 계산하라.

**1. 백준 11404 플로이드 (골드 4)** — https://www.acmicpc.net/problem/11404
- 신호: "모든 도시의 쌍 (A, B)에 대해서 도시 A에서 B로 가는데 필요한 비용의 최솟값". $n \le 100$, $m \le 100{,}000$.
- 상태: `d[i][j]` — 도시 $i$에서 $j$까지의 최소 비용. 이 유형의 원형이다.
- 자료구조: $n \times n$ 행렬. **간선이 도시 쌍보다 열 배 많으므로 같은 쌍에 노선이 여러 개다** — `min`으로 받지 않으면 틀린다. $100^3 = 10^6$이라 Python도 여유롭다.

**2. 백준 1389 케빈 베이컨의 6단계 법칙 (실버 1)** — https://www.acmicpc.net/problem/1389
- 신호: "임의의 두 사람이 최소 몇 단계 만에 이어질 수 있는지". 각 사람마다 나머지 전원까지의 단계 합을 구해 최솟값을 찾는다.
- 상태: `d[i][j]` — 단계 수. **가중치가 전부 1**이므로 정점마다 BFS를 돌려도 된다. 두 방법의 비용을 비교해 보라.
- 자료구조: $n \times n$ 행렬. $n \le 100$이라 어느 쪽이든 통과한다. 관계가 **무방향**이므로 양쪽에 넣어야 하고, 답이 여럿이면 번호가 작은 쪽이다.

**3. 백준 1956 운동 (골드 4)** — https://www.acmicpc.net/problem/1956
- 신호: "가장 작은 길이의 사이클". 사이클이 존재하지 않으면 -1이다. $V \le 400$, $E \le 10{,}000$.
- 상태: `d[i][j]`. **`d[i][i]`가 곧 정점 $i$를 지나는 최소 사이클의 길이가 된다.**
- 자료구조: $n \times n$ 행렬. 함정은 초기화 하나다 — **대각선을 0으로 두면 `d[i][i]`가 영영 0이라 사이클을 못 잡는다.** $\infty$로 두어야 한다. $400^3 = 6.4 \times 10^7$이므로 Python으로는 §4의 실측대로 5초를 넘긴다. 언어 선택이 답에 걸리는 문제다.
:::

## 요약

- 전 쌍 최단경로는 시작점마다 [V-1](#/v-1)을 돌려도 되지만, **음수 간선이 있거나 그래프가 조밀하거나 $V$가 작으면** 처음부터 전 쌍을 대상으로 하는 쪽이 낫다.
- 상태는 $D_k[i][j]$ = **정점 $0..k-1$ 만 중간 경유지로 써서** $i \to j$로 가는 최소 비용이다. **양 끝은 제한을 받지 않는다.**
- 점화식은 "정점 $k$를 안 지나거나, $k$에서 한 번 자르거나" 둘 중 작은 것이다. $D_{k+1}[i][j] = \min(D_k[i][j], D_k[i][k] + D_k[k][j])$.
- **`k` 가 가장 바깥인 것은 계산 순서의 요구다.** $k$ 층을 끝내야 $k+1$ 층을 시작할 수 있다. 안쪽 `i` 와 `j` 는 순서를 바꿔도 되고, `k` 를 훑는 순서도 상관없다.
- `k` 를 안쪽에 두면 무작위 그래프의 13~17%에서 틀린다. 사슬 `0 →3 →2 →1` 에서 `d[0][1]`이 $\infty$로 남는다. **번호를 뒤집으면 우연히 맞는다는 점이 이 버그를 오래 살린다.**
- 경로 복원은 `nxt[i][j]`(첫 걸음)를 함께 갱신한다. `nxt[i][j] = nxt[i][k]` 한 줄이다 — 부모 배열과 방향이 반대다.
- `min`을 `or`로, `+`를 `and`로 바꾸면 **이행 폐포**가 된다. 비트셋으로 접으면 안쪽 루프가 64배로 접힌다.
- $O(V^3)$은 간선 수와 무관하다. $V = 400$에서 Python 5.5초, C++ 65 ms로 **85배** 갈린다. $V \le 400$이 실질 상한이다.
- 세 최단경로 알고리즘은 같은 벨만 방정식을 다른 순서로 푼다. 플로이드-워셜의 순서는 **"경유 가능한 정점 집합을 하나씩 키우는 것"**이다 — [V-4](#/v-4)에서 이 관계를 정면으로 다룬다.
