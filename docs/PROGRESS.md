| 중심축 | 코딩테스트와 실무를 동등하게. Part I(유형 판별)은 그대로 1순위 |
| 언어 기초 | Part 0을 자립적 완결 레퍼런스로 강화(11 → 13챕터) |
| 툴체인 | CPython 3.13 / g++ 13 `-std=c++17 -O2` / Ubuntu 24.04 |
| 목차 확장 | **Part XV「시스템 규모의 자료구조」12챕터 신설** — B-Tree, LSM, 블룸 필터, 스킵 리스트, HyperLogLog, 머클 트리, 일관성 해싱, 캐시 정책, 레이트 리미팅, 합의, 외부 정렬 |

## M1 — 엔진 구축

**상태:** 완료

**만든 것**

- `index.html` — 상단바, 3단 레이아웃, 검색·복습 모달, 오버레이 드로어.
- `assets/markdown.js` — `::: dual` / `::: classify` / `::: trace` / `::: widget` 을 포함한 확장 문법 렌더러.
- `assets/highlight.js` — Python·C++ 구문 강조기.

- `assets/app.js` — 라우팅·목차·검색·인북 목차·진도·SM-2 SRS·언어 토글·위젯 마운트.
- `build.py` — 번들링, 자산 버전 도장, `--watch` / `--serve` / `--single`.
- `tools/` — 콘텐츠 규범·내부 링크·다이어그램 정렬 검사기, Anki 내보내기.
- `content/toc.json` — 16개 Part 147개 절. `content/glossary.json` — 용어 31개.

- `.github/workflows/ci.yml`.

**검증한 것**

| 대상 | 방법 | 결과 |
|---|---|---|
| 구문 강조기 | 줄별 span 균형, 무손실 왕복, 꺾쇠 이스케이프, 비정상 입력 | 7/7 통과 |
| 마크다운 렌더러 | 계약 전 항목 + 상자 중첩 + XSS + 슬러그 일치 | 24/24 통과 |
| 통합 | 실제 브라우저(Chromium)에서 렌더·상호작용·반응형 | 36/36 통과 |
| 가로 스크롤 | 1500·1300·900·700·420·360px | 전 폭에서 없음 |

**통보 사항**

- 계약서에 `.topbar-actions` 래퍼를 적지 않아 아이콘 버튼이 세로로 쌓여 상단바를 넘어가는 결함이 있었다. 브라우저 검증에서 잡아 수정했다. `overflow-x: clip` 때문에 눈으로는 보이지 않던 결함이다.
- 드로어가 열린 동안 상단바는 오버레이 아래에 놓인다. 스크림을 눌러 닫는 것이 표준 동작이므로 그대로 둔다.
- 위젯이 없는 `::: widget` 은 자리표시자로 렌더된다. 콘텐츠가 위젯보다 먼저 쓰이므로 정상적인 중간 상태다.

## M2 — 간판 위젯 4종

**상태:** 완료

**만든 것**

- `assets/widgets/_runtime.js` — 위젯 공용 런타임. 껍데기 DOM, 스텝 재생기, 고해상도 캔버스, 폭 변화 대응, 테마 색 읽기.
- `assets/widgets/grid-search.js` — 같은 격자에서 BFS/DFS/다익스트라/A\* 4분할 동시 재생. 방문 순서를 색 농도로. 벽 드래그 편집.
- `assets/widgets/dp-table.js` — 배낭/LCS/LIS/구간DP/격자 5종. 점화식이 읽는 칸으로 향하는 화살표와 역추적.
- `assets/widgets/heap-ops.js` — sift-up/sift-down. 트리와 배열을 동시에, 같은 노드를 양쪽에서 강조.
- `assets/widgets/hash-table.js` — 해시→버킷→충돌→탐사→리해싱. 체이닝·선형·이차·이중 해싱.
- `assets/style.css` 20절 — 위젯 런타임 크롬.

**검증한 것**

| 항목 | 결과 |
|---|---|
| 13가지 opts 조합 렌더 | 통과 |
| 되감기 결정성(픽셀 해시) | 4종 통과 |
| 상태 줄이 스텝마다 바뀜 | 4종 통과 |
| 비정상 opts 7종 내성 | 4종 통과 |
| 1200·900·700·400px 렌더 + 가로 스크롤 없음 | 16조합 통과 |
| 테마 전환 시 다시 그림 | 4종 통과 |
| 콘솔 에러 | 0건 |

스크린샷을 직접 읽어 산출물을 눈으로 확인했다. 배낭 `dp[3][6] = max(dp[2][6]=7, dp[2][2]+5=8) = 8`,
해시 `318 % 16 = 14`, 힙의 트리·배열 일치를 손으로 검산했다.

**통보 사항**

- `dp-table` 이 큰 표를 조용히 잘라내고 있었다(용량 30→14, 물건 8→6). 자르는 것 자체는 가독성을 위해 맞지만 잘렸다는 사실이 감춰졌다. 제목에 "표가 읽히도록 줄임: 용량 30→14, 물건 8→6" 을 밝히도록 고쳤다.
- `grid-search` 는 700px 미만에서 4분할을 포기하고 한 번에 하나씩 보인다. 그 폭에서는 비교를 잃더라도 가독성이 우선이다.
- 기본 격자에서 A\* 확장 124칸 대 다익스트라 134칸으로 차이가 크지 않다. 벽이 우회를 강제하기 때문이다. V-5 를 쓸 때 열린 격자 프리셋을 함께 보이는 편이 낫다.
